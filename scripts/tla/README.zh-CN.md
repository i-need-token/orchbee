# TLA 验证工具

私有根工作区 orchbee 拥有模型选择、有界执行、可选的任务内续跑和本地成功结果复用。产品模型保留在各自工作区。
仓库合入门禁执行轻量清单和实现测试；实际模型检查遵循[验证规范](../../docs/zh-CN/VERIFICATION.md)。

## 命令

```sh
pnpm test:tla:inventory
pnpm test:tla:tooling
node scripts/tla/run-models.mjs --changed-since main
node scripts/tla/run-models.mjs --models tla-verification-execution
node scripts/tla/run-models.mjs --models tla-verification-execution --run-dir ../orchbee-tla-task
```

运行目录由调用者显式指定和拥有，位于检出目录外，只用于一个冻结的任务版本。使用同一目录重复命令
会继续该轮检查；选择其他模型会扩展其请求范围。普通命令支持有开发改动的检出。可续跑命令要求检出
干净，包括未跟踪文件，并且输入、运行时和参数一致。最后一个集成或恢复使用者结束后，调用者回收记录、日志和快照。

## 本地成功缓存

`pnpm test:tla:changed -- <base>` 启用 `--cache-dir .tools/tla-cache`，其他选择方式也可显式指定此选项。
`--all --cache-dir .tools/tla-cache` 强制重新执行并刷新成功证据；`pnpm test:tla` 仍为不使用缓存的全量基线。
`--run-dir` 与 `--cache-dir` 互斥：不可变任务续跑保持历史失败语义。本地缓存是运行器拥有的派生证据，
可随时删除，每个注册模型只有一个原子记录，其中包含规范配置集的记录。独占租约保护读取、失效及发布；
持有租约时回收退役模型记录和孤立临时文件。根目录只能是检出内已忽略的 `.tools/tla-cache` 或规范化的外部目录，
首次使用必须为空或带有匹配的归属标记。拒绝符号链接、仓库祖先目录、未知文件及写入者不明的状态。
不引入上传或远程信任；CI 仍不使用此本地缓存而执行检查。

每个配置的身份绑定准确的主模块、辅助模块和渲染后配置的字节及路径、规范变体名称、必要覆盖、worker、
堆、截止时间、TLC 语义参数、固定 jar、实际 Java 可执行文件与运行时内容、Node 身份和环境摘要，
以及排序后的生产辅助模块集合与字节。身份不包含无关提交、主张文档文字或其他模型。
它证明数学配置，不证明与修改后的产品实现对应；受影响测试及细化审查仍然必要。
注入的 Node/Java 参数、自定义 classpath 或模块查找路径会拒绝缓存参与。

派发子进程前先读取并验证全部选中记录。证据缺失、过期或损坏时报告未命中，在新执行前使整个相关模型记录失效。
强制全量执行会在首个子进程前使所有选中记录失效，包括后续失败导致尚未启动的工作。
权限、I/O、锁和不安全路径错误会失败，不会伪装成未命中。匹配的配置可以复用完整日志，同时另一个变体重新执行。
日志按原始字节保存为 base64 并附 SHA-256；复用时写入并验证新的运行内普通日志文件，重建报告路径。
输出分别标识新执行和复用的配置。

新证据要求子进程及标准流成功关闭，并具有完整的 TLC 成功终态报告。每次调用都对全部规范配置重新计算模型内覆盖。
只有完整成功的模型才能在输入与工具重新验证后发布单一原子记录。
发布发生在该模型裁定期间、调度槽位释放之前，不等待其他模型完成。
另一模型失败或原子重命名之后观察到取消，不撤回已发布的证明。
失败或未完成模型不发布任何记录。原子重命名前立即检查取消；已经发起的重命名可能先于并发取消的观察发生。
调用结束时再次验证身份，漂移则失败；已发布证据仍绑定原输入。普通缓存损坏可通过新执行恢复，
不可变运行目录损坏仍拒绝续跑。恶意本地写入者和断电持久性不在主张范围内。

执行模型将可变缓存的接纳、发布与不可变运行记录分开。缓存新鲜度及发布性质补充已有的记录、覆盖、资源与完成性质。
文件系统和 CLI 见证覆盖失败、取消前的失效操作、整个模型的原子可见性、各类身份不匹配、原始日志完整性、
新执行与复用混合覆盖、输入变化、归属及全量刷新绕过。不会把旧流程日志导入为证据。

## 建模记录

| 字段     | 契约                                                                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题     | 无关文档和 CI 改动可能触发昂贵模型；未加权并发让 TLC worker 超额；中断会重复完成的配置。在保留规范性质、变体、worker 和预算的同时减少无效工作。                                                       |
| 输入     | 经验证的规范清单、Git 基线及改动路径和文档在基线、HEAD、暂存区和工作区的快照、声明的资源限制、选定模型 ID、冻结的已跟踪输入和显式运行目录。当前清单无效则失败；历史不可用或范围解析不支持时保守选择。 |
| 数据     | 配置键为模型 ID、变体名和执行输入摘要。模型汇总键绑定模型 ID、完整规范变体集和必要覆盖。清单 owner 是描述性元数据。不可变运行清单、唯一日志、已提交结果记录和请求范围具有独立权威。                   |
| 输出     | 新执行或复用的配置通过、配置失败、模型验证或覆盖失败、跳过的待执行工作和累计请求模型摘要。没有选中模型是成功的无操作。取消或选定证据不完整均为失败。                                                  |
| 不变量   | 保持 FIFO；限制进程与内存槽位和声明 worker 总和；当前失败后停止新任务；等待活动子进程收尾；只复用完整且经验证的记录；不跨模型 ID 合并覆盖；不把历史失败变成通过。                                     |
| 决策     | 有效历史或回退；局部或共享文档依赖；队首可容纳、等待或超额单独运行；新执行、可复用、历史失败、缺失记录或无效已提交证据；完整模型覆盖或失败。                                                          |
| 模型     | 进程与持久化工作流中的确定性选择和资源策略。runModelChecks 拥有配置派发及模型内裁决；共享运行器拥有子进程和任务运行生命周期。                                                                         |
| 转移     | 见转移表。子进程关闭先于成功验证；不可变日志关闭和摘要计算先于结果记录的原子发布。                                                                                                                    |
| 依赖     | Git、Node、固定 TLC jar、Java、可用 CPU 与内存、有界子进程、任务拥有的文件系统和可选的本地成功缓存。不使用外部服务、自动重试或产物上传。                                                              |
| 所有权   | 一个运行器租约写入显式运行目录。一个配置记录拥有其结果；一个模型 ID 汇总拥有其覆盖结果。调用者拥有恢复与最终回收。产品工作区拥有现有模型与主张。                                                      |
| 验证     | 选择的正反 Git 样例；加权 FIFO、失败和收尾轨迹；带种子、重放和缩减的状态式独立预言机；记录与日志完整性、租约、取消和续跑测试；真实固定 TLC 的默认、支持模块、变体和复用检查。                         |
| 正确性   | 根执行模型检查有限安全性和进展；主张表声明细化证据及限制。历史汇总恢复还必须通过具名持久化组合测试。                                                                                                  |
| 参考范围 | 现有运行器调用语义、固定 TLC 1.7.4、fp 0、最终活性检查和 coverage 1。现有模型 worker、堆分配规则、性质、变体和截止时间继续具有权威。                                                                  |

## 转移与证据发布

| 状态或事件             | 守卫与效果                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| 待执行到活动           | 运行已验证；FIFO 队首符合进程、内存和 CPU worker 预算。声明 worker 超额的任务单独运行。                    |
| 子进程关闭             | 保留完整日志；退出、信号和原截止时间决定通过或失败。失败在输出收尾前关闭派发。                             |
| 已验证到通过           | 退出码为零、TLC 成功和最终状态报告完整；先关闭唯一不可变日志并计算摘要，再原子重命名引用其准确摘要的记录。 |
| 待执行到复用           | 同一冻结运行、执行身份和完整的已提交通过记录与日志。复用原覆盖和 TLC 耗时，并明确报告为复用。              |
| 历史失败               | 保留已提交失败；另一次显式调用可检查待执行工作。完整请求范围仍为失败。                                     |
| 无效已提交记录         | 模式、身份、摘要、路径或日志完整性错误在启动 TLC 前拒绝续跑。不自动修复或重跑。                            |
| 缺失记录或孤立临时文件 | 不构成通过证据；工作仍待执行。写入者停止后回收拥有的孤立产物。                                             |
| 模型裁决               | 每个规范配置通过且该模型日志覆盖并集满足原标记后才验证通过。覆盖失败单独持久化。                           |
| 成功缓存模型           | 裁决期间重新验证准确输入，并在尚未观察到取消时原子发布完整记录；不要求其他模型进入终态。                   |
| 取消或当前失败         | 关闭新任务派发；终止或有界等待拥有的子进程收尾，报告跳过的工作，写入者停止后释放租约。                     |

原子性只覆盖独占租约下的一次记录发布，不覆盖对已提交配置结果的覆盖写。日志和记录是两个文件。
断电持久性及恶意文件系统或运行时写入者不在主张范围内。失效或不明确的租约需要调用者确认 Node/JVM
写入者停止后恢复。路径规范化并拒绝符号链接、reparse 和路径穿越。自动清理只针对已验证且拥有的尝试
子目录，绝不递归删除调用者提供的运行根目录。续跑身份包含 Node 可执行文件、版本、平台和选项、Java
身份、固定 jar、辅助代码及已登记声明／输入的字节、清单、已跟踪版本及传给 TLC 的每个暂存字节。
不可变清单把独立运行 ID 绑定到规范运行根目录；移动目录不会保持续跑身份。登记输入必须属于 HEAD，
且不能通过 Git skip-worktree 或 assume-unchanged 标志隐藏改动。廉价清单门禁拒绝被忽略的输入，
同时允许开发中的新文件尚未跟踪且未被忽略。结束时重新校验冻结检出和输入身份；检出内容或版本
变化会使本次调用失败，汇总仍标为未完成。

配置和模型的通过记录在调用原子重命名前检查已观察到的取消。临时 JSON 写入后发生取消时，
不会留下已提交的通过记录；此前已提交的配置仍然有效。已经发起的原子重命名可排在并发取消之前；
该约定不取消正在执行的文件系统操作。

## 选择与调度

选择合并当前与基线依赖，包括重命名和删除的两端路径。删除一个清单条目只选择剩余依赖模型，而不是
全部模型。顶层执行元数据、工作流全局配置以及无效/非祖先历史仍保守处理。
变更路径合并基线至 HEAD、HEAD 至暂存区、暂存区至工作区的差异。文档和工作流范围逐一检查相邻快照，
撤回工作区文件不能隐藏已暂存的相关改动。清单同时存在已暂存和未暂存改动，或中间出现第三种不同清单时，
选择全部模型，避免遗漏中间登记。
工具运行时/helper、受支持的 TLC job 变更以及验证/建模规范选择根执行模型；
此显式路由优先于对应的宽泛 sharedTriggers 条目。已知测试入口继续属于必须通过的轻量门禁，
该门禁检查这些入口的实际调用、每项已登记配置覆盖、根工具命令和 CI 真实 TLC 见证。
产品 owner 独立匹配原始路径，再与工具选择取并集，包括显式声明的测试、工作流或清单文件依赖。
规范引入新的产品义务时须更新其登记/配置，从而选中这些模型。

经审查的源码排除项在 `triggerExclusions` 中登记为准确的已跟踪文件，不使用目录 glob。
它们只排除通配源码触发项；主模块、配置、辅助模块、主张和准确触发路径均不可排除。
新增相邻文件仍被选中。分别评估当前与基线登记，再取结果并集，防止同一 diff 中新增排除项隐藏源码变化。
仅触发项或排除项变化时选择工具证据；其他模型元数据变化仍保守选择对应模型。
本地菜单展示与复制模式装饰使用其菜单/复制模型或确定性 Cargo 渲染、本地化证据，
不改变保留历史协议或中继权威。共享会话、输入、渲染根文件，viewport 协调和协议路径仍属于依赖。
清单门禁拒绝失效、未跟踪、含通配符或覆盖直接依赖的排除项。

登记的文档范围分类每个受支持的顶层章节。前言和引用链接定义为共享内容。未知、缺失、重复或不受支持
的标题不能悄悄缩小选择。范围变更会选择对应模型 ID。只有经复核的无关章节可排除；提案保留为宽泛依赖，
不能作为当前主张权威。工作流范围识别独立的 TLC job 和完整全局配置；有歧义的 YAML 或跨 job 依赖选择全部模型。

进程槽位保留现有的 60% 内存预算、最大 4 GiB 堆和每进程 512 MiB 预留。CPU 预算统计不变的声明 TLC worker。
jobs 选项限制进程数，不能覆盖 worker 预算。FIFO 不回填后续轻任务。worker 数超过主机容量的任务独占运行。
JVM/GC 辅助线程、操作系统调度、实际 RSS 和无关进程不在声明资源边界内。瞬时并发降低不会扩大分配的堆。

## 主张与可执行证据

| 主张             | 形式性质                                             | 实现证据                                                             | 限制                               |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------- |
| 资源准入         | ResourceSafe                                         | 加权 FIFO 轨迹和生成式调度预言机                                     | 声明 worker 与堆；超额单独运行例外 |
| 仅有效证据       | CacheSafe、CommitSafe、RejectedSafe、RecordStability | 完整性、错误运行、过期或残缺、日志损坏和原子发布测试                 | 可信运行时和独占文件系统写入者     |
| 失败关闭派发     | FailureSafe、AdmissionSafe                           | 输出收尾前失败和取消进程轨迹                                         | 子进程终止和 I/O 最终完成          |
| 完整模型内覆盖   | ModelSafe                                            | 同模型复用与新执行混合覆盖，以及同 owner 不同模型隔离                | 规范变体和必要标记                 |
| 历史汇总保持失败 | 当前裁决由 ModelSafe 检查                            | 具名轨迹：已持久化模型覆盖失败在配置复用续跑且另一模型运行后仍为失败 | 历史汇总恢复不在有限 Init 中       |
| 有限完成         | Completion                                           | 穷举具名轨迹和带种子、重放的状态式语料                               | 公平的子进程关闭、记录 I/O 和裁决  |
| 不漏选           | 不适用：无状态策略                                   | 每项排除对应的 Git、文档和工作流正向控制                             | 经复核的语义所有权与受支持解析     |

对于可变成功缓存，CacheFreshness 和 CacheAdmissionSafe 由精确输入、损坏封装和强制刷新控制验证；
CachePublicationSafe 由完整模型覆盖、失败模型隔离、取消及发布时身份不匹配见证验证。CacheCompletion
在相同的子进程/I/O 公平性假设下，为满足条件的成功模型增加最终发布义务，不依赖其他模型完成。
真实 TLC 边界见证在相邻模型执行前被阻塞时检查已完成记录，随后取消调用并验证已完成模型的精确复用。
取消可能先于发布，因此进展义务终止于发布或观察到取消。
有限模型允许裁决与发布交错；阻塞相邻模型的见证额外检查运行时在释放调度槽位前完成回调的更强顺序。

有限模型在每次运行中固定 `InputsAtPublication`，检查发布时相对冻结证据输入的身份条件。
发布后的可变文件系统输入漂移及调用结束时的身份不属于此精化主张。
真实 CLI 输入漂移见证在发布后修改输入，要求最终调用失败，再恢复准确字节并验证此前成功模型的复用。
另一个真实 CLI 取消见证在唯一模型的配置均已结束后取消，要求尚未发布的记录始终不存在。

[TlaVerificationExecution](../../formal/tla/TlaVerificationExecution.tla) 建模三个配置、两个模型 ID、两个槽位、
CPU 预算二和 worker 权重一、二、三。十六个变体覆盖新执行、并行、超额、成功或历史配置失败的续跑、
过期身份、损坏的已缓存日志、不完整的新日志、缺失覆盖、精确缓存命中、过期或损坏的缓存输入、强制刷新
和发布时身份不匹配。具名动作标记要求每个语义分支均到达。

`pnpm test:tla:tooling` 检查此模型以及真实固定 TLC 的缓存边界见证。CI 的 TLA job 在运行选中模型、
准备好固定 jar 后运行这些边界见证。普通清单门禁保留不依赖 Java 的文件系统及缓存反向控制，
不会在前置条件缺失时静默跳过真实 TLC 见证。

状态式语料使用种子 1 到 64、有界配置与资源维度及最多 128 条命令。独立预言机不调用生产转移辅助函数。
版本化轨迹序列化必须确定性重放；缩减删除命令块或动作并简化数量或权重，同时保留依赖和原失败指纹。
