## Authorization

The terminal experience must recover the observable behavior of the mature pre-cutover terminal
while retaining Terminal Host as the only PTY and Ghostty VT authority. Desktop and an authenticated
LAN Browser must consume the same canonical Host state through the projected client. Recovery is
split into independently verifiable slices and must not infer completion from a screenshot or from
the presence of an implementation path.

The decision owner accepted this recovery scope and the claim inventory on 2026-08-11. The scope
includes one Tab with one primary terminal Panel. It excludes multi-Panel and multi-Tab product
work, browser-side VT restoration, synchronous whole-buffer APIs, unsupported graphics protocols,
and unrelated new product features. The active-request decision owner separately accepted the
choices under
[Accepted capability and product boundaries](#accepted-capability-and-product-boundaries) on
2026-08-18. Those choices authorize only their recorded boundaries; their implementation and
evidence remain incomplete until each owning slice converges.

### Accepted stopped-terminal archive amendment — 2026-08-23

The active-request decision owner accepted the recommended read-only terminal archive on
2026-08-23 and explicitly required a fresh session not to merge retained history.

| Field                 | Accepted decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Problem               | After a controlled terminal stop and application reload, the retained presentation currently replaces the terminal with an empty centered message. Users lose the output needed to understand prior Agent work, while treating retained rows as a resumable VT would incorrectly imply that the process, modes, and interaction state survived.                                                                                                                                                                                                                                                                                                                                                                               |
| Scope                 | Desktop owns local archive capture, validation, atomic persistence, capacity enforcement, and cleanup. Terminal projection owns the read-only archive transport; the projected Web surface owns archive presentation and the bottom stopped-session action bar; Workbench owns explicit `stop` versus `close` command intent and fresh-presentation replacement. Capture retains the newest 5,000 final render rows or 10 MiB per stopped presentation, whichever limit is reached first. The local archive store is capped at 250 MiB and evicts least-recently-used entries.                                                                                                                                                |
| Claims                | Only a durable `stop` intent may archive a terminal; ordinary Tab or presentation close never creates an archive and removes any existing entry. ## Problem and outcome

The `5677c6f757d2d294dfee6cdb96549bf719d4c2e8` cutover removed the mature browser terminal
composition while the projected replacement did not yet own every rendering, geometry, input,

not evidence that Host-owned VT state is the wrong architecture.

Host-owned state, bounded transport, and source-neutral client composition. A behavior may differ
only when an owning current authority or a separately accepted reserved decision explicitly defines
that difference.

## Evidence and delivery

Every defect first gets a reduced failing regression at the earliest incorrect owner. Compatibility
claims use a pinned differential corpus or versioned golden trace. Geometry, timing, gesture,
focus, accessibility, and platform claims also require deterministic system traces with controlled
fonts, clocks, frames, geometry, capabilities, and interaction. Host concurrency or independently
ordered event changes update and run the owning TLA+ model when its abstraction changes.

Slices proceed in this dependency order:

1. projection and Host control (`PR-01` through `PR-13`);
2. surface geometry, theme, cursor, and runtime presentation (`SU-01` through `SU-16`);
3. scroll presentation and history (`SU-10`, `SU-11`, `HS-01` through `HS-03`, and `HS-09`);
4. input, focus, mouse, context, and Actions (`IN-01` through `IN-17`);
5. selection, search, links, and accessibility (`HS-04` through `AC-04`); and
6. application lifecycle, launch environment, and dual-client convergence (`LC-01` through
   `LC-12`).

One slice advances only after its owning current contract, failing-before regression, focused
checks, and affected package gates pass. Completion additionally requires the root `pnpm verify`
gate and every selected change-triggered correctness command.

## Accepted capability and product boundaries

The choices formerly reserved here were accepted by the active-request decision owner on
2026-08-18 within the exact scope of the
[accepted amendment](#accepted-capability-coordination-and-evidence-amendment--2026-08-18).
Acceptance authorizes governed implementation; it does not establish completion.

- Capability expansions remain unavailable until their owning implementation, negative cases,
  typed failures, owner documentation, and selected system evidence converge.
- The accepted Desktop file-drop path capability does not authorize LAN Browser paths,
  filesystem-link opening, file reads, uploads, Windows support, or automatic command execution.
- Plain-text-only selection export and unavailable filesystem activation are deliberate product
  outcomes, not temporary gaps.
- External URL interaction remains limited to `http`, `https`, and `mailto`; adding another
  scheme is a new reserved decision.
- Clipboard server relay, `execCommand`, silent fallback, HTML/VT export, and a new evidence
  specification framework remain outside this authorization.
- Any implementation that requires a materially different owner, public contract, security
  boundary, product outcome, or evidence limit returns to the decision stage before governed edits.
