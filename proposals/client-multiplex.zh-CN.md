# Client 多路复用连接

## 决策与范围

已接受，2026-10-24。ORC-198 将 TUI 进程的功能连接替换为一次 OBLC 准入和一条
OBWP v1 多路复用载体。一次性 CLI 调用保留现有的单条连接。现有 Terminal、
Workbench 和 Agent 编解码器继续拥有语义权威；载体不重新解释其结果。
改动分类为 Consequential/Modeled。不引入异步运行时或依赖。

## 所有权与顺序

Client 连接 actor 拥有已准入流、重连、流身份、取消和订阅恢复。请求一旦可能
交付就绝不重放。连接丢失或 gap 后，每个订阅以新快照重新打开；旧代次应答
不能完成新流。逻辑 lane 保留各自领域取消和结果关联，但不再打开连接。

Server 每条已准入连接使用一个读线程和一个写入／分发线程。读线程准入有界
消息；写线程拥有终端连接状态、订阅状态和全部输出。状态所有者在提交后发布
非阻塞失效通知。订阅求值和套接字写入均在状态锁外执行。状态订阅合并为
最新值。事件订阅保留有界有序页；溢出时丢弃待发页，在下一份快照前发出 gap。
持续超限只以类型化原因关闭该连接。

## 载体与订阅

OBWP 保持版本 1。通用流打开／帧／关闭记录携带非零、连接局部的流 ID，独立
于终端图片生产者身份。打开记录包含有界的现行语义请求；订阅打开区分快照
请求与增量请求。Server 只准入读取操作作为订阅。取消结束该流，不能撤回
已经提交的变更。连接销毁准确释放每个拥有的订阅和终端资源一次。现有 journal
epoch／sequence 与显式 gap 语义继续具有权威。

## 正确性与证据

小型共享协议模型覆盖独立排序的发布、交付、溢出、重新取快照、取消和重连。
其声明为先快照后增量、取消后或旧代次不得交付、队列有界，以及发布独立于
Client 队列占用仍可执行。最后一项以非阻塞发布为假设，不证明 OS socket 进展或
字节／stream 预算。现有模型不覆盖新增载体边界；普通请求编解码测试无法探索这些竞争
转换。模型抽象载荷校验和操作系统调度；受控实现轨迹检查映射以及畸形／
有界帧准入。

性能对照使用同一 Windows 主机和私有 runtime、一个空闲 Workspace／PowerShell，
预热十秒后采集三段三十秒的 Client／Server／Worker CPU 时间、线程上下文切换
次数、线程数和 OBLC 连接数。基线测量必须使用基线修复后可编译的冻结 main 修订；
原始 d17d2b5e6 源码不是已测量基线。记录实际基线／候选 hash，使用相同负载和工具。
上下文切换是调度代理指标，不是硬件唤醒次数。原生测量和最终验证必须
有明确证据，绝不从源码推断。无通知源的 OS 进程采样和 Host 屏幕采样仍保持
有界，并在轮询代码旁解释缺失的事件源。

## 交付

先实现载体和有界 Server 分发，再实现 Client actor 和全部功能 lane，最后
删除旧连接／重连路径和过时轮询。同步更新 Server／TUI 所有者文档以及架构
数据流的双语文档。完整行为进入现行权威后删除本提案。
