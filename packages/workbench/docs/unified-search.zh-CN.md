# 统一搜索

## 权威与范围

该参考负责维护 Workbench 搜索交互模型、provider协调、结果投影和正确性声明。`@orchbee/actions` 负责注册、已准备调用、执行、确认、并发，以及调用后的取消。搜索provider及其语义数据仍归各功能所有者；应用组合负责选择provider与平台适配器。

当前的实现包括有界同步和异步provider协调、本地操作和设置投影、确定性排名、嵌套操作输入、重试、故障隔离、可访问性行为和陈旧完成拒绝。当前未组合（compose）任何 Agent 自有或活动的 Terminal-instance provider。

文件搜索、持久查询或操作历史记录、用户定义的键绑定、操作链接、不透明排名、包含查询或结果数据的遥测以及工作台拥有的代理或终端运行时状态均被排除。

## 领域契约

| 领域           | 合同                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 问题           | 当独立拥有的provider加载、失败、重试和更改顺序时，人们必须通过一个表面发现和调用功能。       |
| 可信输入       | 审查了开放过滤器、安装的操作范围、注册的provider、验证的provider结果、区域设置和快捷方式平台 |
| 不受信任的输入 | 查询文本和指针或键盘事件；查询文本保留在已安装的内存中并且永远不会执行                       |
| 输出           | 确定性分组的可见结果、加载或失败投影、语义公告，以及至多一个已准备的 Action 调用             |
| 无操作         | 陈旧完成、关闭后完成、不可用结果、重复当前选择以及调用前取消                                 |
| 副作用         | provider请求获取和取消、选择后的操作调用、焦点移动、滚动和可访问性公告                       |

## 所有权

| 可变事实                           | 唯一所有者                          |
| ---------------------------------- | ----------------------------------- |
| 打开会话、过滤器、查询修订和选择器 | 工作台搜索交互状态                  |
| provider请求身份、阶段和结果集     | 工作台provider-协调状态             |
| provider数据和导航含义             | 贡献的功能                          |
| 行动的可用性和执行                 | 已安装 `ActionRuntime` 和语义所有者 |
| 代理会话、编写器和提交生命周期     | 代理能力拥有者                      |
| 终端实例和进程生命周期             | 应用构成及终端能力                  |
| DOM 焦点、测量滚动和实时公告       | 窄工作台 React 适配器               |

provider返回值和运行时拥有的调用令牌。他们从不接收工作台状态编写器，也从不提供任意执行回调。

本地 Action 目录订阅已挂载的运行时，并在订阅后再次核对，因此渲染与订阅之间发生的注册表
变化不会让可见目录停留在旧状态。

## 规范数据

provider有一个稳定的 ID，声明它支持的过滤器，公开有界的默认和查询操作，并可选择在其拥有的读取模型发生更改时通知协调器。每个结果都具有稳定的provider本地身份、准备好的演示、显式分组元数据、可搜索术语、可用性以及准备好的或未绑定的操作调用。

协调器根据 provider ID 与 provider 本地结果 ID 分配仓库范围的结果标识。provider 完成顺序不参与排名。查询匹配度、推荐状态、会话新近度、provider 优先级、Group 顺序及稳定标识共同构成完整确定性比较；数字优先级较小的 provider 排在前面。

一位provider的运行记录：

- provider ID；
- 开放会话 ID；
- 查询修订；
- 重试尝试；
- `loading`、`ready` 或 `failed` 相；
- 准备好后有界结果部分；和
- 发生故障时稳定的内部故障代码。

原始异常（exception）永不进入产品呈现（presentation）。

## 转换

| 活动               | 守卫                                          | 结果                                                             |
| ------------------ | --------------------------------------------- | ---------------------------------------------------------------- |
| 打开               | 任何状态                                      | 创建新会话，重置查询和provider投影，并请求适用的provider         |
| 查询已更改         | 查询值不同                                    | 增加修订、取消先前运行、清除其投影，并请求当前provider           |
| 过滤器已更改       | 浏览和过滤不同                                | 保留查询、增加修订、取消先前运行并请求适用的provider             |
| provider已启动     | 会话和修订是最新的                            | 记录该provider的一次加载运行                                     |
| provider已完成     | 当前执行实例、会话、修订、provider 和尝试匹配 | 仅用有界就绪结果替换该provider投影                               |
| provider失败       | 当前执行实例、会话、修订、provider 和尝试匹配 | 仅将该provider投影替换为稳定的失败状态                           |
| 重试provider       | 当前运行失败                                  | 仅增加provider尝试并开始替换运行                                 |
| provider模型已更改 | provider仍然适用                              | 仅替换该provider运行；其他provider和当前高亮保持稳定             |
| 启动参数选择器     | 当前结果携带支持的未绑定输入                  | 保留浏览快照并进入嵌套选择器                                     |
| Back               | 正在选择参数                                  | 恢复过滤器、查询、修订、高亮、provider投影和测量滚动             |
| 关闭或卸载         | 表面是开放的                                  | 取消provider工作，清除已安装的投影，恢复语义焦点，不调用任何内容 |

`AbortController` 协助释放资源。即使 provider 忽略取消，每次完成也必须同时匹配精确的当前执行实例、会话、修订、provider ID 和尝试。重新连接时复用相同请求字段，不会使旧连接的完成重新有效。

协调器先提交转换并退役被替换的执行，再调用外部取消处理器或快照监听器。同步回调可以提交更新的查询或 provider 模型变化；旧调用不能覆盖、取消或代替新运行启动工作。每个当前加载中的运行最多启动一次，排队中的工作在调用 provider 前再次确认所有权。释放连接期间，清理拒绝后续 provider 转换。

每个连接拥有自己的 provider 订阅。连接部分失败时释放已获取的订阅；清理会先逐一释放全部自有订阅，且每项只释放一次，再报告失败。旧连接句柄不能关闭新连接。获取与清理的失败会保留给工程调用方，不会作为原始产品文案展示。

## 不变量

- 每个可见的异步结果都属于当前打开的会话和查询修订。
- 一个provider和尝试最多存在一次当前运行。
- 陈旧的、取消的、失败的或关闭后的完成永远不会改变可见的结果。
- provider完成顺序不会改变最终分组结果顺序。
- 高亮的结果不存在或在当前可见结果集中解析。
- 一个provider的失败不会删除或禁用另一provider的结果。
- 重试一个provider既不会重新启动也不会清除不相关的就绪provider。
- 一个接受的结果最多达到一个准备好的 Action 执行。
- 关闭、provider取消、选择器取消、高亮、悬停和预取不会调用任何产品操作。

## 正确性证据

| 声明                           | 所有者切片 | 确定性证据                                                 | 边界与排除项                                           |
| ------------------------------ | ---------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 陈旧的完成被排除在外           | 转换       | 重新排序完成并重新打开回归                                 | 有界provider、会话、修订和尝试                         |
| 订阅所有权在失败时仍成立       | 转换       | 部分获取、清理抛错、重复释放及获取期间释放测试             | 注入的 provider 生命周期；不涵盖外部 provider 内部实现 |
| 重入回调保留最新运行           | 转换       | 取消时替换查询、监听器替换、模型变化重入与启动前关闭时间线 | 同步回调和 Promise 调度；不涵盖 provider 内部实现      |
| 关闭会清除provider投影         | 转换       | 关闭、卸载、忽略取消和迟到完成测试                         | 不涵盖provider正确性和网络可用性                       |
| 当前高亮仍然有效               | 不变量     | 有状态交互属性测试                                         | DOM 焦点单独检查                                       |
| 当前 provider run 标识保持新鲜 | 转换       | 直接替换与陈旧完成测试                                     | 不对结果内容与顺序建模                                 |
| 完成顺序与观察无关             | 规范数据   | 排列的provider完成属性测试                                 | 排名输入保持相等                                       |
| 重试是provider本地的           | 转换       | 失败组重试时间线测试                                       | 排除超出显式用户重试的重试策略                         |
| 选择最多调用一次               | 不变量     | 准备调用集成测试                                           | 排除动作域结果的正确性                                 |
| 焦点在较晚完成时仍然存在       | 所有权     | 具有语义焦点检查点的确定性浏览器跟踪                       | 支持的桌面浏览器环境                                   |

## 维护

- provider 生命周期语义变化时，同步维护 provider 转换、协调器、React 适配器及确定性/生成回归。
- 修改实现前，将发现的失败缩减为确定性回归。
- 通过公开 provider 与 Action Runtime 契约组合 provider，不提供 Workbench 状态写入器或任意执行回调。
- 仅在语义所有者公开已接受 read-model 与 Action 契约后，准入 Agent 或 Terminal 结果。
