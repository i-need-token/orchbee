# Workbench Tabs

## Problem and scope

Workbench tabs let a user keep several local work contexts open, identify the active context, and
reorganize those contexts without losing selection, pinning, or group membership. The interaction
follows Chrome's tab-strip model: pointer movement creates an immediate, reversible displacement
preview; release commits one semantic change; cancellation restores the authoritative model.

This contract owns tab ordering, selection, pinning, grouping, group disclosure, contextual tab
actions, and the pointer-reorder timeline. It does not own terminal sessions, editor documents,
processes, persistence, or the creation of durable tab identifiers and labels.

The package must preserve these outcomes:

- selecting or beginning to drag a tab makes that tab active immediately;
- pinned tabs remain before every unpinned tab and reorder only inside the pinned region;
- grouped tabs remain contiguous and an expanded group moves as one block when its header moves;
- a tab crossing an expanded group previews membership before release and previews removal after
  crossing back out;
- displaced tabs animate into their provisional slots while the dragged surface follows the
  pointer above an opaque background;
- release emits one final tab or group move and cancellation emits no move;
- context-menu actions dismiss the menu immediately and a primary outside press may activate the
  tab beneath it with the same press, while a secondary press never synthesizes activation;
- the same pointer path produces symmetric results in the forward and reverse directions.

Keyboard reordering, multi-selection, detachable windows, saved Chrome tab groups, cross-window
dragging, touch-specific gestures, overflow scrolling, and tab content lifecycles are non-goals of
this version.

## Inputs and outputs

The caller boundary is `WorkbenchTabsState`: an optional active tab identifier, an ordered tab
array, and caller-owned group metadata. The core immediately converts that transport shape into a
structural strip model with a pinned region, unpinned tab nodes, group nodes containing their
members, and a selection record. `WorkbenchTab` and `WorkbenchTabGroup` identifiers are stable for
their complete lifecycle. Product labels and optional semantic icons are prepared by the caller;
they are not translated or generated by the model.

`reduceWorkbenchTabs(state, action)` is the principal domain operation. It returns a complete next
state, returns the original state for rejected or intentionally unchanged actions, and performs no
side effects. `createWorkbenchTabsState(input)` is the only normalization boundary and rejects
duplicate identifiers as an invariant violation. Reducers validate authoritative state and fail
with topology diagnostics instead of silently repairing invalid state.

An insert action accepts `WorkbenchTabInsertInput`, which deliberately has no `groupId` field.
The action's `groupId` is the only group-placement authority: an existing target group unpins the
new tab and appends it to that group, while `undefined` preserves requested pinning and inserts the
tab without membership. A missing target group rejects the complete action. The reducer also strips
group membership defensively when a structurally wider runtime object reaches this boundary.

The pointer adapter emits semantic outputs rather than DOM coordinates:

| Output             | Commit point                                                        | Meaning                                                           |
| ------------------ | ------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Activate tab       | Drag threshold crossing                                             | The dragged tab, or one member of a dragged group, becomes active |
| Preview tab move   | Pointer movement after activation                                   | Reversible order and membership projection only                   |
| Preview group move | Pointer movement after activation                                   | Reversible contiguous block projection only                       |
| Commit tab move    | Primary-pointer release                                             | Final tab index and group identifier                              |
| Commit group move  | Primary-pointer release                                             | Final first-member index                                          |
| Cancel             | Escape, pointer cancellation, lost capture, stale input, or unmount | No move; render authoritative state                               |

Closing, pinning, coloring, renaming, grouping, disclosure, and menu commands are semantic actions
owned by the caller-facing Workbench contract. The browser adapter never mutates caller arrays.

## Close layout state

Closing distinguishes pointer intent from non-pointer commands before the caller removes a tab.
A primary mouse press on a tab's close control captures the current rendered width of every visible
tab and enters pointer-closing mode. As long as the pointer remains inside the tab cluster, surviving
tabs keep those captured widths, so the next close control falls under the same pointer position.
The lock accepts only an ordered subset of the captured topology; insertion, reordering, pinning,
or regrouping invalidates it immediately.

Leaving the tab cluster exits pointer-closing mode and restores equal flexible distribution.
`Mod+W`, context-menu close commands, and every other non-pointer close bypass or reset the lock, so
their resulting layout responds immediately. This source distinction is transient presentation
state; it never enters `WorkbenchTabsState` and never changes the caller's close action.

## Data model and invariants

```ts
interface WorkbenchTabsState {
	readonly activeTabId: string | undefined;
	readonly tabGroups: readonly WorkbenchTabGroup[];
	readonly tabs: readonly WorkbenchTab[];
}
```

Every state accepted or returned by the core obeys all invariants below:

1. Tab identifiers are unique and group identifiers are unique.
2. `activeTabId` is absent only when there are no tabs; otherwise it resolves to one existing tab.
   A collapsed group hides its triggers but may retain an active member.
3. Pinned tabs form one leading contiguous region.
4. A pinned tab has no group membership.
5. Every tab `groupId` resolves to one group.
6. Every group has at least one tab, and all members of one group are contiguous.
7. Member order is stable unless the action explicitly moves a member or its group.
8. Collapsing a group hides its member triggers without changing membership or the active tab.
9. A rejected action preserves the original state object so callers can identify a no-op.
10. A drag preview never changes the authoritative input state.

`createWorkbenchTabsState` removes orphaned group references, removes group membership from pinned
tabs, removes empty group metadata, arranges pinned and grouped regions, and resolves an invalid
active identifier to the first visible default (or the first tab when every group is collapsed).
Duplicate identifiers are not normalizable and fail immediately. After that boundary, actions
operate on a valid structural model and project the result back to the public state shape; they do
not run the normalizer after every mutation.

## State actions

The reducer owns these action families:

| Action                   | Guard                                                   | Result                                                                     |
| ------------------------ | ------------------------------------------------------- | -------------------------------------------------------------------------- |
| Activate tab             | Tab exists                                              | Set `activeTabId`                                                          |
| Insert tab               | Tab identifier is new; requested group exists           | Normalize placement, insert after pinned tabs or at group end, activate it |
| Close tabs               | At least one identifier exists                          | Remove tabs, prune empty groups, select nearest visible survivor           |
| Rename or recolor tab    | Tab exists; a label is non-empty                        | Update only that tab                                                       |
| Pin tab                  | Tab exists and is unpinned                              | Remove membership and append to the pinned region                          |
| Unpin tab                | Tab exists and is pinned                                | Insert at the start of the unpinned region                                 |
| Create group             | Group identifier is new and every selected tab exists   | Unpin selected tabs, add metadata, and make members contiguous             |
| Assign tab to group      | Both identifiers exist                                  | Unpin the tab and insert it at the approached side of the expanded group   |
| Remove tab from group    | Tab is grouped                                          | Place immediately after its former group and prune an empty group          |
| Update group             | Group exists; a label is non-empty                      | Update label and/or color                                                  |
| Collapse or expand group | Group exists                                            | Update disclosure without changing active membership                       |
| Ungroup                  | Group exists                                            | Remove metadata and membership while preserving member order and position  |
| Close or delete group    | Group exists                                            | Close every member and remove metadata                                     |
| Move tab                 | Final index is valid and inside the same pinning region | Apply order and target membership atomically                               |
| Move group               | Final first-member index is valid and unpinned          | Move the complete block without changing member order                      |

Pinning and grouping conflict by definition. An explicit pin action clears membership; an explicit
group action unpins before assigning membership. Moving an unpinned tab before the pinned boundary
or a pinned tab after it is a no-op.

## Pointer interaction state machine

The pointer interaction uses one discriminated state owned by the Workbench tab-strip adapter:

| State          | Required data                                             | Accepted events                    |
| -------------- | --------------------------------------------------------- | ---------------------------------- |
| Idle           | None                                                      | Arm tab, arm group                 |
| Armed tab      | Pointer id, source tab, origin, grab offset, source state | Move, release, cancel              |
| Dragging tab   | Armed data, preview state, source state, current pointer  | Move, release, cancel, stale input |
| Armed group    | Pointer id, group id, origin, grab offset, source state   | Move, release, cancel              |
| Dragging group | Armed data, preview state, source state, current pointer  | Move, release, cancel, stale input |
| Settling       | Final preview awaiting authoritative acknowledgement      | Acknowledge, cancel, stale input   |

The primary pointer arms on pointer down only when the event's DOM target is physically contained
by the tab or group item. React events bubbling from a portaled context menu are not eligible to
arm its trigger. Every move also reports whether the primary button remains pressed; a move after a
missing release cancels an armed or dragging state instead of crossing the threshold. Euclidean
movement below `10` device-independent pixels remains a click, so a small diagonal movement does
not accidentally start a drag. Crossing the threshold enters the matching dragging state, captures
the pointer on the stable tab strip, suppresses the following click, and emits activation. Releasing
while armed remains a click.
Releasing while dragging emits one commit and enters settling without discarding the final preview.
The authoritative topology acknowledges the commit and returns the adapter to idle. While authority
still exposes the source topology, the final preview remains rendered for any number of frames;
elapsed frames are not evidence of rejection. A change to the expected preview acknowledges the
commit, while a change to a different topology explicitly rejects it and restores authority.
Cancellation from either active state returns to idle and restores the authoritative projection.
While a drag is active, the adapter captures `Escape`
at the tab strip's owning document because pointer capture does not imply keyboard focus; the same
handler releases pointer capture after dispatching the cancel event.

When a group header crosses the threshold, an active member remains active. If the active tab is
outside the group, the first group member becomes active before displacement starts. The header is
never itself an active tab.

## Geometry, hit testing, and hysteresis

DOM hit testing is a platform capability, not domain state. When the pointer arms, the adapter
captures one strip-local ideal-layout snapshot. Each record names a tab or group header and supplies
its stable `offsetLeft` and width. Animation rectangles are never fed back into the decision model.

For each pointer move, the resolver enumerates every legal structural result: every gap inside the
current pinning region, every valid side of an expanded group, and every gap that does not split a
different group. It constructs the ideal layout for each candidate and selects the candidate whose
dragged slot is closest to the dragged surface. A group header uses the same method with the whole
group treated as one structural block. One large pointer move may therefore cross several items
without applying a sequence of DOM-relative swaps.

The current group receives a sticky distance advantage of one quarter of the dragged tab width, so
layout displacement cannot immediately eject and reinsert a tab at a group boundary. After a new
slot is accepted, another semantic crossing is ignored until the pointer moves beyond a separate
reorder margin: `16` device-independent pixels for a standard `200`-pixel tab, scaled with the
dragged width. Candidate identity and the last accepted crossing are semantic state, not DOM element
references. A missing source, removed group, changed pinning region, or lost strip cancels the
interaction.

The grouped and ungrouped candidates at a group's trailing edge may share the same rendered left
position. The resolver gives the ungrouped candidate a scoring-only anchor one half tab width beyond
that edge. Crossing the virtual anchor can therefore remove the final visible member from the right
side even when the group ends at the strip boundary; it never inserts layout space or changes the
rendered projection before the semantic candidate wins.

## Projection and rendering

The tab strip projects a visual sequence of pinned tabs, unpinned tabs, group headers, and visible
group members from the canonical state. Group headers are not tabs and do not reserve an
independent separator element. Separators are painted by item pseudo-elements and never affect
geometry.

The active, hovered, dragging, and grouped priorities are:

1. Dragging supplies an opaque overlay surface, raised stacking, and no positional transition on
   the dragged item itself.
2. Active supplies the selected surface. Beginning a tab drag activates before the first preview.
3. Group membership supplies one continuous bottom line across the expanded header, provisional
   slot, dragged member, and every visible member.
4. Hover supplies a neutral surface and suppresses both adjacent separators. Transient suppression
   of the post-drag hover surface never restores separators beneath the pointer.
5. Resting items show subtle separators without reserving width.

Tab width also selects one deterministic content presentation. Standard tabs show every available
close action. Compact tabs hide a non-active close action until tab hover or control focus. At the
icon-only boundary, the title is removed from visual layout and the semantic icon remains centered
on the tab. Hovering reveals the close control in the same centered layer above an opaque surface,
so neither the icon nor neighboring tabs move. The tab color marker is the icon-only fallback when
the model has no semantic icon.

After React commits the dragging state, the adapter clones the dragged tab or complete group into a
dedicated overlay surface and hides the source elements without removing their layout slots. A tab
clone continuously mirrors the preview tab's current group membership and line color; membership is
never frozen from the source state captured at drag start. Waiting for the layout commit prevents
group activation and overlay creation from racing when a group drag first activates one of its
members. The overlay follows the pointer above the strip with an opaque surface; it never competes
with later sibling stacking.
Before applying a preview order, the adapter captures each non-dragged item's current rectangle.
After React renders the preview, it applies the inverse delta and transitions each item to its new
slot. Reduced-motion duration resolves to the instant design token. Release commits one semantic
result, removes the overlay, and renders the final preview with the source elements until the caller
acknowledges the same topology. This prevents an intermediate render of stale authoritative props
from returning the dragged tab to its source slot. A different authoritative topology rejects the
preview; an unchanged source topology leaves it pending. The adapter suppresses only the following
click through the next visual frame. Group-header source and clone controls also clear
their pressed transform and transition while dragging, so the two layers cannot leave a stale
pressed raster behind. The armed source remains in its normal stacking and compositing layer until
the drag threshold is crossed, preventing a vertical seam from interrupting the continuous group
line while the pointer is held down.

## Scenario matrix

Core tests cover these independent decisions before browser integration:

| Dimension      | Cases                                                                                 |
| -------------- | ------------------------------------------------------------------------------------- |
| Identity       | unique, duplicate, missing tab, missing group, stale active identifier                |
| Cardinality    | empty, singleton, two tabs, multiple groups, group with one member                    |
| Pinning        | pin, unpin, reorder both directions, reject both cross-boundary directions            |
| Grouping       | create, assign, remove, final-member removal, pin grouped tab, orphan metadata        |
| Disclosure     | expand, collapse inactive group, collapse active group, all groups collapsed          |
| Closing        | inactive, active first/middle/last, bulk, group, all, pointer lock, keyboard reset    |
| Tab movement   | first to last, last to first, adjacent both directions, unchanged, invalid index      |
| Group movement | first to last, last to first, expanded, collapsed, member order preserved             |
| Gesture        | threshold, portal origin, released-button move, release, cancel, stale input          |
| Geometry       | narrow/wide tabs, exact center, multiple crossings, physical edges, group-tail anchor |
| Membership     | enter from each side, leave from each side, boundary jitter, traverse without release |
| Visual state   | active drag, compact close, centered icon overlay, group line, separator suppression  |
| Menu           | action dismissal, submenu final action, primary click-through, secondary reopen       |

Pure reducer and geometry tests own the state and boundary cases. React tests own prepared wiring,
ARIA semantics, and menu dismissal. Browser verification owns pointer capture, real geometry,
motion, stacking, click-through, and both shipped locales.

## Ownership and maintenance

`@orchbee/workbench` owns the canonical state reducer, interaction resolver, transient drag state,
and tab-strip presentation. The consuming application owns durable tab/session data, identifier and
label creation, external effects, and acceptance of semantic commits. React Hooks adapt pointer
events and layout measurement to the pure model; they do not decide ordering or membership.

Update this document whenever a public tab action, invariant, gesture phase, conflict rule, or
verification boundary changes. Every regression first adds the missing case at the lowest owning
layer, then changes integration code.
