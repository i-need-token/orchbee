# Panel 广播输入

## 契约

在同一标签页中操作多个终端 Panel 的用户可以打开一个专用广播输入条，并把实时提交文本或物理按键
敲击发送给每个显示中的终端。该模式是显式的：普通终端输入绝不被镜像，每个目标保持可见，并且输入条
会在接受输入前标明目标数量和结束会话控件。

公开 `workbench.panel.active.broadcast-input.open` Action 可通过 Action 搜索和 Panel 菜单发现。
它没有默认键盘快捷键，也不创建持久设置或存储迁移。仅当活动标签页未最大化、拥有至少两个规范
Panel 叶节点、没有冲突的 Panel 交互，且每个叶节点显示中的 Presentation 都处于 `running`
并拥有一个已挂载且写入就绪的终端 sink 时，该 Action 才可用。

目标快照恰好包含规范深度优先 Panel 叶节点顺序中每个叶节点的一个显示中 Presentation，并包含
此前聚焦的 Panel。隐藏的主或子 Presentation、其他标签页、其他原生窗口、远程客户端，以及未挂载
或只读表面绝不属于目标。

## 领域模型

| 类型                           | 含义                                                                |
| ------------------------------ | ------------------------------------------------------------------- |
| `PanelBroadcastTarget`         | 一个精确 Panel ID 及其显示中的 Presentation ID                      |
| `PanelBroadcastTargetSnapshot` | 启动时捕获的活动标签页 ID、源聚焦 Panel ID 和唯一有序目标           |
| `PanelBroadcastInput`          | 非空提交文本，或一项带精确修饰键事实且与目标无关的物理按键敲击      |
| `PanelBroadcastInputEnvelope`  | 一个会话内单调递增的输入 ID 及其输入                                |
| `PanelBroadcastSessionState`   | `idle`、带不可变快照和 FIFO 的 `active`，或带非敏感通知的 `stopped` |
| `PanelBroadcastCommand`        | 分发精确队首，或恢复精确源终端焦点                                  |
| `PanelBroadcastTransition`     | 完整下一状态、可观察结果和零条或多条命令                            |

DOM 键盘、组合输入、input、粘贴、焦点与失焦事件是不可信的展示输入。广播输入条会在领域边界前
对其规范化。组合输入更新绝不成为输入；只有最终组合提交会成为输入。剪贴板粘贴、文件拖放、鼠标
输入、空文本、未知按键与操作系统 Meta 组合键都会被消费，且不产生广播命令。

瞬态 FIFO 可能包含终端内容，因此绝不持久化、记录日志、包含在 Action 观测中、复制进停止通知，
也不投影进共享文档或 Client View 状态。关闭或使会话失效会清除全部排队载荷。

## 启动决策

| 条件                                                                   | 结果                                       |
| ---------------------------------------------------------------------- | ------------------------------------------ |
| 没有活动标签页、少于两个 Panel 叶节点或存在最大化                      | 不可用                                     |
| 可视选择、调整尺寸、关闭确认、拖动或另一广播会话处于活动状态           | 不可用                                     |
| 任一显示中 Presentation 不处于 `running`、缺少已挂载 sink 或写入未就绪 | 不可用；不会创建部分目标集合               |
| 规范顺序中存在重复 Panel 或 Presentation 标识                          | 作为无效快照而不可用                       |
| 每个精确目标都符合条件                                                 | 以空 FIFO 和可见输入启动一个 `active` 会话 |

启动是该 Action 执行的唯一会话状态提交，不会发送终端输入。Action 会在提交前立即重新校验全部
条件，并且只有活动会话已经存在后才把 Action 标记为已提交。上下文 Panel 目标必须仍然存在，
但快照的源焦点始终是活动标签页真正聚焦的 Panel；辅助指针菜单调用不会静默变成后续焦点恢复的所有者。

## 转换

| 状态与事件            | 守卫和结果                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `active` + 输入入队   | 分配下一个输入 ID 并追加。当没有输入正在处理时，为队首发出一条分发命令。                                                       |
| `active` + 切换可见性 | 只改变本地输入可见性。投递目标、FIFO 和载荷保持不变。                                                                          |
| `active` + 投递完成   | 只接受精确 epoch 和队首 ID。完整目标成功会移除队首并分发下一项。缺少任一目标会进入 `stopped`、清空 FIFO 并报告可能的部分投递。 |
| `active` + 显式结束   | 进入 `idle`、清空 FIFO、使工作流 generation 失效，并在源终端仍是当前焦点所有者时恢复它。                                       |
| `active` + 目标失效   | 进入 `stopped`、清空 FIFO、使 generation 失效，并报告目标集合已在接受后续输入前变化。                                          |
| `stopped` + 关闭通知  | 进入 `idle`，且不发送输入。                                                                                                    |
| 任意状态 + 过时完成   | 忽略 epoch 或输入 ID 不指向当前队首的完成。它不能关闭、推进或使更新的会话失败。                                                |

输入协调器串行化 envelope。每次 fan-out 前，它都会重新解析活动标签页、规范目标快照、
Presentation 生命周期、sink 成员关系和写入就绪状态。预检失败时不会开始任何目标发送。预检成功后，
所有精确目标都会把各自捕获的 sink 修订作为 compare-and-send 守卫并发开始发送，并且当前 envelope
的每个结果落定之前不能开始下一项。

## 不变量与所有权

- 活动快照至少包含两个目标；Panel ID 和 Presentation ID 各自唯一，且顺序等于规范深度优先
  Panel 顺序。
- 至多一个 envelope 正在处理，每个目标观察到的已接纳 envelope ID 都遵循 FIFO 顺序。
- 完整完成要求每个目标都报告 `sent`；空目标或缩减目标集合绝不能报告为成功。
- 结束、失效、部分失败、卸载或处置会阻止所有后续排队 envelope 启动。已经开始的目标发送仍不可撤销。
- 输入可见性绝不改变投递。`Ctrl+Alt+Escape` 切换可见性，`Ctrl+Escape` 结束会话，
  未加修饰键的 Escape 是广播按键。
- 活动期间，输入条拥有键盘焦点，Panel 目标 shield 拥有指针命中测试。Workbench 快捷键和普通
  终端 DOM 输入无法观察广播按键。
- `@orchbee/workbench` 是会话状态、目标成员关系、FIFO 顺序、通知和焦点恢复命令的唯一写入者。
- 每个注入终端表面拥有当前写入就绪状态、针对目标的修饰键与 Option-as-Alt 解释、语义按键发布、
  capability revision 和传输结果。Workbench 绝不构造 Host 协议命令。
- Terminal Host 仍对 VT 模式编码和 PTY 写入负责。本变更不增加 Host 协议、进程、网络、远程控制
  或持久文档写入者。

## 失败、投递与恢复

多 PTY 投递不是原子的。同步拒绝或异步传输失败可能发生在另一目标已接纳同一 envelope 之后。
协调器等待有界 fan-out 落定，进入 `stopped`，报告目标总数中已知接纳该 envelope 的目标数量，
并说明其他终端也可能已经收到它。它绝不重试、补偿、回滚或重放 envelope。

目标失效与显式结束会阻止后续输入，但无法收回已经开始 fan-out 的 envelope。重新打开会使用全新
目标快照创建新的 epoch；旧 epoch 的迟到结果不会产生作用。

该功能以仅限活动标签页的瞬态能力交付，没有迁移或兼容别名。回滚会一起移除 Action、Workbench
会话/输入条及注入表面 sink。此前已经投递的 PTY 输入不属于回滚范围。

## 参考与验证

参考是 Kitty 修订版 `6d5d0c440603ad9bdf6dcd599f73f6dde21acb44` 的
`docs/kittens/broadcast.rst`、`kittens/broadcast/main.go` 和
`kitty/rc/send_text.py`。Orchbee 采用专用实时输入表面、文本与非文本按键 fan-out、
`Ctrl+Escape` 结束、`Ctrl+Alt+Escape` 可见性切换，以及把专用输入表面排除在终端目标之外。
Orchbee 用不可变的活动
标签页快照、精确已挂载 sink 预检和可见部分投递失败，取代 Kitty 的动态全窗口匹配与不报告失败。
Kitty 远程控制、匹配表达式、跨标签页或窗口目标、非聚焦光标渲染、初始命令参数、粘贴、文件、历史
和重放均不在范围内。

| 声明                                                           | 可执行证据                                                                 | 限制                                                               |
| -------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 快照成员关系和启动资格精确                                     | 解析器示例和固定 seed 生成的嵌套布局                                       | 生成布局和已挂载 sink fake                                         |
| FIFO、失效和过时完成保持会话所有权                             | 纯转换示例、有状态属性测试和 `PanelBroadcastInputCoordination` TLA+ 不变量 | 固定属性 seed，以及有界 TLC 标识、epoch、目标和输入                |
| 完整成功要求每个目标；部分投递会停止且不重试                   | 使用受控完成顺序的协调器测试和 TLA+ 部分子集                               | 传输接纳无法证明子进程消费                                         |
| DOM 输入细化为提交文本或一次物理按键敲击                       | 规范化器测试和确定性 Chromium 系统轨迹                                     | 其他浏览器引擎和操作系统保留快捷键不在范围内                       |
| 焦点、目标 shield、可见性控件、Action/菜单路径和本地化通知一致 | React 集成、双语言 Story 和受控三 Panel 浏览器轨迹                         | 像素一致性、compositor 时序和手工 native-window 焦点测试不在范围内 |
| 采用的 Kitty 行为仍映射到自有契约                              | 编码为确定性 Orchbee 契约测试的固定源码场景                                | 不声明源码、远程控制、匹配器或像素一致性                           |

TLA+ 检查一至三个排队输入、二至三个目标、两个会话 epoch、完整与部分完成、显式结束、失效、
重新进入和过时完成。弱公平性只用于活动工作流已接纳的分发与完成；该模型不证明传输可用性、
PTY 消费、无界队列或操作系统故障恢复。

模型中的抽象 `partial-delivery` 原因合并所有已落定但并非全目标成功的结果。接纳数量为零时细化为
具体的 `delivery-failed` 通知；非空真子集则细化为具体的 `partial-delivery` 通知。`Dispatch`
从协调器已经发出全目标 fan-out 之后开始；受控 `Promise.all` 协调器测试是每个预检目标发送都在
落定前启动的细化见证，因此 TLA+ 不再复制一份 attempted-target 集合。
