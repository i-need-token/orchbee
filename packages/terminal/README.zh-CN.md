# @orchbee/terminal

其权威 VT 状态位于 Orchbee Terminal Host 的终端的源中立浏览器客户端界面。

## 适用范围

该软件包拥有一个投影终端表面：

- 原子打包帧提交和快照恢复；
- WebGPU 使用 Canvas 2D 后备进行渲染；
- 有界历史窗口呈现；
- 客户端搜索和有界逻辑线链接发现；
- 当前有界语义命令完成元数据；
- 主机拥有的选择交互和副本关联；
- 键盘、提交的文本、IME、鼠标、焦点、粘贴、调整大小、清除和重置意图；和
- 可见视口可访问性。

它绝不接收或解析 PTY 输出，不加载 VT 引擎，也不公开 `write(ptyBytes)`。Terminal Host 拥有 PTY、Ghostty VT 状态、终端模式、保留历史、选择端点及依赖模式的输入编码。应用拥有传输、终端清单、产品拓扑、剪贴板效果、外部导航及本地化产品 UI。机器可读的范围契约见 [`project.json`](project.json)。

已接受的 [投影终端体验兼容性提案](../../proposals/terminal/projected-terminal-experience-compatibility.md)定义剩余的跨所有者恢复契约；它不是当前运行时权威。

打包的元数据仅携带最新的可选命令完成序列、持续时间、完成时间戳和从主机帧解码的标准化退出代码。该包既不解释 Shell 输出，也不拥有提醒策略、通知权限、焦点规则、新鲜度、重复数据删除、速率限制或产品副本。投影缓冲区输入没有完成事实；快照和增量输入保留严格解码的可选值。

`clear()` 和 `reset()` 是语义主机请求。 `clear()` 擦除活动屏幕并将其光标归位，同时保留终端模式。 `reset()` 首先修复客户端拥有的合成、按下输入、选择、搜索、悬停和历史视口状态，然后要求主机执行 Ghostty 的完全重置。这两种方法都不会注入终端转义字节或重用投影 `store-reset` 恢复。

输入修复将原生输入法组合生命周期与本地提交资格分开。活动组合可能具备资格，也可能已经取消但浏览器仍欠终端一个 `compositionend`。reset、文本区域 blur、窗口 blur、文档进入隐藏状态和处置都会立即清除文本区域与渲染器预编辑，撤销提交资格，并清除按键、组合、`beforeinput`、`input`、粘贴和鼠标关联记录。对于无法提供可用 `beforeinput` 载荷的浏览器与 IME，已提交的 DOM `input` 事件用作后备；其 textarea 值只消费一次，随后清除。迟到的组合更新，以及迟到的 `beforeinput`/`input`/`compositionend` 顺序，都不能重新发布预编辑或文本；它们只会结束已取消的本地工作。即使旧 `compositionend` 从未到达，新 `compositionstart` 也会取代已取消工作。重新聚焦、非组合按键或独立的非组合 `beforeinput` 也能恢复本地推进，无需等待旧组合结束。对于未取消的组合，无论浏览器按何种顺序发出 `beforeinput`、`input` 与 `compositionend`，文本最多提交一次，且状态转换在同步命令端口发送前完成。macOS `keyCode=229` 路径会推迟暂时独立的 `beforeinput` 文本，直至原生 textarea 值稳定，从而保留 IME 生成的标点，而不是发布物理 ASCII 按键。未修饰的标点和数字按键也会让原生文本区域优先处理，使第三方 macOS 输入法能够发布全角标点；若 30 毫秒内没有原生值到达，则把原始 ASCII 字符作为确定性后备发送。原生结算使用同一有序输入调度器：中间的按键、粘贴或指针输入会先封存当前原生批次，再准入后续输入，因此延迟的数字或标点无法越过后续物理按键。相同的短期结算标记也处理原生 `input` 先于 `keydown` 到达的浏览器事件顺序。

在 macOS 上，投影终端还使用源中性 Option-as-Alt 模式：`off`、`left`、`right` 或 `both`。它跟踪来自 `AltLeft` 和 `AltRight` 的物理选项侧，解析每个已承认的关键事件的一个布尔语义意图，并实时更新该模式，而无需重新创建终端。它永远不会在提交的文本前面加上 Escape。 Terminal Host 消耗事件意图并继续拥有当前终端模式的实际 Ghostty 键盘编码。

实时预编辑是一种可逆的演示，从投影的主机光标开始，并在可见网格中按行优先顺序换行。窄单元格和宽单元格保持原子性，超出最后一个可见行的溢出将被剪切，而不会滚动或改变主机状态，并且隐藏的本机输入锚点遵循定位帮助器堆叠上下文内的相同包装插入符，因此平台 IME 候选窗口保持对齐。

普通去重记录都是一次性的。第一次 `beforeinput` 检查会消费之前的按键记录，即使二者不匹配；匹配的组合、`beforeinput` 及相反来源的粘贴检查也会消费各自记录。其时间窗口严格小于 100 毫秒。已取消或被取代的组合使用独立结算守卫，修复不会将其清除。只有由 `isComposing`、`insertCompositionText` 或 `insertFromComposition` 标识的组合来源 `beforeinput` 才会消费该守卫；后来具有相同文本的独立 `insertText` 不会被抑制。组合来源的特殊 input 类型会在粘贴、换行或删除处理前判定，因此已取消原生工作无法进入这些分支。由于浏览器事件不提供组合标识，新的 `compositionstart` 会建立下一个组合事件的所有权，并取代所有尚未结算的旧原生工作。

最后一次鼠标释放和每次修复都会清除保留的鼠标样本。修复会关闭本地输入准入门，并在清除所有权或调用任何可能同步发送命令的辅助函数前启动清理事务。输入处理器还会为历史恢复、选择清除和焦点报告保留修复纪元；先关闭、随后重新开放准入的修复会让旧延续失效，阻止它发布按键、预编辑、文本、鼠标输入或过时关联。组合文本提交还会保留精确的已暂存输入状态标识，因此同步发送返回后，不能清除由可重入修复及更新组合所安装的文本区域或预编辑状态。

普通承认的输入在一代调度程序内保留为 FIFO，包括在粘贴审核待决时。生命周期修复会在快照清理之前关闭准入并使该生成无效，因此重置、模糊、可见性损失和处置无需等待可能永远不会解决的粘贴审查。排队的命令和迟到的审查决议或来自无效一代的拒绝是可以观察到的，但是惰性的。新开的一代在修复后独立进展。

粘贴检查会在用空格替换不安全的 C0/C1 控件之前保留原始文本，并检测原始文本中嵌入的括号粘贴终止符。没有括号保护、替换控件和嵌入式终止符的多行文本需要应用程序拥有的本地化审阅界面；批准仅发送经过净化的文本。该评论快照了预计的括号粘贴模式，并通过语义输入承载了该期望。 Terminal Host 将其与权威的 Ghostty 模式进行比较，同时保持终端锁定，并且仅在完全匹配时进行编码；不匹配会拒绝粘贴，而不会进入队列或自动重播，因此可以根据当前状态检查新粘贴。当承认的剪贴板事件没有纯文本但包含图像项目时，适配器会保持系统剪贴板不变，并准确地发出一个合成的 Control+V 按下/释放对。这符合代理粘贴约定，无需读取图像字节、创建文件或检测特定代理。当文本和图像项目同时存在时，纯文本仍然具有权威性。

适配器跟踪承认的所需所有权与已发布到主机的所有权分开。物理按键和指针按钮是永久所有权；合成 `beforeinput` Enter/Backspace/Delete 命令和滚轮按钮 4/5/6/7 报告是无状态的，并且永远不会进入持有的分类帐。适配器在任何同步边界之前暂存本地所需状态，在一个发布门下调用命令端口，并仅在 `port.send` 同步返回后提交主机发布的所有权。该调用期间的生命周期回调将被合并，直到知道结果为止。同步抛出是现有的浏览器适配器预接受失败边界：失败的按下回滚其本地所有权和相关性，而失败的发布或焦点保留保留已知的主机所有权以供以后修复尝试。返回的 Promise 可能仍会诊断性地拒绝，但同步返回会记录本地传输接受情况，并且不会声明有关远程传送的情况。

每个物理指针按钮在按下时都会快照其所有者：除非按住 Shift，否则当前 Host 投影的鼠标跟踪拥有该按钮；其他情况则由终端选择或链接交互保留。后续修饰键或投影模式变化不能转移由应用拥有的按下。应用拥有的按下会捕获指针，只从应用拥有的按钮账本派生拖动状态，并可在 Canvas 外正常释放。无按钮移动、pointer cancel 或 lost capture 会先为每个已准入或已发布到 Host 的应用按钮排入一次语义释放，再清除捕获，因此后续生命周期修复不能重复释放。投影任意鼠标跟踪模式时，本地链接查找与激活都要求 Shift；激活会在点击时重新检查该条件，已完成的应用拥有主按钮按下也不能激活过时链接。每个滚轮事件的所有权仍是无状态决定。应用拥有的滚轮输入会依据投影单元格与网格尺寸规范化 pixel、line 与 page delta，按轴独立累计不足一个单元格的移动，并先报告垂直按钮 4/5 步，再报告水平按钮 7/6 步。Shift 会绕过应用鼠标所有权。在主屏幕上，规范化垂直步进用于导航有界保留历史；在备用屏幕上，可写输入会将其映射为对应的语义 Arrow Up/Down 点击。只读备用屏幕消费垂直滚轮输入而不发出 Host 输入；只有水平方向的本地滚轮输入仍由浏览器拥有。

画布指针使用相同的所有权策略，而不是独立的仅链接样式。固定的应用程序拥有的手势和未修改的投影鼠标跟踪使用默认指针；终端选择使用文本指针；矩形选择在 Apple 浏览器平台上使用带有 Option 的十字准线，或者在其他地方使用 Alt + Control/Meta；并且，启用的、允许的链接仅在终端交互拥有指针时才使用指针光标。投影模式提交、修改器更改、手势转换和链接呈现都会重新评估此策略，因此清除链接会恢复派生的基指针，而不是空的 CSS 覆盖。

浏览器按键规范化会把旧版 `OSLeft`/`OSRight` code 映射到 Ghostty 的 `MetaLeft`/`MetaRight`，识别完整 W3C key 字符串而非计算 UTF-16 代码单元，并且只有事件携带可打印文本、且已消费修饰键为活动修饰键的子集时才记录后者。按键发布只用持有所有权识别物理按键；已发布的右侧修饰键从浏览器拥有的跟踪中移除后，其文本、修饰键及已消费修饰键字段取自当前 `keyup`。若 `keyup` 重入同步输入发布，则推迟到所属按下操作结果确定，或由并发生命周期修复一并处理，避免已发布按下失去对应释放。应用与终端语义快捷键均有机会捕获后，未被声明的 Apple Command 修饰按键交给 Browser/Electron 原生处理；它既不作为终端输入发布，也不会通过按键名称允许列表被取消。合成的 Enter、Backspace、Delete 及备用屏幕方向键输入使用与成对按下/释放相同的预留发布路径。它们不保留稳态客户端所有权，但按下与释放之间的传输丢失对 Host 附件账本仍然可见，以便在分离时修复。

仅 Shift 的 Page Up 和 Page Down，包括其键盘代码，仍保留本地保留历史导航，并且永远不会成为主机键输入。除无按键的应用鼠标移动外，每个已准入的输入生成路径共享一个有序的表面转换：当历史记录可见时，它首先请求实时底部，然后清除活动的主机选择，然后才发布语义按键或重复、文本、批准的粘贴或应用程序鼠标输入。由任意事件鼠标跟踪准入的无按键移动报告仍会发布到 Host，但会保留当前的历史位置与活动 Host 选择。合成激活在呈现预编辑之前执行相同的转换。物理或合成按键释放会关闭现有的主机输入所有权，而不启动该转换，因此在其按下和释放之间建立的选择仍然可见。焦点报告、生命周期和指针手势修复、拒绝或中止粘贴审查以及本地历史记录导航可保留当前历史记录和选择表面。

`terminal-parity/IN-07-pre-input` 在保留历史与 Host 选择均处于活动状态时，通过有界面 Canvas 表面驱动一个真实的无按键 `PointerEvent`。它要求只产生一条应用鼠标移动报告，不产生回到底部或清除选择命令，并保留可读取的选择。同一轨迹随后合成窗口焦点丢失并折叠真实的无障碍 DOM Range；此时不发布 Host 选择清除命令，可读取的 Host 选择仍保持活动。所有者本地回归覆盖这两种修复，同时保留既有的鼠标按键按下转换要求。

清理只释放已经发布的所有权：排队的释放不能掩盖 Host 可见的按下；排队或失败的按下也不能产生孤立释放。blur 与可见性丢失会按按下顺序分别释放一次已发布按键和鼠标按钮，随后只有当本会话发布过 focus-in 时才发布 focus-out。处置会永久关闭准入并遵循相同顺序；若已经失焦则省略 focus-out。每条处置清理命令只尝试一次；同步失败会被报告并保留为已知所有权，但 DOM 与监听器移除后无法再重试拆卸。reset 本身不要求 focus-out，并会保留焦点。如果 reset 使排队或失败的 focus-in 失效，替代生成会在后续按键或鼠标发布前尝试焦点协调；同步协调失败仍可由下一项输入重试。投影终端把隐藏 textarea、无障碍后代及挂载在同一根下的应用自有控件视为一个焦点边界。在该边界内移动既不修复输入，也不重复焦点报告；离开边界时先释放已发布的按键与鼠标所有权，再发送一次 focus-out；从非 textarea 后代进入时则发送匹配的 focus-in。何时调用 `focus()` 由应用决定；打开包提供的表面不表示取得初始产品焦点。Desktop 与手写笔指针在 pointer down 时聚焦隐藏 textarea。触摸指针处理会在非 passive Canvas `touchend` 上阻止原生兼容鼠标与 caret 行为，随后聚焦 textarea；可写 textarea 会打开移动虚拟键盘。仅触摸激活不会发布 PTY 输入，并保留 Host 选择。由此产生的 `beforeinput` 与组合事件使用和其他浏览器输入相同的共享输入前转换及恰好一次去重；只读附件仍可聚焦，但不准入移动端文本。每条原始输入、按键、已提交文本、粘贴、应用鼠标、焦点和修复命令都携带当前正数附件能力修订。直接构造默认使用初始修订 `1`；Desktop 与 Gateway bootstrap 转发 Host 返回的修订。`applyInputCapability` 只接受精确附件与终端标识、精确重放，或输入值已变化的下一个单调修订。过时修订为空操作；标识不匹配、同修订冲突、跳过修订，或修订已变化但权限未变化时，都会失败关闭为只读。降级会使调度器生成失效，并立即清除组合、原生文本结算、粘贴审核、持有的按键/鼠标/焦点所有权及指针捕获，但不发送会重复 Host 修复的客户端释放。升级会移除原生只读守卫，但不恢复先前输入或排队工作；下一项获准输入只带新修订标记。如果投影客户端在清理完成前消失，Terminal Host 会在撤销其能力前，只释放该附件已经接受的按键、应用鼠标与焦点所有权；其他附件不受影响。

模糊、可见性丢失或在重置暂存或发送清理时重新进入的处置会合并到同一事务中； 该事务在重新开放准入或处理之前会耗尽按键释放、鼠标释放和任何新需要的焦点。 主机重置遵循替换调度程序生成中的清理操作。 当前一代DOM粘贴审查拒绝通过现有命令错误通道报告，并且不会阻止后续输入； 来自无效一代的拒绝仍然是惰性的。 版本化的成熟相关跟踪及其固定源修订版作为严格解析的、数据驱动的重播输入维护在 [`docs/input-repair-conformance-v0.0.1.json`](docs/input-repair-conformance-v0.0.1.json).

`ProjectedTerminal` 恰好代表一个附件。项目、工作区、选项卡、面板和可见性策略仍位于此包之上；隐藏终端不需要实时渲染器表面，并且投影/历史需求可以独立于主机运行时而暂停。

主机铃声效果通过 `ProjectedTerminal.onBell` 作为附件范围的单调事件到达。该包抑制陈旧或重复的序列，但不执行任何声音或视觉效果；嵌入桌面或浏览器应用程序拥有该策略。

有界面 `terminal-parity/PR-11-bell` 见证由三个真实 Canvas 2D 投影表面组成，它们具有不同附件标识并共享一个 Workbench 响铃协调器。该见证证明：重复序列只产生一次效果；不同的交错序列会被接受；附件重连后会抑制旧序列；声音与通知拥有相互独立的失败边界。受控夹具不要求原生音频输出、操作系统通知送达、WebGPU 或跨浏览器行为。

## 安装

```sh
pnpm add @orchbee/terminal
```

## 使用

调用者提供不透明的主机身份、本地化的可访问性标签和传输中立的命令端口。二进制帧和行窗口有效负载的转发无需 VT 解析或每单元代理重建。

```ts
import { ProjectedTerminal } from '@orchbee/terminal';

const terminal = new ProjectedTerminal({
	attachmentId,
	capabilityRevision: '1',
	creationId,
	hostEpoch,
	terminalId,
	canResize: true,
	labels: {
		input: i18n.t('terminal.input'),
		screen: i18n.t('terminal.screen'),
	},
	port: {
		send: (command) => hostConnection.send(command),
	},
});

terminal.onRendererHealth((event) => rendererDiagnostics.record(event));
terminal.onFrameTelemetry((frame) => rendererMetrics.record(frame));
await terminal.open(document.querySelector('#terminal')!);

hostConnection.onFrame((frameBuffer) => terminal.applyFrame(frameBuffer));
hostConnection.onRows((rowBuffer) => terminal.applyRows(rowBuffer));
hostConnection.onTerminalExited((event) => terminal.notifyExited(event));
```

必须在创建附件之前启动可视终端的应用程序可以调用 `measureMountedTerminalGeometry(root, configuration)`。帮助器等待配置的面，并使用与第一个投影表面相同的字体规格、填充、完整单元格网格、所有者文档 DPR、协议边界和 PTY 像素限制。当元素没有正面安装的内容框或填充消耗网格时，它返回 `undefined`；调用者再次观察表面，而不是替换超时或默认几何图形。用于此测量的配置必须保持用于打开投影渲染器的初始配置。

打开表面时，会先等待配置字体中的代表性拉丁、CJK、emoji 与 Nerd Font 字形就绪，再安装帧、渲染器、输入、调整大小及无障碍处理，最后激活投影需求。每次打开尝试都以事务方式拥有 Canvas、输入、无障碍节点、渲染器、观察器及监听器：设置失败只移除这些资源，并让同一实例返回 `constructed` 以便重试；重复打开会被拒绝且不改变当前表面；处置仍是最终状态。包默认使用浏览器通用 `monospace`；应用可提供预置产品字体。Orchbee 的共享 Web/Desktop 应用会在打开表面前注册固定且与 Ghostty 对齐的主字体与符号后备字体，不依赖机器上已安装的字体。调整表面大小时会从可用网格中扣除计算出的内边距，保留既有的两列最小值；若内边距耗尽任一内容维度，则不建议新的 PTY 几何。平衡内边距仍是可选行为。测得的调整大小请求会先于活动投影需求发送；只有它与最近一次 Host 提交几何一致，或仍处于短暂的观察器重入窗口内时，才会去重。Host 几何变化、Broker 拒绝、传输失败或后续未变化的观察结果，都会使该建议可以重试。隐藏 IME 控件使用相同字体并跟随投影光标，让原生候选窗口保持对齐。设备像素比变化会重建渲染器几何与终端像素尺寸，而不留下过时图集。帧会提交到按有界行分区的结构化数组存储中，且只在安排绘制后才确认。`FrameApplied` 确认客户端已提交，而非绘制已完成。精确重复帧会被再次确认；标识、序列、生成、尺寸无效或增量基准错误的输入会请求完整快照，但不改变已提交网格。

当字体或 GPU 初始化仍处于挂起状态时到达的有效帧仍然是单个提交的打开帧。它的 `FrameApplied` 确认将被保留，直到渲染器准备就绪允许绘制该提交；然后初始化在确认之前安排保留的帧。处置会清除待处理的确认，而不是从已停用的表面发布它。

每个已打开表面都会观察其容器并调整本地内边距、渲染、指针及隐藏输入的几何，即使它只是调整大小观察者而非租约所有者。只有持有当前调整大小所有权的表面才能把该测量转换成 Host 调整大小请求；观察者继续使用 Host 的规范帧几何，绝不会把局部裁剪重新解释成相互竞争的 PTY 几何。`setResizeOwnership` 应用附件作用域的 Broker 事件。升级会清除调整大小去重状态并立即测量现有表面，因此取得所有权无需重新打开附件。

开放附件接受一笔完整的 `TerminalPresentationConfiguration` 交易，其中包含 `fontFamily`、`fontSize`、`fontWeight`、`fontWeightBold`、`fontLigatures`、 `fontMetricModifiers`、`paddingBalance`、`allowTransparency`、`backgroundOpacity` 和 `defaultColorOverride`。覆盖是 `null` 或严格的标准化小写 `#RRGGBB` 前景/背景对。 `backgroundOpacity` 是源中立的 `0..1` 配置值；撰写客户端将其应用到其自己的默认背景根而不是终端表面。对于不参与主机运行时主题事务的客户端，覆盖仍然是源中立的兼容性投影。 Orchbee 的共享 Web/桌面组合始终将其设置为 `null`；它的浅色、深色和自定义选项成为完整的主机拥有的终端主题。没有运行时部分设置器。 `updatePresentationConfiguration` 验证并隔离整个候选者，等待其常规和粗体字体描述，然后在发布任何字段之前准备渲染器测量。请求是最新的胜利：被取代或处置的准备返回类型化取消，并且验证、字体或渲染器准备失败使先前的配置可见。

一次成功的本地提交将替换所有十个字段，重新测量一次，重置字形图集一次，使整个表面无效，并安排一次当前重新绘制。同一提交重新对齐隐藏的文本区域和活动的 IME 预编辑锚点，使几何相关的链接悬停无效，修复本地几何手势而不引入复制效果，并使用当前设备像素比计算最多一个新的调整大小建议。打包行、主机选择、搜索、历史记录、可访问性行和 DOM 选择、附件身份、订阅和后端保持不变；附件和包装存储不会重新打开或重置。主机调整大小完成通过现有的调整大小路径异步继续。因此，提交后渲染或调整大小失败会保留已提交的呈现并遵循现有的类型化恢复。隐藏或暂停的表面保留新的配置，并在演示恢复时绘制一次。

运行时终端颜色与客户端覆盖使用彼此独立的修订屏障。组合客户端在请求 Host 变更前，使用一个操作标识与完整覆盖快照调用 `prepareThemePresentation`。该操作活动期间，帧会被确认到私有打包存储，而不替换可见存储。只有暂存帧携带由 Host 分配的精确 `themeRevision` 时，`waitForThemePresentation` 才就绪；遇到更高修订会失败，而不会猜测它属于哪个快照。同步执行 `canCommitThemePresentation` 预检后，`commitThemePresentation` 在一次客户端提交中交换暂存存储与已准备的渲染器覆盖/光标。元数据监听器与绘制只有在交换后才能观察新修订。被取代、处置、渲染器准备失败或显式中止时，会丢弃或隔离未发布暂存状态，继续显示先前完整呈现。隐藏、暂停或保留历史状态的表面会延迟准备，然后在实时呈现恢复时只显示最新且合格的完整修订。

主机驱动的帧几何结构，包括终端发起的 80/132 列转换，直接更新打包存储和渲染器。应用该快照永远不会发出反向 `ResizeTerminal`；只有测量的容器或设备像素比更改可能会请求新的附件大小调整。

文档可见性和显式呈现需求共同暂停渲染器动画和排队绘制工作。隐藏的提交仍然前进并承认拥挤的商店；变得可见会安排一次最新提交状态的绘制，而不是重播过时的目的地。

`freeze()` 是应用程序恢复切换：它取消输入、面向传输的侦听器、动画、调整大小、搜索和飞行中的副作用，同时保留最后绘制的画布和可访问的行列表。冻结的实例拒绝进一步的框架和命令工作。稍后的 `dispose()` 会在应用程序绘制替换后释放保留的渲染器资源和 DOM。

`notifyBrokerFailure` 保留代理的类型代码、语义操作、可重试性、可选主机相关性 ID 以及 `onError` 上的可选客户端请求序列。它还应用所拥有的结果：调整大小拒绝重新接纳未更改的几何图形，历史拒绝完成或修复确切的行请求，选择拒绝释放手势调度，在修复后吸收回流过时的手势拒绝，并且相关复制或链接失败仅完成该副作用。该包永远不会将可重试性转变为自动重播。

渲染器直接消耗打包行。它永远不会重建本地 VT 状态或每单元对象图。绘制完成后，帧遥测记录从可见打包存储中读取的确切提交的主机生成和修订。多个提交可能合并在一个动画帧后面；该检查点命名实际绘制的最新提交，而不是较早计划的修订。

已提交的实时帧元数据将可选的关闭活动扩展映射到 `idle`、`active` 或 `unknown`；缺失、重复和格式错误的载荷会保守解析为 `unknown`。历史行窗口没有实时进程观察，因此保留历史呈现会保留最新实时存储的关闭活动，同时使用历史窗口提供视觉元数据和行。已接受的非焦点按键、文本、粘贴、鼠标或等效原始输入会立即使最新观察失效，并同步发布瞬态 `unknown`；仅焦点输入和同步遭拒的发布不会如此。该覆盖在保留历史、暂存帧、快照请求、失败及处置期间始终具有权威性。新到达的 `idle` 帧可能早在该输入前便已进入在途状态，因此客户端针对其精确序列发送 `NeedSnapshot(activity-stale)` 而非 `FrameApplied`，并保留 `unknown`。下一份完整快照在因果上晚于输入失效，但不证明 Host 接受了输入，也不证明 shell 消费了输入。在协议 `0.0.18` 下，Host 接受的非焦点输入会立即使 Host 缓存失效，而后续当前状态采样可以报告 `active`、`idle` 或 `unknown`。因此，因果上合格的替换帧可以在同一终端生命周期内恢复新鲜的 `idle`。过时的主题暂存帧会在应用时被围栏，不能让暂存阶段就绪；只有因果上合格的暂存帧在其保守呈现实际提交后才会清除本地覆盖。

已提交的实时帧还可以携带有界 Kitty 图形扩展。图形快照会原子替换已解码的内存图像资源与放置位置；只有相对于确切的已提交图像修订，才会接受仅更新放置位置的操作。无效字节或缺失的资源引用会拒绝整个终端帧，并在部分提交文本或图形前请求新快照。渲染器在指针事件透明的覆盖 Canvas 上呈现受支持的 `z >= 0` 放置位置；每个图像代次只转换一次原始灰度/灰度-alpha/RGB/RGBA 像素，并复用该光栅完成裁剪、缩放和移动。空快照、删除、重置、历史呈现和处置都会清除像素与 DOM 资源。该包不解析 PNG、不加载路径或 URL、不持久化图像，也不实现虚拟、负 z、字形或动画图形。

默认情况下，行窗口输入被严格解码。仅当应用程序适配器拥有不可变、同一用户、功能范围的 Terminal Host 传输时，应用程序适配器才可以设置 `projectionBufferTrust: 'local-host'`。该路径保留 OBPB format-`0.0.2` 缓冲区并创建类型化数组视图，而无需重新扫描或重新打包每个单元格。网关、网络、插件和持久输入必须保留默认的 `external` 行为。

## 历史记录、搜索、选择和链接

跟随底部时只保留当前的打包网格。进入历史记录会暂停实时投影，并提交一个有界行窗口；其首行是可见逻辑顶部，并带有限的向前过扫描。`RowsApplied` 允许 Host 固定该顶部；只要锚点仍然有效，导航与回流刷新就使用已提交的原点，并以返回的行窗口起点为权威。当较新的回流事件取代正在进行的视口读取时，该读取完成只会结算旧请求；可读窗口保持可见，而一次事件驱动刷新会使用最新代次、修订和已提交固定点，不向用户呈现已经过时的失败。被取代的后台行读取同样会结算其有界陈旧结果，而不显示用户可见的历史错误。清除、屏幕替换、驱逐或其他任何使锚点失效的事件都会恢复底部投影，并由新快照替换最后一个可读历史窗口。

由滚轮触发的历史导航会为每个新提交的 Host 行窗口呈现一项客户端自有、可逆的 Canvas 事务。它在替换绘制前快照之前已提交的 Canvas，把位移限制在一个可见视口内，并通过固定的 100 毫秒指数运动收敛到规范 Canvas。新的导航意图会先取消旧事务，再开始下一个已提交方向。减少动态效果偏好、文档或投影暂停、Presentation 几何变化、无法捕获或调度帧、渲染失败、冻结及处置，都会移除快照，并让已提交 Canvas 保持在规范位置。通过 API 发起的行/页/底部导航、滚动条导航、搜索定位和选择自动滚动仍然即时完成。该呈现事务既不预测 Host 行，也不改变历史需求、行窗口关联、协议状态或公共 API。

保留的历史记录公开了客户拥有的 DOM 滚动条覆盖层，该覆盖层位于整个终端视口而不是安装的单元格网格画布上。其最右边的16个CSS像素构成交互区域； 8 CSS-pixel 拇指与面板相对右边缘正好保持 2 CSS 像素，与未使用的网格剩余像素无关，并保留 4 CSS 像素的垂直轨道填充加上 20 CSS-pixel 最小高度。历史导航和滚动条交互使其立即可见，并且不活动会在 1,500 毫秒后消除其不透明度。跟踪按键按比例跳跃，捕获的滚动条拖动合并为有界的绝对行窗口请求。发起主指针拥有拖动直到其结束；并发和辅助指针事件和滚轮输入将被消耗，而不替换其捕获或锚点，并且其合成的释放点击被消耗一次。滚动条所有权优先于应用程序鼠标报告、选择和链接，并在无按钮移动、取消、捕获丢失、焦点或可见性丢失、重置和处置时进行修复。拖动期间的导航使拇指完全可见，并且仅在所有权结束或修复后才开始淡入淡出延迟。滚动条覆盖层和画布保留 `aria-hidden` 且不暴露 DOM 滚动条角色；现有键盘和 API 历史导航仍然是可访问路径。

搜索归客户端所有。首次非空查询会惰性创建一个 Worker，并通过来源中立的行读取器流式取得有界文本详情页。管道绑定一个 Worker 页与一个预取行请求；页面额度会刷新空闲看门狗，16 MiB UTF-8 来源上限会得到一个完整不可变结果或明确不匹配。视口、搜索和通用缓冲区读取使用彼此独立的单飞行通道，因此滚动或链接检查不会取消搜索页；请求序列关联允许响应以任意顺序结算，同时把客户端并发行读取限制为三个。防抖或扫描期间请求的导航，只要同一查询修订仍有效就继续排队。装饰数量与结果计数设有上限；定向导航则从最新 Host 选择锚点独立扫描已准入的保留搜索域并循环，不把装饰上限误当成最终匹配上限。活动匹配单独报告，并通过带修订约束的 Host `set-range` 命令选中；即使不在装饰集合中也会显示。查询文本与匹配项绝不会进入 Terminal Host 或 Electron Broker。

```ts
terminal.scrollLines(-1);
terminal.updateSearch('failed', { caseSensitive: false, wholeWord: true });
terminal.findNext();
```

选择端点和导出内容仍以 Terminal Host 为权威。浏览器不信任 DOM 点击计数，而是根据 500 毫秒间隔与一个单元格的界面距离上限推导单击、双击或三击序列，再发送有界的界面位置与单元格几何，以应用 Ghostty 的单词、行、矩形以及单元格内 60% 端点规则。普通单击不会合成一个单元格的选择。拖动超出视口时，会通过有界行窗口请求推进保留历史，并在新显示的行上继续同一个 Host 手势；指针捕获不可用时，文档级移动与释放后备路径保持该行为。按住辅助修饰键三击可选择 Ghostty 的语义命令输出，拖动则跨输出块扩展选择。默认只有普通的主指针释放会完成手势并请求复制。即使最初的按下回复仍在处理中，串行命令队列也会在释放前保留最近一次合并后的拖动更新。无按钮移动、指针取消或捕获丢失、界面焦点或文档可见性丢失，以及 Presentation 几何替换，都会取消已固定的手势，但不会复制或清除最新 Host 选择。串行化的手势回复确保一次正常释放或取消只产生一次复制结果；构造时的 `copyOnSelect: false` 与运行时的 `setCopyOnSelect(false)` 都会关闭正常释放时的复制。应用自有的剪贴板效果结算后，每个已接纳的自动或手动复制都会通过 `onSelectionCopyResult` 发布带来源标记的完成或失败。程序化范围与语义输出选择使用绝对 `bigint` 行。`adjustSelectionEndpoint` 保留 Host 最近发布的起始端点和矩形模式，只替换活动结束端点；它绝不会在客户端重建 Ghostty 文本语义。辅助技术 DOM Range 使用相同的显式单元格范围命令，并把 UTF-16 偏移映射到组合、宽字符和代理对字素。两个端点都可见时，Host 选择会镜像回可见视口的可访问性树。文档全局 DOM Range 移到其他界面，或在同级焦点期间消失时，当前界面只会放弃其可访问性镜像所有权；附件的 Host 选择和 Canvas 覆盖仍保持活动。界面或窗口失焦时，会在浏览器折叠该镜像前同样放弃镜像所有权；这种折叠只属于 Presentation，不能发布 Host 清除命令。构造时没有输入权限或动态降级的附件，仍让隐藏文本区域可获得焦点，但原生保持只读。仅 Shift 的翻页导航、滚轮历史、搜索、选择、复制与已批准链接，在没有 Host 输入能力时仍然可用；防御性的 `beforeinput`、输入法组合、粘贴、按键和鼠标监听器负责拒绝浏览器编辑并清除残留输入状态，不发出 PTY 输入。经过身份校验的自然退出结果会永久封存 PTY 输入、清除、重置与 resize，并把现有文本区域设为只读。保留的最终帧和本地输出交互在处置前仍可使用。应用负责执行剪贴板副作用，并且只报告其结果。

经过身份检查的运行时失败结果应用与自然退出相同的终端控制密封：PTY 输入、清除、重置和调整大小立即变得不可用，而保留的输出、历史记录、搜索、选择、复制和批准的链接交互仍然可读。

终端发起的剪贴板写入使用单独的事件路径。 `ProjectedTerminal` 仅接受对其精确附件的模式验证请求，抑制重复或过时的序列，并将有界文本发布到应用程序而不执行效果。处置会删除侦听器并阻止以后传递。应用程序必须拥有提交策略和平台剪贴板功能；选择副本不会隐式提交 OSC 52 请求。

帧元数据公开一个严格解码的当前进度样本。打包存储以原子方式随帧提交 `remove`、`set`、`error`、`indeterminate` 或 `pause`，并默认将不存在的扩展名设置为 `remove`。贝尔仍然是一个单独排序的依恋事件。 Progress 和 Bell 都不会改变终端生命周期、输入可用性、焦点或应用程序通知策略。

帧元数据还公开最新的严格解码的语义命令完成（如果存在）：终端本地序列、持续时间毫秒、挂钟完成毫秒和标准化退出代码。打包存储从不重建或保留命令文本。它仅以原子方式提交主机事实；该应用程序拥有新鲜度、焦点、重复数据删除、速率限制、权限和任何通知效果。

链接发现扩展了有界生成/修订固定的行读取，直到它具有一个完整的软包装逻辑行。允许的行受到协议行、单元和字节限制的限制；超出限制线不会产生部分检测。 OSC 8 个目标和 OSC 133 个单元/行语义来自主机拥有的 Ghostty 状态；这个包永远不会重新解析它们的转义序列。显式链接优先于检测到的 URL 和路径文本。自动URL检测仅允许`http`、`https`和`mailto`； `normalizePermittedExternalTerminalUrl(...)` 是工作台操作和浏览器效果适配器再次使用的公共策略操作。不受支持的显式 OSC 8 元数据和检测到的文件系统目标可能保留在有界链接缓存中，但它们永远不会接收指针悬停、产品上下文或激活请求。内容修订、视口转换、表面大小调整、设备像素比更改和演示几何形状更改都会使悬停缓存失效。在 `ProjectedTerminal` 发出一个批准的 URL 请求之前，修改器辅助的单击会重新验证悬停的生成、修订、悬停时期和单击的单元格；应用程序决定是否以及如何打开它。此软件包不会打开文件系统和未知目标。

纯文本拖入遵循与粘贴相同的清理、审查、排序和 Host 输入路径。`file-drop` 粘贴来源遵循相同
的风险策略，但来源本身不会强制审查：安全的单行文本会直接发布，control、嵌入的 bracket
terminator 与未受保护的多行输入仍遵循普通审查规则。文件路径的解析与安全准备仍由应用拥有的
capability 负责，因此本 package 不获得 filesystem 权限。

离屏辅助功能镜像是一个标记为 `list` 的直接 `listitem` 行保留空格、字素到列的映射以及绝对 `aria-posinset`/`aria-setsize` 位置。它使用调用者提供的本地化文本来标记行和光标。单独的礼貌状态区域仅宣布更改的可见输出，包括本地化删除通知。保留历史记录检查禁用实时更新而不替换实时输出基线，因此返回到底部仅宣布自上一个实时帧以来更改的输出。

## 渲染器行为

条件允许时优先使用 WebGPU；Canvas 2D 是可观察的后备。两条路径使用相同的打包投影、字体配置、应用拥有的选择/搜索覆盖、预编辑状态和光标元数据。Host 帧元数据保持权威且不被修改。非空客户端 `defaultColorOverride` 只改变打包前景或背景 token 为 `TerminalColorEncoding.default` 的单元格；显式 RGB（包括黑色）、Host 投影调色板 RGB 与 `none` 保持其 Host 投影语义。反色会交换已经解析的显示角色；默认下划线使用有效前景色；光标始终使用 Host 光标颜色，并以 Host 前景色后备。显式客户端光标强调色只影响块光标内的文本。该覆盖位于带修订的 Host 主题路径之外，在共享 Orchbee Web/Desktop 组合中始终为 `null`。`allowTransparency` 只控制透明渲染器的清除方式；组合客户端将 `backgroundOpacity` 用作有效默认背景根，绝不为整个表面应用 CSS opacity。Canvas 在首帧前保持透明，之后以最新有效默认背景进行不透明填充及调整大小。打包字素保留 CJK、组合与 emoji 单元格宽度；显式前景/背景和下划线颜色、反色、粗体、微弱、斜体、不可见、闪烁、下划线变体、删除线和上划线都使用投影中的 Ghostty 样式。渲染器健康状态报告初始化、后备、设备丢失、恢复及恢复失败。
WebGPU 路径为背景、文本和覆盖层三种流分别保留并清空一个实例数组，以及一个按几何级数增长的 `Float32Array` 上传缓冲区。当某个流达到其最大已准备帧所需的容量后，后续不超过该尺寸的帧会复用同一底层 CPU 存储，而不再分配另一个帧大小的缓冲区。销毁时会释放保留的暂存空间。逐单元格的前景色/背景色解析也会复用一个由渲染器拥有的暂存投影，调用方只复制必须比当前单元格存活更久的值。这些规则把两个全视口分配热点限制在已准备视口内容的峰值容量内；它们不定义 GPU 驱动、浏览器或整个进程的 RSS 上限。

字体测量以大的 CSS 尺寸对选定的浏览器表面进行采样，以恢复其未舍入的前进、上升、下降和大写高度比率。网格宽度和高度保留稳定的 CSS 几何形状，而基线在两个后端光栅化之前以当前物理设备像素比进行舍入。这可以防止 CSS-first 舍入将 high-DPI 字形相对于 Ghostty 移动一个物理像素。

每个 Canvas 字体上下文都请求 `geometricPrecision` 文本渲染，包括 WebGPU 字形图集、其增长后的替换以及 Canvas 后备。这会抑制 Chromium 的小尺寸易读性加厚，并匹配 Ghostty 的未加厚 CoreText 覆盖范围，而无需更改所选的可变字体轮廓或配置的粗细。

浏览器字形塑造批次只包含单列 Host 单元格。宽 CJK、表情符号与其他后备字素会从其权威起始单元格光栅化一次，而不继承后备字体面的自然批次步进；延续单元格也不能吸收后续组合簇。在每个窄单元格批次内，Canvas 字母间距会补齐字体面自然小数步进与取整后终端单元格宽度之间的差值。这样，即使终端样式边界切分一行，也能保留复杂字形塑造与编程连字，而不会累积网格漂移。基础前景变化与选择/搜索覆盖会复用原始塑造批次，在单元格边界裁剪，并只为覆盖部分重新着色。因此，移动的动画前景边界不会改变字形光栅或原点；字体、样式、下划线与彩色字形分类仍是字形塑造边界。

Ghostty 仍然是选定字体规格、形状边界、完整 Unicode sprite-face 路由、光标几何形状和终端面板渲染行为的参考。确定性生成的数据提供来自 Ghostty 的四个填充奇数/偶数度量参考栅格的每个固定精灵，而选定的精灵在这些参考几何图形之间按程序缩放。该引用不会使该包成为 Ghostty VT 所有者。维护来源记录在[`docs/ghostty-surface-test-provenance.md`](docs/ghostty-surface-test-provenance.md)中。

搜索行为遵循 [`docs/vscode-search-alignment.md`](docs/vscode-search-alignment.md) 中的有界契约。应用程序拥有查找界面、查询历史记录、快捷方式和本地化标签。

### 光标闪烁演示

主机光标元数据对于光标坐标、可见性、形状以及是否启用闪烁仍然具有权威性。渲染器仅拥有本地闪烁阶段及其 530 毫秒计时器。提交的坐标更改立即在其可见阶段呈现启用的闪烁光标并重新启动该计时器；因此，在一个时间间隔内重复更改会保持光标可见。未更改的坐标永远不会重新启动计时器，因此光标在一个空闲间隔后会在可见和隐藏之间恢复交替。禁用闪烁会停止计时器并使光标可见。暂停渲染器会停止可见阶段的动画，然后恢复会开始一个新的间隔。没有重点的演示仍然是一个不闪烁的空心块。

该呈现逻辑观察已提交的 Host 坐标，而非键盘意图：未移动光标的输入不会产生效果，由终端输出造成的光标移动则具有相同的重置行为。它绝不会改写 Host 元数据或引入第二套光标坐标。确定性渲染器测试控制计时器，并覆盖从隐藏到移动时恢复可见以及首次空闲切换；Host/配置光标模式证据保持独立。

### 光标默认和安装启动证据

精确的 `terminal-parity/SU-13-cursor-defaults` 见证人通过生产表面投射真实的 Terminal Host/PTY 轮廓。它观察显式块/非闪烁默认值、闪烁条 DECSCUSR 覆盖以及提交帧元数据中的 RIS 恢复。确定性Canvas和WebGPU所有者测试分别证明相同的元数据选择相应的光标几何形状和闪烁调度程序；系统见证人不使用平台屏幕截图作为第二光标权限。主机运行时证据还包括应用程序重置和显式非默认配置文件。

`measureMountedTerminalGeometry(...)` 加载选定的字体并应用与第一次投影调整大小相同的网格和物理单元格规则。仅 POSIX 的精确 `terminal-parity/SU-16-startup-geometry` 见证人独立地从真实的 Electron 表面导出安装的网格，在 shell 启动之前记录子 PTY 的初始 `stty size`，并要求唯一的第一个客户端框架携带相同的列、行、以及没有中间 `80x24` 框架的物理单元尺寸。桌面和主机所有者测试涵盖没有子项的延迟身份、附加前启动排序、失败/重复/冲突启动以及核心同步；主导证人未声明 Windows ConPTY 或稍后调整大小的行为。

### 实时输入能力证据

精确的有界面 `terminal-parity/IN-10-read-only` 见证通过真实 Canvas 2D 投影界面驱动单调降级与升级。它观察即时的输入法组合、本机结算、粘贴审查与文本区域修复；持续可用的本地搜索、选择、复制与历史；没有陈旧输入发布；并且升级修订中只接受全新输入。该夹具控制应用交付流，因此 Terminal Host 所有者测试会另行证明对陈旧和已降级 PTY 输入的权威拒绝、按附件修复排序，以及不重放排队输入。它不声称渲染器拥有能力升级权，也不声称任何原生浏览器权限策略。

### 终端操作上下文证据

`ProjectedTerminal.captureActionContext(...)` 是包含产品菜单的源中立边界。当应用程序鼠标跟踪拥有该表面时，除非按住 Shift 键，否则它会返回 `terminal-owned`。否则，它仅公开所请求单元格处允许的 URL 目标以及当时捕获的确切历史生成、历史修订、链接纪元、绝对行和列。 `linkOpenRequestIsCurrent(...)` 重新解析这些规范值，要求完整的修订元组保持最新，再次解析相同的缓存单元，并在应用程序承认效果之前比较确切的 URL。它不打开链接或拥有操作运行时。

领导见证人将真实的 Canvas 2D `ProjectedTerminal` 组合到一个应用程序拥有的工作台操作范围中。 `terminal-parity/IN-09-action-scope` 检查可用、不可用和未绑定的 Apple 命令处理。 `terminal-parity/IN-11-context` 检查应用程序鼠标所有权、有界固定输入、修订无效和零外部影响。 `terminal-parity/IN-12-actions` 检查完整的最小目录、同步可用性、键入结果、无新确认以及本地化可感知反馈。 `terminal-parity/FS-05-file-links` 检查显式文件元数据、检测到的路径和直接浏览器效果请求是否保持非活动状态。 `terminal-parity/FS-06-url-policy` 精确检查相同真实表面的悬停、上下文和直接激活路径，以查找 `http`、`https` 和 `mailto`，包括不支持的自动和显式 URL 情况。所有者本地单元测试还涵盖格式错误的上下文、精确输入复制、规范化、自动检测过滤以及执行前的重新验证。

`terminal-parity/HS-07-selection-export` 通过真实的 PTY 和 Terminal Host 发送 SGR-styled 输出，通过生产 Canvas 表面选择样式字，并观察 Electron 的剪贴板准确接收可见的纯文本。 终端协议已生成TypeScript/Zig一致性语料库分别证明`plain`是唯一承认的请求和响应值HTML和原始的VT请求在主机运行时访问之前失败。 严格的projected-client命令不公开任何格式字段。 带头见证人运行当前 macOS Electron 剪贴板路径； 它不声明另一个操作系统的本机剪贴板格式注册表。

### 可见性与投影需求证据

稳定的 `terminal-parity/SU-15-visibility` 轨迹通过真实的 `ProjectedTerminal` 和 Chromium Canvas 2D 表面绘制初始框架，然后将文档可见性与明确的投影需求相结合。虽然这两个原因都被暂停，但它证明排队绘制和闪烁动画在多个修订提交并发出 `FrameApplied` 时保持暂停状态；仅清除可见性仍然暂停，而清除需求时间表正是最新一代和修订版的其中一个。该跟踪还验证第二次绘制是否未排队，并且处理后的可见性、需求、帧和动画活动是否处于惰性状态。

有界面夹具只在自身测试文档内覆盖 `document.visibilityState`，并派发真实的应用层 `visibilitychange` 事件。它不执行操作系统级标签页后台行为或浏览器节流策略，也不对 WebGPU 或跨浏览器行为作出声明。

## 开发

从仓库根目录运行：

```sh
pnpm --filter @orchbee/terminal typecheck
pnpm --filter @orchbee/terminal build
pnpm --filter @orchbee/terminal test
pnpm --filter @orchbee/terminal test:tla
pnpm --filter @orchbee/terminal test:exports
pnpm verify
```

`test:tla` 检查 [`formal/README.md`](formal/README.md) 中记录的包拥有的运行时表示和输入修复模型。它们是更改触发的正确性证据，不是普通包测试命令的一部分。

当 `../ghostty` 或 `GHOSTTY_SOURCE` 可用时，`pnpm audit:ghostty-panel` 将维护的渲染器/字体出处和生成的数据与固定的 Ghostty 源进行比较。仅当固定的 Nerd Font 约束、精灵范围或精灵参考栅格更改时才运行 `pnpm generate:ghostty-panel-data`。
