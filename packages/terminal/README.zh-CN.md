# @orchbee/terminal

其权威 VT 状态位于 Orchbee Terminal Host 的终端的源中立浏览器客户端界面。

## 适用范围

该软件包拥有一个投影终端表面：

- 原子打包帧提交和快照恢复；
- WebGPU 使用 Canvas 2D 后备进行渲染；
- 有界历史窗口呈现；
- 客户端搜索和有界逻辑线链接发现；
- 当前有界语义命令完成元数据；
- 主机拥有的选择交互和副本关联；
- 键盘、提交的文本、IME、鼠标、焦点、粘贴、调整大小、清除和重置意图；和
- 可见视口可访问性。

它绝不接收或解析 PTY 输出，不加载 VT 引擎，也不公开 `write(ptyBytes)`。Terminal Host 拥有 PTY、Ghostty VT 状态、终端模式、保留历史、选择端点及依赖模式的输入编码。应用拥有传输、终端清单、产品拓扑、剪贴板效果、外部导航及本地化产品 UI。机器可读的范围契约见 [`project.json`](project.json)。

跨所有者运行时权威仍位于 Terminal Host 合约及各应用和协议所有者指南中。本指南保留来源中立行为和稳定兼容性证据索引，但不覆盖这些所有者的权威。

打包的元数据仅携带最新的可选命令完成序列、持续时间、完成时间戳和从主机帧解码的标准化退出代码。该包既不解释 Shell 输出，也不拥有提醒策略、通知权限、焦点规则、新鲜度、重复数据删除、速率限制或产品副本。投影缓冲区输入没有完成事实；快照和增量输入保留严格解码的可选值。

`clear()` 和 `reset()` 是语义主机请求。 `clear()` 擦除活动屏幕并将其光标归位，同时保留终端模式。 `reset()` 首先修复客户端拥有的合成、按下输入、选择、搜索、悬停和历史视口状态，然后要求主机执行 Ghostty 的完全重置。这两种方法都不会注入终端转义字节或重用投影 `store-reset` 恢复。

输入修复将原生输入法组合生命周期与本地提交资格分开。活动组合可能具备资格，也可能已经取消但浏览器仍欠终端一个 `compositionend`。reset、文本区域 blur、窗口 blur、文档进入隐藏状态和处置都会立即清除文本区域与渲染器预编辑，撤销提交资格，并清除按键、组合、`beforeinput`、`input`、粘贴和鼠标关联记录。对于无法提供可用 `beforeinput` 载荷的浏览器与 IME，已提交的 DOM `input` 事件用作后备；其 textarea 值只消费一次，随后清除。迟到的组合更新，以及迟到的 `beforeinput`/`input`/`compositionend` 顺序，都不能重新发布预编辑或文本；它们只会结束已取消的本地工作。即使旧 `compositionend` 从未到达，新 `compositionstart` 也会取代已取消工作。重新聚焦、非组合按键或独立的非组合 `beforeinput` 也能恢复本地推进，无需等待旧组合结束。对于未取消的组合，无论浏览器按何种顺序发出 `beforeinput`、`input` 与 `compositionend`，文本最多提交一次，且状态转换在同步命令端口发送前完成。macOS `keyCode=229` 路径会推迟暂时独立的 `beforeinput` 文本，直至原生 textarea 值稳定，从而保留 IME 生成的标点，而不是发布物理 ASCII 按键。除可选 Shift 外没有其他修饰键的可打印标点和数字按键也会让原生 textarea 优先处理，使第三方 macOS 输入法能够发布其准确的 Unicode 结果。Shift 字母与空格仍走物理按键路径；任何 Control、Meta 或 Alt 组合都在原生文本结算之外保留既有快捷键或物理按键行为。适配器自身绝不映射标点。若 30 毫秒内没有原生值到达，则把 `KeyboardEvent.key` 文本作为确定性的已提交文本后备发送；该后备不保留物理按键身份，Shift 生成的标点也不例外。原生结算使用同一有序输入调度器：中间的按键、粘贴或指针输入会先封存当前原生批次，再准入后续输入，因此延迟的数字或标点无法越过后续物理按键。相同的短期结算标记也处理原生 `input` 先于 `keydown` 到达的浏览器事件顺序。

在 macOS 上，投影终端还使用源中性 Option-as-Alt 模式：`off`、`left`、`right` 或 `both`。它跟踪来自 `AltLeft` 和 `AltRight` 的物理选项侧，解析每个已承认的关键事件的一个布尔语义意图，并实时更新该模式，而无需重新创建终端。它永远不会在提交的文本前面加上 Escape。 Terminal Host 消耗事件意图并继续拥有当前终端模式的实际 Ghostty 键盘编码。

完整的源中性 Presentation 配置包含字体族、整数字号、常规与粗体 CSS 字重、字体连字开关、`0` 到 `32` CSS 像素的统一终端内边距、颜色覆盖和背景不透明度。当前 Settings 来源只接纳 `100` 到 `900` 之间以百为单位的整数字重；其默认字重为 `400` 和 `700`，默认启用连字且内边距为零。完整的实时更新会修改已挂载渲染器并重新计算可用终端几何，而不会替换其 Host 附件。统一内边距是在已测量的界面 CSS 边框和内边距之外额外添加的。

独立的源中性交互配置包含 `copyOnSelect`，默认值为 `true`，并通过 `setCopyOnSelect` 更新已安装终端，无需重建界面。Presentation 与交互来源拥有相互独立的生命周期和持久化所有者。

实时预编辑是一种可逆的演示，从投影的主机光标开始，并在可见网格中按行优先顺序换行。窄单元格和宽单元格保持原子性，超出最后一个可见行的溢出将被剪切，而不会滚动或改变主机状态，并且隐藏的本机输入锚点遵循定位帮助器堆叠上下文内的相同包装插入符，因此平台 IME 候选窗口保持对齐。

普通去重记录都是一次性的。第一次 `beforeinput` 检查会消费之前的按键记录，即使二者不匹配；匹配的组合、`beforeinput` 及相反来源的粘贴检查也会消费各自记录。其时间窗口严格小于 100 毫秒。已取消或被取代的组合使用独立结算守卫，修复不会将其清除。只有由 `isComposing`、`insertCompositionText` 或 `insertFromComposition` 标识的组合来源 `beforeinput` 才会消费该守卫；后来具有相同文本的独立 `insertText` 不会被抑制。组合来源的特殊 input 类型会在粘贴、换行或删除处理前判定，因此已取消原生工作无法进入这些分支。由于浏览器事件不提供组合标识，新的 `compositionstart` 会建立下一个组合事件的所有权，并取代所有尚未结算的旧原生工作。

最后一次鼠标释放和每次修复都会清除保留的鼠标样本。修复会关闭本地输入准入门，并在清除所有权或调用任何可能同步发送命令的辅助函数前启动清理事务。输入处理器还会为历史恢复、选择清除和焦点报告保留修复纪元；先关闭、随后重新开放准入的修复会让旧延续失效，阻止它发布按键、预编辑、文本、鼠标输入或过时关联。组合文本提交还会保留精确的已暂存输入状态标识，因此同步发送返回后，不能清除由可重入修复及更新组合所安装的文本区域或预编辑状态。

普通承认的输入在一代调度程序内保留为 FIFO，包括在粘贴审核待决时。生命周期修复会在快照清理之前关闭准入并使该生成无效，因此重置、模糊、可见性损失和处置无需等待可能永远不会解决的粘贴审查。排队的命令和迟到的审查决议或来自无效一代的拒绝是可以观察到的，但是惰性的。新开的一代在修复后独立进展。

粘贴检查会在用空格替换不安全的 C0/C1 控件之前保留原始文本，并检测原始文本中嵌入的括号粘贴终止符。没有括号保护、替换控件和嵌入式终止符的多行文本需要应用程序拥有的本地化审阅界面；批准仅发送经过净化的文本。该评论快照了预计的括号粘贴模式，并通过语义输入承载了该期望。 Terminal Host 将其与权威的 Ghostty 模式进行比较，同时保持终端锁定，并且仅在完全匹配时进行编码；不匹配会拒绝粘贴，而不会进入队列或自动重播，因此可以根据当前状态检查新粘贴。当承认的剪贴板事件没有纯文本但包含图像项目时，适配器会保持系统剪贴板不变，并准确地发出一个合成的 Control+V 按下/释放对。这符合代理粘贴约定，无需读取图像字节、创建文件或检测特定代理。当文本和图像项目同时存在时，纯文本仍然具有权威性。

适配器跟踪承认的所需所有权与已发布到主机的所有权分开。物理按键和指针按钮是永久所有权；合成 `beforeinput` Enter/Backspace/Delete 命令和滚轮按钮 4/5/6/7 报告是无状态的，并且永远不会进入持有的分类帐。适配器在任何同步边界之前暂存本地所需状态，在一个发布门下调用命令端口，并仅在 `port.send` 同步返回后提交主机发布的所有权。该调用期间的生命周期回调将被合并，直到知道结果为止。同步抛出是现有的浏览器适配器预接受失败边界：失败的按下回滚其本地所有权和相关性，而失败的发布或焦点保留保留已知的主机所有权以供以后修复尝试。返回的 Promise 可能仍会诊断性地拒绝，但同步返回会记录本地传输接受情况，并且不会声明有关远程传送的情况。

每个物理指针按钮在按下时都会快照其所有者：除非按住 Shift，否则当前 Host 投影的鼠标跟踪拥有该按钮；其他情况则由终端选择或链接交互保留。后续修饰键或投影模式变化不能转移由应用拥有的按下。应用拥有的按下会捕获指针，只从应用拥有的按钮账本派生拖动状态，并可在 Canvas 外正常释放。无按钮移动、pointer cancel 或 lost capture 会先为每个已准入或已发布到 Host 的应用按钮排入一次语义释放，再清除捕获，因此后续生命周期修复不能重复释放。投影任意鼠标跟踪模式时，本地链接查找与激活都要求 Shift；激活会在点击时重新检查该条件，已完成的应用拥有主按钮按下也不能激活过时链接。非像素鼠标格式下的无按钮 hover 对同一个夹取后的终端单元格至多发布一次，在 Host 排队前采用 Ghostty 的终端单元格合并规则。SGR pixel hover 会保留每一个有限位置；拖拽、按下、释放和滚轮输入仍保持有序且不合并。每个滚轮事件的所有权仍是无状态决定。应用拥有的滚轮输入会依据投影单元格与网格尺寸规范化 pixel、line 与 page delta，按轴独立累计不足一个单元格的移动，并先报告垂直按钮 4/5 步，再报告水平按钮 7/6 步。Shift 会绕过应用鼠标所有权。在主屏幕上，规范化垂直步进用于导航有界保留历史；在备用屏幕上，可写输入会将其映射为对应的语义 Arrow Up/Down 点击。只读备用屏幕消费垂直滚轮输入而不发出 Host 输入；只有水平方向的本地滚轮输入仍由浏览器拥有。

画布指针使用相同的所有权策略，而不是独立的仅链接样式。固定的应用程序拥有的手势和未修改的投影鼠标跟踪使用默认指针；终端选择使用文本指针；矩形选择在 Apple 浏览器平台上使用带有 Option 的十字准线，或者在其他地方使用 Alt + Control/Meta；并且，启用的、允许的链接仅在终端交互拥有指针时才使用指针光标。投影模式提交、修改器更改、手势转换和链接呈现都会重新评估此策略，因此清除链接会恢复派生的基指针，而不是空的 CSS 覆盖。

浏览器按键规范化会把旧版 `OSLeft`/`OSRight` code 映射到 Ghostty 的 `MetaLeft`/`MetaRight`，识别完整 W3C key 字符串而非计算 UTF-16 代码单元，并且只有事件携带可打印文本、且已消费修饰键为活动修饰键的子集时才记录后者。按键发布只用持有所有权识别物理按键；已发布的右侧修饰键从浏览器拥有的跟踪中移除后，其文本、修饰键及已消费修饰键字段取自当前 `keyup`。若 `keyup` 重入同步输入发布，则推迟到所属按下操作结果确定，或由并发生命周期修复一并处理，避免已发布按下失去对应释放。应用与终端语义快捷键均有机会捕获后，未被声明的 Apple Command 修饰按键交给 Browser/Electron 原生处理；它既不作为终端输入发布，也不会通过按键名称允许列表被取消。在 macOS 上，不带 Alt、Control 或 Meta 的 Shift 修饰键按下与抬起仍作为 Host 按键所有权发布，但不会取消 Browser 默认行为，让系统或第三方输入法决定一次 Shift 点击是否切换输入模式。两个事件继续进入原生输入处理前，界面会重新测量并同步提交隐藏输入锚点；其他平台与修饰键的所有权保持不变。合成的 Enter、Backspace、Delete 及备用屏幕方向键输入使用与成对按下/释放相同的预留发布路径。它们不保留稳态客户端所有权，但按下与释放之间的传输丢失对 Host 附件账本仍然可见，以便在分离时修复。

仅 Shift 的 Page Up 和 Page Down，包括其键盘代码，仍保留本地保留历史导航，并且永远不会成为主机键输入。除无按键的应用鼠标移动外，每个已准入的输入生成路径共享一个有序的表面转换：当历史记录可见时，它首先请求实时底部，然后清除活动的主机选择，然后才发布语义按键或重复、文本、批准的粘贴或应用程序鼠标输入。由任意事件鼠标跟踪准入且符合条件的无按键移动报告会发布到 Host，但不会改变当前的历史位置与活动 Host 选择。纯物理修饰键的按下与重复同样会保留该表面，同时维持 Host 按键所有权，使应用快捷键能够在不先关闭保留历史的情况下解析；第一个未被认领的非修饰输入仍会执行共享转换。合成激活会在呈现预编辑前执行该转换。物理或合成按键释放会关闭现有的 Host 输入所有权，而不启动该转换，因此在其按下和释放之间建立的选择仍然可见。焦点报告、生命周期和指针手势修复、拒绝或中止粘贴审查以及本地历史记录导航可保留当前历史记录和选择表面。

`terminal-parity/IN-07-pre-input` 在保留历史与 Host 选择均处于活动状态时，通过有界面 Canvas 表面驱动一个真实的无按键 `PointerEvent`。它要求只产生一条应用鼠标移动报告，不产生回到底部或清除选择命令，并保留可读取的选择。同一轨迹随后先在该 Host 选择上创建一个辅助技术来源的 Range，再合成窗口焦点丢失并折叠此 Range；此时不发布 Host 选择清除命令，可读取的 Host 选择仍保持活动。所有者本地回归覆盖这两种修复，同时保留既有的鼠标按键按下转换要求。

清理只释放已经发布的所有权：排队的释放不能掩盖 Host 可见的按下；排队或失败的按下也不能产生孤立释放。blur 与可见性丢失会按按下顺序分别释放一次已发布按键和鼠标按钮，随后只有当本会话发布过 focus-in 时才发布 focus-out。处置会永久关闭准入并遵循相同顺序；若已经失焦则省略 focus-out。每条处置清理命令只尝试一次；同步失败会被报告并保留为已知所有权，但 DOM 与监听器移除后无法再重试拆卸。reset 本身不要求 focus-out，并会保留焦点。如果 reset 使排队或失败的 focus-in 失效，替代生成会在后续按键或鼠标发布前尝试焦点协调；同步协调失败仍可由下一项输入重试。投影终端把隐藏 textarea、无障碍后代及挂载在同一根下的应用自有控件视为一个焦点边界。在该边界内移动既不修复输入，也不重复焦点报告；离开边界时先释放已发布的按键与鼠标所有权，再发送一次 focus-out；从非 textarea 后代进入时则发送匹配的 focus-in。何时调用 `focus()` 由应用决定；已打开的表面会先同步其本地内边距、滚动条、隐藏输入锚点及当前 resize 建议，再把原生焦点移到隐藏 textarea。打开包提供的表面不表示取得初始产品焦点。Desktop 与手写笔指针在 pointer down 时聚焦隐藏 textarea。

### 移动触摸与原生输入模型

| 字段         | 契约                                                                                                                                                                                                                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题与范围   | 粗粒度触摸指针必须能操作投影终端，且不继承桌面选择时序，也不依赖硬件键盘。鼠标、手写笔、触控板、硬件键盘、多点触摸、捏合缩放和原生选择手柄行为保持不变或明确排除。                                                                                                                                                                        |
| 输入         | 适配器规范化一条主 `pointerType === 'touch'` 流、有限 CSS 像素坐标、当前单元格几何、投影应用鼠标所有权、活动屏幕模式、输入能力、`touchend`、原生输入/组合事件和生命周期取消。缺失几何、过时指针标识、额外触点及已关闭输入准入均为有意无操作或取消。                                                                                       |
| 状态与模型   | `TerminalTouchGestureState` 为 `idle`、`pending-tap` 或 `scrolling`，由一个已挂载 `ProjectedTerminal` 拥有。`transitionTerminalTouchGesture(...)` 是激活、八 CSS 像素移动阈值、垂直轴优先、累计滚动位移、完成与取消的确定性所有者。DOM 捕获、焦点和 Host 命令是该模型返回的适配器效果。                                                   |
| 转换         | 主触摸按下进入 `pending-tap`，不产生选择、焦点或 Host 鼠标输入。低于阈值的移动保持待定；达到或超过阈值且以垂直方向为主的移动进入 `scrolling`。待定释放在最终单元格产生一次轻触；滚动释放不产生轻触。pointer cancel、lost capture、焦点/可见性修复、能力替换和处置均返回 `idle`，且不产生轻触。                                            |
| 输出与不变量 | 完成轻触后，紧随其后的非 passive `touchend` 会聚焦可写 textarea；若投影应用鼠标拥有该表面，还会收到最终单元格的一对 press/release。滚动绝不聚焦、选择、点击或发布文本。自然垂直位移复用滚轮所有权：应用鼠标接收按钮 4/5，可写备用屏幕接收 Arrow Up/Down，主屏幕导航保留历史。除非后续获准输入使用既有输入前转换，否则 Host 选择保持不变。 |
| 原生输入     | 移动焦点在 textarea 中保留一个可删除哨兵，使空提示符上的 Backspace 仍可观察；每条已提交文本和预编辑后备都会移除该哨兵；原生输入的有效字号至少为 16 CSS 像素，以避免聚焦缩放。Enter、Backspace、Delete、独立文本和 IME 组合继续遵循既有有序且恰好一次的输入契约。只读附件绝不准入移动文本。                                                |
| 所有权与依赖 | 本软件包拥有手势和原生输入正确性。应用拥有移动控件可见性、本地化控件、一次性修饰键策略、可视视口几何和平台验证。Terminal Host 仍是 VT 输入编码、保留历史和选择的唯一所有者。                                                                                                                                                              |
| 验证与限制   | 纯转换测试覆盖阈值减一/等于/加一、轴相等、自然方向、过时标识、完成和每种取消。投影终端适配器测试覆盖轻触、应用鼠标、滚动、哨兵删除、IME、只读和修复。仍需受控有界面浏览器轨迹来验证 DOM 顺序与几何；真实 iOS 和 Android 键盘弹出仍属于发布验证，而不是自动化操作系统声明。                                                                |

每条原始输入、按键、已提交文本、粘贴、应用鼠标、焦点和修复命令都携带当前正数附件能力修订。直接构造默认使用初始修订 `1`；Desktop 与 Gateway bootstrap 转发 Host 返回的修订。`applyInputCapability` 只接受精确附件与终端标识、精确重放，或输入值已变化的下一个单调修订。过时修订为空操作；标识不匹配、同修订冲突、跳过修订，或修订已变化但权限未变化时，都会失败关闭为只读。降级会使调度器生成失效，并立即清除组合、原生文本结算、粘贴审核、持有的按键/鼠标/焦点所有权及指针捕获，但不发送会重复 Host 修复的客户端释放。升级会移除原生只读守卫，但不恢复先前输入或排队工作；下一项获准输入只带新修订标记。如果投影客户端在清理完成前消失，Terminal Host 会在撤销其能力前，只释放该附件已经接受的按键、应用鼠标与焦点所有权；其他附件不受影响。

`injectInput(...)` 是供受信、由应用拥有的实时输入界面使用的窄桥接。它只接收已提交文本或一次物理按键点击，并要求同时提供此前从 `injectedInputReadiness` 读取的精确不透明修订。该修订在准入时和有序调度器真正执行时都必须仍然匹配，因此先降为只读、再恢复为写入就绪的周期无法复活旧授权下的排队输入。获准输入随后使用终端本地按键规范化、Option-as-Alt 策略和共享输入前界面转换。就绪事件会随附件授权、打开、能力撤销、冻结与处置而变化。注入不接收粘贴、拖放、鼠标、历史或重放语义。`sent` 表示命令端口已接纳本次命令尝试，`failed` 表示投递结果可能不确定，`blocked` 表示本界面没有发布该输入。多终端目标捕获、FIFO 扇出、部分投递策略和用户警告仍由本包之上的应用负责，因为跨附件的命令端口发送不具备原子性。

模糊、可见性丢失或在重置暂存或发送清理时重新进入的处置会合并到同一事务中； 该事务在重新开放准入或处理之前会耗尽按键释放、鼠标释放和任何新需要的焦点。 主机重置遵循替换调度程序生成中的清理操作。 当前一代DOM粘贴审查拒绝通过现有命令错误通道报告，并且不会阻止后续输入； 来自无效一代的拒绝仍然是惰性的。 版本化的成熟相关跟踪及其固定源修订版作为严格解析的、数据驱动的重播输入维护在 [`docs/input-repair-conformance-v0.0.1.json`](docs/input-repair-conformance-v0.0.1.json).

`ProjectedTerminal` 恰好代表一个附件。项目、工作区、选项卡、面板和可见性策略仍位于此包之上；隐藏终端不需要实时渲染器表面，并且投影/历史需求可以独立于主机运行时而暂停。

主机铃声效果通过 `ProjectedTerminal.onBell` 作为附件范围的单调事件到达。该包抑制陈旧或重复的序列，但不执行任何声音或视觉效果；嵌入桌面或浏览器应用程序拥有该策略。

有界面 `terminal-parity/PR-11-bell` 见证由三个真实 Canvas 2D 投影表面组成，它们具有不同附件标识并共享一个 Workbench 响铃协调器。该见证证明：重复序列只产生一次效果；不同的交错序列会被接受；附件重连后会抑制旧序列；声音与通知拥有相互独立的失败边界。受控夹具不要求原生音频输出、操作系统通知送达、WebGPU 或跨浏览器行为。

## 安装

```sh
pnpm add @orchbee/terminal
```

## 使用

调用者提供不透明的主机身份、本地化的可访问性标签和传输中立的命令端口。二进制帧和行窗口有效负载的转发无需 VT 解析或每单元代理重建。

```ts
import { ProjectedTerminal } from '@orchbee/terminal';

const terminal = new ProjectedTerminal({
	attachmentId,
	capabilityRevision: '1',
	creationId,
	hostEpoch,
	terminalId,
	canResize: true,
	labels: {
		input: i18n.t('terminal.input'),
		screen: i18n.t('terminal.screen'),
	},
	port: {
		send: (command) => hostConnection.send(command),
	},
});

terminal.onRendererHealth((event) => rendererDiagnostics.record(event));
terminal.onFrameTelemetry((frame) => rendererMetrics.record(frame));
await terminal.open(document.querySelector('#terminal')!);

hostConnection.onFrame((frameBuffer) => terminal.applyFrame(frameBuffer));
hostConnection.onRows((rowBuffer) => terminal.applyRows(rowBuffer));
hostConnection.onTerminalExited((event) => terminal.notifyExited(event));
```

必须在创建附件之前启动可视终端的应用程序可以调用 `measureMountedTerminalGeometry(root, configuration)`。帮助器等待配置的面，并使用与第一个投影表面相同的字体规格、填充、完整单元格网格、所有者文档 DPR、协议边界和 PTY 像素限制。当元素没有正面安装的内容框或填充消耗网格时，它返回 `undefined`；调用者再次观察表面，而不是替换超时或默认几何图形。用于此测量的配置必须保持用于打开投影渲染器的初始配置。

打开表面时，会先等待配置字体中的代表性拉丁、CJK、emoji 与 Nerd Font 字形就绪，再安装帧、渲染器、输入、调整大小及无障碍处理，最后激活投影需求。每次打开尝试都以事务方式拥有 Canvas、输入、无障碍节点、渲染器、观察器及监听器：设置失败只移除这些资源，并让同一实例返回 `constructed` 以便重试；重复打开会被拒绝且不改变当前表面；处置仍是最终状态。包默认使用浏览器通用 `monospace`；应用可提供预置产品字体。Orchbee 的共享 Web/Desktop 应用会在打开表面前注册固定且与 Ghostty 对齐的主字体与符号后备字体，不依赖机器上已安装的字体。调整表面大小时会从可用网格中扣除计算出的内边距，保留既有的两列最小值；若内边距耗尽任一内容维度，则不建议新的 PTY 几何。平衡内边距仍是可选行为。测得的调整大小请求会先于活动投影需求发送；只有它与最近一次 Host 提交几何一致，或仍处于短暂的观察器重入窗口内时，才会去重。Host 几何变化、Broker 拒绝、传输失败或后续未变化的观察结果，都会使该建议可以重试。隐藏 IME 控件使用相同字体并跟随投影光标，让原生候选窗口保持对齐。设备像素比变化会重建渲染器几何与终端像素尺寸，而不留下过时图集。帧会提交到按有界行分区的结构化数组存储中，且只在安排绘制后才确认。`FrameApplied` 确认客户端已提交，而非绘制已完成。精确重复帧会被再次确认；标识、序列、生成、尺寸无效或增量基准错误的输入会请求完整快照，但不改变已提交网格。

当字体或 GPU 初始化仍处于挂起状态时到达的有效帧仍然是单个提交的打开帧。它的 `FrameApplied` 确认将被保留，直到渲染器准备就绪允许绘制该提交；然后初始化在确认之前安排保留的帧。处置会清除待处理的确认，而不是从已停用的表面发布它。

每个已打开表面都会观察其容器并调整本地内边距、渲染、指针及隐藏输入的几何，即使它只是调整大小观察者而非租约所有者。只有持有当前调整大小所有权的表面才能把该测量转换成 Host 调整大小请求；观察者继续使用 Host 的规范帧几何，绝不会把局部裁剪重新解释成相互竞争的 PTY 几何。`setResizeOwnership` 应用附件作用域的 Broker 事件。升级会清除调整大小去重状态并立即测量现有表面，因此取得所有权无需重新打开附件。

开放附件接受一笔完整的 `TerminalPresentationConfiguration` 交易，其中包含 `fontFamily`、`fontSize`、`fontWeight`、`fontWeightBold`、`fontLigatures`、 `fontMetricModifiers`、`paddingBalance`、`allowTransparency`、`backgroundOpacity` 和 `defaultColorOverride`。覆盖是 `null` 或严格的标准化小写 `#RRGGBB` 前景/背景对。 `backgroundOpacity` 是源中立的 `0..1` 配置值；撰写客户端将其应用到其自己的默认背景根而不是终端表面。对于不参与主机运行时主题事务的客户端，覆盖仍然是源中立的兼容性投影。 Orchbee 的共享 Web/桌面组合始终将其设置为 `null`；它的浅色、深色和自定义选项成为完整的主机拥有的终端主题。没有运行时部分设置器。 `updatePresentationConfiguration` 验证并隔离整个候选者，等待其常规和粗体字体描述，然后在发布任何字段之前准备渲染器测量。请求是最新的胜利：被取代或处置的准备返回类型化取消，并且验证、字体或渲染器准备失败使先前的配置可见。

一次成功的本地提交将替换所有十个字段，重新测量一次，重置字形图集一次，使整个表面无效，并安排一次当前重新绘制。同一提交重新对齐隐藏的文本区域和活动的 IME 预编辑锚点，使几何相关的链接悬停无效，修复本地几何手势而不引入复制效果，并使用当前设备像素比计算最多一个新的调整大小建议。打包行、主机选择、搜索、历史记录、可访问性行和 DOM 选择、附件身份、订阅和后端保持不变；附件和包装存储不会重新打开或重置。主机调整大小完成通过现有的调整大小路径异步继续。因此，提交后渲染或调整大小失败会保留已提交的呈现并遵循现有的类型化恢复。隐藏或暂停的表面保留新的配置，并在演示恢复时绘制一次。

运行时终端颜色与客户端覆盖使用彼此独立的修订屏障。组合客户端在请求 Host 变更前，使用一个操作标识与完整覆盖快照调用 `prepareThemePresentation`。该操作活动期间，帧会被确认到私有打包存储，而不替换可见存储。只有暂存帧携带由 Host 分配的精确 `themeRevision` 时，`waitForThemePresentation` 才就绪；遇到更高修订会失败，而不会猜测它属于哪个快照。同步执行 `canCommitThemePresentation` 预检后，`commitThemePresentation` 在一次客户端提交中交换暂存存储与已准备的渲染器覆盖/光标。元数据监听器与绘制只有在交换后才能观察新修订。被取代、处置、渲染器准备失败或显式中止时，会丢弃或隔离未发布暂存状态，继续显示先前完整呈现。隐藏、暂停或保留历史状态的表面会延迟准备，然后在实时呈现恢复时只显示最新且合格的完整修订。

主机驱动的帧几何结构，包括终端发起的 80/132 列转换，直接更新打包存储和渲染器。应用该快照永远不会发出反向 `ResizeTerminal`；只有测量的容器或设备像素比更改可能会请求新的附件大小调整。

文档可见性和显式呈现需求共同暂停渲染器动画和排队绘制工作。文档隐藏时，WebGPU surface 还会解除 Canvas 配置，并释放每 surface GPU 驻留资源与共享 device lease，同时保留 packed store 和 CPU presentation cache。隐藏期间的提交仍会推进并确认 packed store。恢复可见性时会重新取得当前共享 device generation，并恰好绘制一次最新提交状态；即使显式 presentation demand 仍为 paused，也允许这次恢复绘制，随后独立的暂停原因继续抑制后续绘制。Canvas 2D 的可见性变化仍只暂停计时器与绘制。

`freeze()` 是应用程序恢复切换：它取消输入、面向传输的侦听器、动画、调整大小、搜索和飞行中的副作用，同时保留最后绘制的画布和可访问的行列表。冻结的实例拒绝进一步的框架和命令工作。稍后的 `dispose()` 会在应用程序绘制替换后释放保留的渲染器资源和 DOM。

WebGPU 初始化、可见性恢复与 device-loss 恢复会同时按生命周期 epoch 和可见性 epoch 围栏每次异步完成。在初始化仍挂起时隐藏 surface 会退役该尝试；过时工作会释放尚未提交的 lease 与资源，且不能配置 context、激活 Canvas 后备或发布 renderer health。重新显示本身不会发布后端：必须先完成一次新的可见初始化。

`notifyBrokerFailure` 保留代理的类型代码、语义操作、可重试性、可选 Host 相关性 ID 以及 `onError` 上的可选客户端请求序列。它还应用所拥有的结果：调整大小拒绝重新接纳未更改的几何图形，历史拒绝完成或修复确切的行请求，选择拒绝释放手势调度；过时的在途手势拒绝则会终止完整本地手势、丢弃所有未发送端点，然后被吸收。相关复制或链接失败只完成该副作用。该包永远不会将可重试性转变为自动重放。

渲染器直接消耗打包行。它永远不会重建本地 VT 状态或每单元对象图。绘制完成后，帧遥测记录从可见打包存储中读取的确切提交的主机生成和修订。多个提交可能合并在一个动画帧后面；该检查点命名实际绘制的最新提交，而不是较早计划的修订。

已提交的实时帧元数据将可选的关闭活动扩展映射到 `idle`、`active` 或 `unknown`；缺失、重复和格式错误的载荷会保守解析为 `unknown`。历史行窗口没有实时进程观察，因此保留历史呈现会保留最新实时存储的关闭活动，同时使用历史窗口提供视觉元数据和行。已接受的非焦点按键、文本、粘贴、鼠标或等效原始输入会立即使最新观察失效，并同步发布瞬态 `unknown`；仅焦点输入和同步遭拒的发布不会如此。该覆盖在保留历史、暂存帧、快照请求、失败及处置期间始终具有权威性。新到达的 `idle` 帧可能早在该输入前便已进入在途状态，因此客户端针对其精确序列发送 `NeedSnapshot(activity-stale)` 而非 `FrameApplied`，并保留 `unknown`。下一份完整快照在因果上晚于输入失效，但不证明 Host 接受了输入，也不证明 shell 消费了输入。在协议 `0.0.23` 下，Host 接受的非焦点输入会立即使 Host 缓存失效，而后续当前状态采样可以报告 `active`、`idle` 或 `unknown`。因此，因果上合格的替换帧可以在同一终端生命周期内恢复新鲜的 `idle`。过时的主题暂存帧会在应用时被围栏，不能让暂存阶段就绪；只有因果上合格的暂存帧在其保守呈现实际提交后才会清除本地覆盖。

已提交的实时帧还可以携带有界 Kitty 图形扩展。图形快照会原子替换已解码内存图像资源、已解析放置和单调 animation tick；仅放置更新只有在命名精确的已提交图像修订且 tick 不倒退时才会接受。无效字节或缺失资源引用会拒绝整个终端帧，并在部分提交文本或图形前请求新快照。Canvas2D 与 WebGPU 对每项图像 generation 只转换一次 raw gray/gray-alpha/RGB/RGBA 像素，复用所得资源完成裁剪、缩放和移动，并精确绘制单元格背景下方、背景与文本之间、文本上方三个有符号 z 层。Render-detail OBRW `0.0.3` 会原子替换行及其独立图形快照；text detail 不携带图形。纯文本提交会保留同一个图形标识，因此静态放置不会把原本只需更新脏行的 Canvas2D 绘制扩大为整面重绘。空快照、删除、重置、替换和处置会释放过时像素、Canvas 与 GPU 资源。本包有意不解析 PNG 或 Kitty 命令，不加载路径或共享内存对象，也不解析动画、virtual/relative 放置或历史 pin；Terminal Host 会在自有解码像素和绝对放置跨越协议边界前完成这些工作。

默认情况下，行窗口输入被严格解码。仅当应用程序适配器拥有不可变、同一用户、功能范围的 Terminal Host 传输时，应用程序适配器才可以设置 `projectionBufferTrust: 'local-host'`。该路径保留 OBPB format-`0.0.2` 缓冲区并创建类型化数组视图，而无需重新扫描或重新打包每个单元格。网关、网络、插件和持久输入必须保留默认的 `external` 行为。

## 历史记录、搜索、选择和链接

跟随底部时只保留当前的打包网格。进入历史记录会暂停实时投影，并请求一个有界的 `current-view` 行窗口；其首行是可见逻辑顶部，并带有限的向前过扫描。`RowsApplied` 允许 Host 固定该顶部；只要锚点仍然有效，导航与回流刷新就使用 `committed` 或 `tail` 来源，并以 Host 返回的起始行、当前修订和总行数为权威。普通 PTY 输出可在视口请求在途时推进修订，而不会使其失效。代次变化仍会终止请求；精确修订的搜索页和通用 buffer 页仍保留确定性的陈旧结果处理。当较新的回流事件取代正在进行的视口读取时，该读取完成只会结算旧请求；可读窗口保持可见，而一次事件驱动刷新会使用最新代次和已提交固定点，不向用户呈现已经过时的失败。被取代的后台行读取同样会结算其有界陈旧结果，而不显示用户可见的历史错误。当有效锚点维护刷新与显式视口工作同时等待时，会先派发最新的用户逐行、逐页、滚动条、搜索显露或选择自动滚动意图。它的 current-view 请求使用最新 Host 修订和已提交固定点，因此也满足较旧的维护刷新。历史观察可能与 Host 准入该 current-view 读取发生竞态：同一代次、修订不早于已观察修订的响应会建立更新的 Host 待提交固定点，并覆盖响应之前排队的维护刷新或缺锚恢复。修订晚于响应的缺锚事件仍具权威性，会先恢复到底部，任何排队历史意图都不能抢先运行。清除、屏幕替换、驱逐或其他任何使锚点失效的事件都会恢复底部投影，并由新快照替换最后一个可读历史窗口。

### Agent 尾部行显示

应用可以为一个终端 Presentation 启用仅作用于显示的尾部空白行策略。应用拥有当前
Presentation 是否代表存活 CLI Agent 的判定；本包只接收最终布尔策略，绝不根据进程名、命令或
终端文本推断 Agent。PTY 几何、活动屏幕、光标、保留历史与打包单元格内容仍以 Ghostty 和
Terminal Host 为权威。缺少策略来源等同于 `false`。

模型读取一个已提交的实时主屏幕网格、其可见光标、图形放置、应用鼠标模式与保留行数，且只
分类连续尾部。包含非空白文本、可见光标、图形放置、提示符或行标志、非默认背景、样式标志或
下划线显示的行都不为空。备用屏幕及应用鼠标跟踪期间禁用该策略。

| 条件                                               | 显示结果                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------------------- |
| 策略关闭、备用屏幕、应用鼠标活动或没有安全空白尾部 | 显示精确实时网格。                                                               |
| 存在安全尾部，但保留历史短于该尾部                 | 仅替换保留行能够填充的尾部行数；绝不把空隙移到顶部。                             |
| 存在安全尾部，且保留历史充足                       | 请求一个在可移除尾部之前结束的精确 Host tail 窗口，并显示返回的完整高度窗口。    |
| 读取失败、过时、被取代或其锚点失效                 | 结算所有 Host 行确认，丢弃候选，并回退到精确实时网格，直至之后的实时帧可以重试。 |

结果是 Presentation 窗口，而不是 VT 变更：它绝不改变 PTY 行数、Ghostty 状态、保留历史、帧
确认或终端输出。内部空白行会保留，且至少留下一行实时行。已提交的语义尾部窗口使用 Host 历史
锚点解析选择坐标，同时实时投影保持活动；其光标从同一个实时帧重新映射。键盘输入继续指向实时
终端。手动历史导航会接管该窗口；关闭策略、失去存活 Agent 资格、屏幕或代次变化、调整大小或
处置，都会恢复普通的跟随底部状态。无障碍行、链接、搜索、选择、滚动条与隐藏输入几何都消费
同一个已提交可见窗口。

选定的差分行为参考是 Warp 修订 `086dade63ff7327426d6276d57f85b3f2f313af0`，范围仅限
`app/src/terminal/cli_agent.rs`、`app/src/terminal/view.rs` 与
`app/src/terminal/model/blockgrid.rs` 所表达的可见尾部思路。Orchbee 保留 Host 投影行窗口架构；
Warp 的 block 模型、功能开关机制、像素几何、光标策略和鼠标行为不属于该声明。确定性策略测试
覆盖每种内容信号与无操作边界；投影终端测试覆盖精确窗口准入、光标重映射、失败回退、运行时
关闭、备用屏幕与应用鼠标排除，以及向手动历史的交接。

选定的差分行为参考是 Ghostty 源码修订 `9c3ec931d64561a8407dde7ac984ce156ae91539`，具体包括 `Surface.scrollCallback`、`Termio.scrollViewport` 与 `PageList.scroll`，并单独与本地 ZeroGH 0.1 (1) 构建进行交互检查。对齐范围覆盖进度与滚轮呈现：输出推进时，有效固定的主屏幕视口会继续接纳历史移动；每个已准入的整行滚轮增量都会在下一次渲染前提交所得视口，不增加客户端自有的快照、transform、缓动曲线或合成惯性。Orchbee 仍保留 Host 投影的行窗口架构；精确像素、传输延迟、操作系统惯性事件及备用屏幕应用输入不属于该差分声明。

滚轮像素、行与页增量会累积到能够产生完整终端行。每个已准入的主屏幕移动随后委托给与编程式导航相同的 Host 权威历史意图工作流，下一份已提交行窗口会立即替换规范 Canvas。客户端不增加动画阶段；只有平台继续提供滚轮事件时才存在惯性。逐行、逐页、到底部、滚动条、搜索显露及选择自动滚动导航都遵循同一即时呈现规则。

保留的历史记录公开了客户拥有的 DOM 滚动条覆盖层，该覆盖层位于整个终端视口而不是安装的单元格网格画布上。其最右边的16个CSS像素构成交互区域；一个 8 CSS 像素宽的全圆角滑块与面板相对右边缘正好保持 2 CSS 像素，与未使用的网格剩余像素无关，并保留 4 CSS 像素的垂直轨道填充加上 20 CSS-pixel 最小高度。历史导航和滚动条交互使其立即可见，并且不活动会在 1,500 毫秒后消除其不透明度。轨道按下会按比例跳转，捕获的滚动条拖动会合并为有界、相对于尾部的 `current-view` 行窗口请求。发起主指针拥有拖动直到其结束；并发和辅助指针事件和滚轮输入将被消耗，而不替换其捕获或锚点，并且其合成的释放点击被消耗一次。滚动条所有权优先于应用程序鼠标报告、选择和链接，并在无按钮移动、取消、捕获丢失、焦点或可见性丢失、重置和处置时进行修复。拖动期间的导航使拇指完全可见，并且仅在所有权结束或修复后才开始淡入淡出延迟。滚动条覆盖层和画布保留 `aria-hidden` 且不暴露 DOM 滚动条角色；现有键盘和 API 历史导航仍然是可访问路径。

搜索归客户端所有。首次非空查询会惰性创建一个 Worker，并通过来源中立的行读取器流式取得有界文本详情页。管道绑定一个 Worker 页与一个预取行请求；页面额度会刷新空闲看门狗，16 MiB UTF-8 来源上限会得到一个完整不可变结果或明确不匹配。视口、搜索和通用缓冲区读取使用彼此独立的单飞行通道，因此滚动或链接检查不会取消搜索页；请求序列关联允许响应以任意顺序结算，同时把客户端并发行读取限制为三个。查询输入使用 50 毫秒尾沿 debounce。修订失效则保留已经调度的期限，并让已准入的精确修订扫描结算而不取消。只有行读取器的 generation 与 revision 仍等于捕获来源时，结果才会发布；已失效结果或过时、已驱逐页面不发布任何内容，保留已接受的导航，并在 200 毫秒后只调度一次被动刷新。因此重复输出既不能通过重置刷新期限来推迟准入，也不能重新启动已准入扫描。完成仍要求一次精确修订尝试在下一次修订变化前结算；不同修订的页面绝不会混合。防抖或扫描期间请求的导航会跨同一查询的修订失效继续排队。被动修订刷新只更新结果，不会再次定位活动匹配项，因此手动到达实时底部后能保持稳定；已排队或之后显式发起的导航仍会定位目标。装饰数量与结果计数设有上限；定向导航则从最新 Host 选择锚点独立扫描已准入的保留搜索域并循环，不把装饰上限误当成最终匹配上限。活动匹配单独报告，并通过带修订约束的 Host `set-range` 命令选中；显式查询和导航即使目标不在装饰集合中也会显示它。无论焦点在查找界面还是终端输入，活动与普通搜索配色都优先于重叠的 Host 选区配色，同时活动配色仍保持独立。选区配色会将低饱和蓝色强调色以 40% 混合到有效终端默认背景上，并使用其有效默认前景色。查询文本与匹配项绝不会进入 Terminal Host 或 Electron Broker。

增量查询变化只有一个视觉提交边界。`searching` 事件会更新状态，但不会替换渲染器上一次已提交的装饰，也不会清除搜索拥有的活动选择。下一份完整结果会在同一个 JavaScript 轮次内同时替换二者；完整的无匹配结果、无效查询、超时、搜索不可用、显式清除或处置则会移除它们。这样，50 毫秒防抖和异步 Worker 扫描就不会在相邻查询字符串之间呈现空白高亮帧，同时状态与结果计数事件仍绑定到当前请求的查询。

上一个和下一个提示符导航遵循有界的 [Kitty 对齐契约](docs/kitty-prompt-navigation-alignment.zh-CN.md)。它从当前可见顶部开始，通过通用缓冲区通道按最近优先顺序扫描 Host 编写的 OSC 133 行类别，并且只有主屏幕、固定快照、选中的可见锚点或同一意图的修订滞后修复锚点，以及本地历史意图仍为当前时才会提交。每次调用最多接纳 16 MiB 编码行窗口。缺少标记、备用屏幕使用、到达边界、来源耗尽、替换、取消以及过时或不可用读取都会保持视口不变。该包不会注入 Shell Integration，也不会从终端文本推断提示符。

已聚焦终端的逐行、逐页、顶部和底部快捷键遵循有界的
[Kitty 键盘回滚对齐](docs/kitty-keyboard-scrollback-alignment.zh-CN.md)。终端仅在主屏幕上接纳它们，
翻页时保留 Kitty 的一行重叠，并把每个请求委托给现有的 Host 权威历史意图工作流。到达边界会产生
不变的本地结果；备用屏幕快捷键仍留给终端应用。

可见键盘 Hints 遵循有界的
[Kitty 键盘 Hints 对齐](docs/kitty-keyboard-hints-alignment.zh-CN.md)。每次调用只读取固定的可见行窗口，
排除被视口边缘截断的逻辑行，并最多为 512 个允许的 URL、路径、文件位置与小写十六进制 hash
添加标签。overlay 在选择或取消前拥有标签按键事件。`ProjectedTerminal` 返回选中的类型化目标；
应用负责打开 URL，或通过普通 paste 边界插入精确文本。

上一条命令输出的准备遵循有界的
[Kitty 命令输出查看器对齐](docs/kitty-command-output-viewer-alignment.zh-CN.md)。一次主屏幕调用会捕获
通用缓冲区的精确 generation 与 revision，从新到旧扫描 Host 编写的 OSC 133 提示符行，并只把已写入的
输出语义 cell 作为不可变纯文本 document 返回。软换行保持连接，硬行变成换行符。取消、过时、淘汰、
缺少 Shell Integration、备用屏幕使用、畸形页面、传输失败与 16 MiB 聚合来源上限都保持为类型化结果，
且绝不发布局部内容。应用拥有查看器、搜索、复制 Action 与剪贴板效果。

完整保留历史的准备遵循有界的
[Kitty 回滚历史查看器对齐](docs/kitty-scrollback-viewer-alignment.zh-CN.md)。一次主屏幕调用会从一个精确
generation 与 revision 开始，按从旧到新顺序读取 text-detail 行、连接软换行、保留硬边界，并返回一份
带有捕获可见顶部精确 UTF-16 偏移的不可变纯文本 document。取消、过时、淘汰、备用屏幕使用、畸形页面、
传输失败与 16 MiB 聚合来源上限都不会发布前缀。应用拥有的 terminal-text viewer 提供搜索、初始定位、
按来源复制 Action 与焦点恢复，且不改变实时终端历史。

```ts
terminal.scrollPages(-1);
terminal.scrollToTop();

terminal.findNext();
```

选择端点和导出内容仍以 Terminal Host 为权威。浏览器不信任 DOM 点击计数，而是根据 500 毫秒间隔与一个单元格的界面距离上限推导单击、双击或三击序列，再发送已捕获代次、有界的视口相对单元点、界面位置与单元格几何，以应用 Ghostty 的单词、行、矩形以及单元格内 60% 端点规则。Host 在处理时相对于当前活动视口或附件已提交的历史锚点解析该点，因此持续修订变化不会饿死手势。普通单击不会合成一个单元格的选择。拖动超出视口时，会通过有界行窗口请求推进保留历史，并在新显示的行上继续同一个 Host 手势；指针捕获不可用时，文档级移动与释放后备路径保持该行为。按住辅助修饰键三击可选择 Ghostty 的语义命令输出，拖动则跨输出块扩展选择。默认只有普通的主指针释放会完成手势并请求复制。即使最初的按下回复仍在处理中，串行命令队列也会在释放前保留最近一次合并后的拖动更新。代次过时的在途回复会静默取消完整本地手势、丢弃未发送的更新与端点、停止自动滚动、释放指针捕获、保留最新 Host 选择且不执行自动复制；下一次指针按下会开始一个新手势。当浏览器仍拥有已捕获指针时，匹配的无按钮移动不会推断释放或取消手势；即使没有可用的中间拖动更新，显式主按钮释放仍会提供最终端点。指针取消或捕获丢失、界面焦点或文档可见性丢失、Presentation 几何替换、屏幕变化和锚点淘汰，都会取消已固定的手势，但不会复制或清除最新有效 Host 选择。串行化的手势回复确保一次正常释放或取消只产生一次复制结果；构造时的 `copyOnSelect: false` 与运行时的 `setCopyOnSelect(false)` 都会关闭正常释放时的复制。应用自有的剪贴板效果结算后，每个已接纳的自动或手动复制都会通过 `onSelectionCopyResult` 发布带来源标记的完成或失败。程序化范围与语义输出选择仍是精确修订操作，并使用绝对 `bigint` 行。`adjustSelectionEndpoint` 保留 Host 最近发布的起始端点和矩形模式，只替换活动结束端点；它绝不会在客户端重建 Ghostty 文本语义。

隐藏的 textarea 是唯一的浏览器编辑与 IME 所有者。选择和原生粘贴遵循以下所有权模型：

| 浏览器来源                                                      | 权威状态与 DOM 状态                                               | 转换与输出                                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 指针、程序化或搜索拥有的终端选择                                | Host 端点保持权威；Canvas 与无障碍描述对其进行投影                | 绝不创建或替换文档全局 DOM Selection，因此 textarea 仍是原生输入所有者                                          |
| 完全位于可见无障碍行内的非折叠 DOM Range                        | 文档 Range 是辅助技术来源，并且仅在仍位于当前界面内时由该界面拥有 | UTF-16 偏移跨组合、宽字符及代理对字素映射为一条显式 Host 单元格范围命令；精确的 Host 确认可仅规范化该自有 Range |
| 目标为 textarea 或 package 自有终端 Presentation 后代的原生粘贴 | 在既有粘贴策略准入前，剪贴板 MIME 数据仍由浏览器拥有              | 精确执行一次共享文本/图片粘贴路径并停止传播；textarea 交付不会再被 root 后备路径处理                            |

指针或非辅助技术程序化选择会先清除仍由无障碍投影拥有的 Range。文档全局 Range 移到其他界面，或在同级焦点期间消失时，当前界面只放弃其无障碍所有权；附件的 Host 选择和 Canvas 覆盖仍保持活动。界面或窗口失焦时，会在浏览器折叠 Range 前同样放弃所有权，因此这种仅属 Presentation 的折叠不能发布 Host 清除命令。搜索拥有的选择遵循普通 Host 选择行，因此绝不占用文档全局 Range。构造时没有输入权限或动态降级的附件，仍让隐藏 textarea 可获得焦点，但原生保持只读。仅 Shift 的翻页导航、滚轮历史、搜索、选择、复制与已批准链接，在没有 Host 输入能力时仍然可用；防御性的 `beforeinput`、输入法组合、粘贴、按键和鼠标监听器负责拒绝浏览器编辑并清除残留输入状态，不发出 PTY 输入。经过身份校验的自然退出结果会永久封存 PTY 输入、清除、重置与 resize，并把现有 textarea 设为只读。保留的最终帧和本地输出交互在处置前仍可使用。应用负责执行剪贴板副作用，并且只报告其结果。

经过身份检查的运行时失败结果应用与自然退出相同的终端控制密封：PTY 输入、清除、重置和调整大小立即变得不可用，而保留的输出、历史记录、搜索、选择、复制和批准的链接交互仍然可读。

终端发起的剪贴板写入使用单独的事件路径。 `ProjectedTerminal` 仅接受对其精确附件的模式验证请求，抑制重复或过时的序列，并将有界文本发布到应用程序而不执行效果。处置会删除侦听器并阻止以后传递。应用程序必须拥有提交策略和平台剪贴板功能；选择副本不会隐式提交 OSC 52 请求。

帧元数据公开一个严格解码的当前进度样本。打包存储以原子方式随帧提交 `remove`、`set`、`error`、`indeterminate` 或 `pause`，并默认将不存在的扩展名设置为 `remove`。贝尔仍然是一个单独排序的依恋事件。 Progress 和 Bell 都不会改变终端生命周期、输入可用性、焦点或应用程序通知策略。

帧元数据还公开最新的严格解码的语义命令完成（如果存在）：终端本地序列、持续时间毫秒、挂钟完成毫秒和标准化退出代码。打包存储从不重建或保留命令文本。它仅以原子方式提交主机事实；该应用程序拥有新鲜度、焦点、重复数据删除、速率限制、权限和任何通知效果。

链接发现扩展了有界生成/修订固定的行读取，直到它具有一个完整的软包装逻辑行。允许的行受到协议行、单元和字节限制的限制；超出限制线不会产生部分检测。OSC 8 目标和 OSC 133 单元/行语义来自 Host 拥有的 Ghostty 状态；此 package 永远不会重新解析其转义序列。显式链接优先于检测到的 URL 和路径文本。自动 URL 检测仅允许 `http`、`https` 和 `mailto`；`normalizePermittedExternalTerminalUrl(...)` 是 Workbench Action 和 Browser effect adapter 再次使用的公共策略操作。不受支持的显式 OSC 8 metadata 与检测到的 filesystem target 可以保留在有界链接缓存中。调用者必须向单个 attachment 明确授予本地 filesystem link capability，filesystem target 才能获得活动 pointer 样式、产品 context、activation 或 image-preview intent；Browser、Gateway、archive 和 source-neutral default attachment 均不授予该能力。内容 revision、viewport transition、surface resize、device-pixel-ratio 变化、presentation geometry 变化、application-mouse ownership 与 gesture transition 都会使 hover cache 失效。修饰键辅助的单击会重新验证 hover 的 generation、revision、hover epoch、点击 cell、精确 typed target 与当前 capability，之后 `ProjectedTerminal` 才会发出一个已批准的 URL 或本地文件请求。应用决定是否以及如何执行该 effect。此 package 永远不会读取路径或调用操作系统 opener。

### 本地文件系统链接与图片预览模型

本地 filesystem 交互是现有 typed link cache 上按 attachment、默认关闭的投影。URL 保留 `http`/`https`/`mailto` 策略。启用的本地文件或目录在 Apple 平台使用 Command 加主键单击，在其他平台使用 Control 加主键单击；普通主键拖动仍属于终端选择，application mouse tracking 继续拥有交互，除非 Shift 把手势交还产品。相对路径会先按 generation-pinned current directory 解析，再暴露 target。引号和 escape 路径语法只影响检测；effect boundary 接收规范化路径，并把它作为不可信输入再次验证。

只有支持 hover 的 fine pointer 位于检测到的 PNG、JPEG、GIF、WebP、AVIF 或 BMP 路径上时，才可进入图片预览 workflow。300 毫秒 dwell 是可逆 intent，而不是 activation。它不会探测普通路径、改变 selection、取得 focus、捕获 pointer 或创建持久 cache。应用可从可选的本地 Desktop capability 返回最多 8 MiB、经过独立验证的 raster bytes。SVG、HEIC、TIFF、未知、超限、缺失、非普通文件与无法解码的内容都不会产生卡片，也不会通过 hover feedback 暴露 filesystem 详情。

| 状态          | 已接受的转换与输出                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `idle`        | 没有当前合格图片 target、timer、request 或 card。                                                             |
| `waiting`     | 一个当前 revision-pinned image target 拥有 dwell timer；target replacement 或任何 retirement 都返回 `idle`。  |
| `loading`     | dwell 到期后为该精确 target 与 request identity 启动一个请求；replacement 会取消它，并可启动新的 `waiting`。  |
| `visible`     | 当前 request 的有效 bytes 产生一个锚定当前 cell 且 pointer-transparent 的 card；终端与产品 focus 都不会移动。 |
| `unavailable` | 当前失败在该 hover membership 内保持静默，只在 replacement 或 retirement 后返回 `idle`。                      |

最新 hover membership 是权威。Pointer leave、pointer down、wheel、key input、selection start、application-mouse takeover、revision 或 geometry change、attachment replacement、document retirement 与 disposal 都会取消 waiting/loading work 并隐藏 visible content。延迟、重复、失败或乱序 completion 只有在 attachment、request identity、target、generation、revision、link epoch、row 与 column 仍与当前 hover 相同时才可变为 visible。[图片预览模型](formal/README.zh-CN.md#图片预览新鲜度)在 cancellation、replacement 与 reordered completion 下检查此安全声明。对操作系统 filesystem completion 不作 liveness 声明；即使底层 read 无法同步停止，cancellation 对 presentation 仍是权威。

纯文本拖入遵循与粘贴相同的清理、审查、排序和 Host 输入路径。`file-drop` 粘贴来源遵循相同
的风险策略，但来源本身不会强制审查：安全的单行文本会直接发布，control、嵌入的 bracket
terminator 与未受保护的多行输入仍遵循普通审查规则。文件路径的解析与安全准备仍由应用拥有的
capability 负责，因此本 package 不获得 filesystem 权限。

离屏辅助功能镜像是一个标记为 `list` 的直接 `listitem` 行保留空格、字素到列的映射以及绝对 `aria-posinset`/`aria-setsize` 位置。它使用调用者提供的本地化文本来标记行和光标。单独的礼貌状态区域仅宣布更改的可见输出，包括本地化删除通知。保留历史记录检查禁用实时更新而不替换实时输出基线，因此返回到底部仅宣布自上一个实时帧以来更改的输出。

## 渲染器行为

条件允许时优先使用 WebGPU；Canvas 2D 是可观察的后备。两条路径使用相同的打包投影、字体配置、应用拥有的选择/搜索覆盖、预编辑状态和光标元数据。Host 帧元数据保持权威且不被修改。非空客户端 `defaultColorOverride` 只改变打包前景或背景 token 为 `TerminalColorEncoding.default` 的单元格；显式 RGB（包括黑色）、Host 投影调色板 RGB 与 `none` 保持其 Host 投影语义。反色会交换已经解析的显示角色；默认下划线使用有效前景色；光标始终使用 Host 光标颜色，并以 Host 前景色后备。显式客户端光标强调色只影响块光标内的文本。该覆盖位于带修订的 Host 主题路径之外，在共享 Orchbee Web/Desktop 组合中始终为 `null`。`allowTransparency` 只控制透明渲染器的清除方式；组合客户端将 `backgroundOpacity` 用作有效默认背景根，绝不为整个表面应用 CSS opacity。新打开的 Canvas 会保持透明，直到绘制注入的语义呈现快照或首个实时帧，之后以最新有效默认背景进行不透明填充及调整大小。打包字素保留 CJK、组合与 emoji 单元格宽度；显式前景/背景和下划线颜色、反色、粗体、微弱、斜体、不可见、闪烁、下划线变体、删除线和上划线都使用投影中的 Ghostty 样式。渲染器健康状态报告初始化、后备、设备丢失、恢复及恢复失败。

`capturePresentationSnapshot()` 只公开最近一次完成绘制所精确表示的打包来源与元数据。如果较新的 Host 提交已被接受但尚未绘制，捕获会返回空，直到该 revision 完成绘制；它绝不会把未显示的状态标记为可见。捕获的快照不可变且仅用于显示，在可行时结构共享不可变行 backing，统计其保留字节，并包含可见图形资源与 placement。打开新的 `ProjectedTerminal` 时传入快照，会在计划中的实时渲染前先绘制它，但这次绘制不会发出实时帧 telemetry 或 acknowledgement，也不会授予 attachment、输入、resize、transport、元数据发布或持久状态权威。缓存绘制完成后，终端会释放其 opening reference；外部有界缓存仍可为后续呈现保留该快照。

`isPresentationGeometryCurrent()` 会使用与 resize 提交相同的网格、padding、单元格、DPR、协议及 PTY 像素上限规则，同步测量当前已挂载 surface，并与最近一次完成绘制所表示的 metadata 比较。在尚无绘制、surface 无法测量，以及布局、presentation configuration 或 DPR 已改变但匹配的 Host 帧尚未绘制时，它返回 `false`。只有注入的显示快照精确几何已经匹配目标 surface 时，该快照才可能通过比较。该查询只读：它绝不调整 canvas、提交 PTY 几何、确认帧或授予输入权。应用交接可以据此保留旧的有意义图层，直到目标 canvas 可以安全提交。

同一 `Document` 中的渲染器共享 WebGPU adapter 获取、device 创建、首选 format，以及不可变的背景/文本 pipeline 对。每个已配置 renderer 拥有自己的 glyph atlas texture、sampler、uniform/vertex buffer、bind group、Kitty texture、可重建 CPU staging，以及一项可分离的共享 runtime lease。文档隐藏会解除该 Canvas 的配置、销毁这些每 surface GPU 资源、清空峰值大小的 staging array 并释放 lease；renderer 保留 packed source、原始图形数据、glyph map 与 CPU atlas Canvas，因此恢复可见性时可以重建而不改变终端状态。同一可见性 epoch 也会退役挂起的初始化。`freeze()` 的语义不同：它为应用恢复切换保留已绘制 Canvas 及其资源。device 丢失会使 document generation 失效；每个受影响的可见 renderer 都会针对下一共享 generation 走类型化恢复路径，Canvas 2D 仍是可观察后备。共享 runtime 拥有该 generation 唯一待定的 `GPUDevice.lost` reaction。释放 lease 时会先移除 subscriber，再减少引用计数；释放最后一个可见或冻结 lease 会销毁 device 并丢弃共享 pipeline。按 `Document` 索引的 weak map 只负责并发发现，因此隐藏或非活动终端既不保留 GPU surface，也不保留原本空闲的 device。

打包来源仍是唯一的终端内容权威。WebGPU 行准备只为当前可见网格保留可重建的 shaping 以及背景、文本和覆盖层实例分段。只有当打包行并非 dirty，来源 identity、shaping 输入、已解析默认颜色、atlas generation 与该行局部的光标投影仍一致，且没有待处理的全局呈现失效时，条目才可复用。dirty 行会从打包来源重建；移动光标会重建旧行和当前行。完整 Host 重绘、surface 或字体几何变化、主题发布、设备像素变化、选择、搜索、preedit、文本闪烁或链接悬停变化，都会保守地使所有受影响的已准备分段失效。atlas 重置或增长会使全部缓存文本 UV 失效。缓存范围由可见行及其当前紧凑实例载荷限定，并且绝不参与 `markRendered()` 权威。

每个 WebGPU 实例流都会保留行分段 identity 与长度、一个按几何级数增长的 `Float32Array` 镜像，以及一个按几何级数增长的 GPU vertex buffer。当变化的行分段长度保持不变时，只会复制并通过 `writeBuffer` 提交对应的精确紧凑区间。第一次长度变化会移动后续紧凑偏移，因此该流会从该行开始重写后缀；新建或增长的 GPU buffer 会接收一次完整上传。未变化的流不会上传 vertex 数据，但 render pass 仍会把其完整紧凑实例数量绘制到当前 swapchain texture。device 丢失会销毁 GPU buffer，因此即使 CPU 行准备仍然存在，下一次可见绘制也会完整上传。文档隐藏停车与处置都会释放全部行准备和峰值大小的 staging 存储；下一次可见完整绘制会重建它们。

逐单元格的前景色/背景色解析会复用一个 renderer 自有的暂存投影，行准备只复制必须比当前单元格存活更久的值。这些规则把保留的 CPU staging 限制在已准备视口内容的峰值内，并在不改变绘制顺序、像素、Canvas fallback 行为或 device-loss 恢复的前提下减少准备与上传工作。它们不定义 GPU 驱动、浏览器、真实 GPU 执行时间或整个进程的 RSS 上限。

脏字形图集矩形会直接从 Canvas 图集传输到 WebGPU 纹理，因此增量上传不会具体化中间 CPU 像素数组。帧遥测会在接纳或重置字形时维护图集占用量，而不是重新扫描字形映射。隐藏的 IME textarea 会在几何变化之间复用 Canvas 相对于界面的偏移。当注入的仅展示快照仍是已绘制来源且尚无实时 Host 帧时，该快照只为其已绘制光标提供锚点几何，仍不授予输入权威。界面会在调整大小、设备像素比或呈现配置变化后，以及 macOS Shift 原生输入模式处理前重新测量该偏移。

字形图集的两个轴都从 1024 个物理像素开始。因此，在浏览器和驱动开销之外，它的 CPU Canvas backing 与配套 RGBA8 GPU texture 具有 8 MiB 的名义像素载荷。接纳一个完整光栅预留时，只会分别倍增当前边界不足的轴，并以设备纹理上限为界；因此，整行塑形可以使用更多宽度，而不会同时倍增未使用的高度。2048×1024 图集的合计名义像素载荷为 16 MiB。缓存重置会清空条目但保留当前图集尺寸。文档隐藏停车会保留 CPU atlas 与 glyph state，但销毁其 GPU texture；恢复时把整个 atlas 标记为 dirty 并上传到新 texture。冻结会保留最后呈现的 Canvas 与资源；处置则会解除 WebGPU Canvas 配置、销毁每 surface GPU 资源、清除 glyph state，并把 renderer 自有 atlas Canvas backing 重置为零像素。这些约束只限定图集与生命周期分配，并不构成 GPU 驱动、浏览器或整个进程的 RSS 上限。

用于 uniform 和图集资源的 WebGPU bind group 会持续存活到其所属设备或图集被重新创建，而不是随每个提交帧重建。打包行视图还会在当前 backing 的生命周期内缓存已解码的非空字素，让无障碍与渲染共享一次 UTF-8 解码；替换行 backing 时会清除该缓存。缓存范围由当前保留网格中的单元格数量限定。

WebGPU 字形塑造段会按设备纹理上限、设备像素比、单元格步进、图集内边距和字形墨迹外伸余量推导出的终端列容量进行分片。普通段保留完整的塑造边界；超过单个图集条目的行会作为有序的有界段发出，因此设备上限不能静默删除有效的投影文本。Canvas 字形塑造不受 WebGPU 纹理容量限制。

字体测量以大的 CSS 尺寸对选定的浏览器表面进行采样，以恢复其未舍入的前进、上升、下降和大写高度比率。网格宽度和高度保留稳定的 CSS 几何形状，而基线在两个后端光栅化之前以当前物理设备像素比进行舍入。这可以防止 CSS-first 舍入将 high-DPI 字形相对于 Ghostty 移动一个物理像素。

每个 Canvas 字体上下文都请求 `geometricPrecision` 文本渲染，包括 WebGPU 字形图集、其增长后的替换以及 Canvas 后备。这会抑制 Chromium 的小尺寸易读性加厚，并匹配 Ghostty 的未加厚 CoreText 覆盖范围，而无需更改所选的可变字体轮廓或配置的粗细。

浏览器字形塑造批次只包含单列 Host 单元格。宽 CJK、表情符号与其他后备字素会从其权威起始单元格光栅化一次，而不继承后备字体面的自然批次步进；延续单元格也不能吸收后续组合簇。在每个窄单元格批次内，Canvas 字母间距会补齐字体面自然小数步进与取整后终端单元格宽度之间的差值。这样，即使终端样式边界切分一行，也能保留复杂字形塑造与编程连字，而不会累积网格漂移。WebGPU 图集条目会让纹理四边形保持在物理像素边界上，同时在光栅内部保留横向亚像素裁剪余数。因此，光标字形塑造边界可以改变批次首字形的墨迹边界，而不会移动其共享单元格基线；只有有意的连字重塑才会改变字形几何。基础前景变化与选择/搜索覆盖会复用原始塑造批次，在单元格边界裁剪，并只为覆盖部分重新着色。因此，移动的动画前景边界不会改变字形光栅或原点；字体、样式、下划线与彩色字形分类仍是字形塑造边界。

Ghostty 仍然是选定字体规格、形状边界、完整 Unicode sprite-face 路由、光标几何形状和终端面板渲染行为的参考。确定性生成的数据提供来自 Ghostty 的四个填充奇数/偶数度量参考栅格的每个固定精灵，而选定的精灵在这些参考几何图形之间按程序缩放。该引用不会使该包成为 Ghostty VT 所有者。维护来源记录在[`docs/ghostty-surface-test-provenance.md`](docs/ghostty-surface-test-provenance.md)中。

搜索行为遵循 [`docs/vscode-search-alignment.md`](docs/vscode-search-alignment.md) 中的有界契约。应用程序拥有查找界面、查询历史记录、快捷方式和本地化标签。

### 光标闪烁演示

主机光标元数据对于光标坐标、可见性、形状以及是否启用闪烁仍然具有权威性。渲染器仅拥有本地闪烁阶段及其 530 毫秒计时器。提交的坐标更改立即在其可见阶段呈现启用的闪烁光标并重新启动该计时器；因此，在一个时间间隔内重复更改会保持光标可见。未更改的坐标永远不会重新启动计时器，因此光标在一个空闲间隔后会在可见和隐藏之间恢复交替。禁用闪烁会停止计时器并使光标可见。暂停渲染器会停止可见阶段的动画，然后恢复会开始一个新的间隔。没有重点的演示仍然是一个不闪烁的空心块。

该呈现逻辑观察已提交的 Host 坐标，而非键盘意图：未移动光标的输入不会产生效果，由终端输出造成的光标移动则具有相同的重置行为。它绝不会改写 Host 元数据或引入第二套光标坐标。确定性渲染器测试控制计时器，并覆盖从隐藏到移动时恢复可见以及首次空闲切换；Host/配置光标模式证据保持独立。

### 终端操作上下文证据

## 开发

从仓库根目录运行：

```sh
pnpm --filter @orchbee/terminal typecheck
pnpm --filter @orchbee/terminal build
pnpm --filter @orchbee/terminal test
pnpm --filter @orchbee/terminal benchmark:renderer
pnpm --filter @orchbee/terminal test:tla
pnpm --filter @orchbee/terminal test:exports
pnpm verify
```

`test:tla` 检查 [`formal/README.md`](formal/README.md) 中记录的包拥有的运行时表示和输入修复模型。它们是更改触发的正确性证据，不是普通包测试命令的一部分。

`benchmark:renderer` 会针对稳定帧、单个变化行与移动光标，测量确定性的 JavaScript WebGPU 行准备和模拟队列提交。它是用于同一机器前后对比的诊断工具；不测量真实 GPU 执行、浏览器调度、字体光栅化、驱动内存或整个进程的 RSS。

当 `../ghostty` 或 `GHOSTTY_SOURCE` 可用时，`pnpm audit:ghostty-panel` 将维护的渲染器/字体出处和生成的数据与固定的 Ghostty 源进行比较。仅当固定的 Nerd Font 约束、精灵范围或精灵参考栅格更改时才运行 `pnpm generate:ghostty-panel-data`。
