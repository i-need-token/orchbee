# VS Code 终端搜索对齐

## 产品合同

`ProjectedTerminal` 在搜索有界、Host 提供的文本页面而不是本地 VT 缓冲区时遵循 VS 代码集成终端查找模型。

| 行为     | Orchbee合约                                                                                                                            |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 增量输入 | `updateSearch()` 在 50 毫秒后沿防抖上运行。较新的查询会取消挂起的查询、其接受的导航偏移量及其行读取。                                  |
| 导航意图 | 去抖或扫描期间请求的导航被接受为带符号的偏移量，并在不可变结果可用时应用；相同查询修订无效会保留该偏移量。                             |
| 导航     | `findNext()` 和 `findPrevious()` 从 Host 选择锚点导航并环绕已承认的保留搜索域，独立于有界装饰集合。                                    |
| 搜索模式 | 可用字面（Literal）、区分大小写、全字与 JavaScript 正则表达式模式。无效的表达式会产生显式结果错误。                                           |
| 匹配枚举 | 匹配项不会重叠，并按完整匹配推进。软包装行仍然是一个逻辑行；仅当启用 `spanLines` 时，才会跨越硬换行符。                                    |
| 结果状态 | `onSearchResults` 报告查询、有界匹配、独立活动匹配、其有界集合索引（如果存在）、修订/生成、验证、生命周期状态和上限。                  |
| 高亮绑定 | 默认情况下，装饰和结果计数最多收集 20,000 个匹配项。 `maxResults` 可能会降低但永远不会提高该界限。                                     |
| 源绑定   | 一次扫描最多允许 UTF-8 行文本中的 16 个 MiB。超过该界限会使整个不可变扫描失败，而不会发布部分匹配项。                                  |
| 看门狗   | 如果十秒内没有完成行读取或 Worker 页信用，将扫描退役（retire）为 `timeout`；稍后中止或 Worker 结果无法替代该最终状态。                       |
| 修订变更 | Host 修订变化会取消过时工作，并在独立的 200 毫秒刷新防抖后重新启动最新的非空查询。刷新后的结果会保留视口，除非有已排队的导航需要结算。 |
| 空输入   | 空查询会取消行读取、终止活动扫描、清除修饰并返回到空闲状态。                                                                           |

应用程序查找界面拥有快捷焦点、选择播种、模式控制、结果计数呈现、查询历史记录和本地化的可访问标签。 `@orchbee/terminal` 拥有有界匹配、导航、装饰状态、结果事件、取消和去抖。

## 数据流向和权限

第一个非空查询延迟创建一个一次性 Worker。源中立的阅读器通过一个正在运行的有界行请求来流式传输修订和生成固定的文本详细信息行窗口。 Worker 扫描完整的逻辑行，同时客户端最多预取下一页。generation/revision 固定的页面信用放行该预取并刷新不活动看门狗，因此快速行读取无法在 Worker 的 16 MiB 全有或全无决策之前对无限源进行排队。 Worker 仅保留有界装饰集合加上一个定向主动匹配。客户端会通过 Terminal Host 选择每次结算后的活动范围。显式查询或导航动作还会显示其绝对行；同一查询的被动修订刷新只更新选区和结果，不会再次定位该匹配项。超出装饰上限的活动匹配的 `activeIndex` 为 `-1`，而不会变得不可到达。

Host 选择与 Canvas 覆盖仍是权威状态，但活动搜索匹配不会占用文档全局 DOM Range。因此，应用拥有的查找输入框会在增量结果结算期间保持键盘焦点。当任一搜索装饰与 Host 选区重叠时，对应的搜索配色优先显示；活动搜索配色仍与普通匹配不同，且该优先级不受焦点属于终端输入还是查找界面的影响。选区配色会将低饱和蓝色强调色以 40% 混合到有效终端默认背景上，并使用其有效默认前景色，从而在浅色、深色、Host 和自定义终端主题中保持对比度。

查询文本和匹配项保留在渲染器客户端中。它们从不进入 Electron Main 或 Terminal Host。因此，搜索无法检查从 Host 历史记录中逐出的行，并且它永远不会从 GPU 状态重建内容。

窄 ASCII 页面使用其字节/UTF-16/终端列标识映射，而不具体化每个单元的映射对象。 Unicode、宽字和组合字素保留显式映射，因此可以将匹配项投影回精确的终端坐标。

搜索超时、过时或被逐出的页面、无效的正则表达式、不可用的 Worker 和修订替换是显式状态，而不是 UI-thread 异常。
