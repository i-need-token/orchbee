# 共享用户偏好

本契约拥有 Desktop GUI 与原生 TUI 的设备通用偏好。
Rust `user_preferences` 与 TypeScript `user-preferences-contract` 共用
[JSON Schema 与一致性语料](../../../schemas/workbench/README.zh-CN.md#共享用户偏好)。
原生持久化归 [Local Site Runtime](../../local-site-runtime/README.zh-CN.md#共享用户偏好存储) 所有。
客户端呈现、传输和宿主能力不会产生新的权威来源。

## 清单与生效时机

以下叶字段组成一个版本化记录。GUI 与 TUI 提供相同的分类、含义、选项、
边界和重置默认值。客户端可以使用紧凑的分类标题代替独立页面。
每个标签都有英文和简体中文；记录中的机器词汇保持英文。

| ------------ | ----------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 语言         | `locale`：跟随系统 / English / 简体中文                     | `system`                                                  | `system`、`en-US`、`zh-CN`；改变应用文案，保留终端字节。                                                                               |

启动配置保存字面参数，不保存 Shell 命令字符串。集合最多包含 64 个配置，
每个配置最多 128 个参数，名称最多 512 个 UTF-8 字节，可执行文件/单个参数
最多 32 KiB，编码后的集合最多 1 MiB。ID 必须唯一，默认项必须存在。
名称须去除首尾空白且非空；只有 `system-default` 可以使用空名称。
自定义可执行文件必须是本地平台的绝对路径。Windows 拒绝登录 Shell。
保存不代表程序已安装，也不保证未来的 Host 创建信封能容纳该启动请求。

Rust 配置集合校验还通过准入所用的同一套检查，投影可选的内存中配置／字段位置，
包括字面参数索引。集合结构无效（版本、数量、标识、默认项归属或编码大小）时，
不提供字段位置。此诊断不改变序列化配置集合、请求／结果形状或既有拒绝词汇。
本地化修正引导和本地平台路径准入仍由客户端负责。

Desktop 与 Worker 使用相同的原生自动 Shell 解析器。自定义启动不依赖自动
Shell 发现。新的默认启动会重新发现系统 Shell；失败会拒绝此次创建，
不会编造替代可执行文件或重写配置集合。已有终端保留原启动信息。

## 作用域、持久化与迁移

配置身份在进程/Site 启动时冻结。显式 `ORCHBEE_CONFIG_FILE` 隔离该绝对
配置路径；否则由平台原生配置位置选择记录。身份相同的客户端共用配置旁的
一个私有记录。不同开发身份、设备或浏览器来源保持独立。本契约不新增
Workspace 偏好或远程写入路径。

Desktop 开发及本地发行在没有显式覆盖时选择隔离数据根中的配置；release 使用平台原生位置。
验证该开发身份的 TUI 必须选择同一个绝对 `ORCHBEE_CONFIG_FILE`。
这使开发偏好与已安装 release 隔离，同时在每个作用域内保持单一权威。

读取返回完整且已校验的快照、精确源令牌、已声明字段，以及独立的 Desktop
Main/renderer 导入回执。源为 `missing` 或小写 SHA-256 令牌；首次落盘前
也包含显式原生旧配置来源。无效、不可读、不安全或过大的来源会被拒绝，
不会被替换。完整记录/交换上限为 2 MiB。

更新包含预期源和非空类型化补丁。省略字段保持原值；null 将字段重置为
规范默认值。操作系统持有的锁串行化协作写入者，并在提交时再次比较源。
完整候选值在刷盘并原子替换前完成校验。替换后的失败可能返回
`outcome-unknown`，绝不自动重放。保存快照描述该次提交，不承诺之后无人
编辑。不协作的外部编辑器不在共享锁的事务边界内。

显式原生旧配置播种并声明自身字段。Desktop Main 导入启动/默认设置；
renderer 导入其他通用偏好。每部分各有一次性回执，只填充未声明字段。
显式编辑和重置都会声明字段，即便重置值已经等于默认值，延迟到来的旧配置
导入也不能恢复旧选择。对于已声明字段，导入顺序没有影响。旧来源予以保留；
格式错误的旧输入会被报告，不会被标记为成功导入。

## 客户端行为与能力边界

编辑器从草稿开始时冻结源。冲突会保留可见草稿，下一次有意编辑前需要重新
读取。轮询更新已确认的有效值，不会自动把打开的草稿改基到新源。
关闭已提交编辑器不会取消已接受提交。结果不明需要观察，而不是重试。
全部重置包含启动配置集合，并要求明确确认。

持久化和宿主应用是不同事实。新终端默认值已保存但 Host 尚未接受时，
Desktop 会报告此状态，并提供显式重试宿主应用。显示/输入/反馈偏好更新
当前客户端，不重启终端或重写终端输出。原生命令完成使用本地化瞬时状态
提醒和可选终端响铃；Agent 提醒使用客户端通知界面。原生尾部折叠要求精确
且已确认的历史窗口；缺少证明时回退到实时网格。用户选择或历史导航会接管
窗口，自动跟随不会移动进行中的选择。

| 界面                                                             | 分类与归属                                                                                |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 字体、字号/字重、粗体字重、连字、终端内边距、背景不透明度        | GUI 宿主呈现设置。TUI 不拥有外层终端的字体、像素和合成，应在外层宿主配置。                |
| 物理 macOS Option 键处理                                         | Desktop macOS 键盘适配器。TUI 接收已经编码的终端输入，不能改变物理 Option 键处理。        |
| Shell 集成状态与手动备用指引                                     | 能力/状态和安装指引，不是另一份通用偏好存储。能力不可用时，完成提醒设置仍属于通用设置。   |
| Agent 集成安装/修复、插件、远程连接诊断和 Ghostty 导入           | 具有独立副作用归属的管理/诊断/导入流程，不是偏好开关；导入的通用值必须经过通用权威来源。  |
| 原生快捷键、侧栏、窗口标题、终端/系统通知投递和逐 Agent 声音覆盖 | 原生宿主配置/管理。通用 Agent 模式和全局声音开关仍对自动提醒启用状态具有权威。            |

## 验证归属

Schema 语料检查 Rust/TypeScript 词汇、边界和非法输入。Local Site Runtime
检查源冲突、声明、导入、私有存储和提交失败；匹配的辅助程序测试真实有界
进程交换。Desktop 与原生测试检查草稿/源归属、发布、释放、启动捕获和已有
终端呈现。[原生设置模型](../../../apps/orchbee/docs/native-settings.zh-CN.md#正确性与证据)
检查两个写入者、独立导入、重置、不确定回执和发布。可见同步及宿主特有
效果仍要求真实 GUI/TUI 验收；交叉编译不能替代运行时验收。
