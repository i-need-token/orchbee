# Windows 崩溃恢复

此契约负责原生 Windows default 和命名 Site 的进程登记与冷恢复，范围为协作的当前用户 cohort
进程及普通进程中断。Client 拥有激活；Server 和 Worker 分别登记其直接创建的 Worker 和 Terminal
Host。Workbench checkpoint 的解释继续由 Server 负责。

## 状态与输入

一个 catalog 代具有非零激活身份，并分别为 Server、Worker、Host 保留一项登记。登记为
`NotStarted`、`Spawning` 或包含非零 Windows PID 与非零创建 FILETIME 的 `Identified`。
仅有 PID 不能构成身份。Windows 进程观测返回确切身份仍活着、确切身份已消失或未知。
PID 被重用意味着旧身份已消失，不授予对替代进程的终止权限。

私有记录写锁串行协调代、子进程登记和恢复发布。激活还持有 namespace、activation 和 Site
生存期 guard。效果路径从已准入的 scope 与当前用户输入推导，不信任序列化路径。冷恢复前，
checkpoint 存储必须空闲，且全部 Client、Worker、Host、observation 端点不存在。

## 登记转换

| 转换             | Guard                                                                    | 发布与效果                              |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------- |
| 预留子进程       | Active 代；槽为 NotStarted；确切已登记父进程，Server 则由激活 owner 创建 | CreateProcess 前落盘 Spawning           |
| 创建子进程       | 同一预留代与写 guard                                                     | 挂起、detached 创建，不继承句柄         |
| 识别子进程       | 确切保留的子进程句柄                                                     | 执行前落盘 PID 与创建 FILETIME          |
| 放行子进程       | 身份发布成功                                                             | 恢复其保留的初始线程；释放写 guard      |
| 失败或父进程消失 | 任意未完成阶段                                                           | 保留不确定登记；不从缺少 PID 推断不存在 |

身份发布失败时，成功创建的子进程不得放行。创建者尝试通过其拥有的确切句柄终止并确认退出。
未确认的清理仍属于不确定代。这项启动清理权限不授予终止孤儿或按 PID 发现的进程的能力。
Server/Worker 的效果不得绕过登记式创建。

## 冷恢复转换

| Catalog 与观测事实                                                               | 结果                                       |
| -------------------------------------------------------------------------------- | ------------------------------------------ |
| Active v2；无 Spawning；全部已识别身份消失；全部 guard、端点和存储检查通过       | 为旧激活发布 Crashed；对账其标记；开始新代 |
| Crashed v2 且旧标记匹配，或 runtime 丢失后标记不存在                             | 在新代之前继续同一受 guard 保护的对账      |
| 任一确切身份活着、身份查询未知、Spawning、不安全存储、创建后的冲突回执或端点存在 | 拒绝并保留数据                             |
| Active v1、损坏或不支持的记录                                                    | 拒绝；旧格式缺少身份不是死亡证据           |
| 有效 Stopped 记录                                                                | 现有 clean-stop 重启路径；下一次激活写 v2  |

恢复不终止旧进程，不伪造 clean-stop 回执，不删除 checkpoint 数据，也不向仍有 owner 的终端
另行 resume Agent。仍活着的孤儿 Host 受到保护，需要其独立拥有的 Host 接管协议。
拒绝提示提供只读诊断和另一个命名 Site，不声称具有清理未知 owner 的能力。

Crashed 发布先于 runtime 对账。持久发布之后的失败是已部分提交的结果，在相同 guard 下针对
同一激活身份重试。新激活不重用旧身份。clean-stop 发布使用当前记录内容，保留之后登记的
Host 身份，不使用早期保留副本覆盖它。

持久目录发布和 runtime 标记替换是两次独立写入。新的 Active v2 记录发布后，若在替换标记前中断，可能仍留有上一代完整的 Stopped 或 Crashed 回执。只有三个角色全为 NotStarted 时才允许恢复这一边界：先登记后创建的规则证明新代尚未创建子进程，而发布新代本身已要求上一代关闭。只要任何角色已保留或登记身份，就拒绝冲突的旧回执。恢复先将未启动的新代持久发布为 Crashed，再截断并 flush 旧回执，最后写入本代崩溃标记。中断留下的只能是完整旧回执，或空标记／本代匹配前缀；同一组 guard 可继续对账，不伪造干净停止结果。

## 兼容性与持久性

Catalog v1 保持可读。只有有效 Stopped v1 记录能自动进入 v2。Catalog v1 读取器拒绝 v2；
已升级会话不支持早期 cohort，包括 clean-stop 之后。不提供自动降级或推断式旧格式清理。checkpoint 格式不变。
私有 staging、flush 和原子替换覆盖普通进程崩溃；文件系统／设备掉电持久性、移除配置的
runtime base 及恶意管理员不在声明范围。runtime 叶目录被移除不抹除持久 catalog 或 checkpoint。

## 正确性证据

| 声明                                 | 证据                                                 |
| ------------------------------------ | ---------------------------------------------------- |
| 子进程执行晚于身份发布               | Windows 挂起子进程轨迹与登记转换测试                 |
| 未完成登记与未知身份永不授予恢复权限 | 解析器／策略测试及 WindowsSiteCrashRecovery 安全检查 |
| 旧活 owner 不与新恢复 owner 共存     | TLA+ 有界双 Client／双代模型及 Windows 激活争用轨迹  |
| PID 重用不授予终止权限               | 纯身份比较及原生身份观测；恢复不暴露终止操作         |
| 恢复中断保留代与 checkpoint          | 发布边界测试及隔离进程消失重启轨迹                   |
| default 与命名 Site 使用相同策略     | 两种路由的原生 Windows 集成用例                      |

抽象模型在换代后保留物理进程，不遗忘旧 owner。挂起创建、身份发布和 resume 为独立动作；
父进程可以在其中任意两步间消失。进程查询拒绝、旧格式记录和端点阻塞均拒绝恢复。
有限边界及 OS／进程适配假设不证明任意内核行为或 Host 接管。实际 Windows 重启与人工
Windows Terminal 验收为独立证据。
