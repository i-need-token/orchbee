# 原生 Tab 标签

## 规范状态与显示

Server 拥有 `Tab.label` 和可选布尔值 `Tab.automaticLabel`。省略表示 `false`；序列化省略
`false`。旧 Tab 保留精确名称，包括显式选择的数字。读取者不能根据文本推断自动命名。

Windows `tab create` 省略 `--label`、原生 TUI 创建 Tab，以及 `workspace.launch`
的首个 Tab 均请求自动命名。Workspace 启动保留独立的工作区标签，并将 Tab 及主 Presentation
的原始标签初始化为 `1`。显式 Tab 标签及 Panel 迁移标签保留现有固定名称行为。`tab.create` 携带相同
的可选布尔值；请求指纹包含该字段。提供的有界非空 `label` 仍同时初始化原始 Tab 标签和主
Presentation 标签。Duplicate placement 则复制精确源原始标签及自动／固定模式，
新 Presentation 也使用该原始标签，绝不把自动显示序号转为固定名称。普通组内／新组创建仍为自动命名。

每个终端上下文内，自动命名 Tab 显示当前从一开始的位置序号，固定名称 Tab 显示原始标签。
这是规范有序向量的纯投影，在移动或关闭后同样成立；不会重命名幸存者，也不会额外提交修订。
重排不改变原始标签、身份、Presentation 标签和绑定。允许显示名称重复。

原生标签栏、导航器、状态栏与 Tab 菜单共享显示名称，固定名称保持精确不变。自动名称优先使用
所选 Presentation 的自定义标签，其次使用有效实时 OSC 标题；非活动 Tab 可使用有界帧缓存中
最后观察到的标题，但 Site／context／Tab／Panel／Presentation／binding 必须仍与规范成员完全
一致。之后依次回退到启动可执行文件的基本名、本地化位置（`en-US` 为 `Tab 1`，`zh-CN` 为
`标签页 1`）。活动前缀会被移除，显示文本均经过安全处理。这种显示投影不会重命名规范状态，
也不把观察到的标题当作进程身份权威。规范序号标签、CLI 选择器和启动配置选择保留现有语义。

自动重命名草稿初始为空，以相同当前显示名称作说明性占位符；只有输入的文本可以提交。
固定名称预填编辑器。Windows 以已绘制 Tab 为锚点，沿标签栏尽可能扩展到至少 24 列，
原位呈现现有重命名草稿；不足八列时使用完整对话框。Enter 提交，Esc 取消；两种形式使用相同的精确已显示令牌和输入边界。

Windows 紧凑 Tab 以当前表面上的粗体名称表示活动标签页，不显示标记；超过 24 列的名称以省略号
结尾。有已报告 Agent 的标签页以其状态字形开头，并在名称后显示未读圆点。足够宽的标签为关闭控件
保留固定三列：活动标签页以及指针位于该标签上时显示 `[x]`，因此显示它不会移动标签栏；悬停的
`[x]` 使用破坏性强调色。隐藏的关闭区域仍选择其标签页，狭窄标签保留完整名称选择区域。固定的
标签页与其余标签页之间以一条竖线分隔，不再使用文字注记。关闭先验证绘制时的
上下文、修订和精确 Tab ID，再为该单个 Tab 打开现有确认。相同且未改变的 Tab 上，500 ms 内、
横向相差至多一列的两次释放，仅在该 Tab 已被选中时请求重命名。拖动、失焦、其他目标、
Site／上下文身份变化和释放捕获均会中断双击序列。第一次选择产生的新修订保留双击序列；
第二次点击仍须验证新绘制的来源。这些控件不向终端转发输入。

`tab rename` 总是选择固定名称。将自动命名 Tab 重命名为相同的可见或原始文本也是真实变更：
关闭自动命名并递增一次修订。对固定名称 Tab 重复相同重命名则不变。空名称重置不属于本契约。

## 消费者与模型

CLI Tab 行、Workspace 的 Tab 引用以及所有 Tab 标签选择器均使用有效显示名称。精确 ID 和
后缀选择器保留现有优先级；多个同名目标返回现有歧义结果。`api snapshot` 暴露原始规范状态。
查询行结构不变。`orchbee.api.snapshot` v1 接受可选元数据；原生 目录列出当前文档与命令路径。

原生严格投影器保留原始文本和命名模式。精确修订的移动／分屏／关闭检查保留幸存者的完整
元数据；重命名只改变目标文本和模式。同修订刷新仍须精确一致，更高规范修订则可能包含
重命名。创建验证在提交修订固定所提交的模式。幸存固定名称 Tab 不能重新变成自动命名；
自动命名幸存者保留原始创建文本，直到重命名切换为固定模式。后续完成不能覆盖期间发生的
重命名。关闭确认和 Agent 面板依据目标在已捕获上下文中的位置派生标签；原生界面使用上述
显示投影。选择、输入
所有权、几何和终端控制权与命名独立。

命名事实是完整的 `(raw label, automatic mode)`，不只是可见文本。创建或重命名可以在文本不变时清除自动模式。移动保留该元数据，并从顺序派生显示。具体编解码、权威、投影及 Windows 进程测试检查这些义务；不另设标签流程模型。

## 兼容性与验证

这是协调发布的实验性 OBWP v1 批次。Rust 和 TypeScript 只在新字段为布尔值时接受它；旧格式
省略字段仍为固定名称。旧严格读取者可能拒绝新字段，因此应部署匹配的二进制。没有持久迁移，
也不会重新解释既有数字标签。回滚未持久化的测试 Session 需要重启该 Session。

验证覆盖旧格式及非法字段编解码；显式数字名称；创建、重排、关闭和重命名；同文本模式变更
和重放；无关 Tab 与 Presentation 稳定性；跨上下文编号和歧义选择器；严格原生投影以及保持
焦点身份不变的实际 Windows TUI 显示。其他操作系统的运行时行为不在 Windows 验收证据内。

自动终端标题若为 Windows 可执行文件绝对路径，只显示文件名；原始标题观察保持不变。紧凑标签栏溢出时保留当前标签及分组上下文，在空间允许时于隐藏的一侧绘制不可交互的省略标记。关闭控件与省略标记各占独立区域。
