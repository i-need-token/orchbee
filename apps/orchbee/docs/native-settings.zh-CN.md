# 原生设置

## 交互与范围

Windows 全局动作菜单打开设置。捕获输入的覆盖层只编辑本地草稿：
三种内置主题之一、后台 Agent 自动提醒和声音。“保存并应用”是唯一提交入口。
打开、编辑或取消尚未提交的草稿，不写配置也不改变已安装主题。
pane 输出继续。Tab／上下键（或 j/k）选择行，左右键或空格修改值。
在“保存并应用”行按 Enter，或点击该已绘制行，只提交一次。
草稿没有更改时，“保存并应用”即使被选中也保持置灰，并显示没有更改的原因。
选中可用的保存行时，页脚显示 Enter 保存提示；其他设置显示相应的编辑按键。
Esc 取消尚未提交的草稿；已提交后只隐藏界面，保存继续执行。
页脚显示适用的取消或关闭操作。设置替换整行状态及其背景，编辑器提示不会残留先前通知、
Shell 提示或 Machines 指示器。设置捕获输入期间隐藏底层 pane 光标。
完整覆盖层至少需要 36 列、10 行内容区；
不足时关闭并明确提示。打开／保存超过 200ms 后显示固定等待指示，交换截止时间为两秒。
捕获的输入包及分片粘贴尾部在取消和下一次重绘后仍保持归属。

Server 写入 Site 启动时冻结的配置位置，Client 不提交任意路径或 TOML。
其他配置值和注释保留。开启提醒时保留原有已开启的通知通道；
原通道关闭时采用现有应用内提醒。手动通知、延迟、位置、
各 Agent 声音策略和无关设置保留既有语义。集成安装和首次引导另行实现。

## 领域与归属

| 记录字段 | 契约                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 问题     | 本地 Windows 用户无需编辑 TOML，也不打断任务，就能调整常用设置。                                                                                                               |
| 输入     | 完整准入配置、确切源内容／缺失令牌、发布 revision、类型化草稿、已绘制轮次令牌和一次显式保存。                                                                                  |
| 数据     | 每个 Client 一个有界编辑轮次；三个受控设置；Server 拥有源令牌、事务和不可变发布。                                                                                              |
| 输出     | 已打开草稿；无变更；已保存并应用；已保存但未应用；写前拒绝；或传输结果未知。                                                                                                   |
| 决策     | 隐藏／草稿／已提交阶段；候选有效／无效；源及 revision 当前／过期；写入成功／失败；实时应用成功／失败；回执到达／丢失。                                                         |
| 依赖     | 有界设置读取器、现有私有原子文件所有者、完整配置准备、经过身份核验的本地 Workbench 交换和成功绘制。                                                                            |
| 归属     | local-site-runtime 拥有 TOML 转换和受控文件发布；现有 Server 配置 Registry 串行协调保存及重载；现有 Client 配置 watcher 拥有完整准入及实际应用；设置界面只拥有草稿和一次操作。 |
| 模型     | 双 Client、显式绘制及提交、单一写入者、源冲突、先落盘后实时发布、取消和回执丢失的有限安全工作流。                                                                              |
| 参考范围 | Windows 本地 Site、三种内置主题及提醒／声音开关；不含 provider 安装、远端写入、自动外观检测或持久历史。                                                                        |

## 转移与结果

| 状态／事件        | 守卫与结果                                                                                                  |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| 隐藏 → 打开       | 读取 Server 权威和有界源；冻结 revision 及内容／缺失令牌。                                                  |
| 草稿 → 编辑／绘制 | 改动留在本地；成功绘制新帧前撤销旧绘制权限。                                                                |
| 草稿 → 保存       | 要求当前已绘制轮次；调度前消费提交权限、捕获输入包，并拒绝重复保存。                                        |
| 提交 → 准备       | 一个配置事务；写入前拒绝已观察到的 revision／源冲突以及无效或不安全来源；副作用前验证完整候选和可能的响应。 |
| 准备 → 落盘       | 保留未受控 TOML 值／注释，复核已观察源，原子发布一份已刷盘候选。                                            |
| 落盘 → 实际配置   | 原配置所有者完整应用并发布候选；Client 使用已有完整准入。                                                   |
| 写入失败          | 回报未保存配置；保留实际发布。                                                                              |
| 落盘后应用失败    | 回报已保存但未应用；保留旧实际发布，不回滚也不重复已保存写入；仍可显式重载。                                |
| 回执丢失          | 回报结果未知；不自动重放，重新打开是新的显式观察。                                                          |
| 取消／关闭        | 提交前丢弃草稿；提交后隐藏界面不能撤销 Server 已接受操作；迟到结果不能操作替代轮次。                        |

源令牌比较有界文件字节，并区分文件缺失与空文件。协作写入者使用既有私有文件锁；
发现改动便拒绝保存。不协作的编辑器仍可能与最后一次文件比较竞争；
这不是横跨任意外部编辑器的事务。目标缺失时使用不替换创建。
不安全、不可读、损坏或过大的文件会保留并明确拒绝，不隐式修复。

保存回执描述已经完成的保存，不保证后续编辑器不能修改文件。
每个 revision 的发布完整且不可变，落盘和实时应用是不同事实。
控制权、成员关系、pane 尺寸、焦点、剪贴板策略和终端程序调色板不变。

所选主题为实时及保留的终端单元格提供绘制时的默认前景与背景。
“终端默认”通过 `Color::Reset` 使用宿主默认色，与帧提供的 RGB 默认值无关。
程序在单元格上显式设置的颜色保留确切值；
通过默认标记而非 RGB 相等判断哪些颜色跟随主题。
这项绘制策略不改写终端程序调色板或颜色查询响应。
默认标记投影与 OSC 默认色行为见[原生主题](native-themes.zh-CN.md)。

确定已应用的回执必须对应确切请求及紧接的下一个 revision；
无变更及保留旧实际配置的结果必须对应提交时捕获的 revision。
确定已应用或无变更的结果还须符合请求指定的主题。
提交后收到不匹配的回执属于结果未知，不能授权实际应用。

## 正确性与证据

| 主张                       | 必需证据                                                                     | 边界                                                             |
| -------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 显式提交不自动重放         | NativeSettingsSave 安全模型；确定性编辑器／传输轨迹                          | 两个 Client、两个有界轮次；无公平性或送达保证                    |
| 单事务及完整实际发布       | NativeSettingsSave 与 WindowsConfigurationPublication；Server 失败／冲突轨迹 | 设置 payload 抽象为原子值；完整 parser／profile 准入仍是实现边界 |
| 未知设置和注释保留         | TOML 决策案例、Unicode／内联／点分来源案例和未受控值精确核对                 | 三个拥有字段；原 64 KiB 源边界                                   |
| 保存与应用结果独立         | 文件／写入故障、预编码拒绝、实时应用失败和回执丢失轨迹                       | 已提交保存后不补偿；文件竞争边界如上                             |
| 绘制／输入归属及可发现设置 | 双语几何／输入案例及隔离原生双窗口保存                                       | 普通 Windows ConPTY；物理模拟器外观及认证 provider 单独验证      |

两个抽象 Client 是可互换的模型值；对称约简只消除标号排列，仍容纳两个 Client 和各自两轮操作。
抽象源代际对应确切的已观察内容／缺失令牌。模型允许事务阶段间发生外部编辑，
在写入步骤保留其他字段，并允许磁盘和实际状态不同。
发布原子值对应完整准入设置及诊断；既有发布模型拥有 Client revision 准入。
parser 决策和文件／进程边界需要各自证据，不由有限模型证明。

运行 `node scripts/tla/run-models.mjs --models native-settings-save,windows-configuration-publication`
及规定的根级 `pnpm verify`。证据必须匹配最终源码；
表格列出验收义务，不代表所有检查已经执行完成。
