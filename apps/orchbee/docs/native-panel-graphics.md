# Native Windows Panel graphics rendering

## Outcome and owners

The native TUI consumes the existing Site-owned Panel/Presentation image layers. A dedicated instance of the existing cancellable read lane owns graphics queries; it never borrows the UI's terminal/control connection, sends PTY input or changes focus. The main UI owns visible target selection, cache publication, clipping and successful draw receipts. The existing Client control publisher owns capability/draw observation on its already authenticated connection.

Only surfaces included in a successful shell draw enter the read scope. Selected primary/child identity and optional terminal binding are captured exactly; removed, rebound, hidden or switched targets leave the scope immediately. Site identity fences reconnect and cold restore. Stable labels and identity-preserving moves do not invalidate pixel resources. Source membership is checked before reads, after complete resources, and at UI publication. A maximum of 64 surfaces are queried in each bounded batch, rotating over the existing 4096-Panel context bound.

## Complete resources and bounds

Catalog metadata is compared with immutable cached layer metadata. Unchanged exact resource revisions reuse shared pixels without cloning image bytes. New RGBA resources are acquired in at most 256 KiB chunks, checking target, layer, revision, dimensions, total, exact offset, canonical base64 and completion. The repeated catalog must retain exactly the same layer metadata, and the canonical source fence must still agree before publication. Unrelated Site revision advances are admitted with the repeated catalog revision; they do not invalidate a complete resource for an unchanged layer. A failed, stale or interrupted read never produces a partially updated image. The last complete image may remain while the same source awaits a newer frame; its draw receipt retains its actual older revision.

The published cache holds at most 64 MiB of pixels and 64 image resources. One candidate batch is independently bounded at 64 MiB; immutable resources are shared between them. Thus old and candidate pixels together remain bounded at 128 MiB, with bounded carrier/base64 chunk scratch. Publication enforces the resident budget across the merged cache; if old historical resources exhaust it, they are retired before installing the complete new batch. Scope removal frees corresponding references; lane shutdown interrupts, joins and releases its last candidate. No new dependency, service, directory or temporary artifact is introduced.

## Cell raster surface

The baseline transport is actual Ratatui color cells: one upper/lower color sample per cell, represented by the upper-half block. Natural fit preserves the image's logical sample aspect within the real Panel rectangle; it does not invent physical cell pixel dimensions. Extreme aspect ratios clamp to at least one column and at most the body height, so a subcell logical width still shows the complete image. Grid columns/rows accept the full unsigned 32-bit range (zero selects natural fit); explicit dimensions and signed placement are honored, with arithmetic wider than the coordinate inputs and clipping to the body. Z ordering follows the Site catalog. Negative layers preserve existing text glyphs and foreground, compositing their background; positive layers overlay text where image alpha is nonzero. Fully transparent samples preserve underlying content. Known RGB destinations use straight alpha blending; unresolved default/palette colors keep their identity below half opacity and select the image color above it. Wide glyph heads and spacers remain atomic and are preserved where a cell raster would split them. Chrome, other Panels, wide-cell ownership, source hit testing and terminal mouse modes remain with their existing owners.

Rendering uses the actual Panel body after terminal content and before shell overlays. Draw receipts are published only after Terminal.draw succeeds and only for uncovered, current sources. Cache acquisition alone is never a draw acknowledgement. Resizing, zoom, switching, clearing and shutdown recompose through the same surface owner; clearing restores underlying terminal cells on the next ordinary draw.

## Bounded host measurement

The interactive Windows shell probes only its already-admitted terminal, after entering its owned modes and before the first ordinary draw. The existing lifecycle writer issues the xterm `CSI 16 t` cell-pixel query and a Kitty `a=q,t=d,f=32,s=1,v=1` query with a nonzero random image ID. Queries have a 300 ms deadline and never wait before rendering or create image placements. Terminal names, environment variables, font guesses and producer `transport` hints cannot establish these facts. These sequences follow the [xterm control contract](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) and the [Kitty graphics contract](https://sw.kovidgoyal.net/kitty/graphics-protocol/).

The existing input decoder owns complete cell reports and graphics APC replies before key, prefix, popup and confirmation dispatch. The same metadata is consumed during a native text modal; bracketed paste remains literal paste, including bytes that look like replies. A graphics reply is bounded at 256 bytes; oversized or timed-out replies drain to their string terminator without allocating or exposing the remaining reply as typed keys. A bare Alt+underscore retains its ordinary meaning when it is not followed by the graphics introducer. No reply, a malformed reply or a late reply establishes capability, increments human-activity intent or reaches a retained terminal.

Only a timely cell reply to the sole pending query is admitted. Its positive unsigned 16-bit dimensions must produce exact, representable window pixel totals for the queried cell geometry. A geometry change invalidates measured pixels immediately. Since the legacy cell response has no correlation ID, another cell query cannot be issued while the previous response is outstanding, even after timeout; its late response settles that debt and is discarded before a later query is admitted. Known or settled measurements can be re-queried on the next geometry change. The Kitty reply must match the one issued ID and deadline without a placement ID; an unrelated ID cannot establish support. Query support is an internal fact until a physical renderer actually uses it. Cell-raster observations may publish real measured cell pixels, but continue to publish cell-raster transport and pixelMouse false.

The shell passes a measurement only to its exact cell geometry and the active native surface. It applies the same physical pixels to retained pane geometry and popup geometry; a newly selected Machine receives current host facts before its next draw. No filesystem resource, background thread, additional console reader or new dependency is introduced. Focused acceptance must witness timely, late, absent, wrong-ID, malformed and split replies, ordinary keys interleaved with replies, literal paste, modal capture, geometry invalidation and the actual lifecycle writer. Physical image placement and pixel mouse remain separate obligations.

## Facts and acceptance

An additive bounded graphics observation is submitted by the existing Client control connection after its normal synchronized view. The Server checks authenticated generation-derived Client ID, heartbeat, Workbench revision, canonical target/binding and installed revision bounds. Foreign connections cannot replace another Client's facts. Info uses fresh matching observations, reports cell-raster capability and pixelMouse false, and publishes cell pixels only from the current bounded host measurement. Partial surface lists cannot claim an absent Pane is hidden. Stale, disconnected or mismatched observations do not claim visibility or successful drawing.

The fallback does not claim negotiated Kitty/Sixel or pixel mouse support. Managed private producer file leases and complete file-frame CLI inputs are implemented by the [Site graphics owner](../../orchbee-server/docs/windows-graphics.md). Physical capability paths still have separate acceptance obligations. Focused evidence covers actual native renderer output, alpha/z/clipping, complete chunk/resource fences and Client ownership. Real Windows composed graphics workflows and final full regression remain required before alignment or main integration. No TLA, WSL, new macOS/Linux runtime or manual focus-stealing Desktop test is run.
