# 原生终端命令提交

## 命令与所有权

`orchbee terminal run <target> <command>` 将一个带引号的非空 UTF-8 命令字符串
提交到既有 Terminal。操作数看起来像 CLI 选项时，在它之前使用 `--`。
全局 `--format text|json` 仍选择输入回执的展示方式。完整参数包保持 64 KiB 上限，
既有 paste 上限为 256 KiB。命令字节、空白、引号与换行原样保留。
多个未合为一个引号字符串的命令操作数会被拒绝；Orchbee 不重新拼接 Shell argv。

该 Terminal 中的当前程序解释这些内容。CLI 不启动另一个进程、不选择 Shell、
不检查提示符，也不声称 Shell 已就绪。提交回执确认输入进度，不确认命令完成或
退出码。需要时应另外观察输出或规范 Agent 状态。

## 输入生命周期模型

| 阶段   | 规则                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 解析   | 在发现与运行时副作用前校验语法、命令边界和目标语法。空文本、多余操作数及发送来源选项是用法错误。 |
| 定位   | 在一次快照与一个已准入会话上复用 Terminal ID 或类型化后缀定位。不隐式选择焦点目标。              |
| 提交   | 降为一个既有终端输入请求，包含 paste 记录及其后的语义 Enter。Host 按当前终端模式编码 paste。     |
| 结算   | 保留既有 `orchbee.terminal.send` 回执、精确请求／目标身份、已接受前缀证据和清理状态。            |
| 不确定 | 丢失应答保持未知，已确认前缀保持部分提交。不重放、不另补 Enter，也不推断执行成功。               |

该入口遵循既有五秒发送期限、取消和失败词汇。不获取 viewer、controller、resize
或焦点权限，不创建新的共享协议或持久状态。`terminal send` 保留显式来源／按键形式。
快捷入口在一个请求内携带两条有序记录，不为既有发送契约增加更强的全有或全无保证。

## 证据与兼容

解析证据覆盖带引号／中文／多行不透明文本、参数分隔符、缺失／空／多余操作数及
不允许的来源选项。Windows 命名管道进程证据约束一次快照加一次 paste/Enter 请求、
已接受／部分／未知结果及不重放。暂存 Windows cohort 在 TUI 保持 controller 和焦点
时验证真实 PowerShell 5.1 与 7 执行。

帮助、全部补全适配器、离线 Agent Skill 与本参考共同维护。文档形状未变，因此
schema 目录保持 v36/69。旧可执行文件拒绝新动词，回滚不需要数据迁移。
证据仅限 Windows 且由同作者完成；此流程采用实现测试。合入前必须通过根级验证。
