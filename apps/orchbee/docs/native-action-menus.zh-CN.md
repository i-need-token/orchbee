# 原生动作菜单

## 交互

Windows 的 `Ctrl+B F2`、`[keys].menu` 和右上角动作菜单按钮打开全局动作菜单。Minimal 布局中，按钮覆盖右上角内容单元格，留出滚动条列并保持终端尺寸。
无修饰右键为已绘制的 pane、tab 或 Workspace 行打开菜单。打开或取消不改变焦点。
pane 内容保留配置的 `right_click = "panel"` 策略；pane 标题仍属于 Client。
Shift 手势保留外层终端旁路。Machines 保留 `Ctrl+B Shift+M`。
侧栏页脚直接打开设置，不再保留常驻菜单或机器页脚。
Workspace 侧栏仅对当前机器、已绘制 Session 上仍存在的准确行准入右键。
它复用现有 Workspace 菜单，打开或取消不请求机器或 context 切换。

鼠标打开时，菜单框锚定触发它的宿主单元格，包括侧栏行及其动作按钮。菜单框限制在状态行上方的
整个视口内，可以覆盖导航构件。键盘打开仍在 pane 内容区域居中。两种方式都不改变目标或底层焦点。

对象及创建上下文菜单仅绘制矩形边框、动作行及可选的预留禁用原因行，不显示边框标题、头部 X、
页脚提示或选择计数，也不会为省略的控件发布隐藏命中目标。Esc 和点击外部关闭，以及子菜单中
Left 或 Esc 返回，继续使用现有 owner 与绘制守卫。子菜单继承根菜单的构件策略，而不是从替换后
的子目标重新推导。全局动作菜单保留标题和按键发现控件。

呈现决策消费根目标、保留的父级链、准确菜单 token、视口、语言、主题及 owner 派生的不可用原因，
不改变动作身份、选择、捕获或执行边界。被拒绝的帧不发布行或控件权限；成功的上下文帧仅暴露
实际动作行及表面。`src/tui_render/action_menu/tests.rs` 的渲染见证比较上下文与全局组合、两种语言
及随产品提供的主题类别，并覆盖有／无预留原因时的宽高边界。

Tab 菜单遵循 GUI 的创建／分组、复制／固定和关闭分段。
分组归属使用子菜单；选择和移动使用独立子菜单。
已绘制组标题和新建 Tab 按钮通过
[分组配置所有者](native-tab-groups.zh-CN.md#指针排列与菜单导航) 打开各自菜单。
全局菜单也提供新建 Tab 子菜单供键盘使用。
选择动作提供本地切换／区间／全选／清空；目标属于选中集合时配置捕获的完整集合。
固定、建组及移出显示受影响数量。选择或所选成员变化会撤销菜单绘制证明；后台元数据操作
保持当前终端连接。菜单移动采用 GUI 分组边界，包括折叠的相邻组。
元数据操作保留当前终端；子菜单保留准确的目标 Tab。

重复出现的菜单动作与前缀动作共用一份原生元数据投影：稳定动作身份、分类及经过审查的
语义搜索别名。动态分组颜色、分组索引和参数化 resize 输入仍是有类型的 `ClientAction` 或
`MenuAction` 数据，不会变成从行派生的身份；只有 owner 的 GUI catalog 已经定义同一操作时，
方向专用 ID 才复用该 catalog。配置命令 ID 保持不透明且不改写。前缀帮助从每个 Client
已经解析的 binding registry 取得有效按键，包括覆盖与遮蔽结果。仅当显式的 `MenuTarget` 与
`MenuAction` 映射具有相同 dispatch 语义时，菜单行才显示第一条有效按键；不能只因动作共用
元数据，就把针对当前 Tab 或当前 Workspace 的 binding 显示在后台对象上。菜单执行仍使用其
有类型的目标、准确 coordinator 证明及 owner 派生的可用性；元数据和已显示按键都不授予执行
权限。此界面当前没有原生命令搜索，因此别名元数据不表示已经提供搜索入口。

每个已显示按键组合都位于导航轨道和本地化标签之后的独立右对齐槽位；标签与按键组合之间至少
保留一个空白单元格。按键组合必须完整；受限行先截断标签，只有剩余宽度无法同时保留标记、可用
标签与间隔时，才整体省略按键组合。

关闭选中／其他／后续 Tab 及关闭组显示冻结的受影响数量，随后打开一次
[完整集合确认](native-tab-close-sets.zh-CN.md)。相对 Close 保护固定 Tab；
直接关闭选中集合／组时，适用的固定成员也包括在内。被折叠隐藏的成员仍属于目标。

只有关闭 owner 已经呈现准确恢复状态后，菜单才显示可恢复的 Tab 关闭行。打开菜单时冻结一个
不透明 permit，准确标识目标、操作、尝试及状态 incarnation。菜单替换状态行期间，可用性与
一次性转交会重新核对该 permit 及准确菜单来源；既不把被覆盖的状态继续标记为已显示，也不
回退为普通关闭。随后打开的恢复确认仍须呈现自己的准确提示与状态，才能接受确认。

Up/Down 或 j/k 选行；Home/End 选首行/末行；Enter 执行选中动作。键盘选行以最小的
视口移动显示该行。宿主和原生适配器在全局准入或菜单范围请求下收到空闲移动后，无修饰、无按键移动让
已绘制可用行成为临时菜单候选，显示整行选中背景和导航标记。它绝不执行动作、切换活跃
Workspace 或 Tab，也不自动打开子菜单。离开后保留候选，后续方向键从该候选继续。禁用行
和分隔线不移动候选。Hover 保留视口和动作 token；Enter 要求当前候选已成功绘制。未收到空闲
报告时不显示 hover 反馈。左键只有在同一有类型来源、token、行与已绘制矩形上
按下并匹配释放后才执行动作。键盘输入、失焦、释放捕获或目标／矩形变化会取消待定点击。
全局菜单的标题 X 关闭菜单，其返回动作返回父菜单。Right 打开所选子菜单；Left 或 Esc 返回父
菜单并恢复稳定的所选动作、锚点以及重新查询的可用性。返回后必须重新成功绘制，旧子菜单
token 不能执行。

根菜单的 Esc 或点击外部取消。列表外滚轮无效。列表内每格累计三行，以视口容量限制每次
处理量，不循环、不执行；滚轮只改变视口，可以让键盘选择暂时位于屏幕外。反向滚动丢弃旧
方向积压并保留第一个新方向滚轮。分隔线不交互且占用布局行，全局页脚仅统计动作数。菜单行在
菜单内滚动，状态栏始终可见。全局菜单的固定页脚显示选中行与总数（`current/total`），并显示由按键和
本地化动词构成的有序原子提示。退出提示排在第一；空间不足时，Enter 和导航提示按完整条目
移除。空间允许时显示共享的返回或关闭动作。菜单页脚负责常规按键发现，因此正常呈现的全局
菜单让会话状态行保持空白。几何恢复期间，该行改为显示一条不含按键的本地化拒绝或暂停通知，
以及一条共享的 Esc 返回或关闭提示；不会混入底层通知或 Machines 文字。
菜单宽度包含两侧各一个单元格的内边距及边框；标签超出可用宽度时按字形簇边界截断，并使用主题的省略号。
选中背景填满整个内行，并使用共享导航标记轨道；hover 使用独立的共享指针状态。仅当菜单含有
不可用动作时预留原因行，因此 hover 不改变行几何。每帧按当前可用行数计算可见窗口。键盘
导航保持选中动作可见；手动滚动后的视口保持在用户放置的位置。成功绘制为指针及激活准入
提交准确的首个动作、可见动作数与所选动作；窗口增大时填满可用行数，不改变选择。
菜单关闭后，取消或 owner 不可用结果只显示一次；不会重复已打开菜单的页脚或几何恢复状态。
新请求的全局菜单无法显示标题、至少一行和退出说明时拒绝打开并给出本地化提示。上下文菜单则
要求完整边框、至少一个动作行及任何预留原因行；无原因行时，最小完整外框为 16 列乘 3 行。已经准入的菜单
后来变得过小时进入 `Suspended`，保留来源、选择、视口、父菜单与锚点，并且只接受当前本地
退出或返回。几何恢复后，同一菜单 incarnation 必须重新成功绘制才恢复。菜单捕获输入期间，
终端任务继续输出。
捕获期间隐藏底层 pane 光标；取消后恢复普通 pane 投影，不改变焦点。
已知不可用动作仍以禁用文字角色显示，在每种颜色层级保留完整主题样式及其
修饰符。可以选中以阅读本地化原因；Enter 或
点击保持菜单打开，不能确认或导航。固定原因行在最小可呈现尺寸下仍保留全局菜单的
退出说明及选择计数；上下文菜单仅预留原因行，不增加页脚构件。选中项禁用或位于屏幕外时，全局页脚不显示 Enter 动作。
当前宿主不支持的动作会隐藏，而不是作为禁用的学习行展示。因此，在原生 Windows
宿主实现该能力之前，菜单中不显示“将 Tab 移到新窗口”，也不会产生占位或“不支持宿主”
原因行。与当前 context 相关但普通前提未满足的动作仍然可见，并展示 owner 派生的禁用原因。

浏览没有时限：阅读、选行、重绘和激活禁用项都不启动执行计时。
确认可用动作时创建唯一的 30 秒绝对截止时间，目标导航和转交共用该截止时间；
重绘和导航回调不续期。到期撤销尚未转交的动作，不回滚已接受的导航。
目标、来源、配置和捕获失效仍会取消浏览；几何按上述拒绝与暂停生命周期处理。

可用性投影既有动作 owner 的前提，不统一增加 Ready 守卫。已有目录的
Workspace 禁用目录配置；当前 Workspace 同时应用原有空状态及 setup
准入守卫。鼠标捕获已释放时禁用释放鼠标捕获。未知异步前提继续交给原 owner；
菜单不根据只读机器观察推断 Git 支持、Worker 可达性或操作结果。

Project 菜单提供新建 Workspace、重命名、Worktree 创建／打开、解散 Project 及关闭全部 Workspace。
新建 Workspace 经由[setup owner](native-workspace-setup.zh-CN.md#创建默认值与结果归属)接受准确的
已绘制 Project，包括空和非当前 Project。它与未分组 Workspace 使用同一立即创建路径，没有 Project 选择器。
重命名、解散及显式关闭全部也直接针对已绘制 Project，不进入子 Workspace。
Worktree 条目要求当前 Workspace 属于该 Project，否则提示“请先选择此项目中的工作区。”。
有类型的目标准确证明经过 ClientView 和 InputDispatcher 保留。Setup 保留当前来源与焦点，
准入前核对原菜单截止时间，并使用有界准备，不对可选的人工编辑计时。

Workspace 的移入 Project 提供现有 Project、无 Project 或新建 Project。
新建只询问一个名称，并原子地创建 Project 与移动 Workspace。移动非当前 Workspace 不选择它。
解散仅改变分组；关闭全部打开[独立的范围确认](native-workspace-close.zh-CN.md)。两者都不删除 Git 检出目录。

关闭 Workspace 直接针对准确的目标 Workspace，不导航到该 Workspace，并打开常规的
[范围确认](native-workspace-close.zh-CN.md)。后台关闭非当前 Workspace 后，保留与其无关的当前会话。

侧栏 `+` 入口通过 `MenuTarget::Create` 选择原全局菜单或准确 Project 菜单中的创建子集。
Project 入口把快速 Workspace 放在首位；原有前提、目标证明、禁用原因及输入捕获保持不变。
[Shell 布局](tui-shell-layout.zh-CN.md#快捷创建控件) 拥有这些入口的几何及 Tab 顶栏直接创建手势。

pane 菜单提供已有分屏、缩放、键盘调整、复制、接管和关闭动作。tab 菜单提供
新建、重命名和关闭。Workspace 菜单提供快速新建、新建 tab、目录、重命名、移入 Project、
Worktree 创建/打开及关闭。全局菜单提供新建 Workspace、Worktree、重载、设置、机器／Workspace／Agent 搜索、帮助、
侧栏、导航器、Agent 看板、释放鼠标和分离。关闭仍打开原有确认；菜单从不代替
删除确认。设置交给现有编辑器；checkout 删除、策略编辑和自定义或插件菜单不在此界面范围内。

carrier 不可用时，全局菜单仅保留 Client 本地搜索、帮助、侧栏、释放鼠标及分离。
成员菜单要求 carrier 存活；首个会话状态到达之前也必须有已观察的几何。

## 模型与归属

用户希望无需记住快捷键即可发现并执行现有动作。

| 记录字段 | 合约                                                                                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 输入     | 已绘制的稳定目标、准确 context/member/incarnation、投影出的稳定动作身份与有类型输入、当前动作前提、完整解码输入包、配置、单调截止时间及成功菜单绘制回执                                                                                                                              |
| 数据     | 一个本地 episode、`Pending`／`Admitted`／`Suspended` 呈现阶段、相互独立的整体界面 lease 与准确行窗口证明、`Recovery`／`Continuation`／`ActivationReady` 输入 readiness、保留的视口与选择、owner 派生的启用／禁用／隐藏可用性、呈现 token、冻结的已确认动作、父快照和可选准确目标成员 |
| 输出     | 本地捕获与绘制；通过现有 membership owner 进行有界导航；至多一个动作交给完整 ClientView/dispatcher 路径；本地化取消或拒绝                                                                                                                                                            |
| 决策     | 现有捕获（包括 Windows 导航器）优先。帮助和侧栏作为不变底层保留。选择动作才准入导航，打开不导航。每个动作保留原有可用策略，不统一要求 Ready                                                                                                                                          |
| 不变量   | 未绘制或过期时不能激活；打开/取消不改焦点；不对替代目标执行；不隐式重试；输入及决策包尾部不进入 pane；关闭仍需原有确认                                                                                                                                                               |
| 模型     | 捕获、绘制、目标失效、自有/外部导航、取消、前提和一次动作转交的有限安全状态机                                                                                                                                                                                                        |
| 依赖     | 现有原生 membership、终端状态、输入解码器、hit map、布局、本地化和动作 owner；无新依赖、wire 或持久数据                                                                                                                                                                              |
| 归属     | NativeUi 管准入与目标导航；确定性菜单管选择和绘制权限；ClientView 管本地视图决策；仅 InputDispatcher 应用 shell、模式和布局副作用；仅原操作 owner 执行变更                                                                                                                           |
| 参考范围 | 当前 OrchBee 动作的可发现性，不声称完整 Herdr 菜单对齐                                                                                                                                                                                                                               |

`MenuTarget::Project` 携带 `WorkbenchProjectId`，不使用标签或行索引。
准入冻结完整的规范 Project；仅当其 ID 与当前 Workspace 的 Project 匹配时，
同时冻结该 Workspace/Directory 来源。空 Project 和当前 Workspace 之外的 Project
仍是有效菜单目标；setup owner 准入时快速创建 Workspace、Project 重命名、解散及关闭全部可用；
Worktree 动作保留当前 Workspace 前提。确认和转交时必须保持同一 Project 与可选 context
证明；来源改变或记录被替换时取消 episode，不重新定位。

所有对象入口适配器都传入成功绘制的 `DrawnMenuSource` Session 和 revision。
侧栏 owner 同时核对当前机器与稳定的焦点行。右键、行内可见动作入口及对象菜单键
使用同一目标。对象键仅属于明确进入的侧栏导航；终端拥有的键保持透传。
菜单捕获输入期间，调用方保留侧栏焦点，并在关闭时调和已删除的行。
菜单不另存一套侧栏焦点状态。全局菜单仍可独立使用。

[Windows 导航器](native-context-selection.zh-CN.md#windows-捕获输入的导航器)拥有输入时会消费菜单快捷键及鼠标入口。
应先关闭导航器再打开菜单；菜单仍可通过普通动作打开导航器。

| 打开时的 Project context                    | 可用性及副作用                                                                                  |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 当前 Workspace 属于准确 Project             | 既有动作保留自己的前提；确认仅提供一个动作，不导航                                              |
| Standalone、其他 Project 或没有 Workspace   | 新建 Workspace、重命名、解散及关闭全部不导航地针对准确 Project；Worktree 条目解释缺失的 context |
| Project 或捕获的 Workspace/Directory 被替换 | 确认或转交前取消；从不替换成其他子项                                                            |
| 取消                                        | 保留原生来源和调用方拥有的侧栏焦点                                                              |

## 转移与取消

| 状态 / 事件                | 守卫及结果                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| 隐藏 → Pending             | 稳定已绘制来源，无真实捕获或待定手势；冻结目标与当前来源，捕获打开包                                   |
| Pending → Admitted         | 完整绘制报告准确 token、首个动作、可见动作数与所选动作                                                 |
| Pending → 几何阻塞         | 拒绝新界面，显示一次本地化通知，不转交动作                                                             |
| Admitted → Suspended       | 后续确认的几何阻塞撤销绘制权限，但保留来源、选择、视口、父菜单与锚点                                   |
| Suspended → Admitted       | 同一 incarnation 完成新的准确绘制                                                                      |
| Admitted → 键盘选择        | 移动选择、启用跟随选择、生成新 token 并要求重绘                                                        |
| Admitted → 滚轮视口        | 只移动保留视口、禁用跟随选择、生成新 token 并要求重绘；选择不变                                        |
| Admitted → 同界面 revision | 保留整体界面 lease，只撤销准确行权限；选择、视口、标签或可用性等待匹配重绘时发布 `Continuation`        |
| Admitted → 被覆盖或未绘制  | 生成新 token，同时撤销准确行证明和整体界面 lease；保留 owner，并在重新完整绘制前发布 `Recovery`        |
| 打开 → 可用性改变          | 刷新 owner 派生的原因，在重绘前撤销旧 token；已知不可用行不能授权确认                                  |
| 打开 → 禁用项激活          | 保持选择和捕获，显示原因，不转交动作或导航                                                             |
| 打开 → 时间流逝            | 保持浏览和捕获，不创建执行截止时间                                                                     |
| Admitted → 确认            | 完整输入、准确当前绘制及可用所选行；冻结一个动作和前提状态，创建唯一的 30 秒绝对执行截止时间           |
| 已确认 → 导航              | 区分 AlreadyExact、自有 Context generation、自有 Tab generation 和准入的本地 focus；不从无操作推断准入 |
| 导航 → 转交                | 仅自有 prepare/apply 结果授权推进；准确目标仍存在，来源和前提一致；原动作决定可用性                    |
| 转交                       | 在应用完整 ClientView 转移和 dispatcher 副作用前移除一次性意图；不重试                                 |
| 取消 / 执行超时 / 不可用   | 撤销尚未转交意图；不回滚已接受导航，不执行动作                                                         |
| 来源 / 配置 / 覆盖捕获改变 | 撤销尚未转交 episode；外部导航保留自身语义，不能完成菜单意图。变尺寸遵循上述保留呈现状态。             |

呈现 token 绑定 episode、准确语义目标、键盘选择与视口 revision。整体界面 lease 另行证明该 owner
占据最新一帧；成功回执还会记录准确已绘制窗口。`Recovery` 仅接受本地 Esc，包括从保留的子菜单
返回；`Continuation` 允许同界面正常 revision 等待准确重绘时连续导航；`ActivationReady` 还要求
当前所选动作位于该准确窗口内。这些证明都不绑定普通 pane 输出序列。输出可重绘底层而不取消
菜单。新 incarnation、目标删除、结构来源改变或冲突捕获撤销 episode。变尺寸立即撤销两种呈现
证明；随后确认的尺寸失败会拒绝 `Pending`，或暂停已经准入的 incarnation。
renderer 会在改动候选 buffer 或 hit map 前完成几何、行与必要退出提示准入。`NotPresented`
不绘制任何内容，也不发布菜单目标或模态指针背景。

Hover 只更新 Client 本地的临时菜单候选。只有上一已发布帧中准确的可用有类型行可以更新；
coordinator 先重新核对来源与 token，再委托菜单所有者处理。准确已绘制行窗口证明保持有效，
因此同一包中的连续移动都可更新候选；键盘确认仍要求已绘制所选行与当前候选一致。Hover
保留视口、token、可用性、原生导航与执行截止时间；静止指针重协调绝不移动候选。匹配 release
发出有类型激活意图，并重新校验来源与 token。键盘选行及可用性改变生成新 token 并要求重绘。
不维护 hover 队列或计时器。
Pane 重协调取消底层手势，同时在空闲与绘制边界之间保留顶层 ActionMenu owner 已绘制的
hover 与按下状态。匹配释放仍要求相同目标、token、暴露关系与几何；覆盖 owner 或失效的
hit map 会撤销该权限。

全局指针能力仍由 Session 所有。生命周期完整建立全局 `ButtonOnly`（先 `1003l`，再
`1002h` 与 `1006h`）后，endpoint 才按顺序执行一次带 DA1 sentinel 的 `DECRQM ?1003$p`
探测。只有截止时间前收到准确的 Reset 回复（`DECRPM ?1003;2$y`）才准入 `AnyMotion`；Set、
不可用、DA1 先到、300 ms 超时、迟到及重复结果都不会发布全局准入，也不会触发第二次探测。
`Unknown` 与 `Unavailable` 全局保持 `ButtonOnly`，点击、拖动和滚轮继续可用，空闲 hover 缺席。
已准入的升级先写入 `1002l`，再写入 `1003h`，且仅在完整模式写入成功后发布 `AnyMotion`。释放
与恢复清除 `1003`、`1006` 和 `1002`；重新启用时复用已结算能力。捕获已启用、全局尚未准入
时，动作菜单请求 `MenuMotion`：先 `1002h` 再 `1003h`，保留按钮回退与 `1006`。该请求仅为
捕获中的菜单准入实际收到的移动，不改变全局探测结果。关闭、转交或来源失效都先恢复
`1003l`、再写 `1002h`；独立获准的全局升级则继续启用。模式写入失败不发布 lease，且要求完整
生命周期清理。即使键盘打开菜单，已释放捕获仍保持释放。菜单捕获
吞掉移动与决策尾部，不发送给嵌入程序；菜单之外的 pane 跟踪及既有手势保留原归属。

对象入口准入在冻结当前记录之前核对成功绘制 hit map 的 Session 和 Workbench revision。
Workspace 与当前 context 证明保留准确 Workspace 和主 Directory，包括 Worker 和路径；
Tab 证明保留完整投影记录。自有导航候选及最终选中目标必须匹配这些证明。
ID 未改变不能授权被替换的来源。
Context Refresh 与 Tab attachment generation 使用不同类型的导航键，数值相同也不能
结算对方的菜单意图。

打开右键 press 在普通 pointer focus/selection 之前处理。取消或转交后仍捕获其
匹配 release。菜单关闭后仍捕获整个解码决策包，包括分段序列和粘贴。释放鼠标
与缩放在转交前检查冻结前提。
每条菜单关闭或转交路径也捕获已轮询输入，直到发布新帧。已有 pane press、选择、
链接、分隔线拖动、待定 focus 或排队 wheel 流会拒绝菜单准入，继续由原 owner 处理。
仅按下前缀会保留分隔线拖动，直到选定动作；选定的非菜单动作保留原有取消行为。
失去焦点或真实新同按钮 press 会使未上报的打开 release 过期，避免吞掉以后属于
程序的 release。

目录配置暴露与 setup owner 共用的纯拒绝查询。准确冻结的 Workspace/Directory
记录允许在不导航检查非当前目标的前提下，确定其已有目录。键盘或鼠标确认之前
以及转交之前再次查询准入。可用性改变使绘制 token 失效；目标/来源失效仍按
既有规则关闭 episode。

## 正确性与验证

所属实现测试覆盖菜单／帮助共享身份、不透明的配置命令 ID、有效 binding 发现、隐藏不支持动作、
绘制权限、包尾、生成事件重放、取消、来源/目标/焦点变化、准确草稿捕获、最多一次交接、
保留已知提交，以及独立于浏览时间的执行期限。候选 hover 证据覆盖同次绘制前的连续移动、
键盘继续导航、禁用和未绘制行、来源和 token 拒绝、保留视口、指针离开，以及不会隐式打开
子菜单或执行动作。

在 `src/action_menu/tests.rs`、`src/terminal_session/ui/action_menus/tests.rs`、`src/terminal_input/dispatcher/tests/action_menu.rs`、`src/tui_render/tests.rs` 及相邻的状态、carrier、输入和渲染套件中维护实际证据。流程具有多种结果时，使用受控完成/时钟顺序及生成轨迹重放。

运行 `cargo test --locked -p orchbee --all-targets --all-features`。此流程不另设 TLA 模型。证据覆盖命名/生成的实现轨迹，不证明全部交错、物理终端外观或未测试平台。共享身份、所有权和提交协议仍由单独注册的核心模型负责。
