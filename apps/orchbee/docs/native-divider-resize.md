# Native divider resizing

## Contract and owners

A native Client can resize a painted pane split by pressing its divider with the plain left button. While the button is held, each rendered move changes the actual pane layout and the physical controller's terminal dimensions. Release accepts the final ratio once into the shared layout. Ratios remain 10%–90%, shared across Clients and saved by the existing checkpoint owner. Keyboard resizing remains available through [native keyboard resizing](native-keyboard-resize.md). This capability follows [mouse input](../../../docs/tui/mouse-input.md); it does not add a protocol, storage format, input takeover or live process recovery.

`PointerState` owns one reversible `DividerDrag`. `tui_layout` owns the deterministic geometry and its immutable `DrawnDivider`: Session, terminal context, Tab, focused panel, Workbench revision, split, ordered slots, previous ratio, orientation, split area, painted divider and viewport. The Workbench revision records when the source was painted but is not part of the split's identity: every commit anywhere in the Workbench advances it, so a repaint that differs only in revision is the same divider, and the release CAS names the newest installed revision. The renderer records only visible dividers in the last successful frame. Maximized, collapsed and unframed splits expose no resize target. A fresh native check at press, motion, idle and release must agree with that entire canonical source, or with the draft of the owner's own release that is still settling. Separately, the drag retains its last successfully painted draft target. Its own completed frames advance that proof without changing the press origin; multiple moves before a frame still use the prior successful proof. A different canonical focus, geometry, capture or missing/mismatched hit map cancels the draft; it never retargets to a new divider.

Decoded `MouseEvent` coordinates are untrusted cell positions. Only plain left press admits a drag; left-button motion and left or generic release continue it even outside the original region. Ctrl or Alt cannot replace an admitted owner. Other buttons and wheels cannot replace it. Shift cancels the preview and remains Host-owned. The pure `DividerDrag::update` uses displacement along the split axis divided by distributable cells, added to the original ratio and clamped. Perpendicular motion does nothing. Zero displacement preserves the exact original floating-point value. Release projects its own final coordinate, independently of the last motion event. The preview uses the existing minimum-pane-size projection; it may stop moving before the nominal ratio reaches its limit in a small viewport.

The input port returns admission or a visible busy/failure notice and accepts a changed release ratio once. `WorkbenchClientUi` rechecks the selected canonical cache and geometry. A read-only `ResizeProjection` feeds the same tree projector for paint, pointer regions and terminal-size observations. Only the physical controller sends terminal resizes; a local draft grants no new authority. Canonical layout inspection and CAS preparation never consume the draft. The first frame and a newly switched surface initialize their control owner before publication; every draw observes the canonical viewport without another control tick. The shell observes effective pane dimensions before drawing a changed draft. Its own projection is not an external host-geometry change.

`ClientControl` owns the single local asynchronous acknowledgement used by keyboard and mouse: original selection, request identity and deadline. Its lane atomically distinguishes transient backlog from a stopped or failed owner; an idle readiness refusal remains visible. It submits the existing exact split-ratio CAS, waits for canonical publication and a compatible successful draw, and emits no remote receipt. Every commit anywhere advances the global revision, so another Client's unrelated change can refuse a release with `RevisionMismatch` before any effect. That refusal alone is not a failure of the move: the owner reads the newer revision it proves, and while the selection is unchanged and the split still has the previous ratio it resubmits the same move with a fresh request identity against the newest installed revision. Resubmissions continue for at most 5 s after the first such refusal, each once the Client has read a revision newer than the refused one; the released draft stays displayed meanwhile. Exhausting that bound shows the localized `ResizeContended` notice, a changed split shows `ResizeFailed`, and neither the Server protocol nor its CAS semantics change. Keyboard resizing shares this owner and policy. A released divider transfers a presentation lease to that pending operation, retaining the final visible geometry while publication is delayed. While it settles, a press on that draft, or on a split the canonical layout paints, still starts a drag, and the Client control steps that settle the earlier release leave the drag for the next frame to keep or end. Its changed release waits as the one queued release and keeps showing its ratio. A drag on that queued release's own draft replaces it with the newer ratio, against the same layout the queued release was dragged on; while a release is queued, any other divider press receives the busy notice instead of discarding it. Once the earlier release completes it is submitted against the layout that leaves, with the same checks and policy as any release; failure, expiry or interruption of the earlier release discards it under that notice. A drag still held on a draft that such an outcome stops painting, the earlier release's or the discarded one's, ends at its next check under that same notice instead of a separate failure that would replace it; so does one held on a queued release's draft when that release's own submission is refused. A keyboard step while a release settles still receives the busy notice. A resize notice raised while the Client's own resize settles shows on the status line in place of its pending indicator. Canonical publication takes over without adding the displacement again. Refusal, unknown outcome, expiry, interruption, owner/capture loss or external geometry change permanently retires the lease; restoring the old conditions cannot revive it. The submitted mutation still follows its existing completion policy, without retry or rollback claims. [Shared split ratios](../../orchbee-server/docs/shared-split-ratios.md) owns Server mutation and persistence.

Rendering remains pure. Feedback styles the actual moved divider, preserving its junction glyphs and neighboring terminal cells. Hovered and pressed dividers apply the reviewed shared interaction surfaces. Graphics and position receipts are suppressed while local draft geometry is displayed. If the candidate frame no longer exposes the exact projected target, the shell restores the canonical frame and graphics before that same flush. The localized status explains release and Esc while held. A painted draft owns the status tail: the closed machine chooser is hidden until it ends, while an opened machine picker keeps its normal capture priority. Hiding the chooser retires its painted pointer regions in the same frame, so a drag or release crossing that former area keeps its divider owner.

## Transitions and decisions

| State/event                                                                           | Guard and outcome                                                                                      |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Idle, plain left press                                                                | Exact visible source and free mutation lane: retain source and press cell; show preview                |
| Idle, modified/other press                                                            | No drag, no pane bytes or mutation                                                                     |
| Preview, motion                                                                       | Same canonical source and owned painted proof: project pane layout and controller terminal sizes live  |
| Preview, successful own frame                                                         | Retain immutable press source; advance only the painted draft proof                                    |
| Preview, unchanged release                                                            | End locally; no mutation, revision or request allocation                                               |
| Preview, changed release                                                              | Drop gesture before one exact CAS handoff; wait in existing local acknowledgement                      |
| Preview, Esc/Shift/map loss/capture/navigation/external viewport change               | Restore current canonical presentation; no mutation or delayed replay                                  |
| Submission pending, nothing queued, press on its draft or a canonically painted split | Admit the drag; queue its changed release behind the pending one, then submit it with the usual checks |
| Release queued, press on its draft                                                    | Admit the drag; its changed release replaces the queued one against the same layout                    |
| Submission pending, any other divider press                                           | Consume with busy notice; retain no new drag                                                           |
| Refusal for an older revision only                                                    | Read the newer revision, then resubmit the same move while the split keeps its previous ratio          |
| Contention bound passed / split changed                                               | Visible contention / failure notice; canonical state stays authoritative                               |
| Other definite refusal / ambiguous result                                             | Visible failure / unknown; no automatic retry                                                          |
| Held drag on a draft whose release ends without landing                               | End the drag under that release's notice; no separate failure                                          |
| Submission pending, publication delayed                                               | Keep final released geometry under the original source/deadline lease                                  |
| Known commit, publication and compatible draw                                         | Canonical presentation takes over; complete locally                                                    |

Ordinary pane mouse tracking, selection, wheel normalization and Host capture leases retain their existing owners. A release without an admitted drag is inert. Bindings and overlays can cancel a preview; they do not commit it. A ReadOnly Client may change shared ratios but receives no input or terminal-resize authority from the gesture.

## Correctness and maintenance

The owning implementation tests cover hit geometry, two held moves across successful draft frames, canonical source fencing, latest-intent coalescing, interruption, one submission, CAS conflicts and their bounded revision resubmission, a held drag outliving an unlanded release, delayed-publication presentation and publication/draw ordering. Sidebar live width uses the same projection lifecycle under [mouse input](native-mouse-input.md#sidebar-width-input).

Maintain the concrete witnesses in `crates/workbench-client/src/tui_layout/divider/tests.rs`, `crates/workbench-client/src/tui_pointer/tests/divider.rs`, `crates/workbench-client/src/workbench_client/ui/control_steps/tests/divider.rs` and the adjacent state, carrier, input and rendering suites. Use controlled completion/clock order and generated trace replay where the workflow has multiple outcomes.

Run `cargo test --locked -p orchbee --all-targets --all-features`. This workflow has no separate TLA model. Named/generated implementation traces establish the bounded ownership and projection claims, not exhaustive interleavings or physical terminal appearance. Real-host acceptance must capture at least two held moves with an intervening rendered frame before a separate release, checking both visible pane boundaries and actual inner-terminal dimensions. Include both axes, nested splits, sidebar width, clamps and cancellation/retirement. Host observations do not establish untested platforms. Shared identity, ownership and commit protocols retain their separately registered core models.
