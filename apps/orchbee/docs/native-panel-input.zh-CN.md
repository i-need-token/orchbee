# 原生 Panel 输入策略

## 范围与归属

`panel input (<panel> | --panel <panel> | --current) --right-click orchbee|panel`
设置一个规范 Panel 的右键归属。必须且只能选择一种目标，并提供策略。
`--current` 在一次新快照中校验调用者 Terminal/Worker 元数据，不猜测 Client。
显式目标绕过调用者元数据。运行时验收平台是 Windows。
`panel split --right-click orchbee|panel` 在创建时原子提交新 Panel 的策略，
源 Panel 保持自己的策略；省略时使用 `orchbee`。

Server 拥有 `PanelNode.Panel.rightClick`，主 Terminal 尚在启动时也属于该 Panel。
它不是 Presentation 属性、控制权许可、Host 设置或 Client 局部偏好。
默认值 `orchbee` 在序列化时省略，缺失字段解码为该默认值。
出现时必须恰为 `orchbee` 或 `panel`，null 无效。
移动或交换完整 Panel 会保留策略，关闭 Panel 会移除策略。
其生命周期与规范布局一致，限于 Site 进程，不增加重启持久化。

`orchbee` 将右键保留给 Client。`panel` 允许无修饰键的右键按下事件在内容视口内，
且程序启用鼠标上报、现有输入准入允许时透传。Shift 始终属于 Host。
本契约建立路由，不新增上下文菜单或可配置的修饰键绕过。
现有终端编码器拥有上报格式、坐标和不支持像素模式时的拒绝。

## 规范命令模型

| 转换     | 规则                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------- |
| 解析     | 一次快照固定 Site、期望修订及精确 context/Tab/Panel 成员关系。                                          |
| 设置     | 在提交一个后继修订及 `panel-input-configured` 前，准备完整候选、发布及保留结果；只改变目标 Panel 策略。 |
| 相等     | 在当前修订返回 `unchanged`，不改变身份、发布或 Host。                                                   |
| 拒绝     | 授权、陈旧修订、成员缺失、耗尽及容量失败保持所有状态。                                                  |
| 重放     | 现有有界账本为相同语义请求返回原始结果，拒绝冲突的身份复用。                                            |
| 丢失响应 | Client 退役含糊提交并报告未知结果，不自动重试或补偿。                                                   |
| 分屏     | 新 Panel 策略与拓扑、身份一起提交，先于终端启动结算；没有第二次策略修改。                               |

设置操作不改变焦点、缩放、比例、附着、控制权或终端字节。
`orchbee.panel.input` v1 回执记录请求/Site/基础修订、精确目标、请求策略、
已知修订及 `configured` 或 `unchanged`。
它确认规范状态，不确认每个 Client 都已刷新或绘制。Panel 读取暴露有效策略。
创建保留现有分阶段回执，不混淆规范创建与后续 Client 效果。

## 指针状态模型

| 状态    | 转换与不变量                                                                                                                                     |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Idle    | 用新的精确 Pane 实例事实解析最后已绘制的命中区域。保留给 Client 或带修饰键的右键按下不会开启终端手势，不改变焦点或字节。                         |
| Pending | 对未聚焦且可控制 Panel 的许可按下可请求局部焦点。在首个字节前重新检查策略及现有就绪/身份/时限约束；若右键现归 Client，则丢弃整个排队手势。       |
| Pane    | 按下被准入后捕获其按钮及精确 Pane 实例。匹配移动和释放即使策略改变仍属于该目标。其他按钮不能注入新右键或结束本手势；旧格式通用释放结束捕获按钮。 |
| Cancel  | 现有释放捕获、模态所有权、焦点/实例丢失、帧缺失及非实时视口规则继续适用；尾部事件不转移给其他 Pane。                                             |

策略改变作用于下一个手势，不把无匹配按下的释放发到其他位置，也不合成终端字节。
滚轮继续由现有所有者处理。Client 投影刷新更新策略，不替换保留的附着、帧或几何。
同修订矛盾仍然无效，较新修订中的策略改变不改变成员身份。

## 证据与兼容性

与共享 Rust/TypeScript/schema Panel 及命令契约、纯 Workbench 权威、分屏提交、
原生传输/CLI、投影和指针所有者共同维护本参考。
具体证据覆盖严格策略解码、单字段修改、无操作/重放/拒绝、待完成创建及移动/交换保留、
投影身份、按钮归属，以及透传前后的策略变化。
Windows 命令进程及双 TUI 验证覆盖调用者目标、响应丢失、共享策略和实际终端鼠标字节。
帮助、本地化、schema 发现和五种 shell 补全保持同步，最终必须通过根合并门禁。

有限策略/手势模型覆盖准入和捕获归属，不证明任意终端协议行为。
按用户要求继续延期执行 TLA，维护模型和清单但不声称已运行。复核由同一作者完成。

这是增量开发套件契约。旧的严格读取器可能拒绝非默认字段或新命令，因此不支持混合套件。
没有持久化迁移。回退必须使用匹配套件，不为兼容旧读取器而静默抹掉策略。
不新增 macOS 或 Linux 运行时实现。

读取契约：`orchbee.panel.list` v2、`orchbee.panel.get/current` v3、`orchbee.tab.get` v2 及 `orchbee.api.snapshot` v4；目录 v36 含 69 个 schema。旧版本会拒绝新增字段。
