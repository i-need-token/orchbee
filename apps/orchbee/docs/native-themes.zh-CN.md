# 原生主题

## 选择与归属

[共享设备偏好](../../../crates/workbench-protocol/docs/user-preferences.zh-CN.md)将应用外观
（浅色、深色、系统）与终端默认色（Host、浅色、深色、自定义）分开。
应用浅色是通用默认值。系统将 TUI chrome 映射到外层终端语义默认色；
TUI 不修改外层宿主字体或外观。

终端 Host 通过共享内置终端默认色跟随显式的应用浅色／深色。应用为系统时，Host 使用捕获帧／窗口
的前景与背景。显式终端浅色／深色及自定义保持更高优先级；自定义使用校验过的 RGB 对。
只有带默认标记的单元格被替换。
显式程序 RGB、调色板颜色、OSC 覆盖、反色、属性及宽字符几何在实时和保留行中保持捕获权威。
空白画布使用选定终端默认色。

共享 `UserTerminalColors` 解析器还从滚动历史与启动选择的同一确认快照为 Worker 提供新终端
profile。OSC 10/11 查询从终端创建开始就报告这些捕获的默认色，供程序选择自身外观。Host 配合
系统且不存在已捕获的 Host profile 时，保留已有启动基线，不推断外层宿主明暗。现存终端保留
查询默认色，直到运行时所有者显式应用终端主题。Client 外观变化与可撤销的设置预览只重绘带默认
标记的展示，不改变共享查询状态、不重写 ANSI 调色板条目，也不重启程序。因此，保留程序按查询
选定的外观可能与后来的局部预览不同；仅有展示重绘不构成运行时主题已应用的证据。

原生后端在同步帧中合成文字与图形后，于当前输入所有者报告的位置绘制常亮软件块光标。
主题拥有其对比度策略：使用单元格实际显示的背景（包括程序反色），并在该颜色编码内选择
对比度更高的黑色或白色填充。被覆盖字形以前一背景作为前景，dim、hidden 与 blink 属性
不能隐藏光标块，程序隐藏的字形仍显示为空白。这也覆盖自定义前景／背景相同以及空白格的情况。
未知默认色对实际显示的宿主默认色对取反，并计入单元格已有的反色。索引色与 ANSI 对比度使用
规范调色板，仍需物理宿主审阅。

后端保留不含光标的单元格，在每次差异绘制前（包括空差异）擦除旧块，并且只绘制最终请求的
光标。覆盖界面隐藏它或提供自身编辑器位置；面板切换、实时裁剪、保留尾部偏移及恢复均保留
渲染器的输入坐标。宽字符尾格绘制完整字形，同时保持原生输入法锚点的精确位置。光标输出与
原帧共用同一次 flush，写入失败不会重放待绘光标。宿主光标颜色与形状保持不变。Client 绘制时
保持原生光标隐藏，现有终端模式守卫在退出与失败时恢复其可见性。

旧 Windows TOML 接受 terminal-native、one-light 和 one-dark。
它们是迁移输入：显式旧值只为未声明共享偏好提供一次初值。
后续 TOML 重载不能覆盖确认的通用外观。
内置主题角色仍映射 chrome、侧栏、菜单、提示及选区覆盖层；
渲染器消费这些角色，不改变焦点、几何或控制。

浅色／深色角色区分画布、chrome 与浮层。系统使用外层宿主默认值；
量化可能合并表面差异，但边框、标签和焦点仍保留。
浮层边框共享主题角及焦点角色；标题独立使用主要粗体文字。
独立终端弹窗的标题、边框和待定正文使用这一完整浮层表面，包括默认深色的外层宿主。
收到程序帧后，仅内层正文采用其独立终端默认色和显式程序颜色。

标签页分组标题在静止时保留用户选择的成对色块。当前、悬停或按下表面同时将色块前景和背景
替换为对应语义表面上的 `text-primary`，不会把色块的反色文字留在中性填充上。展开标记、数量
及当前标记保留各自几何；移开指针后恢复静止色块或当前表面。低色深和单色宿主使用同一角色
解析器与交互回退。折叠的当前分组始终保留当前标记，包括指针反馈替换中性当前填充时。

主题合约还提供 `accent-action`、`surface-hover` 与 `surface-pressed`。对于共享的浅色和
深色应用外观，这些角色分别适配公开产品色彩权威
[`tokens.css`](../../../packages/design-tokens/src/tokens.css) 中的主要动作、hover 表面与按下表面。
浅色单元格网格适配器在现有 chrome 表面上把半透明 hover 与按下 token 合成为不透明颜色；
深色适配器解析声明的中性色引用。源码一致性测试直接包含 CSS 权威，同时固定语义 token 链与
RGB 投影。系统与 terminal-native 仍随宿主变化，不声称与任一命名外观 RGB 相等。
这些角色已可供渲染器使用，但每个界面仍需消费方渲染证据才能声称已采用。

侧栏显式要求红色的删除意图使用独立的 `accent-destructive` 元数据与调色板归属，绝不借用
`status-error`。随附浅色 RGB 为 `[178, 52, 47]`，深色为 `[224, 108, 117]`，terminal-native
使用 ANSI 红色。禁用内容先于动作语调解析为 `text-disabled`，不能取得 hover 或按下样式。
启用的破坏性措辞保留其强调色，与周围焦点、导航、当前、hover 和按下轨道独立。当低色深或
原生交互使用反色时，主题解析器移除破坏性内容带的反色，并提供独立的对比背景色对。组件既不
构造颜色，也不增加警告用粗体、下划线或闪烁。单色保留本地化删除动词及普通标记。标称调色板
测试覆盖真彩色、ANSI-256 和 ANSI-16 的浮层、hover、按下与选择表面；自定义宿主调色板的
实际外观仍需真实窗口审阅。

命名主题的辅助文字在 One Light 中使用 `[90, 93, 105]`，在 One Dark 中使用 `[170, 177, 189]`。
这些经过审阅的次要色在所有内置表面上都达到 4.5:1，包括按下与临时选区填充，并在 ANSI-256
下与主要文字量化到不同值。同一三元组用于 `text-disabled`、`hint-label` 与 `status-pending`；
pending 修饰与禁用可用性仍保持独立。不得以降低次要文字表面可读性为代价，通过调暗它建立层级。

One Dark 主要文字使用 `[204, 211, 224]`，保留上述次要色与填充。其主要／次要文字的标称
sRGB 对比度约为 1.434:1。标题、主要值、快捷键字形与已有的主要表面前景继承这一由主题拥有的
数值；渲染器不增加局部颜色。破坏性意图、状态、当前身份、导航、hover 和按下轨道保留各自语义。
终端偏好与显式程序颜色保留上文说明的独立权威。

固定 RGB 检查保护所选调色板值及经过审阅的次要色边界。独立回归使用一对可读但近乎等亮的
前景色，说明单靠表面可读性不足以保护层级，再比较内容组合后静止、当前、选中、hover 和按下
表面中的主要／次要文字分离。现有低色深与单色修饰回退继续适用。这些都是标称调色板主张，
不设通用层级比率，也不证明感知区分度；真实窗口下的浅／深色、en-US／zh-CN 与
80x24／120x40 审阅提供独立证据。

## 侧栏行状态

[Workspace 行组合器](../src/tui_render/workspace_sidebar.rs) 负责每行唯一的背景，覆盖 padding、
空白格和续行。[文字组合器](../src/tui_render/sidebar_text.rs) 在应用身份强调前清除继承的整行
粗体，使辅助行保留自身层级。按下、临时导航、悬停、当前与基底表面依次保持该优先级；焦点、
运行状态及未读标记互相独立。悬停与按下不会选择实体。

侧栏和设置共同消费主题的 `paired_pointer_surfaces` 投影，将反色指针回退解析为 ANSI 黑／白配对，
避免 token 前景与继承的 span 背景变成
不同的显示背景。单色保留一条随宿主变化的反色带。导航标记采用同一对比色对；状态与显式 token
颜色保留自身角色。命名 RGB 表面保留其调色板。共享控件消费该投影，不检查活动调色板。

侧栏的持久上下文使用 `surface-current`，与选择器的选区颜色区分。原生主题将 ANSI 灰色背景
与黑色正文配对，随宿主变化的文字不使用 DIM；两个命名主题采用相对 chrome 的中性填充，
并保留主要／次要文字颜色。One Light 在 `[240, 242, 245]` chrome 上使用 `[224, 228, 235]`，
使输入归属终端时持久当前行仍然清晰可见。该填充比键盘选区更克制，同时保留文字的可读对比度。
展开的当前条目中，最具体的行拥有填充：显示活动 Agent 时，其 Workspace 在 chrome 上保留粗体
身份与当前标记，不与该 Agent 的填充合并。折叠 Agent 后，填充回到 Workspace。
当前名称加粗；状态字形与显式 token 颜色保留语义。每行分别为临时导航、当前身份、运行状态
和未读状态预留独立轨道。量化使当前填充与 chrome 重合，或身份 token 显式关闭粗体时，当前行
会在当前轨道显示 `*`，且不改变已配置的 token 修饰。键盘导航使用 `surface-selection`、配套文字
和独立导航标记。临时导航目标同时也是当前项时，`surface-selection` 赢得整行背景，粗体身份或
当前标记继续保留持久当前证据；运行与未读字形仍位于各自轨道。显式 token 颜色和修饰在焦点
样式之后应用。这不推断宿主明暗，也不修改终端调色板。

## 色彩能力

Shell 在绘制前采样一次色彩环境输入。纯解析器依次采用：非空 `NO_COLOR`、
`FORCE_COLOR`、`COLORTERM`、`TERM`。`NO_COLOR` 和 `FORCE_COLOR=0` 关闭界面颜色。
Force 值 `1`、`2`、`3` 分别选择 16 色、256 色和真彩色。非法 force 值为未知，
采用 16 色。`COLORTERM=truecolor` 或 `24bit` 选择真彩色；包含 `256color` 的 TERM
选择 256 色，`TERM=dumb` 关闭颜色。
当 `COLORTERM` 和 `TERM` 缺失或为空时，符合普通 GUID 格式的 `WT_SESSION`
标识 Windows Terminal 并选择真彩色。存在 `TMUX`、`ZELLIJ` 或 `STY` 时，
不采用这个外层宿主回退。显式描述符（包括未知值）保留原有决定；格式错误的会话
标识仍视为未知并采用 16 色。不记录变量值。这是色彩能力决定，不推断终端明暗。

真实宿主对比需随图记录这些描述符。由自动化进程启动的预览可能继承工具专用的
`NO_COLOR=1` 或 `TERM=dumb`；检查普通色彩能力时，仅清除预览进程内这些覆盖，
并将有意执行的单色场景作为独立证据。不得为准备预览而修改用户的持久环境变量。

Windows Terminal 在拉起连接时设置[普通会话 GUID](https://github.com/microsoft/terminal/blob/main/src/cascadia/TerminalConnection/ConptyConnection.cpp)。
没有该标识的宿主仍采用保守回退；不增加终端查询或逐帧环境读取。

接纳主题时在渲染之外完成主题角色量化，使用现有规范 xterm 调色板和感知距离。
16 色下，文字角色排除亮黑，并通过修饰保留次要／禁用层级。无色模式保留文字、
字形和修饰。Host 调色板可能不同；这不构成物理对比度测量或终端明暗协商。
命名 RGB 主题在真彩色和 256 色下仅以已有的柔和前景色显示禁用文字，不额外叠加 DIM。
弱化强度可能把 RGB 前景色变暗，让浅色表面上的禁用文字看起来接近主要文字。
16 色和无色模式下，柔和前景色与主要前景色重合时，量化仍保留 DIM；
`terminal-native` 继续采用随宿主调色板变化的 DIM。
低色级下，宿主可能把 DIM 黑色画得与普通黑色一样。即使禁用修饰已保留，
仍必须显示不可用原因。

Terminal-native 把 `accent-action` 映射为不带修饰的 ANSI 青色。Hover 与按下采用主题解析器的
反色交互带；仅在按下期间由控件而非表面角色为主要标签添加粗体。若 256 色或 16 色量化使
命名 hover 或按下填充与另一交互、基础、当前或选区填充重合，解析器采用同一反色回退；
无色模式同样处理。静止的主要动作不会因此变为粗体或反色：控件稳定的动作语法、动词与分组
保留其可操作性，焦点与按下则保持独立提示。

## 颜色诊断

保留的 Host 继承其启动环境，再应用每个终端的 launch delta。Worker 默认启动声明
`TERM=xterm-256color`、`COLORTERM=truecolor` 与 `TERM_PROGRAM=ghostty`，保留继承的应用
颜色策略。用户显式设置的 `NO_COLOR` 必须继续有效。界面颜色能力绝不重新着色程序的显式单元格。

进行受控颜色对比时，在启动隔离的 Server、Worker、Host 和 Client **之前**，只从夹具环境中
清除已知由自动化注入的颜色策略。对已有 Session 打开新 Client 无法更新保留 Host 的环境。
不得为获得干净夹具而重启无关用户 Session。必须在新建子终端中读取实际环境；只改变前端环境并不足够。

在 GUI、TUI 和参考终端中使用相同应用版本、配置和内容，记录终端默认色、调色板、主题和颜色
能力变量。覆盖 `NO_COLOR` 负对照，以及显式 ANSI、索引色、RGB 前景／背景输出和粗体、淡化等
受支持属性。先检查捕获的单元格样式，区分应用未输出颜色与解析或传输丢失，再检查亮／暗主题
及主题切换下的真实窗口采集。单元格快照本身不能证明最终绘制正确。绝不通过应用专属文本补色
掩盖缺失的输出。

## 发布与重载

有序设置通道在启动时读取共享权威，并每秒轮询。只有完整确认快照更新缓存偏好与其解析后的主题。来源无效或回执丢失时保留最后确认值并显示问题。GUI 编辑和 TUI 保存走同一路径，无需重启终端。渲染器只读已拥有的状态，不读取文件或环境。旧配置重载继续负责无关字段，不能替换确认的通用偏好。

[设置外观草稿](native-settings.zh-CN.md#生效时机与能力边界) 向整帧组合器提供独立、可撤销的调色板与语言，包括背景界面和终端默认标记。该投影不发布运行策略，也不替换已确认缓存；关闭时显示最新已确认外观，程序颜色保留独立权威。
