# Agent 看板

## 范围与归属

Agent 看板是 [native Tab Session](native-tab-session.md) 中一个捕获输入的覆盖层，用于列出
Server 持有的 Agent 会话并跳转到 Agent 已存在的 Panel。Server 拥有一切 Agent 事实——会话
身份、provider、状态、规范新鲜度、注意状态与 presentation 绑定。看板是 Client 投影、导航与
启动界面：会话行绝不从终端像素推断 Agent 状态；空状态操作会把类型化请求交给私有启动流程，
而不是创建 Panel 或伪造会话。本参考文
档随私有 `terminal_session/agent_board/` 模块、其进入 `client_view`、`ui`、`tui_render`、
`tui_pointer` 与 dispatcher 的窄访问点、OBAP 读取通道及它们的正确性证据一同维护。

每行使用共享的六类状态符号：紫色 `◐` 工作中、琥珀色 `!` 需要关注、绿色 `✓` 成功、红色 `×` 失败／取消／中断、灰色 `○` 空闲和灰色 `?` 未知。独立的尾部蓝点表示本 Client 的未读观测。查看只清除蓝点；选中行背景保留语义前景色。新鲜度仍单独标注。

`Ctrl+B g` 切换看板。打开会创建稳定 episode，并在首次绘制前取得顶层输入槽，因此任何
按键都不会漏到终端 shell。首次经过评估的绘制要么接纳该 episode，要么在几何空间无法呈现
界面时拒绝它。新 episode 被拒绝时关闭并单独报告拒绝。episode 一旦接纳，暂时过小的视口会
暂停呈现：行、选择、手动阅读位置及已接受的工作仍由同一 episode 持有。被覆盖或暂停时，
普通按键、粘贴、滚轮及激活均被吞掉且不产生效果；`Esc` 仍是看板的本地关闭路径。模态任务与
确认拒绝配置的前缀后，绑定会经常规 Client 动作所有者执行：`Ctrl+B g` 关闭看板，其他前缀动作
通过目标表面关闭或替换看板。重复前缀也由看板消费，不会到达其下方的终端。之后一次完整绘制
会恢复该 episode；旧 episode 的回执既不能重开它，也不能恢复输入权限。已接受的通道工作可以
落定到同一个隐藏 episode，但分阶段跳转导航仅在 compositor 仍将看板判为顶层原生 owner 且同一
episode 的可见租约仍有效时推进。它绝不会在覆盖界面背后移动 Workbench 焦点，包括子界面已经
打开、下一次覆盖回执尚未到达的间隙。

可交互时，Up/Down 与 `j`/`k` 按不透明 Agent 会话 id 移动逻辑选择并将其显露；仅当选择位于
精确绘制的视口内时，`Enter` 才请求跳转；`r` 请求刷新，`Esc` 或普通背景按下关闭。按行会
选中，内圈滚轮只滚动阅读视口而不改变选择。外圈滚轮、未知按键与粘贴均被吞掉；任何字节
都不会到达终端 shell。modal 或确认持有输入时拒绝打开；prefix 和弦仍然生效，因此
`Ctrl+B g` 同样会关闭看板。打开与关闭两个所有权边界都会使已发布的指针命中表失效，因此
点击绝不会落在已消失的看板行上，也不会穿过覆盖层命中过期前台区域。通知、任务发送、
调度、持久化与新 Panel 创建均不在范围内。

Windows 下，完整列表为空时，看板会让固定的 System32 `where.exe` helper 查询 Client 进程继承
`PATH` 中的规范命令。helper 在输入线程之外运行且没有输出管道。固定本机进程创建与 suspended
Job 分配返回后，自有 Windows Job 会为等待提供单一绝对期限与有界的进程树终止。列出的
provider 只是 Client PATH 候选项：它们不能证明精确目标终端具有
相同环境，也不能证明 provider 可启动。隧道 Session 绝不会把本地 Client 的 PATH 当作目标证据，
因此其目录保持不可用并显示手动 CLI 路径。用户选择一个候选项、输入有界 Agent 名称，再通过
`Enter` 或指针激活**启动智能体**。键盘 Start 与 Cancel 都要求当前成功绘制。激活会注入当时
精确聚焦的 Panel id，
并运行与 CLI 相同的类型化预留、单次提交及 hook 就绪流程。它绝不安装 provider、改变集成／
默认配置或选择缺失命令。接受启动后立即关闭覆盖层并恢复终端输入。后台任务保持单一五分钟期限，把固定的规范关注请求显示为需要输入，并在用户响应后继续观察。启动通知和重开的看板共用同一类型化阶段。已完整发送但超时的命令保持尚未确认且不可重试；投递回执丢失仍为未知。活跃或保留的启动结果取代空会话指引，并与已有规范行同时显示。关闭覆盖层后，已接受的启动工作继续运行；`c` 或可见取消控件才是
显式取消路径。取消会唤醒可取消读取与单次 send 交换；teardown 仍可能等待已开始的 Windows
进程创建或 Job 分配调用，以及最长一秒的尽力预留释放，因此取消并非瞬时。代际与 Panel 身份
会拒绝过期完成，
结果不确定的变更或输入绝不重放。若未找到受支持命令候选项，表单保持禁用，并把
`orchbee agent start <name> --provider <provider> --current` 显示为
手动路径。不完整读取为空时会标注为部分结果，而非声称不存在任何会话。详见
[Windows Agent 启动](windows-agent-start.md)，了解就绪与目标要求。

关闭或取代目录时会取消其 owner，并将其移入退休队列。输入线程只在 owner 已退出后回收它。
Session teardown 负责最终 join；应用取消无法缩短最初的 Windows 进程创建与 Job 分配调用。

成功的界面帧会为同一 episode 授予本地导航与刷新的可见租约。因此，首个步骤即使已使旧行
凭证失效，同一输入包中的连续方向键或 `j`/`k` 仍可继续移动光标。开始跳转以及应用行、滚轮
或控件效果仍要求精确的当前绘制；它们会等待下一次完整帧，而不会对尚未显示的光标执行。

可见的打开、刷新、启动智能体、取消启动和关闭控件使用共享动作语法。本地化快捷键行由原子化的按键与动词项组成，
并将 `Esc` 排在首位，因此窄布局只会丢弃完整的尾部提示。标题也有关闭控件。行或控件会发布
成功帧中的稳定 episode、行来源 revision、逻辑选择、跳转状态、视口偏移及可见行凭证。按下
一行会校验该凭证并立即移动临时选择；控件只有在同一已绘制目标内匹配释放后才执行。键盘
输入、失焦、几何变化或另一输入所有者会取消已触发的控件。列表滚轮每格三行，每次最多合并
一个视口，反向时保留新方向第一格。滚轮绝不改变逻辑选择；下一次键盘导航会将该选择显露。

## 状态与迁移契约

看板在每个打开的 epoch 内运行一条读取通道线程：一个活跃操作加一个合并的待决意图。跳转请求
会替换待决的刷新，并立即取代进行中的跳转——serial 一推进，逻辑跳转即死，无论它已走到
哪一级。被取代的 `Get` 不同：它的结果可能仍在网络上，因此它继续持有物理通道配额，直到
该结果排空或通道退出，新跳转的 `Get` 排在它之后。过期结果只释放它持有的配额——绝不能
清除或取代更新的跳转。在跳转待决期间的刷新请求被吞掉而不会取代它。每一次完成的 List
尝试——成功、不完整或失败——都会启动两秒冷却，`r` 无法绕过；冷却在关闭与重开后仍然
保留，因此重开后立即请求的刷新仍需等完残余冷却。若通道线程在请求未决时死亡，已入队且
仍匹配的结果先照常适用；结果永不会到达的请求诚实地释放其配额——跳转以 `Unavailable`
失败、List 按失败轮次落定——看板绝不悬挂在 flight 中。

Windows 空状态启动 owner 与该读取通道相互独立。它保存一个有界草稿、一个目录任务，并且
至多保存一个启动任务。已接受任务固定其代际与精确 Panel，覆盖层关闭后仍继续，只接受匹配
完成。显式取消会唤醒流程；Session teardown 也会唤醒并加入有界任务，再释放其 origin。已接纳
worker 失联、Pending 或 Unknown 预留、已接受或部分接受输入，以及未知输入前沿，都会跨关闭与
重开保持为 recovery 状态。只有证明零输入且预留已落定的结果才可重试。

| 迁移       | 守卫与结果                                                                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开       | 无 modal/确认占用时看板接纳新 epoch 与一条通道线程；上一条通道必须已经实际退出。last_good 行及其安装年龄、残余冷却在重开后保留；选择按不透明 id 对保留行修复。                                                                                  |
| 绘制裁决   | 首次经过评估的绘制要么接纳 episode、要么拒绝它。后续几何阻塞会暂停已接纳 episode，而不销毁行、选择、视口或已接受工作；被覆盖会撤销当前帧可见性与精确激活凭证。恢复要求一次属于同一精确 episode 的完整绘制。过期回执不能改写或重开另一 episode。 |
| List 轮次  | 一次有界遍历：在单一绝对期限下至多六个同 revision 页、stale cursor 时一次重走、十二次交换共 12 MiB。                                                                                                                                            |
| 读取落定   | 同 revision 的完整遍历为 complete 并成为 `last_good`；预算耗尽或期限到达为 incomplete 或 failed——绝不伪装成空成功，也绝不改写 `last_good` 的安装年龄。                                                                                          |
| 请求跳转   | 按不透明会话 id 选择；通道 `Get` 在当前有界 List 之后重新校验目标，具有独立期限与 128 KiB 上限。更新的请求立即取代逻辑跳转，被取代的 `Get` 同时排空其通道配额。                                                                                 |
| 逐级解析   | 每一级都按当时的规范身份重新解析 context、Tab、Panel；同 context 已附着的 viewer 本地聚焦，否则走 attach/switch。若尚无规范快照喂入 presentation 索引，解析在跳转自身期限内等待并请求会话刷新——未喂入的索引不是 `Gone` 的证据。                 |
| 落定       | 安装精确请求的 Panel，包括非零下标；目标已退役或缺失时报 `TargetGone`，绝不回退。位于当前活跃 Tab 但 viewer 已死的目标原地重挂——按稳定 Panel 身份在同一位置发起新代际 switch；viewer 存活的同 Tab 目标保持无操作。                              |
| 启动 Agent | 完整空读取及当前成功绘制会接纳一个有效名称、一个 Client PATH 候选项和精确聚焦的 Panel。后台流程只预留一次、只提交一次输入，并在单一绝对期限内等待规范就绪。代际／Panel 不匹配会丢弃完成。                                                       |
| 关闭       | 作废看板代际、取消读取／跳转意图，并在实际退出后回收该通道。已接受的启动任务仍由 Session 持有并继续运行；只有显式取消或 Session teardown 才会唤醒它。                                                                                           |

不同 revision 的行绝不拼接。不完整读取保留标记为 stale 的 `last_good`；没有 `last_good` 时
只可展示同 revision 的行并标记 incomplete——且保留 `last_good` 绝不改写其安装年龄，因此
保留行在多次读取以及关闭重开之间保持真实新鲜度。需要注意的行排在普通行之前，组内仍保持
规范顺序；每行原样携带不透明 Agent 会话 id，连同状态、provider、新鲜度与解析出的位置。
侧栏只展示最后一次已完成读取的计数、时间戳与完整性标记——关闭或未读绝不意味着存活或为
零。Get 新鲜度与 List 新鲜度是独立域，绝不互相替代。

刷新按稳定 id 修复选择，并独立保留仍然存在的当前顶部行 id；后台数据绝不会把手动滚动的阅读者
强行拉回选择位置。

导航所经解析的 presentation 索引只由会话实际接受的规范快照喂入——bootstrap 与每个携带
快照的应用器都在其接受分支内重建，被拒绝或未安装的结论绝不进入索引。解析等待索引就绪而
非猜测，过期或无效候选一律保守失败，绝不落到别处。

每个 epoch 的 lane 拥有自身结果接收器；关闭 lane 后，其迟到结果不能送达替代项。Viewer 重新挂接使用既有 detach/candidate/attach 实现及失败路径。失败或过期挂接经生产修复路径报告 Agent Unavailable/Expired。Board、原生执行器与 UI 边界测试覆盖这些结果；不以抽象 board 进展声明保证挂接成功。

## 正确性证据

所属实现测试覆盖同修订行组装、稳定视口锚点、过期或被取代的跳转、准确的非零面板落点、viewer 丢失、有界 lane 清理、精确 episode 输入隔离、首次绘制拒绝、已接纳界面的暂停与恢复、过期绘制拒绝、Client PATH 候选发现、键盘与指针启动、当前绘制取消、worker 失联 recovery、关闭／取消分离及两种语言。

在 `src/terminal_session/agent_board/tests.rs`、`src/tui_render/agent_board.rs` 及相邻的状态、carrier、输入和渲染套件中维护实际证据。流程具有多种结果时，使用受控完成/时钟顺序及生成轨迹重放。

运行 `cargo test --locked -p orchbee --all-targets --all-features`。此流程不另设 TLA 模型。证据覆盖命名/生成的实现轨迹，不证明全部交错、物理终端外观或未测试平台。共享身份、所有权和提交协议仍由单独注册的核心模型负责。
