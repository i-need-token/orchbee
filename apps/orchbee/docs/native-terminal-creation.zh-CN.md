# 原生终端创建

## 输入与所有权

Windows `tab create` 和 `panel split` 先创建一个规范资源，再执行可选的 Client 本地操作。
它们使用已有 Site，绝不启动 Site 或重试结果不确定的创建。`--focus` 与 `--no-focus`
互斥，默认不聚焦。`--client` 指定一个精确交互客户端。总 `--timeout` 默认 30000 ms，
范围为 1 至 3600000 ms。不提供脱离等待模式或调用者指定的创建身份。

`tab create` 接受互斥的 `--workspace` 或 `--standalone`。全部省略时，先使用经校验的
调用者 Panel 所在上下文，再使用无歧义当前 Client 的选中上下文。`panel split` 接受
可选位置 Panel 或互斥的 `--panel`／`--current`；省略时先使用经校验的调用者上下文，
再使用所选 Client 的 Panel。显式 Client 路由忽略调用者环境。部分、格式错误或过期的
调用者身份绝不回退到其他目标。显式上下文或 Panel 且无 Client 操作时仍可无界面使用。
多个可选 Client 明确报错。

创建标签可省略。原生默认标签是预检 Snapshot 中上下文的 Tab 数量加一，或分屏所在
Tab 的 Panel 数量加一。这是原始创建标签。省略 Tab 标签还请求[自动位置命名](native-tab-labels.zh-CN.md)；
显式数字名称保持固定，分屏标签仍为创建回退值。已有几何、exec/args、
profile 和环境变量校验沿用原所有者。Windows 在创建前按下述规则解析目录策略；
显式路径仍是本次启动覆盖。

`panel split --ratio` 指定第一个子区域的份额，与分屏方向无关。有限数字限制到 0.1–0.9。
比例仅属于所选 TUI 会话，其他 Client 保留自己的权重。设置比例不隐含聚焦。右键输入
策略属于独立能力。

调用解析器拥有可选输入。CLI 创建流程固定精确身份并拥有阶段顺序。已有 Workbench
修改解析与类型化 Tab／Panel 创建载体拥有一次规范命令。Server／Worker／Host 保留拓扑、
启动与终端生命周期所有权。TUI 通过已有 Client 控制拥有其比例与焦点。所有者之间不转移状态。

## 流程与保护

| 阶段 | 保护与结果                                                                                                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 预检 | 解析全部输入，启用中断监听，接纳一个会话并读取一个 Snapshot。解析显式／调用者目标。路由、比例或聚焦需要 Client 时，必须在修改前选择已就绪的客户端。                                                                |
| 创建 | 提交一次精确的规范 Tab 创建或 Panel 分屏。保留 Pending／Created 启动事实与分配的身份。拒绝或结果不确定时停止所有后续阶段。                                                                                         |
| 观察 | 已知提交后，观察原 Client 到达该修订或更新修订；不变空视图可由下述控制命令驱动刷新。上下文、Tab、Panel 与 zoom 必须保持原选择；仅允许本次创建导致的数量增长。空目标上下文可自然选中本次精确创建的首个 Tab／Panel。 |
| 比例 | 读取一次新鲜规范 Snapshot，在原 Tab 中定位已提交的 split 及两个有序 slot，提交携带精确预期身份的路径设置。split 或 slot 被替换时拒绝，绝不调整其他目标。                                                           |
| 聚焦 | 如请求，再次观察原 Client，提交一次到新建 Panel 的聚焦。沿用视图修订、中断、附着及绘制保护。                                                                                                                       |
| 完成 | 分别报告规范创建与请求的 Client 效果。后续失败、信号或期限绝不隐藏已知创建或比例结果。                                                                                                                             |

所有阶段共享一个绝对期限。读取可在预算内轮询；规范和 Client 提交绝不重放。信号只停止
后续阶段和等待，不撤销已接纳的效果。不自动关闭、反向调整比例或补偿。已知规范提交在
后续所有失败中保留。规范结果不确定时绝不猜测性地调整比例或聚焦。

空视图没有终端轮询来携带发布提示。原上下文仍为空、选择完全相同且观测修订不回退时，允许提交精确的 Client 命令来驱动已有刷新；命令仍携带创建后的最低修订和刚观测的视图修订。空视图之后显示首个 Tab 时，只允许这次创建的精确 Tab／Panel。

在观察点比较 Client 选择，无法检测两次观察间的选择 ABA。每次 Client 提交还携带新观察
到的视图修订。并发规范变化可使固定路径过期；预期 split／slot 身份防止误调其他分割。
选中比例变化要求绘制；非活动比例只保存、不选择。聚焦、比例与创建之间不保证原子性。
成功绘制不代表 Host 已确认 resize。规范终端启动仍可能待完成或已经失败。

## 回执与恢复

Windows 创建在已知规范提交后输出 `orchbee.creation.result` v3。保留已有规范 `source`
和 `result` 事实，另以 `postCreate` 记录请求的比例／焦点、必要时的精确 Client、各次
已提交 Client 观测、阶段与失败。只有全部请求的 Client 阶段完成才是进程成功；单独规范
提交不代表聚焦成功。无 Client 请求的无界面创建在收到规范回执后完成。已知提交前的
失败沿用现有修改失败信封，包括请求身份和结果不确定语义。

JSON 向 stdout 输出一个完整有界文档。失败文本写 stderr 并包含已知效果。未完成时先
检查返回身份与当前状态，再决定后续动作；重复创建可能再创建资源。Client control-status
可观察已经提交的 Client 操作。不增加持久流程日志或重启恢复。schema 目录为 v36、69
个文档；命令路径仍为 81 个。

## 证据与兼容性

Herdr `e0507237ad8d41f60aece10d00ef29ce2339ca34` 提供可选当前目标、默认不聚焦、显式
focus/no-focus 及分屏比例行为。原生 ID、Client 路由、数字创建标签、f64
规范化及会话期比例仍是明确的原生契约。Panel 右键策略有独立所有者；本契约不声称
实现动态位置标签及持久默认设置。

语法与补全证据覆盖省略、显式形式、歧义、冲突及边界。Windows 命名管道进程轨迹在各
阶段注入失败，并断言不重放及已知效果保留。两个规范载体均验证取消唤醒。独立 Rust、
TypeScript 和 JSON Schema 校验器覆盖可选 split 身份及不匹配回执；TUI 在写比例前拒绝
身份／slot 替换。两个真实 Windows TUI 检查无界面／默认／显式聚焦、嵌套比例、已有终端
身份及其他 Client 隔离。有限阶段模型记录顺序；按用户要求仍不执行 TLA。同作者复核
不是独立评审。

新增 Client 保护要求匹配的开发 cohort；旧严格读取者可能拒绝。已有显式非 Windows
创建保留原路径，不新增平台运行时。不涉及持久迁移。源码回退需协调；已创建资源仍属
用户，只有后续显式操作才能关闭。

## Windows 目录解析模型

`--cwd` 接受绝对路径或 `follow`、`home`、`current`、`workspace`，省略时为 `follow`。
绝对路径、CLI 的主目录／当前目录或 `workspace` 明确跳过来源观测；`workspace` 保留现有
Server Workspace 目录／Worker 主目录默认策略。CLI 在提交创建前将策略解析为现有启动选项，
不新增 Server 设置或持久目录策略。

Follow 使用精确的分屏来源 Panel。创建 Tab 时，只使用目标上下文内已验证的调用者或已选中
Client 的 Panel。显式无界面 Tab 创建不会另选 Client 来猜测来源。只读 viewer 采样精确主
Terminal 的 Windows Job，仅根 PID 对应行提供 cwd，不使用任意子进程／Agent 的目录。
无来源或明确不可用／不可使用的根 cwd 保留启动默认值。拒绝、协议错误、传输丢失、中断和超时
均在创建前停止，读取失败不会重试规范提交。attachment 释放、读取与变更共用整条命令的截止时间。

| 状态      | 允许的转换及证据                                                                 |
| --------- | -------------------------------------------------------------------------------- |
| Parsed    | 效果前解析策略语法；其他创建输入保留原有校验。                                   |
| Targeted  | 一次 Snapshot 固定上下文、Panel 和主 Terminal，不使用无关 Client 的选择。        |
| Observing | 一次可取消 viewer 采样，不影响控制权、焦点、尺寸或终端输入。                     |
| Resolved  | 可用绝对 cwd 成为单次启动覆盖；明确缺失则保留启动默认值。                        |
| Creating  | 原 Snapshot 修订和既有规范载体约束唯一一次提交。                                 |
| Finished  | 创建回执 v3 分别记录请求策略、观测来源／路径及来源 Panel，不将其等同于启动成功。 |

进程 cwd 是某一时刻的观测，不是租约；之后改变进程目录是允许的。目录在启动前可能消失，
启动的既有类型化失败仍为权威。Windows 交互式 PowerShell 通过 Worker 拥有的 prompt 集成
将 FileSystem 位置同步到进程 cwd。仅识别 PowerShell／pwsh 且无参数或只有完整
NoLogo／NoProfile／NoExit 开关的启动。不会改造现有终端或任意启动命令；它们可观测的进程 cwd
可能与 Shell 的私有位置不同。

核心策略／来源测试、实际 PowerShell 5.1／7 prompt 检查、命名管道取消／故障切面及 Windows
ConPTY 创建轨迹覆盖此模型。目录解析后仍沿用既有阶段顺序。TLA 执行继续延期。持久默认配置仍是独立工作；
[Tab 自动位置标签](native-tab-labels.zh-CN.md) 保留原始创建事实。回执版本需要匹配 cohort；回滚不会修改用户 profile 或现有终端进程。

## 插件覆盖层

Windows 插件覆盖层通过活动 Client 的水平 split 和一次带守卫的焦点／zoom 交接创建。创建前被动读取成员，固定返回 Panel 实际选中的主／子 Presentation 与 binding。创建 v5 记录 overlay 请求；v2–v4 保持原有内嵌 Client-control v1 契约。仅 v5 接受新增的 Overlay control v8 答复。成员过期、焦点交接失败或回执不明仍保留已知创建，绝不重复创建。[Windows 插件](windows-plugins.zh-CN.md#覆盖层生命周期模型)负责临时返回链、自然终止、规范移除和 popup 排除边界。
