# 原生键盘调整大小

## 输入与归属

原生 Client 通过 `Ctrl+B P` 进入调整模式。普通方向键将附近分隔线移动五个百分点；Shift+方向键移动一个百分点。`Esc` 退出模式。该模式仅属于当前 Client，不改变焦点、缩放或终端控制权。状态指示持续可见；`?` 打开模式帮助；普通 PageUp/PageDown 翻页。模式拥有输入期间，未绑定按键、前缀组合、释放事件和原子粘贴均被消费。独占对话框和 popup 优先。打开另一种捕获或重载绑定时退出模式。退出后普通输入再次属于 pane。

`ClientView` 拥有模式及纯事件到动作注册表。`InputDispatcher` 拥有解码后的数据包路由；`ClientControl` 拥有异步调整及其唯一变更通道。配置可将 `resize_mode` 和 `resize_pane_left`、`resize_pane_right`、`resize_pane_up`、`resize_pane_down` 绑定到安全直接组合或前缀组合。直接调整使用五个百分点，不进入模式。现有配置及模式外普通方向键的含义保持不变。

窗格动作菜单打开同一个调整模式。工具栏提供四个方向、5%／1% 步长切换、帮助和完成。工具栏替换 Tab 条，Minimal 布局则覆盖内容首行，不改变 Host 几何。方向控件携带绘制时的 Session／context／Tab／焦点／revision 及视口／侧栏；释放时复核全部来源后使用现有键盘调整通道。按下不提交调整。已有提交待定时禁用其他方向控件。键盘输入、失焦、捕获或几何变化取消待定点击；完成退出模式，不取消已经提交的调整。

## 几何与提交

键盘动作仅读取当前选择的原生缓存与视口。`ClientPanelLayout::resize_split` 优先来源的指定方向边缘，其次同轴另一侧边缘，以距离再按规范遍历顺序裁决并列。隐藏或不可用几何明确失败；没有可用分隔线时可见地不执行变更。左/上减少第一个槽位的份额；右/下增加份额。`ClientResizeAmount::apply` 将名义比例限制为 10%–90%；达到边界时可见地不执行变更。这与 CLI 调整使用相同的解析器和有符号比例规则，包含嵌套布局及缩放下未缩放几何。

数值 codec 必须在 JSON 编解码后保留每个已准入比例的精确 `f64` 值。Workbench protocol 在运行时依赖范围显式启用 `serde_json` 的 `float_roundtrip`；仅测试依赖统一开启该特性不能证明实际交付构建。`0.54 - 0.05` 等方向运算经传输后必须保留同值。这是 canonical 比例身份的 codec 精化，不使用 epsilon 比较，也不改变 JSON/存档格式。

捕获的 Session、context、Tab、split、有序槽位、原比例和 Workbench 修订号组成唯一精确的 `layout.set-split-ratio` CAS。不乐观写入本地比例。[共享分屏比例](../../orchbee-server/docs/shared-split-ratios.zh-CN.md) 拥有规范提交、发布及 checkpoint 存储。现有 mailbox 分配新的请求标识，现有可取消变更 worker 只提交一次。不引入新 wire 或持久格式。

| 状态/事件                  | 下一状态与可观察结果                         |
| -------------------------- | -------------------------------------------- |
| 空闲，有效且改变比例的按键 | 提交一次变更；保留原选择及请求标识           |
| 提交待定，继续按调整键     | 消费并提示忙碌；绝不积累或重放按键           |
| Server 拒绝                | 提示失败；保留当前规范状态；不重试           |
| 提交后回复丢失或有歧义     | 提示结果未知；新显式动作前先检查布局         |
| 已知提交                   | 等待匹配发布及兼容的成功绘制                 |
| 发布并绘制精确身份/比例    | 本地完成；绝不发出远程 Client-view 回执      |
| 选择变化、中断或过期       | 若提交可能已生效则提示未完整完成；不声称回滚 |
| 提交后 Esc                 | 退出输入模式；已提交调整仍继续收敛           |
| 本地调整及远程控制投递     | 将远程投递以忙碌拒绝，保持独立的完成归属     |
| 关闭                       | 停止接收、取消有界交换并 join 自有通道       |

已提交的调整会在 publication owner 保留待刷新需求或已有刷新 flight 时继续等待。刷新队列临时满载或繁忙会保留该需求，不构成调整失败；现有 publication drain 在原调整期限内稍后准入读取，不会重新提交 mutation。这对应模型中的延迟 publication 转移，不假定最终一定准入。

读取返回较旧 canonical revision 不代表已知提交失效。调整在原期限内继续等待 publication owner 达到提交水位，不发起第二次由调整拥有的读取，也不重新提交 mutation。

本地与远程调整绝不共享确认标识。结束或中断 UI 等待不能清除 worker 仍待定的交接。迟到的不匹配完成会被消费，不完成另一个请求。只读 Client 可改变共享布局，但不能获取终端输入或 resize 权限。成功绘制确认 Client 几何；Host 物理尺寸调整独立异步执行。

## 正确性与维护

所属实现测试覆盖单一在途修改且不积压、准确完成来源、模式退出/替换、非活动目标纯度及本地成功前完成绘制。

在 `src/workbench_client/client_control/tests.rs`、`src/workbench_client/ui.rs` 及相邻的状态、carrier、输入和渲染套件中维护实际证据。流程具有多种结果时，使用受控完成/时钟顺序及生成轨迹重放。

运行 `cargo test --locked -p orchbee --all-targets --all-features`。此流程不另设 TLA 模型。证据覆盖命名/生成的实现轨迹，不证明全部交错、物理终端外观或未测试平台。共享身份、所有权和提交协议仍由单独注册的核心模型负责。
