# Windows Client window titles

`terminal title set <title>` and `terminal title clear` submit one change to the existing Session. The foreground Client shows the result as its window title: the TUI writes its outer terminal's title, as the lifecycle below describes, and a Desktop window names its page after it, as [the GUI](../../web/README.md) describes. Both accept `--format text|json`. Set removes control characters, takes at most 200 Unicode scalars, then trims; empty results fail before submission. Internal spaces are preserved. No Session or terminal is created.

## State and delivery

The Server owns one ephemeral override and monotonic revision, separate from Panel labels. Set and clear publish even without a Client; foreground Clients receive the latest override, automatic template, or an undelivered explicit clear. When automatic titles are disabled, a clear already delivered to one Client is not automatically reapplied to a different foreground Client. Clear returns to the current configured template, or `Orchbee` when it is disabled or renders empty. The default template is active before the first CLI override. Restart/live-handoff transfer remains separate parity work.

Each authenticated listening connection owns one slot (maximum 32), retained for its active subscription. New attachment or a false-to-true focus transition promotes that connection; idle listening does not steal foreground. Subscription cancellation or disconnect promotes the latest remaining connection; when the foreground leaves, the Server wakes the remaining listeners, so the promoted one receives the current title without waiting for another change. Only that foreground receives the effective rendered title. This describes reported Client focus, not an OS focus query. Clients reapply the current title on foreground promotion; idle repeats are suppressed and demotion discards undrawn state. The latest rendered snapshot replaces older undrawn state; no unbounded event queue is kept. At most 256 request receipts are retained for 60 seconds; exact replay returns the original receipt without republishing, conflicting identity fails, saturation refuses before commit. `changed` records foreground delivery eligibility at commit, not a physical title acknowledgement. With no foreground, the publication is still committed and the receipt says so. Lost submitted responses remain unknown and are not automatically retried.

## Windows lifecycle

A cancellable state subscription uses the shared carrier and coalesces to one latest value. The UI owner consumes its inbox and requests the lifecycle write; it owns no transport thread or 100 ms polling loop. Closing cancels only that subscription and releases its listener. Title changes never alter input, selection, drafts or layout.

The lifecycle captures the inherited console title before its first change, then uses safe Windows title APIs. `win32console` 0.1.5 is admitted only for this capture/write capability: no standard-library or existing safe binding offers capture; it adds no build script and uses the existing winapi version. Its fixed UTF-16 capture buffer is checked for padding and ambiguous truncation; titles of 259 or more UTF-16 units and invalid UTF-16 refuse capture before any title change. Last-error zero distinguishes a valid empty title. Restoring uses the exact captured string, not escaped display text. The existing bounded restoration lease runs on normal exit, errors and owner-thread panic, attempts other cleanup after failures and blocks subsequent title writes. Capture/write refusal shows a localized status notice without closing the TUI or replacing an existing notice; already-owed restoration remains registered. A consumed publication is not retried each UI tick. OS/host settings may ignore requested title changes.

## Contract and evidence

Matched private cohorts add OBWP kinds 43/44 and roll out together. `orchbee.terminal.title` v1 is a closed public receipt. No persisted migration is introduced. Queue acceptance is not display confirmation. The [Windows title API](https://learn.microsoft.com/en-us/windows/console/setconsoletitle) owns physical host behavior.

Focused checks cover Unicode/control bounds, replay/focus/expiry/capacity traces, independent Rust/TypeScript/JSON conformance, real Windows CLI pipe receipts, cancellation, lifecycle restoration/failure and grammar/help/completion. These checks do not replace final provider, multi-Client, physical terminal or full-regression acceptance.

## Configured templates

Windows `[appearance] window_title` defaults to `{hostname}: {workspace}`. It supports `{hostname}`, `{workspace}`, `{tab}`, `{panel}` (manual Panel override), `{terminal_title}` (focused terminal title without activity prefix; a console default title names its program as Tab chrome does), whitespace around token names and `{{`/`}}` literal braces. Missing values render empty. An explicit empty template validly disables automatic writes. Invalid nonempty brace/token syntax, a wrong type, or a value over 4096 UTF-8 bytes defaults only this leaf to `{hostname}: {workspace}` and emits a bounded configuration warning without discarding other settings. The final rendered string removes controls, takes 200 Unicode scalars, then trims; empty rendering uses `Orchbee`.

The Session renders against its admitted configuration and OS hostname, using the foreground listener's bounded display context. On Windows Orchbee queries the OS name; overriding `COMPUTERNAME` does not rename the Orchbee host token. Those strings confer no navigation or terminal authority. Each UI tick refreshes selection labels and the exact live focused frame; stale/unbound frames supply no terminal title. Explicit CLI overrides survive configuration reload and selection changes. Clear removes the override and schedules the latest configured title, or the fallback when disabled. Disabling automatic titles leaves the last host title alone. Delivery revisions and API receipt revisions are independent; idle duplicate rendering is suppressed and promotion reapplies current policy.

`config reload` publishes title changes without restarting terminals. `config reload` v1 exposes the effective `windowTitle` and the admitted diagnostic record; `config check` v1 exposes the same warning and retains the nullable effective-template syntax diagnostic. The private listening request now requires a bounded four-field `context`; matched cohorts roll out together. No live-handoff or persisted override is added.
