# 原生终端输出

## 权威与语法

本文拥有按来源读取的 `terminal read` 和 `agent read`。既有可见屏幕、
`--history --rows`、`--unwrap` 和展示尾部形式仍由
[原生 CLI 查询](native-cli-query.zh-CN.md) 管理。既有调用保持文档和行为不变。

`--source visible|recent|recent-unwrapped|detection` 选择文本快照。`--plain` 直接导出
UTF-8 文本，没有标题或引号，省略来源时默认为 `recent`。
它与 `--format json` 冲突。来源读取拒绝 `--history`、`--rows` 和
`--unwrap`；`recent-unwrapped` 明确选择拼接策略。`--lines` 接受
32 位无符号整数，钳制到 1000，允许零。所有语法在副作用前解析。
Terminal 目标仍为精确 ID 或类型后缀；Agent 选择器沿用既有解析器。

## 选择模型

已应用帧拥有屏幕几何、光标、备用屏幕状态、历史行数、
修订和代次。绝对行空间依次包含保留历史与实时屏幕。

| 来源               | 选择范围和文本                                                            |
| ------------------ | ------------------------------------------------------------------------- |
| `visible`          | 实时屏幕；移除末尾空白行，再应用可选的物理行尾部限制。                    |
| `recent`           | 在最近端点结束、最多 `--lines` 个物理行，默认 80；移除末尾空白行。        |
| `recent-unwrapped` | 相同的最近范围，仅拼接经过验证的软换行续行。                              |
| `detection`        | 一个屏幕高度的最近范围，再应用可选的物理行尾部限制。它不读取 Agent 状态。 |

主屏幕最近端点取光标行与最后一个非空实时屏幕行中的较后者。
完全空白屏幕或备用屏幕使用物理末行。
单元格容量上限可能从开头缩小历史请求；结果报告该事实。
零行生成空文本。文本去除网格填充及宽字符续格，保留 Unicode，
用换行分隔硬行，并为非空输出添加末尾换行。
所选片段可能在软换行逻辑行中间开始或结束；结果暴露这些边缘事实。
限制在拼接前按物理行计数，不猜测逻辑行。

来源词汇对照 Herdr `e0507237ad8d41f60aece10d00ef29ce2339ca34`。
Orchbee 查看器从实时屏幕开始：其他 Client 的私有滚动位置不是共享状态。
只返回当前权威投影；不会用旧的 Windows 缓存屏幕替换空白屏幕。
ANSI 快照和来源等待是该选择模型的独立消费者；本文本契约不承诺原始 PTY 字节捕获。

## 观察生命周期

CLI 拥有 `admit → snapshot → resolve → attach → frame → rows → detach → project → emit`。
Agent 解析在同一会话的附着前完成。可见或空选择无需行请求。
其他选择通过一次缓冲区 `ReadRows` 固定帧的精确修订和代次；
传输、路由、范围与解码行必须全部一致。修订、代次过期或历史被淘汰时
返回类型化失败，不拼接快照或隐藏重试。帧反馈需要确认；缓冲区读取不发送 `RowsApplied`。

既有读取网络期限约束所有会话操作。附着后的每种结果都会尽力分离，
并在输出准备前释放会话。不申请控制器、不调整尺寸、不输入终端、
不启动进程或改变 Client 焦点。畸形或超预算结果在 stdout 前失败。
读取清理及平台准入沿用既有查询契约。

## 输出与兼容性

结构化文本保持本地化与转义。JSON 使用 `orchbee.terminal.output` v1，包含规范
快照来源、终端身份、来源选择、修订/代次、物理范围、
容量截断、片段边缘和文本。目录为 v38、71 个文档；不增加协议形状或命令路径。
`--plain` 在相同准备上限内原样输出 JSON 文本成员的 UTF-8 字节；
文本模式失败保持 stdout 为空。它是
[CLI 输出标准](../../../docs/zh-CN/cli/output.md) 下明确的数据导出，不是普通人类文本展示。

旧二进制拒绝新参数。回滚恢复旧可执行文件；没有存储迁移。
同作者检查覆盖语法、范围/Unicode/换行边界、严格行响应、
输出上限及 Windows 进程/ConPTY 行为。TLA 执行延期；这些是可执行检查和
模型审查，不宣称未运行的模型检查证据。

## 按来源等待

Windows `terminal wait-output` 通过 `--source`、`--lines` 或 `--forever` 选择相同来源。
任一参数会选择来源模式，默认 `recent`，与既有 `--rows` 互斥。既有调用保留
1000 行保留窗口、30000 ms 期限及 v1/v2 文档。来源模式也默认 30000 ms；
`--forever` 则移除总期限，并与 `--timeout` 冲突。
每次准入及 I/O 仍有五秒上限。有限超时沿用既有正数范围，模式沿用非空及
编译程序大小上限。

生命周期为 `admit → snapshot → attach → observe → detach → emit`。每个应用帧在采样前
确认。可见和零行选择无需行请求，其他来源固定一个完整行窗口。
修订或代次过期、历史被淘汰时丢弃该样本并观察新帧，保留原总期限，递增行请求序号。
不拼接样本、不输入、不申请控制器或改变焦点。安静轮询从 10 ms 退避到 100 ms。
I/O、匹配和分离后检查取消及有限期限；迟到的信号或超时优先于成功。
清理保留 confirmed/requested/unconfirmed 区别。

recent 和 recent-unwrapped 等待均在匹配前拼接已验证的软换行；visible 和
detection 在与读取相同的空白行移除及尾部选择后匹配物理行。
文字及正则模式逐个匹配观察到的片段。分开搜索物理行时，正则边缘标记仍描述
原始换行边缘。空的所选文本从不匹配；零行无限等待因此只会在取消或运行时失败时结束。
已有输出可以立即满足等待；成功从不证明新命令或命令完成。

来源模式输出 `orchbee.terminal.wait-output` v3。必需的 `selection` 包含来源及可选行数限制；
观察字段 `timeoutMs` 仅在显式无限等待时为 null。`requestedRows` 是容量/保留范围钳制前
的物理来源预算：visible/detection 为屏幕高度，recent 为显式/默认行数。
`windowTruncated` 只报告容量损失。已完成观察次数统计完成匹配检查的已验证样本，
包括可见帧样本。版本 1/2 文档及约束保持不变；目录为 v38、71 个文档。

固定版本 Herdr 的等待也搜索文本行，将 recent 映射为 recent-unwrapped，并允许无总期限。
其 raw 开关只传递被读取处理器忽略的剥离字段；没有需要复现的原始 PTY 字节匹配器。
不增加无效兼容开关。Windows 进程检查、受控时钟/取消证据及实际终端等待必须验证
来源与生命周期规则。TLA 执行继续延期。

## ANSI 快照导出

Windows `terminal read` 和 `agent read` 接受 `--ansi`，用于导出带样式的数据。默认来源为
`recent`，接受四种来源及来源模式的行数限制，与 `--plain`、`--history`、`--rows` 和
`--unwrap` 互斥。合并软换行应使用 `recent-unwrapped`。所有参数在运行时准入之前解析。
仍可使用 `--format json`；否则 stdout 直接写出准备完成的 UTF-8 ANSI 字符串，不带标题。
这是与纯文本导出相同的显式数据导出例外，不改变普通人类可读文本的转义规则。

ANSI JSON 使用 `orchbee.terminal.output` v2，并包含 `result.encoding:"ansi"`；`content.text`
承载 ANSI 字符串。text/plain 来源读取保留 v1 及其既有结构。目录为 v38，共 71 份 schema、
81 条命令路径。空选择不导出字节。准备及序列化保留既有 8 MiB 输出上限，并在写 stdout 前完成；
超限结果整体失败。直接导出和 JSON 内容都能容纳时，它们的 UTF-8 字节完全一致。

来源范围仍由已确认的帧决定。visible ANSI 使用该帧已验证的单元格样式；recent 来源按帧的
精确 revision 和 generation 请求 render 行窗口。零行不请求行数据。遵循固定版本 Herdr 的
行为，detection 在选择 ANSI 时仍为文本投影。带样式的空白单元格属于内容：只删除无样式的
填充及末尾无样式空行，再应用 visible 的行尾限制。recent 预算仍按物理行计数，先限制后合并。
宽字符延续及占位单元格不得重复字素，也不得在合并的逻辑行中插入占位空格。

CLI 根据规范单元格颜色、样式位、下划线类型及颜色生成 SGR。它输出 RGB 或默认色、粗体、
斜体、暗淡、闪烁、反色、隐藏、删除线和上划线，以及单／双／卷曲／点状／虚线下划线。
样式切换先重置再应用完整样式；行／输出边界恢复 SGR，使选出的尾部可独立显示。Unicode
字素保持完整。单元格字符串及 detection 文本行内的控制字符在相同输出上限内按数据转义。
只有生成的 SGR 与行分隔符属于终端
控制内容；不生成光标移动、终端模式切换、OSC、超链接或图形重放。这是合成的带样式快照，
不是原始 PTY 字节。不增加 Herdr 中无实际作用的 raw 开关。

## Render 观察边界

生命周期仍为 `admit → snapshot → resolve → attach → frame → rows → detach → project → emit`。
来源选择、Agent 解析、精确固定、确认、单次读取的过期拒绝、既有读取时限及清理规则不变。
读取样式不申请控制权、不调整终端尺寸、不发送输入，也不改变 Client 焦点。

既有 buffer `ReadRows` 增加可选 `detail`，取 `text` 或 `render`；省略时为 text，保留旧 OBCS
编码。私有 OBCN 载体的 text 保留动作 tag 6 及精确 body；render 使用 tag 13 和相同的有界字段。
未知 detail/tag 明确拒绝。Server 在既有路由检查之外验证请求的 detail；Worker 转发至既有 Host
行访问操作。viewport 与 TUI 文本读取仍使用 text。不新增 Host 产品输出格式或 Host 协议。

Rust 严格 render 解码器在暴露任何样式或文本之前，验证完整 OBRW、一个 OBPB 快照及一个完整
OBKG 资源快照。投影必须与外层身份、序号、revision、generation、列数、行数和绝对行起点一致。
所有头部、分区、对齐填充、UTF-8 范围、行／换行／宽字符不变量、颜色／样式值、图像字节数、
放置边界及裁剪引用均须验证。借用字符串范围避免重复别名导致内存膨胀；图形字节经过验证，
但不复制像素，也不重放图形。

读取负载上限仍为 8 MiB。即使文本能容纳，render 窗口也可能因图形而超限。应报告有界失败，
不得静默改变 detail、丢弃负载字节、提高预算或改用另一请求重试。旧二进制拒绝新 detail/tag。
开发 cohort 的 Client/Server/Worker/Host 必须一起部署或回退；不新增持久状态或迁移。
新命令运行时由 Windows 承担，共享 wire／codec 保持平台无关。

| 观察                                       | 必须结果                                     |
| ------------------------------------------ | -------------------------------------------- |
| Visible 或零行选择                         | 使用已应用帧或空选择；不请求 render 行。     |
| Recent 带样式选择                          | 帧确认后发起一次精确 render 请求。           |
| Detail、固定值、范围不符，或投影／图形非法 | 写 stdout 前失败，并释放只读查看器。         |
| 固定值过期或历史被淘汰                     | 单次读取的类型化失败；不重放，不拼接样本。   |
| 有效带样式空白或宽字符                     | 在物理行限制及换行规则下保留样式和字素顺序。 |
| 准备后输出或 render 负载超限               | 输出前有界失败，不将截断伪装成成功。         |

## ANSI 证据与限制

TS/Zig 共享 packed-projection 与 render-window 语料提供独立编写的 wire 判定依据，覆盖非法
头部／分区及稀疏 delta。Rust 测试另覆盖图形边界／引用、规范 text 编码、render detail 路由
和精确固定拒绝。CLI 检查覆盖参数、schema、补全、样式切换、控制数据、Unicode／宽字符、
空白填充、换行边界及输出上限。Windows 进程 peer 验证实际生命周期；匹配 cohort 的
PowerShell 5.1/7 会话验证带样式 Unicode 导出、管道、保留输出及 TUI 焦点不变。
这些检查必须在交付前通过。审查由实现作者完成；TLA 执行仍延期，不宣称独立审查或未执行的模型证明。

OBTF 与 OBPB 的网格几何以 `(0, 0)` 保留未知字符像素尺寸，与 Host 及控制几何契约一致。
否则两个尺寸都必须为正；零值与正值混合的组合非法。网格及像素范围上限不变。
终端快照不会为了导出文本或样式而编造像素尺寸。

空白判定按借用字符串的身份与长度缓存；重复别名不会放大填充扫描，也不会在输出预算生效前分配展开文本。

来源范围直接从借用的可见单元格分类得到，不展开共享字符串。可见文本读取及等待先删除末尾
空行并选择物理行尾部，再生成文本。每次追加（含行分隔符）前检查累计 8 MiB 预备上限；
被省略的行及共享空白别名不分配展开文本。recent 和 ANSI 选择不生成未使用的纯文本可见
副本。填充、宽字符及控制数据规则保持不变，同时避免共享字素别名在预备阶段绕过输出预算。
