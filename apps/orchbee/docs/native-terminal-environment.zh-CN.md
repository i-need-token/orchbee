# 原生终端环境

## 范围与归属

本参考治理原生 Client 在运行时拥有的宿主终端契约的两个部分：面对瞬时零几何的视口观测，
以及每个绘制帧的同步更新包裹。它与 `terminal_device.rs`、`terminal_lifecycle.rs`、
`tui_backend.rs`、`tui_shell.rs` 共同维护。准入验证 TTY 身份与描述符安全（两个流上的
交互 TTY、同一终端身份、几何查询本身可用）；获得可绘制的单元格几何是独立的就绪关注，
由 [`native-startup-wait.md`](native-startup-wait.md) 治理。宿主以零报告的像素几何被
如实报告为 "pixel 未知"——一种正常状态，绝不伪造。

## 视口观测

对继承终端的运行时观测区分三种结果。区分基于类型化结果，绝不基于错误文本。

| 观测     | 含义                                        | 运行时效果                                                                  |
| -------- | ------------------------------------------- | --------------------------------------------------------------------------- |
| 有效几何 | 宿主报告了非零行列                          | 变化时应用 resize 并重绘；相同几何是 no-op                                  |
| 零或缺失 | 宿主瞬时报告了零行或零列                    | 不发送 resize、不清退 Session、上一有效几何保持生效，下一个有效几何正常恢复 |
| 检查错误 | 描述符或查询本身失败（权限、关闭、非法 fd） | 致命：故障传播，界面退出                                                    |

像素宽高为零是正常观测而非错误：cell-pixel 对被报告为 `(0, 0)`——"pixel 未知"——字符
网格照常工作。当宿主只报告一个像素轴，或推导出的 cell-pixel 轴向下取整为零时，整个
对按未知报告，而不是虚构缺失轴。像素读数为零的单元尺寸变化同样绝不通过复用旧像素值
来解决——旧像素永远不是新尺寸的度量。已知 → 未知 → 已知 的转移走同一条几何路径；
每个状态都按实测报告，下游依赖像素的功能按"成对已知"门控，而非按任何估计值。

## 同步帧输出

每个绘制帧——完整的单元 diff 及其光标定位——被恰好一对同步更新包裹，并由一次 flush
发布。`terminal_lifecycle` 是该对的唯一所有者：它定义 begin 与 end 序列、在共享租约上
追踪"对仍开启"的义务，并负责恢复。backend 仅通过该租约参与：它在尝试 begin 标记之前
登记义务，因此即使 begin 只部分写入仍欠一个 end；只有当 end 标记与帧 flush 都被写器
接受后才清除该义务。凡无法确认送达时，该对保持待恢复。

| 状态            | 效果                                                                   |
| --------------- | ---------------------------------------------------------------------- |
| 更新已关闭      | draw 操作登记义务、发出 begin 标记并进入更新开启                       |
| 更新开启        | 单元、属性与光标写入在对内累积                                         |
| 更新关闭        | flush 发出 end 标记并对写器执行一次 flush；两者都成功才确认关闭        |
| 更新开启 + 失败 | 保留首个失败；之后的 flush 仍尝试 end 标记                             |
| begin 写失败    | 义务保持登记；下一次 flush 仍尝试 end 标记                             |
| end 未确认      | 该对保持待恢复；下一次成功的 flush 重发 end 标记，或由恢复流程终结该对 |

失败保留其首因。flush 失败仍尝试 end 标记；end 标记自身失败在尝试后报告，绝不在一帧内
静默重试。draw 失败则放弃该未完成帧：错误路径上帧写器在其被 drop 前先被围断，其缓冲
残量连同 drop 时的重试均不再送达终端。已写出的字节无法撤回；仍开启的对由恢复时经控制
通道终结。

恢复由 lifecycle 拥有并按固定次序执行：先阻断后续帧输出，再经由终端控制通道在与其他
模式相同的有界重试预算内终结仍开启的对，之后才关闭 bracketed paste、显示光标、离开
备用屏幕并恢复 raw 模式。帧写器带恢复门控：恢复一旦开始，缓冲的帧字节被丢弃而不再
送达正在恢复的终端，这也覆盖了 panic 展开时的 unwind flush。输出失败后，同一围断在
帧写器被 drop 前先行生效，使其 drop 时的重试同样无法发出被放弃的帧。干净关闭不欠任何东西，
也不多发任何字节。本契约既不承诺每帧一次操作系统写，也不承诺在不支持同步更新模式的
宿主上获得视觉原子性。
