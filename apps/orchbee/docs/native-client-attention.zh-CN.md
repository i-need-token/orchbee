# 原生 Client 提示状态

## 范围与参考

原生 Client 负责记录是否已向用户展示 Agent 观察。Agent 生命周期、语义状态和新鲜度仍归 Server；聚焦不能改写它们。确认属于各个 Client；CLI 投影必须选择 Client，不能虚构全局焦点。

## 宿主焦点输入模型

| 要素 | 契约                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题 | 后台终端不能把新的 Agent 状态确认为用户已看过。                                                                                                           |
| 输入 | Windows 控制台焦点记录及 bracketed paste 外完整的 DEC 焦点报告；不将进程输出解析为宿主输入。                                                              |
| 状态 | 每个原生 Client 以未知外部焦点开始，随后保存宿主最后报告的聚焦/失焦事实；状态随 Client 结束而释放。                                                       |
| 归属 | 控制台适配器编码报告，共享解码器分类，dispatcher 在前缀/确认/Agent 面板处理前向原生 Client 发送类型化观察。模态编辑保留宿主元数据，粘贴内容仍是字面文本。 |
| 转移 | 获焦记录聚焦，失焦记录未聚焦，重复报告幂等；焦点报告本身不确认帧。                                                                                        |
| 效果 | 消费焦点协议，不透传字节，不触发按键绑定；保留两侧普通输入顺序。不激活操作系统窗口，不改拓扑或 Agent 状态，不转移控制权。                                 |
| 租约 | Windows TUI 通过终端生命周期开启 DEC1004；尝试开启前先记录恢复义务。正常/错误/panic 退出均恢复；失败后继续其他模式，保留失败义务。                        |
| 证据 | 控制台事件编码、分段 CSI 与粘贴/捕获路由、模式开启失败及恢复轨迹。每 Client 确认/CLI 投影和真实 Windows 集成属于后续依赖证据。                            |

失焦禁止自动绘制确认；未知焦点不建立操作系统事实，后续展示策略必须在确认模型中明确。仅此输入/生命周期边界不构成 seen/unseen 对齐。不新增 macOS/Linux 运行时，不执行 TLA。

## Client 观察与确认模型

Windows Client 拥有最多 512 个 Agent 摘要及其已确认状态版本。版本由 canonical 观察 generation 与该会话最近一次有意义状态变化的 revision 组成。状态、新鲜度、生命周期与 generation 变化推进版本；其他 Agent 的变化和仅附件元数据变化不推进。初次完整基线标为已读；之后的新版本保持未读，直到成功展示。不得改写 canonical 状态或待处理请求。

后台读取通道在同一五秒期限内消费保留变更并获取一致会话列表。只有列表 revision 与已消费日志头部对齐时才发布结果；对齐重试受固定工作量限制，最多保留 512 条变更，拒绝不完整或拼接的证据。Agent board 通过独立拥有的句柄使用同一读取通道基础设施。提示状态最多有一个在途读取轮次；UI 线程不执行端点 I/O。取消、退役及 Drop 会中断通道、断开并 join 工作者。

| 事件                                         | Client 转换                                                                  |
| -------------------------------------------- | ---------------------------------------------------------------------------- |
| 首次一致轮次                                 | 安装摘要，将当前版本初始化为已读。                                           |
| 后续一致轮次                                 | 折叠每个会话的语义转换，保留无关确认；同时发布已对齐的元数据和版本。         |
| 传输/读取失败                                | 保留展示数据但标为不可用；恢复一致证据前禁止确认。                           |
| 无效游标或保留范围 reset                     | 使连续性和确认失效；恢复的新一致基线保守标为未读。                           |
| 完整成功绘制                                 | 只确认具体可见窗格 presentation 上的精确版本，并要求匹配 Client 快照 token。 |
| 失败、过期、被遮挡、零尺寸或 scrollback 绘制 | 不确认。                                                                     |
| 已知外层失焦                                 | 即使绘制输出也不确认。                                                       |

外层焦点未知时，在宿主报告失焦前，完整有效绘制可以确认。这不保证操作系统前台状态；支持焦点上报的宿主提供更强区分。焦点事件本身不确认。绘制后重新检查窗格身份、当前 presentation 绑定和精确观察版本；zoom 隐藏的兄弟窗格及 Agent board 摘要不算已查看窗格。所有实际可见窗格均可确认，各 Client 独立。查询消费者必须区分观察不可用与已读/未读。

渲染器返回有界的具体绘制证明；旧快照回执不能确认新事件。确认可以请求一次后续重绘以移除未读标记，不能形成无界重绘循环。证据覆盖两个独立 Client、快速中间转换、仅元数据变化、reset、失焦、过期回执、隐藏/遮挡窗格及读取通道退出。下述 Client 查询公开这些观察，但不会确认已读。

显式 `agent focus` 具有独立命令效果：经过验证的导航和绘制完成后，确认所选 Tab 中
当前已知的 Agent 版本，包括被缩放隐藏的主面板及已知外层失焦。它不放宽普通绘制门槛，
也不让只读 attention 产生确认。[Agent 导航](native-agent-navigation.zh-CN.md#agent-身份与显式确认)
负责身份检查、中断及绘制后边界。

## 指定 Client 查询

### 物理终端观察与绘制

终端 Agent 使用报告所有者的语义序号和完整物理绑定，不使用规范 Session 或 provider
观察计数。有界 `states` 读取指定最多 64 个唯一展示（含子展示），按请求顺序返回精简的
当前绑定／序号／Agent／状态行。空行表示没有当前物理观察；展示不存在则拒绝读取。
Session 成员关系、保留的 Host 创建／epoch／终端身份及当前 Worker 门槛一起检查。
这些读取不修改报告，也不确认用户已经看过。

Client 在独立后台读取通道观察 Session 全部展示；只允许一个待决轮次，读取预算五秒，
最多保留 4,096 个物理条目和 8 MiB 精简数据。完整分批轮次中的 Workbench 成员关系与
报告修订必须一致。Client 注意力所有者将物理确认与规范版本分别保存；规范观察不可用时
不能作为物理证据，反之亦然。

| 事件                               | 物理 Client 转换                                            |
| ---------------------------------- | ----------------------------------------------------------- |
| 首个完整基线                       | 将当前物理序号初始化为已看过。                              |
| 同绑定、更新语义序号               | 替换当前状态；新序号尚未看过。                              |
| 仅消息／引用更新                   | 语义序号不变，保留确认。                                    |
| 新物理绑定或重新出现的条目         | 初始基线之后以未看过开始。                                  |
| 绑定移除或不可用                   | 移除可读条目，不虚构已看过／未看过事实。                    |
| 序号倒退或同序号下 Agent／状态变化 | 在任何部分发布之前拒绝轮次。                                |
| 读取失败、退役或关闭               | 禁止确认，中断并等待自有读取者退出。                        |
| 可见内容成功绘制                   | 只确认绘制后仍匹配的精确绑定／序号、Host 帧路由及绘制序号。 |

物理绘制同样遵守既有遮挡、历史滚动、缩放、几何和外层焦点门槛。旧 Host 帧不能确认
替换后的终端。同一展示的规范与物理观察不产生重复未读标记。没有报告 Agent 的普通终端
不产生 Agent 标记。读取不算绘制。

Viewer attach 在 epoch 和 attachment ID 之外返回实际 Host 终端 ID。投影保留这一身份；
帧接收已校验 epoch／attachment 路由。绘制前后均将 epoch 与终端 ID 一起对应到报告绑定。
一个 Host 拥有多个终端，因此仅检查 epoch 不足够。Host 终端 ID 在同一 epoch 内唯一；
包含创建身份的完整报告绑定仍是确认键。这一私有 attach 契约要求匹配的 Client／Server
cohort，Host 帧编码保持不变。

`terminal-agent-attention` 为 1–100 个唯一物理绑定复用既有 ClientView 读取生命周期。
有序条目包含可空的当前序号／seen 值、报告修订及可空外层焦点观察。CLI 合并要求精确的
所选 Client 与物理绑定、相同语义序号，以及覆盖 Client 样本的 Server 报告修订。
Client 证据缺失或过期时，seen 保持未知。状态投影始终保留报告含义：idle、working、blocked、显式 done、error 或 unknown。Seen 不推导完成，也不清除结果。
物理 Get、attention、wait 和 prompt 消费者共用此合并；输入和焦点仍是独立效果。
Wait／prompt 条件独立于已读确认消费状态证据；done 保留既有的已结束结果别名，succeeded 和 failed 选择明确结果。

定向正确性检查覆盖确定性的基线／变化／替换／静默更新轨迹、两个独立内存 Client、
过期与不匹配绘制证明、一致分批边界和有序协议关联。两个真实 Windows Client 及
进程／绘制／查询集成仍属于最终联合验收。
这些有界证据不意味着已认证 provider、操作系统前台、完整视觉或无界证明。

现有按连接归属的 ClientView 通道将 `agent-attention` 读取路由到显式指定、调用者推导或唯一发现的 Client。意图包含 1–100 个唯一 Agent 会话 ID。`attention-read` 从同一个一致 Client 快照立即完成，不导航、不输入、不改变焦点或确认已读。弹层使 Client 忙碌时仍可读取；单次交付、新鲜度、精确视图版本、期限及回执容量规则继续生效。

快照携带规范变化游标及版本、可空的外层焦点观察，以及按请求顺序排列的条目。每项包含当前 generation、观察 sequence、语义变化版本和 seen 标记；会话不存在时 state 为 null。Client 观察不可读取时返回 `projection-unavailable`。查询只证明记录版本上的观察，不承诺 Agent 后续不变。CLI 消费者公开已读/未读前，通过当前 changes 服务认证返回游标；关联规范详情还要求 generation 和 sequence 一致。其他启动周期游标及不一致关联不能制造已读确认。

Workbench 协议复用有界 Agent 协议身份、游标及安全整数 DTO，不依赖运行时。提示状态提交和完成使用上限 64 KiB 的请求类型 29；结果类型 26 已有该上限。Server 回执存储预留提示状态载荷容量，并在发布前验证请求与结果会话完全对应。保留回执不会自行刷新或重复读取。共享 Rust、TypeScript 和 schema 检查覆盖形状、边界、重复、顺序、版本及归属；Windows 进程与双 Client 见证覆盖路由和实际绘制确认。

`agent attention <target> [--client <id>]` 一次解析会话/名称/窗格，读取该 Client 而不聚焦。`--agent-session`、`--name` 和 `--panel` 可显式选择。支持现有 `--request-id`、`--detach`、`--timeout`（默认 30000 ms）及 `--format` 回执生命周期。`client control-status` 也认证提示状态游标。文本报告已读、未读或尚未观察到；JSON 使用 `orchbee.client.control` v1。目录列出当前文档与命令路径。

## 合并规范 Agent 读取

Windows `agent get <target> --client <id>` 在一个已准入会话及五秒总预算内，将精确 Client 观测与后续规范 Get 合并。读取仅路由一次保留的 attention 操作，认证游标，再要求规范修订覆盖 attention 头部。只有 generation 与 sequence 均相同，才输出合并后的 seen／状态变更修订。有界变更读取还须证明 Client 检查点与规范样本之间该会话没有变化；相同计数器无法排除新鲜度跃迁。其他会话的变更保留合并结果；历史丢失或目标的任何中间事件都会保守地标记过期。缺失及过期 Client 版本明确标记，seen 为空；不改写规范状态。不带 `--client` 的 Windows Get 使用带终端、运行时和托管信息的 v1；合并 Get 使用 v1。两者均在同一总预算内，于进程读取后重新核对 Agent 绑定。

独立的 Client 状态将 idle 映射为 idle、succeeded 映射为 done、failed/canceled/interrupted 映射为 error，与 seen 或确认缺失无关。Working、blocked、unknown、ended 及 stale/disconnected 新鲜度采用规范事实。聚焦指匹配的主 Panel 在 Ready Client 视图中被选中，且未观察到外层失焦；外层焦点为空时保留已声明的兼容回退，不证明操作系统前台。Busy 时仍可读取，但不声称内容聚焦。读取不确认已看见、不导航、不发送输入。

CLI results 归属持有此投影；Agent Client view 组合负责读取和版本合并。Windows `agent wait --client <id>` 在 v1 复用此投影：idle/done 依赖包括保留变更在内的规范状态证据，不依赖 Client seen。规范历史事件不证明过去的 Client 已读确认。Get 已包含进程与提交预检信息；托管交互就绪仍单独待办。证据覆盖精确 Client／操作关联、generation 与 sequence 滞后、缺失条目、跨启动周期、当前修订、独立焦点及已看见状态，以及原有期限／取消清理。

Windows `agent prompt --wait --client <id>` 也在规范活动门槛后使用此当前投影。发送前预检精确 Client，后续观察失败时保留发送回执，以 v1 输出所选 Client。期限、采样与不重发规则见 [CLI 查询契约](native-cli-query.zh-CN.md)。

Windows `agent list --client <id>` 先用一个有界规范页选出至多 100 个会话 ID，提交一次保留的 attention 读取，再读取相同页／游标。一次有界变更扫描将全部条目与较新的规范修订核对。目标中间事件或计数器不匹配使对应 Client 投影过期；新增 ID 为缺失，无关事件不影响其他行。页游标过期时失败，不重启分页。空页只验证所选 Client，不执行空 attention 操作。v1 结果增加 `clientId`，并在每个规范条目上增加 `client` 投影；无该 flag 的 list 保持 v1。共用五秒总预算、精确 Client 选择及既有取消／清理规则。列表读取不聚焦、不确认已看见、不逐 Agent 扫描进程。

Windows Agent Get 现在输出 v1（使用 `--client` 时为 v1），增加独立的 `management` 观察，包含来源、修订及 Server 所有的启动状态。Active 记录只来自已完成的启动；手动命名会话仍为非托管。Pending 启动使 promptReady 为 false，`agent prompt` 在输入前拒绝。Status 有界读取共用命令原期限，失败可使用 Agent 读取失败 v1（`operation: management`）；它不重试、不完成启动。`agent start` v1 在现有成功完成后显式报告 interactiveReady。[启动契约](windows-agent-start.zh-CN.md) 拥有生命周期和限制。

## 自动通知确认边界

自动物理 Agent 通知 scheduler 消费本 Client 的物理状态及确认，但不会成为第二个 seen
owner。变化后的精确 sequence 可以调度本地工作。精确可见版本成功绘制后，即使外层焦点
明确丢失，也会取消对应通知；只有本文要求焦点成立的确认才把 attention 版本标为 seen。
这项仅通知使用的取消不能确认、改写或推断观察，不能抑制后续 sequence，其他 Client 的绘制
也不能抑制本 Client 的工作。基线、reset、不可用及替换轮次不提供通知转移。触发矩阵、
延迟、配置、sink 及正确性契约见
[Windows CLI 通知](windows-notifications.zh-CN.md#自动物理-agent-通知)。
