# TUI shell 布局

## 范围与归属

原生 Client shell 把宿主区域划分为顶部条、内容区、可选侧面板、带共享边界的窗格区，以及一行
状态栏。本文档声明 `docs/tui/layout.md` 要求所属应用给出的具体区域、阈值与降级顺序。它只
拥有布局投影：颜色、字形与边框样式归主题层，浮层内容归各自 surface 渲染器，终端单元格绘制
归 `terminal_cells`。

投影是纯函数。`tui_layout::project_shell_areas` 根据当前帧矩形与视图请求的侧面板形态（含首选宽度）计算
所有区域；`tui_shell` 用同一对函数（先 `project_shell_areas` 再 `terminal_area`）计算终端
几何，因此绘制内容区与 wire 几何不可能分叉。渲染代码不修改业务状态、时钟或 I/O，布局值也
不跨帧缓存。

## 视口分级

宽度与高度独立分级，取两者中更低的级别。

| 级别     | 宽度级（列） | 高度级（行） |
| -------- | ------------ | ------------ |
| Full     | >= 100       | >= 24        |
| Compact  | 60..=99      | 12..=23      |
| Minimal  | 20..=59      | 5..=11       |
| TooSmall | < 20         | < 5          |

`tui_layout` 中的 `ViewportTier::from_size(columns, rows)` 是唯一分类器。各级 chrome 行列
配额：

| chrome     | Full               | Compact                  | Minimal  | TooSmall |
| ---------- | ------------------ | ------------------------ | -------- | -------- |
| 顶部条     | 1 行（tabs）       | 1 行（tabs）             | 无       | 无       |
| 状态栏     | 1 行               | 1 行                     | 1 行     | 1 行     |
| 侧面板     | 停靠，有界首选宽度 | 浮层，有界首选宽度，靠左 | 隐藏     | 隐藏     |
| Panel 边框 | 绘制               | 绘制                     | 不绘制   | 不绘制   |
| 内容       | 剩余区域           | 剩余区域                 | 剩余区域 | 仅提示   |

TooSmall 时 Client 只绘制一条本地化的小尺寸提示与状态栏，别无他物；宿主变大即恢复正常渲
染。视图请求的侧面板形态只是一种意图：`project_shell_areas` 按级别翻译它（`Docked` 与
`Overlay` 都表示可见：Full 停靠、Compact 浮层、更低级别隐藏），因此渲染 chrome 与 wire 几
何保持一致，调用方无需关心级别。

Windows 侧栏按配置的行高、行间距及原有标题／上下文／页脚行数分配 Workspace 和 Agent 区域。
短分组不再保留半个侧栏，长列表可以使用腾出的空间。两组内容都能放下时保持紧凑，
当前 Workspace 行与当前／第一条 Agent 行（含观察占位信息）完整显示的优先级高于分组间距；
只有这些行与两组标题／上下文／页脚都能放下时，才留一行间距。
不足六行时，Workspace 保留原有仅显示标题的降级。
过滤、行身份与滚动保留既有语义。
鼠标区域与显示行使用同一份最终矩形记录。

规范导航行可用时，侧栏从项目开始，不再重复应用品牌和底部已有的普通会话状态。
行尚未到达时保留原有连接与业务占位。覆盖式侧栏在分组标题前保留一行顶部留白，停靠分组则直接开始。
活动工作区保留原有标记及准确行目标；导航拥有输入时，仅键盘焦点行的全部配置行使用选中背景。
顶栏显示当前位置，不再附加 Workbench 前缀。
分屏的共享外框不再重复通用标题，基础样式使用中性色；焦点窗格周围已有的边界线段
采用聚焦框架角色，同时保留该窗格的强调标题。不增加边框单元格，鼠标、分隔线和
终端矩形保持原样。分隔线端点更新外框已有边界单元格的交汇字形，
不留半格断口，并保留框架角样式。
单窗格和放大视图保留焦点边框。窗格标题使用本地化“终端”标签，
保留自定义元数据、序号和终端呈现身份。
非焦点终端内容保留正常文字对比度；焦点由窗格 chrome 和光标表达，
不对其他程序的内容附加 DIM。
Shell 先绘制终端画布，再为侧栏、标签／状态栏和分屏标题带绘制持久 chrome 背景。
覆盖层绘制自身完整的不透明表面；边框和标题表达边界及焦点，区域区别不再只依赖它们。

## 侧栏 Agent 计数与入口

侧栏投影已有 Machine 选择器行，不改变观察、过滤、选择、激活或滚轮归属。
空 Agent 结果不能仅因观察占位信息占了一行，就看起来像有一个 Agent。

| 输入／决策                  | 投影与不变量                                                                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 完整 Agent 行               | 标题统计现有视图过滤后的真实 Agent 条目。页脚可见范围只统计这些条目，不包含观察占位行。                                                                                         |
| 加载中或不可用的数据源      | 保留明确状态；没有已知 Agent 数量时不显示零计数标题。非零的部分计数与范围保留 `+`。                                                                                             |
| 窗口内没有可见 Agent        | 窗口外还有已知 Agent 条目时显示 `0/total`；没有 Agent 条目时省略范围。占位行不获得 Agent 序号或激活目标。                                                                       |
| 唯一启用 Machine 上的空结果 | 只用一行状态，不重复 Machine 标签。存在多个启用 Machine 时保留各自标签和独立状态行。                                                                                            |
| 上下文行                    | 有 Agent 或结果无匹配项时保留当前视图／过滤摘要；没有 Agent 的空结果、加载中或不可用状态省略摘要。                                                                              |
| 入口                        | 分组标题与本地化浏览页脚保留已有选择器目标。固定在底部的入口本地化为 `[Menu]` 或 `[菜单]`，打开已有全局菜单，由它提供现有创建与导航动作。第一条已配置快捷键能完整放下时才显示。 |
| 几何与输入                  | 先为菜单预留一行侧栏底部空间，再分配各分组。绘制与命中区域使用相同矩形；隐藏的侧栏不发布侧栏入口。菜单与选择器保留原有准入、取消和键盘归属。                                    |

这是受信任选择器行、现有窗口、当前几何与按键注册表的无状态投影，不拥有新的焦点、
观察、后端命令或持久化。`tui_render::agent_sidebar` 证据覆盖完整／空／部分计数、
仅含占位行的窗口、两种语言、配置后的快捷键，以及既有 Full/Compact/Minimal/TooSmall
渲染矩阵。激活与捕获归已有选择器和菜单输入检查负责；仅绘制入口不能证明宿主交互。

## 侧栏导航模型

原生侧栏从已有完整 Machine 检查点绘制 Project → Workspace 导航，保留独立的 Standalone
行和 Machine/Site 身份。`machine_spaces::Checkpoint` 从与 Workspace 行相同的受围栏保护
Snapshot 中携带 Project ID 和标签，包括没有 Workspace 的 Project；不增加请求、后端命令
或持久状态。该检查点尚不可用时，既有上下文投影提供其中已知的 Project 和 Workspace。

`machine_picker::Picker` 独占 Project 展开状态、键盘行焦点和既有分组窗口。
`SidebarTarget::Project` 携带 Machine、Site 和 Project ID；`SidebarTarget::Context`
携带 Machine 和完整 `NativeContextTarget`。标签与位置不授权激活。相同可见标签保留 ID
标注。保留规范 Project 顺序及每个 Project 内的规范 Workspace 顺序；每台 Machine 的
Standalone 排在 Project 之前。

| 状态／事件           | 决策与可观察结果                                                                                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 进入导航             | 可用的 Picker 进入显式键盘归属状态，空树也不例外。保留有效的已有行焦点，否则聚焦可见的活动 Context、其可见 Project 父行或第一行。进入导航绝不改变 Project 展开状态。可在刚恢复显示的侧栏首次绘制前进入。 |
| 方向键／Home／End    | 只在可见行之间移动稳定行焦点，并通过既有感知行高的窗口显露它；不改变活动 Workspace，也不排入请求。                                                                                                       |
| 右／左               | 右键展开 Project 或进入其第一个子行；左键收起 Project 或从子行返回父行。Project 上的 Enter 切换展开状态。这些操作都不激活终端。                                                                          |
| Context 上的 Enter   | 返回一个校验身份的 `Activate(Selection)` 意图，由原有激活归属者应用；单纯移动焦点不写入 `Picker.request`。                                                                                               |
| 菜单                 | 为焦点行返回 `OpenMenu(SidebarTarget)`。原有菜单准入验证绘制来源、当前 Machine 和 Site；打开与取消保留导航焦点和活动 Context。                                                                           |
| F1                   | 返回 `Help`；分发器显示已有快捷键帮助浮层，同时保留导航归属和行焦点。                                                                                                                                    |
| 来源替换／收起       | 保留准确且可见的目标；否则选择其可见 Project 父行，再退到原有有界位置的邻行。空树没有焦点目标。已删除 ID 不回退到同名标签。                                                                              |
| 滚轮／按键显露       | 复用原有合并且每次刷新受视口限制的滚轮模型；后续键盘移动恢复焦点显露。滚动不激活 Context。                                                                                                               |
| Escape／侧栏实际隐藏 | 退出键盘归属。分发器消费未匹配的导航按键；此模式之外的普通终端输入保持原有归属。                                                                                                                         |

活动 Workspace 保留标记；键盘焦点行仅在侧栏导航拥有输入时使用选中表面。Project 展开按钮、
行内容和可见行菜单使用同一绘制行上的互不重叠矩形。`SIDEBAR_BINDINGS` 同时供按键匹配和
本地化模式提示使用。分发器拥有进入、捕获优先级及输入包尾部围栏；菜单归属者保留能力检查
和执行。Project 菜单绝不代选子 Workspace：依赖上下文的动作要求显式活动 Context 属于该
Project。GUI 对应范围为层级与身份语义，不主张像素或后端等价。

| 主张                     | 可执行证据与边界                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 稳定分组且不隐式激活     | Picker 确定性用例覆盖跨 Machine/Site/Project 的重复标签、Standalone、空 Project、显式 Enter 及重复菜单／收起事件。                                                                   |
| 拓扑变化后焦点仍有效     | 有界生成式 Picker 轨迹覆盖移动、重排、删除、收起、隐藏与重新进入，使用确定性种子及删除式收缩；不主张无界证明。                                                                       |
| 渲染与输入共享身份和几何 | Workspace 侧栏渲染用例覆盖活动与键盘焦点区别、长／宽字符标签、感知行高的显露，以及互不重叠的展开／菜单命中区域。共享分发器／鼠标轨迹按原生鼠标输入权威覆盖捕获、过期绘制和焦点返回。 |

这些同步投影与焦点转换不拥有异步副作用。已有菜单和鼠标模型拥有独立完成、捕获及取消的
排序；截图补充其确定性交互证据。

## 侧栏宽度与恢复模型

`tui_layout::SidebarWidth` 接受 24 至 60 列，默认 30 列。这是 Picker 拥有的显式 Client
本地偏好，不由内容自动撑开，也不持久化。可见侧栏使用 `min(preferred, host columns / 2)` 列，
即首选宽度与宿主列数一半中的较小值；
既有 Full 和 Compact 下限保证此上限仍高于最小宽度。`SidebarSurface` 将首选值沿既有
唯一 Shell 投影器传给终端几何与本地窗格布局校验。状态栏保留完整宿主宽度。宿主缩小时
仅约束有效矩形，保留首选值供以后恢复。

| 状态／事件             | 决策与不变量                                                                                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full／Compact／Minimal | 保留既有分级与可见意图规则：Full 停靠，Compact 显示显式请求的浮层，更低级别隐藏侧栏。宽度不会自动打开浮层，也不改变宽窗口下的显示意图。                                                                                             |
| 键盘宽度               | 侧栏导航拥有输入时，准确的 Shift+Left 和 Shift+Right 发出缩窄／加宽两列的意图，`0` 发出重置为 30 列的意图。共享快捷键注册表同时提供本地化帮助。即使鼠标捕获已释放，也要求准确且当前有效的已绘制侧栏目标；没有目标就不修改偏好。     |
| 到达宽度边界           | 从有效宽度开始调整。若约束后的结果等于该宽度，则保留原首选值；重置显式写入默认值。                                                                                                                                                  |
| 鼠标按下／移动         | 在既有单列右边框上普通左键按下，捕获其准确视口、含完整首选宽度的表面与有效侧栏矩形。绝对位移产生可撤销的线条预览，不改变宽度偏好、终端几何、行焦点、展开状态或导航请求。                                                            |
| 匹配的左键释放         | 重新校验已绘制目标，并将原首选宽度与当前偏好准确比较。通过 Picker 单次提交变化后的候选值，使旧命中几何失效并运行既有布局边界。有效矩形相同不能授权过期首选值。                                                                      |
| 取消／来源过期         | Escape、Shift、宿主尺寸变化、侧栏隐藏、上层捕获或已绘制目标丢失都会丢弃预览。零位移和边界约束下的无效调整释放保留原首选值。输入归属者继续负责释放和输入包退役。                                                                     |
| 宽度提交               | 清除排队的侧栏滚轮工作，恢复感知行高的焦点显露。保留键盘归属、展开状态、活动 Context 和请求。下一帧根据同一宽度重算标签、行高、命中区域和终端几何。                                                                                 |
| 隐藏后恢复             | 当 Full 或 Compact 能呈现侧栏且没有覆盖层捕获该表面时，本地化状态栏入口调用已有 `FocusBusinessSidebar` 动作，与配置的导航进入路径一致；已有显示切换和全局菜单仍可用。Minimal 和 TooSmall 保留既有简化提示与拒绝行为，直到宿主变大。 |

边框命中使用侧栏控件层，只高于自身表面，低于覆盖式模态层。行、菜单和边框矩形互不重叠。
预览渲染复用已有分隔线的图形覆盖与被拒预览重绘生命周期；不增加第二套终端投影，也不在
移动期间发送后端尺寸调整。

纯宽度模型覆盖合法边界、半宿主约束、偏移视口、绝对移动、无效调整时保留偏好，以及
120 → 60 → 50 → 120 的恢复。Picker 用例覆盖比较后设置的拒绝、焦点保留，以及活动
Workspace 已收起时进入导航不展开父项目。侧栏渲染覆盖 24／30／60 列、两种语言、分级降级
和准确边框命中。原生鼠标输入权威下的共享输入证据拥有捕获、过期绘制、取消、匹配释放、
图形清理及终端几何一致性；纯几何本身不能证明这些副作用。已有有界层级轨迹继续作为层级权威。

## 状态栏

底部恰好一行，始终绘制，永不被浮层覆盖。从左到右的分段遵循
`docs/tui/overlays-and-status.md`：输入指示（已 armed 的前缀徽章，普通层为空）、上下文或
通知、右对齐的提示。分段要么完整绘制要么丢弃；上下文分段最先丢弃，提示文本按级别缩短
（Full 完整提示、Compact 用 `Ctrl+B ?`、Minimal 与 TooSmall 只留退出提示）。状态文本区域
只有被完整绘制时才回报给调用方，保留原有绘制门控：部分绘制不产生确认回执。

Windows 普通状态布局为菜单按钮保留独立单元格；仅在当前归属者的完整提示仍能放下时，才为
Machines 指示器分配另一块区域。可选指示器按标签显示宽度计算，最多 28 列；有通知、前缀／
调整大小模式或捕获界面时让位。每帧把分配区域交给 Machines 绘制者，保证最终绘制与鼠标区域
不会覆盖其他状态分段。前缀已 armed 时以徽章和 `Esc` 取消提示替代菜单按钮；空间不足先缩短为
按键，再仅保留徽章。菜单和设置先替换整行状态及其背景，再绘制当前归属者的提示。

## 内容区与浮层

Windows [Workbench 导航器](native-context-selection.zh-CN.md#windows-捕获输入的导航器) 使用现有居中
表面，提供两列标题并围绕本地焦点显示列表窗口。活动标记继续标识已选终端，选择背景表示
Enter 将打开的行。完整可见行随成功帧发布精确凭据。Esc／Enter 提示优先于可选切换键及移动
细节；源用例覆盖两种语言、配置后的前缀标签、长列表滚动列、120x41、120x40 和 80x24。
内部区域小于 40x7 单元格时拒绝呈现，并通过新帧围栏释放捕获。导航器抑制 pane 光标／焦点
强调及普通 Menu 按钮。快捷键 Help 保持非模态行为。

浮层定位所依据的内容区是 `ShellAreas.panel`：顶部条之下、停靠侧面板之右的 workbench 区
域。`tui_layout` 为 surface 渲染器公开两个纯函数：

- `overlay_area(&ShellAreas) -> Rect` —— 所有居中浮层共用的内容区域。
- `place_overlay(area, preferred_width, preferred_height) -> Option<Rect>` —— 解析为
  `min(preferred, area - 4)` × `min(preferred, area - 2)`，居中且多余单元格向左上取整；当
  解析出的内部区域小于 4x3 时返回 `None`。

被拒绝的浮层不绘制，由调用方通过状态栏报告。因为状态行在所有浮层与模态之后绘制，即
使旧 surface 渲染器仍在自行计算几何，"状态栏不被覆盖"这一不变量也成立。

## 分屏窗格

`divide_panes(area, orientation)` 返回 `PaneDivision { first, divider, second }`，其中
`divider` 是两个子窗格之间恰好共享的一个单元格列或行；当任一子窗格小于文档化的 4x3 最小
值时返回 `None`。保留原有 50/50 意图：divider 单元格从第二个子窗格的份额中扣除，`first`
保持过去 50% 分屏得到的宽度。

叶窗格不绘制边缘边框：位于区域边界上的边由区域外框承担，面向 divider 的边由 divider 单
元格承担。每个叶窗格在其矩形内占一行标题；窗格拥有输入时，活动叶窗格的标题使用焦点
强调样式，标题下方区域接
收终端单元格。非活动叶窗格绘制本地化的空状态，说明终端已保留并给出聚焦按键——绝不绘制
伪造的 live 内容。divider 单元格在遍历过程中收集，最后按相邻 divider 单元格解析出交接字
形（`├ ┤ ┬ ┴ ┼`）统一绘制一次。

在 Client 本地 zoom（`Ctrl+B z`；session 契约见 `native-tab-session.md`）下，绘制
集合收缩为焦点叶窗格：它在整个内容区渲染并记录唯一的 pane 命中区，而未绘制的叶子仍按
其规范叶矩形上报，使其 viewer 保持存活。焦点叶子向线上上报整个内容区，使其终端收敛到
放大尺寸；zoom 中不绘制 divider 单元格。绘制/命中集合与观测集合的这一分离是 zoom 唯一
的几何效果——规范投影本身不变。

捕获输入的界面将窗格的焦点强调替换为未聚焦边框与次要标题样式。参考浮层保留窗格焦点，
并使用未聚焦边框。侧栏分组标题使用主要文字加粗，不使用焦点颜色。
Windows 的 Machine 选择器与 Worktree 草稿拥有输入时，也会取消窗格焦点强调并隐藏终端光标。
Site 状态只为图标着色，正文使用主要文字样式。
已就绪状态使用已有成功样式，其他阶段保留警告样式。
实时及保留的终端单元格共用主题默认配色投影：带默认标记的前景与背景跟随主题，
程序显式设置的颜色保持不变。

## 降级顺序

遵循 `docs/tui/layout.md`：先丢弃可选上下文文本，缩短提示标签，丢弃提示标签但保留模式指
示，侧面板解除停靠，隐藏侧面板，截断标签。上表把这些步骤绑定到具体行列配额，任何
surface 不得跳步。

## 调整大小

每一帧都按实时宿主矩形重算投影。宿主至少 4 列 3 行时，退化的终端区域仍得到非零内部投
影，会话循环得以存活，小尺寸界面保持可退出；低于该下限时的 last-valid 几何保留属于环境
切片的职责。

## 正确性证据

`cargo test -p orchbee` 覆盖：含宽高取低规则的级别边界矩阵、一行状态栏与顶部条、按级别呈
现的侧面板、浮层夹取/居中/拒绝、窗格划分几何与共享分隔线；以及在 `en-US` 与 `zh-CN` 下
以 TestBackend 渲染 120x40、80x24、60x12、50x10、15x4 与宽高不一致组合，证明状态行不被
覆盖、小尺寸提示本地化、长标签与活动 Tab 令牌经显示宽度截断后仍可见。

## Tab 元数据标注

原生紧凑标签栏和导航器为每个规范 Tab 保留一个 token／行。固定 Tab 使用本地化 `Pinned`／`固定` 标注，分组 Tab 显示 `group label / Tab label`（分组标签 / Tab 标签）。完整文本沿用既有清理器和字符单元宽度预算，活动／选中样式来自常规 Tab 主题角色。仅已绘制宽度定义基于稳定 Tab ID 的鼠标区域。标注不成为原始名称、自动序号、额外焦点停靠点或合成终端行。
