# TUI shell 布局

## 范围与归属

原生 Client shell 把宿主区域划分为顶部条、内容区、可选侧面板、带共享边界的窗格区，以及按需出现的一行
状态覆盖层。本文档声明 `docs/tui/layout.md` 要求所属应用给出的具体区域、阈值与降级顺序。它只
拥有布局投影：颜色、字形与边框样式归主题层，浮层内容归各自 surface 渲染器，终端单元格绘制
归 `terminal_cells`。

投影是纯函数。`tui_layout::project_shell_areas` 根据当前帧矩形与视图请求的侧面板形态（含首选宽度）计算
所有区域；`tui_shell` 用同一对函数（先 `project_shell_areas` 再 `native_terminal_area`）计算终端
几何，因此绘制内容区与 wire 几何不可能分叉。渲染代码不修改业务状态、时钟或 I/O，布局值也
不跨帧缓存。

## 视口分级

宽度与高度独立分级，取两者中更低的级别。

| 级别     | 宽度级（列） | 高度级（行） |
| -------- | ------------ | ------------ |
| Full     | >= 100       | >= 24        |
| Compact  | 60..=99      | 12..=23      |
| Minimal  | 20..=59      | 5..=11       |
| TooSmall | < 20         | < 5          |

`tui_layout` 中的 `ViewportTier::from_size(columns, rows)` 是唯一分类器。各级 chrome 行列
配额：

| chrome       | Full               | Compact                  | Minimal        | TooSmall       |
| ------------ | ------------------ | ------------------------ | -------------- | -------------- |
| 顶部条       | 1 行（tabs）       | 1 行（tabs）             | 无             | 无             |
| 状态栏       | 覆盖，不预留行     | 覆盖，不预留行           | 覆盖，不预留行 | 退出提示覆盖层 |
| 侧面板       | 停靠，有界首选宽度 | 浮层，有界首选宽度，靠左 | 隐藏           | 隐藏           |
| Panel chrome | 一行标题；分屏边框 | 一行标题；分屏边框       | 不绘制         | 不绘制         |
| 内容         | 剩余区域           | 剩余区域                 | 剩余区域       | 仅提示         |

TooSmall 时 Client 只绘制一条本地化的小尺寸提示与状态栏，别无他物；宿主变大即恢复正常渲
染。视图请求的侧面板形态只是一种意图：`project_shell_areas` 按级别翻译它（`Docked` 与
`Overlay` 都表示可见：Full 停靠、Compact 浮层、更低级别隐藏），因此渲染 chrome 与 wire 几
何保持一致，调用方无需关心级别。

Windows 侧栏顶部固定两个整行宽度的操作入口：`+ 新建工作区` 和 `/ 搜索`
（英文为 `+ New workspace` 和 `/ Search`）。图标与标签左对齐，整行均可点击。
这两行与底部设置行均位于滚动导航树之外。未分组 Workspace 是根条目；
可选 Project 将普通 Workspace 与基于 Git worktree 的 Workspace 组织为同级成员。
Agent 直接位于各 Workspace 下，列表彼此独立且默认展开。Standalone 在同一窗口内
拥有自己的 Agent 子行。条目的行高、间距与 token 样式仍由配置拥有。

宿主不足 24 行时省略操作区后的空行；列表区域不足 10 行时先省略标题留白，再裁剪条目。
统一窗口尽量容纳完整行，单行超高时裁剪到可用正文。
键盘焦点或可见的当前 Agent 决定焦点显露，后者以所属 Context 为后备目标。
工作区标题仅标识列表，不承载操作。绘制与鼠标区域使用相同的最终矩形；
树形列表的展开不改变终端内容几何。

固定操作与工作区标题之间通常保留一行空白。规范导航行可用时，列表不再重复应用品牌和普通
会话状态；行尚未到达时，连接与业务占位位于操作入口下方。两种侧栏形态都保留一行顶部
留白和一列右内边距，不额外添加左内边距；列表左缘由共用焦点边栏负责。标题区分主要标签
与次要计数。计数包含全部规范 Workspace，包括被折叠隐藏的子项，不含 Standalone。
空间足够时，标题与正文间保留一行留白。页脚只显示溢出范围；列表全部可见时保持空白。

每个导航行保留两列焦点边栏。根名称位于两列展开／状态列之后；已分组 Workspace 再缩进两列，
Agent 相对所属 Workspace 或 Standalone 父行缩进两列。
分支与自定义续行对齐 Workspace 名称，包括配置的首行省略状态图标时。Project 标签与说明性元数据
分别使用加粗次要文字与次要文字，Workspace 名称使用主要文字。可用的行菜单与 Project
创建控件只在键盘聚焦的行显示并保持右对齐；普通行将这些列归还给名称。右键菜单和已有
键盘路径继续可用，隐藏控件不发布点击区域。Agent 序号占两列，当前项／焦点标记保留在
共用边栏中；默认标题与 Provider／状态续行对齐。默认 Provider 标签仅在能与状态完整并排时
显示，不留下截断碎片。Project 分组在前序条目后预留至少一行
空白；配置的间距可将其加宽。
当前 Workspace 条目在终端输入时仍保留准确目标和整行宽度的中性 `surface-current`。
同一连续矩形包含名称、分支、配置的元数据、折叠 Agent 汇总与身份续行，以及这些行的边栏和
尾部空白。背景止于条目边界，不包含间距、Project 标题或相邻条目。键盘焦点在独立边栏中显示
`>`，非当前 Workspace 条目整体使用 `surface-selection`。具名主题保留元数据的次要文字颜色；
依赖宿主的文字使用表面配套前景色。显式 token 颜色与强调仍保留其权威。默认当前名称加粗，
填充可区分时不叠加星号。Agent 身份行与已折叠的当前 Project 仍仅在身份行使用相应表面，
续行留在 `surface-chrome` 上。焦点与当前上下文重合时，中性的当前表面优先。
Project 和有可用子行的 Context 展开控件使用单字形
（`▾`/`▸`，ASCII 回退为 `-`/`+`），占独立两列点击区域；边栏、内容与菜单命中均不与展开控件重叠。
顶栏保留上下文路径，使侧栏行滚出视野时仍可辨认当前位置；
活动 Tab 使用带内边距的填充样式，不再用方括号或星号装饰。
分屏的共享外框不再重复通用标题，基础样式使用中性色；焦点窗格周围已有的边界线段
采用聚焦框架角色，同时保留该窗格的强调标题。不在叶子周围增加边框单元格，分隔线矩形
保持原样。分隔线端点更新外框已有边界单元格的交汇字形，
不留半格断口，并保留框架角样式。
单窗格和放大视图使用一行标题带，不绘制外框，归还左边一列和底部一行。每个窗格在右侧
预留一列 chrome，供[历史滚动条](native-terminal-viewport.zh-CN.md#滚动条交互)使用。
历史为空或待定时仍预留该列，输出本身不会改变 PTY 宽度。该列与内容、标题和分屏分隔线
命中区域不重叠。只有一列宽的窗格省略该列；不足两行的轨道不显示滑块。分屏叶子和放大
视图在原生几何、绘制、输入坐标和布局查询中使用同一内容宽度扣减。
窗格标题使用本地化“终端”标签，保留自定义元数据、序号和终端呈现身份；
普通呈现标签与 Tab 标签相同时不再重复。标题表达焦点，侧栏导航拥有输入时取消该强调。
渲染器、PTY 尺寸、弹出终端和只读布局查询共享这份几何；放大视图中隐藏的叶子保留规范的未放大尺寸。
非焦点终端内容保留正常文字对比度；焦点由窗格 chrome 和光标表达，
不对其他程序的内容附加 DIM。
Shell 先绘制终端画布，再为侧栏、标签栏和分屏标题带绘制持久 chrome 背景。
覆盖层绘制自身完整的不透明表面；边框和标题表达边界及焦点，区域区别不再只依赖它们。

## 快捷创建控件

Windows 顶栏在最后一个可见 Tab 后为 `+` 预留三列，空 context 也保留该入口。
较长的路径最多占用顶栏一半宽度，为当前 Tab 和创建控件保留空间。低于 Compact 时，
控件随顶栏一起隐藏。固定的新建工作区行调用已有的即时快速 Workspace 动作；
键盘聚焦的当前 Machine Project 行在其行菜单旁保留 `+`。展开、内容、创建和菜单单元格互不重叠。字形与语言无关；
动作标签和不可用原因复用已有中英文目录。

| 入口           | 既有动作与归属                                                                                                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tab 顶栏 `+`   | `DrawnTabCreate` 冻结 Site、快照 revision 和 context。无修饰左键按下仅启动本地鼠标手势；在同一个仍可见矩形内匹配释放后，请求 `NativeUi` 重新校验证明，再将 `ClientAction::CreateTab` 交给原 dispatcher 和 membership 准入。按下时没有副作用。 |
| 新建工作区行   | 无修饰左键按下将 `ClientAction::RequestQuickWorkspace` 委托给已有创建归属者。直接创建独立 Workspace 与首个 shell，不打开创建菜单；终端目标改变前先捕获决策所在输入包。                                                                        |
| Project 行 `+` | 针对准确的已绘制 Project 打开同一创建子集，把定向快速 Workspace 放在首位。保留原能力检查和禁用原因，不隐式选择子 Workspace。                                                                                                                  |

右键点击 Tab 顶栏 `+` 打开独立的新建 Tab 菜单（普通 Tab、最近分组或新分组）；
全局菜单提供键盘入口。它保留同一个精确的 `DrawnTabCreate` context 证明。
详见 [Tab 菜单](native-tab-groups.zh-CN.md#指针排列与菜单导航)。

身份、几何改变、捕获覆盖、释放鼠标捕获或在控件外释放都会取消 Tab 创建手势。
释放所在输入包的剩余字节（含粘贴）即使在证明被拒绝时也不会进入 pane。菜单入口保留
原捕获与取消生命周期。键盘路径不变：配置的新建 Tab（默认 `Ctrl+B c`）、
Workspace 创建（`Ctrl+B a`）、快速 Workspace（`Ctrl+B Shift+N`）及全局／Project
菜单。这些控件不拥有新的业务状态、终端身份或持久化。

绘制和命中测试覆盖两种语言、默认／RGB 主题、空／有内容的列表、全部视口级别与长标签。
鼠标轨迹覆盖完整点击和失效；NativeUi 测试检查旧 context／快照拒绝，以及向原命令／
草稿 owner 的委托。这些确定性测试及合成缓冲区预览不证明实际宿主的调色板或字体表现。

## 侧栏 Agent 计数与入口

统一侧栏按精确归属关联现有可用 Agent 投影。只有实际 Agent 行保留全局序号；
读取中、不可用、空列表与无匹配占位信息保留在全局 Agent 选择器中。树形列表页脚
统计可见导航条目，包括 Project 与 Context 行，仅溢出时显示范围；不将该数量表示为 Agent 总数。

已折叠的 Project 或 Context 在续行保留完整观测的 Agent 数与待处理数。计数使用 Agent
筛选之前的精确 Machine／Site／Context 归属；筛选隐藏全部子行时仍保留这些信息。
缺失或不完整的观察不会转为零计数。零总数省略，正数待处理计数使用警告角色。
当前 Workspace 样式仍保留在 Context 或其折叠后的 Project 上，不改变活动终端。

固定搜索行打开已有 Agent 选择器并直接进入查询编辑。它保留该选择器的 Agent 范围与筛选
控件，不宣称具有 Web 更广的全部搜索目录。在显式侧栏键盘归属（`Ctrl+B Shift+B`）内，
`Shift+N` 调用同一新建工作区动作，`/` 进入同一搜索编辑器；F1 列出这些绑定。
已有全局 `Ctrl+B Shift+N` 创建路径仍可使用。查询编辑与取消保留选择器的捕获规则，
打开任一动作都会消费输入包尾部。可见范围页脚打开 Workspace 选择器，空白页脚没有动作。
Workspace 浏览与 Agent 筛选仍可通过已有 Machine 选择器模式访问；本布局不为标题分配
新的浏览／筛选控件。底部固定“设置”入口直接打开已有设置编辑器，
与 GUI 侧栏入口保持一致。它位于滚动树之外，不显示快捷键、菜单或机器标签。
键盘使用 `Ctrl+B F4` 打开设置；已有逗号绑定继续重命名 Tab。
全局操作保留 `Ctrl+B F2`，机器选择保留 `Ctrl+B Shift+M`。
隐藏侧栏不发布侧栏命中区域。所有入口保留原有准入与输入捕获归属。

绘制消费受信任的选择器行、共用窗口、几何和快捷键注册表，不执行观察或后端命令。
绘制与输入测试覆盖两种语言、主题、配置行、全局序号、选择器／设置入口及
Full/Compact/Minimal/TooSmall 矩阵。宿主交互需要单独的原生证据。

## 侧栏导航模型

点击 Workspace 或在其上按 Enter 会直接激活精确目标，不绘制机器、工作区或 Agent 选择器作为过渡。
同机激活复用当前 Session 及各位置选择记忆；跨机候选保留既有可绘制交接。
当前 Workspace、Tab 及内容遵循已安装的 Session 选择。等待、被替代及取消的请求遵循
[机器导航](machines.zh-CN.md#跨机器工作区导航)。

原生侧栏从完整 Machine checkpoint 绘制 Workspace 及可选 Project 分组。每台 Machine
的 Standalone 和未分组 Workspace 位于 Project 前面。分组后的普通 Workspace 与基于
Git worktree 的 Workspace 同级，每个 Workspace 都拥有自己的 Agent 子行。
`machine_spaces::Checkpoint` 从与 Workspace 相同的受保护 Snapshot 保留 Project ID
和标签，包括具有独立菜单与创建控件的空 Project。其到达之前，现有 Context 投影提供
已知 Project 和 Workspace。

`machine_picker::Picker` 拥有 Project 展开、各 Context 独立的 Agent 列表折叠偏好、键盘行焦点
及共用窗口。`SidebarTarget::Project` 携带 Machine／Site／Project 身份；
`SidebarTarget::Context` 携带 Machine 与完整 `NativeContextTarget`；
`SidebarTarget::Agent` 还保留精确成员与物理绑定身份。可选 Project 归属是 Context 元数据，
由 `Picker::sidebar_parent` 从当前投影解析。移动 Workspace 或解散其 Project 不改变
终端身份、Tab 或 Panel 目标。Agent 关联不使用标签或行位置。同名同级行保留 ID 注记。
规范 Project 顺序、各组或根列表中的 Workspace 顺序，以及全局可用 Agent 序号保持原样。

| 状态／事件                | 决策与可观察结果                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 初始展开状态／Agent 到达  | 各 Context 的 Agent 列表初始展开，包括新观察到的 Agent；多个列表可同时保持展开。只要 Context 仍存在，显式折叠偏好就跨筛选、Agent 暂缺及到达、Project 折叠保留。                                        |
| Context 展开按钮按下      | 仅切换精确可见的 Context，不激活终端、不获取键盘焦点；其他列表保留原状态。保留手动滚动的视口，取消待处理滚轮几何，使已绘制命中图及输入包尾部失效。                                                     |
| 进入导航                  | 可用的 Picker 进入显式键盘归属，包括空树。保留有效旧行焦点，否则显露活动 Context、其可见 Project 父行或第一行。可在首次绘制前进入。                                                                    |
| 方向键／Home／End         | 仅在可见行间移动并显露稳定键盘焦点，不激活 Context 或 Agent。                                                                                                                                          |
| 右／左                    | 右键打开已折叠的 Project 或有可用子行的 Context；已展开时立即进入首个子行。左键从 Agent 回到 Context；已展开的 Context 先折叠，再返回可选 Project；Project 则折叠。Project 上的 Enter 切换其展开状态。 |
| Context／Agent 上的 Enter | 为精确可见目标返回一个经过身份校验的 `Activate(Selection)`，包括 Agent 已有的 Tab 和 Panel。由既有归属者应用；当前 Agent 无需操作，焦点移动绝不写入 `Picker.request`。                                 |
| 菜单／F1                  | Context 与 Project 保留既有菜单意图及准入；Agent 行不产生虚构的 Context 菜单。F1 打开快捷键帮助，保留行焦点和导航归属。                                                                                |
| 来源替换／折叠            | 仅在目标消失时清理其展开偏好。Project 与 Context 折叠保留活动终端、隐藏的展开偏好及计数／当前目标信息。保留精确可见焦点，否则选择最近可见祖先，再退到原有有界位置。删除的 ID 不重定向到同名标签。      |
| 重新分组／解散            | 从当前 Project 元数据解析仍存在的 Workspace 或 Agent 的祖先。目标可见时保留精确焦点；移入已折叠 Project 时将焦点放在该 Project。身份已移除时，先通过最后已知且仍存在的祖先恢复，再退到原位置。         |
| 滚轮／按键显露            | Workspace 和 Agent 命中使用同一合并且每次刷新受视口限制的滚轮窗口。键盘移动恢复焦点显露；滚轮移动不激活目标。                                                                                          |
| Escape／隐藏侧栏          | 退出键盘归属并消费其输入包尾部。最后一个观察消费者隐藏时释放来源行及失效的展开状态；普通终端输入保留已有归属。                                                                                         |

Agent 序号位于其嵌套行内的固定两列边栏。配置续行对齐首行可选状态图标之后的名称。
次要行使用元数据文字，保留显式 token 覆盖。当前 Context 与 Agent 使用相同的中性表面和
粗体身份，调色板折叠而需要文字标记时使用主题标记。键盘焦点使用独立的 `>` 边栏。

Project／Context 展开按钮、行内容与行菜单使用互不重叠的已绘制矩形。续行（包括 Agent 计数）
在整行宽度内保留父行目标。
`SIDEBAR_BINDINGS` 拥有按键匹配与本地化发现。分发器拥有捕获优先级、过期绘制拒绝及
输入包尾部围栏；菜单归属者保留能力检查和执行。Project 菜单从不代选子 Workspace。
鼠标和键盘展开共用 Picker 转换；导航键仅在侧栏显式拥有输入时生效。
GUI 对应范围为层级与身份语义，不主张像素或后端等价。

| 主张                 | 可执行证据与边界                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 精确分组且不隐式激活 | 确定性 Picker 用例覆盖 Machine／Site／Context 关联、重复标签、未分组 Workspace、Standalone、多个默认展开列表、折叠偏好保留及精确 Tab／Panel 激活。    |
| 焦点和滚动有效       | 有界生成式导航轨迹覆盖拓扑与分组变化；定向用例覆盖重新分组／解散、已移除的祖先、Agent 与父行移动、当前 Agent 显露及手动滚动后展开。不主张无界证明。   |
| 共享几何与输入权威   | 绘制、鼠标与分发器用例覆盖配置行高／间距、两种语言／主题、宽字形、折叠后的计数／当前目标信息、空 Project 控件、过期命中、滚轮取消及不转移焦点的展开。 |

这些同步呈现转换不增加异步副作用或终端确认。现有侧栏输入、菜单与鼠标所有者及其确定性测试
继续负责独立的完成、捕获与取消顺序。新的树形投影与展开语义除这些定向检查外，还需要上述确定性证据。

## 侧栏宽度与恢复模型

`tui_layout::SidebarWidth` 接受 24 至 60 列，默认 30 列。这是 Picker 拥有的显式 Client
本地偏好，不由内容自动撑开，也不持久化。可见侧栏使用 `min(preferred, host columns / 2)` 列，
即首选宽度与宿主列数一半中的较小值；
既有 Full 和 Compact 下限保证此上限仍高于最小宽度。`SidebarSurface` 将首选值沿既有
唯一 Shell 投影器传给终端几何与本地窗格布局校验。状态覆盖层使用可见侧栏右侧的列。宿主缩小时
仅约束有效矩形，保留首选值供以后恢复。

| 状态／事件             | 决策与不变量                                                                                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full／Compact／Minimal | 保留既有分级与可见意图规则：Full 停靠，Compact 显示显式请求的浮层，更低级别隐藏侧栏。宽度不会自动打开浮层，也不改变宽窗口下的显示意图。                                                                                             |
| 键盘宽度               | 侧栏导航拥有输入时，准确的 Shift+Left 和 Shift+Right 发出缩窄／加宽两列的意图，`0` 发出重置为 30 列的意图。共享快捷键注册表同时提供本地化帮助。即使鼠标捕获已释放，也要求准确且当前有效的已绘制侧栏目标；没有目标就不修改偏好。     |
| 到达宽度边界           | 从有效宽度开始调整。若约束后的结果等于该宽度，则保留原首选值；重置显式写入默认值。                                                                                                                                                  |
| 鼠标按下／移动         | 在既有单列右边框上普通左键按下，捕获其准确视口、含完整首选宽度的表面与有效侧栏矩形。绝对位移产生可撤销的线条预览，不改变宽度偏好、终端几何、行焦点、展开状态或导航请求。                                                            |
| 匹配的左键释放         | 重新校验已绘制目标，并将原首选宽度与当前偏好准确比较。通过 Picker 单次提交变化后的候选值，使旧命中几何失效并运行既有布局边界。有效矩形相同不能授权过期首选值。                                                                      |
| 取消／来源过期         | Escape、Shift、宿主尺寸变化、侧栏隐藏、上层捕获或已绘制目标丢失都会丢弃预览。零位移和边界约束下的无效调整释放保留原首选值。输入归属者继续负责释放和输入包退役。                                                                     |
| 宽度提交               | 清除排队的侧栏滚轮工作，恢复感知行高的焦点显露。保留键盘归属、展开状态、活动 Context 和请求。下一帧根据同一宽度重算标签、行高、命中区域和终端几何。                                                                                 |
| 隐藏后恢复             | 当 Full 或 Compact 能呈现侧栏且没有覆盖层捕获该表面时，本地化顶部条入口调用已有 `FocusBusinessSidebar` 动作，与配置的导航进入路径一致；已有显示切换和全局菜单仍可用。Minimal 和 TooSmall 保留既有简化提示与拒绝行为，直到宿主变大。 |

边框命中使用侧栏控件层，只高于自身表面，低于覆盖式模态层。行、菜单和边框矩形互不重叠。
预览渲染复用已有分隔线的图形覆盖与被拒预览重绘生命周期；不增加第二套终端投影，也不在
移动期间发送后端尺寸调整。
仅单列预览线改用焦点强调前景色；背景与相邻单元格保持规范绘制。按下、移动、释放和取消
均不向状态区域或浮层添加宽度数值或拖动提示。

纯宽度模型覆盖合法边界、半宿主约束、偏移视口、绝对移动、无效调整时保留偏好，以及
120 → 60 → 50 → 120 的恢复。Picker 用例覆盖比较后设置的拒绝、焦点保留，以及活动
Workspace 已收起时进入导航不展开父项目。侧栏渲染覆盖 24／30／60 列、两种语言、分级降级
和准确边框命中。原生鼠标输入权威下的共享输入证据拥有捕获、过期绘制、取消、匹配释放、
图形清理及终端几何一致性；纯几何本身不能证明这些副作用。已有有界层级轨迹继续作为层级权威。

## 状态栏

普通终端内容延伸到宿主底部。状态行、空闲快捷键、菜单按钮和当前机器指示器都不再
预留终端高度。`ShellAreas.status` 是底部可见侧栏右侧的覆盖矩形；`ShellAreas.panel`
包含这些单元格。进入和退出前缀态不改变 PTY 几何，后续普通帧恢复被覆盖的终端内容和光标。

覆盖层在前缀捕获、其他输入模式、有意义的通知、连接或恢复及释放指针捕获时出现。
Ready、控制权和放大状态可在前缀提示中查看。TooSmall 保留退出提示。
分段遵循 `docs/tui/overlays-and-status.md`；上下文为模式与退出提示让位。
前缀徽章先将取消提示缩短为 `Esc`，再仅保留徽章。菜单与设置在绘制自身提示前完整覆盖背景。
被覆盖单元格不透传鼠标输入，也不证明终端图形无遮挡。状态文本区域只有完整绘制时才报告，
保留恢复确认的绘制准入。侧栏固定设置页脚位于此矩形之外。

## 内容区与浮层

Windows [Workbench 导航器](native-context-selection.zh-CN.md#windows-捕获输入的导航器) 使用现有居中
表面，提供两列标题并围绕本地焦点显示列表窗口。活动标记继续标识已选终端，选择背景表示
Enter 将打开的行。完整可见行随成功帧发布精确凭据。Esc／Enter 提示优先于可选切换键及移动
细节；源用例覆盖两种语言、配置后的前缀标签、长列表滚动列、120x41、120x40 和 80x24。
内部区域小于 40x7 单元格时拒绝呈现，并通过新帧围栏释放捕获。导航器抑制 pane 光标／焦点
强调。前缀输入也隐藏终端光标。快捷键 Help 保持非模态行为。

居中浮层使用 `ShellAreas.panel` 扣除最后一行，为临时提示留出空间。这只影响浮层定位；
终端内容仍使用该行。`tui_layout` 为表面渲染器提供两个纯函数：

- `overlay_area(&ShellAreas) -> Rect` —— 所有居中浮层共用的内容区域。
- `place_overlay(area, preferred_width, preferred_height) -> Option<Rect>` —— 解析为
  `min(preferred, area - 4)` × `min(preferred, area - 2)`，居中且多余单元格向左上取整；当
  解析出的内部区域小于 4x3 时返回 `None`。

被拒绝的浮层不绘制，由调用方通过状态栏报告。因为状态行在所有浮层与模态之后绘制，即
使旧 surface 渲染器仍在自行计算几何，"状态栏不被覆盖"这一不变量也成立。

## 分屏窗格

`divide_panes(area, orientation)` 返回 `PaneDivision { first, divider, second }`，其中
`divider` 是两个子窗格之间恰好共享的一个单元格列或行；当任一子窗格小于文档化的 4x3 最小
值时返回 `None`。保留原有 50/50 意图：divider 单元格从第二个子窗格的份额中扣除，`first`
保持过去 50% 分屏得到的宽度。

叶窗格不绘制边缘边框：位于区域边界上的边由区域外框承担，面向 divider 的边由 divider 单
元格承担。每个叶窗格在其矩形内占一行标题；窗格拥有输入时，活动叶窗格的标题使用焦点
强调样式，标题下方区域接
收终端单元格。非活动叶窗格绘制本地化的空状态，说明终端已保留并给出聚焦按键——绝不绘制
伪造的 live 内容。divider 单元格在遍历过程中收集，最后按相邻 divider 单元格解析出交接字
形（`├ ┤ ┬ ┴ ┼`）统一绘制一次。

在 Client 本地 zoom（`Ctrl+B z`；session 契约见 `native-tab-session.md`）下，绘制
集合收缩为焦点叶窗格：它在整个内容区渲染并记录唯一的 pane 命中区，而未绘制的叶子仍按
其规范叶矩形上报，使其 viewer 保持存活。焦点叶子向线上上报整个内容区，使其终端收敛到
放大尺寸；zoom 中不绘制 divider 单元格。绘制/命中集合与观测集合的这一分离是 zoom 唯一
的几何效果——规范投影本身不变。

捕获输入的界面将窗格的焦点强调替换为未聚焦边框与次要标题样式。参考浮层保留窗格焦点，
并使用未聚焦边框。侧栏分组标题使用主要文字加粗，不使用焦点颜色。
Windows 的 Machine 选择器与 Worktree 草稿拥有输入时，也会取消窗格焦点强调并隐藏终端光标。
Site 状态只为图标着色，正文使用主要文字样式。
已就绪状态使用已有成功样式，其他阶段保留警告样式。
实时及保留的终端单元格共用主题默认配色投影：带默认标记的前景与背景跟随主题，
程序显式设置的颜色保持不变。

## 降级顺序

遵循 `docs/tui/layout.md`：先丢弃可选上下文文本，缩短提示标签，丢弃提示标签但保留模式指
示，侧面板解除停靠，隐藏侧面板，截断标签。上表把这些步骤绑定到具体行列配额，任何
surface 不得跳步。

## 调整大小

每一帧都按实时宿主矩形重算投影。宿主至少 4 列 3 行时，退化的终端区域仍得到非零内部投
影，会话循环得以存活，小尺寸界面保持可退出；低于该下限时的 last-valid 几何保留属于环境
切片的职责。

## 正确性证据

`cargo test -p orchbee` 覆盖：含宽高取低规则的级别边界矩阵、一行状态覆盖层与顶部条、按级别呈
现的侧面板、浮层夹取/居中/拒绝、窗格划分几何与共享分隔线；以及在 `en-US` 与 `zh-CN` 下
以 TestBackend 渲染 120x40、80x24、60x12、50x10、15x4 与宽高不一致组合，证明状态行不被
覆盖、小尺寸提示本地化、长标签与活动 Tab 令牌经显示宽度截断后仍可见。

整屏评审遵循 `docs/tui/verification.md`：当前 Workspace 的标识独立于键盘焦点，普通侧栏底部只提供设置，完整列表省略冗余范围，单窗格边缘归终端内容使用。评审默认主题及两个内置
RGB 主题、空／非空侧栏、导航、隐藏侧栏和分屏／放大场景。
`terminal_session/ui/viewport_tests/chrome.rs` 在两种语言与原生／RGB 主题下验证末行内容、
前缀覆盖、鼠标遮挡、几何稳定和精确恢复。
这些结果持续约束后续功能变更的验收。

## Tab 元数据标注

固定 Tab 使用本地化 `Pinned`／`固定` 标注。Windows 紧凑标签栏绘制独立的彩色组标题、展开标识及成员数量；
展开成员保留普通 Tab token，折叠标题标识组内活动成员。导航器仍提供每个规范 Tab 及其分组标注。
文本沿用既有清理器和字符单元宽度预算，已绘制宽度定义准确的 Tab／分组鼠标区域。
显示标注不会成为原始名称或自动序号。[Tab 分组契约](native-tab-groups.zh-CN.md)拥有展开、配置及跨宿主能力覆盖。
