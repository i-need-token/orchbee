# 原生运行时状态

## 权威与语法

本参考拥有 Windows `status server` 和 `status client`，两者均支持
`--format text|json`。裸 `status` 保持 Workbench 快照契约。未知操作数、选项及组合在产生
效果前失败。帮助、schema 和补全保持离线。macOS 和 Linux 不实现新增命令运行时。

`status client` 读取本可执行文件的编译版本、操作系统、架构、开发交付标识和无损可执行
文件路径，并独立验证同目录原生 cohort。cohort 缺失、无效（含不支持的清单版本）、无权限、超时或不可读
时，明确输出不可用元数据，不编造标识，也不因此启动 Site。开发交付尚无配置的
stable/preview 更新渠道；渠道管理仍为单独能力。该命令不联系 Server。

`status server` 只探测选中的隐式本地 Windows Site。它不启动 Server、不创建运行时目录
或锁文件、不修复标记、不附着终端、不改变焦点，也不创建 Client Session。成功答复报告
响应的同用户 Server 提供的事实，不复制查询 Client 的值，也不从管道名称推断这些事实。

## 观察模型

| 字段     | 契约                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题     | 脚本需要正在运行的 Server／构建／协议事实，并须在普通 Client 接纳因可执行包不同而拒绝之前诊断 cohort 差异。                                     |
| 输入     | 类型化作用域、格式、本地运行时位置、当前可执行文件／cohort 文件、一个单调时限、取消，以及一个不可信的同用户元数据答复。                         |
| 状态     | 一次读取尝试，可保留已接纳 rendezvous、候选流、完整 Server 元数据和独立本地 cohort 观察；没有持久操作记录。                                     |
| 输出     | 一个有界本地化文本或版本化 JSON 文档，或者一个既有类型化失败；无部分输出。                                                                      |
| 不变量   | 请求前证明同用户；一个已完成连接和一次请求；无普通 Client hello、代次分配、Workbench Session、激活、锁创建、进程启动或修改。                    |
| 决策     | 连接前选中的运行时／端点缺失可表示不存在；部分答复、权限错误、忙／时限、畸形元数据和连接后 EOF 均不可。                                         |
| 归属     | 本地 Site runtime 拥有私有路径接纳；local Client protocol 拥有有界元数据帧及传输；Server 拥有构建／cohort／模式／实现事实；CLI 拥有比较及呈现。 |
| 生命周期 | 一次答复或任意失败后、呈现前丢弃候选连接。取消通过既有输出终结器释放等待源。                                                                    |
| 预算     | 从收集开始计五秒；连接、部分 I/O 和结算均不续期。文件哈希在有界读取之间检查剩余预算；同步内核／文件系统调用是协作式而非抢占式。                 |
| 证据     | 编解码反例、Windows 命名管道对端、Server 接纳／状态测试、CLI 进程／schema／补全测试和真实 PowerShell 5.1/7 可执行包探测。                       |
| 限制     | 只是在选中作用域的一次观察，不证明所有 Server 进程均不存在，不是全局健康检查，也不是本地文件与远端进程状态的原子快照。                          |

| 阶段 | 条件和结果                                                     | 失败／取消                                                                               |
| ---- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 解析 | 作用域与输出格式已识别；不使用运行时能力。                     | 既有用法失败。                                                                           |
| 定位 | 读取运行时位置并验证现有私有目录。                             | 选中运行时缺失输出 not-running；无效／不可检查路径仍为错误。                             |
| 探测 | 只连接已接纳端点一次；元数据请求前完成同用户证明。             | 连接前端点不存在输出 not-running；忙、拒绝和其他连接错误保留其含义。                     |
| 观察 | 在原时限内解码一个完整元数据答复，然后关闭候选连接。           | 错误类型、畸形载荷、EOF、到期和取消均失败；不重连、不回退为文件系统存活猜测。            |
| 比较 | 用剩余预算独立检查当前本地 cohort。                            | 本地元数据不可用使 cohort 兼容性保持未知；已知终端协议不匹配仍需重启。取消仍会取消读取。 |
| 呈现 | 在既有 8 MiB 输出上限内准备完整本地化文本或与语言无关的 JSON。 | 超限或写失败遵守既有 CLI 失败／输出规则。                                                |

`not-running` 表示在该观察时刻无法通过检查的本地作用域访问 Server。运行时目录存在但
端点缺失时，即便还有旧标记文件，也可表示不存在；该命令不删除这些文件。Server 可能在
成功答复后立即停止。可选本地 cohort 元数据不可用不会抹去已知 Server 事实。本地与
Server 观察不宣称同时发生。若 Server 探测本身耗尽预算，结果是超时，不伪造不存在，
也不把超时后答复记作成功。

## 元数据载体与兼容性

私有 OBLC v1 的类型 6/7 在不变的 256 字节载荷上限内承载空元数据请求和一个答复。
既有 hello／accept／reject 和 stop 类型的字节保持不变。答复包含 1–64 字节 ASCII 可见
构建版本 token、既有已验证的 1–64 字节 ASCII cohort token、非零进程 ID、非零 OBCS 终端
协议版本、unmanaged／managed-ready／managed-stopping 模式和 32 位实现特性掩码。
畸形长度、无效文本／版本／PID／模式及尾部多余字节均拒绝。未知特性位保留为不解释的
诊断位，绝不转化为权限或操作。具名已知位覆盖 render 行读取、Client view 控制、Agent
观察和 live handoff；托管停止支持来自实际托管生命周期所有者。

只有 Windows Server 组合响应此新增请求。同用户证明和既有候选／握手上限在分派前适用。
元数据只为报告诊断而绕过 cohort 相等检查和普通 Client Session 接纳；它不授予应用能力，
也不进入后续应用阶段。普通接纳正在停止时，Server 仍可响应；元数据读取不申请关闭记录
租约，也不创建停止请求。共享编解码保持平台无关；不增加 macOS／Linux 命令运行时。

终端协议兼容性比较响应版本和 Client 编译版本。cohort 兼容性比较 Server 保留的启动
cohort 与成功验证的本地 cohort。已知不匹配要求在使用前以匹配 cohort 重启；这不证明
只有 Server 可执行文件发生变化。不可用的比较保持 null。不执行更新、handoff、重启、
渠道变更或命名／远程路由。

旧 Server 以畸形帧或错误消息拒绝未知元数据请求；CLI 报告元数据支持不兼容，而非 not-running。完整开发
cohort 一起部署或回退。新增命令与 schema 为增量能力；裸 `status` 和 `site diagnose`
保持原意，不引入持久状态或迁移。

## 公共输出与证据

`orchbee.status.client` 和 `orchbee.status.server` 为带 local-runtime 来源的 v1 文档；
目录变为 v39／71 个 schema，原生命令清单为 84 条路径。必需的判别式元数据字段区分
已观察的 Server 数据、不存在和本地 cohort 不可用。路径使用既有无损 Windows 表示。
人工文本和路径通过公共文本呈现器转义；JSON 字节不受语言影响。无 Server 和完整诊断
观察退出 0。既有用法、权限、兼容性、协议／传输、超时和取消失败保留现有退出码与封套；
超时退出 7，取消退出 130。两者在既有 v1 失败封套中携带封闭详情
`{stage:"runtime-status"}`；旧命令的详情形状不变。

必需证据包括最大／截断／无效／未知特性位载荷及旧类型不变的黄金数据；同用户 Windows
元数据答复、错误答复、静默、到期和取消；Session 容量已满及停止中时不分配代次的 Server
元数据查询；本地 cohort 不匹配／缺失及旧 Server 拒绝；离线 Client／help／schema／补全；
以及真实匹配 cohort 的 PowerShell 5.1/7 探测，随后停止全部自有 Site。审查由实现作者
执行。TLA 执行继续延期，不宣称独立审查或未执行的形式证明。
