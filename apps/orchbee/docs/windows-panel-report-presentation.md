# Windows Panel report presentation

## Scope and ownership

The native Windows TUI reads terminal Agent reports and Panel metadata for the current Tab's selected Presentation in each Panel. These observations supplement Panel chrome; they do not create canonical Agent sessions, change the Agent board, acknowledge attention, or authorize terminal input. Server report and metadata owners remain authoritative. A child presentation never inherits its primary presentation's report.

The UI owns one logical read lane on the shared Client carrier, using the existing Agent read lane cancellation and join infrastructure. No network I/O runs in drawing or keyboard handling, and report failures cannot retire the terminal input connection. One round has a five-second absolute deadline. Commit invalidations trigger canonical report reads; the remaining one-second sample observes Host titles/process diagnostics that expose no event source. An attached-machine change hint starts the next round immediately, or right after the outstanding one. At most one round is outstanding; scopes are bounded by the Workbench context node limit and encoded rows by 8 MiB.

## Coherent observation model

A scope contains exact Session, Workbench revision and ordered Panel IDs with their selected Presentation IDs and exact bindings. Read all metadata batches, then all Agent report batches, then fence both independent revisions with empty reads. Every response must match the scope revision, requested Presentations, owning Panels and bindings. Metadata guards resolve against the same round's actual report Agent and authority source. Reject a changed revision, malformed binding, missing row, limit failure or partial round as a whole.

| Event                                              | Result                                                                                                                                                                                   |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| New Tab, selected Presentation, binding or Session | Remove observations of what is no longer selected; begin a new bounded read                                                                                                              |
| Workbench revision alone                           | Keep the observation of each still-selected exact Presentation; begin a new bounded read                                                                                                 |
| Complete correlated round                          | Publish report and effective metadata together                                                                                                                                           |
| Ordinary refresh in flight                         | Keep the preceding complete observation for that exact Presentation                                                                                                                      |
| Failed or expired read                             | Keep that observation until ten seconds after its round completed, since a commit landing inside a read says nothing about it; then hide report-derived text and mark status unavailable |
| Old epoch or old scope completion                  | Discard without affecting the current view                                                                                                                                               |
| Retirement, replacement or Drop                    | Interrupt, disconnect and join the owned lane; do not abandon the worker                                                                                                                 |

The renderer checks the current Presentation ID and binding again. Read-only observation does not alter selection, focus, layout, controller, history position, terminal geometry or canonical attention. Both carriers use `read-presentations` in batches of four unique IDs, including empty revision fences. A `presentations-read` result preserves requested order and carries each Presentation ID with its owning Panel row and exact binding. Two members may share one Panel ID; membership is qualified by Presentation ID. Unknown IDs reject the whole batch; an unbound member returns empty metadata and a null Agent report. Existing primary Panel reads and report writes retain their semantics.

## Header behavior

Every TUI Panel name uses the same precedence: the primary Presentation's custom label, then the guarded metadata title from the existing exact selected-Presentation observation, then the primary Presentation's [automatic naming rule](native-panel-labels.md#automatic-display-names), then its position. This applies to the menu title, split header, close confirmation and notification context; a rename placeholder omits the custom override so it shows what a clear would restore. Pending, unavailable or mismatched observations contribute no metadata title. Global metadata tokens append as literal key/value text after the header title; width limits may hide trailing tokens. Absence of a reported Agent does not invent idle or a canonical session.

Split and zoomed Panels paint these observations in titles on the frame or divider line above each leaf. A single Panel is bare and has no title; its terminal content begins directly below Tabs. Report reads and exact-scope invalidation remain available to the owning observation model. The member selector ends the leaf's title line, or the Tab strip for a bare Panel; its pointer regions remain separate from Tabs, Actions and terminal content. The Minimal tier keeps its unframed single-Panel display and keyboard selection route.

When metadata displayAgent or an actual reported Agent exists, one state glyph leads the title in its semantic role: working uses the sidebar's stationary white-to-gray breathing `⬢`, blocked `⬢` yellow with alternating intensity, explicit done `⬢` green, error `⬢` red, idle `⬡` gray, unknown `•` gray. Loading, unavailable and Agent-less rounds show no glyph; state words and Agent names stay in the sidebar and Agent Board. An independent trailing blue solid dot reflects the existing Client unread observation; clearing it never changes the report state. Focus preserves green completion; accepted terminal editing input projects only that exact completion as idle, independently from the canonical report and unread flag. ASCII hosts use `-\|/` frames and `#`, `+`, `x`, `o`, `.`. The remaining title and token text follows existing display-cell truncation and theme separator glyphs; user strings pass through terminal text sanitization. An ended terminal replaces its title with the localized terminal-end notice.

## Verification and delivery

Evidence must cover both revision fences, identity changes, stale epochs, cancellation, missing facts, guarded metadata, full-width/control text, narrow titles and an actual Windows native TUI observing live report changes. Render and process evidence do not authenticate a provider or prove final product parity. Ship a matched cohort; source/cohort revert is rollback. The six-state vocabulary changes the matched cohort and uses the versioned public CLI documents listed in [Native CLI Query](native-cli-query.md#schema-versions-for-independent-agent-status); it requires no durable migration. Complete the affected host gate and real-window status/read combinations before delivery.

Selecting a child immediately invalidates the preceding primary observation. The primary custom label or automatic name remains the fallback while the new exact scope loads; a bare Panel's strip selector retains the member counter. Only a complete correlated round can supply the selected member's report, guarded title and tokens; switching during a read cannot publish the old member’s result. Selector arrows use the existing exact member selection owner.
