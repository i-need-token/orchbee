# 原生 Tab 关闭集合

## 目标与确认

原生标签页菜单可关闭所选集合、其他标签页或右侧标签页；分组菜单关闭完整 canonical 组，包含折叠成员。
`TabStripContextMenu` 与原生 owner 共用
`packages/tab-strip/src/tab-strip/model/__tests__/fixtures/tab-close-targets.json` 中的目标语料。
菜单目标属于选中集合时，直接 Close 按规范顺序使用所选 ID；否则只使用该目标。
其他／右侧 Close 排除固定标签页与目标，且仅在目标属于选中集合时保护该集合。
此时右侧范围从最右侧所选标签页之后开始。直接关闭所选集合／组时，适用的固定成员也包含在内。

一次确认冻结 1–256 个精确 ID、Session／context、完整 canonical Snapshot、名称、位置、
本地标记及焦点选择。焦点包括逻辑 `PaneKey`、物理 `PaneRef` incarnation、所选 Presentation
及绑定；同 key 重新连接也算变化。后台目标按精确 ID 规划，不选中它们，也不冒充仅针对当前选择的 Close planner。
对话框使用与菜单相同的术语：英文为 **Tab**，中文为**标签页**，并与 **group**／**分组**保持区分。
它显示数量、位置、前三项名称／序号及明确的剩余数量。
菜单中的单目标／所选集合／完整分组范围来自[有类型的菜单投影](native-action-menus.zh-CN.md#标签页范围与当前值)，
不来自翻译后的数量。
名称与位置采用已清理、按字素安全截取的预览，上限为 64 个单元格（窄屏时更少），
截断时明确显示省略号；完整冻结 ID 和序号仍是权威。绘制令牌覆盖完整的有界预览、
剩余数量、警告与操作控件。
本地化警告说明运行的任务会对所有连接到此工作区的人终止，标签页将逐个关闭，失败会停止后续关闭。

共享关闭和取消按钮各自包含 Enter／Esc 标签。关闭与继续关闭采用既有破坏性动作色调，取消保持
普通意图；它们不改变 Close owner，也不表示错误状态。只有完整且成功的绘制才能授权无修饰的 `Enter`；
本地 `Esc` 即使在提示未 shown 时仍可取消已武装
确认。首次成功绘制之前，经过评估的几何阻塞会拒绝新确认。成功绘制之后，相同阻塞会挂起
既有确认，同时保留其 token、冻结集合、本地标记与焦点；同一 token 再次完整绘制之前，`Enter`
与鼠标释放均不生效。缺失或被覆盖的绘制回执只撤销 shown 权限，不判定几何，也不丢弃
presentation phase。未见、已取消、过期、缩放后或无法完整显示的确认均不能提交。既有输入
owner 捕获整个决定数据包，包括菜单交接到确认时的尾部。打开和取消不分配生命周期请求，
也不移除 canonical 状态。

## 逐项生命周期所有者

这是既有 Close／Read／协调 owner 上的有界序列，并非原子批量操作。
首次确认准入捕获一次 50 秒序列截止时间。每个新步骤取该截止时间与原操作预算中较早者；
序列活动时，协调的清理／连接预算同样受其限制。进度、排队或 UI 延迟均不续期。
超时、拒绝、不确定、无关变化或退休时，停止新的关闭提交。
已经提交的工作并未取消：保留其 `CloseRecord`、操作／别名、尝试、销毁事实、worker 交接和既有
状态／恢复路径。迟到但经过验证的 `Closed` 事实更新有界的完成／剩余数量，不重启序列。
成功摘要遵循既有有界通知惯例，在五秒后或下一次操作／通知时退场。这只回收显示状态，
保留的数量和 Close 恢复事实仍然存在。停止／部分完成的数量继续可查，当前通知享有显示优先级。

对已经显示且可恢复的状态，精确的 Tab 菜单单独提供 **继续关闭此标签页**，与集合关闭区分，包含后台成员。
它沿用既有单次 Close 确认及 Resume 操作，保留已知请求和尝试代数。它不会重启剩余集合、
再次提交 Start，或导航到其他 Tab。不确定或尚未显示的状态不提供此操作；键盘恢复入口也指向已显示的操作。
定向 Resume 冻结目标当前的选择、Session／context／revision 及具体本地焦点，不复用保留记录的旧选择版本。
同一判定在确认退场、规划及最终准入时校验这些前提。只有 Resume 可以携带此焦点约束，
打开前必须存在已显示的精确记录，缺失记录不能回退为 Start。无关当前 Tab 记录不能替换确认框的状态令牌。
可恢复的单次 Close 状态优先于集合摘要。普通页脚提示可以让位，以便完整绘制恢复状态；
输入模式指示和更新的通知仍保留优先级。Resume 确认框包含该精确停止成员对应的集合数量及已提交工作警告，
使摘要仍可查看，同时不遮挡进入恢复所需的状态。停止成员及随后其 Resume 确认框的状态优先于当前 Tab 的无关记录。

每次提交前读取完整 canonical Snapshot，与冻结来源比较。该预检不预留任何状态。
既有 revision CAS 仍可返回 `RevisionMismatch`；此时停止，不重定向、不重试。
已接受别名按既有 `CloseRecord` 规则关联，不假定主操作 ID 等于新请求 ID。

只有精确关联的 `Closed` 结果、所属成员关系安装及 exchange／协调 lease 释放完成后，下一个目标才可准入。
安装改变状态之前，立即重新检查旧本地标记、焦点 incarnation／Presentation／绑定、context 及完整来源。
安装之后，要求结果精确等于上一 Snapshot 减去该目标与获准分组清理，版本必须恰好递增一次。
存续树、身份、元数据及无关 context 必须一致。只有此所属转换可推进预期的存续选择和来源版本。
错误／更新的 Snapshot 或同一 tick 内的本地变化都停止序列；canonical 恢复仍可依既有规则安装真实状态，
但该安装不能授权剩余集合。

## 分组清理边界

Server 发布 owner 仅在移除关闭 Tab 后其源组变空时删除该组。
非空源组及所有无关组均保留，包括销毁期间由其他 Client 创建的空组。
冻结的下一 Snapshot 预期只接纳这种清理，绝不扫描最新文档并删除无关空组。

这有意不同于 GUI `TabModel.closeTabs`：后者的 `removeEmptyGroups` 会删除该 context 的所有空组。
更窄的终端生命周期 owner 避免长操作期间删除无关 canonical 数据。目标集合语义仍保持一致。
不新增线路命令、共享选择／折叠状态、持久化路径或本地合成移除。

## 证据与限制

所属实现测试覆盖冻结有序关闭集合、准确成员校验、首次绘制拒绝、准入后的挂起与恢复、
回执保留、取消、不明结果、对端移除和幸存者选择。

在 `src/workbench_client/state/tab_close.rs`、`src/workbench_client/mailbox/tests/tab_close.rs` 及相邻的状态、carrier、输入和渲染套件中维护实际证据。流程具有多种结果时，使用受控完成/时钟顺序及生成轨迹重放。

运行 `cargo test --locked -p orchbee --all-targets --all-features`。此流程不另设 TLA 模型。证据覆盖命名/生成的实现轨迹，不证明全部交错、物理终端外观或未测试平台。共享身份、所有权和提交协议仍由单独注册的核心模型负责。
