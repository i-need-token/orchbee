# Windows Panel 上报展示

## 范围与归属

原生 Windows TUI 读取当前 Tab 各 Panel 已选 Presentation 的终端 Agent 上报和 Panel 元数据。这些观察补充面板展示，不创建规范 Agent 会话、不改变 Agent 面板、不确认关注状态，也不授权终端输入。Server 的上报和元数据负责人仍是权威。子 presentation 不继承主 presentation 的上报。

UI 拥有一条独立 Client 连接的读取通路，复用既有 Agent 读取通路的取消和汇合设施。绘制和键盘处理不执行网络 I/O，上报读取失败不能使终端输入连接退役。每轮绝对期限五秒，冷却一秒；最多一轮在途。范围受 Workbench 上下文节点上限约束，编码行总量上限 8 MiB。

## 一致观察模型

范围包含精确 Session、Workbench 修订号、有序 Panel ID、所选 Presentation ID 及其精确绑定。先读取全部元数据批次，再读取全部 Agent 上报批次，最后用空读取校验两个独立修订号。每份应答必须匹配范围修订号、请求的 Presentation、所属 Panel 及绑定。元数据守卫使用同一轮真实上报的 Agent 和权威来源。修订变化、绑定畸形、行缺失、超限或部分读取均整体拒绝。

| 事件                                                         | 结果                                         |
| ------------------------------------------------------------ | -------------------------------------------- |
| 新 Tab、所选 Presentation、绑定、Session 或 Workbench 修订号 | 立即移除旧范围观察，开始新的有界读取         |
| 完整关联轮次                                                 | 共同发布上报及有效元数据                     |
| 常规刷新在途                                                 | 保留该精确范围上一份完整观察                 |
| 读取失败或过期                                               | 隐藏旧上报派生文本，标明状态不可用           |
| 旧 epoch 或旧范围回执                                        | 丢弃，不改变当前视图                         |
| 退役、替换或 Drop                                            | 中断、断开并汇合自有读取通路，不遗弃工作线程 |

渲染器再次核对当前 Presentation ID 和绑定。只读观察不改变选择、焦点、布局、控制权、历史位置、终端几何或规范关注状态。两个载体均使用 `read-presentations`，每批最多四个唯一 ID，并包含空读取修订校验。`presentations-read` 按请求顺序返回 Presentation ID、所属 Panel 行及精确绑定。同一 Panel ID 可对应多个成员，成员身份由 Presentation ID 限定。未知 ID 拒绝整批；未绑定成员返回空元数据和 null Agent 上报。既有主 Panel 读取和报告写入语义不变。

## 标题栏行为

显式自定义 Panel 标题优先，其次是受守卫约束的元数据标题，再其次是既有创建／展示标签。全局元数据 token 以字面键值文字追加在标题之后；宽度限制可能隐藏末尾 token。缺少上报 Agent 时不虚构 idle 或规范会话。

分屏与放大的 Panel 在每个叶子上方外框或分隔线上的标题中绘制这些观察。单个 Panel 不绘制边框，也没有标题，终端内容紧接 Tab 下方。上报读取及精确范围失效仍由所属观察模型提供。成员选择器位于叶标题行末尾，无边框 Panel 则位于标签栏末端；其鼠标区域与 Tab、操作入口及终端内容互不重叠。Minimal 层级保留无边框单面板显示与键盘选择路径。

存在元数据 displayAgent 或真实上报 Agent 时，标题开头显示一个使用语义角色的状态字形：working 以侧栏动画帧显示为紫色、blocked `!` 琥珀色、显式 done `✓` 绿色、error `×` 红色、idle `○` 中性色、unknown `?` 中性色。加载中、不可用及没有 Agent 的轮次不显示字形；状态词与 Agent 名称保留在侧栏与 Agent Board。独立的右侧蓝色实心点反映既有 Client 未读观察；清除蓝点不会改变上报状态。ASCII 宿主使用 `-\|/` 动画帧以及 `!`、`+`、`x`、`o`、`?`。剩余标题和 token 遵循既有显示单元截断和主题分隔符；用户字符串均经过终端文本净化。终端结束后，标题替换为本地化的终端结束提示。

## 验证与交付

证据必须覆盖两个修订号校验、身份变化、旧 epoch、取消、事实缺失、元数据守卫、全角／控制字符、窄标题及真实 Windows 原生 TUI 对实时上报变化的观察。渲染与进程证据不认证 provider，也不证明最终产品对齐。交付匹配 cohort；源码／cohort 回退即回滚。六态词汇改变匹配 cohort，并使用[原生 CLI 查询](native-cli-query.zh-CN.md#独立-agent-状态的-schema-版本)列出的新版公共 CLI 文档；无需持久迁移。交付前完成受影响宿主门禁及真实窗口中的状态／已读组合验收。

选中子项立即使先前主项观察失效。新精确范围加载期间，叶标题保留该成员自身标签与序号；无边框 Panel 的标签栏选择器保留成员计数。仅完整关联轮次可提供该成员的上报、受守卫约束的标题及 tokens；读取期间切换不能发布旧成员的结果。子项报告写入仍属独立集成；选择器箭头使用既有精确成员选择所有者。
