# Windows Workspace 元数据

## 所有权与范围

Workspace 元数据是外部上报的临时展示数据。Workbench 权威在既有 SiteCoordinator 锁下
拥有值、来源序号高水位和单调时钟过期信息。它不改变权威拓扑、Agent 生命周期、终端 OSC
元数据、Git 状态或配置。重启后元数据为空。重命名和移动保留 Workspace 身份；
关闭的 Workspace 身份在下一次元数据观察或上报前清理。

持续消费者是 `workspace report-metadata`、Workspace list/get 及其自动化客户端。
通用元数据／过期事件、附加会话快照和 TUI token 模板仍有各自的集成义务；本契约不以查询
代替事件订阅或模板渲染。Panel 展示和 Agent 上报仍归各自的语义所有者负责。

## 命令与规范化

```text
workspace report-metadata <workspace> --source <id> [--token <name=value>] [--clear-token <name>] [--seq <n>] [--ttl-ms <n>]
```

通过既有 ID／标签选择解析精确 Workspace。运行时准入前完整解析并规范化输入。
来源去除首尾空白，允许 ASCII 字母数字或 `:._-`，长度 1–80 字符。
键允许 ASCII 字母数字或 `_-`，长度 1–32 字符。后出现的重复 token flag 覆盖之前的值。
每次上报改变 1–16 个不同键；每个资源最多保留 32 个 token 键。
值先去首尾空白、去控制字符、截取 80 个 Unicode 标量值，再去首尾空白。
规范化后为空表示清除。来源标识序号新鲜度，不是 token 命名空间：最后获接受的写入者决定键值。

序号是可选的无符号 64 位十进制值。TTL 可选，范围 1–86400000 毫秒，仅作用于本补丁设置的值。
省略 TTL 会取消这些键之前的过期时间；未触及的键保留自己的过期时间。
清除只移除值，不移除来源序号历史。

上报使用既有五秒准入／选择／提交总期限。`orchbee.workspace.metadata` v1 回执包含
请求、Session 和 Workspace 身份，以及观察结果：关联的 Server 应答，或带封闭传输原因的
未知结果。传输交接后丢失应答始终表示结果未知（退出 8），取消也不覆盖它；
已确定应答在迟到的中断后仍保留。交接前适用普通 CLI 失败语义。
两种路径均不重连或重放上报。必需的 `interrupted` 和 `cleanupFailed` 标志独立记录最终
信号清理状态。已知应答发生清理失败时退出 1，但清理失败不能覆盖未知结果及其退出 8。
文本输出经过本地化及转义。

## 状态与迁移

每个 Workspace 拥有一个 token 映射和最多 32 个带序号的来源。输入包含显式的单调时钟 `now`；
确定性所有者自身不读取进程时钟。每次读取／上报边界清除截止时间小于或等于 `now` 的值，
并清理已不存在的 Workspace 身份。注册表拥有与 Workbench 修订独立、经过溢出检查的单调修订。

| 输入                          | 条件                         | 结果                                            |
| ----------------------------- | ---------------------------- | ----------------------------------------------- |
| 新序号或无序号上报            | 目标、完整补丁和资源预算有效 | 原子替换被修改的值／过期时间及接受的序号        |
| 相等或更旧的序号              | 来源高水位已覆盖该序号       | 成功的 stale 无操作；不刷新 TTL、不恢复已过期值 |
| 不带序号的上报                | 其他准入检查通过             | 应用补丁但不改变来源高水位                      |
| 结果键数或新增带序号来源过多  | 将超出容量                   | 拒绝全部写入；不消耗序号                        |
| 过期                          | 截止时间小于或等于 now       | 删除到期值，保留来源高水位                      |
| 旧截止前覆盖                  | 当前值具有更晚截止或无截止   | 旧截止不能删除替换值                            |
| Workspace 消失或 Session 停止 | 身份不再属于此所有者         | 释放临时状态                                    |

注册表最多准入 4096 个资源状态和 16 MiB 的计费保留状态
（UTF-8 内容加每项固定开销）。容量耗尽时拒绝，不驱逐高水位记录。
修订／截止时间溢出明确失败，不回绕。提交前准备完整的资源替换及字节计费。
读取输出只保证观察时刻的值有效，不承诺其将来保持不变。

## 通信与查询组合

既有已认证 Workbench 传输承载 `workbench.workspace-metadata` 和
`workbench.workspace-metadata.result`，OBWP 类型为 31/32。请求上限 16 KiB，
应答在分配前限制为 128 KiB。Read 要求既有读取权限；Report 要求导航管理权限。
高频上报不占用拓扑命令的生命周期账本。CLI 只提交一次：提交后丢失应答表示结果未知，
携带请求身份、退出 8，不静默重放。不带序号的重复上报会按设计重新应用；提供序号时以新鲜度防止重放。

Read 接受 0–8 个有序且唯一的 Workspace ID；空批次只读取修订栅栏。
全部指定 Workspace 必须存在。应答携带 Session、Workbench 修订和元数据修订，
每个请求 ID 对应一行。Report 区分 applied 与 stale 结果。
两种绑定均拒绝未知字段、非规范字符串、超大映射及无效 TTL／计数器。
Rust 原始 JSON 解码还拒绝重复 token 属性；TypeScript 对象边界保留全部合法键，
包括 `__proto__` 和 `constructor`。可选序号／TTL 接受省略或 null，缺省时序列化为省略。

Workspace list/get 在同一个已准入连接和原有五秒总期限内组合全部行。
精确 ID 和权威修订必须一致；全部批次及最后一次空读取必须具有相同元数据修订。
既有最终权威／Client 检查保留。并发变更、过期或目标缺失使查询失败，不发布混合／部分结果。
取消和传输结果保留原有含义。值和来源在两种语言输出中都进行转义，不解释为终端控制序列。

`orchbee.workspace.list/get` v1 为每行增加 `tokens` 映射；没有保留值时也返回空映射。
根级 `metadataSource` 携带 Session、Workbench 和元数据修订，以及全部读取请求 ID。
`orchbee.cli.failure.workbench-query` v1 新增 `metadata-changed`。
嵌入目录列出当前文档与命令路径。

## 证据与交付

确定性用例和生成轨迹覆盖旧／相等／缺省／最大序号、键及来源容量的原子性、延迟过期、
覆盖竞争、清除但不重置序号、UTF-8 规范化、已关闭目标、资源边界和修订／截止时间耗尽。
共享通信夹具覆盖两种语言绑定及帧大小。准入和关联检查覆盖 Server 边界。
CLI 集成还要求以进程检查覆盖修订改变、取消及结果不确定时不重放。
真实 Windows 验收必须覆盖多来源写入、读取、TTL、清除、重命名／关闭，
以及拓扑／Client 状态不变。同一作者的检查不是独立评审；此流程采用实现测试。

交付匹配的 cohort 组件。回滚匹配代码即可撤销，无需持久化迁移或修改用户配置。
不得从拓扑检查点恢复临时序号／TTL 状态。
