# POSIX Host 端点

## 范围与所有权

Electron Main 拥有 POSIX Terminal Host 客户端端点适配器。该适配器准备 Desktop 的产品范围运行时目录、验证实际 Unix 域套接字对端，并把一个已连接描述符移交给 `HostConnection`。它在 Electron Main 进程内运行，不启动端点帮助进程。因此，运行中的 POSIX Desktop 组合只有一个 `orchbee-terminal-host` 进程，其唯一产品命令是 `serve`。

Terminal Host 拥有监听器、端点生命周期锁、绑定后端点验证，以及对每个已接受 Desktop 对端的内核凭据验证。Desktop 和 Terminal Host 分别在连接的各自一侧验证对端。双方都不把端点标识符视为秘密，也不区分以同一有效用户身份运行的其他可信应用程序。

本合同不改变 Windows 命名管道适配器、Host 协议、终端生命周期、保留 Host 的重连行为或 Electron 自身的进程模型。它不会把 Terminal Host 变成加载到 Electron 中的库。

## 连接模型

| 阶段       | 所有者             | 必需转换                                                                                                         |
| ---------- | ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 运行时准备 | Desktop 本机适配器 | 在不跟随链接的情况下打开绝对运行时目录；建立或验证有效 UID 所有权、私有模式，并确认不存在扩展或可继承 ACL 访问。 |
| 端点观察   | Desktop 本机适配器 | 只在该目录下解析已验证的端点标识符，并要求它是由当前用户拥有的私有 Unix 域套接字。                               |
| 套接字连接 | Desktop 本机适配器 | 连接并通过内核对端凭据验证实际已连接服务器的有效 UID。只验证路径绝不构成服务器身份验证。                         |
| 描述符移交 | Desktop Main       | 把一个已验证描述符恰好一次移交给 Node `net.Socket`，然后构造 `HostConnection`；所有移交前失败都会关闭描述符。    |
| 协议准入   | `HostConnection`   | 执行现有的精确版本 Hello 握手，并保留现有的请求准入和未知结果规则。                                              |
| 断开与重试 | Desktop Main       | 关闭当前套接字，并在以后每次连接前重新执行运行时、端点和对端验证。只有已验证连接才能抑制 Host 启动。             |

运行时准备和已验证连接是失败关闭的本机操作。本机代码缺失、内核凭据 API 不受支持、路径无效、所有权错误、权限公开、意外 ACL 访问、端点不是套接字、对端凭据失败或对端有效 UID 不同，都不能回退到未经验证的 Node 连接。

完整运行时目录和端点路径必须符合目标平台的 Unix 域套接字路径名上限。产品默认值和受监督开发工作区会生成有界短路径；显式的过长覆盖会在协议工作前失败。POSIX 开发 supervisor 会直接在 `/tmp` 下使用一个随机、仅所有者可访问的工作区，使 Darwin 路径保持有界。该受控工作区不是稳定产品集合点，并且本机适配器仍应用相同的禁止跟随、所有者、模式和 ACL 检查。

服务器独立拒绝内核身份不可用或与 Host 有效 UID 不匹配的已连接 Desktop 对端。因此，路径名竞态不能跨越有效用户信任边界：Desktop 验证其已连接描述符实际到达的服务器，而 Host 验证监听器接受的客户端。

## 不变量与场景

- Desktop 绝不调用 `orchbee-terminal-host` 来准备运行时目录或建立客户端连接。
- `orchbee-terminal-host serve` 是运行中 POSIX Desktop 组合里的唯一 Terminal Host 产品进程。开发构建监视器属于工具，不是第二个 Terminal Host 产品进程。
- 失败或未经验证的连接不会创建 `HostConnection`，也不会发送 Hello 记录。
- 本机适配器在成功返回前拥有已连接描述符。返回后由 Desktop 拥有，成功构造后由 Node `net.Socket` 拥有。每条失败路径恰好关闭一次描述符。
- Connect-or-launch 只能在已验证连接尝试失败后启动 `serve`。Connect-only 绝不启动它。两种模式在每次重试时都重新验证。
- 保留的 Host 可以比 Electron 存活更久，并接受后来经过验证的 Desktop 重连。关闭 Desktop 套接字既不拥有也不终止 Host。
- 显式开发和测试覆盖与派生产品路径通过相同验证。

| 场景                                                                  | 可观察结果                                                              |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 私有运行时目录缺失                                                    | 本机准备以所需所有权和访问权限创建目录，然后验证已打开目录。            |
| 符号链接、外部所有者、非目录或公开运行时模式                          | 准备或连接在任何协议工作前失败。                                        |
| 原本私有且由当前用户拥有的运行时目录出现意外 ACL                      | 准备会移除它并再次验证已打开目录；如果 ACL 稍后再次出现，连接会拒绝它。 |
| 端点缺失、被替换、由外部用户拥有、不是套接字、公开或具有意外 ACL 访问 | 连接在任何协议工作前失败。                                              |
| 运行时和端点路径超过平台套接字路径上限                                | 连接在任何协议工作前失败。                                              |
| 同 UID 端点和已验证服务器                                             | 恰好一个已连接描述符到达 `HostConnection`。                             |
| 服务器凭据缺失或不匹配                                                | 描述符被关闭，且不会抑制 Host 启动。                                    |
| 套接字丢失后重试                                                      | 先前描述符被废弃，并再次运行完整身份验证序列。                          |
| 本机适配器缺失或无法加载                                              | Desktop 以关闭方式失败，不进行直接连接回退。                            |
| Windows 组合                                                          | 现有命名管道准备、服务器身份验证和直接 `HostConnection` 传输保持不变。  |

## 证据与限制

| 声明                                    | 必需证据                                                                                                     | 限制                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| 运行时和端点检查执行 POSIX 规则         | 支持的 macOS 和 Linux 目标上的本机适配器测试覆盖类型、禁止跟随、所有者、模式、ACL、端点和对端凭据场景。      | 不对支持目标之外的平台内核和文件系统作出声明。       |
| 描述符所有权准确                        | 本机/JavaScript 集成测试覆盖成功移交，以及准备、连接、验证、套接字构造和断开失败。                           | 操作系统终止可以在不运行清理代码的情况下回收描述符。 |
| Desktop 运行一个 Terminal Host 产品进程 | 真实 Desktop 系统跟踪识别配置的端点，并要求有一个 `serve` 进程且不存在 `connect` 或 `prepare-runtime` 进程。 | Electron 帮助进程和开发构建工具进程不计入此数量。    |
| 保留重连行为不变                        | 确定性 Desktop 测试和真实 Host 集成跟踪在第一个 Desktop 连接关闭后重新连接。                                 | Host 或操作系统崩溃恢复仍不属于产品承诺。            |
| 打包加载是确定性的                      | Desktop 构建和打包验证要求代码解析的打包路径存在当前平台本机产物。                                           | 被修改的安装会被拒绝，而不是在运行时修复。           |

连接和重试状态机保持不变：本机适配器只替换协议前 POSIX 身份验证传输。现有确定性 `DevelopmentHostRuntime` 和 `HostConnection` 测试继续作为状态模型细化；上述本机和系统检查负责新的进程边界证据。同用户边界不是多租户隔离，也不能防范已使用相同有效 UID 运行的其他恶意进程。

## 交付与回滚

Desktop 和 Terminal Host 一起构建和打包。本机适配器是构建产物，不是单独版本化的运行时依赖，并且私有 Host 协议和端点身份不迁移。回滚会一起还原先前的 Desktop/Host 构建；没有持久数据迁移或端点转换。生产环境绝不为已移除的帮助 ABI 保留兼容标志或不安全回退路径。
