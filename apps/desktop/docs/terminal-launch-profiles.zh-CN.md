# 终端启动配置

## 作用域与权威

启动配置是设备[共享偏好](../../../crates/workbench-protocol/docs/user-preferences.zh-CN.md)的一项字段。
Desktop Main 与 Native Worker 为新终端捕获同一目录。
Desktop 负责启动适配、Shell 集成与持久绑定；共享运行时负责平台准入和系统 Shell 发现。
Browser Preview 没有原生启动能力。

目录负责可执行文件与字面参数。Workbench 负责 CWD；Desktop 保留产品环境、几何与 Host 配置策略。
已有绑定在重试、页面替换及重启后保留捕获的启动信息。修改配置不会重新启动运行中的终端。

## 目录与校验

严格版本 1 目录包含 `defaultProfileId` 和有序 `profiles` 数组。
每个配置具有稳定 ASCII ID、去首尾空白的显示名称或内置 null 标签，以及唯一命令：
`system-shell(login)` 或 `custom-executable(executable, arguments)`。
只有 `system-default` 可使用 null 名称。名称可重复，ID 不可重复。
默认项必须存在；拒绝删除默认项或最后一项。

通用内置系统 Shell 配置在所有平台关闭登录模式。
POSIX 用户可以显式开启；Windows 拒绝开启。
自定义可执行文件必须是平台绝对路径。参数是有序字面字符串，包括空值；
不进行 Shell 解析、插值或命令字符串拼接。
共享契约负责 64 个配置、128 个参数、UTF-8 字符串及 1 MiB 目录边界。
存储目录不保证可执行文件可用或未来 Host 请求符合独立线协议上限。
具体启动准入发生在首次 Host 创建副作用之前。

## 发现与创建

每个新系统 Shell 启动使用匹配的辅助程序与共享平台解析器。
Main 在等待发现之前捕获选定配置。自定义配置不依赖系统 Shell 可用性。
系统 Shell 缺失时应用仍可启动，只有该终端请求失败，不会虚构可执行文件或回退到其他配置。

同一展示的并发创建请求共享待处理发现。
关闭展示或释放适配器会阻止后续绑定创建及 Host 副作用。
准入后的绑定捕获完整启动信息。受支持的 POSIX Shell 随后获得
[自动 Shell 集成](kitty-automatic-shell-integration-alignment.zh-CN.md)。
自定义可执行文件不可用时通过现有终端生命周期报告失败。

## 命令与持久化

读取、从配置创建、更新、选择默认项、删除及重置使用沙盒关联能力。
每个端口只允许一个待处理请求；无效消息或转移端口会终止能力。
破坏性 UI 操作需要确认；待处理控件防止重叠。

修改携带开始编辑时冻结的来源，通过共享存储更新完整目录字段。
来源过期或写入拒绝时保留提交的目录及用户草稿。
重置写入 null、声明字段并恢复通用内置目录。
回执丢失绝不重放；显式重新加载读取持久结果。
Main 观察确认的共享快照，包括 TUI 编辑。

旧 `userData` 目录只作为有界迁移输入。
有效旧选择，包括保存的 POSIX 登录决定，只向未声明字段导入一次。
无效来源保持可见且不被修改。显式编辑或重置防止延迟导入恢复旧值。
独立文件存储适配器仍作为旧输入测试；生产使用
[共享 Desktop 设置权威](terminal-settings.zh-CN.md)。

## 验证与限制

跨语言一致性覆盖目录边界。Main 和渲染端测试覆盖 CRUD、字面 argv、平台校验、
来源冲突、待处理与释放、迁移及失败保留。
生命周期测试覆盖发现失败、发现期间关闭、合并创建及持久捕获。
真实进程测试使用隔离作用域。适用系统测试及受影响根门禁排除手动原生窗口测试。

配置不包含环境、秘密、启动目录策略、SSH 或 Workspace 配置。
单次非默认选择、远端同步、任意可执行文件行为及未测试系统上的原生执行不属于本契约。
