# Project 文件夹获取

## 权威与范围

本文档负责 Desktop 获取现有本地文件夹，用于创建 Workbench Project 或添加文件夹的契约。Workbench 拥有用户意图与 Project 变更，`apps/web` 拥有 Electron 渲染器适配器，`@orchbee/desktop-client-protocol` 拥有专用渲染器能力端口上的记录，Desktop Main 则拥有原生对话框与文件系统观察。

Browser 与 Gateway 客户端继续使用显式路径输入适配器，绝不会获得该能力。范围不包括创建文件夹、Git 发现或变更、持续可用性监控、远程文件夹访问及通用渲染器文件系统访问。

## 领域契约

| 领域           | 契约                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 问题           | 用户在 Electron Workbench 中选择 `Select Folder…` 时，必须通过 OS 对话框选择现有本地文件夹，而不是输入未经校验的路径。                    |
| 意图           | 为新的 Project 或当前现有的 Project 获取一个文件夹。                                                                                      |
| 不受信任的输入 | 渲染器命令、请求 IDs、本机对话结果、返回路径、异步完成顺序以及任一端点退出后收到的消息。                                                  |
| 成功           | Main 返回已校验、绝对且经 Host 规范化的路径；Workbench 为当前目标调用现有 Project 创建或文件夹添加 Action。                               |
| 取消           | 本机取消返回 `cancelled`，关闭挂起的交互，通过本机对话框生命周期恢复焦点，并且不调用 Workbench Action。                                   |
| 失败           | busy、permission-denied、missing、not-directory，以及对话框、校验或控制失败，都不会调用 Workbench Action，并会投影局部可 dismiss 的失败。 |
| 无操作         | 当一个请求待处理时重复的 UI 请求、陈旧或未知的完成、处置后完成以及目标 Project 中已存在的选定文件夹不提交任何更改。                       |
| 副作用         | Main 打开一个窗口模式本机对话框并执行只读路径观察。选择永远不会创建、更改或删除文件系统内容。                                             |

## 规范数据和所有权

| 可变事实                 | 唯一所有者                                    |
| ------------------------ | --------------------------------------------- |
| 当前获取目标与阶段       | 已挂载的 Workbench 文件夹获取工作流           |
| 渲染器请求身份和完成     | Electron 文件夹获取客户端                     |
| 唯一活动的原生操作       | Desktop 文件夹获取 Broker                     |
| 原生对话和路径观察       | Desktop 文件夹获取运行时                      |
| Project 和文件夹成员资格 | `WorkbenchProjectWorkspaceRuntime` 至 Actions |
| 渲染器文档功能生命周期   | `DesktopApplication`                          |

Workbench 工作流具有 `idle`、`selecting`、`failed` 及最终 `disposed` 阶段。`selecting` 阶段包含一个目标：`create-project` 或 `add-project-folder(ProjectId)`。Electron 渲染器客户端单独拥有对应请求标识。协议结果恰为 `selected(Path)`、`cancelled` 或 `failed(FailureCode)` 之一。

## 路径策略

| 决定       | 规则                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------- |
| 选择基数   | 请求一个现有文件夹；多重选择和文件选择被拒绝。                                                |
| 规范路径   | 需要绝对本机路径并在验证和发布之前应用主机 `resolve` 规范化。                                 |
| 符号链接   | 保留该人选择的标准化路径拼写；目录和访问检查遵循链接目标。                                    |
| 验证       | 所选路径必须仍然存在，解析为目录，并允许在观察时读取和遍历。                                  |
| 可移除位置 | 可以选择挂载位置；日后被删除时由现有终端启动与未来 Directory 协调行为处理，而非本次获取流程。 |
| 隐私       | 所选路径可能会输入规范的 Workbench 文档，但不会输入功能诊断或故障文本。                       |
| 补偿       | 选择和验证是只读的，因此后来拒绝的 Workbench 提交没有外部影响来补偿。                         |

## 转换

| Action               | 前置条件               | 结果                                                        |
| -------------------- | ---------------------- | ----------------------------------------------------------- |
| 请求选择             | 工作流与 Broker 均空闲 | 记录目标与请求标识；打开原生对话框。                        |
| 重复请求             | 正在等待选择           | Workbench 处无操作；直接的第二个协议请求接收 `busy`。       |
| 本地选择验证         | 匹配请求和实时能力     | 发布规范化路径；仅当当前语义保护成立时才调用目标 Action。   |
| 原生选择已取消       | 匹配请求和实时能力     | 返回空闲状态，无 Action。                                   |
| 原生选择失败         | 请求匹配且能力仍有效   | 进入失败呈现，不调用 Action。                               |
| dismiss 失败         | 工作流处于失败状态     | 返回空闲状态。                                              |
| 渲染器文档退役       | 任意非处置阶段         | 处置两个端口端点与工作流；忽略任何后续原生完成。            |
| 未知或过时的完成情况 | 身份与当前请求不匹配   | 停用无效的客户端传输或忽略已经停用的端点；切勿调用 Action。 |

OS 对话框没有超时；其持续时间由用户选择决定。只有原生操作完成且两个端点仍活动时才声明进展。处置端口无法关闭已经打开的 OS 对话框，但会撤销交付及 Workbench 变更权限。

## 不变量

- Gateway 和普通 Browser 客户端无法获取本机文件夹获取端口。
- 一个渲染器文档与一个 Broker 至多拥有一个待处理文件夹请求。
- 仅针对匹配实时请求的已验证 `selected` 结果调用 Workbench Action。
- 取消、失败、目标已存在、处置与过时完成不会调用 Project 变更。
- Main 在发布选定路径之前进行验证； Workbench 从不接收通用文件系统原语。
- 在不明确的客户端或代理传输失败后，不会重播任何请求。

## 正确性和验证

| 声明                       | 证据                                                                                             | 限制                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 一个实时请求和仅选择的突变 | `DesktopLifecycle` `project-folder-acquisition` 配置、确定性 Workbench 转换测试和客户端/代理测试 | TLC 使用有限的请求和目标集；测试建立实施细化。                         |
| 取消、失败与退役安全       | TLA+ 取消/处置 Action、客户端/Broker 延迟完成测试及渲染器卸载测试                                | 原生 OS 对话框取消由注入的确定性结果表示。                             |
| 现有可读目录验证           | 针对绝对规范化、目录、符号链接、权限、消失和意外失败的运行时测试                                 | 验证是一种观察时间声明，而不是持续可用性。                             |
| 仅 Electron 能力交付       | Bootstrap Schema/preload/Main 组合测试及 Desktop-versus-Browser 应用测试                         | 持有端口的可信 Electron 渲染器可以请求对话框，无需第二次用户手势证明。 |
| 可观察的本机集成           | Desktop 系统跟踪，带有注入的本机选择器以及手动当前平台检查                                       | 自动化测试并不要求控制真实的 macOS、Windows 或 Linux 系统选择器 UI。   |

`project-folder-acquisition` 配置检查至多两个请求标识与 Workbench 目标类型。它只在显式建模的原生结果后检查：单一活动请求；只有当前选择才能变更状态；取消与失败为空操作；退役会撤销权限；以及最终结算。
