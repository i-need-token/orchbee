# Workbench 重启检查点

## 范围与归属

`workbench_authority/checkpoint.rs` 拥有 Workbench 保留配置的私有版本化投影，以及将其重建为
新权威的过程。Windows 托管 会话 是存储／启动消费者。领域编解码器与 Windows 文件系统准入、
检查点发布及终端重新启动分离。命名 会话 路由和其他恢复所有者仍有独立义务，不新增其他平台适配器。

检查点保留可选 Project 成员关系、Project 标签、全局本地目录路径、Workspace 及其显示顺序、终端上下文、有序 Tab、分组、固定状态、
分屏结构及比例、Panel 输入策略及 Presentation 标签，同时保留 Launch Profile 定义和分配高水位，
包括已删除 ID。主／子 Presentation 均保留结构，但不携带终端绑定或启动失败。

它不保留运行进程、会话／Worker 身份、控制权、租约、Client 视图／焦点／zoom、请求结果、发布
游标、未完成操作、Agent 状态或终端历史；这些恢复责任属于各自运行时所有者。检查点从不授权
重放终端命令或 Git 操作。

## 模型

| 操作       | 前提                                                                                         | 结果与不变式                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 捕获       | 权威未退役；已提交对象图有效；每个 Directory 和已绑定 Presentation 都属于传入的本地 Worker。 | 一个有界检查点；源权威不变；移除进程绑定和 Worker 身份。                                                       |
| 解码       | 严格当前 version 1 文档、字节有界、规范化导航、配置图、计数器有效。                          | 完整保留配置或类型化拒绝；不返回部分结果或空成功。                                                             |
| 重建       | 调用者传入新启动的 会话 身份及其已准入本地 Worker。                                          | 保留结构 ID 和本地路径，使用新目录所有者、无绑定 Presentation、新 Profile 会话 前缀、revision 0 和空临时状态。 |
| 恢复后分配 | 恢复的高水位允许递增。                                                                       | 新 ID 高于所有已分配计数器；耗尽时保留既有类型化拒绝。                                                         |

调用者负责新会话身份的新鲜性。Profile ID 为 `<sessionHex>:<counterHex>`，存储形式仅保留
计数器、名称和启动定义，重建使用新 会话 前缀。旧 会话 授权和 Profile ID 不获得新启动的权威。
名称不要求唯一，既有选择器歧义语义保持不变。

## 私有格式与校验

### 当前规范化导航

读写器仅使用标识 `orchbee.workbench.checkpoint`、数字版本 `version: 1`。
所有保留字段均必填，包括 `terminalDirectories`、
`projectOrder` 和 `workspaceOrder`。`checkpoint/navigation.rs` 仅有一个 DTO，保存按身份排序的
全局 `directories`、`projects`、`workspaces` 数组。Project 记录含 `projectId` 和 `label`；
Workspace 的 `projectId` 必填且可为 null。Directory 记录含 `directoryId` 和 `path`，重建时
赋予新的 Worker 所有权。Workspace 顺序必须是完整排列；Project 顺序为空时使用规范 ID 顺序，
否则也必须是完整排列。未分组 Workspace、空 Project、共享或未使用的 Directory 及两类显示顺序均保留。
对象图最多容纳 65,536 个 Directory、1,024 个 Workspace，每个 Project 最多 256 个 Workspace，
同时受不变的编码上限约束。

未知、重复或缺失字段、历史嵌套导航、不支持的版本、无效引用和不足的身份高水位均拒绝整份文档。
不进行迁移或历史规范化。版本规则见仓库[数据边界规范](../../../docs/zh-CN/ARCHITECTURE.md#数据边界)。
现存标为版本 2–7 的文件，包括此前写入器生成的版本 7，都会变为不可读；修改版本标记不是受支持的转换。
下述托管恢复策略会保留这些文件。

规范分割比例继续保留，见[共享比例](shared-split-ratios.zh-CN.md)。`lastIdentity` 与每个 Profile 的
`counter` 都是规范化、非零的 32 字符小写十六进制数。所有 Presentation 绑定为 `null`，
`customLabel` 必填且可为 null。
`checkpoint/contexts.rs` 拥有保留对象图形状：Tab 的 `automaticLabel` 和 `groupId`、Panel 的
`rightClick`、Split 的 `ratio` 以及 Presentation 的 `binding` 即使取默认值或 null 也必须显式写出。
仅属于运行时的 `launchFailure` 字段不准进入保留配置。

### 逐终端目录恢复

必填的 `terminalDirectories` 列表保存稳定的 `presentationId` 与已验证的 `path`。
主、子 Presentation 各自独立。null 列表、重复／外部成员和非法路径拒绝整份文档，仍使用 2 MiB 上限。

请求／后台工作静止后，正常停止在 Worker 释放前，通过现有私有查看器所有者采集新的有界观察。有效终端上报目录优先于根进程目录；不会用子进程目录冒充根目录。最终物理成员关系与 Worker 代际必须仍匹配。未知 detach 由已停止的进程观察器继续负责，使本次停止失败并保留之前的检查点；后续停止可结算该精确附着。

正常运行时，既有进程采样器仅缓存已经观测并验证的目录，同时保留确切 Worker generation、Host
终端身份及采样起始时间。缓存捕获在 会话 gate 下重新检查当前物理成员；过期、移除或替换的绑定
不贡献目录。观测不可用时不伪造目录、不清除已有恢复意图。保存不打开 viewer、不采样进程、
不读取屏幕内容。

捕获将准入观察映射到当前 Presentation 身份。观察不可用时保留已有恢复意图，否则使用普通工作区／home 默认值；已移除成员不再保存。全新启动优先使用保留目录，其次工作区默认目录；所选路径已不是目录时，Windows 恢复使用 Worker 的 home 默认值。此策略不改变用户显式启动的校验。共享 PowerShell 提示符同步也应用于恢复后的编码命令 shell，因此 provider 退出后切换目录仍可被观察。

证据必须覆盖精确身份／修订围栏、主子分离、不兼容格式拒绝、非法记录、不恢复活跃权威的捕获／重建、未结算查看器清理、实际 Windows 目录切换及保存目录被删除。启动进程证据本身不能证明此目录生命周期。

检查点编码上限为 2 MiB。重建 Snapshot 必须通过既有完整对象图校验和 1 MiB 传输限制；Profile 目录保留
64 项、256 KiB 限制。全部自有结构／Profile 计数器必须互不重复，且不超过 `lastIdentity`。
引用由 Snapshot 所有者校验。伪造已绑定 Presentation、捕获时的外部 Worker、无效路径、缺失
成员关系、非法启动定义或低于保留 ID 的高水位都会拒绝整个操作。仅 JSON 编码不能证明对象图有效。

领域层不访问文件系统、不启动进程。存储层必须准入 Windows 私有路径、发布完整记录、区分
不存在和损坏，并保留失败证据。启动恢复必须建立新的物理绑定，并处理被中断操作；编解码器
返回无绑定权威不代表已恢复可用会话。格式变更遵循仓库数据边界规范，不提供宽松回退。

## 终端重新绑定准备

`checkpoint/restore.rs` 按 Workspace Context、Tab 及深度优先树顺序枚举每个无绑定主／子 Presentation。每个目标携带新 会话／本地 Worker、准确成员身份及分开的保留／Workspace 目录意图。只读注册遍历全部主、子成员；破坏性操作保留各自守卫。没有保留 cwd 的未配置 Workspace 使用 Worker home。

`prepare_restored_terminal` 重新检查 会话、本地 Worker、成员关系、未绑定状态和 cwd 默认值，
再校验并准备完整的候选投影／发布，之后才允许变更。丢弃准备结果不改变任何状态。提交仅设置
一个绑定并递增修订；结构身份、分配高水位、标签、顺序、分组、输入策略和 Profile 均不变。
拒绝已绑定的目标及重复的物理终端绑定。

准备不创建进程，也不重放命令。托管协调器联合准备新终端预留及规范绑定，在同一锁下提交两者，随后分发并结算准确物理请求，再暴露 Client。恢复快照绑定是唯一附着选择来源，不重建 Open 引用。仅规划测试不证明运行时集成。

## Windows 托管启动与正常停止

托管启动在 `LOCALAPPDATA` 下打开独占 `WindowsSessionStore`，并在启动 Worker 前解析已提交
副本。存储 owner 从三个槽位选择最新且完整验证的 payload。无效副本保留并产生可见恢复提醒；
全部副本无效时明确报告空恢复。数据缺失表示新 Workbench；私有路径或文件系统准入失败仍中止启动。
详见 [Windows checkpoint 存储契约](../../../crates/local-site-runtime/docs/windows-checkpoint-storage.zh-CN.md)。
默认和命名 会话 激活均在使用存储前发布当前版本 1 的 durable 记录。
Server 在打开 store 和清理 pending 文件前准入完整的 durable 形状。
`WindowsSessionStore::read_validated` 将所有无效 payload 作为不可读副本处理：选择有效槽位或
报告空恢复，保留无效字节，并在替换前归档。领域解析失败不再存在特殊的致命迁移错误；文件系统
准入错误仍中止启动。未提交 pending 文件的清理保持不变。

`WorkbenchCheckpoint` 是已准入配置值：私有对象图校验身份不会成为可运行权威，只有使用新 会话
及已准入 Worker 重建后才产生新的权威。

启动 IPC 前，协调器准备所有新 shell 预留和 Workbench 绑定。分发前失败尚无 Host／终端，终止创建所拥有的 Worker 并确认退出。每个准备请求仅分发、结算一次；失败／未知结果保持显式，不自动重试。保留目录优先于 Workspace／home 默认值；保存／配置目录缺失时回退到 Worker home。初始几何为 80x24、单元格 8x16，直到调整尺寸。主、子成员恢复不新增 Tab。期限到达时未分发请求结算不可用。后续启动失败停止维护，请求自有 Host／终端关闭，确认 Worker／传输退出并停止观察。未确认清理保留恢复状态；仅终止 Worker 不证明 Host 清理。

正常停止在请求和后台操作收敛后、释放 Worker 前保存。编码或发布失败阻止释放，保持停止失败；此前
有效存档仍保留，被移走的无效原件仍在 raw 归档中。正常停止先结算唯一后台保存者，再捕获最新目录并发布最终存档，最后才释放
Worker；延迟的后台写不能覆盖最终存档。新物理创建建立终端绑定。Client／历史恢复仍属独立任务。启动失败时的激活标记
仍遵循既有恢复语义。

## 运行中保存模型

Windows 托管 Server 在终端恢复完成后拥有唯一后台保存者。它观察已提交的
Workbench revision；每次变化重置 500ms 防抖。每 30 秒还捕获已缓存目录。payload 不包含终端屏幕、历史、Agent 对话或活跃控制者状态。待办工作只有一份最新
快照，不使用无界队列。
当全部保留副本都无效时，保存者在内存中保留准确的初始空 checkpoint，不发布该基线。之后只有布局或已缓存目录发生变化，使完整 checkpoint 不同时，自动发布才可替换无效槽位。
该抑制仅适用于无人参与的后台保存。显式 `server stop --confirm` 表示确认当前工作区，因此其最新 final
捕获即使仍是空状态也可以发布；存储 owner 会在提交前归档被替换的无效原始字节。

捕获仅在构建有界配置值时持有既有 会话 gate，随后释放。文件系统验证、原件保留、flush 与替换
在 gate 外由唯一写者执行。I/O 期间的新 revision 仍标记为 dirty，安排下一次捕获。保存失败保留
此前有效副本及有界错误状态；不终止终端、不授权新 会话。后台保存者必须在最终正常停止捕获前
结算；无法 join 时停止不能完成，不能产生两个存储写者。

## 证据

确定性测试通过独立对象图预期覆盖捕获／重建、嵌套分屏及子 Presentation、Profile 重映射、
删除身份后的分配、外部所有权、损坏、重复／未知字段、绑定注入、对象图错误和大小限制。
当前形状夹具保留未分组成员关系、显示顺序、未使用／共享 Directory、cwd。
严格夹具覆盖字段缺失与不兼容版本。原生存储和 Server 加载证据验证无效副本的回退／空恢复提示及
准确字节保留，其中包含此前的版本 7 文档。直接 Server 准入也验证在 durable catalog 不受支持时
保留 pending 文件。

协调器测试覆盖物理预留与对象图的联合准备、分组／固定／子成员、绑定重附着，以及不重放的显式
不可用结果。Windows 存储／进程测试覆盖私有替换、锁和准确句柄终止。真实打包 Windows 正常
停止／重启验收对比保留的布局／Profile、新运行时身份、shell 执行效果及 TUI 绑定重附着；
替换受阻时必须保留旧字节和运行中的终端，直到显式重试成功；无效副本必须保留准确原始字节，
产生声明的回退／空恢复提醒，且不得绕过 会话 owner 准入。缓存捕获测试覆盖物理替换、乱序采样与
已移除成员。调度测试使用显式时间及延迟写入，证明防抖、定期补存、有界待办与最终停止顺序。
原生崩溃／重启验收须比较多个 Tab、嵌套分屏、标签、目录；机器重启及交互负载仍须单独提供证据。
