# 终端 Agent 上报转换

本模型拥有显式终端上报事实：来源权威、provider 会话引用、来源水位和旧生命周期上报抑制。
它与 `AgentRuntime` 的规范 hook 观察 Session 独立。核心现已供有界 Windows Server 注册表
和 OBWP 上报／读取接口使用。[原生 CLI 命令](../../orchbee/docs/windows-panel-agent-reports.zh-CN.md)
已提交这些上报。Panel／Agent 查询使用独立修订号校验联合真实上报视图和元数据守卫。
已校验关联身份的 Windows viewer Host 样本现已进入可信进程操作。周期采样、名称及 TUI 发布仍待集成。公开线协议不接受进程观察。

## 输入与归属

参考为 Herdr `e0507237ad8d41f60aece10d00ef29ce2339ca34`，同时包括公共 `AppEvent`
路由和 `TerminalState` 转换。上报者包含精确来源和规范化后的非空 Agent 标签。上报状态仅为
idle／working／blocked／unknown；元数据展示标签 `done` 不是上报状态。上报携带
显式状态／消息、可选的已校验 provider 引用、可选的完整 u64 序号和可选的已识别启动原因。
provider 引用校验与来源策略由 `orchbee-agent-observation-protocol` 提供。独立且可信的进程
观察提供检测到的 provider、回退状态、可见阻塞、退出标记及观察时间。上报字符串不能证明
进程存在。

每份上报状态属于一个终端代际。数据包括当前权威、保留的 provider 引用、来源序号水位、
被抑制的完整生命周期归属、待确认的替换引用／上报以及旧 Session 身份。核心不执行 I/O、
读取时钟、分配规范 Session，不持有名称注册表、Workbench 拓扑或持久化。调用方提供负责人
时钟刻度；进程输入单独保留原采样刻度，不能删除更新的自定义权威。即使收到的是旧进程
样本，新清除抑制仍使用当前负责人时间；回退状态、退出和元数据清理保留样本时间。状态和观察有规范
JSON 轨迹。转换准备新状态，调用方负责准入与提交。

注册表与终端元数据同属 Site／Workbench 提交门。可信进程操作先准备上报和元数据退出候选，
再共同提交。规范观察 Session 及其别名仍由 `AgentState` 管理。二进制程序从已提交绑定和保留
授权取得真实 Worker 代际及 Host 创建／epoch／终端身份；Client 标签、PID 或通用观察分类
不足以构成证明。Windows viewer 适配器仅在成功 Host 样本通过完整关联校验后调用可信操作；核心本身不采集进程。

## 转换决策

| 输入 | 决策与结果事实 |
| ----- | ---------------------------- |
| 保留原生状态来源的状态上报 | 路由至无启动原因的 Session 引用上报；请求中的状态和消息不覆盖原生观察。 |
| 仅身份来源的状态上报 | 忽略状态权威，由公共会话上报操作持有其引用。Qwen 先走保留原生状态路由。 |
| 其他状态上报 | 先检查进程／归属／会话／抑制，再检查来源序号，之后替换权威。缺失引用清除先前的上报引用。 |
| 无有效引用的会话上报 | 不改变状态或序号。 |
| 有效引用的会话上报 | 应用精确 provider／启动来源规则；完整生命周期可能等待进程确认后再采用替换引用。后续守卫可能在消耗序号后拒绝，与参考一致。 |
| 清除权威 | 仅当前匹配来源或省略来源时有资格；由序号控制清除。仅保留的会话身份不能通过此操作清除。 |
| 释放官方来源／Agent 配对 | 公共路由无条件无操作，包括不消耗序号。 |
| 释放自定义上报 | 拒绝其他来源权威，要求匹配有效 Agent／引用并通过序号；保留独立确认的存活进程与其他来源的保留身份。 |
| 进程观察 | 存活的完整生命周期权威优先于较弱检测；拒绝早于释放抑制的观察，确认替换声明，并清理已退出代际的匹配上报。 |

来源接受带序号上报后，后续无序号上报即过期。相等或更小的序号不能前进。只有参考中确认
代际／会话重新锚定的规则能重置该水位。清除／退出抑制与旧身份阻止迟到上报复活旧会话。
待确认的生命周期上报不是有效权威。OpenCode 无序号 `select` 路径显式处理，进程缺失时需
等待确认。合法启动原因本身不是进程证明；`branch` 不具备生命周期重新锚定资格。

有效观察包含标签、状态、真实权威来源／消息和当前 provider 引用。完整生命周期权威仅在
匹配进程存活时生效，否则仍可使用检测进程／回退状态。更新的可见阻塞可覆盖非完整生命周期
上报，但不声称产生新上报来源。清除上报事实不会结束规范 `AgentRuntime` Session，也不会
伪造轮次、审批、就绪性或 provider ID。

## 提交与验证边界

`changed` 描述候选状态，与 applied／ignored／deferred 处置独立。特别是被忽略的会话上报
仍可能推进水位；调用方不能拿处置代替变更检测。在负责人接纳完整候选、元数据效果和编码
结果之前，旧状态保持不变。

运行时注册表每终端最多保留 128 个来源身份、256 个旧会话身份和 512 KiB 编码核心状态；
最多 4096 个逻辑终端，总计核算 32 MiB。失败不消耗候选序号，容量满时无效果上报仍可完成。
没有上报、进程、序号或历史事实的空聚合会被回收。独立上报修订号使用受检加法。维护清理已消失的主／子成员或明确被替换的物理代际，缺少 Host
事实不等于退出。维护使用独立受检修订号，可以在后续请求被拒绝前完成；共享 Workbench 导航
和规范 AgentRuntime 修订号不变。

所有者时钟以首次提交的接纳 Instant 为原点，将它映射到 2^63。采样和接纳时间共用该原点，
包括早于首次接纳的采样；纳秒转换检查溢出，不用墙钟、回绕或饱和定义顺序。

可信进程提交还会清理匹配的官方元数据、较旧的 Agent 守卫展示和已退出 Agent 的序号所有权，
保留全局 token 和较新的自定义展示。元数据所有者分别保存展示上报时间、字段优先级，以及
已接纳序号对应的 Agent，包括纯 token 上报。迟到的匹配元数据在真实进程确认前返回过期无效果。
两个候选都通过容量／修订号检查后才提交，因此任一修订号耗尽都不会导致退出只提交一半。
上报相关名称和 TUI 上下文仍待消费；原生查询已联合上报和元数据状态。

## Windows 上报承载

`workbench.panel-agent` 的请求使用 OBWP kind 35，结果使用 kind 36。读取权限允许查询零至
四个不重复的 Panel ID；导航权限允许四种显式上报。写入要求预期逻辑主绑定匹配，且具有当前
保留的物理身份事实。来源和消息按原文保留，Agent 标签使用共享规范化，序号是完整 u64 十进制
字符串。无效 provider 引用及未知启动原因按参考实现转为缺失；有效 provider 引用与规范观察
Session ID 独立。Windows 组合层提供路径绝对性判断，不访问文件系统或执行 provider。
请求沿用 16 KiB 上限，结果上限为 512 KiB；公开协议不接受进程证明字段。

回执包含 Workbench／上报修订号、解析绑定、applied／ignored／deferred 处置、实际变更标记和
有效上报视图。读取保持请求顺序，无绑定行明确为空。所有者在提交上报候选前校验编码回执。
等待进程的完整生命周期上报保持 deferred，不虚构就绪性。解码结果里的原始引用校验来源／
种类／值资格，平台绝对性属于 Server 发布义务，未来执行 provider 前仍须重新校验。共享
Rust、TypeScript 和 JSON 契约保留旧封闭变体，通过匹配的私有 cohort 发布；旧端拒绝新 kind。
状态为临时数据，可通过源码／cohort 回退恢复。

决策测试和序列化轨迹覆盖过期／无序号上报、来源冲突、公共原生／官方路由、仅会话身份、
清除／释放时保留进程、待确认完整生命周期引用、旧会话抑制、provider 专属替换和迟到观察。
生成的自定义来源事件序列检查输入不变、序号保留、其他来源清除隔离，以及不得虚构 provider／
进程事实；失败时输出缩减后可重放的序列。固定版本参考实现的差分序列还通过公开分派规则，
比较完整上报状态、有效视图和释放结果。这些覆盖核心和所有者准入；原生 CLI 另有承载／
命令验收。声称 CLI/API 对齐前，仍需真实 Host 观察、名称／TUI 行为及最终全量回归。

## Windows 进程采样适配器

Windows viewer 适配器是可信进程观察的第一个真实生产者。它只消费已完整校验关联身份的成功 Host `ProcessInfo` 应答；I/O 结束后，在 Worker 注册表和 Site 协调器锁内再次核对物理代际并提交。样本保留请求开始时间、逻辑绑定、Worker 代际及 Host 创建／epoch／终端身份。Host 固定进程对象，完整读取所有行，并确认采集前后的 Job 成员一致。类型化失败、身份缺失或 Agent 链有歧义都不代表退出。

可执行文件／入口识别和祖先链选择采用共用的纯 Agent 输入规则；Windows 命令行解析留在各自 OS 适配器中。协调器保留选中进程的 PID、创建时间及最新接纳样本的开始时间。较旧或相同时间的样本不能覆盖新观察。完整成员列表能证明此前确认的进程已离开该 Job 或 PID 已复用。退出及元数据清理作为一次所有者操作共同提交；替代进程由后续样本确认，避免两次转换只提交一半。所有者拒绝接纳时不推进缓存身份。选中身份与显式上报输入修订均未改变时，不反复推进上报修订；新暂存上报允许再次确认。保留事实缺失不生成退出。缓存受当前注册成员数量约束，随物理成员关系结束释放。

本适配器只提供 provider 存在性和 unknown 回退状态。屏幕推导的 working／idle／阻塞检测、不依赖 viewer 读取的周期采样、名称、持久化、provider 执行及 TUI 展示仍需接入。即使上报所有者无法接纳样本，既有 CLI 诊断进程读取仍可用；它不承诺上报新鲜度。
