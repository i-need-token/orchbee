# 终端 Agent 上报转换

Server 拥有临时自定义终端上报，与 `AgentRuntime` 中的规范 Hook 观察分离。
[原生命令](../../orchbee/docs/windows-panel-agent-reports.zh-CN.md) 提交带来源的状态；只有关联完整的
Host 观察才能证明进程存在或退出。

## 输入与所有权

作者由精确来源及规范化的非空 Agent 标签组成。所有来源都使用同一自定义上报策略。状态为
idle/working/blocked/done/error/unknown；显式 done/error 表示轮次结果，屏幕匹配或读取确认不会推断它们。
来源名称不授予 provider 身份、生命周期权威或可恢复性。会话上报输入和 provider 引用字段不会改变
上报状态或来源水位。

每个聚合属于一个物理终端代际，保留当前权威、来源序号水位、检测到的 provider、回退证据及最近确认的
退出。核心没有 I/O、时钟、规范 Session 分配器、Names 注册表或持久化。调用者提供所有者时钟 tick；
进程观察保留采样起始 tick，使较旧退出不能擦除更新的自定义上报。准备只返回候选，不修改输入。

仅确认进程存在时保留回退状态及其证据时间。退出、provider 改变或确认退出后的替代进程，在没有新屏幕
证据时清除旧回退。缺失、失败或歧义的 Host 样本不能证明退出。

## 转换决策

| 输入 | 决策                                                                                  |
| ---- | ------------------------------------------------------------------------------------- |
| 状态 | 拒绝与检测进程冲突或已确认退出的已知 provider；随后要求新来源序号，并替换自定义权威。 |
| 会话 | 忽略，不消费序号，也不创建身份。                                                      |
| 清除 | 要求匹配当前来源，或省略来源以选择它；通过序号检查后清除权威。                        |
| 释放 | 拒绝外部权威；要求匹配有效 Agent 及新序号。保留独立确认的存活进程。                   |
| 进程 | 协调 provider／回退证据，清除匹配退出代际的上报，同时保留更新的自定义上报。           |

序号使用完整无符号 64 位范围，以规范十进制字符串编码。来源接受序号后，相等、较小或不带序号的上报
均过期。清除保留水位；确认退出可重置匹配的上报来源。更新的可见阻塞可覆盖上报状态，但不伪造报告来源。
有效视图包含 Agent 标签、状态、权威来源和消息。清除上报不会结束规范 Agent Session。

## 提交与验证边界

`changed` 独立于 applied/ignored 结果，描述候选状态。上报和匹配的 Agent 守卫元数据清理，在任一提交前
共同通过修订、容量及编码结果准入。退出清理保留全局 token 和更新的展示。已确认退出 Agent 的晚到
元数据在进程重新确认前仍然过期。

每个终端最多保留 128 个来源、512 KiB 编码上报状态。注册表最多容纳 4096 个终端，聚合计费上限为
32 MiB。拒绝不消费候选序号；达到容量上限时仍可处理 no-op。成员删除或确认物理替换会退役资源；
Host 事实缺失不会。独立且检查溢出的上报修订不改变 Workbench 或规范 AgentRuntime 修订。
所有者纳秒时钟以 2^63 为检查过的原点。

## Windows 上报载体

`workbench.panel-agent` 使用 OBWP 请求／结果种类 35/36。读取权限允许最多四个唯一 Panel ID；导航权限
允许上报。写入要求当前逻辑成员、预期绑定及保留的 Worker／Host 代际。来源／消息按字面保留；标签使用
共享规范化。请求上限 16 KiB，结果上限 512 KiB。公开请求不能提交进程观察。回执携带独立修订、绑定、
处置结果、变化标记和有效视图；读取保留请求顺序及未绑定成员的 null 记录。

决策轨迹覆盖来源顺序、外部清除／释放、进程保留、延迟退出、可见阻塞及不可变准备。生成的自定义来源轨迹
验证水位及不伪造进程的不变量。所有者／载体轨迹覆盖容量、修订耗尽、原子元数据清理、精确成员围栏及
物理替换。规范 Hook 行为与普通终端恢复继续由各自契约负责。

## Windows 进程采样适配器

Windows viewer 适配器是可信进程观察的第一个真实生产者。它只消费已完整校验关联身份的成功 Host `ProcessInfo` 应答；I/O 结束后，在 Worker 注册表和 Site 协调器锁内再次核对物理代际并提交。样本保留请求开始时间、逻辑绑定、Worker 代际及 Host 创建／epoch／终端身份。Host 固定进程对象，完整读取所有行，并确认采集前后的 Job 成员一致。类型化失败、身份缺失或 Agent 链有歧义都不代表退出。

可执行文件／入口识别和祖先链选择采用共用的纯 Agent 输入规则；Windows 命令行解析留在各自 OS 适配器中。协调器保留选中进程的 PID、创建时间及最新接纳样本的开始时间。较旧或相同时间的样本不能覆盖新观察。完整成员列表能证明此前确认的进程已离开该 Job 或 PID 已复用。退出及元数据清理作为一次所有者操作共同提交；替代进程由后续样本确认，避免两次转换只提交一半。所有者拒绝接纳时不推进缓存身份。选中身份与显式上报输入修订均未改变时，不反复推进上报修订；新暂存上报允许再次确认。保留事实缺失不生成退出。缓存受当前注册成员数量约束，随物理成员关系结束释放。

仅进程读取提供 provider 存在性，不虚构新的回退证据。[屏幕检测模型](agent-screen-model.zh-CN.md) 定义周期真实生产者；名称、持久化及 provider 执行仍需接入。Windows TUI 通过 [Panel 上报展示](../../orchbee/docs/windows-panel-report-presentation.zh-CN.md) 消费相关联的上报和元数据观察。即使上报所有者无法接纳样本，既有 CLI 诊断进程读取仍可用；它不承诺上报新鲜度。

## Windows 周期采样负责人

Windows Site 拥有一个周期采样器，在恢复终端启动之后、Client 准入之前启动；非托管 Windows Site 也启动它。每轮最多选择八个不同的已提交逻辑绑定，覆盖主／子 presentation。已知 Agent 与普通发现各自拥有按排序轮转的游标。存在已知 Agent 时，先采一个待发现终端，再采 Agent，避免空闲终端让 Agent 等待整轮扫描，也避免发现工作饥饿。有已知 Agent 时目标周期为 50 毫秒，否则为 250 毫秒，均包含采样耗时；目标之间的 100 毫秒预算限制单轮工作量，同时保证发现之后至少准入一个 Agent。预算耗尽时仍结算 Required I/O 和清理。这些私有参数约束调度工作量，不保证任意负载下的端到端延迟。成功扫描发现没有注册成员时释放过期跟踪。目标发现与准入分别校验保留的 Worker 代际及 Host 创建／epoch／终端身份。

采样器同时只拥有一个临时只读 viewer，经既有载体和 Host 校验通路执行附着、进程及一致实时屏幕采集与解除附着；不获取控制权、不输入、不聚焦 Client，也不确认显示帧。协调器共同折叠成功接纳的进程与可选屏幕事实。载体必需回执必须消费：取消会阻止新采样阶段，收完进行中的应答，再释放自有 viewer；不得丢弃必需回执，或在 Attach 结果确定前发送清理。不确定的 Detach 保留一份精确的 `PendingCleanup`，在确认 Detached 或得到 Disposed 正向证明前阻止新的 Attach；后续只对同一 viewer 重复幂等清理。关闭在 Worker 关闭前汇合此负责人；协作式期限失败会保留线程句柄及未结算所有权，供同一关闭尝试重试。生产者停止后，剩余清理由 Site 关闭流程明确接管，仅在匹配的 Worker／Host 停止且 Worker 实际退出后释放。启动回滚也会停止它。Drop 发出取消信号；线程在轮次间只保留 Site 弱引用，注册表／协调器锁内不进行 I/O。

目标缺失、容量拒绝、传输失败及无效样本都保留此前上报事实。下一轮是新的观察，不是重放变更。调度器不认证 provider、不创建规范 Agent 会话，也不持久化上报。确定性轮转选择、传输效果轨迹、生命周期／期限测试，以及不由用户主动读取进程的隔离 Windows Site 验证这些声明。

## 物理语义观察

物理 Agent 观察复用报告所有者，适用于主展示与子展示。`observe` 固定展示、Worker 代际、
Host epoch 和 Host 终端身份。当前成员关系与保留的物理证据必须在 Worker 注册表和 Site 锁内
一致；缺失证据拒绝读取，替换不能继承旧游标。结果包含有效报告视图、独立报告修订和终端
局部语义序号。名称不能证明可交互。显式上报可包含 done/error；屏幕观察不推断这些结果。

序号从零及 unknown／无 Agent 开始，仅在有效 Agent 标签或状态变化时以检查加法递增。
仅消息、水位或采样时间变化不推进序号。所有报告和进程写入者
均在提交前准备资源和历史。每个物理资源最多保留 128 条变化和 64 KiB，计入现有聚合准入。
淘汰推进明确下界。报告为空但仍有历史时保留，直到成员删除或确认物理替换。

`afterSequence` 为 null 时记录当前头部且不返回变化。位于保留下界的游标按序获得其后直至
头部的所有变化；低于下界返回 `history-limit`，未来游标返回 `invalid-request`。读取不会推进
序号，也不会把历史丢失降级为采样成功。历史状态与当前状态分离。
CLI 物理 Agent Get 是首个消费者；wait／prompt 活动门槛和 Client 注意力仍是后续消费者，
不在此边界的完成声明中。轨迹覆盖静默更新、瞬态变化、淘汰、溢出、准入回滚、代际重置和
主子隔离；共享线格式向量检查封闭形状与游标覆盖。状态为瞬态；回滚替换匹配 cohort，
无需检查点迁移。

## 精确 Presentation 读取

`read-presentations` 在与主 Panel 读取相同的只读策略和 Site 门内读取最多四个有序唯一的主项或子项 Presentation ID。`presentations-read` 保留独立 Workbench／报告修订号，以 Presentation ID 包装每个精确成员的 Panel 行。共享 Panel ID 合法；未知成员以 `not-found` 拒绝整批。未绑定成员的绑定／报告均为 null；已绑定但无报告的成员使用既有 unknown 视图。查询复用绑定所属资源，不借用主项报告。空读取校验报告修订号。既有主项读写语义不变；调用者必须关联 Presentation、Panel、绑定和 Workbench 修订号。

## 精确 Presentation 写入

`report-presentation` 指明 Panel、其中一个主项或子项 Presentation、期望绑定及已有报告内容。
Site 门内先证明 Presentation 属于该 Panel，再要求其绑定非空、与期望一致，且具备当前物理
事实。错误所属、成员缺失、未绑定及过期绑定都在报告转换前失败。流程复用绑定索引所有者、
来源序列、资源准入及物理代次生命周期；规范结构与其他成员报告保持不变。
`presentation-reported` 回传 Panel、Presentation、绑定及既有独立修订号、处理结果、变化
标志与视图。应答字节准入仍先于提交。与旧的仅主项 `report` 一样，要求导航权限。精确成员
轨迹覆盖隔离、重放、错误所属／绑定和未绑定目标。不新增持久化迁移；替换配套 cohort 发布
或回滚。
