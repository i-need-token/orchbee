# 终端 Agent 上报转换

本模型负责显式终端上报事实：来源权威、provider Session 引用、来源序号水位以及旧生命周期
上报的抑制。它与 `AgentRuntime` 中的规范 Hook 观察 Session 独立。确定性核心目前用于
一致性验证；存活注册表、物理绑定准入、公共命令和查询／TUI 发布仍是集成义务。仅凭本核心
不能让公共操作返回成功。

## 输入与归属

参考为 Herdr `e0507237ad8d41f60aece10d00ef29ce2339ca34`，同时包括公共 `AppEvent`
路由和 `TerminalState` 转换。上报者包含精确来源和规范化后的非空 Agent 标签。上报状态仅为
idle／working／blocked／unknown；元数据展示标签 `done` 不是上报状态。上报携带
显式状态／消息、可选的已校验 provider 引用、可选的完整 u64 序号和可选的已识别启动原因。
provider 引用校验与来源策略由 `orchbee-agent-observation-protocol` 提供。独立且可信的进程
观察提供检测到的 provider、回退状态、可见阻塞、退出标记及观察时间。上报字符串不能证明
进程存在。

每份上报状态属于一个终端代际。数据包括当前权威、保留的 provider 引用、来源序号水位、
被抑制的完整生命周期归属、待确认的替换引用／上报以及旧 Session 身份。核心不执行 I/O、
读取时钟、分配规范 Session，不持有名称注册表、Workbench 拓扑或持久化。调用方提供负责人
时钟刻度；进程输入单独保留原采样刻度，不能删除更新的自定义权威。即使收到的是旧进程
样本，新清除抑制仍使用当前负责人时间；回退状态、退出和元数据清理保留样本时间。状态和观察有规范
JSON 轨迹。转换准备新状态，调用方负责准入与提交。

最终注册表与终端元数据同属 Site/Workbench 锁。进程退出可能同时使权威和来源元数据失效，
这些变更必须一起准备和提交。核心输出该元数据决策需要的 Agent／时间，不修改其他负责人。
规范观察 Session 及别名仍由 `AgentState` 持有。二进制层必须在接纳上报或进程观察前提供
精确、保留的物理代际事实；Client 提供的标签、PID 或通用观察类别都不足以证明。

## 转换决策

| 输入 | 决策与结果事实 |
| ----- | ---------------------------- |
| 保留原生状态来源的状态上报 | 路由至无启动原因的 Session 引用上报；请求中的状态和消息不覆盖原生观察。 |
| 仅身份来源的状态上报 | 忽略状态权威，由公共会话上报操作持有其引用。Qwen 先走保留原生状态路由。 |
| 其他状态上报 | 先检查进程／归属／会话／抑制，再检查来源序号，之后替换权威。缺失引用清除先前的上报引用。 |
| 无有效引用的会话上报 | 不改变状态或序号。 |
| 有效引用的会话上报 | 应用精确 provider／启动来源规则；完整生命周期可能等待进程确认后再采用替换引用。后续守卫可能在消耗序号后拒绝，与参考一致。 |
| 清除权威 | 仅当前匹配来源或省略来源时有资格；由序号控制清除。仅保留的会话身份不能通过此操作清除。 |
| 释放官方来源／Agent 配对 | 公共路由无条件无操作，包括不消耗序号。 |
| 释放自定义上报 | 拒绝其他来源权威，要求匹配有效 Agent／引用并通过序号；保留独立确认的存活进程与其他来源的保留身份。 |
| 进程观察 | 存活的完整生命周期权威优先于较弱检测；拒绝早于释放抑制的观察，确认替换声明，并清理已退出代际的匹配上报。 |

来源接受带序号上报后，后续无序号上报即过期。相等或更小的序号不能前进。只有参考中确认
代际／会话重新锚定的规则能重置该水位。清除／退出抑制与旧身份阻止迟到上报复活旧会话。
待确认的生命周期上报不是有效权威。OpenCode 无序号 `select` 路径显式处理，进程缺失时需
等待确认。合法启动原因本身不是进程证明；`branch` 不具备生命周期重新锚定资格。

有效观察包含标签、状态、真实权威来源／消息和当前 provider 引用。完整生命周期权威仅在
匹配进程存活时生效，否则仍可使用检测进程／回退状态。更新的可见阻塞可覆盖非完整生命周期
上报，但不声称产生新上报来源。清除上报事实不会结束规范 `AgentRuntime` Session，也不会
伪造轮次、审批、就绪性或 provider ID。

## 提交与验证边界

`changed` 描述候选状态，与 applied／ignored／deferred 处置独立。特别是被忽略的会话上报
仍可能推进水位；调用方不能拿处置代替变更检测。在负责人接纳完整候选、元数据效果和编码
结果之前，旧状态保持不变。

核心映射描述抽象有限轨迹，不是有界网络服务。公开写入前，存活集成必须补上来源／历史／
终端数量与总字节准入、受检修订号、精确代际校验、权限和关联回执。必须闭合失败，不能丢弃
序号／旧会话历史而复活旧上报。进程采样不可用必须保持不可用，不能伪造退出或新进程证明。
与上报关联的名称变更、元数据序号清理、公共查询守卫上下文及 TUI 投影仍是必需消费方。

决策测试和序列化轨迹覆盖过期／无序号上报、来源冲突、公共原生／官方路由、仅会话身份、
清除／释放时保留进程、待确认完整生命周期引用、旧会话抑制、provider 专属替换和迟到观察。
生成的自定义来源事件序列检查输入不变、序号保留、其他来源清除隔离，以及不得虚构 provider／
进程事实；失败时输出缩减后可重放的序列。固定版本参考实现的差分序列还通过公开分派规则，
比较完整上报状态、有效视图和释放结果。这些只证明核心；声称 CLI/API 对齐前，仍需匹配
Windows 端到端上报、进程观察、查询／TUI 行为以及有界注册表准入。
