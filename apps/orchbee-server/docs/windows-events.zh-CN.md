# Windows 语义事件订阅

## 已接受行为与参考

Windows 脚本通过有所有者的事件流观察真实 Workspace、Tab、Panel、worktree、Agent 和 Client 变化，或等待指定变化。当前快照不能代替保留历史。

原生命名与载荷遵循规范 Workspace／Tab／Panel 身份，以及 Client 本地焦点和 viewport 所有权。
Panel 对应参考的 Pane；来源可明确指定子 Presentation。原生明确类型回执及结构化终端行
保持权威。本项不增加 Desktop、macOS 或 Linux 事件消费者。

## 事件所有权与顺序

一个 Site 事件日志在真实提交或观察点接收已接受语义变化。拓扑事件在同一次提交内从规范
投影的前后值推导；包括通过完整 Snapshot 发布的提交，每次中间提交都保留到日志淘汰为止。
仅修订号递增、拒绝命令和重复未变化的观察不产生变化事件。移动同一身份不会创建或关闭它。
Workspace 元数据、worktree 结算及物理 Agent 变化由既有所有者在准入后发布。
Client 焦点／布局及 viewport 观察保留 Client 身份，不声明全局焦点。

终端输出变化携带已准入 Host frame 的 generation 与内容 revision，不使用临时 viewer 的捕获
序号。终端退出要求当前准确 Host 生命周期观察证明结算；进程读取失败或 Agent 离开均不能
证明终端退出。既有周期观察器保留有界的最后观察版本，因此未观察的物理变化可能合并。
首次观察来源建立基线；此后观察到的变化进入 Site 日志。输出匹配探测独立读取已准入窗口。

Client 观察在发布前可能合并多个 UI 步骤。可选的全宽 `splitRevision` 跟踪真实 Client 分割比例
所有者，包括直接鼠标／键盘调整；省略它的旧观察不能作为比例变化证据。被拒绝或未变化的
调整不推进该值。已接受的 Client 选择／缩放／比例观察发布对应语义变化，不宣称每个 UI 转换
都曾被观察到。

日志具有新的启动 epoch、递增的全宽序号、最多 512 条记录及 8 MiB 保留字节预算。
单条事件最多 256 KiB。淘汰、超大事件或序号耗尽不能悄悄声明历史完整：读取者收到明确 gap
或 unavailable。Cursor 同时固定 epoch 与序号。错误 epoch 或未来 cursor 拒绝；被过滤的记录
仍推进扫描 cursor。不创建持久日志，也不重放运行时副作用。

## 订阅与等待生命周期

已认证 Client 连接至多拥有一个订阅，包含最多 32 个不可变过滤器。
Open 在安装所有者前捕获日志头或校验显式 cursor。同一重复 open 标识同一个所有者；
其他活动订阅拒绝。Read 与有界 wait 消费同一个保留扫描 cursor 和探测状态。
答复最多包含 32 个事件，独立于全局日志保持有界。Close 或 EOF 释放订阅、已编译匹配器和
观察状态。新连接不能接管其身份。

| 状态 | 输入        | 条件                                             | 结果及下一状态                            |
| ---- | ----------- | ------------------------------------------------ | ----------------------------------------- |
| 空闲 | Subscribe   | Read 权限、有效 Site、有界过滤器／cursor／匹配器 | 捕获基线；打开                            |
| 打开 | Subscribe   | 相同 ID 和不可变定义                             | 已存在回执；打开                          |
| 打开 | Subscribe   | ID 或定义不同                                    | Conflict；打开                            |
| 打开 | Read / Wait | 相同订阅、有效上限                               | Events、current、gap 或等待片段超时；打开 |
| 打开 | Close       | 相同订阅                                         | Closed；空闲                              |
| 任意 | EOF / 取消  | 连接所有者结束                                   | 释放自有状态                              |

Wait 先检查已准入基线，再检查截止时间。CLI wait 使用一个过滤器，在有界等待片段间保留
同一订阅；片段超时不等于整体超时。确定最终超时区别于来源不可用、历史丢失、畸形答复和
用户中断。订阅／等待不改变终端输入、导航、滚动位置或 Agent 状态。取消观察不取消其他
已接受的运行时副作用。

## 物理与 Client 探测

输出子串／正则匹配使用真实、通过内容版本准入的只读终端窗口、既有临时 viewer 回收所有者
及有界匹配行。无效正则在安装订阅前失败。匹配仅在未匹配进入匹配的边沿发出；
未变化的匹配文本不会持续刷屏。Recent／history 探测遵循请求上限。Viewport／scroll 探测
要求当前准确的 Client／来源观察，并沿用既有只读 Client control 路径，保留请求、成员关系及
内容版本关联。不会用新附着 viewer 的底部 viewport 代替所选 Client 的 viewport。

visible 表示所选 Client 的 viewport；recent-unwrapped 合并已证明的软换行；detection 读取真实实时屏幕。
原生 history 是额外的保留滚动历史来源。纯文本与 SGR 读取共用物理来源／版本准入；SGR 从
有效 cell 样式生成，不宣称是历史 PTY 输入字节的精确副本。

物理窗口捕获最多准入 65,536 行及 8 MiB 行存储／文本，超限拒绝且不发出部分匹配。
Recent-unwrapped 仅在不完整的旧前缀之后已有足量完整保留逻辑行时丢弃该前缀；
请求本身包含不完整行时拒绝，不能编造丢失的前缀。

Agent 状态探测可以发出已准入的当前初始状态，与参考一致；后续变化来自真实已准入 Agent
观察。探测记录将物理或 Client 观察来源与日志记录明确区分。单一日志 cursor 不能证明未观察的
物理输出／滚动变化；新探测建立新基线。来源丢失或临时 viewer 回收不确定时，保留明确拒绝／
unknown 所有权状态，旧所有者结算前不附着替代观察器。

物理输出捕获最多使用一个由连接持有的观察 actor。有界等待轮询其关联完成结果，避免阻塞在
Worker I/O 上。Close／EOF 取消并加入 actor；已成为 Required 的 Worker 完成先被消费再回收，
不确定的 viewer 回收仍由既有 Site 观察所有者持有。订阅结束后，只读 Client 查询回执沿用
既有 Client registry 的有界交付／结算所有权。

## 正确性与证据

确定性核心检查顺序、过滤器、cursor gap 及拓扑变化分类；运行时检查订阅所有权、真实发布者、
物理／Client 围栏、截止时间和 EOF 回收。Rust／TypeScript／JSON 共享用例证明封闭形状、全宽
身份及上限。CLI 可执行进程的 stream／wait 证据必须覆盖匹配、超时、gap、拒绝、中断以及
丢失／畸形关联。Windows 集成必须证明真实修改及终端输出能到达已打开订阅。
各项声明需要对应证据；仅协议准入不代表 R089／R090 或最终组合验收完成。

准入后的 CLI 事件失败使用封闭的 `orchbee.cli.failure.events` 文档；既有准入及 target 解析失败
保留其原有公开详情。超时不伪造 Server 回执：wait 返回实际收到的最后一个超时片段；
stream 以自己的 closed 记录结束，并明确确定关闭或释放连接的清理结果。

物理或 Client 滚动探测必须先取得首个准入基线，才能确定报告未匹配超时。此前结束的等待
片段返回 Busy，保留订阅与 actor。CLI 在整体截止时间内沿原所有者重试 Busy；截止时仍未
观察到基线则返回实际 Busy 回执，不伪造超时。
