# Agent 屏幕检测模型

Server 单独拥有屏幕回退解释，与显式 Agent 上报和进程身份分开。成功的有界终端样本可描述工作、空闲或阻塞界面；它不能证明进程属于哪个 provider、认证 provider 或创建规范 Agent 会话。参考为 Herdr `e0507237ad8d41f60aece10d00ef29ce2339ca34` 的 22 个内置检测清单和 `pane/agent_detection.rs`。Windows 周期采样器在启动前一次编译确定性引擎，发布已准入的屏幕回退。物理 explain 经有界观察队列消费同一引擎。覆盖、重载和更新仍是集成义务。

## 输入与规则归属

私有引擎分别接收已知 provider 或缺失、近期实时终端文本、OSC 标题和 OSC 进度。屏幕输入上限 64 KiB，每个 OSC 字段上限 4 KiB；超限整体拒绝，不截断为误导证据。文本已经过终端解码，不是原始转义序列。未知 provider 即使文本像另一 provider 也仍为 unknown。已知 provider 没有规则命中时回退 idle，不带可见置信标记。参考中的 Omp 和 Mastracode 没有内置屏幕清单，使用此已知 provider 回退。

内置 TOML 文件连同 Apache-2.0 许可证和来源说明保留在 `resources/agent-detection`。Server 维护者负责复查及固定版本更新。解析先拒绝未知字段、无效状态／区域、空规则标识、不支持的引擎版本、无效跳过状态组合及复杂度超限，再编译可执行规则集。每份清单最多 128 条规则、512 个 gate、深度 8 和 1,024 个匹配器；每个 gate 最多 32 个直接匹配器，每个最多 512 个 Unicode 字符。正则编译明确限制内存。已锁定的 `regex` 和 `toml` 提供标准库无法实现的语法；不引入新版本或运行时框架。

## 确定性决策

| 输入或匹配               | 结果                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 没有已知 provider        | Unknown，无可见证据                                                      |
| 多条规则命中             | 最高优先级；同优先级取声明最早者                                         |
| Contains                 | 所有字符串均命中，按 Unicode 小写比较                                    |
| Regex／line regex        | 所有模式均命中；除非表达式改变标记，否则区分大小写；逐行模式可命中不同行 |
| 嵌套 all／any／not       | 所有子项／存在时至少一个子项／没有子项命中                               |
| 已知 provider 无规则命中 | Idle，不带可见 idle 证据                                                 |
| 转录／历史查看规则       | 跳过发布、保留已有回退状态并清除待确认 idle                              |
| 可见标记与状态不符       | 派生结果中该标记为 false                                                 |

区域遵循参考的实时提示符、回复标记、提示框、首尾非空行及独立 OSC 字段。LF 和 CRLF 行边界保留正确 UTF-8 偏移，覆盖空行和未换行的末行；字节偏移不可切开 Unicode 字符。匹配完全纯净，不访问文件、进程、时钟或可变全局状态。采样所有者可保留并复用编译规则。

## 发布集成契约

Windows Host 适配器验证精确 attachment、Worker 代际及 Host 身份，并把屏幕证据关联到同一已观察 PID／创建时间身份。不可将失败／缺失帧解释为空屏，也不可从不可用数据推导 idle。既有进程退出保持优先。完整生命周期上报权威强于回退；可见阻塞仅经已有上报聚合覆盖较弱且匹配的权威。

每个自有只读 viewer 先消费初始完整帧，再仅对此 viewer 用 StoreReset 请求新快照，然后在该帧的精确修订号和代际读取底部实时屏幕高度的行。用户滚动位置不决定检测文本。前后两份完整进程样本必须选中同一 PID、创建时间和 provider。失败或过期的帧／行读取不提供屏幕证据；成功的完整进程样本仍可证明存在或退出。传输行上限 8 MiB，解码文本上限 64 KiB；保留物理换行，去除行尾空白和末尾空行。标题与进度来自同一帧；类型化进度投影当前 OSC 9;4 状态，不是原始转义历史。不确认任何 Client 显示帧。

协调器按物理进程身份保留屏幕稳定性和三秒启动宽限。仅进程观察保留屏幕计时；身份退出／替换重置计时。显式上报输入改变时，新的匹配屏幕证据可重新发布已稳定回退，不绕过 idle 确认。准备好的计时与回退只在上报／元数据准入成功后共同提交。内置规则许可证和来源说明随 Windows cohort 放入 `licenses/agent-detection`。

Working 转普通 idle 时保持状态，直到再确认三次或达到 700 毫秒；显式可见 idle／阻塞、provider 变化或退出会清除此保持。稳定可见阻塞每 800 毫秒刷新，使较新弱上报可被重新质疑，同时避免每轮发布。启动宽限期与采样节奏由适配器负责。屏幕和进程采样必须保留已有 Required 回执和不确定 viewer 清理责任。不准入 controller／输入／焦点副作用。

## 证据与交付

物理 `agent explain` 是只读操作，沿用同一检测器和临时 viewer 生命周期。在 Worker／Site
守卫下准备精确绑定及当前 Workbench／上报上下文。有效完整生命周期权威直接返回明确的
屏幕跳过解释，不读取 Host 内容。否则由生效的已知 provider，或自定义标签背后的检测
provider 选择规则。新帧／行／OSC 采集前后须有稳定的完整进程样本；发布前绑定和上报
上下文仍须一致。上下文变化直接拒绝，不重试。原始规则预测与有效、已稳定的上报状态区分。

进程观察线程最多拥有一项执行中的诊断和一项排队诊断，并沿用唯一的待清理 viewer。
CLI 取消结束调用方等待，不构成线上取消请求。Server 为每项诊断设置单一四秒排队／读取
预算；超时及 Site 关闭停止新工作，已接纳的 Required 交换仍须结算。Detach 未确认
时保留归属并阻止新附着。排队过期的工作不能附着。诊断不发送输入、不获取控制权、不改变
Client 焦点，也不发布新 Agent 状态。周期观察保持既有所有者。

Explain 暴露真实清单来源／版本，以及每条被求值规则的标识、优先级、区域、状态、匹配结果、
顶层 matcher 证据、gate 数量和区域字节数。区域预览取 240 个 Unicode 标量，超出时附加
`...`。优先级最高且最先声明的匹配规则胜出；回退和跳过原因来自同一次确定性求值。沿用
既有输入／清单／复杂度限制和 PanelAgent 512 KiB 结果上限，超限整体拒绝。规则维护仍是
待完成集成义务，不虚构更新元数据。纯规则验证、精确上下文拒绝、队列取消／清理序列及
CLI 通信／schema 检查先于最终 Windows Host／provider 验收。

规则、区域、边界、优先级及畸形清单测试先于传输集成验证引擎。固定参考用例及差分求值必须覆盖每个内置 provider、嵌套 gate、转录跳过和 OSC 优先级；静态引擎通过不代表真实 CLI／TUI 义务关闭。后续 Host 验收必须证明真实 Windows 屏幕变化与上报仲裁，且不依靠用户查询副作用。源码／cohort 回退即回滚；没有持久状态或线协议迁移。最终全量门禁继续推迟到全部对齐实现完成。
