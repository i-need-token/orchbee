# Agent 屏幕检测模型

Server 单独拥有屏幕回退解释，与显式 Agent 上报和进程身份分开。成功的有界终端样本可描述工作、空闲或阻塞界面；它不能证明进程属于哪个 provider、认证 provider 或创建规范 Agent 会话。Windows 周期采样器在启动前一次编译确定性引擎，发布已准入的屏幕回退。物理 explain 经有界观察队列消费同一引擎。启动现已加载有界本地覆盖，并在配置了更新目录源时加载合格远程缓存，保留类型化来源告警。规则清单查询和保留回执的实时重载已接入观察器所有者；显式远程更新分别保留缓存和启用事实；自动调度遵循下文策略。

## 输入与规则归属

私有引擎分别接收已知 provider 或缺失、近期实时终端文本、OSC 标题和 OSC 进度。屏幕输入上限 64 KiB，每个 OSC 字段上限 4 KiB；超限整体拒绝，不截断为误导证据。文本已经过终端解码，不是原始转义序列。未知 provider 即使文本像另一 provider 也仍为 unknown。已知 provider 没有规则命中时保持 unknown，不带可见置信标记；缺少证据不能证明空闲或完成。Omp 和 Mastracode 没有内置屏幕清单，使用此已知 provider 回退。

内置 TOML 文件连同 Apache-2.0 许可证和来源说明保留在 `resources/agent-detection`。Server 维护者负责复查及固定版本更新。解析先拒绝未知字段、无效状态／区域、空规则标识、不支持的引擎版本、无效跳过状态组合及复杂度超限，再编译可执行规则集。每份清单最多 128 条规则、512 个 gate、深度 8 和 1,024 个匹配器；每个 gate 最多 32 个直接匹配器，每个最多 512 个 Unicode 字符。正则编译明确限制内存。已锁定的 `regex` 和 `toml` 提供标准库无法实现的语法；不引入新版本或运行时框架。

内置 Devin Thinking 规则要求锚定的实时页脚，同时包含耗时与中断提示；转录中的提及或单独的 Thinking 一词不足以判断。屏幕清单拒绝 `done` 和 `error`：这些结果必须有显式状态权威，不能从文字推断。

内置 Grok 规则包含 Grok Build
`2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8` 的浏览器认证界面。锚定的批准／登录等待文案加上
认证上下文构成可见阻塞，优先于空闲或忙碌 OSC 信号。只有等待文案而缺少上下文时，
`browser_login_unconfirmed` 保持未知，不从通用标题声称就绪。登录界面被可用输入界面替换后
才可恢复空闲；进程退出保留既有优先级。`agent_screen/tests.rs` 覆盖上下文、被裁切的上下文、
独立 OSC 冲突、转录提及与就绪界面替换。这只属于物理屏幕回退，绝不创建或修改规范 Agent 会话。

## 确定性决策

| 输入或匹配               | 结果                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 没有已知 provider        | Unknown，无可见证据                                                      |
| 多条规则命中             | 最高优先级；同优先级取声明最早者                                         |
| Contains                 | 所有字符串均命中，按 Unicode 小写比较                                    |
| Regex／line regex        | 所有模式均命中；除非表达式改变标记，否则区分大小写；逐行模式可命中不同行 |
| 嵌套 all／any／not       | 所有子项／存在时至少一个子项／没有子项命中                               |
| 已知 provider 无规则命中 | Unknown，没有状态证据                                                    |
| 转录／历史查看规则       | 跳过发布、保留已有回退状态并清除待确认 idle                              |
| 可见标记与状态不符       | 派生结果中该标记为 false                                                 |

区域选择实时提示符、回复标记、提示框、首尾非空行及独立 OSC 字段。LF 和 CRLF 行边界保留正确 UTF-8 偏移，覆盖空行和未换行的末行；字节偏移不可切开 Unicode 字符。匹配完全纯净，不访问文件、进程、时钟或可变全局状态。采样所有者可保留并复用编译规则。

## 发布集成契约

Windows Host 适配器验证精确 attachment、Worker 代际及 Host 身份，并把屏幕证据关联到同一已观察 PID／创建时间身份。不可将失败／缺失帧解释为空屏，也不可从不可用数据推导 idle。既有进程退出保持优先。较新的可见阻塞可经上报聚合覆盖匹配的自定义上报。

每个自有只读 viewer 先读取进程身份，再消费初始完整帧，仅对此 viewer 用 StoreReset 请求新快照，然后在该帧的精确修订号和代际读取底部实时屏幕高度的行。同一新快照同时提供目录／投影事实与屏幕解释，无需第二次快照。用户滚动位置不决定检测文本。前后两份完整进程样本必须选中同一 PID、创建时间和 provider。失败或过期的帧／行读取不提供屏幕证据；成功的完整进程样本仍可证明存在或退出。传输行上限 8 MiB，解码文本上限 64 KiB；保留物理换行，去除行尾空白和末尾空行。标题与进度来自同一帧；类型化进度投影当前 OSC 9;4 状态，不是原始转义历史。不确认任何 Client 显示帧。

协调器按物理进程身份保留屏幕稳定性；缺少可见 working、idle 或阻塞标记的证据保留三秒启动宽限。明确可见证据跳过宽限期，使首次短任务也能在三秒内发布 Working 并回到 Idle。仅进程观察保留屏幕计时；身份退出／替换重置计时。显式上报输入改变时，新的匹配屏幕证据可重新发布已稳定回退，不绕过 idle 确认。准备好的计时与回退只在上报／元数据准入成功后共同提交。内置规则许可证和来源说明随 Windows cohort 放入 `licenses/agent-detection`。

Working 转普通 idle 时保持状态，直到再确认三次或达到 700 毫秒；显式可见 idle／阻塞、provider 变化或退出会清除此保持。稳定可见阻塞每 800 毫秒刷新，使较新弱上报可被重新质疑，同时避免每轮发布。启动宽限期与采样节奏由适配器负责。屏幕和进程采样必须保留已有 Required 回执和不确定 viewer 清理责任。不准入 controller／输入／焦点副作用。

## 证据与交付

已接受的规则维护模型由 Server 拥有一份不可变的已编译规则及其来源。Windows 启动复用共享
配置文件父目录的解析，不改写用户设置。每个内置 provider 的
`<config>/agent-detection/<report-label>.toml` 优先于
`<config>/agent-detection/remote/<report-label>.toml`，再回退内置规则。只有配置了有效的更新目录源，
并且缓存状态记录的规则来源正是该目录源时，远程缓存才参与选择；否则不读取其中的规则，本地覆盖之后直接是内置规则。
未配置目录源时，Server 从不读取 `agent-detection/remote`。只读取不超过 256 KiB
的普通 UTF-8 文件，沿用 provider、引擎版本及复杂度校验。存在的版本必须为点分数字；远程缓存还必须声明引擎版本且
不低于内置版本，尾部零段视为等价。清单标识或别名规范化后均可匹配 provider。无效覆盖／缓存产生类型化告警并回退到下一个有效来源。
没有内置规则的 provider 保留未知回退。采样器与 Explain 消费同一份已安装规则；Explain
来源信息给出实际路径、缓存版本、本地覆盖遮蔽情况及告警，不编造更新状态。规范 CLI v1 与历史物理 v2/v3 Schema 保持封闭；当前物理解释使用 v4/v5 表达六态词汇。完整维护流程已包含当前清单查询、有保留回执
的有界重载和稳定状态重置；仍需带原子缓存提交、真实来源／状态、取消／清理归属的实际更新器。

物理 `agent explain` 是只读操作，沿用同一检测器和临时 viewer 生命周期。在 Worker／会话
守卫下准备精确绑定及当前 Workbench／上报上下文。由生效的已知 provider，或自定义标签背后的检测 provider 选择规则。新帧／行／OSC 采集前后须有稳定的完整进程样本；发布前绑定和上报
上下文仍须一致。上下文变化直接拒绝，不重试。原始规则预测与有效、已稳定的上报状态区分。

进程观察线程最多拥有一项执行中的诊断和一项排队诊断，并沿用唯一的待清理 viewer。
CLI 取消结束调用方等待，不构成线上取消请求。Server 为每项诊断设置单一四秒排队／读取
预算；超时及 会话 关闭停止新工作，已接纳的 Required 交换仍须结算。Detach 未确认
时保留归属并阻止新附着。排队过期的工作不能附着。诊断不发送输入、不获取控制权、不改变
Client 焦点，也不发布新 Agent 状态。周期观察保持既有所有者。

Explain 暴露真实清单来源／版本，以及每条被求值规则的标识、优先级、区域、状态、匹配结果、
顶层 matcher 证据、gate 数量和区域字节数。区域预览取 240 个 Unicode 标量，超出时附加
`...`。优先级最高且最先声明的匹配规则胜出；回退和跳过原因来自同一次确定性求值。沿用
既有输入／清单／复杂度限制和 PanelAgent 512 KiB 结果上限，超限整体拒绝。更新元数据来自持有回执的维护所有者。纯规则验证、精确上下文拒绝、队列取消／清理序列及
CLI 通信／schema 检查先于最终 Windows Host／provider 验收。

规则、区域、边界、优先级及畸形清单测试先于传输集成验证引擎。保留的行为用例必须覆盖每个内置 provider、嵌套 gate、转录跳过和 OSC 优先级；静态引擎通过不代表真实 CLI／TUI 义务关闭。Host 验收必须证明真实 Windows 屏幕变化与上报仲裁，且不依靠用户查询副作用。源码／cohort 回退即回滚；没有持久状态迁移。交付本次状态修正前完成受影响宿主门禁和受控实时 Devin Thinking 页脚检查；更广的 provider 对齐属于独立范围。

## 已安装规则维护

Windows 进程观察器拥有已安装检测器及从 1 开始的 会话 生命周期修订号。
`workbench.agent-manifests`（OBWP 37/38）读取此快照、以操作 ID 提交重载，或查询保留的操作。
查询不重新读取文件。重载读取启动时解析的同一配置父目录，在观察器轮次之间执行；采样和 Explain
一起切换。在维护锁和 会话 提交锁下，安装清除屏幕稳定状态，保留进程身份和显式报告，
随后发布新检测器和修订号。

重载与 Update 共用一个排队／执行槽。会话 生命周期内最多保留 1,024 条回执且不淘汰；重复 ID
返回已有回执，忙碌或容量不足在接纳之前拒绝。重载由 pending 转为 applied(revision) 或 failed(reason)。
停止在安装前取消待处理操作。加载失败保留旧检测器。读取及状态查询使用读取权限，Reload／Update 使用导航管理权限。
CLI 使用一个有界预算，只提交一次；确认丢失或中断后，pending/unknown 结果保留操作 ID。
状态恢复不重新提交修改。回执随 会话 代次结束，不支持跨 Server 重启持久重放。
显式远程 Update 及其分开的缓存／启用结果见下文。自动调度遵循下文配置及归属规则。

## 远程更新归属

Orchbee 不内置默认规则目录源。只有 Server 启动时 `ORCHBEE_AGENT_DETECTION_MANIFEST_CATALOG_URL`
设为有效的 HTTP(S) 目录 URL，才会进行远程维护；该值在 会话 内冻结。未设置时，Server 只使用内置规则
和本地覆盖：不调度检查，显式 Update 以不可用拒绝，不发起网络请求，并忽略已有远程缓存，因为其来源已无法确认。
已设置但无效的值效果相同，并报告为类型化来源错误。目录和每个规则文件均限制为 256 KiB；
已知 provider 重复条目、不支持的 schema、不安全的相对路径、非法 UTF-8／provider／引擎／版本／复杂度，
均在提交可执行规则前拒绝。缓存版本不允许下降。数字版本相等时内容字节必须完全相同；
没有升版的内容变更失败。每个有效新版本原子提交，因此各 provider 的部分失败保留独立结果，
不得表示为整个更新成功。

更新器是远程缓存及其 `status.json` 的唯一写入方，该状态文件记录每次更新所用的目录源 URL。
如果本次目录源与已记录的不同，或者没有状态文件，更新器会在记录本次目录源之前删除所有内置 provider 的缓存规则，
因此已记录的目录源就是全部缓存规则的来源。删除失败时不写入任何记录。状态文件缺失或记录了其他目录源时，
视为没有缓存：规则选择和维护状态都忽略它，直到已配置目录源下一次更新。无法读取的状态文件仍报告为缓存状态错误，
并拒绝更新。

Server 拥有逻辑缓存和更新状态。Windows 文件适配器固定已准入的私有祖先目录和文件，
在共享远程缓存目录下提供跨进程写入锁，保留畸形或不安全的用户数据而不修复。
有界的命名 pending 文件归缓存所有者负责；子进程和文件消费者结束后显式清理，
后续恢复只能在同一锁下处理这些自有文件。下载器通过 Windows 系统目录定位内置 curl，
禁用其隐式配置，不使用 shell，并拥有有界 HTTP(S) 下载、输出及进程收尾。子进程环境仅包含
从操作系统系统目录父目录推导的 `SystemRoot`，用于 Winsock provider 加载。
拒绝 URL 凭据、查询串、片段、控制字符及不安全的目录相对路径。每次使用独立输出的下载尝试限时 15 秒，
最多三次，总更新预算十分钟。确认 Job 退出并 join 管道读取线程之后，才返回下载结果。
网络工作由独立且保留句柄的工作线程负责；观察器仍是唯一规则安装点。
下载／缓存完成与激活分别记录，包括取消和部分成功。

生产命令 `server update-agent-manifests` 已接入此更新器，完整缓存报告与规则启用结果分别保留。
显式与自动更新复用相同缓存、版本及清理规则。自动网络活动要求已配置目录源，且发布版／后台策略及更新设置同时允许；源码／cohort 回滚保留本地覆盖和已提交缓存版本。

## 保留回执的生产更新操作

Reload 和 Update 共用一个活动维护槽及有界 会话 生命周期回执账本。已接纳操作 ID 绑定其种类；
跨种类复用是冲突，重复同种类请求读取原回执。Update 在单独拥有的线程上执行。
观察器仅轮询已结束工作、join 线程，并在采样轮次之间安装已校验的检测器。
缓存提交与激活使用不同回执；各 provider 的部分失败保持可见，不能产生整个更新成功的退出码。
加载／激活失败不抹去已提交缓存结果。未配置目录源时禁用 Update，目录源无效时还报告类型化诊断；
终端启动与本地 Reload 仍可用。已配置目录源时，启动和 Reload 读取已持久化状态但不创建缓存路径；
普通 Current 查询读取所有者保留的快照。

Stop 关闭准入、取消网络工作，并在观察器退出前排空并 join 更新线程。
执行中的更新在真实缓存报告与子进程清理完成前保持 pending；Stop 后不得安装。
工作线程 panic 产生效果未知回执，并禁用此 会话 后续 Update 准入。
CLI Update 只提交一次，在同一预算内查询状态；晚到取消或确认丢失保留 ID，不重新提交修改。
原生 v1/v2 保持封闭；自动策略元数据使用 v3。调度及配置归属见下文。

## 自动检查与配置快照

Windows `update.manifest_check` 是严格布尔值，默认 true；只有配置了目录源时才生效。只有持久托管 会话 的发布版、非测试
构建允许后台检查。独立端点、调试和测试运行不调度网络任务。启用后启动时检查一次，再按单调时间
每三十分钟检查。维护槽忙时延后到空闲。自动任务复用显式 Update 的下载器、缓存、启用和 Stop
生命周期，拥有独立身份并只保留最近结果，不消耗或淘汰手动操作回执。

Client 激活只传递已校验的配置路径和是否显式指定。Server 在启动时读取该文件一次；检查值及来源
来自这次读取，观察器从不重读配置。只有已提交的配置发布（`server reload-config`）会改变规则检查开关。
显式规则 Reload 从不读取 `config.toml`：它从启动配置父目录加载检测器及状态，安装失败保留旧检测器。
关闭清除下次检查；重新开启立即调度。这是规则维护重载，不是通用设置或键位重载。
活动 Update 持有维护槽直至收尾。Current 元数据暴露检查值、来源、后台／构建门控、实际启用状态
及最近自动操作；原生 v3 保留封闭的 v1/v2。自动任务 panic 会停用此 会话 后续更新；已知失败保留
下一次间隔。Stop 取消并 join 同一工作线程后观察器才返回。源码／cohort 回滚保留用户配置和缓存；
旧版严格设置读取器要求先移除本次新增的 update 配置节。

自动启用遵循缓存重载条件：provider 有新提交，或成功检查的当前缓存版本与已加载缓存版本不同，才需要启用。无变化的当前检查记录 NotAttempted，保留检测器修订和稳定状态。显式 Update 保持其请求启用的行为。
