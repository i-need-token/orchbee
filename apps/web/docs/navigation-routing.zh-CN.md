# 导航路由

## 适用范围

`@orchbee/web` 拥有路由树以及浏览器历史记录与一个客户端的工作台 Client View 之间的同步。可重用的工作台包保持与路由器无关。桌面、浏览器和未来的 shared-Web 部署在不同源下使用相同的路径。

| Runtime          | Origin 示例                 | Route owner     |
| --------------- | ------------------------ | -------------- |
| 浏览器开发      | `http://127.0.0.1:3000`  | `@orchbee/web` |
| 已包装 Electron | `orchbee://app`          | `@orchbee/web` |
| Shared Web，预留  | `https://192.0.2.1:8443` | `@orchbee/web` |

LAN 服务、令牌交换、Cookie 身份验证、设置屏幕、登录屏幕以及外部深层链接的操作系统交付不在本合同范围内。在成为当前行为之前，他们必须通过单独接受的更改来扩展路由树。

## 路由树

| 路径                                                       | 分辨率                                               |
| ---------------------------------------------------------- | ---------------------------------------------------- |
| `/`                                                        | 来自协调后的 Client View 的当前规范路由              |
| `/terminal`                                                | 第一个独立选项卡，或空的独立终端上下文               |
| `/terminal/tabs`                                           | 第一个独立选项卡，或 `/terminal`（如果不存在）       |
| `/terminal/tabs/$tabId`                                    | `$tabId` 处于活动状态的独立终端上下文                |
| `/projects`                                                | 第一个带有工作区的项目，然后是该工作区的第一个选项卡 |
| `/projects/$projectId`                                     | 项目的第一个工作区，然后是该工作区的第一个选项卡     |
| `/projects/$projectId/workspaces`                          | 项目的第一个工作区，然后是该工作区的第一个选项卡     |
| `/projects/$projectId/workspaces/$workspaceId`             | 工作区的第一个选项卡，或空的工作区终端上下文         |
| `/projects/$projectId/workspaces/$workspaceId/tabs`        | 工作区的第一个选项卡或其空工作区路由                 |
| `/projects/$projectId/workspaces/$workspaceId/tabs/$tabId` | 已命名的项目和工作区，且 `$tabId` 处于活动状态       |

不完整的路由是导航意图，而不是第二显示状态。解析遵循权威的项目、工作区和 Tab 顺序，然后用最深的可用规范路径替换当前历史记录条目。 `/projects` 使用当前有工作区的第一个项目；当不存在此类项目时，它将通过独立终端上下文进行解析。在单独接受项目拥有的屏幕或空状态合同之前，没有工作空间的现有项目将保持不可用。

省略标识符与命名未知标识符不同。结构不完整的路由选择其第一个可用的后代。包含未知 `$projectId`、`$workspaceId` 或 `$tabId` 的路由显示不可用状态，并且永远不会落入其他实体。

路由参数携带稳定的模型标识符，而不是可变的显示名称。路由生成将每个标识符百分比编码为一个路径段，路由解析将其解码一次。查询参数和片段永远不会选择项目、工作区或选项卡。

`/settings` 与 `/login` 不是当前路由。添加任一路径都需要其所属屏幕、本地化副本、可用性行为以及同一授权更改中的验证。

## 状态模型

该路由对于显示的位置和活动选项卡具有权威性。工作台 Client View 对于非路由本地状态（例如扩展项目、多选选项卡、面板焦点、分割权重和最大化）仍然具有权威性。共享的工作台文档对于项目、工作区、选项卡、面板和终端成员资格仍然具有权威性，并且永远不会仅仅通过历史导航而发生改变。

| 输入                         | 过渡                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 初始`/`                      | 替换为源自协调后的 Client View 的规范路由                |
| 初始结构不完整的路由         | 依序解析第一个可用的后代，并替换为其最深的规范路由             |
| 初始有效规范路由             | 在显示工作台之前将其位置和活动选项卡应用到 Client View   |
| 命名缺失实体的初始路由       | 在不改变Client View的情况下显示本地路由不可用状态        |
| 应用内位置或 active-Tab 导航 | 推送目标路由；然后路由协调应用目标 Client View           |
| 浏览器后退或前进             | 将观察到的路由应用到 Client View，而不创建另一个历史条目 |
| 显示后当前实体被移除         | 替换为源自协调后的 Client View 的规范路由                |
| 非导航（non-navigation）Client View 更改        | 保留当前路由与历史记录条目                                   |

协调器通过可重入防护序列化观察。应用路由时，会在同步改变 Client View 之前记录其目标，并且生成的 Client View 通知确认该目标而不是产生第二个导航。后来的 Client View 通知不再解析显示的路由，这是域协调，并且替换而不是推送规范后备。

### 空终端上下文首次打开

- **问题和范围：** 在一次应用 composition 中，每个不同的独立或 Workspace 终端上下文首次
  ready 访问时都可能没有 Tab。路由协调器会按权威终端上下文 identity 分别做一次创建决策，
  因此也覆盖已经显示过其他上下文后才首次打开的 Workspace。空状态渲染、普通新建 Tab 命令、
  持久化重启意图与原生窗口（native-window）Tab 分配继续由现有 owner 负责。
- **状态和转换：** `TerminalContextInitializationState` 是已完成首次 ready 访问判定的上下文
  identity 可序列化集合。重定向和不可用路由不增加 identity。已在集合中的 ready 终端路由
  刻意无操作。首次 ready 路由会加入其 identity，并且只在完整权威上下文没有 Tab 时发出
  `create-terminal`；已有 Tab 的上下文只加入集合而不发命令。
- **提交和失败：** 协调器先应用 ready 路由，使 Workspace identity 与默认 CWD 成为权威，再
  通过现有 runtime 创建路径，以当前本地化终端标题和 `programmatic` source 执行。创建成功后
  重新解析同一请求，使新 Tab 在渲染前成为规范路由。创建被拒绝时保留该空白规范路由，且同一
  协调器生命周期内不为该上下文重试；其他上下文仍可独立触发首次判定。
- **并发和边界：** 决策读取完整的活动终端上下文，而不是页面本地渲染状态，因此 presentation
  state 不能触发创建。每个独立组合页面拥有自己的已判定 identity 状态，可能与
  其他页面竞争；现有 revisioned shared-document coordinator 仍是唯一提交权威，并在不增加
  startup flag、schema field、storage key 或 protocol message 的前提下收敛竞争 proposal。
- **验证：** 纯转换测试覆盖重定向、不可用与 ready 路由、多个上下文 identity、空与非空上下文、
  重复和重新进入。协调器测试覆盖 standalone 与多个 Workspace 创建、当前本地化标题输入、规范
  重解析、逐上下文失败、无效路由，以及关闭已判定上下文的最后一个 Tab 后不补建。现有多客户端
  coordinator 证据覆盖 proposal 仲裁；不选择新 TLA+ 模型，因为本地转换是同步的，没有独立排序的
  completion。

## 渲染器重载焦点恢复

- **问题和输入：** Electron 渲染器重载会替换其内存 Client View，而原生窗口、规范共享文档和 Terminal Host 会话仍然存活。若没有客户端本地交接，活动 Tab 会回退到第一个 Panel，后续键盘输入可能进入另一个终端。可信输入是已协调的共享文档与 Client View；可选的 `sessionStorage` 值不可信，并在 Web 组合边界进行严格解析。输入缺失、格式错误、不可用或陈旧时，不提供恢复提示。
- **数据和所有权：** Desktop Web 组合拥有一个版本 1 的 `orchbee:web:terminal-focus-recovery:v1` 记录，其中仅包含一个有界的 `TerminalPresentationId`。Workbench 仍是 Client View 与逻辑焦点的唯一写入者，路由仍对位置与活动 Tab 具有权威性，Terminal Host 仍对进程与终端具有权威性。该记录随 Electron 页面会话生命周期处置，既不是共享状态，也不是持久应用状态。
- **输出和模型：** 确定性投影器从默认 Client View 开始；当精确 Presentation 仍可解析时，只改变该 Tab 的焦点 Panel 与显示的子 Presentation。它绝不选择位置或 Tab。Workbench 既有的 `autoFocus` 投影仅在恢复后的终端渲染器就绪后移动真实 DOM 焦点。目标缺失是保留默认 Client View 的有意无操作。
- **转换：** 每次已提交的共享文档或 Client View 通知都会解析其唯一显示终端并替换会话记录；没有显示终端的视图会移除该记录。渲染器 bootstrap 只读取一次，并在路由协调前把投影候选交给 Workbench。存储读取、写入、移除、校验或配额失败绝不阻塞启动，也不会改变当前内存焦点。
- **不变量和排除项：** 每个浏览上下文最多存储一个有界 Presentation 标识。独立页面不能共享该提示。恢复不能创建标识、复活已移除的 Presentation、改变共享状态、发送终端输入，或恢复最大化、Split 权重、选择、滚动、搜索、输出及任何其他 Client View 或视口事实。完整 Client View 恢复以及跨原生窗口或应用重启的恢复均不在范围内。
- **验证：** 确定性测试覆盖主终端和子终端目标、陈旧标识、严格解析、缺失、存储失败、移除与投影隔离。Desktop 系统轨迹会聚焦一个非首位分屏终端、重载渲染器，并通过自然恢复的 DOM 焦点把输入发送到同一 Presentation。由于该记录只有一个同步写入者，没有异步完成、排序或取消状态，因此不选择 TLA+。

## 分辨率不变量

- 规范 Tab 路由正好解析为一个终端上下文和一个活动 Tab。
- 空上下文规范路由仅解析为一个终端上下文并且没有活动选项卡。
- 仅当项目拥有工作区并且该工作区拥有包含选项卡的终端上下文时，工作区路由才有效。
- 仅当独立终端上下文包含 Tab 时，独立路由才有效。
- 部分路由解析使用文档顺序，并且从不依赖于可变的显示名称、区域设置、对象枚举或异步到达顺序。
- 两次应用当前路由是幂等的。
- 每个路由协调器生命周期内，每个终端上下文 identity 最多尝试一次首次打开空上下文创建；完成
  判定后关闭其最后一个 Tab 绝不会触发另一次尝试。
- 推送的应用内导航会创建一个历史记录条目；规范化和域协调替换当前条目。
- 后退和前进从不附加历史记录，也从不发布共享文档命令。
- 直接不可用的路由永远不会默默地打开不同的项目、工作区或选项卡。
- 运行时检测可能会选择传输适配器，但它永远不会改变路由语义。

## 运行时检测

打包的 `orchbee:` 源和 Electron 用户代理令牌选择桌面适配器。用户代理检查只是用于环回开发的适配器发现；它不是授权边界。桌面功能仍然只能通过经过验证的沙盒引导端口来实现。现有的显式网关开发标记仍然仅限于本地网关开发路径，直到 shared-Web 服务和身份验证取代它。

## 所有权边界

| Owner                 | 责任                                                     |
| -------------------- | -------------------------------------------------------- |
| `@orchbee/web`       | 路由声明、历史记录、路由解析、不可用状态和工作台导航端口 |
| `@orchbee/workbench` | 与路由器无关的导航意图端口和 Client View 转换            |
| `@orchbee/tab-strip` | 与路由器无关的选项卡选择意图端口和多选语义               |
| `@orchbee/desktop`   | `orchbee://app` 资源交付和初始渲染器 URL                 |

没有可重用包导入 TanStack 路由器、读取 `window.location`、检查用户代理或构造应用程序 URL。

## 正确性证据

确定性测试涵盖路由编码、有效和不可用的解析、根规范化、逐上下文首次打开空上下文转换、route-to-Client-View 应用、Client View 回退、推送与替换历史意图和重入防护。集成测试涵盖首次终端创建、关闭后保持空白、针对同一 Workbench 运行时的应用内导航和后退/前进。Desktop 测试涵盖 scheme 注册顺序、origin 和 method 校验、path containment 检查、asset delivery 以及导航回退到 `index.html`。

打包命令在 Desktop 之前构建 Web 渲染器，将渲染器打包为只读资源，并将可执行文件 Terminal Host 放置在 `app.asar` 之外。发布验证必须针对 `orchbee://app` 启动解压的应用程序，并在自定义源无法加载嵌套规范路由时拒绝候选者。恢复版本会恢复以前的渲染器条目，而无需迁移共享文档，因为路由仅更改 Client View。
