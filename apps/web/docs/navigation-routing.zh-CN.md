# 导航路由

## 适用范围

`@orchbee/web` 拥有路由树以及浏览器历史记录与一个客户端的工作台 Client View 之间的同步。可重用的工作台包保持与路由器无关。桌面、浏览器和未来的 shared-Web 部署在不同源下使用相同的路径。

| 运行时          | 起源示例                 | 路线拥有者     |
| --------------- | ------------------------ | -------------- |
| 浏览器开发      | `http://127.0.0.1:3000`  | `@orchbee/web` |
| 已包装 Electron | `orchbee://app`          | `@orchbee/web` |
| 共享网络，保留  | `https://192.0.2.1:8443` | `@orchbee/web` |

LAN 服务、令牌交换、Cookie 身份验证、设置屏幕、登录屏幕以及外部深层链接的操作系统交付不在本合同范围内。在成为当前行为之前，他们必须通过单独接受的更改来扩展路由树。

## 路由树

| 路径                                                       | 分辨率                                               |
| ---------------------------------------------------------- | ---------------------------------------------------- |
| `/`                                                        | 来自协调后的 Client View 的当前规范路线              |
| `/terminal`                                                | 第一个独立选项卡，或空的独立终端上下文               |
| `/terminal/tabs`                                           | 第一个独立选项卡，或 `/terminal`（如果不存在）       |
| `/terminal/tabs/$tabId`                                    | `$tabId` 处于活动状态的独立终端上下文                |
| `/projects`                                                | 第一个带有工作区的项目，然后是该工作区的第一个选项卡 |
| `/projects/$projectId`                                     | 项目的第一个工作区，然后是该工作区的第一个选项卡     |
| `/projects/$projectId/workspaces`                          | 项目的第一个工作区，然后是该工作区的第一个选项卡     |
| `/projects/$projectId/workspaces/$workspaceId`             | 工作区的第一个选项卡，或空的工作区终端上下文         |
| `/projects/$projectId/workspaces/$workspaceId/tabs`        | 工作区的第一个选项卡或其空工作区路由                 |
| `/projects/$projectId/workspaces/$workspaceId/tabs/$tabId` | 已命名的项目和工作区，且 `$tabId` 处于活动状态       |

不完整的路线是导航意图，而不是第二显示状态。解析遵循权威的项目、工作区和 Tab 顺序，然后用最深的可用规范路径替换当前历史记录条目。 `/projects` 使用当前有工作区的第一个项目；当不存在此类项目时，它将通过独立终端上下文进行解析。在单独接受项目拥有的屏幕或空状态合同之前，没有工作空间的现有项目将保持不可用。

省略标识符与命名未知标识符不同。结构不完整的路线选择其第一个可用的后代。包含未知 `$projectId`、`$workspaceId` 或 `$tabId` 的路由显示不可用状态，并且永远不会落入其他实体。

路由参数携带稳定的模型标识符，而不是可变的显示名称。路由生成将每个标识符百分比编码为一个路径段，路由解析将其解码一次。查询参数和片段永远不会选择项目、工作区或选项卡。

`/settings` 和 `/login` 不是当前航线。添加任一路径都需要其所属屏幕、本地化副本、可用性行为以及同一授权更改中的验证。

## 状态模型

该路线对于显示的位置和活动选项卡具有权威性。工作台 Client View 对于非路由本地状态（例如扩展项目、多选选项卡、面板焦点、分割权重和最大化）仍然具有权威性。共享的工作台文档对于项目、工作区、选项卡、面板和终端成员资格仍然具有权威性，并且永远不会仅仅通过历史导航而发生改变。

| 输入                         | 过渡                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 初始`/`                      | 替换为源自协调后的 Client View 的规范路由                |
| 初始结构不完整的路线         | 解决命令第一个后代并替换为他们最深的规范路线             |
| 初始有效规范路由             | 在显示工作台之前将其位置和活动选项卡应用到 Client View   |
| 命名缺失实体的初始路由       | 在不改变Client View的情况下显示本地路由不可用状态        |
| 应用内位置或 active-Tab 导航 | 推送目标路线；然后路由协调应用目标 Client View           |
| 浏览器后退或前进             | 将观察到的路由应用到 Client View，而不创建另一个历史条目 |
| 显示后当前实体被移除         | 替换为源自协调后的 Client View 的规范路由                |
| 非航海 Client View 改        | 保留当前路线和历史条目                                   |

协调器通过可重入防护序列化观察。路线应用程序在同步改变 Client View 之前记录其目标，并且生成的 Client View 通知确认该目标而不是产生第二个导航。后来的 Client View 通知不再解析显示的路由，这是域协调，并且替换而不是推送规范后备。

## 分辨率不变量

- 规范 Tab 路由正好解析为一个终端上下文和一个活动 Tab。
- 空上下文规范路由仅解析为一个终端上下文并且没有活动选项卡。
- 仅当项目拥有工作区并且该工作区拥有包含选项卡的终端上下文时，工作区路由才有效。
- 仅当独立终端上下文包含 Tab 时，独立路由才有效。
- 部分路由解析使用文档顺序，并且从不依赖于可变的显示名称、区域设置、对象枚举或异步到达顺序。
- 两次应用当前路由是幂等的。
- 推送的应用内导航会创建一个历史记录条目；规范化和域协调替换当前条目。
- 后退和前进从不附加历史记录，也从不发布共享文档命令。
- 直接不可用的路由永远不会默默地打开不同的项目、工作区或选项卡。
- 运行时检测可能会选择传输适配器，但它永远不会改变路由语义。

## 运行时检测

打包的 `orchbee:` 源和 Electron 用户代理令牌选择桌面适配器。用户代理检查只是用于环回开发的适配器发现；它不是授权边界。桌面功能仍然只能通过经过验证的沙盒引导端口来实现。现有的显式网关开发标记仍然仅限于本地网关开发路径，直到 shared-Web 服务和身份验证取代它。

## 所有权边界

| 业主                 | 责任                                                     |
| -------------------- | -------------------------------------------------------- |
| `@orchbee/web`       | 路线声明、历史记录、路线解析、不可用状态和工作台导航端口 |
| `@orchbee/workbench` | 与路由器无关的导航意图端口和 Client View 转换            |
| `@orchbee/tab-strip` | 与路由器无关的选项卡选择意图端口和多选语义               |
| `@orchbee/desktop`   | `orchbee://app` 资源交付和初始渲染器 URL                 |

没有可重用包导入 TanStack 路由器、读取 `window.location`、检查用户代理或构造应用程序 URL。

## 正确性证据

确定性测试涵盖路由编码、有效和不可用的分辨率、根规范化、route-to-Client-View 应用程序、Client-View 回退、推送与替换历史意图和重入防护。集成测试涵盖针对同一工作台运行时的应用内导航和后退/前进。桌面测试涵盖方案注册顺序、来源和方法验证、路径包含检查、资产交付以及导航回退到 `index.html`。

打包命令在 Desktop 之前构建 Web 渲染器，将渲染器打包为只读资源，并将可执行文件 Terminal Host 放置在 `app.asar` 之外。发布验证必须针对 `orchbee://app` 启动解压的应用程序，并在自定义源无法加载嵌套规范路由时拒绝候选者。恢复版本会恢复以前的渲染器条目，而无需迁移共享文档，因为路由仅更改 Client View。
