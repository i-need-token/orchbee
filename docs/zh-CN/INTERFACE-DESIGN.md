# 跨端界面设计

## 权威性和范围

本标准拥有 Orchbee GUI 与 TUI Client 的共同体验契约：共享含义、可辨识的呈现，以及可预测的
跨端操作迁移方式。产品能力默认同时面向两端设计。仅适用于某端的能力或分阶段交付，必须在
所属功能参考和当前任务中明确原因与范围。

先应用本标准，再应用 [`frontend/`](frontend/visual-foundations.md) 和
[`tui/`](tui/visual-foundations.md) 的适配规则。后者拥有渲染、几何、事件解码和宿主惯例，
可以适配表现形式，但不能改变共同的产品含义。具体界面、绑定、设置和支持的能力仍归语义所有者。
本契约不宣称现有 Client 已共享全部实现或能力。CLI 语法和输出仍由
[`cli/command-surface.md`](cli/command-surface.md) 和 [`cli/output.md`](cli/output.md) 约束。

## 职责边界

| 职责                                         | 权威所有者                                                                 | 适配端职责                                               |
| -------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 实体身份、关系、生命周期和持久状态           | 所属领域能力及其公共契约                                                   | 投影权威状态；不得从标签、颜色或行位置推断身份与生命周期 |
| 操作含义、目标、资格、校验和结果             | 拥有语义结果的功能                                                         | 通过受支持边界调用操作并展示结果                         |
| 产品术语、信息优先级、动作分组和默认助记键   | 跨工作区术语由[术语表](GLOSSARY.md) 管理，其余由所属功能的共同体验契约管理 | 使用各端交互词汇本地化并呈现相同含义                     |
| 焦点、悬停、导航高亮、打开的覆盖层和滚动位置 | 最窄的 Client 交互所有者                                                   | 保持端内状态，除非既有契约明确赋予该值共享作用域         |
| 主题值、排版、几何、字形和输入解码           | 各主题与 Client 适配所有者                                                 | 在平台及宿主能力内实现共同角色                           |

共享数据不意味着所有视图状态都共享。区分领域的当前对象、Client 展示的上下文、键盘焦点与
临时选择。共享偏好或视图状态前先声明持久化方式和作用域；一个 Client 移动焦点不得静默移动
另一个 Client 的焦点。渲染适配与主题变化本身不修改领域状态；编辑某个已有归属布局的操作，
仍通过该布局的语义所有者执行。

按照 [`ARCHITECTURE.md`](ARCHITECTURE.md) 复用既有领域和协议所有者。不得在渲染器内创建第二条
业务写入路径、通用 UI Store，或仅为了把两端名称放进同一模块而新增包。跨语言一致性使用所属
序列化契约和有意义的共同示例，不要求共享 React 与 Rust 组件。

## 共同功能契约

实现任一端暴露的能力前，检查另一端，并在既有所属参考、类型或测试中记录以下决策。任务顺序
保留在当前任务中；不要另建逐任务规范或重复的功能目录。

| 决策       | 必须一致的内容                                                                       |
| ---------- | ------------------------------------------------------------------------------------ |
| 意图和目标 | 稳定的语义操作、实体身份、作用域与权威所有者                                         |
| 状态       | 适用时的可用、不可用、处理中、完成、失败、取消和结果未知；区分能力不支持与状态不可用 |
| 信息       | 共同术语、对象层级、任务必需字段、排序含义，以及主要与辅助信息                       |
| 入口和完成 | 可发现入口、默认助记键、目标选择、提交边界、取消和返回位置                           |
| 呈现       | 语义角色、可复用交互模式和 GUI/TUI 映射                                              |
| 差异       | 宿主约束或已接受的产品原因、受支持替代路径、必要的用户可见解释和证据                 |

在权威状态、能力和用户选择等价时，两端必须识别同一目标、应用相同领域规则并解释同一结果。
局部投影可以过滤、分组或延后展示信息，但必须暴露其范围，并保留完成任务所需信息的访问路径。
数据缺失、加载中、连接断开和结果为空是不同状态。

各呈现端使用稳定动作身份。若既有运行时使用不同的本地标识符，在功能契约中保留明确对应关系；
不得从翻译标签推断对应关系。
GUI 调用遵循 [`frontend/actions.md`](frontend/actions.md)，原生 TUI 调用遵循
[`tui/actions.md`](tui/actions.md)。两者投射既有语义所有者，不在呈现者中创建第二套操作或结果模型。

## 快捷键迁移规则

功能所有者共同拥有动作的助记键、语义作用域以及 GUI 和 TUI 默认绑定，必须一起选择。
宿主输入允许时，同一动作保留相同助记键；通过平台修饰键、前缀或具名模式适配调用机制。

例如，搜索动作可以从 GUI `Mod+f` 映射到 TUI `<prefix> f`：GUI 格式化器把 `Mod` 显示为
`Ctrl` 或 `⌘`，`<prefix>` 对应已配置的 TUI 前缀。若前缀为 `Ctrl+b`，TUI 序列就是先按
`Ctrl+b`，再按 `f`。此例说明转换规则，不指定产品默认绑定。前缀是输入层，不是动作助记键。

- 先匹配动作身份以及搜索或操作范围，再匹配字母。同一字母不得暗示无关动作等价，也不得混淆
  局部搜索和全局搜索。
- 增加相关动作时保留同族助记键和限定关系。分配新默认绑定前，检查两端的活动作用域与冲突。
- 不要把每个 GUI 组合键机械转换成前缀序列。编辑键、终端透传、输入法组合、宿主保留键及
  模态归属仍遵守各端契约。助记键不能成为抢占普通终端输入的理由。
- 当冲突或宿主限制阻止使用共同助记键时，优先采用仍可被发现的既有作用域或限定方式。否则在
  所属绑定中记录原因与替代键；不得让两端各自静默选择无关按键。
- 绑定和用户覆盖引用语义动作及其作用域。默认值变化时保留有效的用户显式覆盖。如果设置支持
  跨端迁移，必须校验目标映射，并报告冲突或不受支持的绑定；不得静默改映射或丢弃。
- 帮助、菜单、Tooltip 和命令结果通过各端格式化器展示生效绑定，包括用户覆盖。展示另一端
  绑定时从所属绑定数据派生；不得另行手写一份快捷键对照表，也不得把不支持的动作展示为可用。

[`frontend/keyboard-shortcuts.md`](frontend/keyboard-shortcuts.md) 拥有 GUI 归一化、`Mod`、
作用域解析和显示规则。[`tui/keyboard-input.md`](tui/keyboard-input.md) 拥有前缀与模式路由、
终端保护和 TUI 显示规则。共同助记规则不把 GUI 物理键码等同于终端字节，也不要求相同事件解码器。

## 视觉角色与主题

先按含义选择呈现，再选择端内 Token。既有适配词汇与共同角色的映射如下；此映射不要求 Token
同名，也不要求新增 alias。

| 共同含义                       | GUI 映射                                                                                                                       | TUI 映射                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 主要与辅助信息                 | `--ob-sys-color-text-primary`、`--ob-sys-color-text-secondary`                                                                 | `text-primary`、`text-secondary`                                  |
| 键盘焦点                       | `--ob-sys-color-border-focus` 及控件焦点几何                                                                                   | `frame-focused` 或 `accent-focus`                                 |
| 主要动作                       | `--ob-sys-color-action-primary` 及其控件变体                                                                                   | 动作控件上的 `accent-action`                                      |
| 指针 hover                     | `--ob-sys-color-surface-hovered` 或控件声明的 hover 变体                                                                       | 有效命中目标上的 `surface-hover`                                  |
| 指针按下                       | 前端基础下控件声明的按下反馈                                                                                                   | `surface-pressed`，配合独立焦点和身份提示                         |
| 持久当前上下文                 | 导航中的中性 `--ob-sys-color-surface-selected`                                                                                 | 中性 `surface-current`                                            |
| 临时选择                       | 控件拥有的选择表面与指示器                                                                                                     | `surface-selection` 与 `accent-selection`                         |
| 已勾选值                       | 控件声明的值模型中的勾选指示器，独立于导航光标                                                                                 | 使用 `accent-selection` 的稳定已选字形                            |
| 成功、警告、错误与信息         | `--ob-sys-color-status-success`、`--ob-sys-color-status-warning`、`--ob-sys-color-status-danger`、`--ob-sys-color-status-info` | `status-success`、`status-warning`、`status-error`、`status-info` |
| 处理中                         | 忙碌指示器和本地化操作文本                                                                                                     | `status-pending` 指示器和本地化操作文本                           |
| 画布、持久 chrome 和临时覆盖层 | 按表面需要使用 `--ob-sys-color-surface-canvas`、`--ob-sys-color-surface-raised`、`--ob-sys-color-surface-overlay`              | `surface-canvas`、`surface-chrome`、`surface-overlay`             |

焦点、hover、按下、当前上下文、临时选择、已选值、可用性与操作状态是独立事实。在所属表面
定义它们同时出现时的样式；移动焦点不能抹去当前上下文，hover 绝不提交值或改变焦点。
勾选状态属于控件声明的编辑边界，可以投射父级草稿或权威值；该指示器本身不能证明已经持久化。
主要动作和焦点使用动作或焦点角色，不得仅为强调而使用成功角色。
处理中和未知结果不得看起来像成功。颜色必须配合有意义的文字、形状、字形或强调，使区别在
颜色能力降低或修饰符不可用时仍可辨识。

一起选择对应的 GUI/TUI 产品调色板，包括产品控制的默认值，并由主题所有者声明预期对应关系。
名称不同本身不能成为外观无关的理由。对于对应主题对，包括同名产品主题，必须为其调色板和
共同角色含义声明唯一权威来源。在同一变更中从该来源
派生端内映射，或显式对照验证；分别维护、未经一致性检查的颜色副本不构成共同主题。等价角色
保留可辨识的色系和对比层级。透明度、合成、色彩空间转换和终端量化属于须有渲染证据的适配决策，
不能成为选择无关调色板的理由。显式验证对应关系，不从名称推断。

CSS 注册表仍是 [`frontend/design-tokens.md`](frontend/design-tokens.md) 下的 GUI 实现权威。
原生主题边界仍是 [`tui/visual-foundations.md`](tui/visual-foundations.md) 下的单元格网格权威。
跟随宿主的 `terminal-native`、用户覆盖、未知外观和低颜色能力保持已准入行为；通过非颜色提示
保留可辨识含义，不承诺精确 RGB 一致。程序自己绘制的终端内容不属于 Orchbee chrome 样式范围。

## 排版、密度和布局

- 保留信息优先级：对象身份和任务必需状态优先于辅助元数据与可选提示。GUI 字体角色与 TUI
  强调表达同一层级，不把像素直接转换成单元格，也不要求相同数量的字号层级。
- 保留对象关系、导航含义、动作分组和阅读顺序。GUI 侧栏可以在狭窄 TUI 中变为覆盖层；用户
  仍通过可发现入口到达同一组对象与操作。
- 相关项比无关组更接近。GUI 间距、控件尺寸、圆角和触摸目标遵守前端基础；整数单元格间距、
  框架和尺寸层级遵守 TUI 基础。任一端都不照抄另一端的尺寸。
- 优先减少可选装饰和元数据，再处理任务必需上下文。不得仅为模仿另一端密度而丢弃动作、隐藏
  当前目标、缩小文字或遮蔽取消操作。使用各端已记录的溢出、滚动或空间不足行为。
- 标签截断时保留完整数据的访问方式。在两端验证翻译标签、宽字符、狭窄布局和焦点可见性；
  截图完全相同不是判断依据。

## 可复用交互模式

| 模式         | 共同行为                                                                         | 允许的适配                                                         |
| ------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 导航和资源行 | 相同身份、层级、当前上下文含义，以及高亮与激活的区别                             | GUI 树或列表；TUI 行或导航器；指针和键盘入口                       |
| 菜单和命令   | 相同动作名称、目标范围、共同分组的相对顺序、不可用原因和破坏性含义               | GUI 菜单或命令界面；TUI 菜单或前缀帮助；端特有动作保留在相关分组中 |
| 搜索和过滤   | 相同搜索范围、查询含义、默认选项、结果身份、上一项/下一项顺序，以及清空/关闭效果 | GUI 字段或面板；TUI 编辑器或覆盖层；可见结果数量可以不同           |
| 编辑和选择器 | 相同字段含义、默认值、校验、草稿/提交边界和取消结果                              | 按任务与宿主选择行内控件、Dialog 或捕获覆盖层                      |
| 直接操作     | 相同操作、目标、约束、提交结果和提交前取消                                       | GUI 指针手势与键盘替代路径；具有相同效果的 TUI 命令或模式          |
| 确认         | 相同效果、影响范围、后果和安全取消                                               | GUI 操作控件或精确 TUI 确认键；几何不足绝不视为同意                |
| 异步反馈     | 相同处理中、成功、失败、取消、未知含义和恢复动作                                 | 行内状态、通知或状态行；后台工作不抢焦点                           |
| 设置         | 同一作用域内相同的语义设置身份、单位、领域默认值、校验、应用时机和重置含义       | GUI 控件或原生配置；纯呈现设置可以保留在 Client 本地               |

每种语言内的产品术语保持稳定。TUI 短标签是同一术语的已记录变体，不得给实体或操作重新命名。
本地化文案使用既有目录所有者，并须区分关闭视图与终止其底层工作等不同含义。

关闭界面、取消草稿和取消运行中工作是不同操作。关闭表面不意味着停止其工作。临时任务结束后
把焦点返回先前有效位置；若位置已不存在，则应用各端的回退规则。Escape、Enter、指针和终端
输入遵守当前输入所有者，不采用跨端全局拦截规则。

共享设置的含义不意味着该设置已经同步。其既有存储和配置所有者声明作用域、持久化、传播及
冲突规则。不得静默宣称 Client 本地设置是全局设置，也不得在某个渲染器重新解释共享设置。
同一设置在两端保持相同提交和应用时机。已保存、生效、草稿、预览及导航值保持独立。纯呈现预览
必须可逆；关闭选择器不得暗中持久化预览。GUI 表面规则遵循
[`frontend/settings.md`](frontend/settings.md)，原生表面规则遵循
[`tui/settings.md`](tui/settings.md)。

在各端内部复用已评审组合。GUI 发现流程仍为
[`frontend/experience-components.md`](frontend/experience-components.md)；TUI 发现、归属和可复用控件
契约遵循 [`tui/components.md`](tui/components.md)，TUI 表面选择遵循
[`tui/overlays-and-status.md`](tui/overlays-and-status.md)。跨端共享交互契约与领域操作，
组件仍保留在既有所有者中。

## 开发与验证

1. 开始功能或行为变更时，先确定两端入口和共同所有者。在实现第一端前明确共同契约及映射。
2. 在所属所有者实现领域或协议变更，再在同一交付范围内更新两端受影响投影、生效绑定、本地化
   文案与所属参考。共享默认值变化时，即使请求只提到一端，影响分析也必须包含两端。
3. 分阶段交付时，在既有任务中记录尚缺的对应端、具体限制、责任所有者和完成条件。功能参考
   说明当前支持范围，并在限制解决后移除说明。如实呈现不可用能力；单端完成不能证明跨端完成。
4. 按下表验证共同语义及各端行为，再运行 [`VERIFICATION.md`](VERIFICATION.md) 中适用的本机
   门禁。显式审查产品差异；仅通过 CSS 或 Rust 检查不能证明跨端一致。

| 变更主张       | 证据                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| 共享操作或状态 | 等价领域快照和意图轨迹通过两端产生相同目标、资格、提交结果和结果分类；存在既有契约 fixture 时复用            |
| 快捷键或映射   | 两端生效绑定调用相同作用域的动作；测试助记对应关系、平台归一化、冲突、支持时的覆盖，以及受保护编辑或终端输入 |
| 交互生命周期   | 按适用范围通过两端入口覆盖选择与激活的区别、提交前取消、处理中/失败/未知结果和有效焦点返回                   |
| 视觉角色或布局 | 在可比较产品主题下检查两端同一场景，再检查各端要求的宿主、颜色、几何和语言情况                               |
| 设置           | 检查相同作用域、值含义、校验、默认值/重置及传播契约；区分不支持和 Client 本地设置                            |

浏览器和 Story 证据遵循 [`frontend/storybook.md`](frontend/storybook.md)，单元格网格、输入和
宿主证据遵循 [`tui/verification.md`](tui/verification.md)。断言共同含义和端特有行为，而不是
像素相等或原始事件相同。证据限制和未解决差异留在既有任务中。这些跨端要求由审查和功能测试
承担；目前不存在仓库级自动一致性检查器来强制执行它们。
