# 前端设置

## 权威范围

本规范负责 Orchbee 自有的浏览器端和 Desktop React 界面中“设置”体验的呈现与交互契约。
它规范设置表面、导航、搜索、设置项行、作用域与来源说明、控件选择、提交反馈、重置，以及相关
管理任务的入口。

设置项所属领域仍然负责其值语义、支持的作用域、默认值、优先级、持久化、同步、安全边界、
副作用和兼容性。设置表面负责呈现这些事实并发出语义意图；它不能成为第二个所有者，也不能从
渲染出的控件反推策略。

跨端设置含义与作用域遵循 [`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md)。GUI 设置与原生
对应能力一起设计；区分共享值语义、Client 本地呈现，以及是否实际支持同步。

表面准入和有界编辑任务遵循
[`dialogs-and-forms.md`](dialogs-and-forms.md)，视觉几何遵循
[`visual-foundations.md`](visual-foundations.md)，语义副作用遵循
[`actions.md`](actions.md)，键盘入口遵循
[`keyboard-shortcuts.md`](keyboard-shortcuts.md)，产品文案遵循
[`localization.md`](localization.md)。经审查的组合及其所有权遵循
[`experience-components.md`](experience-components.md)。

本文只定义可跨工作区复用的规则。各包所属参考仍然是单个设置目录、值 Schema、持久化适配器、
平台能力和当前产品行为的权威来源。现有表面在发生实质变更时接受本规范审查；被触及的表面不得
新增或扩大不合规模式。

## 设置项模型

**设置项**是会改变后续产品行为、可持久保留且可再次调整的选择或策略。该模型区分：

- 在一个作用域写入的**显式值**；
- 解析优先级和可用性后，当前实际控制行为的**生效值**；
- 状态可以被编辑的**作用域**，例如账户、组织、项目、工作区、设备或会话；以及
- 提供生效值的**来源**，例如显式覆盖、继承策略、平台默认值或产品默认值。

每个新增或实质变更的设置项都必须有一份包含下列字段的所属记录。记录可以位于类型、包参考、
Manifest 或它们的组合中，但必须无需逆向分析渲染页面即可审查。

| 字段         | 必须做出的决定                                         |
| ------------ | ------------------------------------------------------ |
| 标识与所有者 | 稳定标识符、领域所有者和允许的写入方                   |
| 位置         | 分类、分区、本地化标签、说明和搜索别名                 |
| 值           | 类型、有效值域、规范默认值和缺省语义                   |
| 作用域与来源 | 支持的写入作用域、优先级、继承、强制策略和生效来源投影 |
| 存储与安全   | 持久化所有者、同步策略、本地性、敏感性和保留期         |
| 可用性       | 平台、能力、权限、套餐、策略和依赖守卫                 |
| 提交         | 即时或暂存策略、验证边界、提交点和失败恢复             |
| 生效边界     | 结果影响当前工作、新会话、新资源、重新加载还是重新启动 |
| 恢复         | 单项重置、继承回退、支持时的撤销和破坏性后果           |
| 证据         | 模型、确定性测试、Story、无障碍路径和适用的系统证据    |

设置项元数据是共享契约，不是强制使用单一 Schema 驱动渲染器。通用渲染器不得抹平领域专用控件、
说明、验证或管理流程。

## 准入与分离

- 只有当人们可以合理地再次访问某个值，并预期该选择会在声明的作用域中持久保留时，才将它纳入
  设置。只为一个前台结果所需的值应留在该任务中。
- 不要询问权威上下文已经知道、可以安全推导，或直到后续任务才相关的值。
- 命令、状态、诊断、迁移、凭据交换或资源集合不会因为可以从设置进入就变成设置项。将它们
  呈现为命名清晰的 Action、摘要或专用管理表面。
- 没有可用值、也没有当前可满足前置条件的行属于路线图，不属于设置。不要用禁用控件或“即将
  推出”徽标宣传未来能力。
- 隐藏在当前环境中无关的能力。只有当它用于解释生效行为，或用户能够满足当前前置条件时才
  保持可见；此时需在控件旁说明原因和恢复方式。
- 不要把法律同意、不可逆删除或严重后果确认变成随意的开关。使用所属的经审查流程和确认边界。

## 表面与信息架构

设置是持久导航表面：页面、专用窗口或有界模态面板。Desktop 和宽屏浏览器宿主默认使用下文的
有界组合。只有当有界表面无法保留必要上下文或管理空间时，全窗口面板才是例外；其模态版本仍
需提供完整模态语义、背景不可交互、关闭和焦点恢复。紧凑 Dialog 只用于满足“对话框与表单”
规范准入的有界编辑或设置任务；它不能作为设置目录的容器。

- 按人的目标和词汇组织分类，不要按源码目录、包、存储键或实现团队分类。
- 保持主层级扁平：命名分组可以包含分类，而分类拥有稳定且以目的命名的分区。不要只为减少
  行数而再添加一层永久导航。
- 每个分类使用一个本地化标题和可选的简短说明。把相关行放在一个安静表面上并用分隔线分组；
  不要把每一行都包装成独立卡片。
- 当一个领域拥有集合、历史、凭据生命周期、复杂冲突解决或重复的新增/编辑/删除任务时，使用
  专用子页面，并保留清晰的返回父分类路径。
- 不要创建名为“高级”的杂物区。应命名结果或领域。专家值若有意由文件或命令管理，则链接到
  受治理的路径并说明其作用域，不要复制一个不完整的编辑器。
- 当宿主支持链接时，保持分类标识和深链接稳定。展示顺序变化不能改变设置项的标识或所有者。

## 视觉组合

Desktop 和宽屏浏览器的设置表面使用下述外壳、密度、层级与设置项行结构，并由 Orchbee 的语义 Token 和共享原语实现。

- 在宽视口中使用一个居中、有边界且四周留有呼吸空间的表面。只有可用空间需要时才向视口
  扩展；不要让普通设置目录看起来像另一个 Workbench 画布。
- 把外壳分成一个安静的导航侧栏和一个内容窗格。侧栏负责顶层关闭或返回入口、搜索和分类导航；
  内容窗格负责一个分类标题及其设置项。两者之间一条克制边界已经足够。
- 侧栏和内容窗格使用相差一级的语义表面。用一个克制的中性填充表示所选分类；图标保持单色，
  且层级低于标签。只有确实能改善扫描时才显示分组标题，并且不得与分类争夺注意力。
- 保持适中的内容宽度和平实层级：紧凑页面标题、可选简短介绍，然后是用安静细分隔线隔开的
  直接设置项行。不要添加 Hero、仪表盘装饰、装饰插图，也不要给每个分区或设置项行套卡片。
- 在宽布局中把控件对齐到一致的尾部列。说明位于标签下方；异常状态或恢复方式扩展其所属行，
  不要使用会遮挡其他设置项的悬浮说明面板。
- 圆角和阴影只用于外层模态边界及瞬时锚定表面。内部结构依赖间距和分隔线；强调色用于交互或
  选中，而不是装饰。
- 让外壳和导航保持稳定，只滚动适当窗格。仅当分类溢出时才允许侧栏独立滚动；避免嵌套内容
  滚动区，并让所选分类保持在视野内。
- 在同一稳定外壳内打开复杂管理目标并提供明确返回路径，或转到专用持久表面。不要在设置上再
  叠加一个目录尺寸的模态框。
- 在窄宽度下把双栏外壳替换为一次只显示一个窗格：分类列表、分类内容或管理目标。保留相同
  层级和返回路径，不能把侧栏挤在内容旁边。

## 搜索与发现

拥有多个分类的设置表面必须提供全局搜索。搜索只能用于导航，绝不能产生变更。

- 为当前可用设置项和管理入口建立索引，内容包括本地化分类名、标签、简短说明和经审查别名。
  绝不能索引秘密值、用户输入内容、隐藏路线图或诊断输出。
- 规范化大小写和空白，要求每个输入词都命中，并使排序和同分规则保持确定性。locale 或可用性
  变化时重建索引。
- 结果必须说明设置项及其分类。只有当例外信息有助于区分结果时才显示作用域、来源、平台或
  状态；不要给每条结果装饰重复元数据。
- 输入时保留当前显示页面。激活结果后导航并揭示对应行，然后把焦点移到其标题或行容器；不得
  改变值，也不得意外打开控件。
- 上下方向键在结果间移动，Enter 激活高亮结果，Escape 先清除非空查询。提供明确空状态，
  但不能用它替换稳定的导航模型。
- 搜索别名属于产品文案，必须随每个支持的 locale 交付。切换 locale 后，不应要求用户知道
  上一个 locale 中的标签。

## 作用域、来源与继承

- 支持多个写入作用域时，在控件之前明确当前作用域，绝不能根据上次访问页面静默推断写入
  作用域。切换作用域时必须先处理所有暂存草稿，再展示另一个作用域。
- 由所属领域模型投影生效值及其来源。UI 绝不能通过比较可选值或存储记录重新实现优先级。
- 区分“重置为继承值”和“重置为默认值”。删除显式覆盖后应显露下一个有效来源；不能创建
  一个等于今天默认值的新显式值来冒充重置。
- 当组织、权限或平台策略强制一个值时，显示生效值以及锁定或来源说明，并以编程方式明确编辑
  不可用。只有禁用样式不构成解释。
- 当仅本地、不同步或平台专属这类例外会影响预期时予以标记。不要在每行标记普通同步状态。
- 如果来源消失或失效，通过领域所有者解析下一个生效来源并说明任何降级状态。绝不能保留一个
  已不再控制行为、但视觉上仍为选中的值。

## 设置项行组成

标准设置项行包含持久可见标签、可选辅助文本、当前状态，以及能够表达该值的最小语义控件。
在较宽表面上，文案和控件可以按稳定列对齐；在窄表面上应堆叠，且不能改变阅读、焦点或播报
顺序。

- 辅助文本只解释不明显的后果、作用域、依赖、隐私边界、生效边界或恢复规则。不要重复标签，
  也不要讲解标准控件如何操作。
- 保持经常扫描的值可见。Tooltip 不能成为解释后果、锁定、错误或重置行为的唯一位置。
- 使用“视觉基础”规定的排版、分组表面、分隔线、间距和控件几何。不要通过随意加粗、嵌套
  卡片或一次性宽度创建层级。
- 已知上下文应显示为文本或元数据，而不是禁用文本字段。只有当一个真实值当前不可编辑且原因
  已显示时，才能禁用设置控件。

按值语义选择控件：

| 值或意图               | 首选控件与边界                                                   |
| ---------------------- | ---------------------------------------------------------------- |
| 独立且可逆的布尔值     | 使用描述开启状态的正向标签 Switch；激活时提交                    |
| 多个独立选择           | Checkbox 组；绝不能用单个 Checkbox 通用替代独立 Switch           |
| 两到五个需要比较的选项 | Radio 组；只有选项简短、熟悉且权重相同时才使用 Segmented Control |
| 较长或空间受限的选择   | 使用稳定选项标识符的 Select 或可搜索 Combobox                    |
| 精确文本或有界数字     | 带单位、限制、格式和验证的语义 Input；不要使用无类型的通用字段   |
| 近似连续值             | Slider；精度重要时同时提供精确 Input 或显示值                    |
| 颜色、主题、字体或路径 | 带预览的领域 Picker；专家输入有用时提供明确规范值                |
| 键盘绑定               | 提供冲突、平台呈现、移除和重置的专用录制器                       |
| 资源集合或账户         | 摘要加进入专用表面的“管理”Action                                 |
| 秘密或外部凭据         | 带明确验证的有界安全设置；绝不能成为持久化的普通设置草稿         |
| 命令或破坏性操作       | 以结果命名的 Button，并使用与风险匹配的 Action、取消和确认契约   |

## 提交与生效生命周期

每个设置项必须声明一种提交策略。不要让人们根据是否存在页脚来猜测。

- 独立且可逆的设置项在所属控件提交。Switch 或有限选项在激活时提交；文本和数字编辑器只能在其
  声明的有效边界提交，例如 blur 或 Enter。不要给其他设置均为即时提交的页面添加全页 Save。
- 只有当多个值组成一个原子配置、验证必须一起检查它们，或提交会启动昂贵或外部副作用时，才
  使用暂存草稿。把草稿限制在一个有界分区或专用任务表面，并提供一个以结果命名的主 Action
  和可见脏状态。
- 绝不能混合即时设置项和未说明的全页草稿。如果两种策略都必要，在视觉和语义上明确分离边界。
- 如果变更只影响新终端、未来对话、新创建资源、重新加载或应用重启，提交前必须说明生效边界。
  “已保存”绝不等于“已经应用”。
- 在拥有操作的设置项和作用域上显示进行中状态。按语义标识去重、忽略过期完成；除非领域要求
  原子锁，否则保持无关控件可用。
- 不要为常规成功弹 Toast。就地反映已提交的生效值，以及任何例外来源或生效边界。
- 持久化或外部应用失败绝不能伪装成成功。保留或恢复最后一个权威生效值；可以重试时保留非秘密
  暂存草稿，并显示本地化的行内恢复路径。只有模型明确命名并在界面上标记时，会话内结果才是
  有效状态。

## 依赖、验证与冲突

- 当附近的前置条件可以启用某个依赖设置项时，保持该项可见但禁用。在行旁说明依赖，并以编程
  方式将说明与控件关联。
- 隐藏永久不适用的平台或能力分支，除非必须解释其被强制的生效值。只有当信息有助于理解当前
  行为或具体恢复路径时，才保持套餐、权限或管理员限制可见。
- 在有意义的交互后验证。草稿不完整或无效时保留最后一个有效生效值，在编辑器旁显示错误，
  绝不能暴露原始异常。
- 不要把禁用显式 Save Action 作为唯一验证说明。接受合理的提交尝试，揭示每个相关错误，
  并聚焦第一个无效编辑器。
- 在所属模型中检测冲突。显示冲突的设置项或绑定、其作用域和来源，以及明确的替换、移除或取消
  结果；绝不能按渲染顺序静默决定胜者。
- 异步验证必须命名进行中、已验证、已拒绝、已过期和可重试失败状态。验证结果绑定到产生它的
  精确草稿和作用域。

## 重置、恢复与破坏性 Action

- 当显式值不同于其回退值时，提供单项重置。明确重置会显露继承值，还是恢复规范产品默认值。
- 只有一个一致所有者和作用域才能提供分区或页面重置。预览受影响的值，排除无关资源和数据；
  当范围或影响难以逆转时使用 Alert Dialog。
- 重置是语义 Action，不是第二个默认值写入方。它通过所属领域操作删除或替换状态，并如实报告
  部分成功或失败结果。
- 将账户删除、凭据撤销、历史清理和其他破坏性数据 Action 与普通偏好分离，放入以目的命名的
  危险分区或专用任务表面。确认遵循“对话框与表单”规范，并说明作用域、后果和恢复方式。

## 管理、凭据与工具

账户、Profile、集成、Provider 和绑定等集合需要管理状态，不能塞进一个过大的设置项行。

- 父级行总结生效状态并打开专用子页面或任务表面。管理表面负责空、加载中、有内容、降级、
  进行中和失败状态，以及新增/编辑/删除的恢复。
- 新增或编辑一个有界资源时，如果独立满足模态准入，可以使用 Dialog。长设置、比较、历史或
  重复管理应保持在持久表面。
- 把集成的启用偏好与凭据或资源生命周期分开。Toggle 绝不能静默启动身份验证、创建远程资源
  或接受法律条款。
- 秘密必须直接发送给获准的安全能力，并在有界操作结束后从 UI 内存清除。值被遮罩并不代表
  浏览器存储、日志、搜索索引、分析系统或普通设置文件可以安全保存它。
- 诊断和迁移属于有明确读写边界的命名工具。打开或搜索设置绝不能启动远程变更、凭据提示、
  破坏性扫描或迁移。结果应说明来源、新鲜度、限制和改变行为所需的 Action。

## 导航、焦点与无障碍

- 把打开设置注册为语义 Action。除非所属兼容性契约选择其他绑定，Desktop 宿主通常应提供
  平台的设置快捷键。
- 无深链接打开顶层表面时，如果页面标题已经以编程方式命名，可以把初始焦点放入全局搜索。
  深链接或激活搜索结果后，把焦点移到目标标题或行，不能直接进入会改变值的控件。
- 分类导航以编程方式暴露当前分类，并支持普通 Tab 导航及所选语义模式的原生方向键行为。
  切换分类绝不能改变设置项。
- 从最内层所属状态向外处理 Escape：关闭 Picker 或编辑器、清除非空搜索、从管理子页面返回，
  最后关闭可取消的设置面板。路由或专用窗口应遵循其宿主导航契约，不能伪装为模态。
- 模态全窗口面板必须约束焦点、让背景不可交互、提供可见关闭路径，并把焦点还给调用者。页面
  或专用窗口不得使用 `aria-modal`。
- 将标签、说明、依赖、错误、进行中状态和来源解释关联到控件。礼貌播报异常异步结果，并保留
  可见焦点指示器。
- 在窄宽度下，用明确的分类控件和返回路径折叠或替换侧栏。保持语义顺序、触摸目标、缩放行为，
  并确保无需横向滚动即可访问重置或恢复。

## 建模与证据

实现新增或实质变更的设置表面或设置项前：

1. 记录用户意图、设置项准入、领域所有者、稳定标识、支持的作用域、优先级、生效来源投影、
   持久化边界和非目标。
2. 完成[设置项模型](#设置项模型)字段，并对适用的不可用、加载中、生效、编辑中、无效、
   提交中、已提交、失败、被强制、过期完成、重置和作用域切换转换建模。
3. 为可用性、继承、重置、生效边界、依赖、验证、冲突解决、取消和异步完成定义决策用例。
   每个适用的正确性触发条件都遵循
   [`../MODELING-AND-CORRECTNESS.md`](../MODELING-AND-CORRECTNESS.md)。
4. 执行体验组件发现并选择复用、扩展、替换或新增。在所属 Manifest 中记录设置项行、分类、
   搜索结果和管理表面不变量。
5. 将确定性测试映射到生效值优先级、来源投影、作用域安全写入、重置、不可用和被强制状态、
   验证、过期完成、失败恢复、搜索排序和无变更导航。
6. 为使用到的每种控件类型和提交策略、两种已交付 locale、明暗主题、窄宽布局、缩放、继承值
   与覆盖值、仅本地值与被强制值、进行中与失败、搜索结果与空状态、键盘导航和焦点恢复提供
   Story。

现有设置项被触及时也不能豁免。审查完整的受影响行或管理流程，移除任何新暴露的重复所有者，
并且不得扩大隐藏提交、路线图、仅靠禁用或作用域模糊的行为。
