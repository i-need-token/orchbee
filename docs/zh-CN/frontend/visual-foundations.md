# 前端视觉基础

## 权威性和范围

本文档拥有 Orchbee 自有产品界面中排版、文本层级、间距、圆角、控件、图标、边框和表面的选择规则。在 `apps/*` 或 `packages/*` 中编写或审查 CSS 前先阅读本文档。注册表和 Token 层级机制仍以 [`design-tokens.md`](design-tokens.md) 为权威来源。

以下紧凑桌面端值是 Orchbee 自有产品界面已接受的浅色主题基线。`#141414` 等依赖主题的值是基线映射，不是在组件 CSS 中重复使用的颜色：产品代码使用其 `--ob-sys-*` 角色，每个主题提供具体映射。只有在同一个经过审查的变更中同时修改所属 Token、文档、组件和 Story，才能改变基线；不要引入局部产品覆盖。

Tailwind 替换 Token 和 shadcn 兼容 alias 不会扩大产品编写词汇。新的 Orchbee 自有 CSS 只使用此处定义的语义角色和已批准参考 Token 子集。

## 选择规则

- 按含义选择排版和颜色，绝不能因为外观像另一个元素就选择。
- 使用能够真实表达内容层级的最小角色；不要仅仅为了容纳更多内容而缩小角色。
- 使用一个已注册的间距或圆角 Token。禁止使用原始值和会创建新名义值的计算，例如 `11px` 圆角。
- 相关项之间的距离应小于无关项。外部组间距必须不小于该组内部的间距。
- 同级关系优先使用 `gap`，容器内边距使用 `padding`，只有当双方所有者都无法表达关系时才使用 `margin`。
- 如果没有适合的角色，停止并提出 Token 变更。不要因为当前值看起来正确就借用状态颜色、兼容 alias 或无关尺寸。

由 `pnpm lint:styles` 强制执行的样式契约会拒绝原始视觉值和未注册自定义属性。语义误用仍需要对照本文档审查。

## 排版尺度

通过完整的 `--ob-sys-typography-*` 简写使用排版。不要组合来自一个角色的字号、另一个角色的行高或局部字重。HTML 标题级别表达文档结构，视觉标题角色表达展示，因此它们不需要拥有匹配的后缀。

| 变量                             | 基线默认值      | 使用场景                                   | 禁止使用的场景                   |
| -------------------------------- | --------------- | ------------------------------------------ | -------------------------------- |
| `--ob-sys-typography-body-sm`    | `400 13px/18px` | 默认密集桌面 UI、导航、设置行和描述        | 长篇阅读内容需要更宽松的行框     |
| `--ob-sys-typography-body-md`    | `400 14px/20px` | 多行帮助、新手引导文案和密度较低的产品界面 | 紧凑工具栏或普通设置行           |
| `--ob-sys-typography-body-lg`    | `400 16px/24px` | 空状态或首次运行体验中的简短介绍文案       | 常规 shell chrome 或数据密集内容 |
| `--ob-sys-typography-label-xs`   | `400 11px/16px` | 持久面板 chrome 中的低优先级元数据         | 控件、章节标签或截断补救方案     |
| `--ob-sys-typography-label-sm`   | `400 12px/16px` | 章节标签和低调的类别标题                   | 正文描述或可点击控件标签         |
| `--ob-sys-typography-label-md`   | `500 13px/18px` | 按钮、标签、输入框和需要明确强调的紧凑控件 | 页面标题或解释段落               |
| `--ob-sys-typography-label-lg`   | `500 14px/20px` | 突出的控件标签和主要面板工具栏             | 作为标题的替代品                 |
| `--ob-sys-typography-heading-sm` | `500 16px/20px` | 页面标题、设置标题或主要面板标题           | 每个卡片或行标题                 |
| `--ob-sys-typography-heading-md` | `600 20px/28px` | 主要新手引导章节或层级更强的页面           | 密集桌面设置或导航               |
| `--ob-sys-typography-heading-lg` | `600 24px/32px` | 空状态标题或聚焦的首次运行步骤             | 持久应用 chrome                  |
| `--ob-sys-typography-heading-xl` | `700 36px/40px` | 少见的 hero 或产品介绍语句                 | 普通应用界面                     |
| `--ob-sys-typography-code-sm`    | `400 12px/16px` | 内联代码、紧凑标识符和类似代码的元数据     | 专用单元格渲染或普通散文         |
| `--ob-sys-typography-code-md`    | `400 13px/18px` | 代码块、命令、日志和邻近的只读信息         | 拥有自身字体设置的交互式内容画布 |

应用以下层级规则：

- 共享 UI 样式表在页面边界应用 WebKit 抗锯齿和 macOS Firefox 灰度平滑。组件不得局部覆盖字体平滑。
- 紧凑桌面产品 UI 从 `body-sm` 开始。
- 标题及其辅助描述使用不同角色或颜色；不要把二者都放大。
- `label-*` 用于简短界面标签，不作为让文本加粗的通用方法。
- 一个持久面板最多使用三种可见字号。额外层级应来自文本颜色、间距或分组。
- 不要通过缩小文本解决截断。应换行、在完整值可访问的前提下截断，或者改变布局。
- 专用内容 renderer 的字形尺寸和行高属于 renderer 设置，不属于 UI 排版 Token。

## 文本层级

文本层级描述信息优先级，而不是交互状态。一行中的主要、次要和第三级文本通常使用相同排版角色，通过语义颜色区分。在以下表达式中，`color @ N%` 表示 `color-mix(in srgb, color N%, transparent)`。

| 层级        | 变量                              | 浅色基线        | 使用场景                                     |
| ----------- | --------------------------------- | --------------- | -------------------------------------------- |
| 标题        | `--ob-sys-color-text-heading`     | `#141414 @ 92%` | 页面和面板标题                               |
| 主要        | `--ob-sys-color-text-primary`     | `#141414 @ 92%` | 任务关键内容、行标题、值、用户内容和控件文本 |
| 次要        | `--ob-sys-color-text-secondary`   | `#141414 @ 70%` | 直接附属于主要内容的描述和辅助文案           |
| 章节标签    | `--ob-sys-color-text-label`       | `#141414 @ 70%` | 类别和章节标签                               |
| 第三级      | `--ob-sys-color-text-muted`       | `#141414 @ 48%` | 时间戳、低优先级元数据、提示和弱化上下文     |
| Placeholder | `--ob-sys-color-text-placeholder` | `#141414 @ 32%` | 仅用于空的可编辑控件提示                     |
| 禁用        | `--ob-sys-color-text-disabled`    | 主题映射        | 不可用内容或控件                             |
| 反色        | `--ob-sys-color-text-inverse`     | 主题映射        | 反色语义表面上的文本                         |

用户为做出下一步决策必须阅读的信息使用主要文本。移除文案会降低理解但不改变可用操作时，使用次要文本。移除后不会阻塞任务时，使用第三级文本。Placeholder 文本不是第四级信息，绝不能承载持久说明或必需数据。

不要在文本容器上设置 `opacity` 来创建层级：这也会淡化图标、后代、焦点指示器和状态颜色。应把语义颜色应用到准确文本或图标。状态和链接颜色传达含义或交互，不得替代信息层级。

持久导航在默认状态下使用 secondary 文本和图标角色。Hover、键盘焦点以及 current 或
active 状态使用 primary 文本和图标角色。Hover 与 active 共用相同的前景角色；由持久的
选中表面而不是更深的文字颜色区分 active 目标。

菜单内容、触发器披露和嵌套交互状态遵循 [`menus.md`](menus.md)。

## 间距尺度

只有以下间距 Token 被批准用于产品自有 margin、padding 和布局 gap。同一关系在各组件中使用同一 Token。大于 `32px` 的值是页面级工具，要求可见留白确实是组合中有意的一部分。

| 变量                 | 值     | 使用场景                                      |
| -------------------- | ------ | --------------------------------------------- |
| `--ob-ref-space-0`   | `0`    | 拼接边缘、齐平布局或有意移除间距              |
| `--ob-ref-space-0-5` | `2px`  | 紧邻细线的视觉校正或极紧凑图标细节            |
| `--ob-ref-space-1`   | `4px`  | 焦点偏移、紧凑图标细节或紧凑纵向分隔          |
| `--ob-ref-space-1-5` | `6px`  | 密集图标标签间距，或 `8px` 明显过松时的内边距 |
| `--ob-ref-space-2`   | `8px`  | 默认图标标签间距、紧凑内边距或相邻紧凑控件    |
| `--ob-ref-space-2-5` | `10px` | 紧凑行内边距或密集 chrome 中的中间分隔        |
| `--ob-ref-space-3`   | `12px` | 紧凑堆叠间距、控件组间距或密集行横向内边距    |
| `--ob-ref-space-4`   | `16px` | 默认卡片/面板内边距和相关区块之间的标准间距   |
| `--ob-ref-space-5`   | `20px` | 一行或工具栏中的舒适横向间隔                  |
| `--ob-ref-space-6`   | `24px` | 面板/页面 gutter 或一个章节中不同组之间的分隔 |
| `--ob-ref-space-8`   | `32px` | 页面章节之间的分隔                            |
| `--ob-ref-space-10`  | `40px` | 页面顶部内边距或无关区域之间的大间隔          |
| `--ob-ref-space-12`  | `48px` | 居中组合或有意宽松的页面区域                  |
| `--ob-ref-space-16`  | `64px` | 空状态留白或主要首次运行区域                  |

按关系选择间距：

- 一个原子控件内部使用 `space-0-5` 到 `space-2`。
- 一个组件的元素之间从 `space-1-5`、`space-2` 或 `space-3` 开始。
- 卡片或面板内边距从 `space-4` 开始；只有当表面不需要高密度时才使用 `space-6`。
- 一个章节中相关组之间使用 `space-4` 或 `space-6`。
- 独立章节之间使用 `space-8` 或更大值。
- 重复列表或堆叠使用 `gap`；不要给每个子项任意 bottom margin。
- 当密度需要时，横向和纵向内边距可以不同，但同一组件的重复实例必须使用相同配对。
- `calc()` 可以解析结构性几何，例如从固定控件中减去边框，但不得创造本尺度中缺失的可复用视觉值。

间距 Token 不兼作任意宽度或高度 Token。当决策是尺寸而不是间距时，使用控件尺寸、图标尺寸、容器或有明确所有者的 `--ob-comp-*` 几何槽位。

## 圆角尺度

新的 Orchbee 自有产品 CSS 只使用以下已批准圆角子集。其他已注册圆角 Token 用于 Tailwind 或 shadcn 兼容，不属于额外设计选择。

| 变量                    | 值       | 使用场景                                   |
| ----------------------- | -------- | ------------------------------------------ |
| `--ob-ref-radius-none`  | `0`      | 边到边内容表面、拼接行和内部分隔线         |
| `--ob-ref-radius-sm`    | `4px`    | 微型 badge、紧凑 tag 和低调的内联表面      |
| `--ob-ref-radius-ui-sm` | `6px`    | 紧凑控件和小图标按钮                       |
| `--ob-ref-radius-ui-md` | `8px`    | 标准控件和密集树形导航行                   |
| `--ob-ref-radius-ui-lg` | `10px`   | 独立导航选中项、紧凑菜单和浮层             |
| `--ob-ref-radius-xl`    | `12px`   | 分组设置卡片和中型内容卡片                 |
| `--ob-ref-radius-2xl`   | `16px`   | 对话框和需要更强分隔的大型浮动表面         |
| `--ob-ref-radius-full`  | `9999px` | 头像、状态点、圆形控件和有意设计的胶囊形状 |

应用以下圆角规则：

- `11px`、`13px` 和其他所有未列出的圆角都是无效的，即使视觉上接近已批准值。
- 输入框和按钮使用所属 UI 组件的圆角；使用方不得按界面覆盖。
- 分组列表对外部容器应用圆角。内部行保持直角，让组读作一个对象。
- 嵌套可见表面使用与父级相同或下一个更小的已批准圆角；绝不能超过父级圆角。
- 只有当几何形状确实为圆形或胶囊形时才使用 `radius-full`，不要用它逃避选择组件圆角。
- 不要仅仅为了让边到边内容表面、导航栏或主窗格看起来像卡片就添加圆角。

## 控件、图标、浮层和滚动条尺寸

控件、图标和浮层尺寸是有限的，因为不一致的 chrome 会让 shell 显得不稳定。组件使用方选择已记录的组件 `size` variant，而不是局部指定宽度或高度。

| 变量                                | 值      | 使用场景                                           |
| ----------------------------------- | ------- | -------------------------------------------------- |
| `--ob-ref-size-control-xs`          | `24px`  | 小按钮、内联操作、紧凑图标按钮或密集 utility 控件  |
| `--ob-ref-size-control-sm`          | `28px`  | 工具栏、紧凑 select 或次要桌面控件                 |
| `--ob-ref-size-control-navigation`  | `30px`  | 需要独立紧凑节奏的持久侧边栏导航行                 |
| `--ob-ref-size-control-md`          | `32px`  | 默认按钮、输入框、select 和普通交互控件            |
| `--ob-ref-size-control-lg`          | `36px`  | 主要字段、突出操作或有意舒适的桌面输入框           |
| `--ob-ref-size-icon-xs`             | `12px`  | 状态字形、badge 图标、紧凑元数据或次要指示器       |
| `--ob-ref-size-icon-section-action` | `13px`  | 与紧凑章节标题对齐的低调操作图标                   |
| `--ob-ref-size-icon-sm`             | `14px`  | 产品、导航、菜单、字段、工具栏和按钮的默认图标     |
| `--ob-ref-size-icon-md`             | `16px`  | 具有显式组件要求的有意强调图标                     |
| `--ob-ref-size-icon-lg`             | `20px`  | 突出的独立操作或空状态辅助图标                     |
| `--ob-ref-size-dialog`              | `480px` | 默认表单和确认 Dialog；受视口可用尺寸约束          |
| `--ob-ref-size-menu`                | `250px` | 下拉、右键、菜单栏及子菜单浮层；受视口可用尺寸约束 |
| `--ob-ref-size-scrollbar-track`     | `12px`  | 横向或纵向原生滚动条的布局盒                       |
| `--ob-ref-size-scrollbar-thumb`     | `6px`   | 默认、Hover 和 Pressed 状态下的原生滚动条滑块      |

一个控件内只使用一种图标尺寸。紧凑章节标题上的操作使用 `icon-section-action`；密集的 `control-xs` 或 `control-sm` 通常使用 `icon-xs` 或 `icon-sm`；默认 `control-md` 通常使用 `icon-sm` 或 `icon-md`。文本旁的图标使用 `space-1-5` 或 `space-2` 间距。不要通过放大装饰图标来强调；应提升操作或文本角色。可见控件可以是 `24px`，同时其可复用组件提供更大的不可见指针命中区域；视觉密度和触摸无障碍是不同职责。

### 原生滚动条

共享 UI base layer 统一产品应用中的 CSS 原生滚动条。轨道保持透明。滑块在默认、Hover、
Pressed 和拖动状态下，都以完全圆角的 `6px` 形态居中放置在 `12px` 布局盒中。默认、Hover 和 Pressed 状态分别使用
`--ob-sys-color-scrollbar-thumb`、`--ob-sys-color-scrollbar-thumb-hover` 和
`--ob-sys-color-scrollbar-thumb-pressed`。Firefox 使用原生 `thin` 几何，并使用相同的语义
滑块和轨道颜色。

该契约必须通过共享样式表应用，产品 CSS 不得重复编写伪元素选择器。只有在交互仍可滚动，
且组件已经拥有有记录的隐藏滚动条 variant 时，组件才能隐藏原生滚动条。Canvas 渲染的
Terminal 滚动条和专用 overlay 滚动条属于独立组件行为，不继承这里的原生滚动条几何。

## 边框和表面

分隔线和普通轮廓使用 `--ob-ref-border-width-default`（`1px`）。焦点几何或有意强调的边界使用 `--ob-ref-border-width-strong`（`2px`）。没有组件专属要求时，不要使用更粗的产品边框。

键盘焦点指示器在所有布局状态下都必须完整且不被遮挡，包括菜单或 Dialog 把焦点恢复到
触发器之后。密集控件以及靠近滚动或裁切边界的控件使用内描边焦点几何，使指示器不依赖控件
外部空间。不要用局部偏移或任意提高 `z-index` 来修补被裁切的焦点指示器；应选择保留在所属
控件内部的几何，或为外部焦点指示器预留明确的布局空间。

| 变量                                    | 浅色基线        | 使用场景                            |
| --------------------------------------- | --------------- | ----------------------------------- |
| `--ob-sys-color-border-subtle`          | `#141414 @ 5%`  | 一个分组对象内部的分隔线            |
| `--ob-sys-color-border-default`         | `#141414 @ 12%` | 标准控件轮廓或面板边界              |
| `--ob-sys-color-border-strong`          | `#141414 @ 20%` | 需要比默认更强分隔的边界            |
| `--ob-sys-color-border-focus`           | `#2778c1`       | 仅用于键盘焦点轮廓                  |
| `--ob-sys-color-surface-canvas`         | `#fcfcfc`       | 应用和页面背景                      |
| `--ob-sys-color-surface-inactive`       | `#141414 @ 6%`  | 多面板工作区中非聚焦面板的蒙层      |
| `--ob-sys-color-surface-raised`         | `#fcfcfc`       | 位于画布之上的持久面板              |
| `--ob-sys-color-surface-overlay`        | `#fcfcfc`       | 菜单、popover、对话框或临时浮动表面 |
| `--ob-sys-color-surface-subtle`         | `#141414 @ 4%`  | 低调的分组卡片或内嵌区域            |
| `--ob-sys-color-surface-hovered`        | `#141414 @ 8%`  | 中性交互区域的 hover 反馈           |
| `--ob-sys-color-surface-selected`       | `#141414 @ 8%`  | 当前导航项或选中的中性区域          |
| `--ob-sys-color-surface-selected-hover` | `#141414 @ 12%` | 已选中中性区域的 hover 反馈         |

在持久 shell chrome 中，优先使用表面变化或分隔线，不要使用阴影。`--ob-sys-shadow-raised` 只用于持久抬升内容，`--ob-sys-shadow-overlay` 只用于临时 overlay。阴影不能替代正确的表面或边框角色。

默认 Dialog 和 Alert Dialog 容器使用共享的 `480px` 宽度并受视口约束，同时使用 overlay
阴影而不是外描边。操作 Footer 与内容保持在同一表面，通过留白而不是分隔线或着色框带
进行分组。字段和控件保留自身边界与焦点几何。

表单 Dialog 依次展示一个标题、一段辅助说明和带标签的字段。每个可编辑字段都提供本地化
placeholder 作为输入提示；持续有效的说明必须保持为可见的 description 文本，不能放进
placeholder。Footer 将取消操作放在主要提交操作之前，并在相应标签旁用 `Kbd` 展示 `Esc`
和 `Enter`。这些提示必须对应真实行为：`Escape` 关闭 Dialog 并恢复焦点，表单提交则允许
通过 `Enter` 调用当前可用的主要操作。当 Dialog 进入添加现有集合条目等临时内层任务时，
不得再渲染第二套操作 Footer；原有 Footer 应切换为该内层任务的取消和提交操作，`Escape`
和 `Enter` 先作用于最内层任务，完成或取消后再恢复原 Dialog 操作。可见的关闭控件必须具有
本地化的无障碍名称。结构相同的 Dialog 必须复用共享表单和 Footer owner，不能重复实现快捷键、
禁用状态或提交逻辑。

## 操作和状态

浅色基线以 `#2778c1` 表示主要操作和焦点，以 `#007041` 表示成功。即使参考界面让它们看起来相似，主要操作、选中导航和成功仍然是不同含义。

| 变量                                    | 浅色基线        | 使用场景                       |
| --------------------------------------- | --------------- | ------------------------------ |
| `--ob-sys-color-action-primary`         | `#2778c1`       | 当前上下文中的一个主要操作     |
| `--ob-sys-color-action-primary-hover`   | `#2778c1 @ 90%` | 主要操作 hover 状态            |
| `--ob-sys-color-action-primary-pressed` | `#2778c1 @ 82%` | 主要操作 pressed 状态          |
| `--ob-sys-color-action-primary-text`    | `#fcfcfc`       | 主要操作表面上的文本和图标     |
| `--ob-sys-color-status-success`         | `#007041`       | 成功结果或含义明确为良好的状态 |

通用二元 switch 不会仅仅因为处于开启状态就使用 success。除非其启用状态明确传达成功，否则使用 selected 或组件 action 角色。warning、danger 和 info 角色同样用于传达状态，绝不能作为任意强调色。

## 本地化布局

每个产品组合都必须适应 [`localization.md`](localization.md) 要求的每个 locale。当翻译文本可能换行时，根据内容确定容器尺寸或使用 `min-height`。由一个英文标签推导的宽度或高度不是可复用组件尺寸。

不要为了容纳翻译而缩小字号、删除必需上下文，或者截断操作和说明。截断仅用于用户提供的条目名称等数据，并且必须保留对完整值的访问。让文本远离图片，并在两个发布的 locale 中验证换行、键盘焦点、缩放和窄布局。
