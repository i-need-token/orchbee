# 前端键盘快捷键

## 动作归属

键盘快捷键调用 [`actions.md`](actions.md) 规定的具名语义动作，而不是一个孤立的 keydown
回调。拥有该动作的功能同时拥有其默认绑定、绑定条件、Tooltip 展示、快捷键测试和移除生命周期。

按照 [`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md) 的快捷键迁移规则，一起选择默认助记键与
对应 TUI 绑定。平台修饰键适配调用机制；动作身份、作用域和助记键在跨端时仍可辨识。

在职责明确的 `*-shortcuts.ts` 归属模块中只定义一次绑定。组件和生命周期 Hook 消费描述符或其匹配函数，而不是重复键码或修饰键逻辑。在多个 Workspace 对同一快捷键引擎产生具体需求之前，产品绑定保留在其产品所有者中。

## 绑定契约

- 在工程契约中把跨平台主修饰键写作 `Mod`。`Mod` 在 Apple 平台映射为 Meta，在其他平台映射为 Control。
- 字母快捷键使用 `KeyboardEvent.code` 匹配，例如 `KeyK`，让物理绑定不受修饰键生成字符的影响。有意依赖生成字符的文本输入行为使用 `key`，并记录这一区别。
- 匹配完整的修饰键集合。拒绝意外的 Shift、Alt、Control 或 Meta，而不是接受含义不明确的超集。
- 忽略输入法组合和重复 keydown 事件，除非具名动作明确支持重复。
- 仅在当前可用动作成功匹配后调用 `preventDefault()`。除非经过审查的作用域边界需要，否则不要调用 `stopPropagation()`。
- 平台检测属于应用组合边界。产品 Package 接收经过校验的平台类别，不读取 `navigator` 或操作系统全局对象。

## 上下文与可用性

绑定可以声明一个可选的上下文条件，通常称为 `when`，用于决定其组合键是否路由到对应动作。该条件必须作为纯逻辑，基于一次按键事件的同一份只读上下文快照求值。条件为 false 时跳过该绑定，使其他绑定、外层作用域或原生行为可以处理该事件。

上下文值描述语义产品状态，例如活动焦点作用域、打开的交互界面、选择状态、编辑模式或可用能力。该状态的所有者随其生命周期发布和清除对应值。绑定解析绝不能通过查询偶然的 DOM 结构、CSS Selector 或本地化文本来推断上下文。

动作可用性与绑定适用性彼此独立：

- `when` 决定某条绑定是否参与路由和冲突裁决。
- [`actions.md`](actions.md#可用性与确认)
  中的动作可用性契约决定该动作能否从任意调用路径执行，包括 Menu、Command、指针控件、自动化和快捷键。
- 只有绑定条件与动作可用性都通过时，解析器才调用动作并消费按键事件；否则继续解析且不调用 `preventDefault()`。

在具体产品使用方提出需求之前，不要引入共享字符串表达式语言、全局 Context Key 清单或用户可编辑的条件语法。产品局部条件仍必须是纯粹、确定且可测试的；当快捷键参考界面展示条件时，还必须提供可检查的元数据，UI 绝不能从函数源码派生条件标签。

## 作用域与冲突

键盘事件从最窄的活动作用域向外解析：

1. 打开的 Modal、Menu、Command 界面或其他临时焦点作用域。
2. 获得焦点的 Editor、Terminal 或功能界面。
3. 已挂载的产品 Shell。
4. 应用全局作用域。
5. 应用没有明确保留的浏览器和操作系统行为。

全局快捷键必须使用主修饰键，并代表在焦点位于普通产品内容时仍然有效的动作。不要为了便利动作覆盖无修饰键输入、文本编辑、输入法组合或终端输入。当全局绑定有意覆盖熟悉的浏览器或编辑命令时，要记录产品原因，并通过可见 UI 提供同一动作。

绑定解析基于可枚举的绑定集合，而不是独立浏览器监听器的偶然顺序。对于同一个规范化组合键，按上述顺序检查活动作用域，并跳过上下文条件或动作可用性未通过的候选项。第一个有效候选项消费事件后停止解析。

添加绑定前，搜索所有作用域中的同一规范化组合键。同一作用域内各绑定的条件必须互斥；否则所有者必须声明并测试稳定的优先级。注册顺序和监听器首次匹配顺序都不是冲突策略。

## 展示与本地化

- 只存储一个规范化绑定，并派生其展示形式。不要分别维护匹配字符串和 Tooltip 字符串。
- 在 Apple 平台把 `Mod` 显示为 `⌘`，其他平台显示为 `Ctrl`。使用 `Kbd` 或 `KbdGroup` 展示按键。
- Apple 修饰键符号按 Control、Option、Shift、Command（`⌃⌥⇧⌘`）排序，以符合平台菜单惯例。
- 本地化动作名称，不要本地化键码、修饰键符号或嵌入组合键格式化器的平台名称。
- 可见 Menu Item、Button Tooltip、Command 结果和快捷键参考使用同一个动作描述符与平台格式化器。
- 快捷键参考从已注册描述符派生动作名称、格式化组合键、条件摘要和绑定来源，而不是维护单独的清单。
- 控件仍然可以通过指针和辅助技术使用。快捷键只是额外调用路径，绝不是唯一方式。

## Dialog 原生按键能力

- 由原生表单行为和共享 Dialog 原语提供的未修饰 Enter 提交与 Escape 关闭属于结构化按键
  能力，不是应用级快捷键绑定。不要在产品快捷键注册表中重复它们，也不要附加平行的
  keydown Listener。
- 它们的可见 `Kbd` 提示遵循
  [`dialogs-and-forms.md`](dialogs-and-forms.md#验证与-action)。提示应从当前步骤的默认编辑上下文
  派生，并从 Action 的无障碍名称中隐藏；只要该映射依赖条件或含义不明确，就应省略提示。
  绝不能拦截 Enter 来覆盖显式获得焦点的控件的原生激活行为。

## 生命周期与验证

- 在职责明确的生命周期 Hook 或应用组合所有者中注册浏览器监听器，并在清理时移除完全相同的监听器。
- 保持事件归一化和描述符匹配为纯逻辑，以便在不使用 React 的情况下测试修饰键、平台、组合输入、重复和不匹配情况。
- 在 Apple 与非 Apple 平台类别上测试每个默认绑定，包括意外修饰键、组合输入、重复、上下文条件 true/false、动作禁用状态、作用域回退、冲突优先级和阻止默认行为。
- 浏览器验证同时调用可见控件和键盘组合键，确认两者产生相同的状态转换，并检查焦点仍然有效。
- 具体产品绑定记录在所属 Package Guide 中，而不是本仓库标准中。
