# 前端键盘快捷键

## 动作归属

键盘快捷键调用一个具名语义动作，而不是一个孤立的 keydown 回调。拥有该动作的功能同时拥有它的稳定标识符、默认绑定、可用性规则、调用、Tooltip 展示、测试和移除生命周期。

在职责明确的 `*-shortcuts.ts` 归属模块中只定义一次绑定。组件和生命周期 Hook 消费描述符或其匹配函数，而不是重复键码或修饰键逻辑。在多个 Workspace 对同一快捷键引擎产生具体需求之前，产品绑定保留在其产品所有者中。

## 绑定契约

- 在工程契约中把跨平台主修饰键写作 `Mod`。`Mod` 在 Apple 平台映射为 Meta，在其他平台映射为 Control。
- 字母快捷键使用 `KeyboardEvent.code` 匹配，例如 `KeyK`，让物理绑定不受修饰键生成字符的影响。有意依赖生成字符的文本输入行为使用 `key`，并记录这一区别。
- 匹配完整的修饰键集合。拒绝意外的 Shift、Alt、Control 或 Meta，而不是接受含义不明确的超集。
- 忽略输入法组合和重复 keydown 事件，除非具名动作明确支持重复。
- 仅在当前可用动作成功匹配后调用 `preventDefault()`。除非经过审查的作用域边界需要，否则不要调用 `stopPropagation()`。
- 平台检测属于应用组合边界。产品 Package 接收经过校验的平台类别，不读取 `navigator` 或操作系统全局对象。

## 作用域与冲突

键盘事件从最窄的活动作用域向外解析：

1. 打开的 Modal、Menu、Command 界面或其他临时焦点作用域。
2. 获得焦点的 Editor、Terminal 或功能界面。
3. 已挂载的产品 Shell。
4. 应用全局作用域。
5. 应用没有明确保留的浏览器和操作系统行为。

全局快捷键必须使用主修饰键，并代表在焦点位于普通产品内容时仍然有效的动作。不要为了便利动作覆盖无修饰键输入、文本编辑、输入法组合或终端输入。当全局绑定有意覆盖熟悉的浏览器或编辑命令时，要记录产品原因，并通过可见 UI 提供同一动作。

添加绑定前，搜索所有作用域中的同一规范化组合键，并在归属设计中解决冲突。监听器的首次匹配顺序不是冲突策略。

## 展示与本地化

- 只存储一个规范化绑定，并派生其展示形式。不要分别维护匹配字符串和 Tooltip 字符串。
- 在 Apple 平台把 `Mod` 显示为 `⌘`，其他平台显示为 `Ctrl`。使用 `Kbd` 或 `KbdGroup` 展示按键。
- 本地化动作名称，不要本地化键码、修饰键符号或嵌入组合键格式化器的平台名称。
- 可见 Menu Item、Button Tooltip、Command 结果和快捷键参考使用同一个动作描述符与平台格式化器。
- 控件仍然可以通过指针和辅助技术使用。快捷键只是额外调用路径，绝不是唯一方式。

## 生命周期与验证

- 在职责明确的生命周期 Hook 或 Controller 中注册浏览器监听器，并在清理时移除完全相同的监听器。
- 保持事件归一化和描述符匹配为纯逻辑，以便在不使用 React 的情况下测试修饰键、平台、组合输入、重复和不匹配情况。
- 在 Apple 与非 Apple 平台类别上测试每个默认绑定，包括意外修饰键、组合输入、重复、阻止默认行为和动作禁用状态。
- 浏览器验证同时调用可见控件和键盘组合键，确认两者产生相同的状态转换，并检查焦点仍然有效。
- 具体产品绑定记录在所属 Package Guide 中，而不是本仓库标准中。
