# 前端包边界

## 工作区放置

| 关注点       | 规则                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 可运行前端   | 把独立运行入口放在 `apps/*`；应用拥有启动、路由根、认证、部署和平台组合。                                |
| 共享能力     | 把有具体消费者、稳定且可独立测试的库 API 放在 `packages/*`；包绝不导入应用。                             |
| 应用自有代码 | 在另一个工作区需要相同语义能力之前，把展示和行为保留在所属应用中。                                       |
| 提取         | 随第一个真实消费者一起移动能力；可能的消费者或架构图不能证明应创建包。                                   |
| Storybook    | `apps/storybook` 是仓库视觉目录；Story 所有权遵循 [`storybook.md`](storybook.md)，且不改变运行时所有权。 |

不得为组件、Hook、Store、类型或工具函数等源码类别创建包。

## 能力准入

前端包必须：

- 拥有一个具名能力、可审查契约和具体消费者；
- 不导入应用源码或推测性同级包即可运行测试；
- 按 [`docs/PROJECTS.md`](../PROJECTS.md) 在 `project.json` 中声明责任、非目标、运行时和稳定性；
- 使用分布式 `project.json` 作为工作区注册表，不在此重复包目录；并且
- 遵循 [`docs/PACKAGES.md`](../PACKAGES.md) 的命名、导出、构建、依赖、兼容和验证规则。

包按调用方消费的能力命名，不按框架、传输方式或技术桶命名。禁止的桶名称包括 `components`、`hooks`、`store`、`types`、`utils`、`common`、`shared` 和 `helpers`。

`@orchbee/foundation` 本身并不准入某种源码类别。仅当 API 独立于 UI、产品状态、平台副作用及其当前使用方时，它的 `./react` 入口才可以拥有领域中立的 React 原语；准入规则遵循 [`docs/PACKAGES.md`](../PACKAGES.md#foundation-边界)。

## UI 所有权

| 单元           | 所有者和边界                                                                              |
| -------------- | ----------------------------------------------------------------------------------------- |
| 通用 UI 原语   | `@orchbee/ui`；拥有框架无障碍和视觉交互，不包含产品实体、消息、路由、远程数据或平台副作用 |
| 产品语义组件   | 拥有其业务概念、准备后状态和语义动作的应用或产品能力包                                    |
| 共享产品展示   | 仅当多个应用消费相同语义契约时，归属具名产品能力包                                        |
| 框架无关引擎   | 不包含 React、产品对话框、应用状态或宿主副作用的无头能力                                  |
| 组件所有权单元 | 根组件、Props、作用域状态、Hook、私有后代、样式、资产和测试                               |

- 移动完整所有权单元；不得只导出内部片段而留下其状态、样式或测试。
- React 包装器保留在语义消费者中，直到它拥有独立 API 和消费者。
- 通用原语由消费者提供产品可见文本和无障碍文本。
- 递归组件所有权遵循 [`react.md`](react.md)，样式遵循 [`styling.md`](styling.md)，产品消息遵循 [`localization.md`](localization.md)。
- 体验组件与业务组件的分类绝不改变语义所有权。按照 [`experience-components.md`](experience-components.md) 发现并登记经过评审的组合，而不把运行时源码移入跨领域组件桶。

## 依赖方向

应用和包只通过声明的导出消费其他工作区；绝不导入其他工作区的 `src/*` 或 `dist/*`。

| 来源                 | 允许的依赖方向                                    |
| -------------------- | ------------------------------------------------- |
| 产品展示             | 通用 UI、本地化、设计词汇、无头能力和协议契约     |
| 通用 UI 或设计 Token | 绝不依赖产品展示                                  |
| 无头能力             | 绝不依赖其 React 展示                             |
| 协议或验证层         | 绝不依赖传输、持久化、进程生命周期、UI 或产品展示 |
| 运行时实现           | 保留在拥有其生命周期的应用或运行时包中            |

协议与产品展示共享的序列化契约属于协议包；产品展示消费该契约，只保留其客户端本地状态与转换。

通过把共享契约移动到最窄且可独立成立的能力，或在自有端口后反转一个依赖来打破循环；不得用兜底包隐藏循环。

## 平台集成

- 在消费能力中定义导航、文件选择、通知、持久化或传输等窄平台端口。
- 由组合应用提供浏览器、桌面、服务端和测试适配器。
- 在协议或验证边界解析不可信消息；传输行为保留在传输所有者中。
- 包内不得通过宿主检测选择适配器。
- 不得为无关适配器创建通用 `bridge` 或 `platform` 包；只有多个运行时消费同一个具名集成契约时才提取。

## 状态所有权

| 状态或行为                     | 所有者                                 |
| ------------------------------ | -------------------------------------- |
| 局部视觉和交互状态             | 共享它的最窄已挂载组件子树             |
| 产品展示状态和语义 UI 动作     | 所属应用或产品能力包                   |
| 无头能力状态和不变量           | 拥有该能力的包                         |
| 权威进程、服务端或资源生命周期 | 创建和释放它的运行时或服务             |
| 用户偏好和宿主选择             | 组合应用                               |
| 产品消息描述符和翻译           | `@orchbee/i18n`                        |
| 原始进程、存储、IPC 或网络数据 | 在分配内部所有权前于第一个可信边界解析 |

Zustand 只用于拥有状态的浏览器工作区内的共享客户端 UI 状态；把每个 Store 限定在最窄的已挂载所有权树。

## 边界变更

在同一变更中更新受影响的 `project.json` 契约、导出、README、包参考、测试和消费者，并删除旧路径和权威来源。不得把未创建的工作区或实现顺序描述为当前架构。

变更包边界后，运行 [`docs/PACKAGES.md`](../PACKAGES.md#验证和审查) 中的包检查。
