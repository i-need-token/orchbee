# 浏览器存储

## 范围

浏览器存储是设备本地的持久化边界，不是通用数据库。它只能用于少量、非敏感的界面偏好或可恢复的布局状态；这些数据丢失时，不得影响权威产品行为。

本规范约束 `localStorage`、`sessionStorage`、它们的 key 和编解码器，以及任何具有相同同步字符串接口的存储能力。IndexedDB、文件系统存储、远程持久化、缓存、凭据和权威领域记录需要各自的所有者与契约。

## 存储选择

| 需求                                 | 存储边界                           |
| ------------------------------------ | ---------------------------------- |
| 跨重启保留的设备本地偏好             | `localStorage`                     |
| 仅在一个浏览器标签页生命周期存在的值 | `sessionStorage`                   |
| 结构化、大型、事务性或可查询数据     | IndexedDB 或有明确所有者的数据服务 |
| 跨设备或权威产品状态                 | 有明确所有者的后端能力             |
| 凭据、Token、秘密或终端逐字记录      | 禁止使用浏览器键值存储             |

不要仅仅因为方便就选择浏览器存储。功能所有者必须记录为什么该值是本地的、可丢失的、有界的，并且可以安全地暴露给同源脚本。

## 所有权边界

- 拥有被持久化概念的功能或包，同时拥有它的 key、Schema 版本、编解码、校验、回退、迁移和删除生命周期。
- 每个 key 只在职责明确的 `*-storage.ts` 所有者模块中定义一次。组件、Hook、测试和调用方不得重复该字面量。
- 只有应用组合入口可以读取浏览器的 `localStorage` 或 `sessionStorage` 全局对象。入口把收窄后的 `getItem` 和 `setItem` 能力注入功能所有者。
- 展示组件绝不访问浏览器存储。Presenter Hook 或控制器可以协调注入的能力，并暴露准备好的值或语义动作。
- key 应随功能所有者分布。不要创建包级杂项 key 注册表，导致 key 与它所标识的 Schema 和生命周期分离。

## Key 契约

每个持久化 Orchbee key 都使用以下精确形态：

```text
orchbee:<owner>:<record>:v<schema>
```

- `orchbee` 是固定的产品命名空间。
- `<owner>` 是 kebab-case 的工作区或功能所有者。
- `<record>` 是 kebab-case 的持久化概念，而不是组件实现名称。
- `<schema>` 是正整数。从 `v1` 开始；只要存储表示或校验契约不再向后兼容，就递增版本。
- 只使用冒号分隔段。除非存在显式分区需求，否则不要加入环境、Locale、用户提供的数据、时间戳或不透明标识符。

```text
orchbee:editor:panel-width:v1       # 有效的中性示例
editor-panel-width                  # 缺少命名空间和版本
orchbee:Editor:panelWidth:v1        # 大小写不合法
orchbee:editor:panel-width:latest   # 版本不是整数
```

把版本变更视为数据迁移决策。要么显式读取并迁移旧版本，要么忽略它并使用文档规定的默认值。绝不能在 key 不变时静默地用新含义解释旧 Payload。

## 值契约

- 即使只有一个值，也存储 JSON 对象。命名字段让校验、扩展和诊断保持明确。
- 解析为 `unknown`，并在使用前校验完整对象。拒绝缺失字段、意外字段、无效数字、不支持的枚举值以及超出当前产品约束的值。
- 持久化稳定的领域单位。像素布局偏好存储整数像素值；不能存储依赖视口的百分比，之后再把它称作像素。
- 不要序列化 React State、类实例、服务、回调、翻译文案或第三方内部数据结构。
- Payload 必须小且有界。浏览器配额不是容量预算。

## 读写生命周期

- 绝不能在模块求值期间读取浏览器存储。
- 在客户端组合边界解析注入的存储能力。服务端渲染和测试使用功能的确定性默认值，除非它们显式注入 Fake 能力。
- 在所属客户端状态初始化时读取一次。不要在每次渲染时读取。
- 只在已提交的语义变化之后写入。对于拖动交互，应在指针释放或等价的键盘动作完成后持久化，而不是在每次移动事件中写入。
- 不要仅仅因为组件挂载就写入默认值。存储记录应表示真实的用户选择或有意的迁移。
- 来自其他标签页的 storage 事件不会自动成为权威状态。只有当功能契约定义了冲突与顺序行为时，才能选择跨标签页同步。

## 失败与隐私

- 缺失、损坏、过期、不可用以及因配额被拒绝的存储都是预期的边界失败。安全回退，且不得阻塞应用启动。
- 当当前内存行为仍然正确时，可以忽略设备本地偏好写入失败。产品关键持久化需要另一种带有可见诊断的能力。
- 绝不能在浏览器键值存储中保存密码、Access Token、API Key、认证产物、私有终端输出、Agent 逐字记录或权威会话状态。
- 假设同源脚本和浏览器工具能够读取每个存储值。混淆不是加密。
- 退出登录和切换账号时不得泄露账号范围的值。优先不要在本地持久化账号范围数据；否则必须包含显式校验的分区与清理生命周期。

## 验证

- `pnpm lint:storage` 拒绝应用组合入口之外的浏览器存储直接访问、散落的 `orchbee:` 字面量，以及不符合带版本语法的 key。
- 所有者模块单元测试覆盖规范 key、有效往返、损坏输入、范围校验、不可用存储和写入失败。
- 集成测试验证能力注入、默认值恢复，以及只有在用户交互完成后才发生写入。
- 公开偏好、默认值、约束、key 版本或迁移行为发生变化时，同步更新所属包文档。
