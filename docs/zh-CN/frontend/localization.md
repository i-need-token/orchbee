# 前端本地化

## 权威来源和 Locale

| 责任                                                  | 所有者                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------- |
| 用户偏好、平台检测、持久化、有效 Locale 和文档元数据  | 组合应用                                                                        |
| 支持的 Locale、规范化、方向、格式化、描述符和发布目录 | `@orchbee/i18n`                                                                 |
| 产品术语和重复交互文案                                | [`@orchbee/i18n` 产品语言参考](../../../packages/i18n/docs/product-language.md) |
| 对翻译内容的视觉适配                                  | [`visual-foundations.md`](visual-foundations.md)                                |
| 包放置                                                | [`package-boundaries.md`](package-boundaries.md)                                |

| Locale  | 角色             |
| ------- | ---------------- |
| `en-US` | 源 Locale 和回退 |
| `zh-CN` | 必需发布翻译     |

准确使用这些规范 BCP 47 标识符。每次产品消息增加、修改、移动或删除都在同一变更中更新两个目录；回退绝不允许目录不完整。

标识符、注释和工程文档以英语为权威。已本地化消息值是产品资产。

## Locale 解析

按以下顺序解析有效 Locale：

1. 应用支持的显式用户偏好。
2. 有序操作系统或浏览器语言偏好。
3. `en-US`。

- 把英语变体规范化为 `en-US`，把简体中文变体规范化为 `zh-CN`。
- 无效、不支持和繁体中文标识符回退到 `en-US`；绝不把繁体中文静默映射为简体中文。
- 应用组合边界把已验证 Locale 传给 `@orchbee/i18n`；功能包绝不检查宿主 Locale。
- 无需重新加载页面即可更新渲染消息、文档 `lang` 和派生的 `dir`。
- Locale 变更后不重写外部生成的转录或历史外部内容。
- `@orchbee/i18n` 绝不读取宿主全局对象、存储偏好、修改文档或代替应用选择 Locale。

## 目录和 Provider 契约

每个应用的产品语义界面上方只安装一个本地化 Provider。功能包消费它，不创建 Provider、不选择 Locale，也不通过无关层传递已翻译字符串。非 React 适配器使用相同的已验证 Locale 和目录。

`@orchbee/i18n` 是唯一产品本地化系统；其他工作区不得导入 `react-intl` 或拥有产品目录。

| 产物          | 契约                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| Locale 目录   | `packages/i18n/src/locales/<canonical-locale>/<product-domain>.ts`；Locale 目录镜像领域文件名                        |
| 英语值        | 只位于 `locales/en-US/`                                                                                              |
| 简体中文值    | 只位于 `locales/zh-CN/`                                                                                              |
| 描述符组      | `packages/i18n/src/descriptors/` 下的 `packages/i18n/src/descriptors/<product-domain>.ts`，导出为 `<domain>Messages` |
| 描述符默认值  | `defaultMessage` 引用匹配的 `en-US` 目录值，不重复英语文案                                                           |
| 运行时目录    | 每个 Locale 一个完整目录，并包含相同稳定 ID                                                                          |
| 公共 API 指南 | 导出名称和消费者示例位于所属包 `README.md`                                                                           |

稳定 ID 和英语译者描述是源码元数据。增加领域绝不创建另一个 Provider 或 Locale 契约。

## 产品消息边界

| 本地化                                                      | 不翻译                                                           |
| ----------------------------------------------------------- | ---------------------------------------------------------------- |
| 标题、描述、标签、按钮、菜单、Tooltip、placeholder 和空状态 | 用户值、项目名、文件路径、命令、源码、协议标识符、日志或工具输出 |
| 加载、验证、确认、错误、状态和通知消息                      | 产品名称和已批准技术术语                                         |
| `aria-label`、`title`、`alt` 和视觉隐藏的产品文本           | 原始内部异常或边界诊断                                           |
| 产品自有 onboarding 和指南                                  | 外部生成的内容                                                   |

- 内部失败携带稳定代码和结构化值；UI 把预期代码映射为本地化消息，把意外失败映射为本地化通用消息。
- 原始异常文本可以进入自有诊断通道，但绝不成为产品文案。
- 通用 UI 原语由产品语义消费者提供消费者可见文本和无障碍文本。
- 带固定语言默认值的注册表原语进入产品界面前必须适配。

## 术语和交互文案

所有发布 Locale 都以 [`@orchbee/i18n` 产品语言参考](../../../packages/i18n/docs/product-language.md)作为已批准产品术语映射和重复交互标签的权威来源。

- 新增或修改产品文案前查阅该参考。如果重复出现的产品概念或容易产生歧义的交互尚无条目，在实现受影响产品消息时补充一项具体决策。
- 已批准术语或交互标签发生变化时，在同一个变更中更新该参考和所有受影响的 Locale 目录。
- 根据结果使用具体动作标签：创建、保存、提交处理、应用、确认、知悉、取消、关闭、删除和移除是不同动作。
- 不要强迫不同含义使用相同文案，也不要仅为获得一致文本而复用无关消息 ID。
- 运行时目录拥有完整的上下文相关消息。该参考拥有稳定用词，不是第二套目录。

## 消息标识符和语法

使用说明所属领域和用途的稳定语义 ID：

```text
navigation.actions.open
navigation.emptyState.title
```

- 绝不把英语句子用作 ID、把 Locale 编入 ID，或因当前英语文案相同而复用无关 ID。
- 位置、语气或变量含义不明显时增加英语译者上下文。
- 编写一条完整可翻译意思；绝不拼接片段或假设英语词序。
- 使用 `{itemTitle}` 等具名变量和 ICU MessageFormat `plural`、`select`、数字、日期及时间参数。
- 富文本使用应用控制的具名占位符；翻译不包含任意 HTML，也绝不使用 `dangerouslySetInnerHTML`。

## 运行时和布局

- 功能代码格式化已导出描述符，不直接渲染面向产品的字符串字面量。
- 回退只有一条路径：协商回退到 `en-US`，缺失翻译回退到英语描述符默认值，无效或缺失描述符属于开发错误。
- 数字、列表、日期、时间、相对时间和显示名称使用 Locale 感知格式化器。
- 存储和传输 Locale 无关值；在展示时使用有效 Locale，并在需要时使用显式时区格式化。
- 使用固有尺寸或 `min-height`，让翻译内容无需缩小排版即可换行。
- 不得从英语派生固定宽度、只在 placeholder 中放置必需说明、把文本编码进图片，或截断必需动作、错误和说明。
- 用户数据只有在完整值仍可访问时才能截断。
- 在两个 Locale 下审查换行、缩放、焦点顺序、键盘访问和无障碍名称。

## 验证

| 检查       | 必需结果                                                     |
| ---------- | ------------------------------------------------------------ |
| 目录一致性 | 源描述符和每个发布目录包含相同 ID                            |
| ICU 兼容   | 每条消息都能解析，且对应 Locale 值使用兼容变量               |
| 解析       | 覆盖精确匹配、支持的变体、无效输入、不支持语言和繁体中文回退 |
| 渲染       | 代表性界面在 `en-US` 和 `zh-CN` 下渲染                       |
| 原始字符串 | 变更后的产品代码不包含无所有者的可见或仅无障碍产品字符串     |
| 语言审查   | 变更后的文案遵循已批准术语和重复交互标签                     |
| 布局       | Storybook 和视觉审查覆盖文本扩展、换行、缩放和窄布局         |
| 仓库门禁   | `pnpm verify` 通过                                           |

默认断言行为和消息身份；只有 Locale 选择、插值或文案本身是被测行为时，才断言准确翻译输出。

主要参考：[React Intl](https://formatjs.github.io/docs/react-intl/)、[消息描述符](https://formatjs.github.io/docs/react-intl/api/#message-descriptor) 和 [ICU 语法](https://formatjs.github.io/docs/core-concepts/icu-syntax/)。
