# 前端对话框与表单

## 权威范围

本规范管理 Orchbee 自有产品流程在要求用户做出决定、确认或输入数据时的表面选择与交互行为。
它适用于浏览器和 Desktop React 界面中的行内编辑器、锚定式披露、持久面板、Dialog、表单、
Alert Dialog 和独立任务表面。

视觉几何遵循 [`visual-foundations.md`](visual-foundations.md)，已评审组合遵循
[`experience-components.md`](experience-components.md)，语义副作用遵循
[`actions.md`](actions.md)，产品文案遵循 [`localization.md`](localization.md)。`Dialog`、
`Sheet`、`Popover` 或 `Form` 原语只提供机制；它的名字绝不能证明该表面适合当前任务。

## 中断预算

- 从不增加表面、不提出问题开始。当权威上下文或安全默认值已经确定结果时，直接调用可逆
  Action；需要时提供上下文反馈或撤销。
- 只询问当前结果所必需的信息。复用用户在当前流程中已经提供的权威值，推导安全值，并推迟
  可编辑元数据。
- 保留用户当前上下文。后台状态、教育、可选设置、成功以及可恢复的后台失败绝不能打开模态
  表面或抢夺焦点。
- 仅由需要响应的 Action 或事件打开中断表面。不能仅因为某项能力可用就反复提示。
- 选择能够满足任务状态、后果和无障碍要求的最低中断表面。实现便利不是准入理由。

各自独立且可逆的设置在其所属控件上直接生效，并提供重置或撤销。只有多个值构成一个原子
配置、必须联合验证，或提交会启动外部副作用时，才使用显式提交边界。

## 表面选择

| 表面                  | 使用条件                                                     | 避免条件                                                   |
| --------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 不增加表面            | 现有上下文和安全默认值能确定一个可逆结果                     | 结果有歧义，或必须先审查其后果                             |
| 行内编辑器或披露      | 一个上下文值可以在不遮挡被编辑对象的情况下修改               | 任务需要原子化的多值草稿或排他注意力                       |
| Menu 或锚定式 Popover | 小型有限选项或一个简短上下文输入属于可见触发器               | 内容很长、高风险、多步骤，或必须在与其他区域交互时继续存在 |
| 持久面板或页面        | 用户需要比较上下文、调整可选设置、再次访问值，或继续其他工作 | 在一个有限决定完成前必须让父级不可交互                     |
| 模态 Dialog           | 一个明确任务满足[模态准入](#模态准入)契约                    | 表面只报告信息、收集便利性元数据，或包含很长的流程         |
| 独立任务表面          | 任务很长、包含多步或导航，或需要大量上下文和恢复             | 一个简短决定可以安全返回当前上下文                         |

任何让应用其余部分不可交互的表面都是模态的，无论组件名称是 Dialog、Sheet、Drawer 还是
Popover。响应式呈现可以改变几何，但必须保留模态性、提交、取消和焦点行为。

## Dialog 与表单组合

Dialog 与表单是可以组合、但绝不能互相推导的独立责任：

| 责任            | 管理内容                                                       | 不管理的内容                                                   |
| --------------- | -------------------------------------------------------------- | -------------------------------------------------------------- |
| Dialog 外壳     | 模态机制、几何、标题层级、可选说明、关闭控件、底部操作区和焦点 | 字段语义，或对任务主体一定是表单的假设                         |
| Dialog 任务主体 | 当前任务表示，例如表单、选择器、列表、提示、进度或恢复状态     | 第二套外壳层级，或根据内容类型重新设置外壳样式的权限           |
| 表单            | 问题、值、标签、控件、帮助、校验、草稿状态和提交语义           | 表面准入、模态性、外层标题、关闭行为、几何或外层任务底部操作区 |

Dialog 外壳契约适用于每个 Dialog，包括任务主体不含表单的 Dialog。表单契约适用于表单出现的
任何位置，包括行内编辑器、Popover、Dialog、持久面板或页面。原语组合可以连接两者的提交与取消
Action，但不会合并它们的责任所有权。

## 直接操作与专家输入

当一个语义值同时支持直接选择和精确文本输入时，应把两条路径保留在同一个稳定任务表面内：

- 默认使用成本更低的直接表示，例如面包屑和文件夹列表。只有用户主动要求时才展示文本输入。
- 在原位置用编辑器替换直接表示。不能为了暴露专家输入而追加第二行表单、打开另一个 overlay，
  或移动周围内容和 Action。
- 在直接表示、编辑、过滤和加载投影之间，保持被替换区域的块尺寸以及任务主体视口稳定。不能仅仅
  因为标签、状态或结果行出现或消失，就让 Dialog 改变尺寸或重新居中。
- 在有界的原地导航期间，保持上一个有效视图清晰可读、阻止对过期内容做出决定，并在稳定的任务
  视口内叠加不改变尺寸的进度指示。不要通过淡化整个任务或插入会移动周围内容的状态行来表达加载。
- hover 和键盘 focus 都要展示编辑入口。按钮具有本地化的无障碍名称；Tooltip 可以加强该名称，
  但绝不能成为唯一发现路径。
- 将最后一个规范值与文本草稿分开。输入可以过滤或建议有界候选项，但不能自行提交、导航或
  清除最后一个有效视图。
- 把候选结果作为实时验证。部分或无效草稿继续保留最后一个有效上下文，并解释主要 Action
  不可用的原因；仅有禁用样式不构成解释。
- 只有结果无歧义时，Enter 才接受精确匹配或用户明确高亮的候选项。Escape 离开文本输入模式并
  恢复规范表示；任务的取消 Action 仍然取消其明确声明的任务边界。
- 合并异步候选请求，并将结果绑定到最新草稿和来源作用域。过期响应绝不能替换更新的候选项、
  选择或规范上下文。

## 模态准入

模态表面至少需要满足以下一个理由：

- 在一个原子草稿经过审查和提交期间，父级不得发生变化；
- 一个明确的前台操作必须立即获得响应才能继续，并且忽略或推迟响应不是有效结果；或者
- 一个简短决定用于防止难以恢复的严重后果。

每个获准的模态表面还必须只有一个边界明确的语义结果、较短的完成路径、提交前明确的安全
出口，以及足以做出决定的内部上下文。当用户必须检查或操作被遮挡的父级、比较大量信息、
在层级中导航，或反复返回时，把任务移到持久面板或独立表面。

不能用模态表面承载被动信息、成功确认、普通验证错误、可选引导、提醒、常规单值编辑或能够
安全转入后台的进度。不能堆叠模态表面。临时子任务应在同一个所有者下替换当前模态主体和
Action，或者先关闭第一个模态表面，再打开另一个。

对于容易恢复的 Action，优先直接执行并提供撤销。只有一个简短的重要消息必须获得决定时，
通常是在不可逆或难以逆转的副作用前，才使用 Alert Dialog。Alert Dialog 不包含普通表单、
进度流程或纯信息确认；当意外确认代价很高时，初始焦点应落在破坏性最小的 Action 上。

## 紧凑桌面 Dialog 外壳

紧凑桌面 Dialog 不会把通用原语中较大的默认排版直接当作产品层级。无论任务主体是表单、
选择器、列表、提示、进度视图还是可恢复失败，其每个状态都统一使用以下外壳组合：

| 外壳部分                     | 排版角色                         | 展示规则                                     |
| ---------------------------- | -------------------------------- | -------------------------------------------- |
| 一个状态特定标题             | `--ob-sys-typography-heading-xs` | 常规字重；通过位置和间距建立层级             |
| 说明、状态、错误和普通主体   | `--ob-sys-typography-body-sm`    | 常规字重；通过语义颜色建立优先级或状态       |
| 底部操作和简短任务控件       | `--ob-sys-typography-control-sm` | 常规字重；通过控件几何和主要表面建立强调     |
| 原样命令、路径、标识符或提示 | `--ob-sys-typography-code-sm`    | 只在值确实类似代码时使用                     |
| 补充按键提示                 | `--ob-sys-typography-label-xs`   | 从属于本地化操作标签，并从其无障碍名称中隐藏 |

不要仅因为文本是标题、字段标签或主要操作就增加字重。只有在位置、间距、语义颜色和控件表面已经
应用后，层级仍然不明确时，才使用更强的标签或标题角色。内层步骤只改变文案和操作，不改变这套
外壳层级。任务主体内容绝不能仅仅因为不是表单，就选择另一套外壳标题或底部操作排版。

## 表单契约范围

下面的问题预算、字段契约、校验、草稿和提交规则独立于外层表面，适用于每个产品表单。表单
继承外层表面的任务边界与外壳；它不会创建或重新定义模态性、几何、标题层级、外层关闭行为或
焦点约束。

## 问题预算

设计控件前，先对每个拟议值分类：

| 分类     | 处理方式                                                     |
| -------- | ------------------------------------------------------------ |
| 当前必需 | 只有当前结果缺少用户提供的值就无法有效生成时才询问           |
| 可推导   | 从权威上下文计算，不要求用户重复输入或确认                   |
| 有默认值 | 应用安全且不意外的默认值；仅当修改它会影响当前决定时才展示   |
| 可推迟   | 从流程中省略，稍后由所属资源或 Settings 表面编辑             |
| 当前可选 | 只有它会实质性改变即时结果，且合理用户可能现在需要它时才展示 |

如果一个可选值稍后修改不会造成损失、成本或实质不同的结果，就应推迟而不是展示。其余“当前
可选”值放在主路径之后，归入默认收起、以用途命名的披露区域。不能用“高级”替代对效果的解释。
一次交互中，披露区域在展开和收起期间保留草稿；取消则丢弃完整草稿。

不要把已知上下文渲染为禁用或只读表单控件。应把它呈现为文本、元数据或摘要；如果复制有用，
提供单独的复制 Action。只有标签和辅助文本明确说明结果时，空值才能表示有意恢复默认值。

## 字段契约

- 在紧凑桌面表单中，字段标签和简短控件使用 `--ob-sys-typography-control-sm`，辅助和错误文本
  使用 `--ob-sys-typography-body-sm`，确实类似代码的输入使用
  `--ob-sys-typography-code-sm`。在已准入表面之间移动表单不会改变这些角色。
- 每个控件都有持久可见标签。单独可见的可选字段应在标签后添加本地化的“（可选）”，除非
  外层带标题的分组已经说明整个分组均为可选。绝不能用星号标记必填字段。
- 标签使用最短且无歧义的问题或值名称。辅助文本只解释不明显的原因、后果、格式、隐私边界
  或恢复规则。
- placeholder 是可选的。它绝不能替代标签、承载持久指令，或仅为了填充空控件而存在；当示例
  在输入后仍然有用时，优先使用可见示例。
- 预填权威当前值。除非安全性要求重新证明，否则不要要求用户重新输入 Orchbee 已知的信息。
- 为该值选择语义正确的控件和属性，包括适用时的 `type`、`autocomplete`、`inputmode`
  和 `spellcheck`。必填状态和验证关系必须以程序可识别的方式暴露。
- 密钥响应应说明发送位置以及是否存储。它仅在直接提交前存在于输入框中，并在提交、取消、
  失败和卸载时清除。
- 将有界且原样的认证提示放在隐私说明和密钥字段旁边。除非主机指纹等结构化内容需要保持
  可独立检查，否则不要在单独的视觉面板中重复该提示。

## 验证与 Action

- 当前任务中只保留一个主要 Action。它的本地化标签应描述结果，例如“连接”或“保存”；只有
  会前进到另一个可见步骤时才使用“继续”。
- 非破坏性的取消 Action 位于主要 Action 之前。每条退出路径都必须明确属于哪个任务边界。
  在单步骤表面中，Close、Escape、背景点击和取消只要启用，就具有相同的“不提交”结果。
  在提交前的多步骤表面中，取消和 Escape 取消最内层前台步骤并恢复前一个稳定步骤；外层关闭
  控件和背景点击则退出完整表面。绝不能把步骤内的取消接到完整关闭，也不能把外层关闭表现为
  步骤内取消。
- 不要让禁用提交成为唯一的验证说明。当用户有理由认为可以提交时，应接受尝试、展示本地化
  字段错误并聚焦第一个无效字段。只有存在正在执行的重复提交，或表面已经解释了尚未满足的
  前置条件时，才禁用提交。
- 在失焦或提交等有意义的交互后验证。不要在用户能够回答前显示错误；修复条件时清除错误；
  不得暴露原始异常。
- 可恢复失败后保留非密钥输入。提交只原子提交一次完整且已验证的草稿；提交点前取消不会产生
  语义变更。
- 可恢复失败必须标识有界且非密钥的精确对象或提交值，使用户能够把它与其他活动、已保存或
  已配置项区分开。不能让用户猜测究竟是哪个连接、路径、账户或命令失败，也绝不能重复密钥
  响应。
- 保留原生表单行为。只有聚焦控件、输入法和当前步骤都能让提交含义明确时，Enter 才提交；
  多行响应绝不能由 Enter 提交。
- 在紧凑的桌面端 Dialog 中，当 Escape 始终取消当前任务、且未带修饰键的 Enter 始终
  调用当前无歧义的主要 Action 时，在对应的底部按钮内显示 `Kbd` 提示；该 Action 可以是单行
  表单提交，也可以是被有意设为默认焦点的恢复 Action，例如重试。提示只是补充信息，应从
  无障碍名称中隐藏，因为本地化 Action 标签已经说明结果。
- 可见按键提示是对步骤默认编辑上下文的声明，不会覆盖原生控件激活。当输入法组合、多行
  输入、确认安全性或工作流状态可能导致按键在初始焦点或可编辑焦点上执行其他 Action 或不
  执行 Action 时，应省略提示。显式获得焦点的按钮仍然接收原生 Enter 激活。
- 当 Dialog 原地切换到具有默认 Action 的状态时，在新状态渲染后建立焦点，或提供有作用域的
  无修饰键处理。仅有主要样式和 `Kbd` 提示并不会产生键盘操作权。

## 取消与异步工作

按照 [`actions.md`](actions.md#异步生命周期) 将已提交工作分类为前台、后台或外部工作。
只有离开会让结果不安全或不可观察时，模态表面才为前台工作保持打开。如果已接受的工作可以
安全继续，就关闭模态表面，通过所属的非干扰活动表面报告进度。

- 前台工作等待期间，只要当前对象可能与其他活动、已保存或已配置项混淆，就持续显示有界、
  非密钥的精确操作对象。让该上下文贯穿中间提示和恢复状态，不能要求用户记住之前的界面。
- 定义提交点。在提交点前，每条已启用的关闭路径都请求取消并释放操作所属资源；提交点后，
  UI 绝不能把已提交工作重新标记为已取消。
- 按语义操作身份和作用域防止重复工作，不能使用进程级或组件全局的“Dialog 忙碌”标志。
- 取消、关闭、失败、传输丢失和卸载都是幂等清理路径。任何路径都不能遗留会阻止新调用的
  lease 或锁。
- 从前台子步骤返回是一条取消边界，而不只是视觉导航。恢复前一步之前，它必须撤销当前提示或
  选择、终止提交前工作、使旧交互身份失效、清除密钥输入、保留外层非密钥草稿，并隔离所有
  延迟完成。
- 延迟完成不能重新打开表面、抢夺焦点、覆盖更新的草稿，或把用户从后续工作中导航走。只能
  通过仍然拥有交互的 token 或非干扰结果通道发布。
- 取消后重新打开时，从当前权威状态开始，除非功能明确拥有可恢复草稿。绝不能恢复密钥响应。
- 不要为廉价、容易重建的草稿增加丢弃确认。当关闭会丢失大量用户创作内容时，解释后果并
  提供明确的“继续编辑”和“丢弃”结果。

## 焦点、键盘与无障碍

- 使用共享原语提供模态语义、背景不可交互、焦点约束和无障碍命名。不要手写焦点陷阱；如果
  指针或键盘仍能访问父级，也不能把表面标记为模态。
- 有意设置初始焦点：简短表单使用第一个尚未解决的必填控件；必须先阅读结构化内容时使用静态
  标题或介绍；代价高且不可逆的决定使用破坏性最小的 Action。
- Tab 和 Shift+Tab 保持在模态表面内。Escape 取消最内层可取消任务，并按声明的任务边界返回
  前一个稳定步骤或关闭完整表面。完整关闭后将焦点还给调用者；如果调用者已不存在，则移到
  已完成 Action 创建的逻辑结果。
- 在 Tab 顺序中保留可见关闭或取消控件。Dialog 必须有可见的本地化标题；只有说明能够作为
  一个易懂单元朗读时，才关联简短说明。
- 把提示和错误文本关联到控件。礼貌地播报异步进度；只有失败需要立即关注时才使用 alert。
- 验证指针、键盘、辅助技术、粗粒度指针、窄视口、缩放和两种已交付 locale 的行为，且不能
  改变语义顺序。

## 建模与证据

实现新增或实质变更的表单或中断表面前：

1. 说明用户意图，以及每个更低中断表面不足的原因。
2. 按问题预算对每个拟议值分类，并从主路径移除可推导、有默认值或可推迟的控件。
3. 执行体验组件发现流程并选择复用、扩展、替换或新增。可复用的 Dialog 组合本身并不满足
   模态准入。
4. 对适用的已关闭、编辑、披露、无效、提交中、取消中、已完成、失败、延迟完成和重新进入
   转换建模，包括替代输入模式、规范值与草稿值、提交点和副作用所有者。
5. 将 Story 和测试映射到表面选择、两种 locale、初始和恢复焦点、键盘路径、验证时机、重复
   提交、适用时直接选择与文本输入的一致性、过期候选结果、每条取消路径、可恢复失败、延迟
   完成以及干净的重新进入。

所属 Manifest 应记录 `useWhen`、`avoidWhen` 和不变量，以保留已选表面、问题预算、取消
和焦点行为。现有表面在发生实质变更时接受此审查；被触及的表面不得扩大不合规的中断或字段
模式。
