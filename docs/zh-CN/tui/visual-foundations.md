# TUI 视觉基础

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的颜色角色、主题契约、文本层级、框架、字形和显示宽度规则：
即 Rust Client 绘制到字符单元格网格上的每个表面，包括围绕保留终端 pane 的 chrome。在原生
Client 中编写或审查渲染代码前先阅读本标准。

区域组合和尺寸层级遵循 [`layout.md`](layout.md)；状态、提示和覆盖层行为遵循
[`overlays-and-status.md`](overlays-and-status.md)；宿主能力探测遵循
[`terminal-environment.md`](terminal-environment.md)。
[`frontend/design-tokens.md`](../frontend/design-tokens.md) 中的前端 Token 注册表不适用于单元格
网格，但其"组件只消费语义角色、主题提供具体值"的规则同样适用。

终端 pane 的内容属于运行在其中的程序。这些规则只约束 Orchbee 绘制的单元格。

## 选择规则

- 按含义选择颜色或修饰符，绝不能因为外观像另一个元素，或因为当前值在某个终端上看起来正确就
  选择。
- 渲染代码只引用语义角色。`ratatui::style::Color::Rgb`、`Color::Indexed` 和具名 ANSI 变体只出现在
  把角色映射为值的主题模块内。此规则由审查执行；目前没有自动检查。
- 每个可见状态只有一个角色。不要用两个角色拼出一个状态，不要借用状态颜色做强调，也不要用
  颜色代替修饰符表达层级。
- 用户显式配置的 token 前景色/粗体/淡化覆盖属于展示数据，由主题边界叠加到各 token 的
  语义角色；渲染代码仍不构造颜色。状态 token 使用状态角色，普通值使用文字角色，焦点及
  序号标记保持独立角色；用户样式不改变状态或身份。
- 如果没有适合的角色，停下来并通过主题所有者提出角色变更。不要添加局部常量。

## 颜色角色与主题

主题把下面的每个角色映射为一个具体值。缺少任何角色的主题都是无效的。角色是稳定的名称；
主题改变的是值。

| 角色族    | 角色                                             | 使用场景                                                           |
| --------- | ------------------------------------------------ | ------------------------------------------------------------------ |
| `text`    | `primary`、`secondary`、`disabled`、`inverse`    | 按信息优先级区分的内容与 chrome 文本；`inverse` 只用于已填充的表面 |
| `accent`  | `focus`、`selection`、`link`                     | 获得焦点的框架或控件、当前选择，以及可激活的引用                   |
| `status`  | `success`、`warning`、`error`、`info`、`pending` | 只表达结果和状态含义；绝不用于装饰或层级                           |
| `frame`   | `focused`、`unfocused`、`divider`                | pane 和覆盖层的边框以及分屏边界                                    |
| `surface` | `chrome`、`overlay`、`selection`、`inactive`     | 持久 chrome、覆盖层、选中行的背景，以及未聚焦 pane 的遮罩          |
| `hint`    | `key`、`label`                                   | 页脚和帮助中的按键字形及其动作标签                                 |

主题规则：

- 每个原生 Client 都提供 `terminal-native` 主题，并在宿主明暗或色深未知时使用它。在显式用户
  设置选择其他主题之前，它是默认主题。
- `terminal-native` 主题把文本和表面角色映射到终端默认前景和背景（`Color::Reset`），把强调、
  状态和框架角色映射到具名 ANSI-16 颜色。它用 `DIM` 修饰符而不是灰色表示 `text-secondary`，
  这样弱化效果在浅色和深色背景上都跟随宿主调色板。
- RGB 主题针对一种背景明暗设计，只有在通过探测或显式设置得知宿主明暗时才可选择。它声明自己
  的明暗极性。
- 主题所有者在启动时按检测到的色深（真彩、256 色或 16 色）用最近感知匹配对主题值量化一次。
  渲染代码绝不检查色深，也绝不按当前主题分支。
- 主题值变更需对照消费该角色的每个表面审查；新增角色需在同一变更中更新每个随附主题。

任何主题都禁止：用 `DarkGray`（亮黑）做文本，因为许多配置把它映射得接近背景；在未填充表面上
用 `White` 或 `Black` 做文本；在 `terminal-native` 主题的 `Color::Reset` 上用 `Yellow` 或 `Blue`
做文本，因为它们的对比度取决于明暗极性。

## 文本层级

层级描述信息优先级，而不是交互状态。

| 层级 | 呈现                    | 使用场景                               |
| ---- | ----------------------- | -------------------------------------- |
| 标题 | `text-primary` + `BOLD` | 覆盖层标题和章节标签                   |
| 主要 | `text-primary`          | 值、标签，以及用户做决定必须阅读的内容 |
| 次要 | `text-secondary`        | 辅助文案、元数据、时间戳和按键提示标签 |
| 禁用 | `text-disabled`         | 为可发现性而保持可见的不可用动作       |

- 一个区域最多使用这三个可见层级。额外结构来自间距、分组或框架，而不是更多颜色或 `ITALIC`。
- `BOLD` 标记标题或当前项；绝不标记警告。`UNDERLINED` 只标记 `accent-link`。chrome 中禁止
  `REVERSED` 和 `BLINK`；`BLINK` 在任何地方都禁止。
- 状态角色只给状态字形或状态词着色，而不是整行。

## 交互状态

| 状态        | 呈现                                                                            |
| ----------- | ------------------------------------------------------------------------------- |
| 聚焦区域    | `frame-focused` 边框；无框架区域用标题上的 `accent-focus` 标记焦点              |
| 未聚焦 pane | `frame-unfocused` 边框；只有所有者明确记录时，`surface-inactive` 才可遮罩其内容 |
| 选中行      | 覆盖整行宽度的 `surface-selection` 背景                                         |
| 当前 Tab    | `accent-focus` + `BOLD`；非当前 Tab 使用 `text-secondary`                       |
| 指针悬停    | 无视觉变化；单元格网格没有可靠的悬停                                            |
| 等待中      | `status-pending` 字形加本地化动词；帧宽度固定                                   |
| 禁用        | `text-disabled`；动作连同原因保留在帮助中                                       |

同一时刻只有一个区域显示焦点。焦点在每个布局层级中都可见。

## 边框与框架

- 框架使用单线制表字符。圆角是统一应用的主题选项；表面绝不自行选择角样式。
- 相邻 pane 共享一个边界单元格。不要在两个 pane 之间绘制两条边框。
- 框架标题对标签从末尾截断并加省略号，对路径从中间截断。它绝不撑大框架，也绝不换行。
- 只有内部区域在每个维度至少有一个单元格时才绘制框架；低于此值只绘制边界线或什么都不画。
  绝不绘制残缺的框架。
- chrome 区域之间的分隔线使用 `frame-divider`；宽度为一个单元格。

## 字形

- chrome 假定宿主使用 UTF-8。允许制表符、箭头、`…` 和 `•`。当
  [`terminal-environment.md`](terminal-environment.md#能力探测) 报告非 UTF-8 locale 或启用了简化
  字形时，每个非 ASCII 字形都通过其声明的 ASCII 回退渲染。
- chrome 中禁止私有区字形、Nerd Font 图标和 emoji：它们的宽度依赖宿主，且不保证存在。
- 每组交替帧的字形（如 spinner）保持恒定显示宽度，避免邻近内容抖动。
- 一个字形在整个 Client 中只有一个含义。字形含义与所属表面一同记录。

## 显示宽度与文本安全

- 按显示宽度度量文本，绝不按 `char` 或字节数。东亚宽字符占两个单元格；组合标记占零个。度量、
  截断和布局使用同一个宽度函数。
- 截断标记用同一宽度函数度量，并在文本之前预留预算。`…` 属于东亚模糊宽度；其 ASCII 回退是
  `..`。
- 散文按显示宽度在词边界换行。除非单个 token 本身超过行宽，否则不要在 URL 或文件路径内部
  断开。
- 来自 Client 之外的文本在绘制到 chrome 前先净化：从标签、标题和路径中去除控制字符、转义序列
  和换行。chrome 缓冲区绝不解释来自用户或进程数据的 ANSI。
- 绝不为了适配而缩小、丢弃或缩写必需的动作或说明；用 [`layout.md`](layout.md#尺寸层级) 中的
  层级选择更短的已记录形式。

## 验证

| 变更             | 必需检查                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| 新增或修改表面   | 在 `terminal-native` 和一个 RGB 主题下，按 [`verification.md`](verification.md#渲染证据) 中每个必需几何渲染 |
| 主题角色或值变更 | 重新渲染每个消费表面；16 色量化结果不含任何 `Rgb` 或 `Indexed` 单元格                                       |
| 外部来源文本     | 测试证明控制字符和转义序列不会到达缓冲区                                                                    |
| 截断或换行       | 测试包含宽字符和一个比行更宽的 token                                                                        |
| 新增字形         | 已声明其 ASCII 回退，并在简化字形测试中渲染                                                                 |
