# TUI 视觉基础

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的颜色角色、主题契约、文本层级、框架、字形和显示宽度规则：
即 Rust Client 绘制到字符单元格网格上的每个表面，包括围绕保留终端 pane 的 chrome。在原生
Client 中编写或审查渲染代码前先阅读本标准。

区域组合和尺寸层级遵循 [`layout.md`](layout.md)；状态、提示和覆盖层行为遵循
[`overlays-and-status.md`](overlays-and-status.md)；宿主能力探测遵循
[`terminal-environment.md`](terminal-environment.md)。GUI/TUI 共同含义、层级和主题对应关系遵循
[`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md)。
[`frontend/design-tokens.md`](../frontend/design-tokens.md) 中的前端 CSS 注册表与原生主题模块
在各自媒介中实现这些角色；渲染消费角色，主题提供具体值。
可复用控件及其状态组合遵循 [`components.md`](components.md)。

下述角色清单是新增和迁移渲染代码必须达到的契约。它出现在标准中并不代表每个现有原生主题或表面
已经完成采用；实现支持只能由源码和必需渲染证据建立。

终端 pane 的内容属于运行在其中的程序。这些规则只约束 Orchbee 绘制的单元格。

## 选择规则

- 按含义选择颜色或修饰符，绝不能因为外观像另一个元素，或因为当前值在某个终端上看起来正确就
  选择。
- 渲染代码只引用语义角色。`ratatui::style::Color::Rgb`、`Color::Indexed` 和具名 ANSI 变体只出现在
  把角色映射为值的主题模块内。此规则由审查执行；目前没有自动检查。
- 可见状态的每个视觉通道只使用一个角色。控件可以组合相互独立的通道，例如用背景表达指针交互、
  用标记表达键盘焦点、用字形表达控件声明边界上的已选值。不要在同一通道组合两个角色，不要借用
  状态颜色做强调，也不要用组件局部颜色或修饰符绕过 `text` 角色。
- 用户显式配置的 token 前景色/粗体/淡化覆盖属于展示数据，由主题边界叠加到各 token 的
  语义角色；渲染代码仍不构造颜色。状态 token 使用状态角色，普通值使用文字角色，焦点及
  序号标记保持独立角色；用户样式不改变状态或身份。
- 如果没有适合的角色，停下来并通过主题所有者提出角色变更。不要添加局部常量。

## 颜色角色与主题

主题把下面的每个角色映射为一种具体样式。样式可以包含前景、背景或允许的修饰符。缺少任何角色
的主题都是无效的。角色是稳定的名称；主题改变的是值。

| 角色族    | 角色                                                                                                      | 使用场景                                                                                                                   |
| --------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `text`    | `primary`、`secondary`、`disabled`、`inverse`                                                             | 按信息优先级区分的内容与 chrome 文本；`inverse` 只用于已填充的表面                                                         |
| `accent`  | `action`、`destructive`、`focus`、`selection`、`link`                                                     | 静止的主要动作、明确破坏性意图、获得焦点的框架或控件、临时或已勾选指示器、选区边界，以及可激活的引用                       |
| `status`  | `success`、`warning`、`error`、`info`、`pending`、`working`、`idle`、`unread`                             | 只表达结果和状态含义；绝不用于装饰或层级                                                                                   |
| `agent`   | `attention`、`done`、`error`                                                                              | 只用于“需要关注”“已完成”“失败”的 Agent 状态字形；绝不用于文字、状态词或强调                                                |
| `frame`   | `focused`、`unfocused`、`divider`、`guide`                                                                | pane 和覆盖层的边框、分屏边界及低对比度层级引导线                                                                          |
| `surface` | `canvas`、`chrome`、`strip`、`overlay`、`hover`、`pressed`、`selection`、`current`、`related`、`inactive` | 终端画布、持久 chrome、标签栏、覆盖层、指针反馈、按下控件、临时或范围选择、持久当前上下文、关联祖先的背景，以及非活跃 pane |
| `hint`    | `key`、`label`                                                                                            | 页脚和帮助中的按键字形及其动作标签                                                                                         |

主题规则：

- `frame-guide` 比区域分隔线更淡。`surface-related` 标识当前或临时选中条目的祖先，其填充弱于该
  条目自身的表面；它不会转移焦点或选择，祖先自身的直接交互优先。未知宿主和低色彩主题可以使用
  基础背景，通过层级和独立标记保留关联信息。
- 每个原生 Client 都提供 `terminal-native` 主题，并在宿主明暗或色深未知时使用它。在显式用户
  设置选择其他主题之前，它是默认主题。
- `terminal-native` 主题把文本和基础表面（`canvas`、`chrome`、`strip` 与 `overlay`）映射到终端
  默认前景和背景（`Color::Reset`）。它通过下文的配对颜色和修饰符回退解析当前及交互表面，并把强调、
  框架和其余状态角色映射到具名 ANSI-16 颜色。`status-working` 使用终端默认前景，`status-idle`
  使用加 `DIM` 的默认前景，因此两者在任一明暗极性上都清晰可读。它用 `DIM` 修饰符而不是灰色
  表示 `text-secondary`，这样弱化效果在浅色和深色背景上都跟随宿主调色板。
- `surface-current` 通过中性填充区分持久上下文与强调选区。在 `terminal-native` 中，它使用
  成对的 ANSI 前景／背景色：随宿主变化的正文与元数据文字，以及随宿主变化的 `status-working`
  和 `status-idle` 字形，在该填充上采用配套前景。次要文字与 `status-idle` 在此取消 DIM；工作状态
  保留其呼吸强度。其他状态角色、`agent-*` 角色与显式 token 颜色保留含义。RGB 主题保留文字
  层级。量化使填充与 chrome 重合时，当前身份保留可配置文字强调无法移除的提示：稳定标记，或在
  所有者文档说明填充是唯一当前提示的行上加下划线。
- `agent-attention`、`agent-done` 和 `agent-error` 各有一个所有主题共用的固定值，包括
  `terminal-native` 和跟随宿主的外观。量化把它们映射到各色级中最接近的颜色，在 16 色下即
  `Yellow`、`Green` 和 `Red`；单色下映射为宿主默认色，由形状回退区分各结果。该状态的文字
  无论出现在何处，都保留其 `status-*` 文字角色。
- `surface-hover`、`surface-pressed`、`surface-selection` 和 `surface-current` 在量化后仍须保持
  有序且可区分。当终端原生或低色深映射无法提供四种不同填充时，悬停使用解析器提供的
  `REVERSED` 带，按下还会加粗动作主要标签，临时选择保留其 `accent-selection` 标记，当前上下文
  在仍有填充时保留填充，否则保留其当前标记、`BOLD` 或下划线。在该色带内，颜色已知的
  `status-*` 或 `agent-*` 字形保留其前景，衬在 ANSI 黑色与白色中与它对比度更高的一方上，而不变成
  自身颜色的色块；随宿主变化的状态字形与色带文字一同反色。混合多种文字角色的行以 chrome 上的
  主要文字配对该色带，其余每个单元格（包括次要文字、静止的强调色、显式 token 颜色和空白格）都使用
  该前景，且不带 `DIM`。即使宿主在反色交换颜色之前应用 `DIM`，该行也只显示一种背景。各组件应用
  语义状态，但绝不按调色板分支。
- 单色模式用下划线表示当前上下文、粗体反色带表示临时选择、粗体反色轮廓表示焦点框架。
  独立的当前、导航和已选值标记继续可见；焦点和选项不能只依靠粗体文字。渲染器保留完整的
  角色样式，包括其修饰符。
- `accent-destructive` 标识明确的破坏性动作意图，独立于动作层级、焦点、当前上下文、悬停和按下。
  它拥有独立调色板值，绝不借用 `status-error`。禁用意图使用 `text-disabled`。原生反色带、未知
  宿主背景或量化填充会遮蔽该含义时，主题解析器为破坏性前景保留对比色对；周围交互带和导航／
  焦点标记继续保留。单色模式保留明确的本地化动作文字及普通交互线索，不增加警告粗体、下划线
  或闪烁。具名 ANSI 的对比度通过参考调色板和实际宿主证据检查；RGB 测试不推断自定义宿主调色板。
- `accent-action` 标识当前决策上下文中静止的唯一主要动作。它绝不标识键盘焦点、选择或成功结果；
  这些含义继续使用各自角色。
- RGB 主题针对一种背景明暗设计，只有在通过探测或显式设置得知宿主明暗时才可选择。它声明自己
  的明暗极性。
- 主题所有者在启动时按检测到的色深（真彩、256 色或 16 色）用最近感知匹配对主题值量化一次，
  随后把坍缩的交互角色解析为已记录的修饰符和标记回退。渲染代码绝不检查色深，也绝不按当前
  主题分支。
- 主题值变更需对照消费该角色的每个表面审查。运行时代码采用新角色时，该实现变更要原子更新
  每个随附主题；运行时角色清单只填充一部分属于无效状态。
- 通过表面角色绘制区域的完整背景，包括内边距和空白单元格。RGB 主题区分画布、持久 chrome
  和覆盖层；边框本身不构成区域表面。终端原生主题及较低色级保留既有宿主行为。
- 宿主报告了默认背景时，跟随宿主的外观把该背景按各角色的固定比例向宿主报告的前景混合，
  得到 `surface-strip`、`surface-related`、`surface-hover`、`surface-current` 和
  `surface-pressed`；深色和浅色背景使用不同的比例。因此标签栏与紧贴其下、不带边框的终端
  保持可区分，交互填充在任何宿主背景上都可见。`surface-selection` 保留调色板值。派生值与调色板
  值经过相同的量化和坍缩角色回退。宿主没有报告背景时，该外观解析为 `terminal-native`，不绘制
  这些填充。主题所有者记录具体比例。

任何主题都禁止：用 `DarkGray`（亮黑）做文本，因为许多配置把它映射得接近背景；在未填充表面上
用 `White` 或 `Black` 做文本；在 `terminal-native` 主题的 `Color::Reset` 上用 `Yellow` 或 `Blue`
做文本，因为它们的对比度取决于明暗极性。这些限制约束文字，包括状态词。`agent-*` 字形不是
文字：其固定值在宿主默认表面上可以量化为 `Yellow`，因为该字形是单单元格指示器，其状态另有
状态词和不依赖颜色的形状回退。

## 文本层级

层级描述信息优先级，而不是交互状态。

| 层级 | 呈现                    | 使用场景                               |
| ---- | ----------------------- | -------------------------------------- |
| 标题 | `text-primary` + `BOLD` | 覆盖层标题和章节标签                   |
| 主要 | `text-primary`          | 值、标签，以及用户做决定必须阅读的内容 |
| 次要 | `text-secondary`        | 辅助文案、元数据、时间戳和按键提示标签 |
| 禁用 | `text-disabled`         | 为可发现性而保持可见的不可用动作       |

- 一个区域最多使用标题、主要和次要这三个层级。禁用是应用于受影响内容的可用性处理，不是第四个
  层级。额外结构来自间距、分组或框架，而不是更多颜色或 `ITALIC`。
- `BOLD` 标记标题、所有者文档说明以粗体表示身份的当前项（例如当前 Tab），或可用动作按下时的
  标签或字形；绝不标记指针悬停或警告。`UNDERLINED` 只标记 `accent-link`，以及无法显示当前填充时
  的当前上下文。只有主题解析器可以把 `REVERSED` 用作终端原生或低色深下交互带的回退；组件渲染器
  绝不直接请求它。`BLINK` 在任何地方都禁止。
- 状态角色只给状态字形或状态词着色，而不是整行。

## 交互状态

| 状态        | 呈现                                                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 聚焦区域    | `frame-focused` 边框；无框架区域用标题或专用标记上的 `accent-focus` 表达焦点                                                                                                                                  |
| 未聚焦 pane | `frame-unfocused` 边框；只有所有者明确记录时，`surface-inactive` 才可遮罩其内容                                                                                                                               |
| 指针悬停    | `surface-hover` 覆盖有效命中矩形，不加 `BOLD`；静止时为 `text-secondary` 的可用动作标签提升为 `text-primary`；纯图标动作改为把字形增强为 `text-primary`，不添加填充；动作菜单可移动临时候选，并使用其选中背景 |
| 指针按下    | 主按钮仍在已武装目标上按住时使用 `surface-pressed`，并给可用动作标签或字形加 `BOLD`                                                                                                                           |
| 临时选择    | `surface-selection` 覆盖完整行；组件提供指示器时再使用共享的 `accent-selection` 导航标记                                                                                                                      |
| 范围选择    | `surface-selection` 覆盖已选单元格；绘制端点或活动边缘时使用 `accent-selection`                                                                                                                               |
| 当前上下文  | 中性的 `surface-current` 覆盖完整行；当前身份独立于焦点加 `BOLD` 或稳定标记，或由所有者文档说明填充是唯一提示，并在无法显示填充时给该行加下划线                                                               |
| 已勾选值    | 用 `accent-selection` 的稳定字形表达控件声明边界上的值；导航与之保持独立                                                                                                                                      |
| 当前 Tab    | 中性的 `surface-current` 加 `BOLD` 或稳定当前标记；键盘焦点与临时导航保持独立                                                                                                                                 |
| 等待中      | 固定宽度的 `status-pending` 字形加本地化动词；控件占位保持固定                                                                                                                                                |
| 禁用        | `text-disabled`；无悬停或按下处理；动作连同原因保留在帮助中                                                                                                                                                   |

同一时刻只有一个区域显示焦点。焦点在每个布局层级中都可见，并且只在键盘所有者边界投影一次：
有框架的集合用 `frame-focused` 边框，无框架的聚焦行使用专用 `accent-focus` 轨道。捕获输入的覆盖层
改为通过独占遮挡拥有输入：它保持中性的 `frame-unfocused` 边框，由其标题以及终端光标或临时标记标识
所有者。集合框架内的行不再重复所有者的焦点标记；它的可逆导航锚点仍独立可见。

当前上下文与键盘焦点是不同事实。输入归属其他区域时，当前上下文仍须可辨认；移动键盘焦点
不能抹去这个标识。表面应记录两者的呈现方式及同时出现时的效果。填充是唯一当前提示时，导航或
指针表面只在持有该导航或指针的行上取代它，离开该行即恢复。

已勾选值既可以表示暂存值或父草稿值，也可以表示已确认领域值，本身不能证明已经持久化。它与已确认或
有效基准不同时，控件保留 [`components.md`](components.md#值控件) 定义的独立草稿变更提示。

当前、已勾选、临时选择、焦点、悬停、按下、可用性和等待状态是相互独立的事实。在背景通道内，
优先级依次为按下、临时选择、悬停、当前，最后是组件基础表面。当更高优先级背景生效时，标记、
字形、文字层级和状态仍须可见。[`components.md`](components.md#状态模型) 拥有必需的组合与控件行为。

## 边框与框架

- 框架使用单线制表字符。圆角是统一应用的主题选项；表面绝不自行选择角样式。
- 相邻 pane 共享一个边界单元格。不要在两个 pane 之间绘制两条边框。
- 框架标题对标签从末尾截断并加省略号，对路径从中间截断。它绝不撑大框架，也绝不换行。
- 只有内部区域在每个维度至少有一个单元格时才绘制框架；低于此值只绘制边界线或什么都不画。
  绝不绘制残缺的框架。
- chrome 区域之间的分隔线使用 `frame-divider`；宽度为一个单元格。

## 字形

- chrome 假定宿主使用 UTF-8。允许制表符、箭头、`…` 和 `•`。当
  [`terminal-environment.md`](terminal-environment.md#能力探测) 报告非 UTF-8 locale 或启用了简化
  字形时，每个非 ASCII 字形都通过其声明的 ASCII 回退渲染。
- chrome 中禁止私有区字形、Nerd Font 图标和 emoji：它们的宽度依赖宿主，且不保证存在。
- 每组交替帧的字形（如 spinner）保持恒定显示宽度，避免邻近内容抖动。
- 行临时导航统一使用单单元格 `›` 标记，其 ASCII 回退为 `>`。功能渲染器只预留该轨道，绝不
  自行选择替代字形，也不将它复用为当前、已勾选或已变更状态。
- 展开时披露控件使用 `▾`，折叠时使用 `▸`，ASCII 回退分别为 `v` 和 `>`，使折叠的披露控件
  绝不会被读成 ASCII 状态字形中的 `+` 或 `-`。
- 已勾选的选项（例如菜单中分组已应用的颜色）在勾选轨道中显示 `✓`，ASCII 回退为 `*`。
- 一个字形在整个 Client 中只有一个含义。字形含义与所属表面一同记录。只有当两个 ASCII 回退
  所在轨道绝不重合时，它们才可共用同一字符：折叠披露的 `>` 跟在身份或标签之后，导航的 `>`
  占据行首导航轨道。

## 显示宽度与文本安全

- 按显示宽度度量文本，绝不按 `char` 或字节数。东亚宽字符占两个单元格；组合标记占零个。度量、
  截断和布局使用同一个宽度函数。
- 截断标记用同一宽度函数度量，并在文本之前预留预算。`…` 属于东亚模糊宽度；其 ASCII 回退是
  `..`。
- 散文按显示宽度在词边界换行。除非单个 token 本身超过行宽，否则不要在 URL 或文件路径内部
  断开。
- 来自 Client 之外的文本在绘制到 chrome 前先净化：从标签、标题和路径中去除控制字符、转义序列
  和换行。chrome 缓冲区绝不解释来自用户或进程数据的 ANSI。
- 绝不为了适配而缩小、丢弃或缩写必需的动作或说明；用 [`layout.md`](layout.md#尺寸层级) 中的
  层级选择更短的已记录形式。
