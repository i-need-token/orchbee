# TUI 操作

## 权威与范围

本规范负责用户可调用语义操作的原生 TUI 适配器契约：投影、可用性、调用路径一致性、执行观察与结果呈现。操作含义、目标资格、验证、提交和持久效果仍由结果所属的功能或领域按照
[`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md) 负责。

这是新增和实质性变更的 TUI 行为必须满足的契约，并不声称当前每个界面都已符合。对于分阶段缺口，应记录负责人和完成条件，而不是削弱契约或把尚不支持的行为呈现为可用。

按键解码、绑定、所有权和有效快捷键显示遵循
[`keyboard-input.md`](keyboard-input.md)。指针准入和手势有效性遵循
[`mouse-input.md`](mouse-input.md)。控件外观遵循 [`components.md`](components.md)，确认、等待反馈、通知和焦点返回遵循
[`overlays-and-status.md`](overlays-and-status.md)。前端运行时仍由
[`frontend/actions.md`](../frontend/actions.md) 规范；本规范不要求两个客户端共享运行时或实现。

## 准入与所有权

当一个具名产品意图能从多个调用路径进入、需要稳定的可用性或发现能力、会启动可观察工作，或具有语义结果时，使用操作。悬停、焦点移动、展开、临时选择、编辑器内部变更和连续手势输入由其组件所有者负责。手势提交后的结果可以调用操作。

| 职责                                       | 所有者                                                        |
| ------------------------------------------ | ------------------------------------------------------------- |
| 标识、类型化输入和目标、产品名称及语义结果 | 结果所属的功能                                                |
| 领域不变量、授权、验证、提交和持久状态     | 所属领域能力                                                  |
| TUI 上下文投影、可用性、调用和执行观察     | 原生应用组合层                                                |
| 按键绑定与输入优先级                       | [`keyboard-input.md`](keyboard-input.md) 和所属应用的绑定目录 |
| 命中几何、指针手势、控件状态和视觉处理     | 指针与组件所有者                                              |
| 进程、存储、传输、导航和宿主效果           | 现有应用或运行时边界                                          |

不得在渲染器中创建第二个业务写入者、通用 UI Store 或进程级操作单例。操作定义、组件局部键位映射和命令条目可以由不同的结构化所有者维护。TUI 组合层可以为发现和分发规范化这些投影；本契约不要求所有交互进入同一个注册表或框架。

当语义所有者把激活声明为提交点时，操作可以立即提交局部视图效果。呈现者不得仅因局部投影发生变化就自行引入持久化、外部效果或延迟提交。

## 操作投影

每个反复使用的操作投影都要提供或引用以下事实。一个语义标识只代表一种结果；实例、实体和选项值是类型化输入，不是新的 ID。

| 字段       | 契约                                                                |
| ---------- | ------------------------------------------------------------------- |
| 标识       | 由功能所有的稳定、非本地化操作 ID                                   |
| 输入与目标 | 经验证的输入和类型化语义句柄；绝不能是行号、单元格、标签或指针地址  |
| 作用域     | 操作解析所在的输入所有者、功能实例和目标作用域                      |
| 元数据     | 本地化标题、可选的决策相关说明、类别和经审查的搜索别名              |
| 可用性     | 当前上下文快照下的 `enabled`、带本地化原因的 `disabled` 或 `hidden` |
| 语义状态   | 由功能所有的可选选中值或当前值；绝不从焦点或悬停推断                |
| 入口       | 当前提供的有效绑定引用以及指针、菜单或命令入口                      |
| 执行       | 工作可观察时的提交点、界面生命周期、取消、并发与结果策略            |

ID 不得来自翻译文案、控件位置、快捷键或菜单顺序。动态或外部输入在功能所有的边界验证并复制所需的规范快照之前都不可信。呈现元数据携带本地化描述符而不是预格式化字符串，使所有界面都能按有效区域设置格式化同一含义。

## 解析、可用性与拒绝

- 从当前输入所有者和准确的功能实例解析操作。注册或渲染顺序绝不是优先级；过期目标不得回退到无关的当前项目。
- 为呈现而进行的可用性计算必须纯粹基于一个只读上下文快照。在跨越效果边界前立即重新验证输入、目标、授权和领域守卫。
- `enabled` 表示可见且可调用。`disabled` 表示相关但暂不可用，保持可见并说明原因。`hidden` 表示无关、不支持、未授权或不宜暴露，在菜单、帮助、搜索和枚举中都不存在。
- 如果状态在呈现和调用之间变化，应以类型化原因拒绝调用。不能仅因旧行、命中矩形、已准备的菜单条目或快捷提示曾经有效就执行。
- 可用性回答操作现在是否可以开始。等待中、选中、选择、焦点和当前上下文状态彼此独立，不得编码成可用性。

## 调用路径一致性

同一操作的键盘、指针、菜单、命令及其他获准的本地入口必须解析到相同的操作标识、已验证输入、目标、可用性、确认、提交边界和结果映射。各入口可以适配布局和提示，但不得实现另一条变更路径。

- 已呈现入口携带足够的标识，把激活绑定到其界面实例、操作、目标和呈现状态代次。指针激活还必须满足 [`mouse-input.md`](mouse-input.md) 中当前命中映射和按下/释放契约。
- 移动焦点、悬停、选择一行、打开菜单或输入搜索查询都不会激活操作，除非该转换本身就是控件已记录的语义意图。
- 菜单或命令结果调用其所描述的已准备目标。如果目标或定义已经过期，应拒绝，而不是通过另一个作用域重新解析。
- 确认是功能所有的结构化数据。所有入口都进入相同的确认和重新验证路径；呈现者不得绕过它，也不得把确认当成授权。
- 激活只消耗一次调用权。按键重复、缓冲输入、双击或第二个呈现者不得启动另一次执行，除非操作的并发策略允许。

## 执行与效果边界

可观察的调用在工作跨越效果边界前获得唯一执行标识。其快照按适用情况单调经历准备、等待确认、运行、已请求取消，并到达一个终结结果。即时工作可能在调用者订阅前就到达终结快照，因此当前快照和终结结果才是权威；仅靠边沿通知不是事实来源。

通过以下分类呈现语义所有者的终结结果。这些分类定义 TUI 含义和映射，不是新的 Rust enum、共同运行时或所有者专用变体的替代品。

| 呈现分类      | 含义                                                 |
| ------------- | ---------------------------------------------------- |
| `completed`   | 语义所有者报告操作已经提交                           |
| `unchanged`   | 请求有效，但按设计没有产生变更                       |
| `blocked`     | 已知守卫、拒绝、过期目标、冲突或不可用能力阻止了提交 |
| `cancelled`   | 所属生命周期在提交前结束了操作                       |
| `failed`      | 所有者按照现有结果契约报告明确失败                   |
| `unsupported` | 当前没有能力可以处理该操作                           |
| `unknown`     | 所有者明确报告提交状态不确定，再次尝试前必须重新观察 |

现有所有者专用的 `refused` 变体映射到 `blocked` 呈现含义，同时保留其稳定原因。适配器绝不会因延迟、截止时间或缺少回复而自行产生 `unknown`，也绝不会把所有者报告的 `unknown` 强制转换成明确的 `failed`。此映射不会改变当前前端操作运行时，也不声称它已经符合本规范。

TUI reducer 可以产生窄化的效果请求，但存储、进程、传输、导航和其他外部工作由现有应用或领域边界执行。完成结果携带产生它的执行标识、语义目标和请求代次。只有仍然匹配的当前呈现者可以更新等待状态、预览、选择、焦点或导航。呈现者关闭后，效果所有者仍把完成结果结算到权威领域状态；没有匹配呈现者时，它只能更新应用所有的活动或通知通道，绝不能改变替代界面的交互状态。

原始异常和外部字符串只进入诊断。产品结果使用稳定代码和本地化消息。除非所属工作流明确规定，否则适配器绝不重试、超时、回滚或把失败转换成成功。

## 取消、并发与生命周期

- 关闭或替换呈现者只释放其订阅和交互权，不取消已接受的工作。取消工作是由工作流所有的显式操作或执行请求。
- 取消是协作请求。提交前的请求可以以 `cancelled` 结束；在取消前已经提交的工作按其已提交结果完成。
- 每个异步操作定义一个语义并发键和一种策略：相互独立地并行执行、拒绝重复、替换最近一个可取消执行，或按确定顺序串行执行。并发键使用稳定的操作、目标和已验证输入事实，不使用组件标识或翻译文本。
- 所有者规定延迟取消、队列目标重新验证、乱序完成，以及被替换执行已经越过提交点时的行为。调用者的截止时间不会暗中取消共享工作。
- 当前景界面必须拥有一项必要决策时，应拒绝关闭；或者由工作流显式停放该任务并提供返回路径。后台完成绝不抢夺焦点、切换上下文或覆盖更新的草稿。
- 即发即忘的工作不是操作结果。应返回可观察执行，或返回拥有独立生命周期的稳定外部作业标识。

## 发现与呈现

发现信息来自分发所使用的同一个有效投影。按钮、行操作、菜单、快捷键页脚、完整帮助界面和命令搜索不会分别维护标签、绑定、可用性或目标规则。

- 显示当前上下文下有效的本地化标题和有效绑定，包括已准入的用户覆盖和宿主限制。绝不能把被遮蔽或不支持的组合键宣传为可用。
- 在页脚优先显示当前所有者最有用的少量操作。完整帮助可以为学习保留禁用操作，但必须说明原因；隐藏操作仍然不存在。
- 搜索本地化标题、说明、类别和经审查的别名。搜索只改变投影，绝不调用操作。
- 在等价入口界面之间保留破坏性含义、选中状态、分组和相对顺序。短标签可以是已记录的同一产品术语变体，不能成为新的操作名称。
- 绘制前净化外部目标文本。默认不得通过操作元数据、进度或诊断暴露原始错误、秘密、终端内容或用户输入。

## 验证

| 变更声明     | 所需证据                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| 标识或解析   | 测试覆盖准确作用域、类型化目标、重复或过期定义、隐藏能力，并证明不会回退到无关目标 |
| 可用性       | 测试覆盖启用、禁用原因、隐藏、重新验证、选中状态独立性，以及状态变化后的拒绝       |
| 调用入口     | 键盘、指针、菜单和命令路径到达同一个操作、输入、目标、确认和提交点                 |
| 执行         | 测试覆盖即时与延迟完成、唯一标识、恰好一个终结结果、异常映射，以及订阅前的当前快照 |
| 取消或并发   | 受控顺序测试覆盖声明的策略、重复输入、提交前后取消、队列中过期目标和乱序完成       |
| 呈现生命周期 | 测试拒绝过期界面和命中代次，保留更新的焦点与草稿，并通过非侵入反馈路由延迟完成     |
| 发现         | 两种发布区域设置都显示有效标签、绑定、顺序、禁用原因和紧凑截断，并且不显示隐藏操作 |

依据 [`verification.md`](verification.md) 使用单元格网格、输入、尺寸调整、区域设置和宿主证据。只有当独立排序的参与者或效果所有权风险满足
[`MODELING-AND-CORRECTNESS.md`](../MODELING-AND-CORRECTNESS.md) 的触发条件时才添加形式化模型；仅有异步语法并不足以要求模型。
