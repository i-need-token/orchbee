# TUI 鼠标输入

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的指针捕获策略、命中测试、交互状态、手势词汇、向终端 pane
内程序的透传、滚轮归一化和选择。宿主模式协商遵循
[`terminal-environment.md`](terminal-environment.md)；键盘归属遵循
[`keyboard-input.md`](keyboard-input.md)；组件状态与组合遵循
[`components.md`](components.md)。所属应用记录哪些已绘制区域接受哪些语义意图；本标准定义
这些映射必须满足的规则。

这是新增和实质性变更的 TUI 指针行为必须满足的契约，并不声称当前 Client 已经符合。运行时采用
只能由源码和 [`verification.md`](verification.md#契约评审) 要求的证据建立。对于分阶段缺口，应记录
负责人和完成条件。在完成采用前，应用自有参考仍是当前捕获与指针行为的描述性权威。

## 捕获策略

- 全屏 Client 在其界面活动期间优先启用任意移动报告（DEC 模式 `1003`）和 SGR 编码（`1006`）。
  这是 Orchbee 所绘 chrome 和覆盖层获得悬停的准入级别。当任意移动报告不可用或尚未获准时，
  使用按钮事件跟踪（`1002`）和 `1006`；点击、拖动和滚轮仍可用，在下述菜单范围策略与原生记录能力之外悬停
  如实缺席。全局捕获同一时刻只选择 `1002` 与 `1003` 之一。
- 动作菜单独占输入且捕获已启用期间，可以先启用 `1002` 再启用 `1003`，保留 `1006`，请求带
  按钮回退的空闲移动。忽略 `1003` 的宿主保留按钮报告；反馈仍要求真正收到移动报告。这不提升
  全局能力结果。菜单退出时先恢复 `1003l`、再写 `1002h`，除非全局任意移动已独立获准。
  已释放捕获保持释放；模式写入失败或结果不明时进入完整生命周期清理，不发布也不重试。
- 原生控制台记录传输可以依据捕获启用期间实际收到的无修饰、无按钮移动准入悬停，独立于 VT 能力查询。
  此观察不改变宿主模式，不重新启用捕获；粘贴从不构成证据。所有界面共用该能力，释放和失焦仍清除临时指针状态。
- 任意移动报告只是外层 Client 的传输机制，并不表示 Client 拥有 pane 内程序的输入。Orchbee
  消费其 chrome 上的移动，并且只按[透传](#透传)规则转发 pane 视口内的事件。未请求的移动绝不
  到达 pane 内程序。
- 像素位置报告（`1016`）只在 pane 内程序请求像素坐标期间启用，需求结束时禁用。它不改变手势
  由哪个表面拥有。
- Client 提供一个有效绑定和一个命令来释放捕获。释放会禁用 Orchbee 拥有的全部指针模式，包括
  `1002`、`1003`、`1006` 和 `1016`，取消已预备的手势，并清除悬停。释放期间，持久状态指示器
  说明宿主拥有选择、链接和滚动，Client 指针交互不可用。同一操作恢复此前获准的捕获级别。
- Client 绝不绑定带 `Shift` 修饰的手势。支持 `Shift` 绕过的宿主继续用它进行原生选择。由于并非
  每个宿主都能证明支持该绕过，显式释放命令始终是可移植路径，发现界面也绝不承诺宿主未准入的能力。
- 暂停或把宿主终端交给外部程序之前，释放全部指针模式。只有在 Orchbee 恢复并重新绘制界面后，
  才恢复获准的捕获级别。

## 交互状态

指针交互保持以下事实彼此分离：

| 事实       | 含义                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 悬停       | 指针位于上一已呈现帧的一个命中区域上；它是短暂的 Client 本地呈现状态 |
| 键盘焦点   | 一个已绘制区域拥有上下文键盘输入，并独立于悬停显示焦点               |
| 临时选择   | 列表、选择器或编辑器中尚未跨过提交边界的候选项                       |
| 当前上下文 | 当前持久打开的领域对象或位置；指针移动绝不改变它                     |
| 已预备手势 | 正在进行的按下或拖动，绑定到一个稳定目标身份及其交互修订号           |
| 激活       | 手势满足所有者提交规则后分派的语义意图；它是事件，不是焦点           |

- 移动可以改变悬停样式或显露局部构件。打开的动作菜单可通过所有者让已绘制可用行成为
  临时候选；其他集合保留临时选择。移动绝不移动键盘焦点、激活动作、提交数据、修改共享
  领域状态或写入终端输入。
- 只有所属组件声明了相应步骤，按下才能移动焦点或选择。立即动作行、先选后确认的选择器、
  展开项和可编辑值行是不同的交互契约；渲染器绝不为所有行虚构一种点击规则。
- 终端失焦或释放捕获时，会清除悬停和已预备手势且不激活。目标的几何、可用性、遮挡、归属、接受的
  手势或语义意图发生变化时，也会取消其已预备手势。仅视觉重绘或无关目标的变化不会仅因帧序列推进
  就取消该手势。只有在捕获启用且终端保持焦点期间，Client 才保留最后指针位置；任一条件丢失后，
  在收到新的移动报告前悬停始终缺席。
- Orchbee UI 已接受的按下被取消后，其所有者只能为该次按下的主键释放保留类型化清理所有权。清理在
  普通捕获、焦点或命中图准入之前解析：匹配的迟到释放只结束手势一次，并让其完整物理数据包（包括
  粘贴及未完成的解码片段）继续归 Client 所有，且不重新命中、不激活，也不再次产生效果。期间的指针
  报告不能借该债务重新命中。新的非滚轮按下会退役债务。孤立释放既不创建债务，也不创建数据包围栏。
  pane 程序手势、链接和文本选择继续遵循各自所有者的清理契约。

## 命中测试和重绘

- 渲染器记录每个实际绘制的交互区域的矩形、层级、稳定目标身份、接受的手势、语义目标、可用性和
  交互修订号。只要其中任一交互属性发生变化，目标修订号就会变化；文字、颜色、进度动画和其他仅
  呈现变化保留该修订号。候选命中图随成功刷新的帧原子地成为权威。
- 区域种类有限且由所有者记录：导航条目、pane 视口、pane 边界、集合行、展开项、动作、编辑器、
  值控件、滚动指示器、状态段和覆盖层控件。新增种类需要交互契约，不能只有一个矩形。
- 同一层中的同级区域不重叠。已声明的子目标（例如行的辅助动作）先于父目标测试，并在其绘制范围
  内胜出。其他层从前到后解析。捕获型覆盖层按其消除契约拥有控件外的手势，并阻止下层目标悬停
  或预备。
- 如果渲染器能证明所有交互属性都未变化，重绘等待期间仍以最后一个成功刷新的命中图为权威。不能
  仅因尝试写出字节就让候选图成为权威；部分写入或结果未知不能授权新几何。尺寸变化或结构性布局
  替换会在下一个输入决策前使受影响的权威失效，并在新图成功呈现前丢弃事件。包含交互变化的写入
  若只完成一部分或结果未知，权威保持暂停，而不会回退到过期映射。
- 新图发布后，按稳定目标身份和交互修订号调和瞬时状态。只有目标仍然存在且修订号相同时，才保留
  已预备手势；否则取消且不激活。因为宽度、能力、可用性或遮挡而省略的目标没有命中区域，也不能
  通过旧几何保留悬停、焦点权威或激活权威。权威暂停期间只要丢弃过指针事件，就会取消活动手势，
  避免之后的帧完成该手势。
- 指针移动只在解析出的目标变化时更新悬停。在同一单元格或目标上的重复报告不请求重绘。真实变化
  通过 [`terminal-environment.md`](terminal-environment.md#输出纪律) 中的有界节奏请求一次重绘；
  移动绝不强制每份报告绘制一帧。已预备目标的边界跨越会在重绘合并之前按事件顺序应用到手势状态；
  即使只保留最新悬停呈现，也绝不能抹去一次移出后返回的经过。
- Client 保留最后一个指针位置。新帧呈现后，它可以针对新命中图重新计算悬停；目标变化时为之后
  请求一次有界重绘。该调和绝不能聚焦、选择、预备或激活任何目标。
- 主按钮按下会预备解析出的稳定目标身份及交互修订号。只有释放时在当前权威命中图中仍解析到同一个
  可用目标和修订号，才能激活。拖动离开目标后仍由原目标拥有手势以便清理或预览，但会取消点击激活；
  释放前返回也不会静默重新预备。捕获丢失，或几何、可用性、遮挡、归属、接受的手势或语义目标变化
  引起修订号变化时，都会取消手势。

## 手势和意图词汇

每个获准手势最多解析为一个有作用域的语义意图。已提交操作的指针和键盘路径使用相同的动作身份、
目标、可用性规则和结果。悬停、光标放置和拖动预览是输入方式本地的呈现；最终操作仍必须能从键盘
到达。

| 区域契约       | 指针行为                                           | 必需键盘路径                             |
| -------------- | -------------------------------------------------- | ---------------------------------------- |
| 立即动作       | 主按钮在有效释放时调用动作                         | 焦点加 `Enter` 或 `Space`，或其有效绑定  |
| 立即导航       | 主按钮点击打开记录的目标或使其成为当前目标         | 焦点加 `Enter`，或其有效导航绑定         |
| 先选后确认集合 | 主按钮点击移动临时选择；接受是另行记录的手势或动作 | 焦点移动加相同的显式接受动作             |
| 展开项         | 主按钮点击展开目标以切换展开状态                   | 行有焦点时用 `←`/`→` 或已记录的切换动作  |
| 编辑器         | 主按钮点击使其获得焦点，并可放置光标               | `Tab` 或已记录的焦点移动；然后使用编辑键 |
| 值控件         | 主按钮点击调用其声明的编辑、选择器或立即切换契约   | 焦点加同一个语义编辑或切换动作           |
| pane 视口      | 主按钮按下聚焦 pane，随后透传可以接收该事件        | 已记录的 pane 聚焦路径                   |
| pane 边界      | 主按钮拖动预览调整大小；释放时提交一次调整         | 能够预览、提交和取消的调整大小模式       |
| 可滚动区域     | 滚轮移动该区域且不改变焦点                         | 同一区域中的方向键或翻页移动             |
| 滚动指示器     | 主按钮点击把视口移动到所表示的位置                 | 能到达相同视口位置的翻页或跳转命令       |

- 集合所有者声明接受操作使用再次点击、双击、专用控件还是其他显式手势。第一次点击绝不只是因为
  目标画成一行就激活。多击检测使用有界间隔、同一目标身份和同一单元格；移动到其他目标会开始新序列。
- 禁用目标绝不获得悬停或按下效果，也不能预备或激活。其持久禁用呈现以及键盘或帮助路径显露
  本地化原因。
- pane 文本选择和边界调整拖动可以在按下时开始，以便移动有锚点；它们仍只在记录的释放边界提交，
  并可在此之前取消。
- 右键和中键按下保留。上下文表面和指针粘贴需要另行接受的契约以及键盘可达的结果，之后才能绑定。
- 滚动是 Client 本地视图状态。保留终端的选择属于其 Terminal Host attachment，并由 Client 投影。
  共享 workbench 状态只在语义操作声明的提交边界变化。

## 透传

- pane 内程序只拥有其视口内已请求的指针事件类别：其按钮模式下的按钮事件、`1002` 下的按键拖动
  移动、`1003` 下的全部移动，以及 `1016` 下的像素坐标。Orchbee 把获准事件转换为 pane 本地坐标，
  并按程序请求的格式重新编码。绝不因为 Client 自身使用 `1003` 就转发外层悬停。
- 视口外的事件绝不转发。无论程序启用了哪些模式，pane 边界和全部 Orchbee chrome 都属于 Client。
- 由主按钮按下引起的 pane 聚焦在转发之前于本地发生。转发的按下及其之后的拖动或释放保持同一
  pane 目标，除非捕获丢失或无效几何取消了手势。
- 在不以其他方式报告指针的备用屏幕程序上，仅当 DEC `1007` 开启时将滚轮移动作为方向键按下
  转发，默认每档三次。关闭该模式会结束排队的方向键工作，并把后续滚轮移动交回 Client。
- `Shift` 绕过和显式释放捕获属于宿主路径，绝不合成为 pane 内程序的输入。

## 滚轮归一化

- 滚轮报告只携带方向。把间隔小于一个短间隙的连续报告视为一个流，并以已记录的默认每档三行把流
  转换为行增量。
- 把滚动应用合并到重绘节拍；绝不每收到一个报告就绘制一次。
- 单次刷写最多滚动一个视口高度。多出部分留在流中，在后续刷写中应用。
- 类触控板的流可以累积小数行；方向反转清空累加器。
- 方向反转和速度是应用拥有的用户设置，在归一化之后应用。

## 选择与剪贴板

- Terminal Host 拥有 pane 选择端点和导出文本。Client 在实时输出或保留历史上用
  [`visual-foundations.md`](visual-foundations.md#颜色角色与主题) 中的 `surface-selection` 投影该
  选区。命名选择所有者可以把 `Esc` 公开为本地清除步骤；否则 pane `Esc` 仍然透传。在选区外按下
  或其交互修订号失效会清除本地手势工作。Host 端点被驱逐时清除选区并显示通知。
- 应用为每次复制声明一个剪贴板 sink。它绝不把同一次复制广播到多个 sink，也绝不把没有回执的
  OSC 52 写入当成可以安全执行平台回退的证据。剪贴板工作绝不阻塞渲染，失败会产生状态通知。
- 导出文本是由 Host 完整生成、带 pane 自身逻辑换行的纯文本；chrome 单元格和 pane 边界绝不
  包含在内。残缺、畸形、超限或 UTF-8 无效的导出不写入任何内容。
- 所在行被从保留历史中驱逐的选择会连同通知一起清除，而不是被静默移动。

## 验证

| 变更           | 必需检查                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 捕获策略变更   | 字节轨迹证明优先 `1003` 和回退 `1002` 的启用、精确释放与恢复、`Shift` 不绑定、悬停清除以及释放状态指示器                           |
| 悬停行为       | 测试证明进入、移动、离开、遮挡、同目标合并、保留焦点和已提交选择、已声明的菜单候选例外、不激活，以及没有任意移动报告时如实缺席     |
| 新增区域       | 测试针对上一成功呈现帧解析每条边和外部；仅视觉重绘保留权威，而过期、未绘制、被遮挡、已调整大小及未知结构写入均不能授权激活         |
| 手势映射变更   | 表驱动测试把每个手势映射到一个意图，在仅视觉及无关重绘间保留预备状态，在交互修订号变化时取消，覆盖提交边界，并证明存在等价键盘路径 |
| 透传变更       | 测试覆盖每个请求的事件类别、未请求的外层移动、pane 本地转换、主屏和备用屏报告关闭、DEC `1007`，以及 chrome 或边界输入              |
| 滚轮归一化变更 | 测试覆盖滚轮流、触控板流、反转、同节拍合并和单次刷写上限                                                                           |
| 选择变更       | 测试覆盖手势顺序、实时／历史投影、保留历史的 revision 移动、交互修订号取消、所有者本地 `Esc`、pane 透传、多行 Unicode 导出和驱逐   |
