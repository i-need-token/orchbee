# TUI 鼠标输入

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的指针捕获策略、命中测试、手势词汇、向终端 pane 内程序的透传、
滚轮归一化和选择。宿主模式协商遵循 [`terminal-environment.md`](terminal-environment.md)；键盘
归属遵循 [`keyboard-input.md`](keyboard-input.md)。所属应用记录哪些区域接受哪些手势；本标准
定义这些映射必须满足的规则。

## 捕获策略

- 全屏 Client 在启动时启用指针报告：按钮事件跟踪（DEC 模式 `1002`）加 SGR 编码（`1006`）。禁止
  任意移动跟踪（`1003`）；它会淹没输入，并完全剥夺宿主的原生选择。
- 像素位置报告（`1016`）只在某个 pane 的透传需要像素坐标时启用，需求结束时禁用。
- Client 提供一个绑定和一个命令来释放捕获。释放期间，状态行显示持久指示器，宿主终端拥有选择、
  链接和滚动，Client 的每个手势都不可用。同一绑定恢复捕获。
- Client 绝不绑定带 `Shift` 修饰的手势。宿主保留 `Shift` 用于绕过报告以做原生选择，该绕过始终
  可用。
- 在任何外部程序接管宿主终端之前释放捕获，Client 恢复时再恢复捕获。

## 命中测试

- 渲染器记录它在一帧中绘制的每个可交互区域的矩形和类型。指针事件针对上一绘制帧的区域解析，
  绝不针对预测的布局。
- 区域类型有限并由所有者记录：导航条目、pane 视口、pane 边界、列表行、动作、滚动指示器、状态
  段和覆盖层控件。
- 同一层内区域绝不重叠。覆盖层所在层先于其下方的层测试，捕获型覆盖层吞掉其外部的每个手势。
- 记录的区域在尺寸变化时以及任何改变布局的帧之后被丢弃。在变化与下一次绘制之间，指针事件被
  丢弃，而不是被误路由。
- 按下及其释放都针对按下时的区域解析。离开其区域的拖动在释放前仍归属该区域。

## 手势词汇

区域上的每个手势最多解析为一个语义意图。下面的意图是共享词汇；区域可以只实现其子集。

| 手势     | 区域         | 意图                                                  |
| -------- | ------------ | ----------------------------------------------------- |
| 左键按下 | 导航条目     | 选择该条目                                            |
| 左键按下 | pane 视口    | 聚焦该 pane；若 pane 内程序报告鼠标，则随后转发该按下 |
| 左键按下 | 列表行       | 把选择移到该行；再次按下已选中行则激活它              |
| 左键按下 | 动作         | 动作可用时调用它；否则显示其原因                      |
| 左键拖动 | pane 边界    | 拖动期间预览调整尺寸；释放时提交一次调整              |
| 左键拖动 | pane 视口    | 当 pane 内程序不报告鼠标时选择文本                    |
| 左键双击 | pane 视口    | 选择指针下的词                                        |
| 左键三击 | pane 视口    | 选择指针下的行                                        |
| 滚轮     | 列表或覆盖层 | 滚动该区域                                            |
| 滚轮     | pane 视口    | 进入或在保留历史中移动，或在备用屏幕中作为方向键转发  |
| 左键按下 | 滚动指示器   | 把视口跳到按下的位置                                  |
| 右键按下 | 任意         | 保留；上下文表面是另一个待接受的决定                  |
| 中键按下 | 任意         | 保留；通过指针粘贴是另一个待接受的决定                |

- 多击检测使用有界间隔和同一单元格。在不同单元格按下会开始新的序列。
- 手势在释放前绝不修改共享状态，选择和滚动除外，它们是 Client 本地的。
- 每个手势意图都有键盘等价物。指针是附加路径，绝不是唯一路径。

## 透传

- 当 pane 内程序启用了任何指针报告模式，或者它使用备用屏幕、开启 DEC 1007 且手势是滚轮移动时，该程序拥有其
  pane 视口内的指针。
- 转发的事件被换算为 pane 本地坐标，并按程序请求的模式重新编码。视口之外的事件绝不转发。
- 在不报告鼠标的备用屏幕程序上，仅当 DEC 1007 开启时将滚轮移动作为方向键按下转发，
  默认每档三次。关闭该模式会结束排队的方向键工作，并把后续滚轮移动交回 Client。
- 由按下引起的焦点变化是 Client 本地的，并发生在转发之前。
- 无论程序的报告状态如何，pane 边界和每个 chrome 区域都属于 Client。

## 滚轮归一化

- 滚轮报告只携带方向。把间隔小于一个短间隙的连续报告视为一个流，并以已记录的默认每档三行把流
  转换为行增量。
- 把滚动应用合并到重绘节拍；绝不每收到一个报告就绘制一次。
- 单次刷写最多滚动一个视口高度。多出部分留在流中，在后续刷写中应用。
- 类触控板的流可以累积小数行；方向反转清空累加器。
- 方向反转和速度是应用拥有的用户设置，在归一化之后应用。

## 选择与剪贴板

- 对 pane 历史的选择是 Client 本地的。它用 [`visual-foundations.md`](visual-foundations.md#颜色角色与主题)
  中的 `surface-selection` 高亮，跨越逻辑行，并在 `Esc`、在其外部按下，或新输出驱逐其锚点时
  清除。
- 复制在宿主声明或被配置支持时使用 OSC 52，否则使用平台剪贴板，再否则用状态通知说明失败。
  复制绝不阻塞渲染。
- 导出文本是带 pane 自身换行的纯文本；chrome 单元格和 pane 边界绝不包含在内。
- 所在行被从保留历史中驱逐的选择会连同通知一起清除，而不是被静默移动。

## 验证

| 变更           | 必需检查                                                             |
| -------------- | -------------------------------------------------------------------- |
| 捕获策略变更   | 测试证明精确的启用和释放序列，以及释放状态指示器                     |
| 新增区域       | 测试针对上一绘制帧解析区域内部、每条边上和外部的按下                 |
| 手势映射变更   | 表驱动测试把每个手势映射到其唯一意图，并证明键盘等价物存在           |
| 透传变更       | 测试覆盖报告开启、报告关闭且备用屏幕、报告关闭且主屏幕，以及边界按下 |
| 滚轮归一化变更 | 测试覆盖滚轮流、触控板流、反转和单次刷写上限                         |
| 选择变更       | 测试覆盖多行导出、驱逐和 `Esc` 清除                                  |
