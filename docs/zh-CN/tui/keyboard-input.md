# TUI 键盘输入

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的按键解码、绑定模型、输入归属、焦点与激活语义、编辑与草稿约定、
返回行为和快捷键发现。具体绑定、模式名称、文案和前缀组合键属于所属应用的指南；本标准定义它们
必须满足的形状。宿主键盘协议协商遵循
[`terminal-environment.md`](terminal-environment.md)；指针输入遵循
[`mouse-input.md`](mouse-input.md)；控件状态和组合遵循
[`components.md`](components.md)。

[`frontend/keyboard-shortcuts.md`](../frontend/keyboard-shortcuts.md) 中的前端契约约束浏览器和
Desktop 绑定。按 [`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md) 一起选择 TUI 绑定和对应 GUI
绑定：保留动作的语义作用域、本地化名称、助记键、提交边界和取消结果，再按下述规则适配修饰键、
前缀或模式。

这是新增和实质性变更的 TUI 键盘行为必须满足的契约，并不声称当前 Client 已经符合。运行时采用
只能由源码和 [`verification.md`](verification.md#契约评审) 要求的证据建立。对于分阶段缺口，应记录
负责人和完成条件。在完成采用前，应用自有参考仍是当前绑定与输入行为的描述性权威。

## 解码

- 在任何所有者看到之前，先把宿主原始字节流解码为类型化按键事件。所有者匹配类型化事件，绝不
  匹配字节。
- 用能保持输入法组合正常工作的 flag 请求键盘协议消歧：消歧转义码、报告事件类型和报告备用键。
  默认不要请求把所有键作为转义码报告；只有在有证据表明每个受支持宿主上的组合仍然正常时才
  启用。
- 只对按下和重复事件采取动作。释放事件被消费且绝不分派。
- 匹配前先归一化：无修饰符的原始 C0 控制字符即对应的 `Ctrl` 组合键；大写字母隐含 `Shift`；
  旧式 `Ctrl+5` 即 `Ctrl+]`。原始 `ESC`（`0x1b`）和 `DEL`（`0x7f`）绝不归一化为 `Ctrl` 组合键。
- 只有在宿主不做消歧时，才用有界等待把单独的 `ESC` 与 `Alt` 前缀区分开。等待绝不超过一个输入
  轮询间隔，也绝不延迟已消歧的事件。
- 括号粘贴始终启用。一次粘贴作为一个原子文本事件到达，绝不与绑定匹配，并按原始顺序恰好交付
  给一个所有者。
- 格式错误、越界或超时的粘贴必须作为整段输入帧拒绝。丢弃其内容，并静默消费到与起始记法匹配的
  终止符；只有之后的字节才能恢复为普通输入。
- 多字节 UTF-8 片段和被拆开的转义序列在分派前重新组装。读取边界处被截断的序列在有界窗口内
  等待下一次读取。

## 绑定和意图模型

一个规范绑定是一个键码加一个完整的修饰符集合。匹配和展示都从该值派生；任何表面都不单独存储
标签字符串。

| 关注点 | 规则                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------- |
| 匹配   | 归一化后的事件等于归一化后的绑定；修饰符的超集不匹配                                                              |
| 备选   | 一个动作可以列出多个绑定；第一个是展示的提示，顺序不承载分派优先级                                                |
| 标签   | 修饰符按 `Ctrl`、`Alt`、`Shift`、`Super` 顺序排列，用 `+` 与键连接                                                |
| 键名   | `Enter`、`Esc`、`Tab`、`Space`、`Backspace`、`Delete`、`Home`、`End`、`PageUp`、`PageDown`、`F1`…`F12`、`↑ ↓ ← →` |
| 平台   | 在 Apple 宿主上把 `Alt` 显示为 `⌥`；由客户端操作系统决定，而不是服务端                                            |
| 组合   | 前缀后跟一个键时，显示为用一个空格分开的两个标签                                                                  |
| 回退   | 简化字形下箭头字形使用 `Up`、`Down`、`Left`、`Right`                                                              |

除非 `Shift` 是绑定的一部分，字母以小写显示。数字范围显示为 `1..9`，绝不显示为九个条目。

- 绑定解析为有作用域的语义意图，而不直接解析为渲染器修改。同一个已提交操作的键盘和指针路径使用
  相同的意图身份、目标、可用性检查、提交边界和结果。
- 有效绑定是经过用户覆盖、能力门控和遮蔽之后，在当前所有者和状态中确实可以执行的绑定。分派、
  页脚提示和快捷键帮助都从该有效模型派生；展示的默认值绝不声称一个被遮蔽的按键可以工作。
- 已注册产品动作使用其动作定义。组件本地编辑器、选择器和模式可以拥有结构化 keymap，显式命令
  表面可以拥有结构化命令条目。它们通过各自所有者参与发现；任何规则都不假设全部命令来自同一个
  全局注册表。

## 输入归属

每个按键或粘贴事件恰好有一个所有者，按以下四层解析：

1. 独占捕获，例如最上层模态任务、行编辑器或确认。
2. 当前命名输入所有者或模式，包括具有显式焦点和可见指示器的 Orchbee chrome 表面或控件。
3. 更高所有者准入时的已激活前缀层。
4. 向聚焦终端 pane 的原样透传。

归属规则：

- 只有焦点目标已绘制且焦点指示器可见时，聚焦的 Orchbee 表面才是命名所有者。若目标变得不可绘制、
  隐藏或被遮挡，该表面必须先把焦点移到记录的已绘制回退目标或放弃归属，之后才能接受另一个按键。
  禁用目标遵循所属组件声明的焦点策略：它可以保持可聚焦，使当前所有者能显露本地化原因；也可以被
  跳过并采用同一确定性回退。它绝不激活。记忆中的目标绝不通过过期几何授权输入。
- 命名所有者只可为其可见交互契约绑定裸导航键、`Enter`、`Space`、`Tab` 或编辑键。把焦点移入
  chrome 必须是显式操作；仅悬停绝不建立键盘归属。
- 在独占捕获或命名所有者之外，Client 不绑定任何无修饰符的可打印键，不绑定裸 `Enter`、`Tab`、
  `Esc` 或 `Backspace`，也不绑定 `Ctrl+C`、`Ctrl+D` 或 `Ctrl+Z`。更高所有者拒绝后，前缀组合键是
  唯一的默认无条件拦截；没有捕获所有者时，连按两次会转发字面组合键，捕获所有者也可按自身契约消费它。
  用户显式配置可以在更高归属之后添加安全直达键；上述可打印字符、编辑键及信号键排除规则仍适用。
- 已激活的前缀没有超时。`Esc` 与宿主失焦撤销它。发送给终端的粘贴也在后续按键前撤销被中断的前缀；捕获界面拥有的粘贴保持该界面的契约。宿主能力响应不撤销前缀。前缀后的未绑定键撤销前缀、不转发任何内容，并显示一条
  指明有效帮助绑定的瞬时通知。
- 命名模式在其持续期间拥有一个领域。它的名称和返回路径始终可见；每个键最多解析为一个意图；
  未绑定键被忽略，绝不转发。模式不嵌套：进入另一个模式会通过已记录的转换替换当前模式。
- 模态任务或确认等独占捕获消费每个键，包括前缀组合键，直到通过记录的本地返回步骤提交、取消或让出。
  只有独占捕获可以在尚未取得可见命名归属时接受无修饰符的可打印文本。
- 捕获型覆盖层可以准入配置的前缀，用于关闭自身或切换到另一表面，但这些动作仍由常规绑定所有者解析。
  普通按键和粘贴仍归覆盖层所有；此路径绝不绕过其上方的独占捕获。
- 没有更高所有者消费的字节原样、按序到达聚焦终端。Client 绝不重排、合并或丢弃透传输入。尤其
  当终端 pane 拥有键盘时，`Esc` 仍然是 pane 输入；命名所有者按自己的本地返回契约处理 `Esc`。
- 归属是基于上一已呈现交互状态和一个事件的纯决策。网络进度和后台工作绝不静默移动归属。完成的
  一帧可以为后续事件建立新所有者；绝不把正在分派的事件改路由。

## 焦点、选择和激活

- 键盘焦点、指针悬停、临时选择、持久当前上下文和激活彼此独立。chrome 拥有键盘时，恰好一个
  已绘制 Orchbee 区域显示键盘焦点；聚焦的终端 pane 按 pane 契约显示自身焦点。
- 焦点移动不激活目标，也不改变持久当前上下文。集合所有者声明方向键移动焦点、临时选择还是二者，
  并声明组合状态如何渲染。
- `Enter` 和 `Space` 没有一套通用于所有行的行为。每个聚焦控件声明其主意图：立即动作、导航、
  临时选择、显式接受、展开、编辑，或另一种经评审的组件契约。对应的指针路径调用同一意图，而不是
  从行的形状推断行为。
- `Tab`、方向键、翻页键和组件助记键只在上一已呈现焦点图中的目标间移动。隐藏、不可绘制、被遮挡，
  以及因宽度或能力而省略的目标都会被跳过。禁用目标只有在组件声明其可聚焦时才参与；它在聚焦时
  保留禁用呈现、不分派激活，并通过组件或当前帮助所有者显露相同的本地化不可用原因。除非所有者
  记录了空间关系，导航顺序遵循阅读顺序。
- 打开临时表面时记录此前的语义焦点目标，而不只是其单元格。关闭后，目标仍有效则焦点返回该处；
  否则所有者使用其记录的已绘制回退目标。焦点绝不返回被遮挡或过期的目标。

## 编辑与草稿

每个内联文本编辑器都遵守下列适用约定。编辑器可以增加绑定；绝不静默重新绑定它声称支持的约定。

| 键                             | 单行行为                       |
| ------------------------------ | ------------------------------ |
| `Enter`                        | 草稿有效时提交；否则在页脚说明 |
| `Esc`                          | 调用编辑器当前的本地返回步骤   |
| `Backspace`                    | 删除光标前的一个字素           |
| `Delete`                       | 删除光标后的一个字素           |
| `← →`                          | 移动一个字素                   |
| `Home` `End` `Ctrl+A` `Ctrl+E` | 移动到开头或结尾               |
| `Ctrl+W`                       | 删除光标前的一个词             |
| `Ctrl+U`                       | 显式清空草稿                   |
| 粘贴                           | 在光标处原子插入               |

- 编辑器声明其值是持久 composer 草稿、暂存编辑还是立即控件。移动焦点、打开帮助或选择器、停放
  Orchbee 自有阻塞任务以及访问临时覆盖层，都会保留持久 composer 草稿。只有成功提交、显式清空或
  所有者记录的取消动作才移除它。
- 取消暂存编辑会恢复本次编辑边界开始时的值。仅移动焦点或关闭子弹层不提交也不丢弃它。
- 多行编辑器声明彼此独立的换行和提交绑定。页脚显示这一对有效绑定；`Enter` 的含义绝不因为
  终端变窄而改变。
- 设置提交策略遵循 [`settings.md`](settings.md#草稿预览与提交) 及功能的共同契约；键盘输入绝不从
  控件形状推断应用时机。在原子编辑器中，键盘和指针编辑同一份草稿，只有其显式 `Save` 跨过写入
  边界。返回效果按层级区分：子级返回恢复已记录的父级导航和草稿，保留父级已接受编辑，只把子级
  尚未接受的编辑或预览恢复到进入时投影。根草稿有修改时，原始已保存基准仅保留用于和最新已确认
  有效状态比较冲突。根级在提交前关闭时丢弃其草稿和预览，再投影该最新状态。立即控件只有在所有者
  声明该策略，且控件不处于外围原子草稿中时，才在激活时提交。
- 草稿有以 Unicode 标量计的已记录最大长度。超出的输入以可见通知拒绝；绝不静默截断。粘贴按
  同一个上限原子处理。
- 编辑现有值的编辑器会预填该值，并把光标放在记录的选择位置或末尾。重新打开保留的 composer
  时，只要状态仍有效，就恢复其草稿、光标和选择。
- 通过输入法的组合必须正常工作：编辑器绝不在组合期间消费绑定，也绝不以会遮住组合候选行的
  方式重绘。
- 破坏性确认只接受其精确确认动作和本地返回动作。它捕获包含该决定的整个输入包，尾随字节绝不
  到达终端；默认结果是取消且不产生破坏性效果。

## 本地返回与取消

- 活动所有者以结构化数据公开当前唯一的本地返回步骤：语义意图、有效按键、本地化标签、状态效果、
  草稿效果和焦点目的地。处理器、页脚、帮助以及指针关闭或返回控件消费同一个步骤；绝不承诺不同
  的结果。
- `Esc` 最多执行当前所有者的一个可逆步骤。依所属所有者而定，该步骤可以关闭子搜索或下拉框、
  离开编辑器并保留 composer 或恢复暂存值、清除临时选择、关闭临时表面、停放 Orchbee 自有阻塞
  任务并让它继续等待，或离开命名模式。这些是本地可能性，不是所有表面共享的全局优先级列表。
- 命名 Orchbee 所有者没有本地返回步骤时，采用其记录的焦点回退。默认 chrome 的 `Esc` 绝不取消
  正在运行的工作、终止 Agent 或清除无关草稿。离开产品表面或 Client 是另有所有者的返回或退出
  动作，绝不从本地步骤缺席这一事实推断。取消运行工作是独立命名的语义动作，拥有自己的作用域和
  确认策略。
- 终端 pane 拥有输入时，`Esc` 会转发给其中的程序。由 pane 内 Agent 呈现的阻塞提示和卡片保留
  Agent 自身的输入语义；Orchbee 不会把它们重新解释为 Client 自有任务。
- 只有指针关闭、返回或背景手势具有相同的状态、草稿和焦点效果时，它才映射到同一本地返回意图。
  否则使用单独命名的动作。几何未命中绝不算作同意或取消。

## 发现

- 活动所有者从与分派相同的状态和解析器提供结构化有效提示。动作定义、组件本地 keymap、widget
  状态和显式命令条目都可以参与；重复手写的标签不是绑定事实来源。
- 状态行或页脚通过 [`layout.md`](layout.md#尺寸层级) 中的层级显示当前所有者最有用的动作。当前
  返回或焦点恢复路径以及完整帮助入口在紧凑截断下仍可发现。待确认动作以其精确下一步替换普通提示。
- 完整快捷键帮助标识活动作用域，优先展示有效按键；只有在明确显示不可用状态和本地化原因时，
  才可以为了学习保留非活动或禁用动作。被遮蔽按键不会在活动作用域中显示为可用。
- 前缀帮助列出该前缀拥有的有效绑定。模式帮助显示该模式的有效绑定及当前返回步骤。组件本地帮助
  留在组件所有者中，不会被迫塞入无关的全局注册表。
- 具体产品绑定、文案和业务动作留在所属应用指南中。可行时从结构化所有者生成文档，并通过相同的
  意图及有效绑定测试核对显式条目。

| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| 绑定或意图   | 测试证明精确修饰符匹配、Apple 与非 Apple 标签、覆盖与遮蔽解析，以及键鼠在目标、可用性和提交方面一致                                                                          |
| 归属变更     | 表驱动测试证明全部四层、可见聚焦 chrome 的准入与回退、过期目标拒绝、禁用焦点策略、前缀行为、pane `Esc` 和有序透传                                                            |
| 可聚焦控件   | 测试覆盖已绘制目标顺序、隐藏目标无条件迁移、两种已声明禁用焦点策略的原因发现及不激活、焦点与选择、尺寸变化或遮挡后的回退，以及语义焦点返回                                   |
| 编辑器或草稿 | 测试覆盖编辑键、长度和粘贴上限、输入法、焦点与覆盖层间的保留、提交、显式清空、暂存取消、光标恢复和多行提示                                                                   |
| 设置控件     | 测试证明已声明策略：键鼠共享草稿；只有显式 `Save` 写入；子级返回保留父级已接受编辑并恢复进入状态；根级关闭丢弃本地工作并显示最新已确认状态；立即控件只在原子草稿外按声明提交 |
| 返回行为     | 测试从同一本地步骤派生提示与处理器，并覆盖其精确状态、草稿、工作取消、指针、pane 透传和焦点返回效果                                                                          |
| 确认         | 测试证明决定包中的尾随字节不会到达终端，并且取消不产生破坏性效果                                                                                                             |
