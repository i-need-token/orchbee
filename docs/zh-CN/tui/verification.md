# TUI 验证

## 权威性和范围

本标准拥有 Orchbee 自有终端界面变更所需的证据。它把 [`TESTING.md`](../TESTING.md) 和
[`RUST.md`](../RUST.md#测试) 中的仓库测试义务应用到单元格网格，并选出其他 `tui/` 标准引用的证据
类别。变更分级和建模遵循 [`DEVELOPMENT.md`](../DEVELOPMENT.md#变更分级) 和
[`MODELING-AND-CORRECTNESS.md`](../MODELING-AND-CORRECTNESS.md)；新增模式、手势、覆盖层生命周期
或归属变更属于 Modeled 工作。

## 结构前提

只有界面保持以下边界时，下文的证据才可能成立：

| 职责 | 契约                                                         |
| ---- | ------------------------------------------------------------ |
| 状态 | 纯数据，不持有终端、网络或时钟的句柄                         |
| 决策 | 从一个输入事件和当前状态到至多一个类型化意图的纯函数         |
| 布局 | 从几何和状态到区域及已记录命中矩形的纯函数                   |
| 渲染 | 从状态、区域、主题和 locale 到缓冲区的纯函数；无修改，无 I/O |
| 效果 | 由所有者在决策之后应用，绝不在决策、布局或渲染内部           |
| 时间 | 注入；决策、布局或渲染内部绝不读取墙上时钟                   |

把 I/O、时间或修改拉入决策、布局或渲染的变更在审查中被拒绝，无论其测试如何。

## 渲染证据

- 通过 `ratatui::backend::TestBackend` 渲染，并把缓冲区作为文本与保存在测试内或旁边 fixture
  中的预期值比较。添加快照库是 [`DEVELOPMENT.md`](../DEVELOPMENT.md#决策权威) 下的依赖决定。
- 每个表面在这些几何下渲染：80×24、120×40、来自 [`layout.md`](layout.md#尺寸层级) 的一个 Compact
  和一个 Minimal 几何，以及"过小"几何。
- 每个表面在 `terminal-native` 和一个 RGB 主题下，以及 `en-US` 和 `zh-CN` 下渲染。凡是文本截断或
  换行之处都有宽字符 fixture。
- 样式断言通过主题检查角色，而不是字面颜色；唯一例外是证明 16 色色深不产生任何 `Rgb` 或
  `Indexed` 单元格的量化测试。
- 预期文本更新作为视觉差异审查。审查者未看到前后行之前，快照绝不改变。

## 输入证据

| 类别   | 必需用例                                                                     |
| ------ | ---------------------------------------------------------------------------- |
| 解码   | 每个 C0 归一化、大写隐含 `Shift`、`Ctrl+]`、单独 `ESC`、拆开的序列、原子粘贴 |
| 绑定   | 匹配、带额外修饰符时不匹配、Apple 和非 Apple 宿主上的标签、备选显示第一个    |
| 归属   | 每对所有者的表驱动优先级；未消费字节按序透传                                 |
| 模式   | 指示器可见、`Esc` 退出、未绑定键被忽略、模式不嵌套                           |
| 编辑器 | 每个编辑键、长度上限、预填、原子粘贴、组合期间不消费                         |
| 确认   | 只有精确键确认、`Esc` 取消、决定包中的尾随字节不到达终端                     |
| 指针   | 针对上一绘制帧的命中测试、透传决定、手势到意图表、滚轮归一化                 |

输入测试把类型化事件送入决策函数，并断言完整的结果意图和状态，而不是单个字段。

## 环境证据

- 模式序列作为字节串针对写入器测试：启用、恢复、逆序，以及前一步失败后每一步仍然执行。
- 能力查询用及时应答、迟到应答、无应答，以及与按键输入交错的应答测试。
- 环境变量优先级是表驱动的，并包含 `NO_COLOR`。
- 输出循环测试每个节拍间隔一次刷写，以及每帧一对同步更新。

## 宿主证据

有些行为只存在于真实模拟器中：键盘协议协商、指针透传编码、明暗报告和 multiplexer 拦截。

- 通过驱动 Client 二进制并断言其写出字节的伪终端 harness 来演练，或通过已记录的手动运行。
- 随证据记录模拟器名称和版本、multiplexer（如有）以及操作系统。
- 宿主证据补充单元证据；绝不替代上述类别。

## 变更清单

| 变更             | 证据                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 新增表面         | 每个几何、主题和 locale 下的渲染证据；捕获输入时还有归属和页脚测试 |
| 主题角色或值     | 重新渲染每个消费者；量化测试                                       |
| 绑定或模式       | 绑定、归属和模式类别；帮助输出从注册表派生                         |
| 手势或区域       | 指针类别；证明键盘等价物                                           |
| 终端模式或查询   | 环境类别；协商的宿主证据                                           |
| 布局层级或降级   | 每个层级的渲染证据；每个降级步骤一个测试                           |
| 通知或等待指示器 | 注入时间的测试覆盖到期、替换和恒定宽度                             |
| 仓库门禁         | `pnpm verify` 通过                                                 |
