# TUI 验证

## 权威性和范围

本标准拥有 Orchbee 自有终端界面变更所需的证据。它把 [`TESTING.md`](../TESTING.md) 和
[`RUST.md`](../RUST.md#测试) 中的仓库测试义务应用到单元格网格，并选出其他 `tui/` 标准引用的证据
类别。变更分级和建模遵循 [`DEVELOPMENT.md`](../DEVELOPMENT.md#变更分级) 和
[`MODELING-AND-CORRECTNESS.md`](../MODELING-AND-CORRECTNESS.md)；新增模式、手势、覆盖层生命周期
或归属变更属于 Modeled 工作。

## 结构前提

只有界面保持以下边界时，下文的证据才可能成立：

| 职责 | 契约                                                         |
| ---- | ------------------------------------------------------------ |
| 状态 | 纯数据，不持有终端、网络或时钟的句柄                         |
| 决策 | 从一个输入事件和当前状态到至多一个类型化意图的纯函数         |
| 布局 | 从几何和状态到区域及已记录命中矩形的纯函数                   |
| 渲染 | 从状态、区域、主题和 locale 到缓冲区的纯函数；无修改，无 I/O |
| 效果 | 由所有者在决策之后应用，绝不在决策、布局或渲染内部           |
| 时间 | 注入；决策、布局或渲染内部绝不读取墙上时钟                   |

把 I/O、时间或修改拉入决策、布局或渲染的变更在审查中被拒绝，无论其测试如何。

## 契约评审

实现前按适用范围对照 [`components.md`](components.md)、[`actions.md`](actions.md) 和
[`settings.md`](settings.md) 评审所属契约。指出应复用的既有组件，或说明扩展、替换、新建本地组件
的理由；明确状态轴、槽位、提交与返回边界、有效绑定、命中目标、降级及效果归属。通过
[`INTERFACE-DESIGN.md`](../INTERFACE-DESIGN.md) 评审 GUI/TUI 共同语义。将决定保留在既有所属
参考、类型或测试中，不另建任务目录。

选择呈现或交互变更前，先在运行中的终端里检查现有界面。如果体验目标尚不清楚，应通过所选
参考产品的相关操作流程，确定层级、可发现性、反馈和任务完成方面的可观察目标。

仅修改规范时，通过语义、双语、链接和适用仓库检查验收；这不能证明运行时已符合规范。受影响的
实现必须提供下述证据后才能声明采用。使用参考产品时，区分实测行为、明确版本下的源码行为和
拟定的 Orchbee 要求；已安装产品与源码不同不能成为两者实现同一版本的证据。

## 渲染证据

- 通过 `ratatui::backend::TestBackend` 渲染，并把缓冲区作为文本与保存在测试内或旁边 fixture
  中的预期值比较。添加快照库是 [`DEVELOPMENT.md`](../DEVELOPMENT.md#决策权威) 下的依赖决定。
- 每个表面在这些几何下渲染：80×24、120×40、来自 [`layout.md`](layout.md#尺寸层级) 的一个 Compact
  和一个 Minimal 几何，以及"过小"几何。
- 每个表面在 `terminal-native` 和一个 RGB 主题下，以及 `en-US` 和 `zh-CN` 下渲染。凡是文本截断或
  换行之处都有宽字符 fixture。
- 变化控件覆盖适用的静止、hover、按下、焦点、当前、临时选择、已选、禁用、处理中和结果状态。
  包含 [`components.md`](components.md#状态模型) 中有意义的组合，不穷举所有笛卡尔积组合。
- 样式断言通过主题检查角色，而不是字面颜色；唯一例外是证明 16 色色深不产生任何 `Rgb` 或
  `Indexed` 单元格的量化测试。还须演练 `NO_COLOR` 与宿主默认颜色重合的情况：焦点、当前上下文、
  已选值、临时选择、可用性和操作状态仍能通过要求的标记、文字或修饰符区分。没有 RGB 单元格
  本身不能证明对比度可用。
- 预期文本更新作为视觉差异审查。审查者未看到前后行之前，快照绝不改变。

## 整屏视觉评审

呈现和交互变更须在真实终端模拟器里使用运行中的 Client，并通过实际窗口截图评审，
从默认主题开始。在等价的几何、
语言、数据和输入归属下对比；把变化区域与周围的导航、内容及状态一起检查。
检查当前上下文辨识、焦点区分、文字层级、重复标签和操作、空状态、分组，以及主要内容
可用空间。覆盖受影响的普通、导航和分屏／放大状态；单个组件渲染不能证明整屏质量。
检查静止时的动作可辨识性、hover 不移动焦点、稳定的标签列、狭窄几何下完整的主要及退出提示，
以及操作目标的身份。

- 截取变更前后的完整合成画面；检查变化区域时，保留周围导航、内容和状态。
- 截取判断变更所需的适用状态，包括 hover、按下、焦点、选择、展开、覆盖层及狭窄几何。
  单张静止画面不能证明这些状态或状态转换。
- 使用相关鼠标和键盘输入，走完受影响的主要任务及取消或返回路径。随截图记录实际观察结果；
  仅凭图像不能证明输入路由、焦点恢复或响应情况。
- 从用户任务的角度评审结果，修复视觉或交互缺陷，再重复受影响的流程并截取最终效果。

应用拥有已接受的画面组织及可观察视觉不变量。后续功能变更须保留这些结果，或明确重新
审视所属决策。测试保护可机械检查的结果；仅更新预期字符行或通过角色断言，不代表接受
视觉退化。对比及判断记录在当前评审中，不另建入库任务报告。

说明每张图像的来源及正在执行的构建或版本，并记录下文要求的宿主信息。渲染缓冲区及
PTY/ConPTY 回放属于补充的画面组织和协议证据，不能替代实际窗口截图或实际使用观察，
也不能证明物理宿主的调色板、字体、对比度或字形绘制。

真实宿主评审是人工或 Agent 评审要求，不是自动化根门禁的结果。无法使用或截图运行中的
界面时，应分开报告实现与自动化检查，并保留体验验收为待完成状态。不得仅因测试、角色
断言或渲染预览通过，就宣告呈现或交互变更已经完成。

## 输入证据

| 类别   | 必需用例                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 解码   | 每个 C0 归一化、大写隐含 `Shift`、`Ctrl+]`、单独 `ESC`、拆开的序列、原子粘贴                                                   |
| 绑定   | 匹配、带额外修饰符时不匹配、宿主标签、受支持的有效覆盖、遮蔽及显示提示与活动定义一致                                           |
| 归属   | 每对所有者的表驱动优先级；未消费字节按序透传；隐藏所有者和过期目标不能执行                                                     |
| 模式   | 指示器可见、局部 `Esc` 步骤、未绑定键被忽略、模式不嵌套，以及无具名所有者时保护 pane `Esc`                                     |
| 编辑器 | 每个编辑键、长度上限、预填、原子粘贴、组合期间不消费，以及临时任务前后的草稿／光标保留                                         |
| 确认   | 只有精确键确认、`Esc` 取消、决定包中的尾随字节不到达终端                                                                       |
| 指针   | 最近成功刷写的命中图、子目标优先、精确 pane 事件类别过滤、hover 不选择、同目标释放、离开／失去捕获取消、过期图失效及滚轮归一化 |

输入测试把类型化事件送入决策函数，并断言完整的结果意图和状态，而不是单个字段。

## 生命周期证据

| 变化契约   | 必需用例                                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 语义动作   | 键盘、指针及发现入口解析到同一动作和类型化目标；效果前重新检查资格；重复调用遵守声明的并发策略；每次执行有唯一归类结果                     |
| 嵌套表面   | 子任务返回恢复查询、选择、逻辑滚动锚点、草稿、预览及有效焦点；根表面关闭恢复调用者或声明的兜底位置；关闭不暗中取消已接受工作               |
| 预览与设置 | 已保存、生效、草稿、预览及光标值保持独立；取消预览恢复进入时的值；校验／拒绝保留草稿；Save、重置、外部更新及未知写入结果遵守所有者提交契约 |
| 异步更新   | 替换的请求、移除的目标、关闭／重新打开的表面及过期 generation 不能修改新视图或夺取焦点；有效结果通过语义所有者落定                         |
| 视口       | 尺寸变化、过滤、插入、移除及换行内容变化保留声明的身份或逻辑内容锚点；显式跟随底部与手动阅读分开                                           |

使用注入时间和可控完成顺序。不得用 sleep 或仅断言最后渲染标签正确来替代过期结果测试。

## 环境证据

- 测试模式序列或平台适配器调用的启用、恢复、逆序、部分获取、重复清理，以及前一步失败后
  每一步仍然执行。包含正常、错误、panic、受支持信号及交给外部程序的路径。
- 能力查询用及时应答、迟到应答、无应答，以及与按键输入交错的应答测试。
- 环境变量优先级是表驱动的，并包含 `NO_COLOR`。
- 输出循环测试每个节拍间隔一次刷写、每帧一对同步更新、效果只在帧间发生、未知写入不重放，
  以及输出和指针移动突发下输入仍能有界推进。hover 重绘只在解析目标变化时发生，并遵守已准入
  捕获与节拍策略。

## 宿主证据

有些行为只存在于真实模拟器中：键盘协议协商、指针透传编码、明暗报告和 multiplexer 拦截。

- 通过驱动 Client 二进制并断言其写出字节的伪终端 harness 来演练，或通过已记录的手动运行。
- 随证据记录模拟器名称和版本、multiplexer（如有）、操作系统、几何、locale、主题及协商能力。
  视觉评审还须记录字体、字号和显示缩放比例；无法获取的元数据应明确标出，而不是推测。
  PTY 或 ConPTY 字节回放证明协议行为与单元格组织，不能证明物理宿主的调色板或字体质量。
- 宿主证据补充单元证据；绝不替代上述类别。

## 响应与空间稳定性

响应主张在计时前先明确语义动作、精确目标和期望的本地反馈。比较应使用同一宿主、实际内部几何、
数据、locale、主题及可比较的构建模式；源码、安装程序和执行 cohort 身份分别记录。
用启用与禁用采集的运行记录测量扰动。参考产品的源码机制不能证明安装版本的行为或 CI 实际执行。

| 测量                 | 必需节点及边界                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 输入到可见反馈       | 用实际宿主捕获包围输入交付与首个期望控件／内容变化。采用语义区域和判定条件；光标闪烁、动画、无关输出或标题变化均不满足该条件，并报告捕获的不确定区间。 |
| 创建到有用内容       | 识别被创建目标及其首个有用终端或任务内容。即时本地接受、后台完成和 canonical 就绪是不同节点。                                                          |
| 输入就绪后或队列等待 | 明确被观察队列及其准入／出队时间戳。无法获取到达时间时，只报告已测的应用边界或外部上界；主动轮询等待不等于队列停留。                                   |
| 准备与输出耗时       | 区分布局／buffer 准备、编码、原样转发的写器／flush 调用及确认。调用墙钟耗时可能包含 CPU 与阻塞；输出完成不证明物理绘制或语义反馈。                     |

- 执行完整任务及取消、失败和返回路径。把期望位置中的即时本地接受，与延迟进度及最终内容分别检查；
  其他地方的 spinner 变化不能证明被请求目标已经响应。
- 记录样本数与分布、环境／负载、失败及超时样本，以及测量边界。截断、中止、无效或不完整轨迹不能
  证明完整分布。场景回归目标应来自实际基线，不得推导通用预算或跨不匹配构建的速度倍率。
- 在有界、可重现的内容生产者持续输出时驱动输入。验证输入进展、取消／release 顺序及期望反馈，
  判定条件须排除该输出。先定位首个延迟阶段，再修改调度或写器架构。
- 按方向、数量、时间和 burst／反向边界描述滚轮报告。分别执行密集及稀疏流、归属变化、pane
  passthrough 和自有列表／历史场景。等价合成报告不能证明物理滚轮或触控板移动等价。
- 在阅读有逻辑标识的内容及新内容到达期间 resize。验证已声明的行／身份锚点、焦点和选择，
  并把显式跟随底部与手动阅读分开。捕获的终端网格与自绘换行文档可以拥有不同 reflow 契约；
  不能用另一产品的算法取代本产品的权威规则。
- 实时拖动轨迹在 release 前至少包含两次持续按下的移动，且中间经过绘制帧。观察两个位置下受影响
  内容的实际几何、单独 release 后的保留结果及已声明的取消和旧归属／视口行为。只有终点图像不能
  证明实时调整，也不能区分自有投影和外部几何变化。

循环使用的场景定义与采集工具归语义所有者维护。时点测量、截图和对比判断放在当前问题／评审中，
注明消费者和释放条件，不创建受跟踪任务报告。这些检查补充上面的渲染、输入、生命周期和宿主证据；
计时与截图都不能替代这些契约。

## 变更清单

| 变更             | 证据                                                               |
| ---------------- | ------------------------------------------------------------------ |
| 新增表面         | 每个几何、主题和 locale 下的渲染证据；捕获输入时还有归属和页脚测试 |
| 组件或组合       | 契约评审、适用状态组合、消费者采用及整屏视觉评审                   |
| 主题角色或值     | 重新渲染每个消费者；量化与非颜色可区分性                           |
| 绑定或模式       | 绑定、归属和模式类别；帮助反映有效定义和本地按键映射               |
| 手势或区域       | 指针类别；证明键盘等价物                                           |
| 动作或设置       | 适用的生命周期用例、语义目标、提交、失败及并发证据                 |
| 终端模式或查询   | 环境类别；协商的宿主证据                                           |
| 布局层级或降级   | 每个层级的渲染证据；每个降级步骤一个测试                           |
| 通知或等待指示器 | 注入时间的测试覆盖到期、替换和恒定宽度                             |
| 仓库门禁         | [适用的根门禁](../VERIFICATION.md#合并门禁)通过                    |
