# TUI 终端环境

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的宿主终端准入、平台适配、终端模式生命周期、能力探测、输出纪律、
尺寸变化处理和恢复。它约束 Client 进程与承载它的终端模拟器或原生控制台之间的边界。保留 pane
内部的终端语义属于终端执行服务及其协议，不属于本标准。

这些条款是必需契约。在这里命名某种模式或能力，并不表示每个当前 Client 都已实现它。只有适配器和
可观察的宿主路径提供了本标准要求的证据后，所属 workspace 才能宣称支持该行为。

## 准入

- 全屏 Client 要求输入和输出都是交互式 TTY，并满足当前同一终端身份与描述符安全规则。非交互
  流或几何查询失败都是用法失败，以有效 locale 写入 stderr；不改变任何终端模式。
- 正常界面绘制以及任何被保留终端工作开始之前，必须获得真实的非零单元格几何。绝不猜测单元格
  尺寸。
- 应用可以在其 owning contract 中声明一个有界的 awaiting-geometry 阶段，处理零行列或暂不
  可绘制的单元格上报。该阶段只使用已准入的同一组描述符和原启动截止时间；等待输入及其界面
  由终端模式生命周期拥有，可为其等待界面进入并随后恢复所需模式。该阶段不启动任何 site、
  服务或被保留的终端；取消、超时或故障恢复所有已获取模式，等待中消费的输入绝不重放。未
  声明该阶段的路径对不可绘制上报保持拒绝。
- 像素几何只在宿主报告时使用。绝不根据字体假设猜测；缺少像素尺寸是一种合法未知，它禁用
  依赖像素的功能，而不是阻塞纯单元格界面。
- Client 只准入 TTY 一次，并把同一组描述符交给界面。准入后绝不按路径重新打开控制终端。
- 帮助和版本输出绝不触碰终端模式。

## 模式生命周期

Client 启用的每个模式都有一个配对的恢复步骤。恢复按启用的逆序执行。

| 模式         | 启用                                                                                | 恢复                 | 时机                                           |
| ------------ | ----------------------------------------------------------------------------------- | -------------------- | ---------------------------------------------- |
| 原始输入     | 平台适配器禁用回显和规范或已处理输入                                                | 恢复保存的属性       | 始终                                           |
| 备用屏幕     | DEC `1049`                                                                          | 离开并恢复主屏幕     | 全屏 Client                                    |
| 括号粘贴     | DEC `2004`                                                                          | 禁用                 | 始终                                           |
| 键盘增强     | 对 [`keyboard-input.md`](keyboard-input.md#解码) 中的 flag 做一次自有压入           | 做一次配对弹出       | 能力获准后                                     |
| 指针报告     | 全局选择 DEC `1003` 或 `1002`，并启用 `1006`；菜单范围回退遵循策略；按需启用 `1016` | 禁用所有自有指针模式 | 按 [`mouse-input.md`](mouse-input.md#捕获策略) |
| 焦点报告     | DEC `1004`                                                                          | 禁用                 | 某个表面在失焦时改变行为时                     |
| 同步输出     | 每帧包裹 DEC `2026`                                                                 | 结束更新             | 每帧；不支持时无害                             |
| 配色方案通知 | DEC `2031`                                                                          | 禁用                 | 宿主应答明暗查询时                             |

- 以终端生命周期模块拥有的显式命令序列发出模式变更，并为每个变更记录恢复步骤。其他模块绝不
  写模式序列。
- 发出每个自有获取之前先创建待定恢复项。成功后把它标记为已获取；写入部分完成或结果未知时，
  保守地保持其可恢复且绝不重放获取；当失败能证明效果没有发生时将其退役。如果获取在仅部分步骤
  成功后中止，则在返回失败前按逆序撤销已获取或可能已获取的子集。后续进入绝不覆盖仍由先前进入
  拥有的原始状态。
- 恢复在正常退出、错误退出、panic hook、受支持且可捕获的终止信号，以及允许清理的平台关闭回调时
  执行。无法捕获的 kill 或强制进程终止没有进程内恢复机会。即使前一步失败，每一步也都会尝试；
  所有步骤执行完后再报告第一个错误。
- 一次键盘增强激活最多发出一次自有压入。它的配对弹出最多消费一次且绝不重放；弹出在离开备用屏幕
  之前运行，以免把 flag 栈与屏幕绑定的宿主保留这些 flag。重复或迟到的能力应答不能再向宿主栈
  压入一帧。
- 切换全局指针跟踪级别时，先禁用旧级别，再启用新级别；菜单范围请求按
  [`mouse-input.md`](mouse-input.md#捕获策略) 保留按钮回退。`1006` 是与所选跟踪级别配合的编码；`1016`
  是独立的按需坐标模式。释放捕获会禁用全部自有指针模式。释放或从 `1003` 降级时，清除悬停以及
  已预备或按下的呈现，取消活动指针手势，并消费切换期间收到的移动，不把未请求的移动转发给 pane
  内程序。
- 恢复之后，Client 除了在 stderr 上写一条最终的本地化失败消息外，不再向终端写任何内容。
- 挂起到 shell 或把终端交给外部程序时先恢复每个模式，返回时再重新启用仍获准的模式集合。只有在
  Client 重绘出带有当前命中图的一帧后，才恢复指针捕获。

## 平台适配器

- 生命周期表达的是语义，不以转义序列为前提。POSIX 适配器拥有获准的 TTY 描述符和保存的终端
  属性。原生 Windows 适配器拥有获准的准确控制台输入、输出句柄、它们保存的 mode word，以及
  它修改的其他控制台属性。两类适配器向 Client 公开相同的获取、挂起、恢复运行和还原结果。
- 适配器在第一次修改某项原始属性前先捕获它，并恢复该准确值，而不是重建的默认值。在 Windows
  上，这包括分别保存输入与输出控制台模式；如果 Client 修改控制台标题或其他原生属性，也按同一
  所有权规则保存并恢复该值。
- 每次成功的原生修改都立即登记清理。如果后续句柄查询、模式变更、VT 路径激活或命令写入失败，
  适配器恢复它拥有的所有较早修改。单项原生或流恢复失败后，清理仍继续。
- Windows 适配器只有在所需输入和输出路径已启用或原本存在后，才准入依赖 VT 的能力。成功写入
  ANSI 序列不能证明对应输入报告会到达。不支持的能力使用其已声明回退，或在不遗留部分变更控制台
  模式的前提下让准入失败。
- 生命周期所有者使原生 API 调用与 VT 命令写入保持串行，并通过输出协调器提交这些写入。平台
  适配器不会建立第二个终端写入者。
- Client 只拥有启动时获准的宿主描述符或句柄。子进程或 pane 内程序通过终端执行服务表达其终端
  模式；它绝不直接修改外层宿主的原生控制台模式或写入生命周期序列。

## 能力探测

| 能力         | 来源                                                                                                                          | 未知意味着                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 色深         | 按此优先级：`NO_COLOR`、`FORCE_COLOR`、`COLORTERM`、`TERM` 和 terminfo；无显式描述符及 multiplexer 时可用有文档依据的厂商回退 | 16 色                                 |
| 默认颜色     | 按顺序查询一次 OSC `10`／`11`；根据有效 OSC `11` 背景分类；仅 Windows 在期限内没有有效 OSC `11` 背景时读取 `AppsUseLightTheme` | 外观未知；System 使用 `terminal-native` |
| 明暗变化     | DEC `2031` 报告，只有在明暗查询成功后才接受                                                                                   | 不做实时主题切换                      |
| 键盘增强     | 带有界应答期限的键盘协议能力查询                                                                                              | 只做旧式解码                          |
| 指针任意移动 | 显式宿主或适配器能力结果、带有持续一致性证据的产品自有平台契约，或显式且受支持的用户选择                                      | 菜单范围之外使用 DEC `1002` + `1006`  |
| UTF-8        | 按此优先级：`LC_ALL`、`LC_CTYPE`、`LANG`                                                                                      | ASCII 字形回退                        |
| Multiplexer  | `TMUX`、`ZELLIJ` 和 `STY` 是否存在                                                                                            | 不在 multiplexer 内                   |
| 终端名称     | `TERM_PROGRAM` 和厂商变量                                                                                                     | 不应用任何厂商特定变通                |

- 每个查询都有一个能容纳在 Client 启动预算内的期限。迟到的应答被丢弃，绝不应用。
- Client 通过生命周期写入器在首帧之前发送 OSC `10` 和 `11`，但不等待 350 ms 外观期限再绘制。
  有效 OSC `11` 背景决定浅色或深色；前景应答会被消费，但不用于分类。期限到达时，若没有有效
  OSC `11` 背景，Windows 就读取当前用户的 `AppsUseLightTheme` 注册表值，包括只有前景应答、应答
  畸形、部分或完全缺失的情况。其他平台在没有有效背景时 settle 为未知。
- 普通与模态解码器都会消费已识别的 OSC `10`／`11` 应答字符串。payload 有界；畸形或超长应答
  不用于分类。期限到达且没有有效背景时，Windows 使用注册表回退，其他平台 settle 为未知。迟到应答
  不能更改已 settle 的外观，也不能作为输入到达 pane。
- 查询在普通按键分派开始之前发出并消费其应答，或者解码器识别并移除应答序列，使其绝不作为输入
  到达 pane。
- 在 multiplexer 内部，由 multiplexer 应答关于它自身的查询。把它的应答当作宿主，不要假定外层终端
  的能力。
- 只有显式颜色描述符缺失且未检测到 multiplexer 时，才可使用有文档依据的厂商颜色标识提供能力。
  使用前验证其有界格式；继承的外层宿主标识绝不覆盖显式描述符或 multiplexer。
- 未知是一种真实状态。它绝不默认为深色或浅色极性、真彩，或增强键盘支持。指针任意移动有获准、
  不可用和未知三种结果。除 [`mouse-input.md`](mouse-input.md#捕获策略) 中捕获型菜单范围的请求
  外，不可用和未知都使用 `1002` 与 `1006`；该请求不提升全局能力，也绝不重新启用已释放捕获。
- 不假定存在通用的 DEC `1003` 查询。写入成功、没有立即报错、终端名称、multiplexer 名称或厂商
  环境变量都不能准入全局任意移动。如果准入它的证据被撤销，生命周期执行上文定义的串行降级和状态清理。
- 厂商特定变通以检测到的名称为键，记录观察到的缺陷，并在厂商修复后移除。变通不能在缺少上述
  获准证据来源时把指针任意移动升级为可用。

## 输出纪律

- 界面活动期间，一个输出协调器是宿主终端的唯一写入者。它串行化渲染帧和已准入的终端效果。
  日志写入文件或自有诊断通道；子进程输出绝不直接到达宿主 TTY。
- 每个候选帧都是相对上一帧的一次差异，作为一次同步更新提交，并请求一次刷写。Client 绝不有意
  提交残缺帧。如果底层写入部分完成或结果未知，该候选帧就不会成为已呈现权威：渲染基线和
  [`mouse-input.md`](mouse-input.md#命中测试和重绘) 中的命中图都会失效；交互保持暂停，直到一次已
  验证的完整重绘建立新的权威帧；结果不明确的字节绝不重放。
- 只有当前同步帧已经关闭且 flush 成功后，才能 dispatch 终端效果。终端效果字节在途时不能开始
  新帧。写入结果未知的效果会被退役，不重放。
- 重绘合并到有界节拍。输入、输出和定时器事件请求重绘；循环每个节拍间隔最多绘制一次，空闲时
  立即绘制。
- 跨过已预备目标命中区域的有序指针事件，在重绘合并前应用到手势状态。合并可以只保留最新悬停
  呈现、最终尺寸几何或重绘请求，但必须保留移出事实：回到同一目标不会重新预备点击激活。它绝不
  丢弃已解码按键、按钮转换、指针释放、释放捕获命令、能力应答或终端效果结算。每轮调度限制 pane
  输出和渲染工作量，并在有界时间内回到待处理输入和生命周期应答；输出或移动洪峰不能无限延迟
  取消、释放或恢复。
- 绘制 chrome 时隐藏光标，只在编辑器或拥有光标的 pane 内、在其报告的位置显示。
- 终端标题和其他 OSC 副作用只通过生命周期模块写入，并在退出时恢复。

## 尺寸变化

- 尺寸变化信号或事件重新查询单元格和像素几何，并触发完整重绘。
- 零或缺失的几何被忽略；上一个有效几何持续生效。
- 尺寸变化事件被合并，一轮变化的最终几何总会应用。
- 保留 pane 只在其内部几何变化时才接收尺寸变化，由 [`layout.md`](layout.md#尺寸变化) 约束。

## 验证

| 变更           | 必需检查                                                                                                                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增或修改模式 | 字节轨迹证明启用序列、每个已获取步骤有一项清理、逆序恢复、部分获取撤销，以及键盘增强压入和弹出最多一次                                                                                                     |
| 恢复路径       | 测试覆盖正常和错误退出、panic hook、受支持且可捕获的终止信号与平台关闭回调、挂起与恢复运行、外部交接，以及较早恢复失败后仍尝试每个已获取步骤                                                               |
| 平台适配器     | POSIX 与 Windows 适配器测试使用注入句柄或描述符，证明准确恢复已保存属性、分别处理 Windows 输入与输出模式、部分失败、重复清理幂等以及不存在第二写入者                                                       |
| 能力查询       | 测试覆盖及时应答、迟到应答、无应答，以及与按键输入交错到达的应答                                                                                                                                           |
| 指针准入       | 轨迹覆盖任意移动获准、不可用与未知、`1003`／`1002` 互斥、`1006`、降级与重新准入、释放与恢复运行、状态清理，以及没有未请求 pane 移动或终端名称升级                                                          |
| 环境变量优先级 | 表驱动测试证明每个变量的优先级，包括 `NO_COLOR` 高于所有其他颜色来源                                                                                                                                       |
| 输出循环或调度 | 轨迹证明每个节拍间隔最多一次刷写、每帧一对同步更新、部分完成或结果未知的帧写入后不授予权威且不重放、效果只出现在帧之间、重绘合并期间已预备目标边界转换仍有序处理，以及洪峰期间输入和应答仍在有界时间内推进 |
