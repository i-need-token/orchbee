# TUI 终端环境

## 权威性和范围

本标准拥有 Orchbee 自有终端界面的宿主终端准入、终端模式生命周期、能力探测、输出纪律、尺寸变化
处理和恢复。它约束 Client 进程与承载它的终端模拟器之间的边界。保留 pane 内部的终端语义属于终端
执行服务及其协议，不属于本标准。

## 准入

- 全屏 Client 要求输入和输出都是交互式 TTY，并满足当前同一终端身份与描述符安全规则。非交互
  流或几何查询失败都是用法失败，以有效 locale 写入 stderr；不改变任何终端模式。
- 正常界面绘制以及任何被保留终端工作开始之前，必须获得真实的非零单元格几何。绝不猜测单元格
  尺寸。
- 应用可以在其 owning contract 中声明一个有界的 awaiting-geometry 阶段，处理零行列或暂不
  可绘制的单元格上报。该阶段只使用已准入的同一组描述符和原启动截止时间；等待输入及其界面
  由终端模式生命周期拥有，可为其等待界面进入并随后恢复所需模式。该阶段不启动任何 site、
  服务或被保留的终端；取消、超时或故障恢复所有已获取模式，等待中消费的输入绝不重放。未
  声明该阶段的路径对不可绘制上报保持拒绝。
- 像素几何只在宿主报告时使用。绝不根据字体假设猜测；缺少像素尺寸是一种合法未知，它禁用
  依赖像素的功能，而不是阻塞纯单元格界面。
- Client 只准入 TTY 一次，并把同一组描述符交给界面。准入后绝不按路径重新打开控制终端。
- 帮助和版本输出绝不触碰终端模式。

## 模式生命周期

Client 启用的每个模式都有一个配对的恢复步骤。恢复按启用的逆序执行。

| 模式         | 启用                                                         | 恢复                 | 时机                                           |
| ------------ | ------------------------------------------------------------ | -------------------- | ---------------------------------------------- |
| 原始输入     | 禁用回显和规范处理                                           | 恢复保存的属性       | 始终                                           |
| 备用屏幕     | DEC `1049`                                                   | 离开并恢复主屏幕     | 全屏 Client                                    |
| 括号粘贴     | DEC `2004`                                                   | 禁用                 | 始终                                           |
| 键盘增强     | 压入 [`keyboard-input.md`](keyboard-input.md#解码) 中的 flag | 弹出                 | 宿主应答能力查询时                             |
| 指针报告     | DEC `1002` + `1006`；菜单期间的 `1003`；按需 `1016`          | 禁用所有自有指针模式 | 按 [`mouse-input.md`](mouse-input.md#捕获策略) |
| 焦点报告     | DEC `1004`                                                   | 禁用                 | 某个表面在失焦时改变行为时                     |
| 同步输出     | 每帧包裹 DEC `2026`                                          | 结束更新             | 每帧；不支持时无害                             |
| 配色方案通知 | DEC `2031`                                                   | 禁用                 | 宿主应答明暗查询时                             |

- 以终端生命周期模块拥有的显式命令序列发出模式变更，并为每个变更记录恢复步骤。其他模块绝不
  写模式序列。
- 恢复在正常退出、错误退出、panic hook 和致命信号时执行。即使前一步失败，每一步也都会尝试；
  所有步骤执行完后再报告第一个错误。
- 键盘增强 flag 在离开备用屏幕之前弹出，以免把 flag 栈与屏幕绑定的宿主保留它们。
- 恢复之后，Client 除了在 stderr 上写一条最终的本地化失败消息外，不再向终端写任何内容。
- 挂起到 shell 或把终端交给外部程序时先恢复每个模式，返回时再重新启用。

## 能力探测

| 能力        | 来源                                                                                                                          | 未知意味着                            |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 色深        | 按此优先级：`NO_COLOR`、`FORCE_COLOR`、`COLORTERM`、`TERM` 和 terminfo；无显式描述符及 multiplexer 时可用有文档依据的厂商回退 | 16 色                                 |
| 默认颜色    | 带有界应答期限的 OSC `10` 和 `11` 查询                                                                                        | 明暗未知；使用 `terminal-native` 主题 |
| 明暗变化    | DEC `2031` 报告，只有在明暗查询成功后才接受                                                                                   | 不做实时主题切换                      |
| 键盘增强    | 带有界应答期限的键盘协议能力查询                                                                                              | 只做旧式解码                          |
| UTF-8       | 按此优先级：`LC_ALL`、`LC_CTYPE`、`LANG`                                                                                      | ASCII 字形回退                        |
| Multiplexer | `TMUX`、`ZELLIJ` 和 `STY` 是否存在                                                                                            | 不在 multiplexer 内                   |
| 终端名称    | `TERM_PROGRAM` 和厂商变量                                                                                                     | 不应用任何厂商特定变通                |

- 每个查询都有一个能容纳在 Client 启动预算内的期限。迟到的应答被丢弃，绝不应用。
- 查询在普通按键分派开始之前发出并消费其应答，或者解码器识别并移除应答序列，使其绝不作为输入
  到达 pane。
- 在 multiplexer 内部，由 multiplexer 应答关于它自身的查询。把它的应答当作宿主，不要假定外层终端
  的能力。
- 只有显式颜色描述符缺失且未检测到 multiplexer 时，才可使用有文档依据的厂商颜色标识提供能力。
  使用前验证其有界格式；继承的外层宿主标识绝不覆盖显式描述符或 multiplexer。
- 未知是一种真实状态。它绝不默认为深色或浅色极性、真彩，或增强键盘支持。
- 厂商特定变通以检测到的名称为键，记录观察到的缺陷，并在厂商修复后移除。

## 输出纪律

- 界面活动期间，一个输出协调器是宿主终端的唯一写入者。它串行化渲染帧和已准入的终端效果。
  日志写入文件或自有诊断通道；子进程输出绝不直接到达宿主 TTY。
- 每帧都是相对上一帧的一次差异，包裹在一次同步更新中，并且只刷写一次。绝不刷写残缺的帧。
- 只有当前同步帧已经关闭且 flush 成功后，才能 dispatch 终端效果。终端效果字节在途时不能开始
  新帧。写入结果未知的效果会被退役，不重放。
- 重绘合并到有界节拍。输入、输出和定时器事件请求重绘；循环每个节拍间隔最多绘制一次，空闲时
  立即绘制。
- 绘制 chrome 时隐藏光标，只在编辑器或拥有光标的 pane 内、在其报告的位置显示。
- 终端标题和其他 OSC 副作用只通过生命周期模块写入，并在退出时恢复。

## 尺寸变化

- 尺寸变化信号或事件重新查询单元格和像素几何，并触发完整重绘。
- 零或缺失的几何被忽略；上一个有效几何持续生效。
- 尺寸变化事件被合并，一轮变化的最终几何总会应用。
- 保留 pane 只在其内部几何变化时才接收尺寸变化，由 [`layout.md`](layout.md#尺寸变化) 约束。

## 验证

| 变更           | 必需检查                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 新增或修改模式 | 测试证明启用序列、恢复序列，以及恢复按逆序执行                                                 |
| 恢复路径       | 测试覆盖正常退出、错误退出、panic hook，以及前一步失败后每一步仍然执行                         |
| 能力查询       | 测试覆盖及时应答、迟到应答、无应答，以及与按键输入交错到达的应答                               |
| 环境变量优先级 | 表驱动测试证明每个变量的优先级，包括 `NO_COLOR` 高于所有其他颜色来源                           |
| 输出循环变更   | 字节轨迹证明每个节拍间隔最多一次刷写、每帧一对同步更新、效果只出现在帧之间，且结果未知后不重放 |
