# Zig

## 范围和权威归属

本标准约束仓库内手写的 Zig 源码和构建代码。应用形态、工具链固定、依赖和脚本仍以[应用标准](APPLICATIONS.md)为权威；仓库级测试执行仍以[测试标准](TESTING.md)为权威。

所有 Zig 源码和构建文件都使用工作区固定的 `zig fmt` 格式化。仓库不要求额外的 Zig linter。

## 命名和模块

- 类型使用 `TitleCase`，可调用值使用 `camelCase`，其他声明和命名空间模块文件名使用 `snake_case`。根节点表示单一具名类型的文件可以使用 `TitleCase.zig`。
- 把 `pub` 视为架构边界，而不是便利手段。只导出所属入口点或使用方需要的内容，并把组合保留在所属根节点。
- 按照[语义模块设计](MODULE-BOUNDARIES.md#语义模块设计)确定模块职责和依赖方向；Zig 命名空间模块文件名描述所属领域职责，而不重复其完整限定命名空间。
- 注释解释所有权、不变量、外部约束和不明显的决策；名称和结构解释普通控制流。

## 资源和失败

- 每项分配、句柄、线程、进程和操作系统资源都只有一个明确所有者。保留自有资源的类型应提供 `deinit`，除非它通过 API 转移所有权。
- 需要分配时，从所属边界接收 allocator。不要引入隐藏的进程级全局 allocator。
- 成功获取资源后立即放置 `defer`，并使用 `errdefer` 回滚部分构造的状态。
- 对预期的输入、操作系统和资源失败返回错误。只有局部不变量能够证明失败不可能发生时，才使用 `catch unreachable`、`.?` 或 `unreachable`；绝不能用它们忽略外部输入或可恢复的运行时状态。

## 边界和安全

- 在分配、索引或转换前，验证来自 CLI、环境、IPC、PTY、文件或外部代码边界的长度、范围、标签和标识符。
- 线协议、ABI 和持久化布局使用定宽整数；内存中的长度和索引使用 `usize`。显式执行并检查窄化和符号转换。
- 把 `undefined`、裸指针、指针转换、volatile 访问和平台专属导入限制在最小的所属适配器内。只有每个字节都在读取前完成初始化、外部 ABI 要求输出存储，或在自有值生命周期结束时有意将其毒化，才能使用 `undefined`。
- 产品代码保持运行时安全检查开启。局部使用 `@setRuntimeSafety(false)` 必须具备测量证据、已记录的不变量和明确的人工审查。
- 当 C ABI 或线协议契约依赖精确布局时，在编译期断言大小、对齐和字段偏移。

## 并发和有界工作

- 为可变状态指定明确的线程或锁所有者，并说明每个同步原语保护的不变量。
- 保持临界区有界。等待 IPC、PTY、进程或线程完成时，或调用外部回调时，不要持有锁。
- 限制用户可控的缓冲区、队列和每次分派的工作量。达到限制时，应定义可观察的错误、背压或截断结果。
- 明确关闭阶段的所有权：停止接收新工作、唤醒阻塞 worker、join 自有线程或进程，并且只释放一次资源。

## 测试

Zig 允许将 `test` 声明放在被测源码中，也允许放在独立 Zig 源文件中。本仓库将生产代码和测试的审查界面分开：

- 把所有 Zig `test` 声明、可执行测试 helper、fixture 和测试根节点放在所属源码树的 `__tests__` 目录下。生产 `.zig` 文件不得包含测试声明、fixture 或测试场景；只有下文所述的窄化条件访问接缝可以保留在其中。
- 模块配套测试命名为 `<source-stem>_test.zig`。跨模块一致性、共享 fixture 和系统 harness 根节点按其所属职责命名，并使用相同的 `_test.zig` 后缀。保留测试目录必须精确拼写为 `__tests__`。
- 优先测试公开行为，不依赖私有实现。当白盒不变量无法通过生产边界测试时，只通过窄化的 `pub const testing` namespace 暴露必要声明；该 namespace 不得持有可变状态或改变产品行为。
- 每个测试根节点都必须接入所属构建图和非交互式测试脚本。测试文件仅仅存在，并不代表它进入了仓库门禁。
- 分配型测试使用 `std.testing.allocator`；所有权逻辑不简单时，覆盖错误路径上的清理。
- 除正常路径外，还要覆盖无效输入、配置限制、边界值和预期失败路径。原生行为和交叉编译证据遵循[原生应用测试契约](TESTING.md#原生应用测试)。
