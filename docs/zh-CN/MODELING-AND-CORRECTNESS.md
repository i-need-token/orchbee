# 建模与正确性

## 门禁和权威来源

先从 [`DEVELOPMENT.md`](DEVELOPMENT.md) 开始。本标准适用于发生变化的行为与声明，按失败后果、状态空间复杂度和可观察边界选择证据。考虑每项适用风险，但不要仅因功能使用异步、取消、手势或多个文件就累加方法。

| 行为                                           | 必需记录和证据                                                 |
| ---------------------------------------------- | -------------------------------------------------------------- |
| 未引入领域状态或转换的局部展示                 | 现有组件契约，以及 [`TESTING.md`](TESTING.md) 要求的有意义证据 |
| 在已有所有权和副作用策略内的有界局部完成或取消 | 类型，以及覆盖相关过期结果、取消、失败和清理的聚焦测试         |
| 自有领域状态、相互作用的转换、持久化或进程协调 | 状态、所有权、不变量和相关轨迹的紧凑模型，以及确定性核心测试   |
| [正确性加严](#正确性加严)中的风险              | 针对每项受影响声明和未覆盖失败风险选择的证据                   |

- 把公共行为放在所属包 README 中，把内部维护契约放在所属所有者旁边。
- 类型、转换和面向行为的测试可以构成完整建模记录。仅为它们尚未解释的决策、假设或边界补充文字，不要在单独模型文档或按变更创建的 manifest 中重复表达。
- `docs/` 保存可复用的跨工作区规则；包行为由所属所有者保存。

已有的所有者专属证据义务和维护中的模型登记继续生效。通用选择策略变化不等于退役模型、削弱属性或删除已有必需检查。这些变化需要按所属生命周期另行提供针对声明的理由并取得接受。

## 建模记录

使用具体领域名称和类型维护一份可发现的记录。只使用适用字段，并链接到已有所有者。类型和测试可以提供决策与用例；不要仅为复刻此表而创建空标题、重复文字或 N/A 行。

| 字段     | 必需内容                                             | 完成证据                                 |
| -------- | ---------------------------------------------------- | ---------------------------------------- |
| 问题     | 参与者、上下文、触发条件、期望结果、约束和非目标     | 一条可观察的问题陈述                     |
| 输入     | 可信与不可信输入，以及缺失语义                       | 具名输入类型和验证边界                   |
| 数据     | 实体、标识符、关系、所有权、生命周期和规范形式       | 具名领域类型                             |
| 输出     | 成功变体、失败、语义事件、副作用、取消和无操作       | 具名输出类型                             |
| 不变量   | 每次操作前后都保持为真的事实                         | 断言或不变量测试                         |
| 决策     | 会改变结果的独立维度                                 | 决策表或面向行为的测试用例               |
| 模型     | 提取器、规范化器、策略、构建器、状态机或工作流       | 选定形态和主要公共操作                   |
| 转换     | 状态、事件、守卫条件、下一状态、派生状态、命令和取消 | 有状态行为的转换规则或测试               |
| 依赖     | 时间、存储、网络、进程、DOM 和其他能力               | 最小能力接口                             |
| 所有权   | 权威状态所有者和允许的写入方                         | 每个可变事实只有一个所有者               |
| 验证     | 核心用例、集成边界和真实交互路径                     | 不依赖生产 UI、映射到决策的确定性测试    |
| 正确性   | 声明、信任边界、精化映射、证据、限制和排除项         | 自有状态、自有转换或命中正确性风险时必需 |
| 参考范围 | 版本、环境、采用的行为、可观察投影和排除项           | 仅兼容或复制行为时必需                   |

另一位维护者必须无需查看预期 UI 就能推导出公共领域操作、声明和测试用例。对受正确性门禁约束的行为，同一记录就是正确性论证，必须表明声明了什么、每项声明由哪个可执行产物支持，以及哪些内容不在声明内。

## 领域契约

先用用户可观察的术语定义问题，再命名组件、Hook、存储键或实现技术。明确成功、失败、取消和有意无操作行为。

| 输出种类 | 必需决策                                     |
| -------- | -------------------------------------------- |
| 返回值   | 形态、含义、顺序和缺失语义                   |
| 语义事件 | 名称、载荷、发出时机、幂等性和所有者         |
| 状态变更 | 权威所有者、提交点以及回滚或取消行为         |
| 渲染状态 | 有意义的视觉、焦点、无障碍和减少动态效果结果 |
| 副作用   | 目标、时机、重试、失败处理和可观察性         |
| 无操作   | 拒绝工作的守卫条件，以及拒绝是否可见         |

选择能表示所有有效情况并拒绝无效组合的最小模型。

| 形态           | 适用场景                             | 公共操作                       | 副作用       |
| -------------- | ------------------------------------ | ------------------------------ | ------------ |
| 提取器或解析器 | 从编码输入中派生含义                 | `extract` 或 `parse`           | 无           |
| 规范化器       | 把外部或旧数据变成一种规范形式       | `normalize`                    | 无           |
| 策略或解析器   | 根据显式事实作出一个决策             | `resolve` 或 `decide`          | 无           |
| 构建器或投影器 | 由规范输入产生一个完整读取模型       | `build` 或 `project`           | 默认无       |
| 状态机或归约器 | 事件通过带守卫条件的转换改变长期状态 | `transition` 或 `reduce`       | 作为命令返回 |
| 工作流或编排器 | 有序阶段协调副作用、短路和恢复       | `execute`、`load` 或 `prepare` | 显式允许     |

- 为持久实体提供稳定标识符，并定义关系基数、排序、唯一性、成员关系、生命周期和引用完整性。
- 为每个可变事实指定一个权威所有者；分离权威状态、可逆预览、派生值、动画投影和展示状态。
- 当独立布尔值可能表示不可能的组合时，使用不同变体。
- 在边界解析不可信输入并定义缺失语义；不得从可选值之间的偶然相等推断转换。
- 在领域边界把必需数据设为非可选，并只公开操作可以使用的能力。
- 返回完整语义结果，并让结果变体无法表示无效字段组合。
- 确定性领域单元不得直接使用网络、存储、时间、随机性、进程 API 或 DOM 测量。
- 领域单元按其拥有的结果命名，不按页面、组件或框架生命周期命名。

## 状态和工作流

只有长期状态或多事件交互才使用转换模型。每个转换都定义守卫条件、下一状态、命令、可观察输出、不变量结果和取消路径。

```ts
interface TransitionResult<State, Command> {
	readonly commands: readonly Command[];
	readonly state: State;
}

declare function transition<State, Event, Command>(
	state: State,
	event: Event,
): TransitionResult<State, Command>;

declare function observe<State, Observable>(state: State): Observable;
```

- 把指针数据、测量值、时间和外部响应规范化为显式事件。
- 把副作用作为命令返回，并通过后续事件应用结果。
- 定义无效、重复、陈旧、乱序、中断和取消事件。
- 可逆预览期间保持权威状态不变，除非契约明确拥有乐观状态。
- 在每个已接受转换后检查不变量，而不只在最终提交后检查。
- 选定证据需要重放或比较时，让状态、事件、命令和观察结果可序列化，或提供无损规范轨迹。
- 测试完整转换序列，包括反向、中断、取消、回滚和重新进入。

工作流拥有阶段顺序、短路、重试、恢复和副作用；领域单元拥有决策。只选择适用阶段，并按照所属契约对它们排序。

| 阶段   | 消费                     | 产生                     | 副作用策略             |
| ------ | ------------------------ | ------------------------ | ---------------------- |
| 规范化 | 不可信或旧输入           | 规范领域输入             | 仅边界验证             |
| 决策   | 规范输入和语义意图       | 决策或投影               | 确定性                 |
| 准备   | 决策加外部能力           | 准备好的数据或类型化失败 | 不产生未追踪的权威修改 |
| 提交   | 准备好的结果加权威状态   | 已提交状态和语义结果     | 具名权威提交           |
| 发布   | 已提交语义结果           | 交付结果或已追踪结果     | 显式交付语义           |
| 展示   | 准备好或已提交的领域结果 | 公共输出模型             | 不新增领域决策         |

- 为每个阶段提供所需的最小能力和类型化输入输出。
- 如果无法避免可变工作流上下文，记录每个写入方。
- 除非输出类型定义了降级行为，否则不得把意外失败转换为空成功。
- 直接测试确定性阶段；单独测试编排器的顺序、调用、短路、重试、恢复、提交边界、发布结果和错误映射。

### 提交和发布边界

- 指明权威提交点，并把每个可能失败的动作分类为提交前或提交后。在契约允许时，在提交前完成可能失败的分配、编码、验证和容量检查。
- 提交前失败应保持权威状态不变，或调用由同一边界拥有的回滚。提交后失败应保留并报告已提交结果，然后遵循显式幂等、重试、补偿或终止失败策略。
- 绝不能先修改一个所有者，再在另一项必需修改或副作用前执行未追踪的可能失败工作。把工作置于一个所有者和提交边界下，或在模型中表示部分结果及其恢复路径。
- 当多项能力无法原子提交时，建模中间状态和歧义结果；不得声明实现无法提供的原子行为。

## 测试和交互设计

生产 UI 集成前识别相关决策和用例，并以面向行为的核心测试表达；仅当独立清单或场景矩阵能解释测试尚未说明的复杂性时使用它们。测试主要公共操作，而不是私有辅助函数。

| 覆盖维度 | 必需用例                                             |
| -------- | ---------------------------------------------------- |
| 等价类   | 每个含义不同的有效状态                               |
| 边界     | 适用时覆盖空、单项、首项、末项、阈值、最小值和最大值 |
| 无效输入 | 被拒绝的身份、关系、转换和陈旧引用                   |
| 方向     | 方向不应改变语义时覆盖正向和反向                     |
| 序列     | 重复、中断、取消、回滚和重新进入                     |
| 不变量   | 每个已接受操作或转换都保持的属性                     |
| 所有权   | 调用方更新、延迟提交和被拒绝的乐观假设               |
| 歧义     | 零个、一个和多个匹配，以及决胜规则                   |
| 层级     | 支持的深度以及缺失、空、部分和完整分支               |
| 回归     | 按 [`TESTING.md`](TESTING.md#回归覆盖) 选择的证据    |

- 根据独立决策和冲突点推导用例；不得依赖正常路径覆盖或盲目的笛卡尔积。
- 使用领域语言测试名称、有效的最小夹具默认值、表驱动用例和适用的属性断言。
- 核心测试不得依赖渲染、浏览器自动化、网络服务或持久化存储。
- 一次性验证可以回答一个可行性问题，但默认不得成为生产实现。

当激活、预览、提交、取消、焦点、几何或动态效果会改变行为时，建模完整手势时间线。

| 维度       | 必需决策                                   |
| ---------- | ------------------------------------------ |
| 激活       | 指针或键盘阈值和选择时机                   |
| 命中测试   | 合格目标、重叠和边界滞后                   |
| 几何       | 测量所有者、坐标空间、滚动和尺寸变化行为   |
| 层叠       | 每个交互阶段的绘制顺序                     |
| 预览       | 可逆投影、插入反馈和成员关系指示           |
| 焦点和菜单 | 焦点所有权、关闭、点击穿透和键盘连续性     |
| 动态效果   | 位移、中断、减少动态效果和完成             |
| 取消       | Escape、捕获丢失、卸载、陈旧数据和平台取消 |

定义激活、悬停、焦点、选中和拖动状态之间的优先级。反馈必须描述此刻提交的结果；样式和动画不得掩盖无效或有歧义的转换。

测试位置、命名和回归规则遵循 [`TESTING.md`](TESTING.md)。

## 正确性加严

选择能够判断受影响声明的最小证据集合。为每种新增方法指明它解决的失败风险或保证缺口。一个产物可以支持多项声明；不同方法仅在覆盖不同的必需缺口时累加。

| 风险触发条件                                                       | 证据选择                                                          |
| ------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 自有领域状态或转换                                                 | 显式状态、事件、输出、不变量和确定性行为测试                      |
| 具名示例无法充分探索的大量组合或序列                               | 带收缩或反例缩减与重放的属性测试或基于模型的探索                  |
| 所有者单一且已有规定、副作用有界的局部异步完成、取消或重试         | 可控完成顺序、过期结果、取消、失败和清理用例；异步本身不要求 TLA+ |
| 独立排序的参与者可能破坏共享所有权、提交、恢复或不可逆副作用不变量 | TLA+ 安全性检查和适用进展检查，以及将抽象关联到实现的证据         |
| 关键纯转换需要超出采样或有界状态的全称声明                         | Lean 保持性、确定性或精化定理                                     |
| 源码兼容移植或行为复制                                             | 固定参考版本、显式一致性范围和差异或精化验证                      |
| 时机、几何、焦点、手势或平台行为无法在核心边界判断                 | 最低可信集成边界上的受控适配器或系统轨迹                          |

评估谁可以独立行动、哪些结果可能丢失或重复、如何发现失败，以及恢复是否有界。看似局部的操作只要写入持久数据或协调多个参与者，仍需要相关的更强证据。具名用例无法限定排序风险时，升级为探索或模型检查；作者信心不能替代证据。

其他方法支持相同声明和保证限制时，可以提出替代建议。改变已有必需方法或已接受的后果性证据计划，需要决策所有者接受，并更新所属契约和执行门禁。成本本身不豁免证据；实现行为、抽象模型和物理平台仍是不同声明。

| 方法           | 支持的声明                           | 限制                     |
| -------------- | ------------------------------------ | ------------------------ |
| 示例测试       | 一个选定用例产生预期结果             | 只覆盖选定用例           |
| 属性测试       | 不变量在生成的状态和序列中保持       | 对配置的搜索空间进行采样 |
| TLA+           | 抽象机器没有已检查的安全性或进展反例 | 在声明的边界内检查模型   |
| Lean           | 定理对其定义和假设允许的所有值成立   | 不证明无关的 TypeScript  |
| 确定性系统测试 | 集成系统复现受控的可观察时间线       | 覆盖声明的轨迹和环境     |
| 差异验证       | 实现与采用的参考投影一致             | 取决于参考范围和观察质量 |

将每个选定证据产物映射到实现声明。形式化模型或定理需要显式精化映射或可执行比较；仅模型通过不能证明实现正确。可能的链为：

`reference evidence -> owned contract -> abstract model and theorems -> deterministic core -> platform adapters -> observable system`

只包含为声明选中的层，并解释它们的实际连接。普通行为测试不需要占位的形式化、参考或系统产物。

## 决策边界

观察到不一致后，在改变行为前：

1. 记录参考来源、环境、规范初始状态、语义动作和第一个分歧。
2. 识别离散模式、所有权、选择、焦点、交互阶段、平台开关和连续输入。
3. 当输出竞争同一资源时定义优先级。
4. 对每个守卫条件和阈值分区；边界 `b` 在有效时包含 `b - 1`、`b`、`b + 1` 和相邻内部值。
5. 为每个分区和转换定义规范语义状态、控件、几何、焦点、重叠和裁剪。
6. 让最低有效层的证据失败，再修复最早的规则所有者。

选中时，属性测试按等价类探索支持的连续域，确定性轨迹检查适配器投影；具名示例固定相关边界。一个控件的可见性、位置、命中测试和无障碍必须来自同一语义策略或可证明等价的投影。

聚焦检查器只提供局部证据；完成时按 [`VERIFICATION.md`](VERIFICATION.md) 运行适用的根门禁。在契约、优先级、边界或适配器映射解释更广回归之前，把它视为反例。

## 正确性证据

### TLA+

- 建模能暴露所声明安全性或进展失败的最小语义抽象；仅当 UI 或平台细节会改变声明时才纳入它。
- 定义全部权威变量、恰好支持的 `Init` 状态、具名语义动作和完成事件、`Next`、停顿、结构与领域不变量、适用的进展属性，以及仅由契约保证的公平性。
- 提供已检查的 TLC 配置，显式列出常量、边界、对称性、状态约束，以及动作和属性到自有声明的映射。
- 考虑身份、引用完整性、排他成员关系、排序、分区、连续性、活动项有效性、预览可逆性、提交原子性、取消恢复和所有权不变量。
- 不得用状态约束排除可达失败；声明探索限制。
- 覆盖两个方向、边界、空和单项状态、建模最大尺寸、相关模式、重复或陈旧动作、取消、乱序完成和阶段重新进入。
- 把最短 TLC 反例转换为确定性回归；先修复缺失的契约或模型，再修改生产代码。
- 固定工具链。合并配置必须在记录的边界内执行每个维护中的动作和安全属性；更大的探索配置可以单独运行。

#### TLA+ 产物生命周期

| 生命周期节点 | 要求                                                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 准入         | 指明一个可证伪的 owner claim，以及独立排序行为为何需要模型检查；不要添加只枚举固定示例或复述类型的模型。                                                    |
| 登记         | 在 `scripts/tla/models.json` 中为每个维护中的模块/配置对精确登记一次 owner、claim 权威、变更路径触发器、超时、变体，以及 coverage 所要求的每个语义 action。 |
| 变更         | 在所依赖的运行时行为之前更新抽象，并运行选中的已登记检查；未改变且通过的模型不是已变更实现的精化证据。                                                      |
| 合并或拆分   | 对同一语义 owner 和抽象族使用配置变体；当独立维度的乘积掩盖有用 coverage、超过声明的资源边界或削弱受检 claim 时，将其拆分。                                 |
| 退役         | 当 claim 消失、被更强的维护中产物覆盖，或不再存在可执行的精化映射时，一并删除模块、配置、登记和过时的 owner 文档。                                          |

清单是执行索引，而不是模型权威。状态数、深度、耗时、action coverage 和配置摘要属于有界运行
证据；它们不是无界正确性或实现精化声明。

### Lean

- 定义形式化输入、输出、有效性谓词、转换或状态转换、具名定理、最小假设，以及精化所需的可执行预言机。
- 对关键身份、成员关系、排序、分组、选择、规范化、确定性、逆行为或不变量保持的全称声明使用 Lean。
- 必需定理不得使用 `sorry`、`admit` 或项目创建的公理；披露不可避免的公理、经典假设、外部代码和解析器信任。
- 通过共享规范模式或语料连接 Lean 与生产代码，并比较规范观察结果。
- 新的一致性默认使用 Lean；已有替代证明助手必须提供等价的内核检查、信任披露、精化和合并保证。

### 属性测试

- 定义有效状态和有状态命令生成器、模型派生前置条件、对抗性无效或陈旧事件、预言机或不变量集合、语义收缩器、覆盖分类和稳定序列化。
- 在适用时使用保持性、确定性、幂等性、逆、对称性、精化和无操作稳定性属性。
- 使用显式种子、尺寸限制、确定性调度器和已记录参数；合并门禁拥有稳定的种子语料。
- 把每个探索失败缩减为可重放的最小用例，并加入回归语料。
- 报告已到达的状态类别、动作、边界、方向和阶段；迭代次数本身不是覆盖。

### 确定性系统测试

控制或记录每个适用的非确定性来源：

| 来源       | 必需控制                                                                      |
| ---------- | ----------------------------------------------------------------------------- |
| 时间和调度 | 墙上时钟和单调时钟、定时器、帧、任务、微任务、异步完成顺序和随机性            |
| 环境       | 视口、缩放比例、缩放、字体、语言区域、主题、动态效果偏好、平台开关和生成的 ID |
| 交互       | 指针和键盘序列、坐标、捕获、取消、合并、焦点和动画                            |
| 几何       | 测量、滚动、命中测试候选、尺寸变化观察和快照                                  |
| 外部状态   | 网络、存储、worker、进程、操作系统响应、持久化状态和参考版本                  |

- 记录模型状态、阶段、命令、投影、焦点、几何和渲染标识符的语义检查点。
- 推进逻辑时间或等待具名语义条件；不得使用任意休眠。
- 使用固定逻辑帧驱动动画，并断言开始、位移、中断和稳定结果。
- 先比较规范状态和几何，再比较像素；每条轨迹都必须能按稳定名称独立重放。
- 重试不得掩盖竞态。人工观察在被带断言的确定性轨迹捕获前只属于发现证据。

### 参考实现精化

兼容或复制声明需要带版本的一致性契约。

| 字段     | 必需内容                                                   |
| -------- | ---------------------------------------------------------- |
| 来源     | 产品版本、源码修订、构建开关、平台、主题和运行时配置       |
| 范围     | 支持的操作、状态、输入、模式和显式排除项                   |
| 投影     | 语义状态、检查点、几何、无障碍、时机和必需绘制细节         |
| 规范化   | 声明的非领域噪声，以及移除它为何不会掩盖行为差异           |
| 权威规则 | 源码、观察到的行为、上游测试和本地自有契约发生冲突时的规则 |

- 把参考行为视为由修订、开关、渠道、平台、实验和运行时配置共同选择的结果。
- 审计行为依赖闭包：策略、所有权、生命周期、常量、开关、调度、几何、命中测试、动画、平台集成、无障碍、测试和共享状态。
- 对每个场景建立干净前置条件，应用相同语义动作，捕获相同检查点，只规范化声明的噪声，比较完整投影并分类每个不一致。
- 源码检查和探索性使用可以发现行为；合并证据需要可重复执行的工具或带来源及捕获记录的版本化黄金轨迹。
- 重新捕获必须是有意操作。参考版本升级需要审计依赖闭包、重跑场景、审查黄金结果并更新一致性范围。

## 可追踪性和变更纪律

通过现有契约、稳定测试名称和导入维护可发现的声明到证据映射。形式化或差异证据、跨所有者精化，或无法通过其他方式还原的映射，使用明确表格行；不要为普通局部测试创建第二份清单。

| 声明         | 契约所有者     | 选定证据和映射               | 限制       |
| ------------ | -------------- | ---------------------------- | ---------- |
| 领域具名声明 | 所属参考或类型 | 稳定检查名称及其与实现的连接 | 边界和假设 |

- 为每条可观察规则和不变量在最低有效层提供一个可执行见证。
- 把每个选中的形式化属性和定理映射到自有声明；省略未使用的方法列。
- 记录相关边界和信任假设；随已删除行为移除陈旧映射。
- 覆盖百分比是诊断信息，不是可追踪性。

对每个反例：

1. 保留环境、种子、状态、事件、参考版本和观察结果。
2. 把它缩减为最短的失败语义轨迹。
3. 找到第一个分歧检查点以及被违反的声明或假设。
4. 分类缺失契约、无效假设、不完整生成器、实现、适配器或测试工具缺陷。
5. 修复最早的错误权威来源。
6. 保留缩减用例并重新运行更广探索。

不得通过削弱属性、排除可达 TLA+ 状态、增加公理、重试竞态或用截图替代语义回归来接受当前行为。

| 变更种类                         | 必需更新                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------- |
| 状态、事件、守卫条件、命令或取消 | 自有契约和状态模型、相关行为测试，以及受影响的已选形式化或轨迹证据               |
| 纯转换或不变量                   | 自有契约、回归用例，以及适用的已选证明或性质证据                                 |
| 平台、几何、焦点、时机或动画     | 环境契约、确定性输入和检查点、适配器测试，以及适用时的一致性投影                 |
| 参考修订或兼容范围               | 来源、依赖闭包审计、差异场景、已审查黄金结果和声明的限制                         |
| 缺陷                             | [`TESTING.md`](TESTING.md#回归覆盖) 要求的回归证据、根因分类和修正后的最早所有者 |

在依赖改变后的生产行为前更新抽象模型或证明。不得保留竞争的语义模型，除非显式兼容边界同时拥有它们并由差异测试比较。

每项实现都遵循相同证据契约：

- 修改生产代码前，获取所属记录，识别参考依赖闭包，列出状态、事件、输出、不变量、假设、选中的证据和受影响的精化连接。
- 把已有缺陷复现为最小语义轨迹。
- 在有用的反馈边界运行聚焦检查，在完成时运行适用的根门禁；复用未变化的有效证据，并在继续修改前保留反例。
- 审查契约、选定证据与实现之间受影响的映射。
- 完成报告列出已检查声明、边界、参考修订、已执行证据和排除项；仅检查文件、生成代码、示例或截图绝不能证明完成。

## 集成和实现

通过薄壳集成稳定核心：

- 组件渲染准备好的状态并发出语义意图。
- Hook 协调框架生命周期和适配器，不拥有隐藏状态机。
- CSS 渲染模型提供的展示状态，不推断领域状态。
- 副作用消费显式命令，并通过显式事件报告结果。
- 薄壳可以测量 DOM、捕获指针、调度帧和渲染像素；绝不能决定成员关系、排序、选择、资格、取消或提交语义。
- 组件测试验证接线和无障碍，浏览器测试验证真实时间线，视觉审查验证展示；它们都不能替代领域证据。

实现顺序：

1. 记录问题、非目标、输入、输出、不变量和所有权。
2. 定义规范类型、决策、模型形态和主要操作。
3. 在适用时增加转换、工作流阶段和正确性声明。
4. 识别相关用例，并针对受影响声明和失败风险选择证据。
5. 实现确定性核心并让其证据通过。
6. 实现并测试工作流和外部适配器。
7. 把稳定操作集成到应用薄壳。
8. 在选中时增加确定性浏览器、视觉、形式化和差异证据。

实现暴露缺口时修正所属产物。仅按 [`DEVELOPMENT.md`](DEVELOPMENT.md) 升级新的保留决策；普通纠正在已接受任务内继续。

源码拆分与可见性遵循 [`MODULE-BOUNDARIES.md`](MODULE-BOUNDARIES.md)，React 所有权遵循 [`frontend/react.md`](frontend/react.md)，视觉决策遵循 [`frontend/visual-foundations.md`](frontend/visual-foundations.md)，跨工作区依赖遵循 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 验证和完成

每个确定性、有界、固定版本且由仓库提供的证据产物都公开一个由所属包记录的真实命令。
[`VERIFICATION.md`](VERIFICATION.md) 定义的根合并门禁运行默认实现证据。TLA+ 模型检查是
默认门禁之外、由变更触发的证据。产品模型、配置和抽象语义变化时，必须验证其受影响模型。
运行器或验证/建模规范变化时，按 VERIFICATION.md 的工具路由执行完整清单/配置检查、
执行工具模型及真实固定 TLC 的执行/复用/失败见证。独立受影响的产品模型仍须验证；
规范引入新的产品义务时，在同一变更更新其登记和配置。在该契约下允许精确复用未变化的
完整成功结果，并保留显式全量基线。

适用门禁或选定的证据命令必须在以下情况失败：

- 已检查 TLA+ 安全性或进展属性出现反例；
- Lean 定理未检查、使用占位证明或存在未声明的信任假设；
- 属性失败、必需生成器类别不可达或生成的失败不可重放；
- 确定性轨迹不一致或存在会影响结果的不受控时机；
- 声明的一致性范围内存在差异；或
- 变更声明缺少可追踪性。

固定工具和配置，限制资源，快速失败并保留可操作反例。不得使用重试。外部参考捕获和环境特定探索在输入被固定并由仓库提供前属于维护验证；兼容版本发布前运行它们，但不得让合并门禁依赖环境外部状态。

满足以下条件才能开始生产集成：

- 建模记录（包括其类型和测试）定义适用行为、所有权、不变量、用例和未解决决策；
- 确定性核心测试在不依赖生产 UI 的情况下通过；并且
- 每项相关失败风险都有选定证据和显式限制。

满足以下条件才能认为功能完成：

- 所属权威来源描述当前行为且不包含任务历史；
- 选中的核心、工作流、集成、浏览器、无障碍和正确性证据保护受影响声明；
- 在最低有效层提供满足 [`TESTING.md`](TESTING.md#回归覆盖) 的回归证据；
- 声明到证据的映射没有无法解释的空缺或陈旧声明；
- 原型、重复状态和过时标志已删除；
- 建模记录选定的每个变更触发正确性命令都无重试通过；
- [适用的根门禁](VERIFICATION.md#合并门禁)无重试通过；并且
- 完成报告说明已检查声明、边界、参考修订、证据和排除项，不使用“完全验证”或“完美复制”等无界声明。
