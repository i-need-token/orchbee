# 仓库卫生

## 跟踪文件准入

只有当一个文件的持久仓库价值超过其持续维护成本时，才把它加入版本控制。创建或保留文件前，回答以下所有问题：

1. **未来使用方**：当前变更完成后，哪个运行时、构建、测试、维护者或用户会读取或执行它？
2. **权威职责**：它拥有哪些尚未由其他位置拥有的当前行为、契约、配置或可复用能力？
3. **重复使用**：什么可重复工作流以后还会再次使用它？对已经完成工作的描述不属于重复使用。
4. **生命周期**：什么情况会导致它被更新或删除，什么验证能防止它过时？
5. **仓库适配性**：为什么已跟踪文件是正确的交付机制，而不是现有源码文件、测试、权威文档、Issue、Pull Request 描述、Git 历史或临时工作区？

只要有一个问题没有答案，就把产物留在仓库外，或者在交付前删除。存在不确定性时，默认不跟踪该文件，直到识别出持久使用方。

## 仓库价值

文件通常在提供至少一项下列持久价值时才有保留理由：

- 运行时所需的生产行为或资产。
- 可重复工作流使用的构建、测试、发布、迁移或维护自动化。
- 可观察不变量的回归覆盖。
- 仓库工具使用的配置或 Schema。
- 操作、扩展或使用项目所需的当前权威文档。
- 遵循 [`docs/DOCUMENTATION.md`](DOCUMENTATION.md#研究生命周期) 生命周期、仍有未决决策的活跃研究。

下列理由本身并不充分：

- 记录某个 Agent 或维护者在一次任务中做了什么。
- 在结论已经并入后保留调查证据。
- 让一次性手工检查更方便。
- 因为产物耗费了大量精力而保留它。
- 提供已经存在于 Git 历史、Pull Request 或权威来源中的上下文。

## 工作产物

不要跟踪任务局部产物，包括：

- 一次性审计、迁移、检查或数据提取脚本。
- 草稿笔记、复制的上游文件、补丁、命令记录和临时 fixture。
- 时间点报告、覆盖率快照、截图、日志、基准输出或历史工作总结。
- 本地路径、环境专用启动器、编辑器状态、缓存和构建输出。
- 没有已提交使用方、生成器和过期状态检查的生成文件。

尽可能在操作系统临时目录中创建一次性产物。如果工具必须把它们放入仓库，在交付前删除它们；不要仅仅为了让临时文件显得合理就添加包命令或文档条目。

沉淀成果，不保留过程痕迹：添加回归测试、更新当前契约或实现可复用工具，然后删除中间产物。

## 持久脚本和生成文件

只有在新脚本具有具名可重复工作流、稳定入口点、明确的输入输出所有权、已记录的前置条件以及与风险相称的验证时，它才是持久的。只用于完成或验证当前变更的脚本即使很完善，也仍然是临时脚本。

只有当运行时、构建、发布或外部使用方需要实体化输出时，才跟踪生成文件。提交其确定性生成器以及能在已跟踪输出过期时失败的检查。否则只在本地或 CI 中生成，并保持不跟踪。

静态证据清单和来源报告需要持续的符合性或合规工作流。它们必须定义由谁更新、对什么来源具有权威性，以及如何验证完整性。调查快照属于研究或任务历史，不是永久契约。

## 文档准入

文档描述当前事实、活跃提案或未解决研究。不要添加主要用于叙述已完成任务、列出已修改文件、保存审查发现或记录时间点审计的文档。

调查结束时：

- 把稳定行为和决策移入现有权威文档。
- 对可机械验证的不变量使用测试表达。
- 把任务时间线留在 Pull Request 和 Git 历史中。
- 删除已经解决的研究和中间证据。

## 交付前审查

把变更作为完成结果提交前：

1. 运行 `git status --short`，逐一审查每个新增和未跟踪路径。
2. 对每个新增文件应用跟踪文件准入问题，包括脚本、文档、fixture 和生成输出。
3. 删除任务局部产物，以及引用它们的每条命令、链接、配置项或文档陈述。
4. 确认剩余新文件位于 [`docs/MODULE-BOUNDARIES.md`](MODULE-BOUNDARIES.md) 或 [`docs/DOCUMENTATION.md`](DOCUMENTATION.md) 所确定的所有者之下。
5. 运行 `git diff --check` 和 [`docs/VERIFICATION.md`](VERIFICATION.md) 要求的验证。

即使新文件技术上正确，只要没有具体的未来使用方或生命周期，审查者就应要求删除它。
