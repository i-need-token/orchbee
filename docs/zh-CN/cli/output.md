# CLI 输出

## 权威性和范围

本标准拥有一次 Orchbee 命令行调用写出什么以及如何退出：标准输出与标准错误的划分、人类与
机器格式、机器文档信封、退出码词表、转义、上限、流式记录和本地化。语法遵循
[`command-surface.md`](command-surface.md)；输出背后的效果遵循 [`process.md`](process.md)。
每个可执行文件的具体 schema、失败类别和字节上限由其应用指南拥有，并且必须满足下文的形态。

## 流

| 流       | 承载                                                                 | 绝不承载                                               |
| -------- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| 标准输出 | 所请求命令的恰好一份契约文档，或一条有序的记录流                     | 进度、提示、诊断、日志行，或失败之后的第二份文档       |
| 标准错误 | 本地化的人类诊断：失败原因、导致失败的有界回显输入，以及一个帮助提示 | 机器字段、载荷数据、secret、栈追踪或自由格式的内部细节 |
| 退出码   | 来自下文词表的一个值，通过一个全映射从文档的失败类别或终态结果派生   | 任何需要调用方解析文本才能恢复的信息                   |

因此调用方可以只依赖标准输出和退出码做自动化，仅在有人在场时才读取标准错误。

## 格式

- `--format text|json` 选择投影；`text` 是默认值。`json` 是机器格式，在所属 schema 下稳定。
  `text` 是本地化的人类投影，自动化不得解析它，其布局可以在不升版本的情况下变化。
- 唯一消费者是机器的命令，例如 schema 列表或快照导出，在两种格式下输出相同的 JSON 文档。
- `help`、`--version` 和 `completion` 等固定文本命令不接受 `--format`。当语法合法的
  `--format json` 伴随语法失败出现时，该失败以 JSON 失败文档报告；在 `text` 下失败保持标准
  输出为空。
- 在 `json` 下，失败是标准输出上的一份失败文档加标准错误上的本地化诊断。在 `text` 下，失败
  不向标准输出写任何内容。
- 显式选择的数据导出可以输出请求的 UTF-8 内容，不添加人类展示的引号或标题。
  所属契约必须定义选择、字节上限、编码和失败行为，并将其与普通 `text` 区分。
  原始字节与 JSON 信封是互斥的输出模式。内容编码选择器可以在 schema 定义的 JSON 投影中
  提供同样的内容；仅用于直接导出的参数则与 JSON 互斥。直接导出保留负载字节，
  不应用人类文本展示规则。

## 机器文档

| 规则        | 契约                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| 形态        | 一个以换行结尾的 JSON 对象；文档使用两空格缩进，流则每条记录一行。                                                 |
| Schema 身份 | 每份文档都命名其 schema 标识符，且被标识的 schema 可从同一构建离线获取。形态变更就是新的 schema 标识符或版本。     |
| 封闭词表    | 失败类别、阶段、原因、resource 名称和枚举值是有限的、小写的、kebab-case 的、有文档记录的值，并由内嵌 schema 校验。 |
| 失败信封    | 失败文档携带失败类别、一个按类别固定形态的 details 对象，以及仅在派生自权威来源时才有的该来源身份。                |
| 无散文      | 机器文档不含 `message`、不含本地化文本，也不含异常或 `Display` 文本。呈现属于标准错误和 `text` 投影。              |
| 来源        | 每个字段都有可信来源。`null` 表示来源说没有；`"unknown"` 表示来源无法回答；二者绝不混用，且不伪造任何字段。        |
| 不可信数据  | 用户控制的 label、路径和终端文本用标准 JSON 编码无损保留；在 `json` 下绝不截断、清洗或翻译它们。                   |
| 请求身份    | 修改结果和分离受理都包含请求身份，以便调用方之后 `get` 或 `wait` 它。                                              |

## 退出码

退出码划分的是谁决定了结果，而不是运行了哪条命令。所属应用把每个失败类别和终态结果映射到
恰好一个退出码，并且该映射经测试证明是全映射。

| 退出码 | 类别     | 含义                                                                                                                                   |
| ------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | 成功     | 读取完成（包括空结果）；修改完成或无变化；分离提交已受理                                                                               |
| `1`    | 本地失败 | 本地配置检查失败、输出无法准备或写出，或在任何请求之前内部不变量失败                                                                   |
| `2`    | 用法     | 无效的语法、选项、值、target 语法、输入文档或参数信封                                                                                  |
| `3`    | 拒绝     | 权威明确拒绝：not found、ambiguous、denied、rejected、blocked 或冲突；激活拒绝可能发生在部分运行时效果之后，而不是承诺什么都没有被应用 |
| `4`    | 不可用   | 没有可达的服务、容量耗尽，或当前平台无法服务该请求                                                                                     |
| `5`    | 通道中断 | 传输丢失或协议违反                                                                                                                     |
| `6`    | 不兼容   | 协议、cohort 或版本不匹配                                                                                                              |
| `7`    | 已取消   | 操作已受理并以已取消的终态结果结束，或已声明的截止时间到期——包括 `terminal send` 输入源在任何请求存在之前耗尽获取预算                  |
| `8`    | 结果未知 | 效果可能已被应用且无法确认                                                                                                             |
| `9`    | 失败     | 操作已受理并以失败的终态结果结束                                                                                                       |
| `130`  | 被中断   | 默认的 `SIGINT` 语义                                                                                                                   |

- 修改上的拒绝、不可用、通道中断或不兼容结果意味着什么都没有被应用。只有结果未知承认效果
  可能存在。激活动词遵循自己的规则：其 `rejected` 拒绝意味着半激活的运行时状态可能残留，
  因此命令报告该拒绝而绝不声称什么都没有被应用。
- 被中断的等待不取消所观察的操作；见 [`process.md`](process.md#信号与取消)。
- 表外的退出码是保留的且不可达，但源阶段中断退出除外：已声明的 `terminal send` 输入源在其
  物化窗口内被中断时，在 `orchbee.cli.failure.source` 信封上以 `128 + signo`——129、130、
  131 或 143——退出。
- `orchbee.cli.failure.source` 信封仅是机器文档：只在 `--format json` 下写入标准输出。
  在 `text` 下，源失败不向标准输出写任何内容，由标准错误上的本地化诊断承载原因。

## 文本渲染

- 用户控制的字符串渲染为带引号的转义值：反斜杠和引号被转义；包括 `ESC` 在内的 C0 与 C1
  控制字符、U+2028、U+2029 和双向格式控制字符渲染为 `\uXXXX` 转义；其他 Unicode 保留。
- 表格只按声明的宽度截断 label 的显示列，并加省略号，保持转义和收尾引号完整。标识符绝不
  截断，`get` 输出是完整的。
- 显示宽度按 [TUI 视觉基础](../tui/visual-foundations.md#显示宽度与文本安全)以终端单元格度量，
  绝不以字节或标量度量。
- 文本输出不携带颜色或样式序列；命令行调用不查询终端。

## 上限与写入失败

- 完整文档在第一个字节到达标准输出之前，在一个有界缓冲区中准备好。超过声明的上限是本地
  失败，且不向标准输出写任何内容。
- 标准输出上的写入或刷新失败以非零退出，绝不追加第二份文档，并在标准错误仍可用时在其上
  报告。
- 标准错误上回显的不可信 token 被截到声明的标量前缀并加省略号；非 Unicode 和过大的参数列表
  只被描述，绝不回显。
- 标准错误诊断每次失败限定为一个原因和一个提示；读取路径不打印进度。

## 流式记录

- 随时间输出多个结果的命令每行写一条 JSON 记录。每条记录命名其类别；流以一条说明结束原因的
  终态记录结尾。
- 截止时间、停滞或通道丢失以一条类型化的终态记录和非零退出结束流；部分流绝不被呈现为成功。
- 同一流内的记录保持来源顺序，且一条记录绝不跨行拆分。
- 在 `text` 下，流式命令按相同的转义规则在每条记录到达时渲染它。

## 本地化

- 标准错误诊断、帮助和 `text` 投影按 [Rust](../RUST.md#本地化产品文案)本地化；`json` 文档、
  schema 标识符、枚举值、补全脚本和退出码在每种 locale 下保持一致。
- 帮助提示指明一条真实路径，拼写与语法权威完全一致，且无需运行时即以 `0` 退出。
- 每条诊断在同一变更中同时存在于两种已交付的 locale。
