# CLI 进程

## 权威性和范围

本标准拥有一次 Orchbee 命令行调用从第一个参数到退出码之间发生的一切：其输入的信任边界、
对终端的独立性、解析先于任何效果的顺序、截止时间、副作用、请求身份、信号，以及进程如何定位
其运行时。语法遵循 [`command-surface.md`](command-surface.md)，输出遵循 [`output.md`](output.md)。
与每个原生可执行文件共享的操作系统边界以 [Rust](../RUST.md#本地进程与-ipc-边界) 为权威。

## 输入与信任边界

| 输入       | 契约                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 参数       | 敌意输入。参数总大小有声明的上限；非 Unicode 参数或溢出是标准输出为空的用法失败，不论其余参数拼写了什么。                                                                                 |
| 环境       | 只读取有文档记录的 `ORCHBEE_*`、locale 变量及显式声明的平台用户目录输入。用户目录输入仅用于操作数展开，绝不选择运行时。格式错误的已记录值是指明该变量的用法或本地失败；绝不用默认值代替。 |
| 标准输入   | 只在命令声明了输入操作数（例如 `--input-file -`）时读取。输入在解码前被限长，并按严格 UTF-8 JSON 或声明的格式解码。                                                                       |
| 文件       | 只从显式命名的操作数读取，在解码前限长，绝不从当前目录、仓库或项目文件中发现。                                                                                                            |
| 终端       | 绝不读取。没有命令依赖控制终端、其尺寸或其能力；启动界面的命令在解析之后把终端交给 `tui/` 生命周期。                                                                                      |
| 运行时响应 | 只有在类型化的传输层和协议层受理之后才可信。绝不从显示文本、错误类别猜测或字节数重新推导裁决。                                                                                            |
| 快照数据   | label、路径和终端文本是任意 Unicode，对每个人类表面都视为敌意输入，在机器输出中作为数据保留。                                                                                             |

## 解析先于效果

一次调用按以下阶段顺序推进，某一阶段的失败阻止其后的每个阶段：

1. 扫描参数信封的大小、编码和格式选择，使之后的语法失败已经知道其输出格式。
2. 校验完整语法：命令路径、选项、操作数、target 和值集。语法失败不触碰配置、文件系统、cohort
   或端点。
3. 仅凭构建回答离线命令——帮助、版本、默认配置、补全和 schema 列表。
4. 通过已配置的 base 发现运行时，并拒绝不安全的路径而不修复它们。
5. 受理恰好一个会话。普通命令至多执行一次读取和一个效果。
   已声明的观察命令可以重复有界读取；已声明的工作流程可以在最初的同一截止时间内
   执行有限个具名效果阶段。
6. 准备完整输出，然后一次性写出。

## 截止时间与等待

- 每个网络步骤都有一个由调用而非服务拥有的截止时间。一个截止时间覆盖受理加上单次读取或
  命令；等待命令的截止时间是以毫秒计的 `--timeout`，带有文档记录的默认值和上限。
- 默认有限等待，除非观测命令的所属契约明确规定无限等待。每种无限模式都须说明默认值或显式选项，保留有界准入和单次读取，并支持以 `130` 退出的中断。普通修改命令仍保持有界。
- 显式拥有本地子进程的流程可在工作期限外声明有界清理预算；两者共同组成原始调用总预算。工作期限到达后，只允许继续清理及明确报告的恢复。
- 截止时间到期作为其自身的类型化结果报告。它绝不声称所观察的操作已停止、失败或从未送达。
- 长轮询和变更源返回游标，并在调用方落后时返回显式的重置信号；重置绝不被呈现为连续的源。

## 副作用与请求身份

| 规则       | 契约                                                                                                                                                                                                                                                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 读取       | 不创建目录、锁、标记、终端、viewer 或授权。声明的读取侧附着以最小方式持有，在输出之前释放，并在所属指南中具名。                                                                                                                                                                                                                                                               |
| 单次提交   | 普通修改只有一个效果阶段。已声明的工作流程在所属契约中逐项定义有限阶段；每阶段至多提交一次，身份在语法校验后独立生成或受理。工作流程不重试阶段，也不因后续阶段失败而隐藏已提交效果。                                                                                                                                                                                          |
| 不重放     | 调用绝不重试、重放或重新提交效果。未确定的结果作为携带请求身份的结果未知报告，而不是猜测或重复。                                                                                                                                                                                                                                                                              |
| 预提交拒绝 | 确定的预提交拒绝表示该阶段未应用任何效果。此前工作流程效果仍独立记录，后续拒绝不授权重放整个流程。传输歧义仍是未知，不能猜成拒绝。                                                                                                                                                                                                                                            |
| 分离       | `--detach` 在提交被受理后立即返回并产出请求身份；之后的 `get` 或 `wait` 观察它。分离绝不改变所提交的内容。                                                                                                                                                                                                                                                                    |
| 输出读取   | 终端或转录读取只返回当前内容，绝不自动脱敏，并被记录为可能包含 secret，以便调用方限制其转发的内容。                                                                                                                                                                                                                                                                           |
| 持久状态   | 对读取与修改，进程不拥有任何持久状态：不写历史、缓存、锁文件或 PID 文件；服务是唯一的持久权威。已声明的离线用户配置流程、激活和已停止运行时清理是例外。离线配置流程可通过其配置所有者串行化并保留明确拥有的恢复记录；它们不能成为另一个在线运行时权威。激活可创建运行时状态并拉起服务；清理可与激活串行化，只删除经证明归属明确的已停止状态。所属指南具名每个工件和恢复规则。 |

已声明的工作流程在实现前记录阶段顺序、权威提交点、拒绝与未知结果、取消切点及有界恢复。
每个后续阶段消费其依赖的精确前序回执。发布或 Client 确认失败不能抹去已知提交；组合成功必须
满足全部已声明成功条件。一次 CLI 调用不意味着跨权威原子性。恢复或释放效果必须显式声明、
受最初截止时间约束并单独报告，不允许隐藏的补偿修改。

## 信号与取消

- `SIGINT` 和 `SIGTERM` 只中止调用自身的等待与观察。它们绝不发出语义取消；取消已受理的
  操作需要显式的 `cancel` 动词。已声明的离线安装流程可停止并回收自身尚未移交的子进程；所属指南定义提交与恢复切点。已声明、由 Session 运行且不暴露请求标识的配置 job（如 provider 接入）改为对本次调用自己启动的 job 登记协作取消，并等待该 job 的最终报告；所属指南定义取消切点。
- 已声明的 `terminal send` 输入源只在其物化窗口内监视恰好 `SIGHUP`、`SIGINT`、`SIGQUIT`
  和 `SIGTERM` 四个信号，并扣除任何以忽略或阻塞方式继承的信号。捕获到的信号在
  任何请求存在之前以类型化源失败结束——在 `orchbee.cli.failure.source` 信封上报告；
  调用以惯例 `128 + signo` 退出。该监视集是源阶段自身的策略：其他命令不采用它，
  且获取结束时按原样恢复继承的处置。
- 被中断的调用以惯例退出码退出，中断后不写部分机器文档，并且因为未改变任何终端模式而无需
  恢复任何东西。被中断的激活还可能留下已提交的运行时状态；所属指南具名该残留，后续调用
  报告它而不是修复它。
- 在操作已受理后被中断的等待让操作继续运行；已打印或已提供的请求身份仍是之后 `get` 或
  `wait` 的句柄。

## 定位运行时

- 运行时 base 来自一个有文档记录的配置来源；当前目录、仓库、项目文件和 `PATH` 绝不选择它。
- 发现过程通过共享的 rendezvous 所有者，按所有者、mode、类型和符号链接策略校验 base、作用域
  目录和端点。不安全的路径是本地失败，缺失的端点是不可用结果，二者都不被修复。
- 兄弟可执行文件或 cohort 在被信任或启动之前按 [Rust](../RUST.md#本地进程与-ipc-边界) 验证
  身份。版本或 cohort 不匹配是不兼容结果。
- 除非其动词声明了该效果，调用绝不启动、激活、修复或锁定服务。声明了激活效果的动词
  可创建作用域运行时目录、获取其锁、提交其标记或拉起服务；它仍在任何运行时目录工作
  之前验证 cohort，为整个尝试持有一个调用拥有的 deadline，把半激活状态报告为拒绝，且绝不
  修复、停止或删除运行时状态。

已声明的停止后清理须在删除精确归属的工件前验证所有权和生命周期证据，与激活串行化，
并拒绝运行中或不确定状态。跨多个文件系统效果的清理用持久意图阻止准入，直到有界、显式
恢复完成。部分删除报告为未完成；清理绝不杀进程或静默修复无关状态。

## 调用之间的并发

- 调用之间不通过文件或共享内存协调，例外是已声明的激活与停止后清理在运行时所有者的锁上
  串行化，使激活收敛到同一个服务并避免与删除竞争。两个并发调用除此之外仍是通向同一权威的独立会话，排序由
  权威拥有。已声明的离线配置流程通过其共享配置所有者串行化，包含有界中断及恢复。
- 分页游标和请求身份对调用方都是不透明的。已声明的生命周期清理还可保留私有恢复意图，
  直到清理完成。

程序名准入在路由前必须仅处理语法。若命令拥有 PATH 解析职责，则最终执行的 CLI 必须在配置、发现与变更前解析出有界的绝对程序路径，逐字传递参数，并记录解析路径而不将其视为进程成功的证明。
