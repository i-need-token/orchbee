# CLI 命令面

## 权威性和范围

本标准拥有 Orchbee 自有的每个命令行可执行文件（不论实现语言）的调用语法：命令路径、选项、
target、帮助、版本、补全，以及面向人和 Agent 的可发现性契约。输出、退出码和本地化遵循
[`output.md`](output.md)；进程输入、副作用和截止时间遵循 [`process.md`](process.md)；证据遵循
[`verification.md`](verification.md)。命令进入终端界面之后的全屏行为属于 `tui/` 标准。具体的
命令清单、其 schema 和失败矩阵属于所属应用指南；本标准约束它们的形态。

## 语法权威

每个可执行文件在源码中有一个语法权威：对每条命令路径、选项、值集和 target 规则的声明式描述。
帮助文本、补全脚本、机器 schema 列表和应用的参考文档都派生自该权威，或经测试证明与其一致。
存在于 binary 中却不在帮助、补全或参考文档中的命令是缺陷，反之亦然。

## 命令路径

| 规则     | 契约                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 形态     | `<executable> [global options] <resource> <verb> [operands] [options]`；resource 命名一个领域名词，verb 命名一个效果类别。像 `status` 这样的根级单词是一条完整路径。 |
| 单词     | 固定的小写单词，没有缩写、别名或替代拼写。添加同义词是语法变更，而不是便利。                                                                                         |
| 动词     | 先复用现有动词再新增。读取动词绝不修改；修改动词最多提交一个效果；等待动词观察直到条件满足或截止时间到达；激活动词使运行时向就绪收敛并可创建持久状态。               |
| 族       | 没有动词的 resource 路径，或缺少必需操作数的动词，是用法失败，其诊断指明确切的 `--help` 路径。任何东西都不会带默认值执行——本条款只管动词与操作数推断；当命令的 `--help` 文本写明确切默认值时，可省略的选项组允许声明默认值。 |
| 根       | 裸可执行文件及其根级模式，例如启动界面、`--version` 和 `--help`，与任何命令一样由语法权威枚举。                                                                      |
| 离线集合 | `help`、`--help`、`--version`、`completion` 和机器 schema 列表是离线的：不读取配置，不发现运行时，不打开端点。                                                       |

| 动词类别 | 动词                                                             | 效果                                                                                       |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 读取     | `list`、`get`、`read`、`status`、`describe`、`explain`、`check`  | 观察现有状态；不创建任何在调用结束后仍存在的东西                                           |
| 修改     | `create`、`rename`、`move`、`split`、`close`、`invoke`、`cancel` | 在一个请求身份下提交恰好一个效果                                                           |
| 等待     | `wait`、`changes`                                                | 观察直到声明的条件、游标边界或截止时间                                                     |
| 激活     | `start`                                                          | 在一个调用拥有的 deadline 下使运行时向就绪收敛；可创建持久运行时状态，且在目标已就绪时幂等 |

## 选项

| 规则     | 契约                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 拼写     | 只用长选项，`--kebab-case`；唯一的短形式是帮助的 `-h` 和版本的 `-V`（当可执行文件提供它们时）。                            |
| 值       | `--name value` 与 `--name=value` 等价。即使下一个 token 以短横线开头也被当作值消费；裸 `--` 绝不被消费，并产生用法失败。   |
| 布尔     | 布尔选项不带值，也没有 `--no-` 对应形式，除非语法权威声明了它。                                                            |
| 重复次数 | 除语法权威声明可重复外，每个选项都只能使用一次；重复使用单次选项是用法失败。                                               |
| 声明     | 选项只在声明了它的命令上有效。未声明、冲突或缺少必需的选项在任何运行时访问之前就是用法失败。                               |
| 全局选项 | 选择目标运行时、机器或输出格式的选项，在可执行文件把它们定义为全局时位于命令路径之前；命令范围的选项绝不因位置而改变含义。 |
| 终止符   | `--` 结束选项识别；之后的每个 token 都是操作数。                                                                           |
| 值集     | 封闭单词集精确且小写；数字为十进制并带有声明的边界；缺失、为空、未知或越界的值是指明该选项的用法失败。                     |

## Target 与过滤器

- `<target>` 操作数首先按完整的类型化标识符解析，其次按显式 selector `@<kind>:<suffix>`
  解析——`<kind>` 为 `project`、`workspace`、`tab`、`panel`、`terminal` 之一，`<suffix>`
  为一至三十一个小写十六进制字符——selector 在命令本就读取的快照上解析到该 kind 中
  标识符以该后缀结尾的唯一成员。两者都不是的 token，在该 resource 允许 label 时，是
  精确、区分大小写的 label 候选。不存在前缀、模糊或不区分大小写的匹配。
- 标识符只按身份匹配。kind 与操作数 resource 不符，或后缀为空、含大写、为完整 32 位
  数字的 selector，在任何运行时访问之前就是用法失败；其余 `@` token 保持 label
  解读——只有五个已识别前缀是 selector 语法。本身具有标识符或 selector 形状的 label
  只能通过其真实标识符到达。
- 零匹配是 not-found 拒绝。多个匹配——精确 label 或 selector 后缀——是 ambiguous
  拒绝，报告有界的候选列表和真实总数；命令绝不替用户挑选一个。
- selector 指名的是该次调用快照中标识符以该后缀结尾的成员——是当下句柄而非持久句柄：
  删除再创建后同一后缀可能指名不同成员；需要稳定身份的命令使用完整类型化标识符。
  selector 候选是该快照中可见的成员，且服从命令声明的作用域；限定于某上下文的操作数
  （如 `panel move --target-panel`）只在该作用域内解析，无全局回退。
- 按契约 label 不唯一的 resource 只接受标识符及其自身 selector。
- 过滤器使用与操作数相同的 target 规则，并按命令声明。指向不存在实体的过滤器是 not-found；
  存在的实体但结果为空是成功的空列表。
- 命令声明分页选项时，使用带声明边界的 `--limit <n>` 和上一页返回的不透明 `--cursor <cursor>`。

## 帮助、版本与补全

- 作为已识别路径最后一个 token 的 `-h` 或 `--help` 输出与 `help <path>` 相同的文本。已识别
  路径的帮助以 `0` 退出且不需要任何运行时；未识别的路径是用法失败。
- 帮助以有效 locale 描述命令的操作数、选项、值集和效果类别。它绝不枚举实时资源。
- `--version` 只在作为唯一参数时合法，并打印一行，命名可执行文件及其版本。
- `completion <shell>` 为声明的封闭 shell 集合打印语法的静态投影。它枚举命令、选项和封闭
  值集，绝不枚举运行时状态。
- 族路径加 `--help` 描述该族并列出其命令，使读者可以在不执行任何东西的情况下向下探索。

## 破坏性与交互式命令

- 关闭、删除或以其他方式丢弃用户工作的命令需要显式的 `--confirm` 选项；缺少它是用法失败，
  它出现在非破坏性命令上同样是用法失败。
- 命令绝不在标准输入上提示，也不读取终端。唯一的例外是语法权威声明为交互式设置的命令，
  例如安装或信任审查；该命令必须接受 `--yes` 以供非交互使用，并且在 `--yes` 缺失且没有
  交互式终端时必须拒绝，而不是猜测。
- 可能超过其截止时间的修改声明 `--detach`；此时调用返回请求身份，供之后的 `get` 或 `wait`
  使用，而不是阻塞。

## Agent 可发现性

- 已安装的 binary 是其自身语法的权威。构建中存在的每条命令路径都可通过 `--help` 逐级下探、
  `completion` 和机器 schema 列表到达。
- 内嵌 Agent Skill 的可执行文件通过一个离线的根选项打印它，且该 Skill 描述的是它所嵌入的
  同一构建。
- 族的帮助包含一个有界的页脚，告诉 Agent 如何获取 Skill 以及参考文档在哪里；当裸可执行文件
  会启动界面时，它绝不指示 Agent 运行裸可执行文件来做发现。
- 发现过程完全不依赖正在运行的服务。

## 环境变量

| 规则     | 契约                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------- |
| 命名空间 | 可执行文件读取或注入的每个变量都命名为 `ORCHBEE_*`；所属应用指南列出每个变量的用途、读取方和写入方。                      |
| 注入     | 由 Orchbee 运行时注入到受管进程中的变量，例如启动器路径或运行时目录，在与调用方提供的值冲突时具有权威性。                 |
| Locale   | `LC_ALL`、`LC_MESSAGES` 和 `LANG` 按 [Rust](../RUST.md#本地化产品文案) 选择诊断 locale；没有 `ORCHBEE_*` 变量能覆盖它们。 |
| 别无其他 | 没有未记录的变量、当前目录内容或仓库文件影响一次调用。                                                                    |
