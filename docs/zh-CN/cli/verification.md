# CLI 验证

## 权威性和范围

本标准拥有 Orchbee 自有命令行面变更所需的证据。它把 [`TESTING.md`](../TESTING.md) 和
[`RUST.md`](../RUST.md#测试) 中的仓库测试义务应用到 [`command-surface.md`](command-surface.md)、
[`output.md`](output.md) 和 [`process.md`](process.md) 中的契约。变更分级遵循
[`DEVELOPMENT.md`](../DEVELOPMENT.md#变更分级)：新的命令族、修改动词、退出码映射或请求身份
规则属于 Modeled 工作，而退出码词表或机器 schema 的变更属于 Consequential。

## 结构前提

只有可执行文件保持以下边界时，下文的证据才可能成立：

| 职责 | 契约                                                                             |
| ---- | -------------------------------------------------------------------------------- |
| 语法 | 从参数列表到一个类型化请求或一个类型化用法失败的纯函数                           |
| 投影 | 从已校验响应到机器文档和文本渲染的纯函数                                         |
| 映射 | 从失败类别或终态结果到一个退出码的全函数                                         |
| 能力 | 文件系统、端点、时钟、随机性和信号来源均被注入，使测试可以拒绝或脚本化其中每一个 |
| 输出 | 标准输出和标准错误各有一个有界 sink，二者在测试中都可观察                        |

在语法或投影内部读取环境、文件系统或 socket 的变更在审查中被拒绝，无论其测试如何。

## 语法证据

- 每条命令路径、选项、值集和 target 规则都有正向用例及其拒绝的用法用例：未知单词、重复选项、
  未声明的选项、缺少值、缺少操作数、无效值、位置错误的帮助或版本，以及 `--` 终止符。
- 帮助、补全和机器 schema 列表由语法权威生成或与之比较，测试在任一命令存在于其中一处而不
  存在于其他处时失败。
- 用法诊断输出的每个帮助提示都在测试中执行，并在无运行时的情况下以 `0` 退出。
- 参数信封上限在上限处、超出上限一个单位处以及带非 Unicode 参数时被验证。

## 解析先于效果的证据

- 每个用法失败都在拒绝文件系统、端点和 cohort 能力的情况下运行；任何能力被触碰则测试失败。
- 每个离线命令以同样方式运行，且必须成功。
- 读取命令针对一个记录每个请求的脚本化端点运行；测试断言恰好一次受理和一次读取，且没有
  创建、锁或授权。已声明的观察命令还需证明重复读取有界且不产生效果。
- 修改针对一个在受理提交之后失败的脚本化端点运行；测试断言一次提交、无重试，以及一份携带
  请求身份的结果未知文档。
- 已声明的工作流程在每个阶段边界和提交回复处注入故障。证据检查有限阶段顺序、精确回执依赖、
  每效果阶段单次提交、总截止时间不变，以及后续失败、取消或结果未知时保留已知效果。
  拒绝与无变化路径证明哪些后续阶段不能执行。
- 激活动词针对真实或 staged 运行时 fixture 运行：冷调用拉起服务，重复调用报告已在运行，
  模拟的半激活状态在不改动已提交状态的前提下拒绝，且整个尝试遵守一个调用拥有的
  deadline。

## 退出码与信封证据

| 类别 | 必需用例                                                                           |
| ---- | ---------------------------------------------------------------------------------- |
| 映射 | 表驱动测试覆盖每个失败类别和每种终态结果类别，断言退出码，并断言没有任何类别未映射 |
| 信封 | 每份成功和失败文档都通过内嵌 schema 校验，包括每个失败类别下封闭的 `details` 形态  |
| 格式 | 每个失败类别在 `text` 下保持标准输出为空，在 `json` 下恰好写出一份文档             |
| 来源 | `source` 只在派生自已校验快照时出现；`null` 与 `"unknown"` 两种情况都被验证        |
| 身份 | 分离受理和结果未知都携带请求身份                                                   |

## 文本与本地化证据

- 文本渲染用控制字符、`ESC`、U+2028、双向控制字符、引号、反斜杠、宽字符和超过截断宽度的 label
  测试；断言标识符未被截断。
- 每条标准错误诊断和每段帮助文本都在 `en-US` 和 `zh-CN` 下渲染，且对 `LC_ALL`、`LC_MESSAGES`
  和 `LANG` 的 locale 选择顺序是表驱动的。
- 机器文档在两种 locale 下逐字节一致。

## 上限与流证据

- 输出上限在低于上限一字节和高于上限一字节处验证；超出用例断言标准输出为空并返回本地失败
  退出码。
- 失败的标准输出 writer 断言非零退出、没有第二份文档，以及标准错误上有诊断。
- 流式命令测试每行一条记录、来源顺序、正常结束时的终态记录，以及截止时间和通道丢失时带
  非零退出的类型化终态记录。

## 进程证据

有些行为只存在于真实进程中：流分离、退出码传播、信号处理和启动器解析。

- 以管道流作为子进程运行构建出的可执行文件，并分别断言标准输出、标准错误和退出码。
- 在针对脚本化端点的等待期间发送 `SIGINT`，并断言以 `130` 退出、没有取消请求，也没有部分
  机器文档。
- 向激活动词发送终止信号，断言进程按信号处置死亡——绝不产出合成的类型化取消文档。
- 在没有控制终端的情况下运行，并断言除声明为交互式的命令外，每条命令的行为完全一致。
- 随证据记录操作系统和端点 fixture；进程证据补充上文的确定性类别，绝不替代它们。

## 变更清单

| 变更               | 证据                                                                |
| ------------------ | ------------------------------------------------------------------- |
| 新命令或选项       | 语法类别；帮助、补全和 schema 一致性；其用法失败的解析先于效果验证  |
| 新失败类别         | 映射与信封类别；其诊断的两种 locale                                 |
| 退出码词表         | 每个 Orchbee 可执行文件的全部映射测试；所属指南在同一变更中更新     |
| 修改动词           | 针对脚本化端点的单次提交、不重放、结果未知和分离用例                |
| 等待动词或截止时间 | 截止时间到期、中断、游标重置和上限用例                              |
| 激活动词           | 冷启动、幂等重跑、已提交状态不变的半激活拒绝，以及单一有界 deadline |
| 文本渲染或截断     | 文本类别；预期文本更新按可视 diff 审查                              |
| 运行时发现         | 不安全路径、缺失端点和 cohort 不匹配用例，并拒绝修复                |
| 仓库门禁           | [适用的根门禁](../VERIFICATION.md#合并门禁)通过                     |
