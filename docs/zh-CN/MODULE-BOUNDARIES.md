# 模块边界

## 语义模块设计

本节适用于每种手写代码语言。先遵循 [`MODELING-AND-CORRECTNESS.md`](MODELING-AND-CORRECTNESS.md) 中已接受的领域契约和建模记录；本节只负责把这些语义职责映射为源码模块。变更授权和任务切片仍由 [`DEVELOPMENT.md`](DEVELOPMENT.md) 管理，跨工作区依赖方向仍由 [`ARCHITECTURE.md`](ARCHITECTURE.md) 管理，语言专属可见性仍由下文各节和所属语言标准管理。

| 模块角色         | 所属职责                                                       | 排除的职责                               |
| ---------------- | -------------------------------------------------------------- | ---------------------------------------- |
| 确定性领域模块   | 一项内聚领域契约及其规范类型、主要操作、结果和不变量集合       | 工作流顺序、框架生命周期和外部机制       |
| 状态所有者或聚合 | 一组内聚可变事实、允许的转换、不变量和权威提交边界             | 无关状态、其他所有者的写入和适配器机制   |
| 工作流           | 阶段顺序、短路、重试、恢复，以及通过类型化所有者操作进行的协调 | 重复实现领域决策或修改其他模块的内部状态 |
| 适配器           | 在一种外部能力与规范领域输入、输出、事件或命令之间进行转换     | 领域策略和独立权威状态                   |
| 组合根           | 构造、依赖接线和自有运行时生命周期                             | 领域决策和隐藏状态机                     |

- 只有当模块职责可以用一句话说明，而且能够指明其类型化输入、输出、所有者、允许的依赖、受影响声明和证据时，才准入该模块。
- 当一项职责包含可独立变化的契约、所有者、不变量集合、工作流阶段或适配器能力时进行拆分。当一个所有者和提交边界必须共同保持其不变量时则保留在一起；行数、文件数、框架类别和测试便利性绝不能决定边界。
- 把可复用代码放在最近的语义所有者中。只有具备稳定的具名契约和真实使用方时，才创建共享领域模块；偶然重复和包罗万象的工具分组不能建立所有权。
- 通过类型化操作、结果、事件和命令通信。不要仅仅为了让抽取后的代码通过编译就暴露内部状态或修改能力。
- 依赖方向跟随权威：工作流和适配器依赖可见的领域操作；领域模块和状态所有者模块绝不能依赖其编排器、框架薄壳或组合根。
- 如果抽取会产生循环依赖、宽泛的内部公共 API、回调到原父级，或在单一所有者之外协调写入，则拒绝该边界。返回领域模型，修正所有权或提交边界。

## 源模块树

`orchbee/module-boundaries` 强制执行：

| 关注点     | 契约                                                                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 源模块     | `apps/*/src` 或 `packages/*/src` 下包含 TypeScript 源码的每个目录，测试目录、自有 React 组件分组和已识别公共或私有组件树拥有的支撑目录除外。                              |
| 根模块     | TypeScript 工作区的 `src` 目录。                                                                                                                                          |
| 测试目录   | `__tests__` 属于最近的源模块祖先，不创建模块。                                                                                                                            |
| 边界入口   | 每个 TypeScript 源模块都有 `index.ts`；唯一例外是仅导出显式子路径或资产、没有根导出及 `main`/`module`/`types` 字段的私有包根模块，见[包](PACKAGES.md#公共-api-和包导出)。 |
| 同一模块   | 文件直接相互导入。                                                                                                                                                        |
| 后代到祖先 | 后代可以直接导入祖先实现，因为它位于词法可见范围内。                                                                                                                      |
| 横向依赖   | TypeScript 导入目标 `index.ts`；即使 TypeScript 可以解析，横向边界之下的路径仍为私有。                                                                                    |

## 原生源码树

`orchbee/module-boundaries` 只管理 TypeScript 和 TSX 导入。原生应用通过其固定的原生构建图声明
可执行和可导入模块根，绝不添加占位 `index.ts`。原生工作区在增长到一个以上源码模块前，其所有者
必须在已接受的所属本地权威中定义语言专属的可见性和横向导入契约；仅凭相对路径可达性不能让另一棵
原生子树成为公共边界。Rust crate 和 module 可见性遵循 [`docs/RUST.md`](RUST.md#模块和可见性)；
Zig 可见性遵循 [`docs/ZIG.md`](ZIG.md#命名和模块)。

应用内部 Rust crate 是所属应用内的编译边界，按 [Rust](RUST.md#放置和工作区所有权)准入。
其 library root 只显式 re-export 应用或同级内部 crate 使用的契约。移动模块不代表允许扩大
状态访问、回调应用或引入依赖环；保留语义所有者，并在提取之前断开环。

## 结构化组件分组

| 关注点           | 契约                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 识别             | 包含 `<ComponentName>.tsx` 的自有 `components/<component-name>/` 是 [`docs/frontend/react.md`](frontend/react.md#组件目录边界) 约束的私有组件所有权边界，不是模块。 |
| 所有权           | 包括递归组件、支撑目录和已声明语义子系统在内的整棵子树，都属于拥有最外层匹配组件分组的源模块祖先。                                                                  |
| 入口和导入       | 它没有 `index.ts`，绝不能跨源模块边界导入；所有者和实现文件作为同一源模块的成员直接相互导入。                                                                       |
| 外部依赖         | 对其他源模块的依赖遵循正常可见性表。                                                                                                                                |
| 提升             | 另一个模块需要私有组件时，把该组件及完整所有权树提升到合适的源模块边界。                                                                                            |
| 目录名称例外     | `components` 目录只有匹配组件分组形态时才是结构分组；`packages/ui/src/components/ui` 仍是正常公共模块树。                                                           |
| 公共边界组件文件 | 只把 `index.ts`、根组件 `.tsx` 和可选的同名 `.module.css` 作为直接组件文件。                                                                                        |
| 公共组件支撑目录 | React 组件契约允许的支撑目录和内聚语义子系统继续作为源模块的结构部分，并且没有 `index.ts`。                                                                         |
| 其他目录         | 非组件目录和组件所有权树之外的目录是源模块，需要 `index.ts`。                                                                                                       |

## 模块可见性

源模块可见性遵循词法树作用域：

| 源模块 | 目标模块                     | 允许 | 必需目标   |
| ------ | ---------------------------- | ---- | ---------- |
| `B/B1` | `B/B1` 自身                  | 是   | 实现文件   |
| `B/B1` | `B` 或其他祖先               | 是   | 实现文件   |
| `B/B1` | `A`，某个祖先的同级模块      | 是   | `index.ts` |
| `B/B1` | `B/B2`，当前层级的同级模块   | 是   | `index.ts` |
| `B/B1` | `A/A1`，另一棵子树           | 否   | 隐藏       |
| `B`    | `B/B1`，子级或后代           | 否   | 隐藏       |
| `A/A1` | `B/B1`，同祖但不同分支的子树 | 否   | 隐藏       |

该规则同样适用于运行时导入、仅类型导入、动态导入和重新导出。

## 边界入口点

- `index.ts` 是导出清单，不是实现文件。
- 它只包含带来源的显式命名重新导出，包括 `export type`。
- 禁止导入、声明、可执行语句、本地导出、默认导出和 `export *`。
- 它可以重新导出自身模块的实现文件和直接子级的 `index.ts`；更深层 API 必须逐层提升。

```text
src/
├── a/
│   ├── index.ts
│   └── a1/
│       └── index.ts
└── b/
    ├── index.ts
    └── b1/
        ├── index.ts
        └── consumer.ts
```

```ts
// src/a/index.ts：通过 A 显式提升选定的 A1 API。
export { createA1 } from './a1';
export type { A1Options } from './a1';

// src/b/b1/consumer.ts
import { createA1 } from '../../a'; // 允许：通过 A 的边界。
import { createA1 as hiddenA1 } from '../../a/a1'; // 禁止：A1 对 B1 隐藏。
```

即使 `src/a/a1/index.ts` 存在，第二个导入仍然被禁止。只有通过 `src/a/index.ts` 的显式导出，其 API 才会对 `B/B1` 可见。TypeScript 会验证请求的符号确实已导出。

## 测试

- 生产源码绝不能从 `__tests__` 导入。
- 测试继承所属模块的可见性，包括祖先测试辅助函数。
- `src/__tests__` 中的包级测试可以通过后代的 `index.ts` 检验它们，绝不能通过私有后代文件。

## 组合和循环依赖

- 父模块不作为子模块的组合根；把编排放在使用可见同级边界的专用叶模块中，需要时再向上重新导出。
- 模块实现绝不能导入自身的 `index.ts`；直接导入本地实现文件以避免 barrel 循环。
- `import/no-cycle` 以 `ignoreTypes: false` 运行；仅类型和运行时循环依赖都会失败。
- 通过把共享契约移动到双方都可见的最近模块、在接口后反转依赖或引入专用同级模块来打破循环；绝不能抑制或降级规则。
