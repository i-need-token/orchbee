# 模块边界

## 源模块树

`orchbee/module-boundaries` 强制执行：

| 关注点     | 契约                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 源模块     | `apps/*/src` 或 `packages/*/src` 下的每个目录，测试目录、自有 React 组件分组和已识别公共或私有组件树拥有的支撑目录除外。 |
| 根模块     | `src` 目录。                                                                                                             |
| 测试目录   | `__tests__` 属于最近的源模块祖先，不创建模块。                                                                           |
| 边界入口   | 每个源模块都有 `index.ts`。                                                                                              |
| 同一模块   | 文件直接相互导入。                                                                                                       |
| 后代到祖先 | 后代可以直接导入祖先实现，因为它位于词法可见范围内。                                                                     |
| 横向依赖   | 导入目标 `index.ts`；即使 TypeScript 可以解析，横向边界之下的路径仍为私有。                                              |

## 结构化组件分组

| 关注点           | 契约                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 识别             | 包含 `<ComponentName>.tsx` 的自有 `components/<component-name>/` 是 [`docs/frontend/react.md`](frontend/react.md#组件目录边界) 约束的私有组件所有权边界，不是模块。 |
| 所有权           | 包括递归组件、支撑目录和已声明语义子系统在内的整棵子树，都属于拥有最外层匹配组件分组的源模块祖先。                                                                  |
| 入口和导入       | 它没有 `index.ts`，绝不能跨源模块边界导入；所有者和实现文件作为同一源模块的成员直接相互导入。                                                                       |
| 外部依赖         | 对其他源模块的依赖遵循正常可见性表。                                                                                                                                |
| 提升             | 另一个模块需要私有组件时，把该组件及完整所有权树提升到合适的源模块边界。                                                                                            |
| 目录名称例外     | `components` 目录只有匹配组件分组形态时才是结构分组；`packages/ui/src/components/ui` 仍是正常公共模块树。                                                           |
| 公共边界组件文件 | 只把 `index.ts`、根组件 `.tsx` 和可选的同名 `.module.css` 作为直接组件文件。                                                                                        |
| 公共组件支撑目录 | React 组件契约允许的支撑目录和内聚语义子系统继续作为源模块的结构部分，并且没有 `index.ts`。                                                                         |
| 其他目录         | 非组件目录和组件所有权树之外的目录是源模块，需要 `index.ts`。                                                                                                       |

## 模块可见性

源模块可见性遵循词法树作用域：

| 源模块 | 目标模块                     | 允许 | 必需目标   |
| ------ | ---------------------------- | ---- | ---------- |
| `B/B1` | `B/B1` 自身                  | 是   | 实现文件   |
| `B/B1` | `B` 或其他祖先               | 是   | 实现文件   |
| `B/B1` | `A`，某个祖先的同级模块      | 是   | `index.ts` |
| `B/B1` | `B/B2`，当前层级的同级模块   | 是   | `index.ts` |
| `B/B1` | `A/A1`，另一棵子树           | 否   | 隐藏       |
| `B`    | `B/B1`，子级或后代           | 否   | 隐藏       |
| `A/A1` | `B/B1`，同祖但不同分支的子树 | 否   | 隐藏       |

该规则同样适用于运行时导入、仅类型导入、动态导入和重新导出。

## 边界入口点

- `index.ts` 是导出清单，不是实现文件。
- 它只包含带来源的显式命名重新导出，包括 `export type`。
- 禁止导入、声明、可执行语句、本地导出、默认导出和 `export *`。
- 它可以重新导出自身模块的实现文件和直接子级的 `index.ts`；更深层 API 必须逐层提升。

```text
src/
├── a/
│   ├── index.ts
│   └── a1/
│       └── index.ts
└── b/
    ├── index.ts
    └── b1/
        ├── index.ts
        └── consumer.ts
```

```ts
// src/a/index.ts：通过 A 显式提升选定的 A1 API。
export { createA1 } from './a1';
export type { A1Options } from './a1';

// src/b/b1/consumer.ts
import { createA1 } from '../../a'; // 允许：通过 A 的边界。
import { createA1 as hiddenA1 } from '../../a/a1'; // 禁止：A1 对 B1 隐藏。
```

即使 `src/a/a1/index.ts` 存在，第二个导入仍然被禁止。只有通过 `src/a/index.ts` 的显式导出，其 API 才会对 `B/B1` 可见。TypeScript 会验证请求的符号确实已导出。

## 测试

- 生产源码绝不能从 `__tests__` 导入。
- 测试继承所属模块的可见性，包括祖先测试辅助函数。
- `src/__tests__` 中的包级测试可以通过后代的 `index.ts` 检验它们，绝不能通过私有后代文件。

## 组合和循环依赖

- 父模块不作为子模块的组合根；把编排放在使用可见同级边界的专用叶模块中，需要时再向上重新导出。
- 模块实现绝不能导入自身的 `index.ts`；直接导入本地实现文件以避免 barrel 循环。
- `import/no-cycle` 以 `ignoreTypes: false` 运行；仅类型和运行时循环依赖都会失败。
- 通过把共享契约移动到双方都可见的最近模块、在接口后反转依赖或引入专用同级模块来打破循环；绝不能抑制或降级规则。
