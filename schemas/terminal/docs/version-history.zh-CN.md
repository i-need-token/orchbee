# 终端协议版本政策及发布历史

本文档是 `schemas/terminal` 所拥有各语义版本的权威来源，也记录首次公开发布后的版本历史。

## 版本域

本文涵盖五个彼此独立的协议契约版本：

| 合同                | 当前版本 | 拥有                                              |
| ------------------- | -------- | ------------------------------------------------- |
| 线协议              | `0.1.0`  | 握手、传输信封、控制消息、输入和消息注册表        |
| `OBTF` 终端帧       | `0.1.0`  | 打包终端帧字节                                    |
| `OBPB` 投影缓冲区   | `0.1.0`  | 打包 Host 渲染投影字节                            |
| `OBRW` 行窗口       | `0.1.0`  | 打包渲染/文本历史窗口字节与 render-detail 图形    |
| `OBKG` 图形扩展记录 | `0.1.0`  | 自有解码图像、已解析放置、合成层与 animation tick |

NPM 包版本、Terminal Host 可执行文件版本、Zig 工具链版本和第三方依赖版本均由各自的发布所有者管理。它们不是线协议兼容版本，也不会自动随这五项契约递增。

## 在第一次公开发布之前

遵循仓库的[发布前版本规则](../../../docs/zh-CN/ARCHITECTURE.md#数据边界)。当前契约变化时，
必须同时更新 `v1/constants.json` 及 Rust、TypeScript 和 Zig 常量、编码器、解码器、夹具、导出、测试及当前协议参考。

## 公开发布及以后

首次公开发布契约时，每项已发布契约的版本均设为 `1.0.0`。此后，每项外部可观察的变更都必须更新所属契约的语义版本，并在同一变更中添加发布历史条目：

- `MAJOR` 表示不兼容的契约变更。
- `MINOR` 表示向后兼容的新增内容。
- `PATCH` 表示向后兼容的修正。

当前运行时只接受精确的当前版本；语义版本用于区分契约变更类型，并不意味着存在尚未实现的版本协商范围。同一版本下，已发布的夹具字节绝不能被静默覆盖。

## 夹具命名

夹具名描述内容，不带版本后缀，例如 `transport-envelope.bin` 和 `ghostty-render-row-window.bin`。
所属线协议或格式的精确版本写在夹具内容和实现常量中。`canonical.json` 是当前夹具的生成器输入，
而非兼容性工件。

## 已发布版本

没有。发布历史条目从第一个公开的 `1.0.0` 合约开始。
